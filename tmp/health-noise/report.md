## Top 3 producer changes

1. **Test findings carry the age of their evidence and only count current evidence** (removes 91 failed + 11 unknown = 102 of 223 findings; 0 of the 13 faults).
   - Rank only, one line, minimal risk: `resources/seon/schemas/seon.problems.edn:7` and `:16`: add `:seon.health/at :seon.test/run-at` to `failed-test` (unknown-test needs the run time in its value). Score halves per day: the 240 red becomes ~2 after 7 days. Does not reduce counts.
   - Count: `src/seon/problems.clj:393 failed-tests`: after `latest-results`, keep a red only when its recorded `:seon.test.member/reach-digest` equals the current one from `test.runner/reach-digests` (cached `::reach-digest`, runner.clj:999-1001), and report the rest as ONE unit `no current evidence: N tests` (a number, not 2,300 rows). Measured now: 91/91 and 47/49 differ, so the failed list becomes 0 until tests run on the current program, which is the truth ("Require current positive proof": a stale red proves nothing about this program). Cost check required first: `reach-entries` warm cost, it is currently the top discipline warning.
2. **Definition regression impact is absolute added time, not calls** (fixes the 16 -> 32 us rank-1 case; count of findings unchanged, rank fixed).
   - `src/seon/health.clj:460 definition-comparisons`: add a derived member `:seon.health/added-ms` = (after-us - before-us) x calls / 1000 (a data value from the two measurements already in hand, no filter); `resources/seon/schemas/seon.health.edn` `:definition-regression`: `:seon.health/impact :seon.health/added-ms`. 16 -> 32 us over 377 calls is 6 ms of added time, scores ~120 against a 1.3 s over-bound at 180 and a 3-test red at 196 that is real; and it ranks by cost to the cluster, which is what "regression" should mean. Also make the unit not list sub-200-call or p99 rows the finding schema rejects anyway (health.clj:~476, comparisons that cannot match are not derived): unit 30 -> 13.
3. **Errored receipts decay and are not eternal problems** (98 -> 0 findings of any weight; the family stays for queries).
   - `resources/seon/schemas/seon.problems.edn:32` `errored-receipt`: add `:seon.health/at :seon.cluster.eval/at`, and have `errored-receipts` (problems.clj:190) pull `:seon.cluster.eval/at` into the row; severity 1 x 2^-7 rounds to 0. Honest alternative if the owner agrees the family is mis-derived (agent errors already return to the agent): delete the family (problems.clj:426 and the `an-errored-receipt-is-a-problem-without-being-a-fault` test, problems_test.clj:440, message_assignment_test.clj:83,113 read it) so that only recorded core faults reach health; that is a semantic decision for root, not taken here.
   - Unowned namespaces (4): trace what records `:seon.ns/source` for scratch namespaces (`user`, `result`) and stop it there; then `unstewarded-namespaces` (problems.clj:307) needs no change.

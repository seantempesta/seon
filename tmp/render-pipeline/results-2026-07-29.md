# Render-pipeline experiment results — 2026-07-29

These are non-gating measurements. The scripts beside this file reproduce
them. All measurements ran from `/Users/sean/src/seon` on the same machine.

## Commands and environment

```text
clojure -M:test bench/seon/render_bench.clj --trials 2000
clojure -M:test tmp/render-pipeline/server_bench.clj
await import('./tmp/render-pipeline/client_morph_bench.mjs')
```

- JVM: OpenJDK 26.0.1, 18 available processors.
- Browser: installed Google Chrome 150.0.7871.187, headless.
- Datastar browser bundle: 1.0.0-RC.7.
- Server and browser extension runs were each repeated twice.
- Browser timing starts inside Datastar's `DOMParser.parseFromString` and ends
  in the `MutationObserver` microtask after the synchronous ID-aware morph.
  It excludes localhost transport.
- Fast-write timing submits already-framed bytes to continuously draining
  loopback TCP sockets. It measures the healthy-reader path, not the settled
  http-kit pending-write-state fork.

## Serialize once, share the object

This compares rebuilding the complete 250-event package per tab with building
it once and distributing the same object through `mult`. Ranges are the two
runs.

| tabs | per-tab serialization p50 | once + `mult` p50 | p50 speedup | once + `mult` p95 |
|---:|---:|---:|---:|---:|
| 2 | 1.312–1.503 ms | 0.702–0.977 ms | 1.5–1.9× | 0.956–1.134 ms |
| 10 | 6.779–8.025 ms | 0.704–0.990 ms | 8.1–9.6× | 0.916–1.222 ms |
| 50 | 31.783–42.479 ms | 0.636–0.765 ms | 50.0–55.5× | 0.872–1.171 ms |

Bare `mult` fan-out of the already-built object was at most 0.047 ms p95 at
50 taps. The live REPL additionally observed the exact same object identity at
both taps.

## Fast writer and streamed-token churn

The 250-event shapes were 437 bytes for a stable-ID active-row patch, 85,532
bytes for a transcript-block patch, and 86,239 bytes for a keyframe after UTF-8
conversion in the loopback write experiment.

| tabs | active row write p95 | transcript block write p95 | keyframe write p95 |
|---:|---:|---:|---:|
| 2 | 0.019–0.020 ms | 0.061–0.068 ms | 0.067–0.073 ms |
| 10 | 0.038–0.039 ms | 0.264–0.265 ms | 0.259–0.266 ms |
| 50 | 0.227–0.241 ms | 1.208–1.262 ms | 1.105–1.213 ms |

One complete streamed-token server frame renders and serializes the newest
keyframe once, fans out the same package, and submits either the active-row or
block delta to every fast tab:

| tabs | active row p95 | transcript block p95 |
|---:|---:|---:|
| 2 | 0.941 ms | 0.861 ms |
| 10 | 0.911 ms | 1.302 ms |
| 50 | 1.172 ms | 2.387 ms |

At 60 updates/s, 50 fast tabs imply about 1.25 MiB/s for the 437-byte row
patch versus 244.71 MiB/s for the 85,532-byte transcript patch. Serialization
sharing removes N-fold CPU but cannot remove N-fold socket bytes.

## Real Datastar client morph

Ranges are the two browser runs' p95 values. The “leaf” is a stable-ID active
token span. Datastar still uses its normal default `outer` morph in every row.

| events | target | patch bytes | client morph p95 |
|---:|---|---:|---:|
| 250 | whole page | 85,839 | 1.3–1.6 ms |
| 250 | transcript block | 85,559 | 1.2–1.5 ms |
| 250 | active leaf | 87 | 0.1–0.2 ms |
| 1,000 | transcript block | 342,434 | 4.9–5.0 ms |
| 1,000 | active leaf | 87 | 0.1–0.2 ms |
| 2,500 | transcript block | 859,184 | 12.4–13.1 ms |
| 2,500 | active leaf | 87 | 0.2 ms |
| 5,000 | transcript block | 1,720,434 | 25.0–32.2 ms |
| 5,000 | active leaf | 87 | 0.2 ms |

Datastar's client morph avoids unnecessary DOM mutation, but it cannot avoid
parsing and walking the bytes the server sent. A 250-event block is comfortably
inside 16 ms; 2,500 events nearly consume the browser budget alone; 5,000
events exceed it.

## REPL buffer falsifiers

The live `default` cluster's JVM REPL returned:

```clojure
{:sliding-kept :r2
 :mult-replayed-to-late-tap? false
 :same-object-to-both-taps? true}
```

A separate revision simulation offered revisions 1, 2, and 3 into
`(sliding-buffer 1)`. The consumer retained revision 3; from delivered revision
0 it chose keyframe snap 3, and from delivered revision 2 it chose delta 3.
This is the loss-is-free rule used in the design.

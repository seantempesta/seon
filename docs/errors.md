# Errors and problems

An error is data: one error map, recorded once per cause on main, and read with every other recorded problem through one report, so health is the absence of open problem facts.

Every failure is the one error map (`seon.contract/error`: `:seon.error/type`, `:seon.error/operation`, `:seon.error/message`, and its data), whether a contract refused a call, an edge caught the outside world ([failure points](failure-points.md)) or an entrant boundary caught a defect. It flows to whoever can act on it: the requester gets it as its answer, a task holds it as its error, and an observer records it. Nothing here files tasks or resolves errors; root and the owner mine them into tasks.

## Errors

A recorded error is one entity per signature on main, with its count, the agents it hit and its first example: `seon.error`.

The signature is the digest of the error's cause (```seon.error/cause```: its type, operation, member, its Malli problems' paths and expected schemas, its class, an exit or HTTP status, and its message with digit runs normalised by `seon.error/digits->n`), so one cause is one signature however often it repeats. An observer builds an occurrence (`seon.error/occurrence`, of class `:platform`, `:eval`, `:agent` or `:effect`) and folds it into its own state (```seon.error/fold```), costing one hash. ```seon.error/flush-tx``` writes only the signatures that changed, and the observer keeps one such write in flight, so a storm of identical errors costs one update per write.

The observers: root's api proc (Flow's error channel, an agent's death or stall, an agent's failed effect; `seon.root/errors` answers its fold, with the true counts); root code that asked an effect, which records its failure once, with its own fact of the outcome in one transaction (```seon.error/asked-tx```, the row naming that fact's attribute as subject, so the next good outcome closes it): `seon.root/import-source!` (`:seon.root/source`), `my.root/gate!` and the reconciler's `:tests` (`:seon.task/deferred-results`), the reconciler's `:git` (`:seon.task/commit`), `my.root/build!` (`:seon.root/generation`), `my.root/first-moves!` (`:seon.judge/digest`) and `seon.vector/vectors-proc` (`:seon.vector/model`, its own commit starting no round). `seon.root/wiki-baseline`'s failed `:history` writes no row: each section's `:seon.doc/baseline-unread` records it, and health shows it as a derived `:stale-section` row; an agent, which folds its own eval errors (`seon.error/note`) and sends them with its next commit, recorded at root as `:eval` (`seon.error/sent->occurrence`); and the source watcher (`my.root/watch!`), whose loader error or failure to start is written as a `:platform` error by `seon.root/platform-tx`. The wiki written in boot's fact (`seon.root/wiki-tx`) never refuses the load: a link to no section is kept and shows as a dead citation ([health](health.md)). `seon.error/record` reads one back.

### An error keeps data

An error is data, never a Throwable or a live object, when another process keeps it past its moment (AGENTS.md section 4; measured 2026-10-29: root's `*e` reached 78 MB, once 1.08 GB, because an exception's ex-data held live values). What an asker gets back, and what an agent's own eval, test or reply carries, is the error with its full data (owner, 2026-10-29: "do not put any artificial limits or cuts on agents context or evals"): `seon.contract/error`, `seon.agent/error-map` (an exception's `:data` whole), `seon.server/respond` and `seon.proofs` (an unreported test's `:data`) cut nothing. Where root keeps the errors of other processes for its life, the data is bounded by `seon.contract/kept`: a value is kept as it is when it is small [plain data](storage.md#plain-data) (```seon.contract/plain?```, so a sorted map is its print), within `seon.print/budgets` `:part` nodes and, for a string, four characters a token of the form budget), else a string as the printer's cut of it (`seon.print/prose`, which says what it omitted) and any other value as the one printer prints it under that budget, marked code (`seon.print/code`); a db value, conn, atom, Throwable or lazy seq is always its print. `seon.contract/bounded` keeps every member of a map. The root-kept site is `seon.root/flow-error` (Flow's error channel value, which `:root-errors` merges); a new place root keeps another process's error calls them too. Throwing a value within a call stack is fine; keeping it in root is the problem. Proofs: `seon.contract-test/an-error-keeps-bytes-that-do-not-grow-with-its-value` (the bytes root keeps for values of 1 KB, 100 KB and 10 MB) and `an-agents-own-error-keeps-its-full-data`.

### An eval error's diagnostics

An exception from an evaluated form is the `:seon.agent/eval-error` map (`seon.agent/error-map`). Its ex-data is data on that map: every `:jolt.error/` and `:clojure.error/` key stays a key (Jolt's `:jolt.error/line`, `/column`, `/symbol`, `/ns`, `/kind`, `/type`, `/suggestions`, and `:clojure.error/*`; the schema is in `seon.problems.edn`), any other ex-data, qualified or not, is `:data`, a map. Jolt's "did you mean" suggestions are `:seon.error/fix`, and an unresolved symbol's message is built from `:jolt.error/symbol` as Jolt's nREPL words it (`jolt.nrepl/err->msg`), so the suggestions are not in it twice. `(prinltn 1)` reads `Unable to resolve symbol: prinltn in this context`, `fix: did you mean print, printf, println`, then the type, the operation and the remaining keys (line, column). `seon.repl/located` adds where, in the form's own terms (what `(source v)` prints, 1-based): `:seon.error/at {:line :column}`, and for a runtime error the fn it was in as `:seon.error/in`. Jolt's own positions are the request's text's, so a compile error is shifted by its form's start and a runtime error by its var's `:line`; the request-relative `:jolt.error/` and `:clojure.error/` line and column stay in the data, and out of the text only when `:seon.error/at` is stated. A runtime error reads `at line 3 of ns/f`, a compile error `at line 3:6` (a form with no recorded position keeps the request's, `:jolt.error/line`); proof `seon.repl-test/an-eval-error-says-where-in-its-forms-own-text`. An item's `:err-text` is a second error render, not the first: `(str err (nrepl/err->msg ..))`, the form's `*err*` output followed by Jolt's text with the request-relative position. It stays only because `repl_test` reads it; task `seon.repl/err-text-is-the-err-stream` splits the stream out and deletes it. The one render prints each fact once (`seon.render.ui/error-hidden` names the keys its own lines already carry, and the request-relative position only once the form's own is stated); proofs `seon.repl-test/an-eval-errors-data-is-printed-once` and `an-ordinary-exception-is-its-error-map`. A throw inside an anonymous fn is framed `ns/var$fn`, often with no line (one a core fn such as `map-indexed` calls, inside a contracted function): it is in that var, at the line the var's own frame has in the trace, so the error names the fn around it (`seon.repl-test/an-error-in-a-fn-a-core-fn-calls-is-in-the-fn-around-it`).

A macro's syntax error (phase macroexpansion, or its syntax check) also carries `:seon.error/given`: the forms the failing call was given, each printed whole (never cut: the swallowed forms sit at a form's tail), as the reader read them, found in the eval's form by Jolt's position (`seon.repl/given`). Such an error is about a count or a grouping, and the reader's grouping is what the writer cannot see: "cond requires an even number of forms" from an `and` one paren short names neither; `given` shows the one form the `and` swallowed the rest into.

Deliberately unused (researched in the scratch paper `jolt-debug-features`, in git history), so nobody proposes them again:
- `JOLT_DIAG`: read only by the CLI's top-level uncaught handler, which our eval's catch never reaches; the same data is already in the exception's ex-data.
- `JOLT_CHECK`: warnings go to the process's stderr (read only on death), and the variable is a Scheme global with no Clojure setter. `jolt.passes.types/check-form` over the node the REPL's tap holds would need no variable; measured silent on all of `src` (3397 forms, 0 findings, the archived paper check-form-measure-2026-10-23.md (git history)) but a new item key waits for an owner ruling: task `seon.repl/type-findings-are-an-evals-warnings`.
- `JOLT_DEBUG`: stderr traces of the builder (AOT cache misses, dependency fetches); not an eval's concern.
- `jolt.nrepl` as a server: a second request path beside `seon.server`'s `:eval`, bypassing recording, ticks and the middleware, on a second port. Its `err->msg` is used as a library.
- `clj-kondo`: it only knows Jolt's `jolt.ffi` macros, our `seon.contract/defn` would flood it with unresolved symbols, and the compiler already reports those with suggestions.

## Problems

Every problem Seon recorded is read by one function, ```seon.problems/report```: main's db in, one report out, by class; ```seon.problems/health``` is that report with the classes the program's facts make true now (dead citations, unnamed sites, stale pins and sections, orphan pages, sections with no lead, uncited tasks) added.

Its classes are the recorded errors counted by signature (`seon.problems/counted-classes`) and what a task or its agent holds (`seon.problems/ended-classes`: red assertions, cost verdicts, merge conflicts and refused answers, a death, an error that ended the loop, overrun, task conflicts, and `:unrun`: a merge that left its process tests unrun), plus each root cause with what it blocks ([root](root.md#root-causes-at-quiescence)) and a task marked failed while it is held ([tasks](tasks.md#a-refused-run-is-held-for-root)). Each problem carries what a task needs (producer, owning namespace, evidence, the proofs that reproduce it) and the tasks whose `:seon.task/evidence` already answers it (`seon.problems/answers`). Its cost follows the problems, never the program: each class is read through an index that holds only problems.

`my.root/problems` is `seon.problems/health` for root, with the api's fold; root's context and the dashboard's problems banner read it rather than re-deriving problems from the live view ([render](render.md#health-is-what-flows)). `bin/check problems` provokes every class through the paths agents and root use and reads them back.

## Learn

An agent's overrun is charged to the producer of what the agent was shown: ```seon.learn/waste``` (stored as `:seon.task/waste`, reported as the `:waste` class).

At its end the agent folds its turns: a form that looks for code instead of changing it (`source`, `doc`, `ns-publics`, ...) is charged to whoever should have shown that code: `:re-read` to the render that already showed it, `:missing` or `:search` to the template; an error repeating an earlier turn's signature is `:repeats-error`, charged to `seon.context/status`, which delivered it. `seon.learn/summary` counts it by producer. It is stored as `:seon.agent/waste` on the branch, carried to `:seon.task/waste` by the judge, and reported as the `:waste` class. What a producer is charged is a context to improve ([references](references.md), [render](render.md)).

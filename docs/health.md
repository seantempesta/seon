# Health

Health is the set of open problems: a value computed when something reads it (`seon.problems/health`). It is never stored, never precomputed and never polled. Root's page, an agent's context and the done rule each read it on the db they hold. It is the recorded classes (`seon.problems/report`) beside the derived ones (`:unnamed-site`, `:stale-pin`, `:stale-section`, `:orphan-page`, `:leadless-section`, `:uncited-task`, `:stale-plan`, `:waived-proof`, `:problem-unlinked`), one value by class (`:seon.problems/report`).

## Two kinds of problem

A **recorded** problem is one only an effect can observe. Any code reports one by transacting it: an error recorded once per signature (`seon.error`), or a task's red proof, cost verdict, death, conflict, unmerged entry, deferred test or waste written as a fact at its end, a task held for root (`:failed`), and a test's newest red result. `seon.problems/report` reads what was recorded, at a cost that follows the problems and never the program. A task's problems stay open while it is still to be worked: they close when the task is done or root cancels it. A recorded error closes, with nothing written, once its subject has a fact written after its last occurrence (`seon.problems/closed?`). The subject (`:seon.error/subject`) is a var, a section, or an attribute that only a live proc writes, so its cause being gone is itself the fact. For example, a refused build names root's `:seon.root/generation` (```seon.error/asked-tx```, from `my.root/build!`), so the next build's outcome closes it. A subject's fact is the producer's latest outcome: written on success and on failure, never a counter, and an unchanged outcome writes nothing. An error that names no subject stays open until someone reads it.

A **derived** problem is something the program's facts make true now. It is a read over facts the loaders already write, so nothing writes the problem and nothing closes it. It is open exactly while it is true, and fixing the fact closes it. `seon.problems/health` is `report` plus the derived classes, in the same value, and `my.root/problems` answers it for root's main with the api's fold of repeats not yet written. Not this: a check that stores its findings and must remember to retract them, or a timer that re-runs a scan.

A dead citation is no class: a cite's target is a ref, and a task's or a page's citation of nothing is refused at its write ([references](references.md#task-references), [the wiki in the store](references.md#the-wiki-in-the-store); owner, 2026-11-09).

## A law's unnamed site

A law the compiler's facts answer exactly is a derived class too: `seon.problems/laws` holds each one as data (the fact that marks a site, the page that must name it, the check drivers it leaves out), and `seon.problems/unnamed-sites` lists each site whose page does not cite its function (`:unnamed-site`). A site is a live form of Seon's own `src` (bin/laws scans src; `seon.check` and `seon.e2e`, the check drivers, are left out): an agent's app and any test are not, since a deftest's `is` expands to a catch. A form is named by the var it defines, else the multimethod or protocol it extends, else its form id. The one law held so is `catch`, whose sites come from `:form/catches` and page is [failure points](failure-points.md). Clocks, measures and resolution stay `bin/laws`' text scan until the compiler's facts can tell their sites: a host member is recorded as `jolt.host/static-member`, not by its name, and a quoted symbol counts as a ref.

## A red test

A red test is a verdict, not a problem fact: a test's verdict is derived data, cached by digest outside the store ([merging](merging.md#verdicts-are-a-cache)), and the store keeps only decisions. A red on a branch is that branch's, read by its own plan and its judge's done rule (`:proof-red`, `:stray-red`); no class reads main's verdicts yet. Showing "red on main" as a class, from the cache at main's reach digests, is a follow-up task, measured first.

## A flaky test

A test's verdict is a function of its reach digest, so one that judged both green and red at one digest is a defect at its cause (a clock, a race, an input its digest misses), never a reason to run it again. Every verdict is kept: the cache holds `<digest>.pass.edn` for a green and `<digest>.red.edn` for a red, two files written once each, so two writers of one digest never lose either (```seon.fx/write-verdicts!```), and the bound never evicts a digest with a red file. ```seon.proofs/verdict``` judges a digest that holds both as ```seon.proofs/flaky```: red, its failures led by one saying so, never reused as green and never run again until a change moves the digest. `bin/test` and `bin/prove` print it (`FLAKY test digest`) and end red, and an agent's plan judges it red. Fixed at the cause: the test, or what it reaches, changes, and the new digest judges again. Not kept: a test that never reported (its namespace's run threw first), which has no verdict of its own, and a `bin/check` step's red (a step missing from bin/check's greens may have been cut short, not judged), so a step is never flaky.

## A stale section

A wiki section that cites code is stale when what it describes of that code changed after its text: a cited var's contract or docstring (`seon.problems/stale-sections`, class `:stale-section`; owner, 2026-10-25, DECISIONS Dogfood rulings). A body that changed while both stayed is not a change of what the section describes. When the loader writes a section's text it records the form id of each var the text cites (`:seon.doc/read`, `seon.doc/read-map`; a form id is the form's own digest, so it moves exactly when the form's text does), and while the text is unchanged a reload keeps what was recorded: it is the code as it stood when the section was last written. A cited var whose form id now differs has its `:var/contract` and `:var/doc` facts read as of the transaction that wrote the section's read (or its review) and compared with today's: a contract or docstring change is itself a transaction (`seon.program/def-tx` asserts and retracts them, history kept), so no digest of meaning is stored. The problem names the section, the var, what changed (`:changed`), what it was (`:was`) and is (`:now`). The eval that makes such a change says so in its response (`:redefined`, `seon.program/meaning-changes` over its own transaction), with the sections citing the var, so the agent sees the change it made and what to update. A form id unchanged since the read cannot have changed what it says, so only the names whose form moved read history (the before and after on main are in the commit that made this the rule). It closes when the section is edited, which re-reads the code, or when someone has read it as it is and says so with `my.doc/reviewed!` (who, and the form ids it read at; the older reviews stay in the history), with the text untouched. The comparison is by value, never by tx: a branch's tx counter is its own.

A section with no record yet (every section the day this was merged, and the first load of an old store) takes its baseline from git, so the sections already stale show up (`:seon.config.root/wiki-baseline`, `seon.root/wiki-baseline`): the commit that last changed the section's lines (`git blame --porcelain` of its page, the newest committer time among the section's lines; a line not committed yet means today), and for each var it cites the id of the form defining it in its file at that commit (`git ls-tree` for whether the commit has the file, then `git show`, read without loading by `seon.source/defining-ids`, which finds the form by its head and name and gives it the id `seon.program/account` would). Git is the `:history` effect (`seon.fx/wiki-history`, the effect owner); the loader stays pure over what it answers (`seon.doc/baseline-plan`, `baseline-reads`). A var the old file does not mention at all, or a file the commit did not have (`git ls-tree` says so), is recorded as `:absent` and is stale: it is code that appeared after the section, and the section may not describe it. A var whose form changed since the commit is read both ways by one reader, the old file and today's form as written (`seon.source/defining-meanings`: docstring and `:malli/schema`, read without loading; the contract carries the arity), and recorded as `:changed`, stale, when they differ, else as today's form id; the live `:var/contract` is not compared there, since it is the resolved schema and old text cannot give it. A var the old file mentions but no form `defining-ids` knows (one by its head) defines is not guessed `:absent`: the section is unread. A section with an uncommitted line is recorded as of today, nothing unread. A review is a git commit, so a rebuilt store reads a reviewed section fresh: `my.doc/reviewed!` also makes an empty commit with the trailer `Reviewed: docs/x.md#heading` (the `:git` effect, on the merges branch; off a checkout the commit is owed), and the baseline takes, per section, the newer of the commit that last changed its lines and the last commit whose trailer names it, from one `git log HEAD --grep='^Reviewed: '` (the checkout's own history: a review on a branch that never reached it, or was abandoned, does not freshen the section) (an empty commit touches no file, so a per-file log would never find it; a tie goes to the review). A section git cannot answer for (not a git checkout, a file git cannot show, an old file that does not read) is recorded as of today and carries `:seon.doc/baseline-unread`, shown as one attention entry until the section is edited. Measured on Seon's own wiki on 2026-10-23, once: 4.7 s (0.3 s planning, 3.9 s of git for 46 commits and 299 old files, 0.5 s reading them), 139 of the 303 sections cite code, and 88 of those were stale (229 problems: 214 changed, 15 cited code that appeared later).

It is attention, never a reason to refuse done (root's ruling, 2026-10-23): every edit of a var stales the sections that cite it, and refusing done for that would force a doc edit with every code edit. A branch that changes a var sees, in how its work stands under `:attention` (```seon.ctx.status/status```), the sections it made stale (`seon.problems/caused-split`), the docs to read and probably fix; `seon.problems/caused` and the done rule do not carry them.

## A stale pin

A pin the wiki states is stale when it is not the gitlink root's last source import recorded (`seon.problems/stale-pins`, class `:stale-pin`). The page that states pins is `docs/forks.md`: each line of the form "`reference-code/<name>` pinned at `<sha>`" (`seon.problems/pins` holds the page and the line's shape). Root records the gitlinks of `reference-code/` when it imports its source (`:seon.root/source`, its `:pins`); the class compares the stated sha, as a prefix, with that record.

While root has recorded no import there is nothing to compare, and the class has no problems: unknown is not a mismatch. A problem names the section, the path, the sha stated and the gitlink recorded; fixing the page, or bumping the pin and rewriting the line in the same commit, closes it. Cost: the page's sections (one range of addresses) and their text.

## An orphan page

A page of the wiki that no other page links to, the map (docs/README.md) included as a linker, is an `:orphan-page` (`seon.problems/orphan-pages`): a section of another page has a reference to one of its sections, or it is orphaned. The map is the root and is not judged, and a db whose wiki has no map has no orphans (unknown). Adding a link anywhere closes it, with nothing written.

## A section with no lead

A section whose first block is a list, a table or code, not a paragraph, has no lead and is a `:leadless-section` (`seon.problems/leadless-sections`): its summary is its heading alone and its embedding has no sentence saying what it is about. [The wiki's rule](README.md) is a leading sentence that stands alone for every section, and a heading that only groups subsections says what they share. Writing the sentence closes it, with nothing else written.

## A task that cites nothing

An `:implement` task that is ready (not done, every task it needs done) is an `:uncited-task` (`seon.problems/uncited-tasks`) when the plan it holds, its own and its needs' (its design step's, `seon.task/accumulate`) cites no var, attribute or section (`:no-references`), when it names no proof (`:no-proofs`), when a proof is still the placeholder `seon.ctx` writes for a missing one (`:placeholder-proof`), or when its text cites what the db no longer holds (`:gone`, naming each: the task's `:seon.task/gone`, which the write that ended those cites left on it, [task references](references.md#task-references)). The context pulls what the plan cites ([references](references.md#task-references)), so a plan in text alone gives the agent nothing to read. A design step's text plan is its input and is never judged: the design step writes the cited plan. The problem closes when the design step's plan cites a name (one backtick, [references](references.md#the-delimiter-picks-the-depth)), the proofs are named and no proof is the placeholder, with nothing written to close it. Rewriting the plan to name what exists (or the two-backtick literal of what it will make) clears the fact and closes `:gone`. Cost: the task, kind and `needs` datoms once, then a walk of each ready task's needs and one datom of each for `:gone`.

## A plan that went stale

A ready task whose own plan cites a var whose form was written after the plan is a `:stale-plan` (`seon.problems/stale-plans`): the plan was written before the var took its present form, so what it says of it (a function it calls missing, code it describes) may no longer be true, and an agent spends evals finding out. It compares the transaction of the task's current `:seon.task/plan` datom with that of each cited var's `:var/form` datom; the task's needs' plans are not judged. The problem closes when the plan is written again (a new plan datom), after reading the var: what no longer holds rewritten, or, when it all holds, a line `Checked <date> against <var>: holds.` added, since writing the same text again is no new datom and closes nothing. Cost: the ready tasks, then two datom reads a cite.

## A function that cites no section

A public function, macro or def of Seon's own source whose docstring cites no `docs/` section is an `:uncited-var` (`seon.problems/uncited-vars`): a docstring says what one var is and cites the wiki section that describes its mechanism (its page's path and the section's anchor, bare: [the summary depth](references.md#the-delimiter-picks-the-depth)), and never restates it. It is read only for the vars a branch changed (`seon.problems/caused-split`, as a dead citation is), so what the branch made uncited is shown to its agent and in root's page as attention, never a reason to refuse its done (an agent is not gated: [processes](processes.md#an-agent-is-never-gated)), and the vars cited before it are not its problem. A private var (`defn-`) and a test are not judged; a definition is told by the head of its recorded form, read by the reader (`seon.source/first-head`, so `seon.contract/defn` counts), never by matching its text. The fix is the citation: the section that cites the var at code depth is its home, and a var no section cites needs its mechanism written into the section that describes it, not into the docstring.

## A form too long

A live form of the program, in source or in a test, whose text (`:form/src`) is longer than `:seon.config.shrink/form-tokens` tokens, as the model reads it (the printer's estimate, `seon.print.emit/chars-tokens`), is a `:long-form` (`seon.problems/long-forms`): a form that long does several things, and splitting it by what it does makes each part reusable and testable ([measured](../resources/seon/config/default.edn) over this program: 83 of 2,082 source forms and 76 of 2,052 test forms were over 1,000 tokens). It is read only for the vars a branch changed (`seon.problems/caused-split`, as `:uncited-var` is), so a branch that adds one is shown it as attention (never refused: get out of an agent's way), and the forms long before it are not its problem. The problem carries the var, its tokens and the bound, and closes when the form is split under the bound; each becomes a held task from its template (```seon.template/finding```: split it by what it does, its behaviour and its tests unchanged, its cost per call no worse), written once a var by ```my.root/file-findings!``` for root or the owner to release. Cost: one seek per named var and its form's text length.

## A proof that passes by waiver

A cost proof whose estimate carries an `:overrun` ([cost](cost.md#an-accepted-overrun-and-its-ratchet)) is green because of it, so it is a `:waived-proof` (`seon.problems/waived-proofs`): the row holds the test, the task the `:overrun` names, the size it was taken at, the numbers it recorded and the multiple of the proof's own bound that record is at that size, in its worst counted dimension (`seon.cost/expected` and `seon.cost/row-ratio`, the arithmetic of a verdict, so nothing is measured). The proofs are found by the test forms that reference `seon.cost/proof` (one `:form/refs` seek) and the `:overrun` map is read out of the form by the reader, never from verdict files. It is a listing, not a refusal: no branch is judged on it (it is not among `seon.problems/caused-classes`), and it closes when the proof's `:overrun` is deleted, which is the fix of its task. `bin/prove` ends its output with `prove: N proofs pass by waiver`, counted by the same function on the tree it proved. Cost: the forms that call `seon.cost/proof`, each read once.

## A problem with no page

Every problem class declares the section of the wiki that says what it is and how it is fixed (`:seon.problems/docs` on `:seon.problems/class`, beside its area), and a problem shows the link. A class with an open problem whose section is no stored section, or that declares none, is a `:problem-unlinked` (`seon.problems/problem-unlinked`, area health), itself a class that declares its own section, so a missing page for the unlinked class is one more problem. A db with no wiki has none (unknown). Not built: the case of a recorded error that no task answers and whose owner namespace has no task file.

## Checks are callers of Seon

`bin/check health [CLASS ...]` (`bin/test --health`, ``test-runner/health!``) is the one check of these classes, and it holds a checkout to what a Seon agent is held to: what its branch caused (root's ruling, 2026-10-23). The head is the working tree's program db, kept in the program store (``test-runner/program-db``: a tree it never saw is the nearest kept tree with the changed files refreshed). The base is the base commit's tree's, made by the base's own code in a process of its own and only read here (``test-runner/base-program``): the program store's branch when it keeps that tree, else the base store's (the program store's stem with `-health-base`), which, when it lacks the tree, a checkout of the base commit (`bin/worktree --at`) fills by its own runner's plan (`bin/test --plan tests`), the checkout removed after. Analysis runs each file's `ns` form in the live namespace, so a base analyzed in the head's image retargeted the image's own aliases (a base that aliases a namespace to another target, as across the rename of `seon.root` to `seon.system`) and expanded the base's macros with the head's code; a base whose program schema is not the head's keeps no branch the head reads, and health says so. Each has its task files and its wiki loaded by root's own loaders. The program is what root imports, `:seon.config.source/dirs` (test/ among them), so a dead citation or an unnamed site a branch adds under test/ is its own too. It boots no root, imports no whole program and needs no binary, so it costs what the two trees differ by and two wiki loads (8 s warm, against 27 s on the binary and its 50 s build, 2026-10-28); a base the base store lacks adds its checkout and its plan (21 s on the rename's tree, 38.6 s in all against 17.1 s with the base kept). The base commit is ```seon.fx/base-commit```: with a branch checked out, its merge base with git's main (`:seon.config.source/main`), so a branch with no commits of its own caused nothing; with main checked out and a clean tree, the previous main, so the merge session's run on a merged main judges the merge; with main checked out and uncommitted changes, HEAD. The step judges `seon.problems/caused-split` of the two, the classes `seon.problems/caused-classes` names (a class it does not read is refused, never a green check), the done rule's own reading (```test-runner/branch-health```). It prints each problem the branch caused (and `attention` entries, the sections it changed under the wiki, which never fail it), and how many problems the head holds open in all, and ends `HEALTH OK` or `HEALTH FAILED`. A problem the base already had is not the branch's: it is root's to show, live, in its context and on its page. `bin/prove` keys the step by the tree and the base's tree (`seon.proofs/step-digests`), so an unchanged pair reuses its result. `bin/laws catch` calls it for `:unnamed-site`; it checks nothing of its own. Not this: a second checker over the files (`bin/check docs` beside the class), or the tree's absolute open problems as a branch's verdict (red on an unchanged main, so every session learned to read past it).

## What a branch caused

`seon.problems/caused` is the set of derived problems a branch's head has that its merge base had not and that refuse its done: what the branch's own work broke (`seon.problems/caused-split`'s `:caused`, which also answers `:closed`, the problems the base had and the head has not; both take the branch's changes since its merge base, and the datoms that differ between base and head (the whole `:eavt` diff or `seon.problems/caused-datoms`), when the caller already holds them: the candidates are found from those datoms and looked up by entity, so the cost follows what the branch changed, not the wiki or the program ([cost](cost.md#a-diff-per-attribute-costs-a-descent-each)); the classes `:seon.problems/attention` declares, the stale sections, go to its `:attention` instead, [above](#a-stale-section)).
- The agent's turn computes it each turn (`seon.turn`'s observe, by `seon.problems/caused`), so its context lists them with the done rule's other reasons; the task render's `caused` view draws them, with what the branch made stale, when the branch or its merge base moves.
- Root's judge computes it at the agent's end from the writer's `:branch-diff` and the done rule reads it; it is not stored.
- `seon.reconcile/done-explain` gives `:open-problem` as a reason while any is open, so the task is held for root naming it ([tasks](tasks.md#the-done-rule)).

Nothing gates an evaluation. An agent may break a citation in one eval and fix it three evals later (get out of an agent's way: [processes](processes.md#an-agent-is-never-gated)). A merge needs no rule of its own: a branch behind main is refused `:behind` and judged again after merging main.

Health is computed on the trees as they are kept and needs no built binary: the verdict itself (`seon.problems/caused-split`) takes 22 ms, and the 8-14 s the whole takes replaced a 27 s run on the binary plus a 50 s build, which had built two whole databases from scratch (root's boot 5.1 s and 3.7 GB, the base's 2.4 s and 2.3 GB, the wiki loaded twice). The base's db reads the base's task files through the checkout's own path: a tasks directory held absolute in the config names nothing under another root. ```seon.program/graph-index``` selects, per test, only the config its reach names (232 to 119 MB and 33.7 to 17.0 M ticks over 1,049 tests and 37 roots, with identical digests).

## Every writer: the db is written, files follow

Nothing in a running root reads a file: whoever changes the system writes main, and main's files are written from it (owner, 2026-11-09: "From that point on we are syncing data TO files not reading from them"). A Seon agent's change merges from its branch and the merge writes the files back ([source](source.md#write-back-mains-files-byte-for-byte)); a Claude session's landing enters main as data through `bin/land`'s bridge ([source](source.md#a-landing-enters-main-as-data)); an edit on disk made any other way acts on nothing until a person re-indexes (```my.root/import!```, ```my.root/load-docs!```, ```my.root/load-tasks!```: [source](source.md#indexing-a-tree)). A boot reads no file either ([source](source.md#a-boot-resumes-from-the-db)). Root had a file watcher over the wiki and the task files (FSEvents, an OS child); it went with the ruling, and with it every event that loaded a checkout's files into a test root's main.

A re-index's typed error (a refused task file, a file that does not load) is answered to whoever asked, never dropped and never recorded by a watcher.

## A stale binary

Root's binary is stale when it was built from another git tree than the one main was last brought to from outside (an import or a landing; what agents merged since is main's own): its boot writes the tree its build recorded beside main's on root's `:seon.root/source` fact (```seon.root/booted-source```), and ```seon.problems/stale-binary``` derives one `:stale-binary` row while they differ, naming both. Root then forks no agent (```seon.root/stale-binary```), since an agent would run main's code over an image of another tree, and its agents share no verdicts, since their inputs are the binary's tree's ([source](source.md#the-binary-records-its-program)). Its message names the acts that bring the two into agreement (```seon.problems/stale-binary-acts```: [files and the db](source.md#files-and-the-db-two-directions)), and the next boot on a binary of main's tree closes the row, with nothing written to close it. A landing shows it between git's move and its bridge's merge, and on a root whose bridge failed. Cost: one pull.

## Cost

`unnamed-sites` costs about 75 us and 75 KB per catch form (measured at n=10, 100 and 1000: linear, two contracted calls per site, `seon.problems-test/unnamed-sites-follow-the-catch-forms`); `stale-pins`, `health` and `caused` have their own cost proofs in the same file. `caused` compares base and head by value (not by tx: a branch's tx counter is its own) and reads the rules only for what differs: the sections whose citations differ, the sections citing a name a var or task lost, and the forms carrying a law's fact whose catches or text differ (every site when a section of a law's page changed). Its floor is a scan of those attributes' datoms, with no pull and no rule. Measured in a REPL on Seon's own program (300 sections, 880 citations, 1,735 vars, 30 catch forms), after deleting a var that is cited: 11-12 ms, against 26-29 ms for reading both classes in full over both dbs; an unchanged branch 7 ms. With `:stale-section` read only for the vars the branch changed (`seon.merge/changed-vars` of the turn's one diff) and the sections that differ, an unchanged branch is 7.7 ms and a change 8.5 ms; the whole of `health` on that program is 12.7 ms (0 stale sections right after a load, 0 orphan pages, 0 unlinked classes). `seon.problems-test/caused-follows-what-changed` holds it at 10, 100 and 1000 sections and sites with a fixed change (its bounds: 5,900 ticks and 32.5 KB per section and site for the scan, 24 contracted calls however large), and `caused-agrees-with-the-full-reading` checks it against the full reading on eight changes.

`my.root/problems` reads the render proc's health, kept by what each move of main changed (`seon.render.proc/health!`): root's api asks the render proc with the main the caller read (`:health`), the render proc brings its held main and health to it, and the api answers at its error fold's counts (`seon.problems/with-fold`, the one place a fold is applied, `seon.problems/fold-counted`), so a read costs what main changed since the last, where it read the whole program every call (`seon.agent-test/root-reads-the-health-the-render-proc-keeps`: 196 MB a read in a test root before). A whole read (`seon.problems/health`: the render proc's first, bin/check's own) is, in a test root, `unnamed-sites` (62 MB), the stale sections' vectors and `current-forms` (measured before the class that read every text was deleted; 508 MB then, 225 MB after it read each text once).

A move of main costs what it changed (`seon.problems/health-moved`). The render proc already reads the datoms that differ between the main it holds and the new one (`d/datoms-diff`, O(changed)); `health-moved` takes them with the held health. It is wired: the render proc keeps main's health in root's ctx beside root's process (`seon.render.proc/health!`, on each move of main, from the datoms `advance-main` already reads) and the problems tile (`seon.render.ui/problems-tile`) draws that value, so it runs again only when a class changed (`seon.render-test/the-problems-tile-follows-main-without-reading-it-whole`). `health-moved` is given those datoms, and `seon.merge/delta-changes` over them (`seon.merge/touched-by`), so the program is not diffed a second time: for a one-branch change 384 K ticks at 10 finished tasks, 519 K at 100 and 46 contracted calls at any size, where `health` whole is 430 K, 1.69 M and 37 to 127 calls; on main's own db (514 tasks, 3,472 vars) a one-branch change costs 8.2 M ticks, 43.6 MB and 77 calls against 168 M, 462 MB and 3,674 for `health` of the head, with identical classes (`seon.problems-test/problems-move-at-the-cost-of-what-changed`). The classes `caused-split` reads are the held problems less those the old main had and the new one has not (`:closed`) plus those the new one has and the old had not. So closed history is never read: `seon.problems-test/problems-move-at-the-cost-of-what-changed` measures 34 contracted calls at 10, 100 and 1,000 finished tasks, and about 1,000 ticks per finished task (`uncited-tasks`' one scan of the task ids), where `report` read every task's cost verdict and waste (3.3 M ticks at 100 tasks with a one-task change). `health-moved-is-health` holds it equal to `health` over a changed docstring, an edited section, an agent that died and the agent that finished its task. A section's state compared by value includes what opens and closes its stale problems (`:seon.doc/read`, `:reviewed`, `:baseline-unread`).

Health reaches each ctx as one layout over the same problem facts. Root's page draws every open class (`seon.render.ui/problems-tile`, the report `seon.problems/health` changed by each move of main). An agent's page draws only the problems on its own task and branch (`seon.render.ui/own-problems`, from `seon.problems/own`): its task's problems by the same ended classes (`seon.problems/ended-classes`), its task's failure and the recorded errors last raised in its task, as a report the same `:seon.problems/report` render draws, nothing when none is open. Its cost does not follow finished history (`seon.problems-test/an-agents-own-problems-cost-nothing-for-the-history`: 4 contracted calls at 10, 100 and 1,000 finished tasks); the derived classes (wiki, program) reach an agent as its turn's caused and attention, as before (`seon.problems/caused-split`).

# Measured gates: pay for changed content

Independent plan, measured-gates-plan-astra, 2026-10-15. All phases proposed.

`seon.test/run` already measures bodies, records ordinary assertion results, and reuses evidence by reach and input content. Derive schema and function checks into that same runner; judge their recorded work against an explicit cost law. Replace generator-construction booleans and traffic-relative performance judgments, not the runner.

## One check, one observation

Derive test declarations lazily through the existing program writer: schema checks when Design requests evidence, authored successor tests in Prove, function checks in Implement. Incomplete stubs do not acquire failing derived tests during Design. Identity derives from subject/check kind through `seon.id`; the body calls one contracted function in `seon.test.accretion`. No authored file per schema or second runner. Authored deftests include bounded `clojure.test.check/quick-check` properties where a law exists; repeating a zero-argument deftest is not generative.

For schemas, hold the branch's compiled registry; obtain `malli.generator/generator` and `malli.core/validator` once, generate N bounded values and assert each validates. Retain failure data and seed/size. For functions, use `malli.generator/function-checker` on each `:=>` through its native multi-arity support: generated arguments, actual call, output validation. Nil means success. Behavioral proofs still establish semantics beyond output shape.

**Library prerequisite:** Malli pin `dd13ff81139159778edb0a67b491eccc0baa991d` calls `quick-check` with only iterations and property; seed, maximum size and shrink limits are not forwarded. `malli.generator/check` also drops its supplied options when arranging the checker. Fix forwarding at Malli's owner in root's scheduled fork batch; never clone the checker. Bound shrinking and include its work and diagnostic reapplication in the observation; the failure path can cost more than N calls.

All three kinds use `seon.test/measured-body` → `seon.test.runner/complete-members`. Extend the existing member value with the named observation shape needed for setup, generation, validation and execution measurements; the schema renderer follows the derived test identity instead of copying cost onto program entities. Retain subject, executed digests, seed/size/trials, work units, evaluator, allocation, calls, elapsed time, scope and failures for the runner, stage proofs, done rule and reply.

Extend `seon.test.runner/reach-digests` with the check body, declaration, transitive named schemas, predicate/generator definitions, and harness inputs. Use the existing reuse identity `[test-symbol reach-digest input-digest evaluator]`; sampling policy is an input. Identical content across agents shares `seon.cache`; unrelated writes do not rerun anything. Changing only a cost coefficient rejudges the same observation, without executing it. Changed generators, supplied resources or executable content require new evidence. Interpreted and compiled execution never share a cost judgment.

Function arguments naming connections, contexts or external effects must come from the runner's canonical fixtures and explicit injected inputs, under the same named contracts. An arbitrary object is not a generator for a live resource. Missing generation/fixture support is red at its producer, never skipped. Census determines support; arbitrary external calls are not test fixtures.

## Cost is part of the proof

| Work on a content miss | Proportional to | Frequency and cost owner |
|---|---|---|
| Compile generator and validator | Reached schema/predicate graph | Once per compiled content and generator options; retain Malli objects, measure setup separately |
| Schema check | N × generation plus validation of bounded values | Once per check identity; stream samples, retain only failure; no census during an ordinary eval |
| Function check | A arities × N × (generation + call + output validation), plus bounded shrinking | Once per check identity; ordinary member owns the complete measurement |
| Authored deftest | Its explicit fixture and asserted work | Once per current identity; property trials belong inside that body |
| Lookup/judgment | Selected checks and their reached inputs | Existing runner selection; constant arithmetic per observation, zero bodies on reuse |

Observed here: 20 small-map samples generate in 0.38–1.21 ms / about 409 KB; validation costs 0.01–0.02 ms / 1.44–1.60 KB. The enclosing request costs 139.2 ms / 128.9 MB on its step. These illustrate overhead, not universal coefficients. Acquire once per check, run N inside it, record in the ordinary transaction; no second cost-test run.

**Gate on attributed allocation and meaningful call/work counts.** Use the body's thread allocation and its own sink; `seon.profile/measure`'s call totals and JVM window include concurrent work and cannot gate a member. Allocation detects uninstrumented library work; calls alone miss it. Neither is exact across cold caches, JIT behavior or evaluator changes. Measure setup and steady execution separately for reusable compiled generators; an arbitrary effectful test is not warmed by silently running it twice. Calibrate comparable complete fixture runs, including setup, for those tests.

The designer specifies the necessary work law in the proof: for example fixed setup + N bounded samples, or candidate count × edit-distance cell count. Config dials supply measured coefficients and justified tolerance for that law and evaluator, not a percentage of the candidate's own measured cost. Ship coefficients from census/representative reference measurements and their spread, with evidence; do not invent universal milliseconds per schema or infer algorithmic complexity from `:=>`. A valid quadratic operation needs its own law; tenfold excess is wrong work, never a baseline to learn. Unknown coefficients or missing attribution are unknown, never a performance pass.

An excess is an ordinary failed assertion carrying measure, observed value, expected bound, work units and the member's instrumented top functions. `seon.profile/explain-slow` is absent; reuse `seon.batch/top` and stored member evidence, not its retired JVM-wide snapshots. Calls/top identify candidates, not causal allocation attribution. Wall time remains feedback and the execution deadline; replace both hard-coded 5000-ms defaults with one configuration dial, preserving declared-long reasons and actual-exit ownership. CPU-bound work with few allocations/calls needs an explicit work-count proof or a controlled CPU experiment; this plan does not pretend these counters detect every slow algorithm. CPU and wall observations alone do not become flaky red tests.

“Once per content” means reuse every available content-valid outcome, including a deterministic red; no automatic retries. Bounded-cache eviction and lost retained evidence can require execution again. Current `seon.test/carried-results` scans other branches on a cache miss, contrary to the current owner ruling. Replace that discovery at its owner with shared immutable cached observations and this branch's recorded evidence; root explicitly carries needed evidence with branch advancement. No new cross-branch reader or permanent second result store.

## Stage exits and the reply

Amend TASK-CHAIN §2.4 and §4 in the implementation commit. `seon.cluster.source/done-refusals` remains the single judge of recorded results and runs no test. Its judged value carries the selected derived checks and cost judgments: Design requires the changed/referenced schemas' checks green and within their law; Prove requires successor proofs executed red for the intended behavior and within cost, with expected failure data asserted by the stage proof; Implement requires proofs and derived function checks green within cost. ## Phases and red proofs

Proposed proofs below must run red first through the existing entrance. Each phase commits its consumers and leaves HEAD booting.

1. **Census first (docs/probe; own-agent SCI, read-only).** Enumerate the packaged keys once, reuse the handed registry, and submit bounded per-schema forms through the existing REPL boundary: construction, `mg/generate`, validation and cost. Report complete success/failure counts, generator failure classes, cold/setup versus reused cost, and fixture gaps. No catch-and-hide loop. Proposed `seon.test.accretion-test/a-schema-check-records-generation-failure-and-invalid-samples`: a constructed generator returning `"wrong"` for `:int` must produce a failed validation report, not true generatability. Calibrate before choosing N, size or coefficients.
2. **Reproducible library check (host-bound, root fork batch).** Proposed `malli.generator-test/function-checker-forwards-check-options`: two checks with fixed seed produce identical argument traces; declared trial, size and shrink limits reach `quick-check`. Verify failure reapplication and multi-arity behavior. Ship no Seon checker copy.
3. **Derived checks and content reuse (host-bound runner/schema publication).** Phase 1's proof plus proposed `seon.test.accretion-test/derived-checks-reuse-their-reached-content`: schema, function and authored test record ordinary members; another agent with identical content executes zero bodies; changed referenced predicate reruns only affected checks. Include an effectful fixture case, stale evidence and cache-miss ownership. Delete generator booleans and their consumers together.
4. **Measured assertions and dials (host-bound accounting/config).** Proposed `seon.test-cost-test/a-work-budget-judges-the-members-own-observation`: changing a coefficient changes the result without another body; excess carries numbers; unrelated concurrent calls cannot change the judgment; evaluator and missing-attribution cases stay distinct. Replace both timeout literals and delete the dead auto-check dial and its test writes.
5. **Stage consumption (REPL-first predicates; host-bound if done-rule schema changes).** Extend `seon.step.design-test/handoff` and `seon.step.prove-test/handoff`; proposed `seon.cluster.source-test/stage-completion-consumes-measured-checks` proves missing schema evidence, unintended red, slow proof and slow implementation cannot complete; matching evidence does. Amend the owning spec in this slice.
6. **Compact presentation (REPL-first renderer).** Proposed `seon.request-cost-test/a-cost-summary-retains-queryable-detail`: small returned render data links to the unchanged full observation and exact failures. Delete inline verbose presentation; retain accounting. Measure the complete same eval before/after.

Retire FEEDBACK-LOOP's separate schema-cost writer proposal in favor of member evidence. Delete `:seon.config.test/auto-check-cases`, the boolean-only corpus test and orphaned generatability production when their last readers convert. Preserve historical error renders that still read stored data. Never restore COST-REG's assignment baseline runs, history ratios or acceptance exemptions.

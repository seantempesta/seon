# Own writes over the loaded program — Astra independent plan

Authority: [branch-model-rulings](branch-model-rulings.md), rulings 1–6. Existing flow: branch facts → overlay and declaration readers → SCI execution → reach identity → recorded result. Replace three-way selection with one held value: loaded declarations plus the branch's own declaration writes. No rebase, copied database, or second evaluator. Status: proposed; no implementation phases complete.

## Definition and the cost prerequisite

`seon.cluster.registry/own-delta` owns the branch/base decision; `seon.db` owns its Datahike read. Proposed schema `:seon.cluster.registry/own-delta` is `[:map-of :seon.program/declaration-identity :seon.program/digest-or-absence]`. These member schemas already exist; absence is the existing `:seon.program/absent` value in this derived map, never a stored tombstone. Consumers: acquisition, program reads, schema projection, test identity, and next round's merge candidate selection.

For held branch value B and its retained base on B's ancestry, let t be that base's transaction. Read `(seon.db/since (seon.db/history B) t)`: strictly later transactions **present in B's history**, not all store transactions with larger numbers. Select assertions and retractions of declaration digests; recover each affected declaration's identity from its historical entity, then read its final digest in B, or absence. Use declared program families, including defs represented as function declarations; runtime facts are not program. A change back to the original definition remains owned; add-then-delete remains an owned absence; an idempotent assertion producing no datom creates no ownership. An unmap therefore cannot resurrect the loaded Var. Required histories must remain retained.

Nested forks toward the same main inherit the parent's retained base and its already-written delta, plus the child's writes; they do not include subsequent parent writes. This is installed `seon.cluster.registry/branch-fork-entity`/`fork!` semantics. A fork explicitly targeting its parent has a different merge base; execution still composes the inherited program delta toward the loaded program. Keep immediate merge ancestry and effective program ancestry distinct, deriving the latter through fork facts once at acquisition. Do not mistake child creation for an empty effective delta. A chain's base stays fixed until its terminal merge; no new lifecycle is needed.

**The `since` expression specifies the answer, not its complexity.** At Datahike pin `62f94893faf929c9ee37f4188dd88983495c960a`, `datahike.api.impl/since` constructs `SinceDB`; `datahike.db/post-process-datoms` filters temporal index results. `datahike.index.persistent-set/index-type->kwseq` has EAVT/AEVT/AVET, no transaction-leading range. `seon.program/declaration-changed-identities` explicitly walks digest history; `seon.db/entities-changed-after` still scans the attribute range. Neither delivers cold O(branch writes). This repeats the existing [since-scan issue](../../../seon/issues/system-plan-scans-since-views-for-read-evidence-changes-on-every-open.md).

Recommendation: make a transaction-range temporal read efficient **in Datahike**, preserving `since`/`history`, with a transaction-leading retained index supporting assertions and retractions. This is a prerequisite requiring a dependency-owner design and root's scheduled fork bump, not permission for a Seon journal or listener-maintained mirror. Target O(log H + W) to obtain W post-base datoms from history H, plus identity seeks and final reads for D touched declarations; extra index storage/write cost must be measured. A cached AEVT scan is the smaller implementation, but its cold O(H_digest) cost does not satisfy ruling 1. Do not label it complete.

Reuse the delta in `seon.cache` by store identity, fork/base identity, and `seon.db/content-revisions` of declaration identity/digest attributes (including the conservative revision). Result/evaluation writes preserve that key. Carry the obtained delta through the request; never rebuild its key per declaration. As-of program inspection includes its fixed transaction bound; speculative requests fold their actual transaction report onto the held delta. After a program write, advance from a retained ancestor's report/range when available; reconstruction after eviction uses the same temporal read. Semantic cache keys downstream use the delta's identity/digest content, not branch ids or transaction numbers.

## One selection for execution, reads, and identity

Hold an explicit program-view value: B, the delta, and L, the successfully loaded commit. Obtain L once through `seon.sci.eval/loaded-source`/`loaded-database` and the acquisition snapshot's loaded commit; never through the branch's inherited publication fact. L's declarations and loaded Var digests agree. Main advancing without reload changes **no inherited program answer**: execution, source and reach still use L. After successful reload, acquire the new L. Config is deliberately different below.

One selection operation in `seon.cluster.registry` consumes that held view: owned identity → B's declaration/explicit absence; otherwise → L's declaration. Discover identities through this selection too: checking the branch's AVET first misses newly loaded names. Pull refs and namespace bindings from the selected declaration's own database, then resolve referenced program names through the same view; numeric eids are not portable across sides. Retain ordinary branch reads for tasks, evaluations and other runtime data.

| Existing reader | Replacement and proportional work |
|---|---|
| `seon.sci.eval/derive-overlay-plan`, `overlay-plan` | Walk D own entries, compare only these with loaded digests, traverse their reverse call closure A using loaded edges with owned edges replaced. Cache by loaded program content and delta content. No `authored-rows` population scan or missing-function census. |
| `seon.sci.eval/install-function-from-database!`, `promote-member!`, `lazy-root` | Install selected source, including L's source for an affected caller. Preserve lazy interpretation: only called members incur source/analysis cost. Lazy roots retain the selected immutable basis/identity and reopen through executing custody, not an undifferentiated branch commit. Host-bound code keeps the loaded compiled Var; staged host changes require platform proof. |
| `seon.sci.lookup/function-documentation`; `my.program/declaration-source` | One identity lookup and selected pull, O(shown declaration). Contract compilation uses L plus owned schemas/predicates. Convert `directory-value`, namespace documentation, `stored-source` and schema-source reads too; an owned absence must not fall through to host metadata/source. |
| `seon.ref/brief`, `resolve-name`, identity discovery, schema documentation | Same selection, including nested references; O(requested references and shown data), no per-reference store-head read. |
| `seon.context/current-state`, `must-reads`, `attempt-start` | Keep the attempt basis for task input/history; resolve its program references against the current program view. Cache rendered references by selected content/read evidence. An attempt-start AsOfDB must not freeze current code. |
| `seon.test.runner/reach-entries`, `reach-digests`, reach graph/memberships | Overlay owned nodes and edges on L, including schema/predicate dependencies. Reuse loaded components only outside A; a loaded caller reaching an overridden callee cannot be a sealed loaded digest. Recompute changed nodes and their reverse closure, then only requested reachable components. |
| `seon.test.runner/executed-roots`, recorder, `current-results` | Compare observed execution against that same captured program view; record and request the same content identity, including dynamic calls and task input. Keep result facts on B. Existing result lookup still costs historical members of requested tests and distinct dynamic-call sets; this round does not make that scan constant-time. |

Share loaded indexes by store plus loaded commit/content. Persistent map updates share unchanged nodes; do not copy the whole loaded map per branch. Reach identity excludes branch/eid/base stamps. Thus a test with the same effective closure and inputs on branch and merge candidate has the same identity. If main has an **unloaded** change in that closure, its candidate is a different program and legitimately needs new evidence; do not manufacture equality. Next round alone chooses the proof reach closure from own-delta and reuses matching results (rulings 5–6).

## Config and the checked writer

`seon.config/effective` and `agent-cluster-dial` read branch-written **coordinates**, not the whole inherited config entity: own assertion/retraction wins, otherwise main's HEAD. Derive those coordinates from branch history with the same ancestry rule, scoped to schema-declared config attributes; key by their revisions plus main's config revisions and declaration content, not every main commit. One dial read is indexed; a whole effective map costs its declared dial count. Explicit optional retraction remains absence, never inherited main's value. Keep task/agent explicit settings as overrides; creation must not copy effective defaults into settings and thereby freeze them. `seon.turn/max-episode-runs`, `turns-left` and turn admission use this owner at each decision, so applying a cap reaches the next running-agent decision without rebuilding its graph.

`seon.turn.batch/write-entity` already reads `seon.sci.kernel/context-bound-projection`; final `seon.db/validate-write-report` instead chooses `speculative-report-projection`/`carried-projection`. Pass the request's SCI context and bound predicate Vars explicitly through the existing writer callback. Derive the final declarations with those bindings **before compilation**, using `seon.schema/projection-with-declarations`, and execute both admission and entity validation under that same `sci.ctx-store/with-ctx`. Do not merely bind the caller thread or stamp a context-dependent projection onto shared database metadata. The writer remains compiled; predicates follow the branch. Reuse the base projection's existing bindings-keyed holder; retain Malli's `malli.core/-fn-schema` Var invocation and `malli.core/validator` cache. Work follows changed declarations, predicate bindings, their schema referrers and armed dependents; the installed rebound scan is O(population forms) on a binding transition, not zero, and is measured before proposing another index.

## Phases, deletions and proof

Each phase leaves HEAD loadable; new names below are proposed deftests, not recorded reds. Each implementation lane first records the red on its parent. No lifecycle change; amend TASK-CHAIN if implementation discovers one.

1. **Datahike prerequisite + own-delta (host-bound, scheduled bump).** New `seon.cluster.registry-test/a-branch-program-is-its-own-writes`: table asserts exact identity→digest/absence for add, replace, return-to-base, delete, nested fork, main-only change and runtime-only write. New `seon.sci.acquisition-cost-test/own-delta-work-follows-branch-writes`: equal post-base edits under growing inherited histories visit equal changed datoms; repeated requests and result-only transactions derive delta zero times. Measure cold/repeated request CPU, allocation and elapsed cost parent/change; index backfill/publication must also be proven on a live-store branch.
2. **Acquisition and all program readers (host-bound).** New `seon.sci.eval-test/one-context-reads-and-runs-one-program`: assert returned values, source/contract data, references and selected identities agree for owned/untouched/deleted declarations, changed affected callers, main-before-reload and main-after-reload. Include schema and attempt-start rows. Convert reader consumers atomically; remove their old route in this commit.
3. **Reach and recording (host-bound runner).** New `seon.test.reach-test/a-branch-and-its-effective-program-share-result-identity`: assert equal reach/input identity on independently constructed L+delta, a nonempty recorded digest, and second execution count zero. Cases include an unchanged caller of an owned callee, owned schema predicate, dynamic call and unrelated main edit. Convert `seon.test.reach-test/a-work-branch-result-is-not-current-after-main-changes-what-it-reaches` and `seon.test.reach-test/a-work-branch-result-that-ran-what-main-moved-past-is-recorded-at-its-identity`; remove the moved-reach mechanism.
4. **Config (host-bound configuration/turn path).** New `seon.config-test/a-running-agent-reads-main-config-unless-it-wrote-an-override`: assert turns-left/admission reflect main's new cap, explicit own cap wins, optional retraction stays absent, siblings remain independent. No graph restart.
5. **Writer (host-bound).** Existing `seon.turn.batch-test/a-contract-naming-a-predicate-defined-on-the-branch-is-admitted-and-armed` proves task `seon.schema/a-contract-naming-a-branch-predicate-is-refused-at-the-writer` (the latter is a task, not a deftest). Assert stored authored contract, accepted result 2, rejected odd input and unchanged facts on refusal; add sibling and named-attribute validation rows through the final writer. Keep predicate transition tests green.

All five use `bin/lane commit --test` with named reaching vars; no honest REPL-first classification for evaluator, runner, writer, config or schema publication. SCI probes still precede files. Measure the whole block/eval/test-recording loop, not only helper calls. Ruling 8's `ns-unmap!` argument-shape change remains a separate slice; this plan changes deletion reads, not that interface.

Delete registry `seen-database`, `moved-past`, `merge-sides`, `identity-digests`, `commit-digests`, `main-changed`, `side-commits`, `moved-identities`, their two cache kinds; runner `moved-reach`, `moved-changed`, `seen-digests`, moved maps/keys; overlay side keys and obsolete scans. Keep `fork-of`, base retention and `seon.program/three-way`: merge still needs them. Replace the five eval tests named `a-work-branch-interprets-only-what-main-has-not-moved-past`, `a-work-branch-documents-what-main-moved-past-as-main-holds-it`, `every-view-of-a-work-branch-sees-what-main-moved-past`, `a-work-branch-reads-what-main-moved-past-once-per-commit-pair`, `a-work-branch-as-of-view-reads-its-own-digest-by-index-probe`; retain their useful behavior cases in phases 1–2. Keep the independent uncompilable-contract documentation test. Estimate: Seon production −100 to −250 lines net after replacing roughly 250–350 obsolete lines; tests approximately neutral. Datahike index work is separately sized, not hidden in that estimate.

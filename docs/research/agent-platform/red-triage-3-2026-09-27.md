## Platform defects first

These are wrong values, lost runs or wrong-world reads, and each is confirmed at the REPL or from recorded evidence.

1. **The floor silently drops members of a counted seq.** This is a wrong value shown to agents and has no cut marker.
   A probe on default with the value-test profile (max-children 3) rendered these:
   - `'(0 0 0 0)` rendered as `"(0 0 0)"`.
   - `(list 1 2 3 4)` rendered as `"(1 2 3)"`.
   - `(range 5)` rendered as `"(0 1 2)"`.
   - `(seq [1 2 3 4 5])` rendered as `"(1 2 3)"`.

   Vectors (`[0 0 0 …1 (drop 3 …)]`), sets and lazy seqs (`(1 2 3 …? …)`) are cut correctly.
   - **Owner:** `seon.render.value/list-row` and `more?` (src/seon/render/value.clj:461-470, 651-657).
   - **Cause:** `seq-cells` keeps only `limit` members. `list-row` then records `:total (count x)` for a Counted seq without
     `:pending?`. `more?` for `:coll` asks only `:pending?` or `(seq (:pending node))`, so the node ends with no cut.
   - **Introduced by** dcbd0be4d (09-25 21:02, "every ISeq … prints as a list"). The shrunk counterexample of
     value-test `generated-values…` is exactly `(0 0 0 0)`.
2. **An NPE in a turn step loses a whole agent run.** Open fault signature `8f6fdfc0…` records
   `Cannot invoke "java.util.concurrent.Future.get()" because "fut" is null`, raised at
   `seon.sci.eval/install-function-contract!` (eval.clj:1343-1359, `@sci-var` where `(sci/resolve ctx sym)` is nil). The
   operation is `seon.cluster.agent/turn-step` and the layer is `:seon.flow/proc`.
   - **Occurrences:** 02:23:54, 02:25:01, 02:51:57 and 03:05:12 UTC. Each lines up with a stored host-test or
     evaluate-source-test run.
   - **Effect:** the run's reply channel closes, so the caller gets `seon.await/diagnostic` ("awaited channel closed
     before completion") or a result without `:seon.db/db`. It does not get the value beside a diagnostic, which the
     total-path law requires.
   - **Reds explained:** host-test `a-run-reads-its-earlier-declarations` (all four assertions) and evaluate-source
     `code-evaluates-…` (the `run-receipts … db nil` error).
   - **Unconfirmed:** why the Var is absent. The most likely path is that the gate refuses the run's third form (a
     breaking redefinition). The refusal arm then `ns-unmap`s `run-square` in the context (eval.clj:1845-1848), and the
     evaluated first row's `install-function-contract!` resolves nil.
3. **`get_value` pages report `beyond-end? false` past the end.** This is wrong page metadata for MCP agents. A probe on
   a stored 4,975-char string at offsets 0, 4974, 4975 and 9000 shows:
   - Only offset 0 carries `:seon.render.data/total`.
   - Every uncut page has no total and no next-offset.
   - `beyond-end?` is false at offsets 4975 and 9000.

   The owner is `seon.cluster/mcp-get-value` (cluster.clj:544-555), which derives `total` only from the page tree or its
   cut, and an uncut page carries neither. The page adapter arrived with 97f4d1f90 (09-25 19:37). This explains mcp-test
   line 428.
4. **A test body's supplied database is the member's value from the start of the body, not the world the body works
   in.** a0f795375's `seon.test/member-world` scopes `(db/db connection)` once at the body's start. That has two effects:
   - A `with-database` body, which works on its own branch under custody, has the member's database supplied to any call
     that omits one.
   - The member's own later writes are not in that value either.

   **Observed:** error-test line 155 calls `(error/render-html row)` with no database and expects "Resolution unknown".
   The HTML printed "Open", so a database was supplied, and it could not have held the fixture's signature. This is a
   wrong-world default in tests only. It reads nothing false in production, but it makes a test pass or fail against a
   world it did not name.
5. **Slowness and hygiene seen in passing** (not reds):
   - `runtime_status` reports `seon.schedule/invoke-handler` at 389,885 ms (×1), with `fire-due!` and `schedule-step`
     at about 390 s inclusive.
   - fn-test `indexing-uses-a-prebuilt-manifest…` builds a whole-checkout manifest in a test (20.3 s against its 5 s
     bound).
   - fn-test uses `with-redefs` in two reds (`indexing-resolves…`, `indexing-uses-a-prebuilt…`).
   - mcp-test fixtures `swap!` the JVM-global `running-instances`.

   All of these break AGENTS "Run tests as agents run".
6. **Ugly output.** The runner's report for value-test `a-reference-prints…` renders the assertion's own form through
   attribute renderers. The quoted symbol `eid` under `:seon.turn/agent` produced a spurious
   `referent-identity refused eid … got a symbol` diagnostic in the expected form (runner shown-unit path, a7da37645).

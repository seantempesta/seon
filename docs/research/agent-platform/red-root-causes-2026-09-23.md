# Red root causes: finish the cuts, repair the authorities

The system already owns declaration construction, branch acquisition, contracts and storage. The smallest improvement is to make tests enter those owners with explicit inputs, and remove superseded mechanisms in the ordered cuts—not reconstruct their guarantees independently in fixtures.

**The dominant failure is incomplete caller conversion after an authority changes.** A branch replaced an empty fixture, analyzed declarations replaced minimal maps, symbols replaced string identities, and acquired database values replaced raw reads. Old callers continued describing the old world. Stronger contracts then exposed those disagreements, often before the behavior named by the test ran. Fixing downstream assertions would conceal the useful signal.

**Decision:** prioritize canonical fixture admission, explicit cluster scope, honest contract/refusal reporting and execution evidence. Continue the ordered cuts; do not make all 92 historical red identities green first. Only two identities clearly contain obsolete machinery assertions. Most of this particular sample covers surviving behavior, unlike the much broader legacy runner census in B4. No evidence supports claiming that all—or most—of these reds vanish merely by deleting the planned mechanisms.

### R1 — fixture literals are a second declaration producer

Mechanism: handwritten namespace/test/agent/config rows bypass the *construction* owner, even when they subsequently use the validating database writer. It is inaccurate to say all bypass validation: many reds are the writer correctly refusing them. Others discard the returned refusal and create cascades. Required branch/digest/partition accretions reveal every duplicated producer independently.

Evidence: `test/seon/ai_test.clj:605`, `test/seon/background_test.clj:21`, `test/seon/blob_test.clj:38`, `test/seon/bootstrap_test.clj:181`, `test/seon/call_preparation_test.clj:182` at the constructor report's `d49b574be` boundary; additional declaration/identity failures at `error-constructor-reds-2026-09-23.md:339`, `:347`, `:353`. Raw examples are `proof-errcons.txt:5`, `:13`, `:36`; `p-seon.error-test.txt:23`; `proof-1600.txt:75`. The context-selection setup continues after missing `:db-after` (`proof-1600.txt:158`), manufacturing many apparent ordering/selection failures from one absent agent.

**One owner-level correction:** canonical fixture construction and mandatory refusal-checking admission in `seon.test-support`. Reuse `program-fn-row`, the analyzed namespace producer, cluster/config writers and `seon.cluster.agent/creation-tx`; `transacted!` already stops a failed setup (`test/seon/test_support.clj:215`, `:690`, `:697` at baseline). Convert repeat callers once by script; never sprinkle placeholder digests/branches into literals. Add the enforcement to the existing analyzer/lint path: ordinary fixture seed writes must use the canonical admission helper; synthetic declarations belong to explicitly designated declaration tests. This is a **proposed enforcement**, not a claim that origin/fidelity of arbitrary maps is currently mechanically detectable. Writer validity alone cannot prove canonical provenance.

Regression: on a branch containing a real program, construct the supported entity families through their owners, adopt a valid schema accretion incrementally, and show the same constructors still produce admitted rows; a refused seed prevents the subject body from running. Retain one class regression rather than dozens of literal-shape copies. B4 c1 already changed the fixture; B4 c4–6 does not fix missing digests, owned components or symbols. This class survives every planned cut unless the producer/caller rule is enforced.

## Where long-term value is

1. **Now: stop manufacturing bad worlds.** R1/R2 account for **40 identities**. Enforce canonical seed admission and explicit cluster identities in the existing fixture/analyzer owners, then perform one scripted caller conversion. This prevents the next schema accretion or inherited fact from producing another cross-namespace fire. Do not patch 40 fixture literals independently.
2. **Now: protect feedback and fault truth.** Repair contract-refusal normalization and runner context capture at their owners; preserve actual termination and immutable execution evidence. A diagnostic that fails while explaining an invalid value, or a reporter that hides the original failure, makes all later work less reliable. Implement through the relevant reviewed A1/B4 slice, not a new error handler beside it.
3. **Now, at small surviving seams:** cluster-scoped configuration, backend callback contract, value-semantic observation declarations and declaration-time predicate explanations. Keep one regression for each class. These are useful to namespace agents and will survive the refactor. The observations/retirement rule belongs to incremental schema admission; never loosen native identity validation or rebuild from zero to accommodate it.
4. **With their cuts:** source custody with B1; obsolete census with A1; cancelled backstop with B2; fixed definition-time gate with D1; plan-specific subjects with B3. Preserve cleanup, caller-wins, diagnostics and durable history while deleting their superseded mechanism. R3's small cold-read helper correction may land earlier when needed for platform proof; it must not resurrect ambient fallback.
5. **Leave unlocalized duration reds recorded, not excused.** Do not make the constructor cut own every slow fixture, assume unchanged source means unchanged cost, or spend days restoring an implementation due for deletion. Finish the named request-path cuts and measure their surviving boundaries once. Continue namespace-agent work within the ruled dependencies.

The four AGENTS habits explain the pattern: **fetching instead of holding** produces R3 and repeated derivation; **silence as health** turns refused setup/unfinished work into misleading downstream evidence; **fixing the site instead of the owner** multiplies fixture constructors and diagnostic patches; **retiring without converting** leaves R1/R2/R4 callers in the old world. The lasting intervention is one authoritative producer/entry with all callers converted and its behavior regression—not a broader suite, another registry or more tolerant contracts.

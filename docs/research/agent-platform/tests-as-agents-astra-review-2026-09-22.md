## 1. Yes: simplify B4, but do not delete the isolation guarantee

**Do not implement B4's request pipeline as a second execution platform.** The ruling is smaller: acquire a candidate through the agent owners, publish into it, select tests, invoke them through the agent evaluator, record their evidence, release it. The plan moves B4 forward without moving all of its behavioral prerequisites: `README:182` promises in-process lane testing; `README:186` puts candidate acquisition later; `README:190` leaves B2 context work in cut 4. The explicit one-mechanism ruling at `README:364` must control that order.

This is the exact accretion pattern in `AGENTS.md:88`: missing carried inputs cause reconstruction; caller fixes become a second owner; old machinery survives retirement. However, “branch + SCI fork” does not replace the guarantees that motivated every surrounding check. The distinction is execution ownership versus selection/evidence policy (`README:97`, `README:102`, `README:110`).

B4 actually numbers **13 rows**, including tally, at `B4:80`; §6 has seven table rows grouping more than seven keys, and its illustrated union has eleven alternatives including success (`B4:309`). None of those counts is the architectural defect.

**Host classification stays, host machinery goes.** A2's branch guarantee expressly excludes blobs, roster, GC, flock, classes and globals (`A2:118`). Do not require retained historical database materialization for every reuse check: GC may remove it; absent history means execute/refuse unless sufficient retained signatures prove equivalence.

**B2's five steps are substantially necessary, not a runner feature** (`B2:119`):

1. Keep definition/resolver/private-override and contract differences as seeds (`B2:121`). Otherwise copied callers bypass context contracts.
2. Keep their reverse executable closure (`B2:122`). A compiled caller still calls JVM callees.
3. Keep interpreted installation plus context contracts and named refusal when unsupported (`B2:123`, `B2:127`). Delete JVM fallback for an affected row.
4. Keep change-driven maintenance (`B2:124`); delete whole-program scanning on every call or ordinary transaction. It is an update to acquisition, not another invalidation registry.
5. Keep protection against shared reload (`B2:125`), **but replace the sentence accepting an in-flight reload tear**. Recording that the wrong program ran does not satisfy `README:61` or `B4:168`. Boundary refresh protects the *next* evaluation, not a compiled call already in flight. The remaining owner decision is below.

Correct the misleading “1 row” cost at `B2:110`: finding/installing an override may cost its affected closure, as the same section explicitly measures at `B2:122`. Neither branch creation nor raw SCI fork timing prices this work.

## 3. Lane edits: facts can target a branch; execution cannot yet promise isolation

**Not possible end to end today through the named publication API.** Three separate answers matter:

* **Indexing: yes, with its real inputs.** `seon.fn/index!` receives `:seon.db/connection` and `:seon.source/previous-database` (`src/seon/fn.clj:3305`, `:3322`). An already populated branch needs that previous database; otherwise it refuses (`:3361`). Incremental reconciliation also requires its manifest/input evidence (`:3370`). Do not interpret “accepts a connection” as “index any namespace with an incomplete map.”
* **Publishing: not to an arbitrary candidate today.** `refresh-source!` says “one current-src” and optionally invokes development adoption (`src/seon/cluster.clj:2171`, `:2220`). `source/publish!` reads `current store`, creates a scratch branch, and finally force-publishes to `current-branch` (`src/seon/cluster/source.clj:371`, `:397`, `:460`). Its expected commit chooses a basis/guard, not a different destination. Extend THIS publisher with an explicit destination and expected head; keep scratch validation and writer-side comparison. A candidate request must not call the JVM reload arm (`cluster.clj:1981`).
* **Loaded behavior: B2 §2a is not implemented in the examined acquisition.** `base-ctx` explicitly copies core JVM roots (`src/seon/sci/eval.clj:2150`). `install-row!` chooses JVM execution from `:core` provenance and falls back to the JVM after interpreted failure (`:893`, `:909`); it does not select `overridden ∪ affected`. `acquire!` loads core namespaces (`:2210`), and that loader can `require` missing names from the shared classpath (`:1190`, `:1272`). Tests' stored forms can be interpreted (`:929`), but their compiled callees may still be wrong.

The reported **15 of 109 host-defining namespaces** is a historical planning census, not a freshly measured allowlist (`B2:127`, `README:357`). It means some forms depend on JVM classes/protocols/macros or other host facilities. It does not mean “the other 94 are proven isolated,” “all 15 are forbidden,” or “refusals are rare” for core edits. An ordinary function in such a namespace may interpret; a seemingly simple edit may reach an unsupported caller outside it. The unit is the actual affected closure, with a named refusal, as already ruled.

Shortest path: land B2 §2a **steps 1–3 plus change handling in step 4**, destination-aware publication, and the minimal D1 §2a branch handle before claiming `README:182`'s lane-edit behavior. Resolve step 5 before concurrent shared adoption. The rest of B2's turn/history/render rewrite and D1's task/merge/export workflow need not move forward. A test needs no wake loop, provider request, inherited-agent recovery or full cluster startup (`D1:79`, `D1:85`).

Input custody matters too: a “lane namespace” read from a shared dirty checkout can include somebody else's edits. Publication must receive the exact admitted source inputs and resolver context, and its ordinary changed-input checks must still hold. Branch isolation does not select file ownership. Do not replace the publisher's input authority with a second test snapshot/indexer (`README:93`, `B4:112`, `src/seon/cluster.clj:2210`).

## 4. Retirement: unlink now; collect later

**Recommendation: after actual exit and durable recording, release the connection and call the existing `retire-branch!`; do not run GC per test.** “Delete immediately” and “leave unlinked for GC” are the same operation here. Datahike `delete-branch!` only removes the name from `:branches`; data remains accessible until GC (`reference-code/datahike/src/datahike/versioning.cljc:279`, `:316`). Do not delete store files or blob keys.

It refuses `:db`, absent branches, and active/opening/releasing connection entries (`versioning.cljc:285`, `:303`, `:306`). Opening reservations and release completion are authoritative in `reference-code/datahike/src/datahike/connections.cljc:11`, `:37`; releasing one of several references is not final release. The Seon lifecycle should translate these outcomes once; A2 already plans removal of redundant retirement pre-reads (`A2:192`). Do not swallow a failed cleanup as current publication scratch cleanup does (`src/seon/cluster/source.clj:241`). Keep an unexited body's branch owned and report it; retirement is not a timeout escape.

Leaving the branch **named but unused** is not retirement. GC roots every roster head regardless of its age; the cutoff limits following parent commits (`reference-code/datahike/src/datahike/gc.cljc:22`, `:41`, `:72`). The landed policy uses the largest captured configuration window anchored to the newest head; absent policy refuses (`src/seon/cluster/registry.clj:472`). There is no cleanup job or adoption hook (`README:366`). Thus “GC landed” is neither automatic collection nor permission to leak named branches.

The landing reports an armed 13-test/71-assertion retention pass and a synthetic 43.903 ms sweep, **not full adoption or heap proof** (`docs/prds/agent-platform/landing/lane-a2-storage-retention-2026-09-22.md:262`, `:282`, `:287`). Store-global blob reachability is composed into that existing collector (`src/seon/cluster/registry.clj:459`). Record required run/member content and comparison signatures on the durable authority *before* unlinking. A saved commit UUID alone does not retain its contents. If D1 still needs that exact commit for acceptance/export, retain its branch until acceptance/export releases it; otherwise GC may remove it (`B4:174`, `D1:83`).

## 5. Smallest design to implement

This is the replacement design, not a claim that these contracts are installed. An execution value carries the captured program identity/database/projection, branch connection, context/environment and owned resources. It is the candidate handle already required by `D1:79`, with no graphs armed for a test. A run owns a pinned starting branch until all member forks have been acquired/executed; each independent member starts from that same captured commit. Ordinary data writes update custody, not installed program rows (`B2:113`).

**One genuine decision remains: shared JVM reload while admitted work is running.** B2 currently acknowledges the tear (`B2:125`), while the execution guarantee rejects it (`B4:168`). Exactly three options, simplest first:

1. **Defer shared JVM reload until affected admitted execution has actually exited — recommended.** Candidate edits still publish/interpret immediately on their own branches. Guarantee: host code remains stable throughout each admitted execution, then B2 refreshes retained contexts before their next entry. Cost: extend the existing agent execution/adoption admission boundary and account for background host users; bounded refusal if safe drain cannot be established. Gives up immediate shared reload during active work. A test-only mutex is insufficient.
2. **Interpret every affected live path before allowing concurrent host reload.** Guarantee: context-owned code/contracts throughout, only for a closure proved free of mutable shared host dependencies. Cost: stronger closure/interop proof, potentially broad installation, and refusal of unsupported paths. Gives up compiled reuse for those paths; interpreting one caller alone is not a universal isolation proof.
3. **Use a separate platform host for changes requiring shared JVM mutation.** Guarantee: process isolation for host-defining/global changes while ordinary data-level tests remain on shared branch handles. Cost: retained platform startup and deliberate routing at the existing host owner. Gives up the shared-JVM ordinary-edit path for that explicitly classified work; it cannot be an automatic fallback for an unsupported ordinary candidate.

Review summary: B4 is too elaborate as an execution owner and scheduled too early. Move only the indispensable B2/D1 seams forward, generalize publication at its owner, keep honest selection/evidence/termination, and unlink branches after release with deferred existing GC.

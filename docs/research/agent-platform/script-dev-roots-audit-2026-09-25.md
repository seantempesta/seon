# Script and development roots: publish the program, retire the duplicate owners

Seon already analyzes file declarations into program rows, derives their contracts, and loads and arms JVM Vars; its BB commands separately load some of the same files. The principal composition is to publish those declarations through the existing indexer, preserve each process's execution ownership, and delete obsolete selectors, readers and printers before extending their reach.

**Recommend `seon.fn/source-roots = ["src" "test" "script"]`, with the retirements and loading corrections below.** Keep the useful BB tooling in place. Move the JVM-only diagnostic and the small set of real system namespaces into `src/`. Do not add `.` or all of `resources/`, invent a `dev/` root, or move 6.4k lines merely to satisfy a hard-coded prefix. Directory membership is not an execution or isolation policy.

The ranked ledger identifies **1,037 existing lines for retirement: 1,010 in `script/`, 27 in `src/`**. These are gross, nonoverlapping deletion candidates, not promised net savings. Caller changes, replacement adapters, contracts and tests must be priced in the implementation design. Pure relocations earn **zero** saving. The largest cut is the **663-line obsolete changed-test/cache-helper family**; MCP reader/render reconstruction is **145 lines**; the one-off schema splitter is **141 lines**; duplicate status presentation is **88 lines**.

## Findings and proof limits

1. **The hole is larger than a missing directory.** `seon.fn/source-roots` is `src` and `test` (`src/seon/fn.clj:35`); `source-file?` admits `.clj` and `.cljc` (`:67`). But `seon.cluster/published-program` independently selects namespace files beginning with `src/` (`src/seon/cluster.clj:2403`), and `seon.test.cache/graph-roots` independently repeats `src` and `test` (`src/seon/test/cache.clj:12`). Adding one vector element does not finish publication, loading, test selection or arming.
2. **“Never armed” needs qualification.** Script declarations are absent from the program roots and program namespace loader. Nevertheless, `seon.instrument/collect-contracts!` scans every loaded namespace (`src/seon/instrument.clj:815`), using Malli `mi/-schema`; `compiled-wrapper` has an authored-contract fallback (`:624`). Independently required script Vars therefore can already be armed. The reported 43 are evidence of that distinction, not a contradiction to explain away.
3. **The 43-Var census is inherited live evidence, not a new measurement.** The [derived-prerequisites landing](../../prds/agent-platform/landing/lane-impl-derived-prereqs-2026-09-25.md) reports 27 `seon.operator`, 12 `seon.dev.*`, three `dev-cache`, and one `seon.operator.runtime` Var armed without projection contracts. Its default probe also found 81 differing forms and 31 unloaded projection-only contracts. This audit did not repeat that probe. Adding `script/` addresses the locations of **39/43**, not the other four or contract equivalence.
4. **Source declarations exceed that census.** The script files contain **47 actual `:malli/schema` declarations**: operator 27, changed-test two, dependency-digest one, docstring four, harness-costs five, issues one, markdown six, MCP one. A literal text count returns 48 because `mcp.clj:488` contains an example in a comment. Neither count proves validity, load, arming or complete coverage of private functions. Many functions have no authored contract.
5. **Process custody is currently protected by exclusion.** `resources/seon/operator/runtime.clj:1-7` explicitly says that absence from the program graph prevents SCI installation. Its three atoms and delayed executor pair (`:11-22`) must not be recreated per branch. Merely moving this file would remove that protection. The per-declaration classifier (`src/seon/fn.clj:1012-1065`) is the owner to assess; it is not proof that plain `defonce` atoms already receive the necessary treatment.
6. **No `dev/` tree exists at this pin or in the inspected checkout.** There are **17 script files / 6,429 physical lines**, including **four files declaring tests / 827 lines** and **13 other files / 5,602 lines**. A suffix-only `_test.clj` inventory incorrectly counts the 380-line `changed_test.clj` helper as a fifth test file; classify declarations rather than names. The older duplicate-paths audit's 6,416 is a different revision: markdown and markdown-test have grown by seven and six lines. The extra root-level/resource files below are outside this denominator.

This assignment explicitly forbids code changes, tests and `bin/seon`. Only this report is changed. No JVM, BB program, test, linter, runtime-status call, publication or arming probe was executed. Runtime health, timing, memory, incremental cost and BB/JVM compatibility after the proposed changes are **unavailable evidence**, not passes. Concurrent changes to SCI/turn sources and tests were left untouched. Measurements and source citations below use **842e86f4f31ffeced586c14590061a6cd13212a2**; the audited script files and root/arming owners remained byte-identical to that pin during the audit.

## Root, runtime and contract changes

**Indexing BB-loaded code and keeping it BB-loadable are compatible.** The indexer reads/analyzes source and publishes declarations; `bin/seon`, `bin/mcp-server` and the hook decide where the commands execute. `bb.edn:1` and the launchers already provide `script`, `src` and `resources` to BB. Main JVM paths are `src` and `resources`, while `:test` adds `test`, `script` and `.`. These are different authorities for different operations; do not infer indexed membership from classpath presence.

The recommended root cut has these concrete responsibilities:

1. **Publish the retained `script/` declarations.** Change the existing source-root owner and reconcile `test.cache/graph-roots` with it rather than introducing a third roster. `cluster/source-roots` (`src/seon/cluster.clj:1800`) extends the function roots with `config/default.edn`; `publication-roots` (`:1805`) holds that input across reload. `cluster.source/discover-paths` (`:133`) also includes `test.cache/input-roots`: scripts may already affect gate digests without having program rows. Verify reclassification, changed identities and retirement against the same captured inputs. Do not widen gates because this documentation changed.
2. **Preserve suffix/language policy.** All 17 current files are `.clj`; no rename to `.cljc` is needed for BB. Existing `.cljc` files use the CLJ analysis face (`src/seon/fn/analyzer.clj:177,365`). A new `#?(:bb ...)` branch would need explicit proof that indexed JVM declarations and BB behavior still express the intended contracts. `.bb` and extensionless `bin/*` are currently not function source files; keep those executable launchers thin, with semantic producers in indexed `.clj` owners. Do not simply broaden suffixes without a reader/declaration contract.
3. **Separate publication from requiring namespaces.** Replace the `published-program` assumption that “src means load all, anything else means test” with the existing declaration and supported execution semantics. Test declarations remain request-loaded even under `script/`. A bridge's presence in the program must not launch a second MCP process or create a watchdog/session registry in a cluster. `mcp.clj` requires Cheshire, available to BB but not explicitly a main JVM dependency in `deps.edn`; blind JVM loading is not justified. Index bridge declarations and move JVM policy into existing src owners; prove the supported host/SCI cases by declaration and refuse unsupported overrides by name. Do not add a namespace allowlist that pretends every member has the same behavior.
4. **Close the extra four omissions.** Move `dev-cache` only with a verified tools.deps launch/classpath change. Move the runtime holder only when classified host declarations reuse the original compiled cells across branches. Its current placement is an actual custody mechanism, not untidy filing. The prepl move also needs a degraded-bootstrap check; the diagnostic move needs its manual entry retained. None requires adding all resource files or repository root to program roots. `fn/containing-root` (`:73-91`) walks containing directories, so an exact file path is not an established substitute for a program directory root; `cluster.source`'s snapshot support for file roots is a different seam.
5. **Produce contracts at the existing writer, not a metadata exception forever.** `fn/var-row` copies `:malli/schema` into a canonical declaration (`src/seon/fn.clj:777`); compile those declarations against the packaged projection, including referenced private schema values, and pull them back before changing arming authority. Malli's actual metadata seam is `malli.instrument/-schema` (`reference-code/malli/src/malli/instrument.clj:44-47`, gitlink **befcd302a8e626a67d84b80aabee0cd1b38dadb6**). Its fallback to arglist schemas is real; it does not establish a projection row. Catalogue every newly admitted private function lacking a contract and the reaching tests required for it. Directory inclusion alone supplies neither.
6. **Adopt and measure incrementally.** Publish rows, require/reload only appropriate existing JVM namespaces, arm from the accepted projection, record adoption, and compare actual armed symbols and contract forms before/after. Loaded symbols without a projection row must be a named unresolved set. First publication necessarily visits the added source, O(added declarations/dependencies); unchanged subsequent reads must reuse content-valid derivations. Cost must follow changed inputs, not scan all script files per evaluation. The cold and warm time, memory and cache-miss costs are unmeasured here.

There is no recommendation to merge markdown, docstring and citations into one “developer tools” owner. They have different inputs and reasons to change. Conversely, “runs in BB” is not a reason to preserve the obsolete changed-test evaluator/report pipeline. Keep process adapters small and indexed; keep domain execution in its current owner.

## What this unblocks, and what it does not

**MCP task migration.** The [task-slice-2 landing](../../prds/agent-platform/landing/lane-impl-task-slice2-2026-09-25.md) left the MCP record unimported; its prospective task handle is **`"bce01f35637e"`**, aspect **`[seon.dev.mcp "mcp-jvm-eval-drops-reader-metadata-on-a-defn-name" :function]`**, because producer `seon.dev.mcp/jvm-evaluation-form` had no program row. If S2 retires the producer first, move the task to the actual replacement producer in that same transaction rather than fabricating a function to carry it. The landing already reports successful metadata-preservation probes; migrating the record does not establish that the historical bug still exists. Retire the old issue input only after the migration proof.

**Derived-contract S2.** This is the arming-authority slice discussed by the 43-Var landing. The intended rule is that every admitted, loaded function has its accepted projection contract, including external-host program functions. Script indexing plus the extra moves supplies locations for all 43 reported omissions. Publication, contract compilation and an installed census must prove coverage and resolve the 81 differences before removing the metadata fallback. BB runs in a separate process: arming a JVM Var proves nothing about a BB function. Keep that distinction explicit rather than claiming the root change instruments every operator invocation.

**One-REPL S2 is a different slice.** Follow [one-repl-language §2.5](one-repl-language-2026-09-25.md), coordinated with [duplicate-paths R7 and R3](duplicate-paths-audit-2026-09-25.md). Indexing does not implement read → eval → record → print. The MCP entrant must submit to the ordinary agent owner, reaching the real reader/evaluator and `seon.turn/record-evaluated-*` (`src/seon/turn.clj:1452,1525`), then consume the declared rendered result. Preserve the plan's explicit session ID, selected branch custody on every call, listener-before-submit/recheck completion, timeout retaining ownership, actual-exit fence and retirement of only session-owned agents. Remove the bridge's reader and value reconstruction; do not add another recorder, scheduler, busy registry or printer. The plan's retained/deleted `get_value` decision remains its own authority and earns no saving here.

JVM mode must also evaluate successive source forms in order, allowing an earlier namespace change to affect the next read, without printing/re-reading the submitted form and losing reader metadata. Its degraded recovery PREPL remains available before the cluster exists; the unresolved host record boundary in the one-REPL plan is not settled by moving `prepl.clj`.

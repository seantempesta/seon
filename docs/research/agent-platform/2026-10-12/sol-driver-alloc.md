# Central driver and store allocation evidence

The central driver selects declared members, submits one runner request per part, and prints the returned evidence. Store allocation now reserves a fresh id where `datahike.db.transaction/next-eid` assigns it, with one transaction evaluation rather than a transaction-wide CAS retry.

The driver removes readiness polling, retry, message-only errors, direct printing and fixture-name matching. `seon.test/bounded-result` joins the actual body under its bound; the runner retains resources until its watcher observes exit, and `seon.test.runner/record-exit!` records the separate terminal fact. The driver preserves unfinished, pending and error values and ends the round; a PREPL total deadline also records unknown transport outcomes without resubmission. `seon.test/declared-bound-ms` supplies the body bound, the operator supplies its transport bound, `seon.error.refusal/error` constructs the entrant error, and `seon.print/form-text` / `seon.render.value/core-text` own shown output. Output now contains each part's runner answer, including its run id, rather than census rows.

Branches do not share a transaction processor. `datahike.store/connection-id` includes the branch; `datahike.connector/-connect-impl*` creates that connection's writer, and `datahike.writer/create-thread` serializes its queue. The existing store counter is shared by those writers. `AtomicLong.updateAndGet` repeats only the pure integer calculation under contention, never the transaction or its functions. Successful explicit-id writes advance the counter from the report. A refused fresh-id write can leave a gap; speculative `datahike.core/with` stays local. Existing tempid conflict resolution is unchanged: this is an allocation-contention guarantee, not a new guarantee over that separate mechanism.

The installed lane command initially refused the pin because it rehearsed the new dependency in default's old JVM. `bin/lane commit --at-candidate` now constructs a commit from its already held candidate tree and calls the existing `bin/seon check --at` entrance. Its checks run publication, adoption and the named proofs in that candidate's JVM. File claims, lint, candidate-byte comparison and `git commit --only` remain the same commit operation. This supplies the requested dependency workflow inside the lane entrance; it does not restart default or substitute a different test runner.

Cost is proportional to assigned ids plus one successful-report observation; allocator initialization reads the branch heads once, O(branches). Raw import previously called `next-eid` for every datom even with an existing mapping; it now calls it only for a new entity or ref mapping. The store counter is the same existing owner and state; no new writer, lock, registry or replay mechanism was added.

## For root

1. `agent-test/park-wake-test`: waits for `::closed-turn` (`test-support/await-event!`, 20 s) for an agent with no assignment. Production that should deliver it, `seon.turn/next-agent-work`, opens no model turn without a held task (CX-2, 7e39aeed3). Alone: 26.0 s, 0 provider calls, answers `{}`, body over 5 s bound. Stored (results.edn): `remainder 1942 ms`.
2. `agent-test/restamp-recovery-test`: waits for `::database-state` (quiescent, 20 s) for two unassigned agents. Same gate; unanswered triggers never clear. Alone: 25.7 s, error "expected terminal database fact did not arrive".
3. `agent-test/pause-during-in-flight-call-test`: waits for `::provider-entered` (20 s), then `::plan-frozen` and `::resumed-quiescence` (20 s each) after failing, so one failure costs 60 s. Agent unassigned; the provider is never called. Alone: run 64.96 s; test body 60.7 s against a 5 s bound.
4. `agent-test/release-joins-every-owned-graph-before-it-closes-the-branch`: waits for latch `::stuck-prelude-entered` (20 s) inside a `with-redefs` of `context/model-context`; the model context is reached only by a model turn, which the unassigned agent never opens. Alone: 25.0 s against its 15 s `long-ms`.
5. `agent-test/routing-conservation-waits-for-terminal-evidence`: waits for `::provider-entered` (20 s) from `routing-trial`, which creates unassigned agents; its `finally` awaits the verdict again. Alone: 25.0 s against 5 s.
6. `agent-test/stop-flow-interrupts-an-in-flight-turn-and-records-it-interrupted`: waits for latch `::interruptible-prelude-entered` (20 s) before `agent/stop-flow!`; the prelude needs a model turn, which the unassigned agent never opens. Alone: 24.7 s against its 12 s `long-ms`.
7. `agent-test/n-agent-parallel-turns-property`: waits for quiescent terminal state (`await-database-state!`, 20 s) per trial; agents unassigned; each failing trial costs 20 s and shrinking repeats it. Not run alone; stored: 120.5 s body, shrink 100.4 s, `:failed-after-ms 20123`.
8. `agent-test/wake-routing-conservation-property`: same routing trial. Its own docstring (`BOUND:`) records that a failing trial costs the 20 s backstop and shrinking repeats it. Not run alone; round: 25.2 s before the round left it live.
9. `blob-publication-test/publication-and-collection-are-exclusive-in-both-orderings`: NOT a hang. Alone: all 20 assertions pass; the one failure is `exceeded its declared duration: 70,906 ms` (`66,278 ms` in the body) against 5,000 ms. Cost is unattributed (`registry/collect!` twice over a store, plus two `with-redefs`). Bound shorter than work (d).
10. `armed-test/a-message-committed-during-boot-start-is-conserved`: waits for `await-fact` "database fact" (20 s) for a run opened by a boot-window message; a real `boot/start!` runs inside the 5 s bound (round left 2,158 ms for the body). Alone: 67.5 s body, error at the 20 s await. The message is committed; no run opens (cause unverified beyond the wait).

Common cause: the test's own 20 s event backstop (`seon.test-support/event-backstop-seconds`, `await-event!`) exceeds the runner's per-member bound (5 s, or the declared 12 s and 15 s `long-ms`). On timeout `seon.test/bounded-result` returns `:seon.test.run/terminated? false` and calls `watch-exit!`: release happens only when the thread exits, and `seon.test/run`'s batch loop stops the request (`:member-unfinished`), with "later requests hold only this test". `seon.central-round/run-round!` (script/seon/central_round.clj) ends the round on any `:seon.test/unfinished`, so the driver rebuilds. The runner does not continue past an overrun member.

M17's end state ("every agent has an assignment") makes unassigned fixtures invalid, so they must convert (filed task below).
Already filed: `seon.cluster.agent-test/wake-fixtures-observe-real-terminal-events` (covers park-wake; its own note says a bare assign-task! gave 61.6 s and stayed red). Tasks in seon.cluster.message and seon.cluster.registry need `seon.turn/a-held-task-opens-no-model-turn` (the M13 phase).
Not filed: the same conversion for pause, release-joins, restamp, routing (both), stop-flow, n-agent, wake-routing, armed a-message; the 20 s-versus-bound mismatch as one defect; blob-publication's bound and its two `with-redefs`.

## Notes

- **Method limits.** Stored-result numbers come from one parse (`agent-test-hangs-results.bb`). `results.edn` lines for the ten tests have `:seon.test.member/run-ms` absent (they never terminated), so all run times there are remainders, not body times. `remainder` is the batch's shared deadline (`seon.test/run`: `deadline = started + sum of declared bounds`), so a member's `remainder` depends on earlier members in its batch, not its own 5 s.
- **Class (a) rests on code and two runs.** `seon.turn/next-agent-work` (`:open` arm: "A MODEL TURN NEEDS AN ASSIGNMENT"); park-wake alone shows zero provider calls and `answers {}`. Unverified: whether every wait listed is for a model turn in the same way; the armed and release-joins waits were traced by the await site only.
- **Assignment is necessary, not sufficient (verified by round-waste.md, not rerun here).** Candidate 4a3b4c82f with `test-support/assign-task!` in park-wake: 61.6 s body and still zero provider calls. The working tree now carries the same one line in park-wake (uncommitted, another lane). Its outcome is not known here.
- **Runner release.** `seon.test/bounded-result` `watch-exit!` releases only after `.join thread`; the central round never releases a live body, so the driver rebuilds (matches central-round-head.md "Unfinished").
- **Earlier notes checked.** round-waste.md classified these by source trace and a measured unfinished answer; red-triage.md row 30 (pause) had no commit. `git log -S` on the test names: last introduced in 11b2ee1a0 (2026-07-28), with later edits in 7004818dc (2026-09-09) and b60b12b2d (2026-08-11). - **Prose and sizes.** Blob-publication's `with-redefs` and armed's and agent_test's are forbidden by the CLAUDE.md law ("never `with-redefs`"); recorded as facts, not fixed here (survey only).

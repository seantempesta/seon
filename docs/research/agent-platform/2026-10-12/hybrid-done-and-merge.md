# Done is derived from proofs; root merges the merge request from main

## 1. The design in one page

**What exists.** The agent's loop derives an end (`seon.turn/task-end`), then performs the agent's own verb `my.program/request-merge!`, which writes a second entity (a merge task plus a merge request keyed `[assignment commit]`). Root's `db<->flow` copies cluster facts with `seon.cluster.squash/copy!` (fixed base, three-way computed before the writer, a transaction marker `:seon.squash/attempt` as the completion test, conflicts as prose tasks), and code reaches main through `seon.cluster.source/land!` (a Datahike merge commit with parents, then write-back and one git commit, no path after a crash). Two merge shapes, two bases, a marker, an agent verb, four catches. Both plans independently reach the same skeleton; the hybrid takes it, and the owner's answers (§4) settle the points where they differ.

**The owner's model (2026-10-12).** Everything a step made, facts and code (schemas, contracted stubs, deftests, functions, task facts), **auto-merges onto main at the end of each step**; a successor forks main after its needs merge. The agent knows this at every REPL call: its current-state block shows the derived diff of its branch since its merge base, and **the branch is the proposal**: the agent curates by editing its branch (define; delete an entity no live caller uses, the existing deletion law; restore an entity to its merge-base value). No include/exclude list, no curated move. Root looks only at unmerged coordinates.

**The entity.** The **assignment** (`:seon.task/assignment`, `seon.id/id [task number]`, the entity `seon.task/attempt-tx` writes today) is also the **merge request**: one per assignment, open from the moment root assigns the task, closed once by root. The separate merge task (`:seon.task/kind :merge`), `:seon.task/merge-request-row` and `my.program/request-merge!` are deleted.

Kept: `:seon.error.occurrence/count` with its declared `:add` rule and `add-count`: with the base advanced in the same transaction the delta is exact (hybrid-push measured base 1, source 2, main 2 → 3; repeat → 3), so the counter's readers in `seon.fault`, `seon.error`, `seon.problems` and `seon.render.transcript` are untouched. Retired: `:seon.squash/attempt`, `:seon.squash/copy`, `/datoms`, `/conflicts`, `/conflict`, `/context` (the unmerged entity carries the values), `:seon.task/merge-request-row` with `:merge-request`, `:merge`, `:of-assignment`, `:proved`, `:red-first`, `:run-id`, `:program`, `:seon.task/merge-request-view`, `:seon.task/kind :merge`, `:seon.task.attempt/fork`, `:seon.task.attempt/commit` as a fork basis, `:seon.config.root/land?` (no replacement: the owner decided auto-merge, Q-a).

**Done, derived.** An assignment is done at source commit C when `seon.context/step-status` answers `:done` over `step-observation` (head = C's latest results for proofs, product and reached reds by reach digest; fork point = the merge base), with one change to the `:implement` rule: **at least one proof was red at the merge base** (Astra's reading of the law; a task may tag an existing regression test beside its new red one). Today nothing produces a proof's result at the base: `seon.turn/prove-turn` only runs the proofs, `record-broken!` asks `seon.test/fork-point-red` only for the reds at the head, and `step-observation` rebuilds the fork point as `(not (broken s))`, which is `true` for a proof green at the base too (narrow check failure 2; verified §7 P1 and at the code). The producer is M1: `record-broken!` asks the fork point for the proofs as well; `fork-point-red` first reads the branch head's own result at the base program's reach digest (`seon.test.runner/latest-results` keyed by `:seon.test.member/reach-digest`, which `prove-turn`'s first run recorded while the branch still held the base program) and opens the fork commit only for a test with none; the proofs green there are written as `:seon.agent/green-before` beside `broken`/`new-red`, and `step-observation` gives them fork point `false`. A proof set green at the base is reported as `:seon.context/green-before`; when it is the whole set, root closes the assignment `:closed` with reason `satisfied` (R-8: the task is already true on main) and no model call happens. `:prove` is unchanged (R-7). The agent's test step writes this judgment on its branch and stops calling the model; root recomputes it on each wake only for branches whose head moved since it last judged them, at about 1 ms per proof. `seon.task/assignment-read` already refuses `:no-proofs` (corrected from the first draft); what it lacks, the all-green refusal, M1's rule supplies at completion and M8 at assignment.

**One merge shape: a three-way per coordinate, squashed, base stored, one partition.** `seon.merge/three-way` is today's `squash-merge` with one addition: cardinality-many attributes merge member by member, `(ours − (base − theirs)) ∪ (theirs − base)`, as git merges lines (verified: today disjoint additions to a set conflict, §7 P3). Rules per coordinate `[attribute entity]`: changed on one side → that side; both to the same value → nothing; both to different values → the attribute's declared `:seon.cluster/conflict` (`:ours`, `:theirs`, `:add`), else **unmerged**. The merged result is one plain transaction on main with one parent (ours) and the base advanced in the same transaction: Datahike's `merge-db!` records parents and computes nothing (`datahike.writing/merge-writer!` is `transact!` plus `:datahike/merge-parents` metadata, verified), and parents would keep the agent's lineage reachable inside the snapshot window for no reader (`datahike.gc/reachable-in-branch` follows parents only `in-range?`). `accept-merge!` drops `:parents`. The owner's answer to Q-b makes the partition the whole declared program and cluster set (`:seon.program/partition`, exists) with one base; the separate fact partition and second base are gone from this design.

**Root's merge (`seon.merge/merge!`, called by `db<->flow` and by `my.root/merge!` at root's REPL; the same function).** (1) Fork a merge branch `merge/<assignment>` from main's head B; apply three-way(base, theirs = C, ours = B) there; conflicts become `:seon.merge/unmerged` entities on that branch and the merge stops there with the assignment open and the three values as data. (2) Gate: `step-status` on the merge branch with the fork point at B (proofs, product, the tests reaching the change, through the one runner, results reused by reach digest). This is P3's conversion: `seon.test/change-reds` is deleted; "a red is the change's unless main is red" is exactly `:seon.context/broken` judged at B. **Designed reds are data, not an exemption:** a red whose recorded failure is an `:error` of type `:seon.error/unimplemented` (the runner records the type since be32e7501, `seon.test.runner` `error-type`) on a deftest whose `:seon/tasks` names a task with no `:merged` assignment is `seon.context/designed-red?` (exists) and is a Prove step's product; `accept-merge!`'s "every member green" and "a replaced function reaches no green test" refusals become: every reached test green or designed, every added or replaced function reached by a green test or by a designed red tagged to an open task. Main therefore holds the red proofs of every assignable task between steps, which is the state `seon.task/assign!` already requires. (3) Transact `[[:db.fn/call seon.merge/merge-tx assignment C tested]]` on main. Inside the writer, on its own db value, the function recomputes three-way(base, C, db) and compares the merged digests of every touched coordinate and every definition the gated tests reached with `tested` (the merge branch's digests): equal → it writes the merged result, `:seon.task/merge-base C`, `:outcome :merged` and `:merge-commit`, in that one transaction; different → it returns `[]`, and the main transaction that moved them has already woken `db<->flow`, which re-derives (git's `update-ref new old`, per coordinate; verified: a root edit after capture becomes a conflict inside the writer, never an overwrite, §7 P4). Fast-forward is the trivial case: main unmoved since B, nothing unmerged, step 3 passes. (4) **Publication is derived due work, not a step of the merge** (Q-e default). Datahike is the authority; files are the write-back of accepted entities. `next-actions` derives `:publish` for an assignment with `:merged`, program entities changed and no `:git-commit`; `seon.merge/publish!` runs `write-back!` (which already checks file bases and reindexes) and `commit!`, then writes `:git-commit`. A crash anywhere leaves a derivable state: accepted-not-published is due again, and a write-back finding equal bytes commits nothing. Datahike, files and git share no atomic commit; the design keeps the three facts distinguishable (`:merge-commit`, `:git-commit`, the loaded commit). Git plumbing with a private index and a request ref (Astra §3) stays deferred by plan.md §6 until a collision in the shared checkout is observed.

**Auto-merge (Q-a, decided).** `apply-actions!` runs `:merge` whenever the source is done, the gate is green on the merge result, nothing is unmerged and `merge-tx`'s compare-and-swap passes. Root reviews only unmerged coordinates (`my.root/merge-requests` shows them with their three values). `:seon.config.root/land?` is deleted without replacement; R-10 is superseded.

**The branch is the proposal.** At every eval request the current-state block carries `:seon.context/changes`: the entities the branch added, changed and removed since its merge base (`seon.program/changed-identities` from the base to the head over the program and cluster attributes; 0.8 ms warm on default per hybrid-push §4), grouped by family (functions, tests, schemas, namespaces, task facts, other cluster facts), each entry with the form that digs into it (`my.program/declaration-diff`, `my.program/history`, a pull for a fact), never stored (M14). The agent curates by editing its branch: `defn`; `my.program/ns-unmap!`/`remove-ns!` for an entity no live caller uses (the existing deletion law, refused by the writer while a referrer survives); and **`my.program/restore!`** (git's `restore --source=<merge-base> <path>`): one entity, by identity, returns to its merge-base value on the branch, retracted when the base lacked it, through `seon.program/exact-replacement-tx`; after it the entry leaves `:seon.context/changes` (M15). No include/exclude list exists: what the branch holds at C is what merges.

**Merging main into the source branch.** Trigger: the source is done and the gate on the merge result is not (main moved under the change: a sibling's merge turned a reached test red, edge 16). Root runs the same three-way with source = main and target = the agent's branch, `update-tx` sets the base to M, unmerged coordinates go to the agent's branch as `:seon.merge/unmerged` entities for the agent, the branch's listen route wakes it, and its next pass reruns the proofs pending at the new reach digests (prove-first generalized from "keyed by assignment" to "pending at this program").

**Forking and joins (Q-c, decided: C1).** Every assignment forks **main** once all its `:seon.task/needs` have a `:merged` assignment; a Prove step's product merges into main like any change. Joins are ordinary; no predecessor branch is kept; `successor-waits?`, `seed-attempt!`, `attempt-rows-tx`, the octopus and the held-successor pin go. R-6 decision F is superseded.

**Lifecycle, derived (`next-actions`, pure; absorbs P7–P10).** From main's facts and the roster: `:merge` (done ∧ gate green ∧ nothing unmerged); `:update` (done ∧ gate not done); `:stop` (`outcome` present ∧ graph in roster, orderly: the pass finishes); `:cancel` (intent `:cancelled`: interrupt, await actual exit, then `close-tx` `:cancelled` and `:delete-branch`; no task for root, no end written by `follow!`); `:delete-branch` (`outcome` present ∧ graph exited ∧ (head = base ∨ ¬done(head)) ∧ no unmerged ∧ no publication due ∧ `keep-ended-branches?` false); `:publish`; `:close` with the end the branch holds at C (`:sent-back` with target, `:given-back`, `:capped`, `:stalled`, `:error` for a failed start or a refused action); `:relaunch` (P9: the closed assignment carries `:seon.task.attempt/relaunch`, so assignment n+1 is written, forking main or the named `relaunch-fork`); `:attempt`+`:start-flow` (one starter, P10: `plan` over assignments of `:running` tasks; `agents-to-start`, `host/start!`'s graph start and the held clause go). Every action is idempotent by identity or by `head = base`; a failed action is the assignment's `:error` close written by the entrant boundary (the Flow proc), never a catch-and-continue; the facts are unchanged so the next pass derives the same action once. A stopped task keeps its branch and open assignment; `:held` has no assignment and no model turn.

**Messages (U5, absorbed).** The sender transacts the message on its branch; root records it on main by `:seon.message/id` *before* its one `offer!`; a crash between leaves "unknown", never a second offer (in-flight loss accepted, R-4); an undeliverable offer is data on main's message entity.

**Retention.** Open assignments' merge bases are commit ids passed to `datahike.gc/gc-storage!` as `:datahike.gc/roots` (fork change, option A, R-4; absent from the pinned reference, zero hits). Until it merges, the `:base/<branch>` ref is moved to the stored base with `force-branch!` `:expected-current-commit` (exists) by root's `db<->flow` alone, the one writer of base refs, which satisfies the docstring's "exclusive write access".

**Words (Q-d, decided).** Clojure, Datahike, Malli, git only. One Seon word for vocabulary.md: **assignment**: one task given to one agent on one branch, numbered within its task, the entity of `:seon.task/assignment`; it replaces "attempt" (no library names this relationship; the attribute already carries the word). "Merge request" (GitLab, already in vocabulary) names the same entity's merging role, so the vocabulary entry changes to "an assignment, as the thing root merges: source branch, target branch, merge base, outcome". Retired on this path: land/landing/landed/unlanded → merge/merged; copy/end copy → squash merge; settle (branch) → delete-branch; `:root` rule → **unmerged** (git); problem task → a task assigned to root; `seon.cluster.squash` → `seon.merge`; `retire-branch!` → `delete-branch!`; `frontier` → `ready` (CN-27). `step` stays (owner's word, vocabulary).

## 3. Every edge case, and the design that makes it impossible or correct

| # (dig §3) | Design |

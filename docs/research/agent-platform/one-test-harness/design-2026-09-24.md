# One test harness (2026-09-24)

**Changed from v1:** all nine accepted findings are integrated below.
The agent attempt owns preparation, custody, lifecycle, program validity and effects.
Core and SCI tests use clean checkpoints, including the agent's differing program rows.
Seeds preserve order and declared inputs; unknown results change schemas and every reader together.
Owner changes 2 and 3 disappear; function-provider carriage and the effect authoring path are specified.
Validity and confinement proofs precede reuse and drift deletion; independent deletions move forward.
All slices include schema, graph, reader, caller and regression costs; S5 is a grouped campaign.

**What exists.** `seon.test/run → member-result → acquire-context! → bounded-result → runner/run-var!`
provides the existing composition. On normal completion, `bounded-result` releases before returning the
captured outcome; `commit-results!` then records it (`src/seon/test.clj:126,181,1447,1621`).
**Principal approach:** move attempt responsibilities to the existing agent owners and pass a deftest body
through them. The harness supplies that body and records its outcome. It has no seed cache, lifecycle
executor, capability registry or separate task-proof language. Everything that cannot use this confined
attempt is a platform test through the same interface, under the orchestrator's process ownership.

## 2. One entrance, agent-owned preparation

`seon.test/run` remains the interface for `my.test`, CLI, save/merge gates and issue tests. Its body adapter
uses the ordinary attempt sequence: **validate program → prepare checkpoint → fork/inject → run → await
exit/cleanup → return outcome**. The harness records that outcome on the explicit recording connection.
A timed-out attempt records unfinished evidence while retaining ownership until actual exit; it admits
no successor body. Resource release never depends on evidence writing succeeding.

Preparation belongs to the checkpoint/acquisition owner described in decoration-language §4b:

1. Capture a valid base program under adoption exclusion (§5). Derive cluster program as **base plus the
   agent branch's differing program rows**, including retractions and affected callers. Use schema-declared
   program partitions, not an operational-row blacklist. Core requests take the same path with an empty
   overlay. The source branch commit is provenance, **not world identity**; never inherit its faults/messages.
2. Apply the shared boot facts writer with explicit effective manifest and relevant process inputs, excluding
   executable root routing. Apply ordered seeds through checked canonical writers, passing each resulting
   database to the next seed. A refused write stops preparation. Program-changing seeds go through ordinary
   program acquisition, with changed callers reinterpreted; host-bound overrides refuse by name.
3. Content identity includes base/overlay definitions, ordered seed dependency closure, declared external
   bytes, manifest/config inputs and any relevant process inputs. Seeds receive declared file data as captured
   values from the preparation input; no untracked file read inside a purported pure cached function.
   Changed helper, referenced provider/handler definition, seed order or file bytes invalidates its dependants.
4. Use existing serialized branch/publication ownership to prepare privately and expose only a completed
   checkpoint. A contender cannot consume a branch merely because `registry/branch!` returns `created? false`.
   Failure exposes no ready checkpoint. Publication retains an ordinary branch head until dependent attempts
   have acquired their branches; old checkpoint retirement respects that handoff. No test-owned ready cache.
5. Freeze the checkpoint's database/SCI pair. Never evaluate into the published parent again. It holds no
   attempt connection, atom, result handle, routing or branch-bound recorder. Cache opening **form plans**, not
   evaluated values. Each attempt receives new private resources; share compiled validators by full content.

Cost follows changed inputs: reuse compares captured content identities; preparation visits changed program
closure and supplied seed data, not all program rows per body. First preparation includes checked writes and
is measured separately. `registry/branch!` retains the shared-root write floor (historically ~22 ms);
SCI fork (~0.006 ms) is not the whole acquisition cost (~55 ms historical). Reusing a checkpoint is not “0 ms”.

**Sibling worlds:** a thin support helper calls the same attempt owner on the completed checkpoint, not the
parent's mutated head. It gets independent custody, routing, evaluation and cleanup. Store-global subjects
use the store owner's existing fresh-store route; file/process/unconfined subjects are platform (§7).

## 2b. Agent-friendly authoring, ordered seeds and graph edges

The authored form is plain `clojure.test/deftest` with `:seon.test/seed`, an ordered vector. **Owner
ruling 2026-09-24:** each entry is one of three forms, taught in this order:

1. **Literal transaction data**: an entity map or a vector of them. The quick way to load data; no
   function at all.
2. **A qualified symbol** naming a contracted seed function, `:seon.test.seed/input → :seon.test.seed/value`.
   Use it for shared seeds: its own row, docstring, contract and reach edge. Promote an entry to a symbol
   once a second test wants it.
3. **An inline `(fn [input] ...)`**, when the data depends on the database. `deftest` expands to `def`,
   which evaluates the symbol's metadata (verified 2026-09-24 in the JVM and on an MCP SCI branch: an inline
   `(fn [x] (inc x))` in deftest metadata is callable, `[{:a 1} 2]`), so the entry is a real function in the Var's
   metadata. It returns `:seon.test.seed/value` like a named seed.

Function bodies stay out of EDN task files, where nothing evaluates or analyzes them; deftest metadata is
Clojure source, so forms 1 and 3 are part of the test's own definition. The returned seed map has a
**different schema name**, `:seon.test.seed/value`: an open map with optional checked
`:seon.test.seed/tx-data` and `:seon.config/manifest`. Its declared input `:seon.test.seed/input` carries the
immutable database and captured external inputs; ordinary no-file seeds only use the database. These are
proposed schema names.

```clojure
(ns my.workout-test
  (:require [clojure.test :refer [deftest is]] [my.workout :as w] [seon.db :as db]))

(defn week-37
  "Prepare three sessions from the domain's canonical transaction builder."
  {:malli/schema [:=> [:cat :seon.test.seed/input] :seon.test.seed/value]}
  [{database :seon.db/db}]
  {:seon.test.seed/tx-data
   (w/sessions-tx database [["s1" "2026-W37" 500]
                            ["s2" "2026-W37" 450]
                            ["s3" "2026-W37" 300]])})

(deftest ^{:seon.test/seed
           [{:my.workout/athlete-id "a1" :my.workout/name "Ada"}          ; 1. literal data
            my.workout-test/week-37                                        ; 2. shared seed
            (fn [{database :seon.db/db}]                                   ; 3. inline, reads the db
              {:seon.test.seed/tx-data (w/assign-tx database "a1" "2026-W37")})]}
  weekly-volume-sums-the-week
  (is (= 1250 (w/weekly-volume (db/db) "2026-W37"))))
```

**Why every form keeps reuse and context sound.** Forms 1 and 3 live inside the deftest form, so the test's
own definition digest covers them: change the data or the inline body and the test's reach digest changes,
so it reruns; no new key. The analyzer sees their keywords and calls as part of the test's analysis, so the
same edges as a named seed reach the written schemas (for context generation, the schema docs of
`:my.workout/*`) and any helper called (`w/assign-tx`). Form 2 adds the seed function's own row and digest to
the reach. Every entry's transaction data goes through the checked writer, so a wrong shape refuses by name
whichever form produced it; an inline function is not separately contracted, but its output is validated.
Costs of form 3: not reusable, and not a separate row or contract.

This illustrative domain must first admit its session schemas, builder and function contracts; no
hand-built function/test/config rows are implied. Seeds return transaction data, not transactions, and the
attempt checks the writer's `:db-after`. Manifest application uses `config/apply!` (`config.clj:723`).

Store seed occurrences as owned components with ordinal and form: the qualified symbol (form 2), or the
entry's written schema keys and called symbols from the test's analysis (forms 1 and 3; the value itself
stays in the test's source); reconstruct the vector by ordinal. Cardinality-many refs alone lose order.
Indexed symbol edges denote authored names; resolve their
current rows for validation and walking. Extend the **existing** admission/analysis and reach walk
(`runner/reach-facts :675,749`) with test→seed→helper/written-schema and declared dispatch edges. No shadow
reference graph. Apply language-requirements §7.9b: validate seed tx-data, of every form, against its written
schemas at admission using the captured prepared world, before publishing readiness. Also validate qualified names,
existing definitions, complete contracts, coherent references and cycle/bound refusals; preserve analysis digest
for an empty seed vector. Retraction must repair surviving users or refuse. Returned runtime symbols are
not automatic graph edges: domain declarations must expose them to the same walk and invalidation inputs.

`callers` and task context walk then find seeds; equal ordered inputs share a completed checkpoint. Task
`done-when` names qualified test symbols. No reverse task metadata or EDN deftest-body strings are added.

**REPL route:** `(run-tests)` supplies the current authored namespace to the existing named request;
explicit namespaces override it. Change `my.test/run-owned` and its request/return schemas to return the
full `seon.test/run` result, delete `owned-symbols`' assigned-namespace selector, then expose the SCI alias.
It is not a two-line alias fix. `(my.test/check {:seon.test/changed ['my.workout/weekly-volume]})` uses the
same request. Verify from an agent assigned elsewhere: a real red assertion reports this authored source
line, a seed refusal prevents entry, and a correction returns green. Preserve counts, reports, exclusions,
unfinished members and refusal data. A bare test function returning nil is not a recorded proof.

## 2c. One complete agent-authored effect substitution

Existing `:seon.effect/capability` is a qualified-symbol declaration on the owner function and the observed
handler on receipts (`resources/seon/schemas/seon.effect.edn`). `effect/request*` already declares
`:seon.fn/invokes #{:seon.effect/capability}`. Its current JVM-only resolution and absent test evaluation
context are the gaps; S4 fixes these in the ordinary attempt/effect path, not in an override map.

Example candidate program, authored and admitted as ordinary forms in the agent's namespace. The normal
`my.catalog/label` owner names an HTTP handler; the candidate changes that **declaration** to `canned-label`.
All functions below are rows, not private defs assumed to survive acquisition:

```clojure
(ns my.catalog
  (:require [clojure.test :refer [deftest is]] [seon.effect :as effect]))

(defn canned-label
  {:malli/schema [:=> [:cat :string :seon.config/effective] :string]}
  [request _effective]
  (if (= "wait" request) (loop [] (recur)) "fixture label"))

(defn label
  {:seon.effect/capability my.catalog/canned-label
   :malli/schema [:=> [:cat :string] :seon.effect/request-result]}
  [request]
  (effect/request! #'label request))

(defn catalog-seed
  {:malli/schema [:=> [:cat :seon.test.seed/input] :seon.test.seed/value]}
  [_] {})

(deftest ^{:seon.test/seed [my.catalog/catalog-seed]} reads-canned-label
  (is (= "fixture label" (label "item-1"))))
```

`label` is a thin dispatcher facade; its polymorphic result is the existing effect dispatcher contract,
while the handler has the concrete string result contract. No new catch-all error family is invented.
Installation: canonical program admission validates the owner→handler edge and contracts. Preparation
applies that candidate overlay and empty seed through the normal owner; no domain config is needed because
this capability is a declaration. The attempt creates its own agent/turn/evaluation and request context,
with effective config, caps, projection, ctx, counter and launcher. `label` then calls real `request!`:
validate owner input → open receipt → invoke handler in that ctx → validate result → settle receipt.
Change handler-refusal validation to use the admitted declaration, not JVM Var metadata alone.

Acceptance reads the receipt on the attempt branch: owner `my.catalog/label`, capability
`my.catalog/canned-label`, requesting evaluation, request `"item-1"`, settled `"fixture label"`; no network
call. A second attempt evaluating `(my.catalog/label "wait")` under the declared bound must produce the
existing interruption/timeout evidence and actual exit before release; background coverage additionally
uses `request!`'s execution options, owned launcher and terminal receipt. A missing handler or invalid
request refuses before dispatch. A separately captured base sibling keeps its original handler; a candidate
sibling keeps the candidate declaration but neither sibling inherits receipts or private mutation. Live
default is unchanged. This is required proof, not a claimed executed example.

## 2d. Function provider: carriage and first proof

Owner change 5 keeps `seon.ai` as the one provider owner. First prove an ordinary attempt through the existing
`with-provider` loopback (`test/seon/ai_stream_fold_test.clj:218`, revision inspected): port 0, no-auth config,

- **Descriptor and carriage:** add an optional qualified handler symbol to the existing provider descriptor
  schema/manifest reconciliation, with a declared dispatch edge; no second provider registry. Transport
  selection distinguishes HTTP and function descriptors by declared fields and refuses ambiguous forms.
  The turn/attempt carries ctx, immutable db, projection, environment, caps, remaining deadline and recorder
  through a declared execution argument to the AI owner; update every caller. No ctx lookup from globals.
- **Contracts:** existing `:seon.ai/request` requires HTTP endpoint/credential fields. Keep that HTTP contract;
  add named function-request and function-reply schemas in the same AI family. Function request carries

  alternatives. Declare a provider invocation refusal for missing/invalid handler or unusable envelope.
- **Dispatch:** resolve the admitted symbol via `sci.kernel/invoke` (`:585`) using the carried ctx/db, argument,

- **Stream and errors:** initial function transport returns one normalized completion; a request requiring

- **Proof:** identical captured prompt through loopback and function handler yields equivalent normalized

  invalid reply, thrown cause, deadline/actual exit and stream refusal before converting any caller suite.

## 5. Program validity, provenance and evidence reuse

The adoption/program owner marks affected execution unavailable **before** any root changes; it publishes
readiness only after exact source bytes, loaded definitions, arming and adoption record agree. Commit the
record inside `call-with-program-change`. Reload, arming or record failure leaves affected execution
unavailable after unlocking. An old record equal to an old seed never certifies changed/unarmed Vars.

Acquire validity, resolve the test/seed callable and enter under the same exclusion; do not hold a Var
resolved before locking. Apply this to ordinary agent evaluations and seed execution too. Refuse mismatch
before effects. A body cannot bypass write exclusion by already holding a read lock: self-adoption is
refused/deferred to the program owner at the idle boundary; host adoption tests are platform. Keep existing
validity/loaded-source-drift checks until all failure paths are covered by the replacement.

Evidence records the actual base program provenance, candidate overlay/content, reached definition/schema/
seed/dispatch digests and declared input digests (`seon.test.cache/input-roots` plus seed inputs). Reach is
computed on the prepared candidate. A source commit is provenance, not identity of the clean test world.
For core calls require compatibility with the valid loaded program; for differing SCI rows interpret the
changed definitions **and affected callers**. Unsupported host-bound differences refuse. Program-changing
seeds repeat ordinary acquisition before body entry. Add required attempt/member provenance fields and
update schema, writer, selector, readers and reuse together; old records lacking proof are unknown.

Reuse needs current green, completed cleanup and equal exercised program/input identities. Red, unknown,
unfinished or refused evidence never reuses. Test successful inter-member adoption, partial reload, arming
failure, record refusal, replaced/deleted/recreated test Vars, seed mismatch and self-adoption separately.
Only after these proofs may the duplicate selector/drift paths be deleted.

## 6. Bounds and cost

Keep the 5 s ordinary body bound with measured `long`/`long-ms`, request remainder, actual-exit join and no
successor body while an earlier body lives. A bound expiring does not release exclusion/resources; unknown
host termination remains platform. Bound adoption acquisition by the existing request/config policy,
not the maximum `long-ms` anywhere in the database (formerly 1,200,000 ms); name the missing lock/exit event.

Historical end-to-end 3,319 ms included a 121 ms body, admission and recording. The ~130 ms private-fork
experiment omitted those costs and is not a harness target measurement. `program-written-since?` cost
124–1,600 ms; blob publication in recording cost 617 ms. Measure first preparation, warm lookup, acquire,
body, cleanup and recording separately, with allocation and process heap distinguished. Target warm harness
**overhead** ≤150 ms excluding body; end-to-end is overhead + measured body. No claimed speedup yet.
Use dependency revision tracking and conditional blob publication only at their owners (S14); changes must
reduce work for unchanged inputs, not merely move it outside the clock. >1 s needs the causing functions
and proportionality; >10 s needs explicit owner authorization and an issue. Record raw clocks/allocations.

## 7. Platform through the same interface

`bin/test --platform → bin/test-check --isolated → seon.test/run` remains orchestrator-owned. Ordinary lanes
use the shared JVM and focused requests; this document revision starts none. No second worker pool.
Derive known host reach from owner declarations (`:seon.fn/platform` reason, analogous to `destroys`) and the
existing graph. Include setup and dispatch; retain explicit justified markers for external dependencies and
unresolved dynamic host work. The survey's 230 is an inventory comparison, not an acceptance oracle.
Same attempt cleanup applies; after damaged-root drift, no next platform member runs until validity is
re-established. Fresh-store metadata belongs to store-global subjects; it does not make host mutation safe.

## 8. Agent benefit and retirement boundary

Clean checkpoints serve task attempts and retries; declared seeds teach the existing graph about setup.
Attempt-owned custody, evaluation, loop resources and cleanup apply equally to tests and ordinary agents.
Function providers allow bounded virtual attempts; effect declarations allow authorable substitutions.
Program validity and complete outcome readers make merge/readiness evidence trustworthy. The harness adds
only the body/report adapter; none of these features justifies a second owner in `seon.test`.

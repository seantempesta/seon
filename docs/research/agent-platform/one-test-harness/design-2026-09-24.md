# One test harness (2026-09-24)

**What exists.** A test already runs as an isolated agent for one body. `seon.test/run` (`src/seon/test.clj:1621`)
calls `member-result` (`:1447`). That calls `acquire-context!` isolated (`src/seon/cluster/agent.clj:786`), then
`bounded-result` (`test.clj:126`, with the adoption read lock since 2bd861329), then `runner/run-var!`, then
`commit-results!`, then `release-context!` (`agent.clj:753`). **Data flow:** the captured commit gives a branch.
The branch gives a forked ctx and custody. The body produces report maps, which are recorded, and then the branch
is unlinked. **Principal approach:** keep that one pipeline. Move each lesson the tests taught into the *agent*
path: the world's seed, graph stop on release, program identity per attempt, and the loop handle. After that the
harness keeps only two jobs: it runs a body, and it records evidence. Whatever cannot run on one branch in the
shared JVM is a PLATFORM member, and it goes through the same request. **What disappears:** the second world per
test (936 `with-database`, 238 `fork-cluster-ctx` and 108 hand-built handle or environment sites), ≈200 lines of
`test_support.clj`, the ambient drift trio on ordinary members, 431 rebinds of default's Vars (census classes a–e),
and 19 tests.

`:seon.db/connection`, `:seon.db/db`, `:seon.sci.eval/ctx`, `:seon.sci.eval/base-ctx`, `:seon.env/environment`,

### 1a. Capabilities as values

A capability is a config fact, an explicit argument, or a real external condition. It is never a rebound Var.
Rebinding is refused for ordinary members (§3), because a compiled `:core` body never enters SCI. That is why
fork-private redefinition covers 0 of the 359 sites (census §Replacement).

| capability (census rows) | how a test supplies its stub | production change |

## 2. The one entrance

`seon.test/run` stays the only way in (`my.test`, `bin/test-check`, the save gate, the merge gate and
`plan/run-issue-tests!` already call it). The whole path is **fork → inject → run → record → unlink**:

1. **Seed** (once per request, reused while the loaded commit is unchanged). Read the loaded commit under the read
   lock. Take the existing `:seed-*` branch head, or create it with `registry/branch!` from `current-src` plus
   `seed-facts!`.
2. **Fork.** `acquire-context!` isolated from the seed commit, with its own routing. This is the call at
   `test.clj:1464`, given a different `:seon.cluster.registry/from`.
3. **Inject.** Custody and projection for host bodies, as in §1. SCI bodies already get this (`test.clj:1510`).
4. **Run.** `bounded-result` under the adoption read lock. The body bound is 5 s (`long-ms` when declared), and the
   thread's actual exit is joined.
5. **Record.** `commit-results!` with the member's identity (§5).
6. **Unlink.** `release-context!`: disarm and join the graphs, release the connection, retire the branch
   (`agent.clj:753`). This happens only after the body thread's exit has been observed, which is already true.

Step 1 (seed) also applies the test's declared seeds (§2b). A seeded checkpoint is keyed by content:
`[loaded commit, cluster, seed digests]`. Every test that names the same seeds branches off one retained head.

**Sibling worlds** (H2, 23 tests): about 8 lines remain as `tu/with-sibling-world`. It is
`with-branched-database` (`test_support.clj:638`) renamed. It acquires a second isolated handle off the member's
seed commit, not the parent's head.

## 2b. Writing a test: for an agent at its REPL

**The form is a plain `clojure.test` deftest** plus at most one new metadata key, `:seon.test/seed`. It names
qualified symbols only and holds no function bodies:

```clojure
(ns my.workout-test
  (:require [clojure.test :refer [deftest is]] [my.workout :as w] [seon.db :as db]))

(defn week-37
  "Seed: three sessions in ISO week 2026-W37 (1,250 kg total)."
  {:malli/schema [:=> [:cat :seon.db/database-value] :seon.test/seed]}
  [_db]
  {:seon.test.seed/tx-data [#:my.workout.session{:id "s1" :week "2026-W37" :volume 500}
                            #:my.workout.session{:id "s2" :week "2026-W37" :volume 450}
                            #:my.workout.session{:id "s3" :week "2026-W37" :volume 300}]})

(deftest ^{:seon.test/seed [my.workout-test/week-37]} weekly-volume-sums-the-week
  (is (= 1250 (w/weekly-volume (db/db) "2026-W37"))))
```

**The world reaches the body through ordinary calls.** `(db/db)`, the elided write arities and `db/*conn*` are the
member's own seeded branch, through custody (§1). There is no argument, no fixture macro and no world registry.
`seon.test/*member*` (`test.clj:112`) remains for the few host tests that need the whole handle.

**What each piece of root's proposed form keeps, and why:**

| proposed | ruling | reason |
|---|---|---|
| plain `deftest` | **keep** | familiar from training data, works with `is`/`testing`/`thrown?`, and needs no macro |
| `:seon.test/seed #{…}` | **keep as a vector** | seeds can depend on earlier seeds, and a set loses that order |
| seed = a function returning tx-data built through the real writers, **or** EDN seed data | **functions only**, `db → :seon.test/seed` | one form. It is a pure function of the seed value, so it is content-keyed and cacheable. It returns an open map: `:seon.test.seed/tx-data` goes through the real writer, and `:seon.config/manifest` goes through `config/apply!` (`config.clj:723`), because a hand-written config row is refused (`test_support.clj:766`). An EDN file, if wanted, is read by the function |
| `:seon.test/capabilities {seon.ai/complete my.x/canned-reply}` | **drop** | keying a stub by the Var it replaces is `with-redefs` under another name, and it cannot reach a compiled `:core` caller. A capability is a config fact, so a seed carries it: `{:seon.config/manifest {…provider transport 'my.workout-test/canned-reply…}}` (owner change 5) |
| `:seon/task :my.workout.task/…` | **drop from the test** | the task already names its tests (`:seon.task/done-when`, language §3), and the reverse edge is a query. Writing both directions is a hand-kept mirror |
| declared-input alternative (a contracted test fn whose arguments name what to inject) | **not added** | the law permits it, but custody already injects the only per-member inputs (db and connection), and everything else is facts. Two forms would split tooling and evidence. Prefer `deftest` |

**A stub capability** is an ordinary function. It is an agent's own `defn` in its namespace, admitted as a row like
any definition, or a shared one in a test namespace, such as a recorded provider reply. For example:
`(defn canned-reply {:malli/schema [:=> [:cat R] P]} [_] …)`, where `R` and `P` are the request and reply schemas that
owner change 5 declares (no such pair exists in `seon.ai.edn` today).
The seed's manifest names it. Recorded replies are that same function reading a blob digest, not a second
mechanism.

**Seeds are graph nodes.** A seed is a program row with a contract. Publication records each `:seon.test/seed`
symbol as a ref from the test row to the seed's `:seon.fn` row. This is the same analyzer slice that stores
`^{:seon/task}` (open-items §Scheduled, ingestion). As a result:

- `(callers 'my.workout-test/week-37)` lists the tests that use the seed.
- The context walk from a task reaches its tests and then their seeds.
- A seed's digest is inside the test's reach digest, so changing a seed invalidates exactly its tests.

Reuse follows from that: two tests with equal seed vectors share one seeded checkpoint.

**Running a test from the REPL.** A `deftest` settled in a turn is an admitted row.

- `(run-tests)` runs the namespace through the one entrance. In SCI, `run-tests` is referred to `my.test/run`
  beside `deftest` and `is` (`sci/eval.clj:272-278`, +2 lines). Today a bare `(my-check)` returns `nil` and loses
  its failures.
- `(my.test/check {:seon.test/changed ['my.workout/weekly-volume]})` runs the tests that reach a change.
- `(my.test/prove "(deftest …)")` or `(proofs)` runs task proofs before they are rows (S13).

All of them return the run value, and the REPL response shows it through its AI renderer:

```clojure
my.workout=> (run-tests)
;; illustrative shape; the keys are the recorded ones (runner.clj:189)
#:seon.test{:passed? false :executed-count 1
            :results [{:seon.test/sym my.workout-test/weekly-volume-sums-the-week :seon.test/fail-count 1
                       :seon.test.failure/reports
                       [{:type :fail :expected "(= 1250 (w/weekly-volume (db/db) \"2026-W37\"))"
                         :actual "(not (= 1250 1200))" :line 14}]}]}
```

That value is the re-prompt: the agent reads expected versus actual at the source line. For schema claims,
`(is (nil? (me/humanize (m/explain S x))))` puts the Malli explanation inside `:actual`, with no custom
`assert-expr` (unprobed). The report must name the test's own source line, not a JVM frame (`AFn.java:154`, deftest
note §3b). That is a runner defect to fix in S13.

**The only other metadata** is what already exists: `:seon.test/long` with `:seon.test/long-ms` (a measured
bound), `:seon.test/platform` or derived platform reach (§7), and `:seon.test.world/store :fresh` for
store-global subjects (H8). The last replaces `:seon.test-support/fresh-store?`, and its opener moves from
`test_support.clj:603` into `seon.cluster.store`.

## 3. Failures return as data

- **Member results.** A result already carries `:seon.test.failure/reports`: type, expected, actual, message,
  `testing` contexts and a failure identity (`runner.clj:189`). Its messages are blob-staged above the threshold
  (62d97cfcc). `seon.test/run` returns these, and `seon.test/tally` (`test.clj:1908`) and the result's AI renderer
  show them. No second format is added.
- **Refusals.** Refusals stay flat `:seon.error` values: selection, admission, recording and unavailable
  (`test.clj:1641-1645`).
- **New refusal: a rebinding test outside the platform.** At admission, a non-platform test whose analysed calls
  reach `with-redefs`, `with-redefs-fn`, `alter-var-root` or `intern` on a Var outside its own namespace (census
  class f is allowed), or `instrument/apply!`, `restore!` or `remove!`, is refused by name, with the call and its
  line. This uses the stored call edges; there is no regex. The refusal enforces "Protect execution ownership" for
  a shared JVM that the drift check could only observe after the fact.
- **Defect: `latest-results` refuses the whole batch.** `runner/latest-results` (`runner.clj:1724`) throws
  `execution-refusal!` for the first incomplete member (`:1758`). The single `catch` (`:1762`) turns that into
  "Recorded run coverage is unavailable." (`:1710`) for **all 2,162** symbols, in 189 ms (survey §Recorded state).
  **Fix:** give each member its own answer. An incomplete member becomes a typed
  `:seon.test/population-unknown` value in its own slot, and the others keep their results. Only a failure of the
  query itself refuses the whole read. About 6 lines. Readiness (`problems/failed-tests`) already selects per
  member on counts, so it keeps working. "Missing evidence is typed unknown", never a blindfold over the others.

## 4. Drift: what remains when members are isolated by construction

The drift check exists to catch a body that changes JVM-global state or a program that changes under a body. In
the design each cause is removed where it arises:

| cause | removed by | check that remains |
|---|---|---|
| a body rebinds or arms Vars | the admission refusal in §3; such tests are PLATFORM | none on ordinary members |
| adoption during a body | the program-change lock, both halves (da9910fec, 2bd861329) | none |
| a member's program differs from its evidence | per-member loaded commit (§5) | typed unknown, not drift |
| a live cluster's projection atom is mutated (`restore-live-cluster-schema!`, `test.clj:1522`, `runner.clj:483`) | shrink-db row D (the projection derives from the db value) | none after row D |
| platform members (they arm and redef by design) | — | the ambient compare stays **only** for platform members in the platform JVM |

This deletes `ambient-snapshot`, `bounded-drift`, `drift-directions` and `ambient-drift` from the ordinary path
(`runner.clj:581-676`, ≈90 lines, 37 ms and 143 MB per member). Their two tests go with them
(`the-drift-snapshot-names-the-running-clusters` and `in-process-results-detect-worker-global-drift`). The
`instrument/state` compare proposed in testing-2026-09-24 is **rejected**, because at 19 ms it costs the same as
the snapshot. After row D, the restore family in `member-result` (`test.clj:1509,1540-1550`) and
`preserving-schema-registry` (`test_support.clj:816`) go too.

## 5. Evidence identity and reuse

A member's evidence is keyed by **(test symbol, reach digest on the seed, loaded commit, input digests)**.

- **Reach digest.** This is `runner/reach-digests` (`runner.clj:896`), computed over the seed. Because the seed *is*
  the loaded commit's rows, the digest describes the compiled Vars too. The declared seeds are reached edges
  (§2b), so their digests are inside it.
- **Loaded commit (new).** The member reads `loaded-commit-id` **under its read lock at body entry** and records it
  as `:seon.test.member/loaded-commit` (one attribute in `seon.test.run.edn`, about 8 lines). This is root ruling 5,
  "each member records the program it actually ran". An adoption between two members of one request
  (fix-adoption-excludes-tests §Broken) is then named, not hidden. If a member's loaded commit differs from its
  seed's, the result is the typed unknown `:seon.test/program-moved`, never green.
- **Input digests.** Unchanged, from `seon.test.cache/input-roots`.

**Reuse** requires a recorded green whose digests are all equal, and, for `:core` members, an equal loaded commit.
Red, unknown, unfinished or refused evidence never reuses. The existing selection-time `loaded-source-drift`
(`test.clj:829-897`) becomes a consequence of this rule and can be removed.

Agent (SCI-row) requests are out of scope here. They seed from their own branch commit as they do today, which
means they still inherit that branch's operational data. The §4b cluster level (base plus differing rows) is the
later fix. An agent's own tests are not claimed clean until then.

## 6. Bounds

- **Unchanged.** The 5 s body bound (`runner.clj:284` `duration-failures`, which needs `long` and `long-ms`), the
  request bound `:seon.test/check-time-limit-ms`, the actual-exit join, and "no further body after a live one"
  (`test.clj:1827`).
- **Changed: the adoption wait.** Today adoption waits up to the longest `long-ms` declared anywhere in the
  database, 1,200,000 ms (fix-adoption-excludes-tests §Broken). It becomes the cluster's
  `:seon.test/check-time-limit-ms`. No member of any request holds the read lock past that bound without being
  recorded unfinished. The refusal names the dial. About 2 lines in `call-with-program-change`
  (`cluster.clj:2210`).
- **Measured, not yet fixed: the harness's own cost.** One member measured 3,319 ms, of which the member itself was
  121 ms. `program-written-since?` (`runner.clj:946`) takes 124 ms to 1.6 s, and waits on the datahike-fork
  revisions patch (open-items §Scheduled). `blob/with-publication!` in `commit-results!` (`runner.clj:1612`) takes
  617 ms. Both are "record evidence" costs, so they belong to the runner owner. The target is ≤150 ms per member
  warm: seed reused, acquire about 55 ms, body, record, release about 9 ms.

## 7. Platform path

`bin/test --platform` (`bin/test:21`) boots committed HEAD under a fresh root. Then `bin/test-check --isolated`
runs **the same** `seon.test/run` request over `isolated-members` (`test.clj:1571`). Members there get the same
world: seed, branch and release. Two changes:

- **Platform membership is derived, not hand-listed.** Host owners declare `:seon.fn/platform "reason"`, the same
  pattern as `:seon.fn/destroys` (`destructive-reach`, `test.clj:259`). There are about 12 of them:
  `seon.cluster.boot/start!`, the `seon.cluster.process` owner, `instrument/apply!`, `restore!` and `remove!`,
  development reload, the konserve file-store opener, and the operator and `script/` entrances. A member that
  reaches one is platform. That replaces 230 per-test markers with about 12 owner facts. Tests that rebind
  `clojure.core` Vars are covered by the §3 refusal.
- **Per-member cleanup** there is the same `release-context!`. The platform JVM is disposable, but the ambient
  compare (§4) still runs there, so that one platform member cannot silently corrupt the next.

## 8. What agents gain from each piece

| piece | what the agent gets |
|---|---|
| seed checkpoint, `seed-facts!` | a clean base for task attempts, with the one facts writer boot uses |
| declared seeds | test data as a program row that the context walk finds and `callers` answers for |
| release joins graphs | retiring any agent is safe |
| per-member loaded commit | a record of the program each attempt ran, which merge and reuse can trust |
| custody in the member, public `loop-handle` | one rule for agent and host tests, and one handle constructor |
| function provider | virtual turns for evals and dry runs, without a paid call |
| owner changes 1–4 | explicit arguments any caller can supply |
| per-member `latest-results` | `problems` stays readable when one test is incomplete |
| rebind refusal, derived platform | the name of each test it cannot run, and the command that runs it |
| proof entrance | `done-when` and `my.test/prove` through one pipeline (≈130 ms), failures returned as data |

## 10. Smells found and justified, or open

- **Seed checkpoint.** It is not harness machinery: it is the agent path's attempt base (§4b) and the boot facts
  writer. Without it, every test inherits live operational rows (the issue).
- **The function provider** is production code in the agent path, not harness code. The local http-kit server
  stays inside the `ai_*` suites, which test the HTTP leaf itself.
- **Open for owner ruling.** Whether agent (SCI) requests should seed from base plus their differing rows now (the
  §4b cluster level, cross-owner, hours) or stay on their branch commit, as this design assumes.
- **UNVERIFIED.** That every turn test reaches a function provider through config alone; the credential rewrite per site;
  which of the 6 `agent-*` and 13 `cluster-*` branches on default are leaks; the per-site line savings of the
  sweeps; the seed's first-write cost. No test was run and nothing was edited except this file.

# Independent REPL audit — repl-auditor

## 1. Verdict

**No: this is not yet an unrestricted SCI REPL, and the extra machinery is already breaking valid programs.** SCI performs the actual evaluation, and ordinary definitions, changed arities, macros, letfn, records, multimethods, atoms and lazy sequences work in the tested corpus. But Seon vetoes namespace and persisted-Var mutations, rejects SCI record literals and ordinary response-shaped maps, fails to carry SCI's dynamic reader binding, loses a namespace change when its form throws, and splits a valid model-authored multiline string at backticks inside the string. Its model reader also classifies several valid column-zero Clojure forms as prose. Recording is not merely an observer: native mutation asks program facts for permission before changing SCI. The paid model path still writes an intent before evaluation, separately from settlement. A plain SCI loop already gets these language semantics right. Retain Seon's custody, observations, durable facts and presentation; remove the competing language policy.

### Observation/admission details that matter

The hot evaluation does **not** send its result through `seon.sci.admit/admit` to convert it into a storage tree. `evaluate` constructs `{:seon.sci.admit/value value :seon.sci.admit/record record}` directly. The retained value is real. Do not blame that 871-line admission namespace for a stage the current evaluator does not call. Bounds on printed output, contract input/output validation, source limits, definition analysis, db/with and final writer validation are separate checks.

One definition invokes an observed bind, may replace its root with a Malli wrapper, prints while observations remain open, analyzes source, and proposes facts. Later forms still execute when those facts fail. The ordinary examples did not lose definitions, including a closure over a local, but native mutation is separately refused **before** it reaches SCI. That refusal is the decisive violation of “recording never restricts the agent.”

### Performance and reply size

Both allocation measurements use `com.sun.management.ThreadMXBean.getThreadAllocatedBytes` on a **platform thread** and decimal MB. The plain control's main thread reports `virtual=false`. The Seon probe explicitly creates `Thread/ofPlatform`, reports `virtual=false`, and synchronously runs the production `code-sources` → `evaluate-sources` fold on the auditor's held private SCI context. It includes read, evaluate, observe, print and definition analysis. It excludes acquisition, final durable settlement, proc scheduling and MCP transport. Its own frame does not settle or propose a merge. This avoids pretending that allocation on an awaiting MCP caller measures work on the agent worker.

- `:ms 0` in the arithmetic and small-definition replies is **not end-to-end latency**: it measures the evaluation frame, excluding much of the read/derive/record/reply work. ## 5. What must stay

1. A persistent per-agent SCI context and explicit branch/world custody. SCI owns namespace resolution, Vars, macros, binding, records and evaluation; Seon owns which agent/context/database are used.
2. Serialized entrance and ownership until actual exit. A model reply and an MCP request for the same agent must not interleave forms.
3. A thin prose-to-comments/fence adapter. It must leave complete valid Clojure forms to SCI and must not inspect string contents as Markdown.
4. Producer observations of completed writes and macro expansions, source-span joins, and evidence for recording program entities. SCI alone does not store a Seon program or provenance. The pinned SCI observer extension is justified by that job.
5. One durable transaction for the pass record, plus separately executed effects the agent requested. Recording failures must remain diagnostics beside actual results. Program publication/merge can reject facts without vetoing experimental SCI execution.
6. Malli for published contracts and Seon's explicit supplied-world policy. The mechanism already delegates to Malli; remove only implicit language restrictions and redundant plumbing.
7. Live result handles, captured stdout/stderr, errors, measured costs, bounded lazy printing and schema-specific renderers. SCI evaluation alone supplies none of Seon's durable history/HTML/agent presentation requirements. Renderers must not execute proposed forms.
8. A small JSON-RPC adapter. JSON serialization is a transport requirement, not a second value printer for Clojure results.

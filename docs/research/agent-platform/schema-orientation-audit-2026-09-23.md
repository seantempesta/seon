# Schema orientation: data tells its own story

## 1. Answer first

**VERIFIED scope:** Seon already declares program/data maps, component ownership, symbol observations, and render functions in its schema population. This audit read all 210 EDN resources through `clojure.edn/read-string`, inspected their declarations, and traced the families below. The smallest proposed composition is the existing database query → declared entity renderer, with names retained as values and reverse relationships derived.

1. **VERIFIED — issue citations are the clearest wrong orientation.** `functions`, `tests`, `keys`, and `namespaces` resolve observed names to refs (`resources/seon/schemas/seon.issue.edn:8`, `:10`, `:16`, `:18`). `citation-index` converts identity values into entity ids (`src/seon/issue.clj:231`); `citation` returns those ids (`:253`). **UNVERIFIED proposal:** retain cited symbols/keywords as values; resolve current targets on reading. Do not make unresolved names a separate stored population.
2. **VERIFIED — deletion risk is real in the source, but not a measured runtime outcome.** Datahike `retract-entity` sweeps incoming refs (`reference-code/datahike/src/datahike/db/transaction.cljc:999`). Issue function citations are optional (`resources/seon/schemas/seon.issue.edn:53`); Seon's removed-definition obligations omit issue citations (`src/seon/db.clj:3861`). Publication explicitly retracts file-citation components when their file disappears (`src/seon/fn.clj:3224`). **UNVERIFIED:** an actual default-system deletion silently losing a citation was not run; other writer checks can refuse a particular transaction. This is a conditional loss mechanism, not proof every deletion succeeds.
3. **VERIFIED — the program graph already models observed tokens correctly.** Function calls/references/keywords and schema references are values (`resources/seon/schemas/seon.fn.edn:46`, `:63`, `:124`; `resources/seon/schemas/seon.schema.edn:88`). **UNVERIFIED proposal:** extend that convention to documentary citations; do not replace the working call graph with generic link entities.
4. **VERIFIED — some apparent back-links express different facts.** Agent assignment and namespace stewardship differ explicitly (`src/seon/cluster/agent.clj:186`, `:434`, `:453`). Conversely, creation writes both agent→runtime and runtime→agent, and agent→plan and plan→agent (`:207`). **UNVERIFIED proposal:** remove redundant component owner back-pointers through reverse queries; retain assignment and stewardship separately.
5. **VERIFIED — 2,968 of 3,369 declarations have no direct root `:description`; only 401 do.** The complete per-file/key census below distinguishes this syntactic fact from inherited documentation. Core examples include `:seon.fn/ns`, `:seon.ns/doc`, and `:seon.schema/key`. **UNVERIFIED proposal:** descriptions can supply primary semantic context when they explain meaning, lifetime, unknown/empty behavior, and a consumer; merely adding names or restating types will not teach an agent.
6. **VERIFIED — named component schemas are often good data modeling, not tables.** Namespace alias/import/refer values reproduce Clojure bindings (`resources/seon/schemas/seon.ns.alias.edn:1`, `seon.ns.import.edn:1`, `seon.ns.refer.edn:1`). Plan steps own nested steps without parent back-links (`resources/seon/schemas/my.plan.item.edn:60`). **UNVERIFIED proposal:** preserve these values; do not flatten them solely to reduce the schema-file count.
7. **VERIFIED — a renderer observation has both a symbol and a ref.** `:seon.eval/renderer` and `/renderer-fn` describe the same historic rendering operation (`resources/seon/schemas/seon.eval.edn:2`). `stored-record-content` pulls the ref back to a symbol (`src/seon/turn.clj:1409`). **UNVERIFIED proposal:** retain the symbol and saved shown text; query any current function documentation by symbol, without a second persisted ref.
8. **VERIFIED — infrastructure is not all disposable bookkeeping.** Manifest is a transient map, not a stored entity (`resources/seon/schemas/seon.fn.manifest.edn:8`); accretion assembles test and generated-check evidence (`src/seon/test/accretion.clj:298`); maintenance performs collection (`src/seon/maintenance.clj:929`). **UNVERIFIED proposal:** delete redundant request/receipt routing fields and parallel install reporting only after ordinary evaluation/test evidence carries their guarantees. Ten subsystems is not evidence that collection or test evidence can vanish.
9. **VERIFIED — most minimal families exist; unified task does not.** The census finds issue, plan-step, and scheduled-task shapes, not a canonical `seon.task` declaration (`resources/seon/schemas/seon.issue.edn:45`, `my.plan.item.edn:60`, `seon.schedule.task.edn:5`). **UNVERIFIED proposal:** one task model should replace issue/plan lifecycle duplication; scheduled execution still requires distinct scheduling facts.

### Description quality and context links

**VERIFIED good examples:** `:seon.ns.alias/local` explains the local symbol with `[clojure.string :as str]` (`resources/seon/schemas/seon.ns.alias.edn:10`); `:seon.message/about` says “The supplied subject identity token. A value that survives target deletion” (`resources/seon/schemas/seon.message.edn:33`); `:my.plan/current-step` explains that focus neither owns nor copies the step (`resources/seon/schemas/my.plan.edn:41`). These teach source syntax, deletion behavior, and ownership, respectively.

**VERIFIED weak examples:** issue `/status` says “The issues README lifecycle; a closed set.” (`resources/seon/schemas/seon.issue.edn:3`) without explaining transition authority; issue `/functions` accurately describes resolution but teaches the wrong token/ref choice (`:8`); call-preparation `/schema` has a substantial comment but no schema `:description` (`resources/seon/schemas/seon.call-preparation.edn:22`). Comments are not the requested description property. Error `:error/message` is also a different property; the census does not count it as documentation.

**UNVERIFIED proposal:** yes, key descriptions plus fully qualified keyword links can be the primary *semantic* context mechanism. The key remains identity, its declaration supplies constraints, its description explains meaning, and observed links identify follow-up queries. They cannot replace ownership refs, actual invocation edges, tested-input evidence, or a query's declared work bound. A short description should name meaning, producer, one consumer, and relevant absence/deletion semantics; expand linked documentation only when requested or relevant.

**VERIFIED dependency seam:** Malli `properties` reads schema properties (`reference-code/malli/src/malli/core.cljc:2586`); `form`, `children`, and `walk` expose authored structure and children (`:2579`, `:2600`, `:2616`). Existing `schema-form-refs` walks real schema references (`src/seon/render/ns.clj:139`); it does not establish description-string wikilink extraction. **UNVERIFIED:** end-to-end `[[qualified/symbol]]` resolution, description keyword expansion, reference-code symbol lookup, and agent-local renderer override inheritance were not demonstrated by this audit. Do not confuse schema reference traversal with prose-link support.

### Reproduction and landing limits

**VERIFIED reproduction:** the following read-only Babashka form reads every EDN declaration and reproduces the direct-description counts and exact missing key set. Run outside the system REPL; it does not load Seon or change runtime state. The appendix's key line coordinates were additionally obtained from a lexical pass over those same EDN files; every top-level parsed key set matched the lexical key set.

```clojure
(require '[clojure.edn :as edn] '[clojure.java.io :as io])
(let [files (sort-by str (filter #(.endsWith (str %) ".edn")
                                (file-seq (io/file "resources/seon/schemas"))))
      rows (for [f files [k form] (edn/read-string (slurp f))]
             {:file (str f) :key k
              :described? (and (vector? form) (map? (second form))
                               (contains? (second form) :description))})]
  (prn {:files (count files) :declarations (count rows)
        :described (count (filter :described? rows))
        :missing (count (remove :described? rows))})
  (doseq [row (sort-by (juxt :file :key) (remove :described? rows))]
    (prn (select-keys row [:file :key]))))
```

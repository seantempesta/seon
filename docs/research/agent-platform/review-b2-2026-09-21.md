## Exact replacement text

Replace §0's “simpler way” paragraph and §2a with:

> Acquire program definitions once, then process admitted differences. A database transaction that changes no program declaration updates the supplied database value without rebuilding a base or walking namespace interns. Use B1's existing changed-declaration facts for both publication and agent writes; source adoption identity alone does not cover both. Each agent forks once and retains that context. Before its next evaluation boundary, install changed/deleted program identities and changed resolver bindings while preserving its private Vars, closures, atoms and result objects. There is no private-state discovery pass on an unchanged program. The initial cost is proportional to installed declarations; update cost is proportional to changed declarations, resolver bindings and affected contracts.
>
> Select the loaded implementation by definition equivalence, as R4 requires. A JVM Var is a supported callable and follows root replacement, including through already-created forks; that is shared behavior, not version isolation. The implementation first proves direct and indirect override behavior and older-cluster behavior. Definitions that differ are interpreted under their supplied program. Do not bulk-copy every `ns-interns` entry as a function. Candidate-owned functions are armed before tests; accepted evaluated roots transfer only after writer acceptance, using the existing installation seam without re-executing source. Do not mutate a base-owned SCI Var shared by active forks when a replacement generation is required. The B1/A1 seams and these proofs precede removal of acquisition or arming state.

Replace §2b's deadline/executor paragraphs and §5 commit 1 with:

> Withdraw F-async as a required fork change. Flow owns proc lifecycle and error reporting; its timed get bounds waiting and neither cancels nor joins the transform. Keep one serial `:io` turn function, with the existing provider and SCI deadlines at their operation boundaries and computation on the carried compute executor. A deadline error identifies the admitted operation and turn. No subsequent wake may start work against that agent's context until the previous execution has actually exited; no late execution may settle a closed turn. Preserve the existing completion and stop evidence until replacement behavior proves these properties. The proc's pre-transform state cannot supply an identity minted inside the timed-out transform.
>
> First simplify source selection and the shared evaluation/settlement tail, retaining the distinct wake-answering and continuation rules. Then probe deletion of launcher and watchdog plumbing at the actual operation seams. A Flow change is considered only if a missing dependency guarantee remains after those probes; changing which executor runs an abandoned task is not that guarantee. Do not relabel blocking IO as `:compute`.

## Verdict

The deletion direction is sound for duplicate history assembly, namespace presentation ladders, wake relay and revision packages, and the JVM Var/Brotli premises are verified narrowly. The plan is not ready to implement: it substitutes whole-context discovery for incremental installation, equates program identity with database identity, treats abandoned execution as recovery, and removes socket completion while multiplying rendering by tabs. Correct those algorithms and the incomplete caller/reset order before committing to line targets. Prefer the existing admitted-change, read-evidence, SCI installation and IO-completion seams; none of the findings requires a new cache or a parallel mechanism. The 24,500/20,000 targets remain ambitions, not evidenced estimates.

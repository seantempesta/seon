## Exact replacement text

### Replace §0 in full

**We built repeated work around facts the system already had.** A database value already carries its compiled schemas, yet acquisition rebuilt them; the recorded fixture spent 3,995.96 ms of 4,647.8 ms doing that reconstruction [A1 §1]. Tests already had an in-process execution path, yet the launcher copied stores and started worker JVMs [B4 §0]. The simpler design carries the compiled value into a branch and SCI context fork, then runs the selected work in the hosting JVM.

The largest opportunity is deciding what must happen after a change. A docstring edit should process the edited declarations. A contract change must also process affected callers. An ordinary data transaction should rebuild neither the program nor its contracts. Publication, validation, acquisition and test selection must agree on those dependencies; deleting a check before that agreement would make the system smaller by losing a guarantee.

The recorded repeat docstring edit took 2,723.412 ms and the no-change request took 264.119 ms [publication data pack §5]. These are historical measurements, not this session's baseline. B1 proposes narrower work; the fresh implementation session will measure the same cases before and after. The source-size target remains an aspiration until the disjoint file counts and the new merge/write-back work reconcile (§2b).

Three proposed shortcuts are not yet justified. Past test execution does not establish every dependency of a changed program. Shared mutable JVM Vars do not preserve an older cluster's program merely because the database was forked. Aggregate callee timings do not establish a caller's self time. We will retain those guarantees while simplifying their existing owners.

**Compute derived data where its inputs change, carry it with those inputs, and read it thereafter.** Cold construction processes the initial program. Later changes process affected declarations and their dependents. Rendering and test execution still cost the data rendered and the work executed; those costs must be stated honestly.

| Concern | Computed when and carried where | Work and evidence |
|---|---|---|
| Program facts | Analyze changed inputs using clj-kondo's cache; reconcile through the writer; carry identities from the report into adoption | Changed declarations and affected callers. B1's direct-write alternative needs resolution against the report-based ruling [B1 §2a; goals §3]. |
| Compiled contracts | Construct at boot; update changed declarations and their reverse dependencies; carry the projection on database/context values | Acquisition is a read. All constructors must establish carriage before A1 removes its fallback [A1 §5b]. |
| Candidate/test isolation | Acquire a branch and SCI context from the named program value | Branch/fork cost plus actual changed definitions/private objects. Shared JVM roots require an isolation proof [B2 §2a; goals R4]. |
| Read currency | Retain dependency evidence at evaluation; compare through A2's one authority before rendering | Retained reads and their dependencies; conservative `:all` evidence can cause replay [A2 §1–2]. |
| Tests | Select from current dependencies and each member's tested basis; record through the existing runner | Changed dependencies plus selected work. Observed reach informs diagnosis; it does not prove an unexecuted path safe [B4 §2; goals E2/F1]. |
| Errors/tasks | Validate the declared return contract; record the error; admit its task at the task writer | Declared contract and affected subject. Missing evidence is unknown, never completion [B3 §2]. |
| Profiling | Time through the existing wrapper; retain definition identity and branch attribution | Inclusive duration only until stronger attribution is proven. Measure final overhead, flush cost and failure behavior [C1 §1–2; profiling pack §9]. |

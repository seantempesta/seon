## 3. Gates and the actual current path

The current successful route is approximately:

`agent/submit-source!` → reply segmentation/reader → frozen source plan → `turn/resume-turn` → `fork-for-turn` → per-form acquire/read → reader-directed schema path or Seon-directed `do` or SCI → snapshot/analysis/admission → render → install/test gate → speculative `db/with` for later forms → prepare receipts → one settlement transaction → install committed rows → offer run report → read saved observation → MCP rendering.

* **Entry gate is not the advertised pre-evaluation policy.** `admit-program-change!` runs after SCI changes Vars (`eval.clj:987`); it restores rejected changes. `missing-contract` explicitly says no entry dial exists (`:2460`). Its non-macro/non-host function check and post-eval arming (`:1007`, `:1016`) are real. There is no implemented general schema/test/test-first `:gate`/`:warn` switch on this route. A rollback cannot undo an initializer's external effects. The source tests intentionally enforce this current restricted behavior (`test/seon/sci/entry_gate_test.clj:85`, `:120`, `:242`).
* **Install gate is real but singular.** `turn/gate-function-install:3398` only enters for a function row with a spec; otherwise a function row is removed (`:3470`). `evaluate-candidate` (`eval.clj:5103`) tests the retained candidate in a disposable branch/context; it does not simply re-evaluate the candidate function to discover its result. Preserve that distinction and context ownership.
* **Test gate is not a language parser.** `fn/gate-set`, `accretion/auto-check:190`, `gate-report:337` select and combine evidence. Skipped effectful/non-generatable checks are explicit; zero failures can install even with zero selected tests. `run-candidate-test` (`eval.clj:5026`) separately re-evaluates a test declaration and invokes the real runner. Keep dependency/test evidence and Malli validation, remove no gate merely because it follows evaluation.
* **Arming in two worlds is not necessarily duplicate work.** Runtime candidate arming and committed/acquired-context arming serve different contexts. Delete redundant work only after proving identical function, contract and context inputs. Preserve generation-aware restoration (`eval.clj:712`, `:830`) and private-layer regeneration (`:3320`). A shallow SCI fork does not roll back shared atoms or arbitrary host effects.
* **“One reader” currently means one facade, not one read.** Reply segmentation reads; `one-event` reads the retained string again; `analyzed-rows/source-rows` invoke kondo; the analyzer reparses kondo nodes; signature code invokes JVM `read`. A necessary independent static kondo pass is not a second evaluator, but the duplicated execution reads and handwritten signature grammar are avoidable.
* **JVM MCP is another entrance, not this same recorded loop.** `script/seon/dev/mcp.clj:370` reads one source form then calls host `eval`; `:403` sends SCI source through `evaluate-source!`. A target claiming all entrants share recording still needs to compose the JVM evaluation stage into the shared owner. Do not conflate today's JVM inspection tool with agent SCI execution.

### The four reported failures, reconciled

1. **Nested `defn`:** historically missed; the audited source now has real intern observation and a specific nested-`do` workaround. ## 5. One design: shared syntax, definition-time observation, exact provenance

**The owner's ruling supersedes the former A/B/C options.** There is no after-form observation option and no weaker same-form arming mode. The design is one source reader, SCI-owned mutation events at the actual operation, kondo-owned static analysis, one candidate population, one settlement and a total reply. All nesting goes through SCI. No list of permitted enclosing forms exists.

**Proof result:** this design can make observation total and matching exact. The stronger assertion that *every* executed definition has a unique kondo definition keyed only by namespace/name/original-source span is false. The pinned implementations do not supply that invariant, and arbitrary Clojure macros make it impossible from the original text alone. The counterexamples below are specification boundaries, not a workaround list. I cannot honestly mark all C01–C19 green under that assertion. In particular, definition-time observation does not turn an unknown macro into known static structure or serialize a closure's captured objects.

### 5.1 Read once means once, including kondo

Do not silently redefine “one read” as “one execution read plus kondo's second parse.” Current kondo `analyze-input` calls `p/parse-string input` at `reference-code/clj-kondo/src/clj_kondo/impl/analyzer.clj:4477`; its parser builds rewrite-clj nodes (`reference-code/clj-kondo/parser/clj_kondo/impl/rewrite_clj/parser.clj:8`). Its existing parsed-node analysis entrance is `analyze-expressions` (`impl/analyzer.clj:4350`), not a public edamame-form entrance. Merely passing the same string to two readers violates ruling (1).

The one-reader design therefore needs a **shared syntax product at edamame's reader boundary**, not `pr-str` followed by another parser:

* Retain the immutable submitted source and a source identity, with exact half-open start/end offsets and the reader's line/column coordinates for each syntax occurrence. Use one declared offset unit; translate coordinates using one source line index. Do not compare UTF-8 offsets to UTF-16 columns. Identical source text in two submissions can share static analysis but still has distinct evaluation observations.
* While edamame consumes that text, produce both its normal evaluated-reader form and a lossless syntax tree. SCI receives that exact normal form. Kondo receives a projection of the lossless nodes into its existing node representation, retaining the **same occurrence/span identities**; it does not parse text again. The text remains kondo's source of locations and diagnostics, not a reconstructed string.
* `edamame/core.cljc:72` supplies `:postprocess` with `:obj` and `:loc`; `impl/parser.cljc:821` captures start/end around `dispatch`. This is a useful seam but **not already a lossless syntax-tree API**. Reader macros resolve/desugar before `:postprocess` (`:795`, `:827`, `:895`); syntax quote, metadata, selected reader conditionals and tagged-reader output cannot be recovered faithfully just from the final Clojure value. Preserve their syntax at dispatch, before that information is lost. A kondo bridge built only from `api/coerce` (`hooks_api.clj:105`) cannot prove exact-source equivalence.
* Export a maintained kondo parsed-node entrance around `analyze-expressions`, retaining `analyze-input`'s analysis setup and finalization. The adapter changes representation, never recognizes `defn`/`do`/`register!` itself. Kondo keeps its own language analysis. This is a necessary dependency change, not an existing installed seam.
* Read one next top-level form under SCI's actual current resolver, analyze/evaluate that form, then read the next. That is a reader boundary, **not the time at which definitions are observed or armed**. Namespace changes inside a form do not retroactively change how its already-read syntax resolves. Kondo gets the actual SCI analysis namespace/alias context as an explicit input; it must not invent it from top-level `ns`/`in-ns` guesses. Its current `analyze-in-ns:610` takes a quoted operand structurally and `analyze-known-call:3383` only treats it as a namespace switch at top level.

Maintain one kondo analysis context for the run, accumulating all original syntax and actual expansion inputs and performing its whole-input finalization once; do not create a fresh analysis for each submitted form or reconstruct source preludes. Preserve the namespace/alias context at each SCI-analyzed occurrence, not merely the run's initial namespace. Forward-reference results are finalized against that complete candidate. `analyze-expressions:4350` currently initializes a synthetic namespace itself, so exporting it unchanged is insufficient; the bridge must accept the supplied context and retain analysis configuration.

The bridge is required to meet the strict wording. It has not been implemented or verified; its price is included in P2. There is no truthful small-patch claim that the present public reader APIs already meet (1). Runtime `read-string` creates a *new* source input; it cannot be prohibited while promising ordinary Clojure. Read each such input once and give it a new source identity. A string is never silently reread to recover facts about an earlier submission.

### 5.2 Observe and arm at the operation, inside SCI

Carry one evaluation observation sink and mutation policy in SCI's runtime context, inherited by its fork and scoped to the evaluation. Its accumulation belongs to that context/evaluation, not a global registry or another atom beside the connection. Pass native result/root, metadata, origin, and the precise operation to it. The consumer folds events into candidate entities; it never discovers definitions by comparing namespace snapshots after a form.

The **smallest def seam** is explicit: add an immutable origin argument to the definition node at `sci/impl/analyzer.cljc:832` / `:877`; consume it in `impl/evaluator.cljc:25`. After evaluating the initializer and metadata, prepare/validate the actual contract and wrap the candidate root **before it is bound**; after the successful mutation, record the observed Var and root before returning from the node. Thus the next expression in any `let`, `when`, `do`, function or macro expansion sees the armed root. The disabled `#_(defn analyze-defn ...)` is not a second seam to implement. No existing hook does this: `:built-in-call-observer` (`analyzer.cljc:1743`, `:1773`) reports a native callee symbol before a call, not definition identity, root, metadata or successful mutation.

A definition's prepare phase may refuse a malformed contract before installing the root; a later recording/gate/renderer failure must preserve the produced value and attach diagnostics. Do not run tests in the definition callback. Retain existing rollback/custody and loaded-identity fences; they are not replaced by the observation sink. `my.program` changes must use the same candidate and mutation events, rather than transacting against a connection that cannot see the run's earlier definitions. Render evaluation enters with a read-only mutation policy enforced at these same owners.

**Concurrency proof obligation:** the current `eval-def` mutates a Var inside `swap!`'s function (`evaluator.cljc:46`). A callback inserted there can run more than once under retry. A callback after the swap must receive the root/metadata that operation wrote, not dereference a possibly later root. The fork review must prove the mutation's linearization and once-only event under concurrent access; a context-local sequence assigned after the write is not proof of global write order. No new global lock or scheduler is proposed. Host/JVM mutation bypassing SCI's owners is outside this observer's coverage and cannot be claimed observed without instrumenting that owner too.

For a directly authored declaration, define the static key as **(source identity, reader occurrence/full span, namespace, name)**. Both consumers carry the reader's origin, so matching is an equality lookup, not offset inference or a search for the closest symbol. The kondo fork must explicitly retain/export this origin in `namespace/reg-var!:161` and `analysis/reg-var!:87` and carry containing-definition origins into usage records. Today `analysis/reg-var!` selects a fixed field set; arbitrary node metadata will not automatically survive into analysis. This is part of the priced bridge, not an assumed extension point. Definition event identity is separate: **(evaluation identity, mutation occurrence)**. Repeated execution of one declaration (a function called twice, a loop) legitimately produces multiple events pointing to one static declaration. Redefinitions at different source occurrences point to different static keys; the writer uses the actual final mutation, retaining the observation history.

For generated declarations, the origin includes **(macro call-site origin, expansion occurrence/path)**. All generated declarations retain the call site's source span in both consumers, but that span is the *origin of generation*, not a claim that generated definition text occurs there. Namespace/name/span alone cannot distinguish two generated definitions of the same name at that call site. The expansion path is required identity, not a tie-break heuristic.

Kondo owns arities, lexical usages/call edges and authored contract syntax. SCI owns the actual evaluated metadata/contract value; Malli owns compiling it. A computed contract cannot be inferred from syntax alone. Static call edges are not a claim that a dynamic callee ran, or that every computed invocation has a statically resolvable target.

**Our macros:** use kondo's existing analyzer / `lint-as` only when its declaration structure genuinely matches. Otherwise use an analyze-call hook with explicit origin propagation. `lint-as` does not execute a macro and cannot prove its expansion. Independent hooks that happen to assign the same call-site span are also insufficient: their generated declaration origins must correspond to the actual SCI expansion. The strict reconciliation path supplies **SCI's already-produced expansion** to kondo's node analyzer, preserving generated occurrence identities; the hook is an adapter, never a second macro execution. Analyze each expanded occurrence once in its actual SCI analysis context. Syntax-to-node conversion is not rereading source. These expansion values are additional compiler input linked to the original text, not additional authored source.

**An unknown third-party macro:** SCI still executes its normal expansion and records every definition at its def node. Kondo's present catch-all (`analyzer.clj:3176`) analyzes the call's children; it does not know the hidden definitions. The design feeds the actual expansion to kondo through the same generic expansion entrance. It adds no macro-name allowlist. For forms within both analyzers' supported grammars, kondo analyzes those nodes with explicit origins. For example, its `analyze-def:1852` analyzes the initializer and takes arity from its analysis metadata (`:1914`–`:1955`), so a generated `def` of a syntactic `fn` need not masquerade as a handwritten `defn`. Merely being executable in SCI is not proof that kondo can infer every fact about the expansion. If it uses an unsupported host construct or contains opaque objects, static structure is recorded as unavailable with its actual reason; no fabricated source entity and no rejection of the evaluated value.

That last case is **not** a proof that kondo analyzed a nonexistent declaration in the original text. If ruling (3) requires original-text-only analysis with a unique namespace/name/span key for every unknown macro, it cannot be met. Reconciliation requires the expansion input and generated origin above. Calling absence a successful match would conceal the very defect this audit is meant to remove.

### 5.4 Runtime definitions and the limits of the requested invariant

The operation, not a failed source search, determines provenance. Runtime `eval` enters through `sci/impl/namespaces.cljc:1569` / `impl/utils.cljc:262`; runtime `intern` through `namespaces.cljc:610`. Such an entity records that it was defined at runtime, its observed identity, mutation operation and evaluation, actual metadata, and a live-root handle. **It has no authored source-form field.** A source call-site reference is allowed as causal evidence, not substituted for definition source. Even if a runtime form carries copied or forged `:line` metadata, the operation provenance wins. If the caller supplies a read-origin-bearing form, retain that origin as evidence without pretending an `intern` initializer is source code.

Source-backed, macro-generated and runtime-created origins are a deterministic partition by production mechanism. They are not a list of forms that fail. Every successful mutation produces an entity/observation; static facts may only be asserted when derived from real analyzable input. Source absence is represented by an absent source field with a declared runtime-origin fact, never stored nil, guessed text or an “unindexed” refusal.

Four counterexamples delimit what can actually be proved:

1. **No second parse with today's APIs:** edamame returns read values; kondo `analyze-input:4477` independently parses text. The lossless reader product and parsed-node entrance are necessary changes. `postprocess` plus `pr-str` is not equivalent: `#_`, reader conditionals, alias spellings and tagged-reader values lose original syntax.
2. **No universal unique span join:** a macro can expand one `(make-f)` into `(do (def f 1) (def f 2))`. Both definitions have the same namespace/name/call-site span. Even a perfect hook produces two entries at that key. Separately, `(make-f)` can compute a name with `gensym` or external input; original-text-only kondo cannot know that value. SCI's macro application at `analyzer.cljc:2083` executes arbitrary code. The actual expansion and generated occurrence identity are indispensable.
3. **No complete static facts for arbitrary runtime values:** `(intern *ns* (symbol (str "f" (rand-int 10))) supplied-function)` supplies neither definition source nor the function's body. `sci-intern` receives a value and metadata, not AST (`namespaces.cljc:610`). Runtime classification meets ruling (4), but cannot manufacture kondo arities/calls/contracts. It still records the actual definition and value.
4. **No general closure replay from a nested def substring:** SCI explicitly implements lexical closures (`analyzer.cljc`'s `:closure-bindings`, `interpreter.cljc:45`); its own `test/sci/core_test.cljc:189` covers `(let [x 1] (defn foo [] x))`. The live root is usable and its definition observable, but source span alone lacks `x`. Replaying the enclosing form can repeat arbitrary effects; serializing a captured socket/atom/host function is not a general solution and violates the no-private-object-recovery law. Fresh acquisition of every such closure is not proved by this design. Preserve runtime lifetime/replayability as explicit data; do not claim source availability implies replayability.

These refute the universal assertions, not the requirement to observe **every** supported definition. SCI's own language limits remain distinct: corpus `m-definterface-*` fails in plain SCI too. No Seon admission policy can make that a proven SCI implementation.

### 5.5 Construction proof and C01–C19 coverage

### 5.6 Complete the same pipeline through the reply

The shared read product enters SCI once per submitted top-level form; SCI handles all nesting. Mutation events and exact static facts feed one candidate fold. Pre-bind contract arming belongs to execution; entry policy retains malformed authored contracts as data, and the install/test gate judges the completed candidate. Gate refusal may roll back program mutations without erasing the values already produced. The static bridge must avoid counting both an authored macro declaration and its expanded definition as two independent installed entities: the executable node's explicit origin is the join key, and source-level analysis is linked evidence. Preserve distinct expansion occurrences instead of deduplicating by symbol or span.

Settlement receives the candidate's final entities plus ordered observations and evaluation receipts. It derives namespace upserts from **every required namespace reference in the final owning transaction**, including receipt start/end, definition owners and binding targets, using their declared schemas. One writer transaction validates full owners, contracts, digests and reference closure; no namespace is selected from segmentation. Speculative immutable database values may support later forms, but a refused speculative update is explicit. `my.program` mutations join this candidate rather than independently publishing mid-run.

Keep the completed-prefix envelope independently of settlement: native values, handles, output, duration and diagnostics remain separate members. Rendering failure uses the floor and adds a diagnostic; gate, recording or installation failure retains the held value/prefix. A double settlement failure still answers the live submitting port with held evidence and truthful commit status before fault escalation. No fallback store or retry loop is needed. Process death remains the physical limit identified in C18.

**Already suitable:** SCI's reader/evaluator and retained forks; generation-aware custody/restoration; actual metadata used by `definition-row` (`eval.clj:926`); kondo's nested analysis; the schema delta owner (`schema.clj:3603`); compiled Malli contracts; disposable gate worlds; normal batch settlement and refusal receipts; replies reading the returned settlement basis (`cluster/agent.clj:815`, MCP `:446`). Compose these. Delete the source-identity guesses, duplicate readers and `do` evaluator, singular-declaration interfaces, return-equals-registration-key test, namespace predictions, swallowed speculative refusals and empty error closes catalogued in §§1–4. P2–P4 price those deletions without replacing them with an enclosing-form recognizer.

### 7.1 The value, the owners, and the transaction boundary

Call the value **an evaluation batch**, with proposed Malli schema **`:seon.eval/batch`**, declared in the existing `resources/seon/schemas/seon.eval.edn`. A registry-source search found no existing declaration under that name. It is an **in-memory open map**, not a new database entity, run identity, object, scheduler or registry. Existing `:seon.turn.loop/evaluated-sources` (`seon.turn.loop.edn:141`) and `:seon.sci.eval/evaluation` (`seon.sci.eval.edn:33`) are the structures it replaces/composes; current `:seon.repl/response` is already printed text (`seon.repl.edn:158`), so it cannot be the native value passed between stages.

The target owning shape is explicit below. Names marked new in the following paragraph are design declarations, not claimed installed contracts. `[:ref …]` supports the recursive stage contract; compile with Malli's `schema` / `function-schema` (`reference-code/malli/src/malli/core.cljc:2596`, `:3130`).

```clojure
;; Target registry member :seon.eval/batch; no :seon.db/attributes property.
[:map
 [:seon.eval/input :seon.eval/input]
 [:seon.eval/read-stage [:=> [:cat [:ref :seon.eval/batch]] [:ref :seon.eval/batch]]]
 [:seon.eval/evaluate-stage [:=> [:cat [:ref :seon.eval/batch]] [:ref :seon.eval/batch]]]
 [:seon.eval/entries [:vector :seon.eval/entry]]
 [:seon.eval/effects [:vector :seon.eval/effect]]
 [:seon.db/db {:optional true} :seon.db/database-value]
 [:seon.db/connection {:optional true} :seon.db/connection]
 [:seon.sci.eval/ctx {:optional true} :seon.sci.eval/ctx]
 [:seon.agent/id {:optional true} :seon.agent/id]
 [:seon.turn/id {:optional true} :seon.turn/id]
 [:seon.render/profile :seon.render/profile]
 [:seon.eval/diagnostics [:vector :seon.error/base]]
 [:seon.eval/commit {:optional true} :seon.eval/commit]]
```

**New members' precise responsibilities:** `:seon.eval/input` is the declared union of exact submitted text plus file/starting-world coordinates, an already-read syntax product, or a resolved body/data input with runtime origin. It carries the input itself, never instructions to reread a stored form. `:seon.eval/entry` is an open map with an ordinal, the shared reader product/origin from §5, optional native `:seon.sci.admit/value` under existing `:seon.schema/value`, optional evaluation error under `:seon.error/base`, ordered diagnostics, timing/read evidence and optional final shown text/handle. The value key's **presence**, including nil/false, means evaluation produced a value. Before execution it is absent. Do not require a namespace for schema-only/runtime inputs; observed namespaces are optional evidence. `:seon.eval/effect` is the tagged union of the actual operations in §5.2 (Var reserve/bind/root/meta/unmap, namespace/binding changes, register/unregister), each with mutation ordinal, exact origin and producer-owned payload; its tag names an operation, never an entity kind inferred from a form. `:seon.eval/commit` carries attempted/applied/durable evidence and the writer's refusal, with no fabricated basis on failure. `:seon.eval/diagnostics` holds ordinary flat errors. These leaf declarations and consumers must land together; the sketch is not a claim that missing named schemas compile today.

Read/evaluate callables are **stage values**. They use named Malli contracts and the live host-object roster already held by the execution, never enter stored transaction data, and need no plugin dispatch table. The default reader is §5's edamame product; the default evaluator is SCI. An already-read form or resolved test body supplies that input stage directly, never `pr-str` → read. File bytes are a new input with their own origin. Static analysis is one kondo context over the batch's exact original syntax plus observed expansions, with explicit occurrence identities. No stage walks enclosing forms to discover effects.

Grow the existing owners in place: `seon.turn/evaluate-sources` becomes the batch fold; `seon.sci.eval/evaluate` is its SCI evaluation stage; `seon.turn`'s existing receipt/settlement functions are the single record owner; `shown-result`/`seon.render.value`/`seon.repl` remain the print/response owners. The Flow proc owns scheduling and the retained context, not the fold. No `pipeline2`, generic runner framework, second acquisition roster or trampoline through a second agent graph is needed. Private helpers take this value or its declared projections; wrappers that merely translate old envelopes disappear with their callers.

Each successful evaluation appends its entry **before** invoking a gate, renderer, writer or adoption callback. Child render entries use the same fold and extend their parent batch; they do not publish their own receipts. Static and gate facts are additions, not replacements for `:seon.sci.admit/value`. The bounded value renderer runs once at the edge; its exact shown text must be ready for the owning settlement that records what was shown. Thus “record → print” means native observations first, presentation only at the edge—not a second database transaction to save text after replying. No validation traverses an arbitrary live result; validating its `:seon.schema/value` slot is not printing or realizing it.

**One transaction means one terminal settlement per batch in one custody branch.** It contains all accepted program mutations, namespace upserts, receipts, diagnostics, fault links and participant-produced record data. The schema registration and `my.program` mutation calls contribute to that same candidate. Test completion/capture owners produce transaction data; they do not each commit the same evaluation again. Entry/reservation and branch-lifecycle facts that must exist before execution retain their durable owner. A refused program proposal can be stripped from the held batch and recorded as refusal evidence through that same writer; an aborted transaction applied nothing. If even that evidence transaction refuses, return the held batch with both failures and no commit claim. This is failure recording, not re-evaluation or a retry loop.

This is **not global atomicity across connections or external effects**. A gate child on another branch has its own batch/settlement; its evidence is an input to the parent's gate. Explicit arbitrary host/database I/O and a filesystem rename cannot be rolled back by a receipt transaction. Preserve their effect/receipt evidence and durability requirements; do not silently buffer arbitrary `db/transact!` calls and change Clojure semantics. Ordinary accepted program writes owned by this pipeline are accumulated once. If “one transaction” instead means every explicit user write, child branch and file rename is one atomic operation, the current dependencies cannot supply it; that larger promise is not hidden in these prices.

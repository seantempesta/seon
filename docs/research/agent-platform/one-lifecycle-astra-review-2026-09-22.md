## 2. Walk the five callers with actual types

Common allocation, when needed: `registry/branch! {:seon.store/store store :seon.store/branch b :seon.cluster.registry/from C}` → creation result; then `(store/open-branch! store b)` → connection `c`; capture `(db/db c)` → database `X`; then `(sci.eval/fork-cluster-ctx base X c projection-state arm-request)` → ctx; `(sci.eval/acquire! {:seon.sci.eval/ctx ctx :seon.db/db X})` → acquisition report, **not ctx or handle** (`registry.clj:193`, `store.clj:542`, `eval.clj:2300`, `:2202`). The composer retains ctx and checks the report before returning the D1 handle.

1. **Live turn.** Existing `(agent/acquire-context! handle agent-id)` returns the retained per-agent ctx, while the handle supplies connection (`agent.clj:682`). Feeding a connection to `acquire!` where it expects `:seon.db/db` is wrong; dereference at the chosen evaluation boundary. `fork-for-turn` preserves entering custody, so changing only its `:seon.db/db` does not move writes (`eval.clj:2120`, `:2141`). Live callers borrow the cluster connection and release no branch. They still require the common program-acquisition/refusal/adoption logic.
2. **Isolated agent.** Capture C from the parent's immutable db, allocate a fresh branch b, open b, repoint the context/environment and assemble the existing handle shape (`D1:75`, `:79`). C is accepted as registry `::from`, but **not** as the `open-branch!` branch argument. The existing `acquire-context!` wants an agent ID, not C or a request. A caller conversion is mandatory. The handle must not inherit the parent's context-state map entries, fault writer or armed unrelated agents (`eval.clj:2329`; `D1:85`). Arm only the selected agent after start admission.
3. **Test.** Capture one execution C for the run; allocate each isolated member from C, not from the preceding test's mutated head (`B4:158`). Selection returns symbols; resolve each under the matching ctx into a test Var before `run-test`. Hand `{ctx, :seon.db/connection c, :seon.test/var v, time-limit}`: `run-test` does not extract runner custody from `ctx` (`eval.clj:3208`; `runner.clj:687`). Keep recording connection r outside body custody; `(run v r options)` currently distinguishes it (`test.clj:537`). Calling r's writer inside c's dynamic custody can refuse cross-connection use (`db.clj:4537`). Record after execution scope exits, then release/unlink only after actual termination.
4. **Save.** A persistent staging branch already has its held connection. The proposed entrance unconditionally allocates another branch; opening staging again refuses (`store.clj:559`). Acquire on the held staging handle, freeze its exact candidate commit S for selection, and create disposable test children from S. Indexing needs a prior db plus admitted analysis inputs/projection, not an unstructured connection (`fn.clj:3323`, `:3371`). A staging update during tests cannot silently change the tested subject. Promote only the exact tested program under default's writer guard, then reload at the shared boundary.
5. **Merge.** Capture base B, source C and destination H; derive the proposal; allocate intermediate S from H; apply portable program rows; acquire **on S**. The design's entrance would otherwise allocate yet another intermediate after one already exists (`L:28`, `:41`). Only member isolation needs child branches. `source/changed-identities` cannot take B/C/H as three UUID arguments: its middle argument is a publication result. `gate-sets` needs db plus symbols; `exact-replacement-tx-in` needs shapes and destination current row with `:db/id`, not a digest map (`program.cljc:1030`). Named accept keeps C/S available on red/conflict; unconditional unlink loses repair and evidence (`D1:82`, `:185`).

No §1 caller needs dropping. Drop the requirement that all acquire operations allocate branches. Branch allocation, context acquisition and owned release compose, but their resource ownership is not identical.

## 3. Live turns belong inside acquisition, outside allocation

Keeping live custody on the cluster connection is right. Excluding live turns from the acquisition owner is a second path and contradicts today's public function: live acquisition is what `agent/acquire-context!` already does (`agent.clj:683`). Reuse the owner with a supplied/borrowed handle; use registry/store only when requesting new isolation.

A live agent needs the same matched db/projection, loaded-versus-selected program comparison, affected-call installation, named refusal and private-context retention as an isolated agent. `acquired-database?` already compares committed value identity (`eval.clj:2184`); `acquire!` currently rebuilds on a different database (`:2211`). Refactor that owner instead of adding a context cache. Ordinary data writes may change the commit while requiring zero program installation (`B2:113`); distinguish “constant-time unchanged check” from “literally zero work.”

Commit identity alone is insufficient for a retained branch: another cluster can reload the JVM while that branch's commit stays unchanged. Loaded-program identity must invalidate reuse at the same shared boundary; private override changes also affect the result (`B2:121`, `:125`; `SCI/core.cljc:112`). No reload under any admitted evaluation is the owner's rule (`docs/seon/architecture/clusters-branches-contexts.md:51`), superseding B2's acceptance of an in-flight reload tear. Serial turns per agent do not serialize all agents, MCP evaluations and tests. Add that cross-surface proof before claiming isolated execution.

## 4. Save-time gate: real branch, wrong promotion and feedback today

**Yes, staging must be a real same-store Datahike branch.** It isolates rows, schema state and branch writes; it does not isolate files, blobs, roster, GC, flock, loaded classes/Vars or mutable host objects (`A2:118`; `DH/versioning.cljc:212`; `SCI/core.cljc:345`). Filesystem lane ownership still isolates edits. The gate must preserve destructive/host-bound classification; “tests as agents” grants no store/JVM confinement (`B4:156`, `:170`).

**No force is needed to install program rows on default.** Default is an open live connection with continuing operational facts. The existing adoption path already applies selected rows through `index!`/`db/transact!` on that connection (`cluster.clj:2070`, `:2105`; `fn.clj:3404`). Reuse its prepared reconciliation with a writer-side expected tested H guard and final validation. The current sequence of schema/program/adoption transactions is not yet one atomic acceptance; consolidate the acceptance operation rather than declaring this path finished.

`force-branch! [db branch parents opts]` replaces the entire destination value, requires exclusive store write access and leaves existing connections stale (`DH/versioning.cljc:323`). Its expected-head check is explicitly **not** cross-operation CAS against another writer (`:331`). Replacing default with stale staging could also overwrite operational facts with inherited copies or test writes. Source publication's refresh monitor only coordinates its callers (`source.clj:370`); it does not stop default's ordinary writer. Use a guarded transaction of the program delta; any H movement refuses/recomputes rather than weakening the tested basis. Multi-parent acceptance uses the D1 merge-writer adaptation below.

**“Red → failures to editor” has transport pieces, but no pre-advance gate today.** Hook `publish-source-paths` launches `bin/seon init --dev … --changed …` (`bin/seon-hook:1533`). Operator `request-form` sends `boot/request!` over the live prepl and decodes its map (`script/seon/operator.clj:138`, `:166`, `:173`). Boot's `:init` calls `refresh-source!`, then keeps only source commit and cluster name (`src/seon/cluster/boot.clj:434`). The hook calls `bin/test-check` **after** a successful commit result; timeout explicitly says adoption remains converged (`bin/seon-hook:1566`, `:1582`). Publication and checks are disabled (`.claude/seon-hook.edn:52`, `:58`).

Make that existing prepl request own prepare → immutable candidate → test → guarded accept → reload, and return the recorded run/refusals directly through the operator/hook result contract. Preserve the failing identities and recording authority, not just commit ID. On red, no default row advance or reload; retain staging for repair. This needs changes at both boot result selection and hook result validation (`bin/seon-hook:1486`), not merely replacing the subprocess with a socket call. B1's old hook row promises an adopted edit (`B1:379`); L adds a gate and must specify its terminal result.

File-byte equality and reload failure are separate guarantees. `require` reads current files, not S's rows; the dirty source's verification occurs after loading (`cluster.clj:2135`). Pin/check admitted bytes at the execution boundary and refuse further evaluations after partial reload/arming failure until reconciliation proves a loaded program. A post-load digest check can detect drift; it cannot undo arbitrary top-level effects. Host-bound changes need the retained platform path before shared adoption, not silent JVM fallback (`B4:168`).

## 5. Merge: sound comparison, unsound “just compose” claim

The pure classifier is sound over complete canonical `[identity-attribute value] → digest` maps, using a distinct absent state. If A=B keep B; if A=base keep B; if B=base take A; otherwise conflict. This covers equal independent additions, both deletions, delete/edit, and edit/revert. A present row without its required digest is unknown/refusal, not absence. The identity and hashing owners already exist (`program.cljc:312`, `:336`); `test/definition-digests` currently collapses fn/test to symbols and omits undigested rows (`test.clj:644`). Generalize the reader at its owner, preserving typed identities and completeness checks.

The plan must supply B, not assume that arbitrary numeric transaction positions identify ancestry. D1 already records the fork basis (`D1:77`, `:104`). Use that retained immutable basis for the first merge; if repeated/divergent histories require ancestor discovery, use Datahike parent commits and refuse unavailable/ambiguous evidence. That composition is missing work, even if no new subsystem is needed (`DH/versioning.cljc:463`; merge pack §6).

**The `since` shortcut is neither general branch diff nor O(delta).** `source/changed-identities` can reuse an exact publication report, which is the cheap path (`source.clj:165`); its fallback enumerates history through unbound EAVT (`:180`). `SinceDB` applies a temporal predicate to underlying searches/indexes (`DH/db.cljc:633`, `:677`). The merge pack's probe measured 3 datoms in 134.57 ms and 802,730 in 144.43 ms, not a proportional delta scan (merge pack §1). B4 still labels this O(datoms since basis) (`B4:84`, `:86`), and L's unchanged reuse of that reader inherits the wrong cost. Narrow identity/digest attributes before joining and compare immutable maps where ancestry is not established. Map construction costs the scanned identities/history; the pure diff costs the union of its input keys. Report those costs separately. No new measurement was possible here.

**Conflict granularity is a whole function/declaration, not an arity.** Function identity is `[:seon.fn/sym f]`; arities are owned components, not independently mergeable definitions (`program.cljc:17`; `resources/seon/schemas/seon.fn.edn:150`). `call-arities` is excluded from the digest (`program.cljc:331`). Two distinct arity edits to the same function conflict if final digests differ. The L proof “same function → conflict” is also too strong: identical final definitions do not conflict (`L:73`; `D1:149`). Do not create arity identities to make the proof convenient.

**Recompute derived rows in the combined resolver world.** Portable refs/components from `published-index-rows` are reusable (`fn.clj:3141`), but portability does not prove current analysis. Contrary to the merge pack §3's “reindexes exactly the named identities,” `index!` with `source-database`/`adopt-identities` reads and reconciles existing rows (`fn.clj:3330`, `:3412`); that arm does not run fresh canonical analysis. Even the current file caller pass reconciles only lint findings (`fn.clj:3441`), a gap B1 already names (`B1:371`).

Extend the canonical declaration analyzer/reconciliation path to recompute changed authored declarations and required resolver/schema/macro/caller closure against S. Do not copy branch-local eids, old call edges, arity trees, lint, spans or recorder outcomes and call them freshly analyzed. Reuse unaffected derived facts only when their full input evidence still matches. Program partition does not mean every program-derived row is independently authored or conflict-worthy (`program.cljc:158`, `:323`; program-rows pack §4). Schema refs/deletions validate final owning values through ordinary write admission (`db.clj:4265`).

**`force-branch!` plus `merge!` is not an atomic acceptance protocol.** `merge! [conn parents tx-data tx-meta]` records parents and applies caller tx-data, but `merge-writer!` calls `core/with` directly while ordinary `transact!` checks expected basis (`DH/versioning.cljc:742`; `DH/writing.cljc:865`, `:872`). D1 explicitly requires extending that existing merge operation through the guarded prepared writer and carrying Seon's final validator (`D1:190`; `db.clj:4265`). Calling unguarded merge after force exposes an intermediate head; doing it before force still inherits force's open-connection hazard. Neither sequence is the promised composition.

Accept validates the immutable proposal, exact tested S/run, destination H, all required executed/reused members and named accepter; the existing writer atomically installs only program changes plus allowed settlement/provenance. Positive green excludes missing coverage, omitted members, recording refusal or unexited work (`D1:162`, `:176`; `B4:333`). Retain S/C and durable evidence through the declared lifetime; parent lineage alone is subject to GC cutoff (`D1:200`). Conflicts/red keep the source and intermediate available for repair; `L:28` must say when release is allowed.

## 6. Delete, add guarantees, and the corrected ≤15-row design

Delete the “new `acquire-context!`,” “NOT live turns,” unconditional allocate-on-acquire and “unchanged bodies” claims (`L:41`, `:43`). Delete `affected = gate-sets`, merge via forced live-head replacement, and the claim that copying adopted rows reanalyzes them (`L:40`, `:50`; `fn.clj:3330`). Delete unconditional source/intermediate unlink and the unqualified “Nothing else” (`L:28`, `:56`). Remove unconditional worker/slot deletion until platform hosting and actual-exit guarantees have replacements (`B4:140`, `:170`). Do not delete namespace fixtures, per-member reuse, complete input evidence or recording to make the table short (`B4:97`, `:108`).

Add explicit guarantees, at their existing owners:

- **One world per evaluation:** matched connection/db/projection/ctx/environment, loaded-program invalidation, preserved private objects; adoption excludes all admitted evaluations (`eval.clj:2293`; `B2:121`; architecture model item 5).
- **Fresh isolation and complete release:** owned/borrowed resources distinguished; creation failure cannot reuse somebody else's branch; setup failure unwinds; actual body/child-work exit precedes listener/connection release; cleanup refusal remains visible (`registry.clj:198`, `:327`; `B4:140`).
- **Tested-head acceptance without lost data:** exact immutable candidate and H guard at the writer, program-only normalized changes, final validation and positive run evidence, named acceptance and retained lineage (`D1:146`, `:176`, `:190`).
- **Save feedback before mutation:** red returns the recorded failure to the initiating hook; byte drift, host-bound exclusion or reload failure cannot report convergence (`bin/seon-hook:1486`, `:1566`; `cluster.clj:2135`).
- **Change-proportional work:** same selected and loaded identities skip installation; data-only commits install zero rows; closure, analysis, retained-history reads, heap retention and compile time are measured separately. Raw SCI fork is one env atom, not the cost of context acquisition (`SCI/core.cljc:345`; `eval.clj:2337`; `B2:109`).

# Astra review: Flow PRD

**Verdict: retain the direction; correct the terminal/error paths before approving MUST-NOW.** N1–N4 address real prerequisites, but the proposed implementation still loses launcher faults, can hang during panic, can recurse through listener failures, and attributes unknown failures to an arbitrary cluster. Keep the pre-agent slice smaller: synchronous recording and delivery, complete failure coverage, bounded stop admission and observed exit. Defer batching and the broader restructure.

Evidence baseline: PRD and first-party source at `c83470611`; core.async gitlink `dc35f3e0d7bc2eef502e77982f48641f025c8051`, Datahike `fbd1ad2d10fb1261ef7092737a02801537c16e70`. **P** = `docs/prds/agent-platform/plan/lane-flow-owns-running-machinery.md`; **R** = that directory’s `README.md`; **B2** = `lane-b2-walk-flow-fork.md` there; **F** = `reference-code/core.async/src/main/clojure/clojure/core/async/flow/impl.clj`; **D/** = `reference-code/datahike/src/datahike/`; **T** = `docs/research/agent-platform/flow-fact-pack-and-triage-2026-09-23.md`; **E** = `docs/research/agent-platform/error-route-final-design-2026-09-23.md`. Citations using these aliases are file:line references, not runtime evidence.

1. **P0 — N1 misses errors deliberately emitted as data.** `src/seon/flow.clj:569-578` returns a launcher task failure as an output to `::flow/error`; no catch fires. Removing the launcher join and declaring the channel observational (P:163-168) makes that failure silently losable again. Convert this producer to the same acknowledged `fault!` boundary using the submission’s carried world, preserving admission release and exactly-once settlement; do not add another channel reader. Cover callback/Future failures too (`src/seon/flow.clj:425-445,474-486`). This is necessary before agents, not L4.

2. **P0 — N1’s terminal protocol does not yet prove cleanup or graph termination.** `[:exit state …]` bypasses `handle-transition` (F:209-217,321-323), whereas Seon delivers `proc-stopped` inside that transition (`src/seon/flow.clj:526-528`). A stop-transition throw under `:record` currently restores the old running/paused state (F:285,299,317-320); recording it alone does not stop the proc. Retain the requested terminal disposition even when cleanup fails. Put exact terminal observation at Flow’s run boundary, preserve the cleanup exception and actual cleanup outcome, and never claim resources released merely because the loop returned. Partial startup must settle already-started procs too (F:149-171).

3. **P0 — N1/N2 still contain unbounded control admission.** Sending stop from the failing proc with `>!!` (P:124) can block behind the fixed-10 control channel and fixed-10 taps (F:71-75,99-100,153-154). A mult waits for every tap (`reference-code/core.async/src/main/clojure/clojure/core/async.clj:797-804`); a busy or exited proc can therefore obstruct siblings. Public `stop` additionally holds a lock across that send (F:174-183). Bound command admission at the dependency owner, retire terminal taps, and expose admission failure; do not move the blocking send into an unobserved Future. Bound the entire request/stop/join sequence, not just subsequent `<!!` calls. `src/seon/await.clj:110-122` supplies the right request/reply mechanism, but `src/seon/flow.clj:760` calls Flow stop before its bounded join. Expiry retains custody and denies restart/overlap until actual exit (AGENTS.md:250-257; R:110-112).

4. **P0 — N3 needs a nonrecursive failure lifecycle.** The catch location is correct: `D/writer.cljc:379-388,399-413` settles the transaction before notifying listeners. A failure callback is the minimal way to honor “throw into Datahike” while retaining listeners; it cannot retroactively fail that transaction. However, recording a listener fault causes another transaction and another notification of the same failing listener. The PRD supplies no termination for this feedback. Define failed-listener retirement at its owning lifecycle before recording; remaining consumers continue under `:record`, and failed delivery remains visible pending work requiring repair. Account for callbacks already in flight. A handler throw aborts the remaining `doseq`, so “later listener still runs” only follows if the handler returns. Never route a recording failure back through another `fault!` attempt. This extends the existing listener/error class, not a new retry service.

5. **P0 — N4’s custody choice violates values-carry-their-world.** `running-instances` is legitimate process custody (`resources/seon/operator/runtime.clj:11`), but default-or-first is not evidence of a throwing thread’s branch (P:288-299; AGENTS.md:228-238). N3 already has the exact connection: keep its captured world through recording and emergency handling. An already-recorded panic receipt must propagate without another count/write; a recording failure takes the terminal emergency path, not a second write into default (E:40,82-84). For genuinely unattributed failures, expose an explicit process failure; any durable process-error sink must be deliberately supplied by the process owner, never selected from map iteration. Retain full failure evidence in the existing process/graph observation seam so status/REPL can report it; stderr-and-return alone (P:297-300) fails the policy. Install one chainsafe handler, but do not mistake it for a universal Future handler (F:29-36; `reference-code/core.async/src/main/clojure/clojure/core/async/impl/dispatch.clj:63-69`).

6. **P1 — shrink MUST-NOW and close its bounds.** N1’s dependency hook plus channel-xform refusal is the smallest complete catch solution; an extra Seon step wrapper is not. There are three actual `catch` clauses (F:163,312,317), a channel exception callback (F:107), and a timed `.get` that throws into the inner catch (F:259); do not implement four independent catch adapters. `send-outputs` is inside the inner try. Graph construction/describe errors also need the outer construction boundary (F:38-68,246; `src/seon/flow.clj:85`). Reject xforms before creating channels; never transact under the channel mutex. A handler failure must bypass the surrounding catch, not be recorded again.

N2 is necessary now, with finding 3’s correction. N3 and a minimal N4 are necessary while foreign callbacks remain. Their current day estimates omit recursion, custody and terminal proofs. P:195-200,267-273 explicitly permits waits whose bounds are unresolved; that cannot be accepted in this prerequisite. Supply the system-write bound now, report outcome-unknown without retry, and keep the recording connection alive through producer stop/cleanup. Do not require acknowledged batching now: T:275 specifies synchronous M4, T:301 defers batching, and R:373 adopts that triage. Remove the committer dependency from this slice; revisit batching after first agents with measured repeat load. This also removes the stop-order cycle where a stopping cluster proc awaits a committer being stopped in the same graph.

**Second mechanisms and stamps.** No new durable stamp is needed: panic-mode on an occurrence is a historical observation, and a verified committed receipt is propagation evidence (E:40,74). Proc basis state is progress, not a duplicate database authority. Do not let either become a mutable health flag or whole-program invalidation key. The unjustified additions are batching in minimal M4, a temporary backstop proc that B2 will remove, and a readiness dispatcher implicitly required by decision A. Fault transactions must invalidate zero program/schema/context derivations; relevant declaration changes invalidate only their dependents (AGENTS.md:71-106).

**Decision A — recommend option 1 for the first router conversion, with a real recovery contract.** One offer-only sliding-1 listener feeds the existing Flow in-port; the proc reads its own connection, not the callback’s report. Thus the PRD’s objection about unordered/batch-collapsed callback reports (P:361-363) does not apply. Register before deriving initial work, capture a single database value, process through that value’s basis, and advance only after successful delivery. Old callbacks may cause redundant looks, never a backward cursor. Compare dependency revisions before rebuilding matchers; the derivation is proportional to relevant changes, not every commit.

Neither option’s bare `d/since` claim proves loss-free recovery. SinceDB supplies a temporal predicate (`D/db.cljc:678-680`); nonhistorical postprocessing collapses assertions/retractions into surviving values (`D/db.cljc:154-192`). It is not automatically the router’s `[e a v tx added]` event stream (`src/seon/cluster/wake.clj:524-542`) or a transaction-index seek. Specify a history-preserving bounded query for the declared interests, ordering where required, and reconstruction of current durable work after restart; prove retraction, assert/retract within one interval, no-history attributes, and schema-plus-wake changes. A need to recover nonretained events is a contract failure, not permission to invent a replay store. Price option 1 at the PRD’s ~1 day only after this probe; range cost remains unmeasured here.

The existing committed-report seam has value—ordered per-transaction payloads and bounded overflow evidence—but **option 2 as written cannot work**. `poll-batch!` is explicitly nonblocking (`D/committed_report.cljc:175-180`), `poll-ready!` consumes a process-global queue (`:7-11,259-275`), and `take-ready!` blocks without a timeout (`:278-284`). Per-cluster polling either steals another cluster’s readiness, busy-spins, or stops waking when empty; a self-fed in-port supplies no new external readiness event. Moreover `:gapped` rejects every subsequent offer (`:115-117,129-134`); “since once and continue” never reopens it. Ordered reports still share batch `:db-after` (`D/writer.cljc:256-261`), so a cursor must not jump to that basis after only the first report.

If measurements later justify option 2, extend the dependency’s per-source readiness into an event-driven Flow port and specify close/reopen-before-catch-up with overlap deduplication, generation fencing and bounded drain. Reuse the dependency source; add no process-wide Seon dispatcher. Budget beyond the quoted 1.5 days for these fork/lifecycle proofs. `offer!` also takes a monitor (`D/committed_report.cljc:13-15,105`): it avoids queue backpressure but is not literally wait-free. History confirms prior use (`2b584a6f2`, `2750c158d`) and removal in the tree split (`f25e34594`), not present suitability. Option 3 is not ordered per listener: concurrent notifications remain concurrent even with a blocking handoff (`D/writer.cljc:390-413`).

**Decision B — preserve the existing admission guarantee now; keep B2’s conditional retirement.** B2:166-172 already prohibits retirement until another existing owner proves bounded admission; option 2 in P:375 misrepresents that gate as permission for an unbounded executor queue. The current “bounded” executor is merely `newFixedThreadPool` (`src/seon/flow.clj:186-190`); bounded workers are not bounded admission. Keep the launcher until the gate passes. In cut 4 prefer option 3’s reduction in place if no smaller dependency seam supplies refusal, queued cancellation, arm transfer and retained ownership until actual body exit. Do not decree all 750 lines permanent or introduce a second admission owner. Estimated ~2 days for shrinking remains a design estimate; avoiding this restructure now costs no additional prerequisite work. Decide model-call message splitting with B2, not through a competing execution plan.

**Placement of L1–L9.** R:155-163 makes cut 4 last; R:373 prioritizes first namespace agents. L1/L2: correctly after those agents, before cut 4 where limited to notification/lifecycle plumbing; context adoption semantics stay with B2. L3: after first agents unless a measured leak blocks operation. L4: capability plumbing can precede cut 4, but wiring turn evaluation changes execution semantics regardless of being “one call”; put it in cut 4 unless measured starvation earns an explicit MUST promotion. L5: do not build a disposable backstop proc ahead of B2:318’s deletion; preserve the existing bound until the replacement proves it. L6/L7: cut 4, conditional on the single B2 execution design; async model calls alone do not justify deleting interrupts needed by evaluations/other host work. L8: drop unneeded readers/casts; measure render scheduling, and preserve valid attribute/declaration-keyed caches rather than reinstating commit-keyed reconstruction. L9: remove from the four-cut deliverable; a future measured compute optimization is separate follow-up, not an implicit fifth cut. Generic host computation does not gain termination merely from an SCI arm (R:110-112).

**Acceptance: retain P:388-401’s behavioral classes, but they are insufficient as written. Add these measurable gates:**

- Exercise direct launcher error outputs and throwing completion callbacks, every hook entry, startup partial failure, and ordinary construction failure. Assert one durable occurrence and wake on the correct branch before acknowledged continuation; force a two-link cause when testing two links. Under panic there is no “next input” on which to place the assertion: observe from the supervisor.
- Saturate control and taps before panic; throw during stop in both modes; fail the recorder while stopping; timeout a compute Future whose body remains alive. Prove bounded command admission, truthful terminal/cleanup outcomes, no self-join, no resource reuse or replacement work before exit, and an independent graph/REPL remaining responsive. A proc-completion promise alone does not prove its child computation exited.
- Fail a listener on every transaction, including its fault transaction; prove bounded fault writes, no recursive recording, remaining listener behavior under each mode and subsequent writer usability. Inject faults on two branches plus an unattributed process thread; prove no cross-branch recording, no receipt recount, and explicit database-unavailable status. Verify recipient wake delivery separately from transaction-promise delivery.
- For L1, test registration races, reordered callbacks, batch boundaries, retractions, restart and query bounds; if option 2 is selected, force overflow twice, idle-to-ready, concurrent clusters and close/reopen races. Measure matcher recomputation only on relevant declaration changes. Listener-count zero is not a valid global assertion while other listeners remain.
- Compare candidate against its immediate parent with identical admitted workload, fixture basis, dependency pins and linked valid caches. Commit the measurement script and raw samples: wall/CPU/allocation, p50/p95, retained memory, queue depth and phase breakdown for no-fault Flow steps, ordinary/data-only writes, first fault, repeated fault, concurrent faults, router wake and stop. Report absolute/delta timings and sample count; do not present previous P4 numbers as new measurements. Unchanged work must produce zero cache misses/reconstruction; relevant changes recompute only their closure. Target subsecond hot operations; every >1 s operation gets phases, every >10 s operation is a defect requiring authorization, not an excused benchmark.
- Prove new schema/occurrence fields by incremental declaration adoption on a live branch with warm-cache reuse, retirement refusal and affected re-derivation (R:374). No reset/nuke/from-zero reindex as schema proof. Pin/adopt the modified fork and prove loaded behavior separately from source; retain fork compatibility tests. Use focused installed `seon.test/run` requests per slice, platform/affected integration at the orchestrator boundary. Destructive stop/handler tests use owned isolated custody; P:397’s proposed stop of default violates AGENTS.md:401-405 for a lane.

## Exact replacement text

The following blocks replace the named D1 sections; referenced owners remain the existing owners. These are spec changes, not implementation claims.

### Replace §0's final paragraph and §1's cost claims

A candidate is a cluster with its own connection forked from one immutable shared commit. Starting it includes configuration, recovery decisions, context acquisition and graph admission; branch creation and SCI fork timings do not measure this cost. The candidate executes only the assigned task's work, selected at the existing arming owner, without rebinding an agent's connection. Merge is an explicit request: capture candidate and shared commits, derive their net definition changes from the fork basis, apply the proposal to a scratch branch of the shared commit, validate the combined program, run every required test against that exact program, then accept through the writer with the tested shared basis as a precondition. Export the accepted delta in an isolated checkout and admit the complete file change through B1. Measure start, projection, validation, selection, execution, merge and export separately; test cost is the selected tests' work, not a promise of tens of tests or two seconds.

### Replace §2a's trigger, startup, lifetime and discard rows

Trigger records the task through B3's trigger-call; start-call owns assignment and first-turn admission. Candidate startup captures the exact shared commit and records its immutable fork basis through the registry. The same task/agent must not execute on both shared and candidate branches. Before implementation, agree the B3 start/B2 arming transaction order and prove that inherited open turns and schedules neither recover nor run as unrelated candidate work. Use task facts at those existing owners, never a permanent exclusive namespace batch. The task's candidate address includes its cluster; its environment retains that connection for its lifetime. Candidate refusal preserves the working branch. After acceptance, stop and release its live resources and retire disposable branches only after the accepted source and test evidence remain queryable under the declared retention rule; collection stays at the existing maintenance owner. Ordinary root clusters need no invented fork basis. A persisted schema change is RESET NEEDED and lands with every writer and reader.

### Replace §2b, including its pseudocode and three-use claim

Use one net-definition projection over an immutable basis commit and descendant database value. Select identities with added or retracted B1 definition-digest datoms in since(history), joining removed identities through history. Deduplicate before reading complete rows. Compare each identity's basis and final digest: equal means unchanged, including delete/recreate or edit/revert with identical content; final absence means deletion; missing required digest on a surviving row means a typed refusal. Include resolver/binding changes through the owning declaration digests and B4's namespace/input rules. Verify the supplied basis belongs to this history; do not equate branch-local transaction numbers with commit ancestry.

The projection returns definition changes only. Normalize complete declaration values through the indexer's existing identity/ref/component owner before replacement; never export local entity ids. New identities upsert, existing identities use exact replacement, removed identities retract. Keep database access in an existing database-reading owner and pure comparison in program, or explicitly declare the read dependency and prove the complete require graph loads. Publication's missed-commit fallback and B4's per-test-basis selection consume this projection only where their complete semantics match. Run/member facts remain the recorder's facts, queryable on the tested commit.

### Replace §2c

Only an explicit my.task/merge! request runs this function. Capture B (candidate fork basis), C (candidate head), and H (current shared head) as immutable commits. Derive candidate and shared net changes relative to B. Conflict means both changed the same identity away from B to different final digests, including deletion; equal final content does not conflict. The conflict identity includes the competing definitions and basis. In one shared transaction compose B3 trigger-call and start-call assigning existing root, with both source commits and the subject-local detector. Repeated identical conflict produces one task; changed competing content remains a distinct conflict. Root's repair must satisfy that task's tests through this same gate.

Fork scratch from H and apply C's normalized proposal in one transaction through Seon's write admission. Reuse schema compilation/materialization and final-report validation before selecting tests. Refuse incomplete contracts, malformed schemas, invalid final refs, unresolved surviving callers and every admitted function lacking a reaching test by identity. D3 permits an untested candidate definition while working; it does not make absent merge evidence healthy.

Derive required tests from the combined program's changed declarations and their before/after caller, reference, namespace-binding and schema-contract dependencies, union the task's explicit test symbols. Use B1's schema dependency closure rather than functions-using's keyword mentions. Pass that exact set to B4's one run function with named policy. B4 must capture the scratch's tested program and use it for fixture branches, projection, callable resolution and recording; its current-src-only fixture contract must change in the same slice. A required member excluded, unfinished, missing, unknown or red refuses acceptance. Reuse requires B4's positive per-member proof. If only atomic content acceptance is required, Seon's transact! request already carries the expected-basis guard; no fork change is needed. To retain multi-parent merge lineage, extend the existing merge request to carry that argument and have its writer reuse the transaction operation before adding parents. This is one guard and one validator path, with public API and stale-basis regression included; it is not a four-line copied check. If H moved during testing, the writer refuses before mutation. Rebuild scratch from the new H, recompute conflicts and required tests, and run/reuse only evidence valid for that new combined program under the existing request bound. Do not apply a smaller untested delta. Release materialized values and scratch connections on every exit; retire only after evidence retention is satisfied.

### Replace §2d and §6.3

Write-back consumes the accepted definition delta at its merge commit, including schemas, tests, additions and deletions. overrides is a useful post-publication check for its declared function scope, not the export inventory.

# Shrinking `src/seon/db.clj` — region audit, first slices, target

Lane `shrink-db`, 2026-09-23. Read-only research; no source edits. Subject:
`src/seon/db.clj` at HEAD `04e00fc23` (4,654 lines, 231 top-level vars). The
Datahike fork is `reference-code/datahike` at `684d3290` ("Share committed query
results by store and commit across branches"). Owner direction, AGENTS.md "The
codebase shrinks" / "Small or wrong" / "Algorithmic analysis" / "No stamps".

Method: `clj-kondo` var-definitions with row spans over `db.clj` and var-usages
over `src test` (usage counts below are call sites outside `seon.db`, tests
included), a full read of `db.clj`, reads of the fork seams named with
`file:line`, and read-only JVM probes through MCP `eval_clj` in the throwaway
namespace `tmp.shrink-db-probe` on cluster `default`. Nothing was redefined and
nothing was written. Every timing below is a mean over 20–50 warm calls in the
live default JVM with contracts armed.

## Summary

- **Four regions account for about 2,100 of the 4,654 lines:** read evidence and
  currency (686), the codec and declaration plumbing (~460), the write validator
  (~1,100 across the pre-flight check, the final-report check, owned values,
  retention and arity), and the pull/q wrappers with their guards (~490).
- **Seon's wrapper, not Datahike, is where reads spend their time.** Measured:
  `seon.db/q` takes 3.55 ms against raw `d/q` at 0.0067 ms (a 4,930-row find of
  `:seon.fn/sym`). All of the difference is the decode walk: the query has
  **no** EDN-encoded attribute (`query-find-attributes` answers `[nil]`), and
  `decode-query-result` still rebuilds every row (2.09 ms against 0.77 ms for a
  plain `mapv`). `seon.db/pull` by lookup ref takes 1.29 ms against raw
  `d/pull` at 0.019 ms. 1.02 ms of that is `lookup-ref-error`, which builds a
  sorted map of all 1,219 installed attributes (`installed-attribute-declarations`,
  0.82 ms) **on the happy path, before any error exists**. The same pull by
  numeric id takes 0.12 ms. Both costs grow with the whole schema or the whole
  result, where the needed work is zero. These are the findings the brief asks
  for.
- **Only 25 of 1,219 installed attributes are EDN-encoded** (probe P1). Among
  them are `datahike.read/dependency-plan`, `datahike.read/revision` and
  `seon.db/read-request`, which store read evidence. The codec's minimal form is
  a set of 25 attributes and one decode per value, and it applies only where an
  encoded attribute is actually in play.
- **The projection stamp is dead weight.** A raw `(d/db conn)` derives the
  identical projection object (`identical? true`) in 0.11 ms through
  `carried-projection`'s cache-context memo. The stamp serves only genesis
  (`construction-projection`) and seven external `(meta db)` readers.
- **Target: db.clj ≈ 2,500 lines.** The eight slices below reach about 3,450
  (−1,200), each adding far fewer lines than it deletes. The rest is the deeper
  write-validator consolidation (§4).

The ~950 lines between 3,450 and 2,500 come from §1 rows H, R, O, K and N, and
from the contracts. There are 106 inline `:malli/schema` forms, several over 500
characters. The ten repeated `[:any {:seon.schema.admission/exemption …}]`
polymorphic-boundary declarations and the pull/pull-many schema triplets become
registered schema keys once, in the schema resources. Retention (issue-test
append-only) and the arity gate are program policy rather than database access.
Moving them to their owning namespaces (`seon.issue`, `seon.fn`), registered
through the same `validate-report` callback, does not shrink the codebase. It
makes db.clj ≈ 2,100, and the owner should decide it only if the 10k whole-program
target needs file-level clarity more than line count.

## 4. Risks and open decisions

- **Slice 7 coarsens currency** from per-pattern to per-attribute. The result is
  extra rereads, never a stale read. It is scheduled as A2 c1. The owner's "the
  happy path to be fast" favours it: today's precise path costs extra `d/q`
  sub-queries per capture.
- **Slice 8 changes refusal paths.** Tests that assert submission-index paths
  test a retired assumption (question 2 of the three). The owner should confirm
  that entity-id paths plus identities are acceptable steering for agents.
- **Codec narrowing (slice 2, row I(4))** refuses a q that compares a constant
  with an encoded attribute through a rule or an `or` branch. Before landing,
  query program rows for such queries.
- **C′ versus the "no general error predicate" law.** The slice reuses the
  private `error-value?` already in db.clj rather than adding a predicate. If
  the owner reads the law as forbidding even that, the alternative is to stop
  threading error values through db functions (narrow `[:or db error]` inputs
  to `db`), which is a caller-conversion slice over the ~60 sites that pass
  them.

## 5. Probes (exact forms and results)

All forms were run in namespace `tmp.shrink-db-probe`, `mode jvm`,
`read_only true`, with `c = (seon.cluster.boot/connection "default")` and
`db = (seon.db/db c)`.

- **P1 (encoded population).** Count the qualified keys of `(:schema db)` for
  which `(seon.schema.datahike/edn-encoded-attr-in? (seon.db/carried-projection db) a)`
  is true. Result: `{:installed 1219 :edn-encoded 25}`, 8.1 ms.
- **P2 (pull cost).** Mean of 50 calls, selector `[:seon.fn/sym :seon.fn/doc]`
  on `[:seon.fn/sym 'seon.db/q]`: `seon.db/pull` 1.29 ms, `d/pull` 0.019 ms,
  `pull-plan-with-evidence` 0.030 ms, `#'seon.db/lookup-ref-error` 1.02 ms,
  `#'seon.db/attribute-observation` 0.95 ms, `#'seon.db/installed-attribute-declarations`
  0.82 ms, `seon.db/pull` by numeric id 0.12 ms.
- **P3 (q cost).** `'[:find ?s :where [?f :seon.fn/sym ?s]]` (4,930 rows), mean
  of 20: `seon.db/q` 3.55 ms, `d/q` 0.0067 ms, `d/q-with-evidence` 0.013 ms,
  `query-attribute-error` 0.023 ms, `carried-projection` 0.028 ms,
  declarations + `decode-query-result` 3.73 ms. `query-find-attributes` →
  `[nil]`. The per-row `decode-query-tuple` walk takes 2.09 ms, against
  0.77 ms for a plain `mapv` walk.
- **P4 (stamp redundancy).** `(identical? (carried-projection (d/db c)) (carried-projection (seon.db/db c)))`
  → true. The stamped meta projection is identical to the carried one. The raw
  value derived it in 0.11 ms. Stamped meta keys are
  `[:seon.sci.eval/projection-state :seon.schema/projection]`.
- **P5–P7** are defined in §2 and are to be run by the implementing lane.

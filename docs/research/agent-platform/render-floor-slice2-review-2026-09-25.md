## P1 findings — fix before committing

### 1. Minimum measurement recursively renders hidden descendants and can invoke producers twice

**Evidence:** `src/seon/render/value.clj:598–621` (`diff:972–995`) computes an item's minimum by calling `value-node` with share zero at line 609. That enters `allocate-children` again, forces its `first-level`, and measures another first child. Line 651 then calls `value-node` again for the selected child with its real share. Producer selection at lines 737–744 occurs on both calls.

A chain of singleton maps therefore descends its first-child chain during minimum measurement, even if the outer collection will become one elision. Selected nested chains repeat this work at successive ancestors; with depth ceilings removed, a fully retained depth-d chain can incur quadratic visits. The current depth dial limits the damage but cannot substantiate §3's no-hidden-subtree and recurse-once claims. A producer on a candidate can run during pricing and again during allocation, including candidates ultimately omitted.

**Smallest fix:** separate shallow measurement from allocation. Return the floor/first-level target and already obtained leaf/producer result as data; do not obtain a minimum by entering `value-node` recursively. Allocate only selected children once, retaining any producer result already obtained. Verify producer-call counts and visits on a deep singleton chain and a wide collection whose candidates are mostly omitted.

### 2. Candidate pricing and ordering perform unbounded content work before affordability is known

**Evidence:** `value.clj:587–595` (`diff:961–969`) calls `cost` on a whole scalar string before deciding that the shallow collection is too expensive. `value.clj:599–600` (`diff:973–974`) renders every candidate map key through the unbounded HTML path. `value.clj:516–519` (`diff:890–893`) uses `sort-by` with `emit-text` as the key function for node maps/sets. Clojure's `sort-by` calls its key function during comparisons; these bytes are not cached once per key. `print.cljc:439–446` (changed comparator hunk at `diff:300–310`) recursively sorts composite maps/sets inside comparisons and treats uncounted sequences as equal rather than using the specified opaque identity order.

Thus `[a-five-megabyte-string]` still prints that entire string to reject its shallow floor, despite the landing's fast **root-string** measurement. A tiny-budget map with a huge composite key fully traverses that key before omitting its entry. A lazy key reaches the HTML collection walker, where all entries are collected (`value.clj:568`); an infinite lazy key need not terminate. Ordinary lazy collection values also enter `live-parts`, realizing candidates rather than becoming opaque. The changed comparator protects only one comparison branch, not this rendering path.

**Smallest fix:** use the string's raw length as an early lower-bound rejection before escaped printing; use one cached safe ordering key per reached finite key; treat lazy/host keys as opaque before any traversal. Bound whole-key measurement by the available allowance and elide the whole entry if the key cannot fit. Use the same ordering operation for live and admitted children. These changes implement the existing §3 algorithm; no new cache registry or printer is needed.

### 3. Reconstructible original paths and carried retrieval refusal are not preserved

**Evidence:** `value.clj:522–523` (`diff:896–897`) reconstructs a node map's step from the key node's `:seon.print/value`, falling back to its ordinal. Node sets always receive ordinal steps. `value.clj:606` constructs a new path and `value.clj:761` (`diff:1256`) unconditionally overwrites an existing node path. The deleted `fit-node` instead preferred the carried path. The depth-cut branch at `value.clj:719–720` copies only `:seon.print/requery-id`, unlike the allocation branch's id/refusal handling at lines 561–564.

For an admitted map keyed by `[1 2]`, its vector key node has no scalar `:seon.print/value`; the new cut path becomes `[0]` rather than `[[1 2]]`. For an admitted set, `[0]` is not a member-based path accepted by `print/value-at`. A producer child already naming `[:original :payload]` instead gets its display position. Existing elision nodes can acquire a new path while keeping their old `:seon.print/requery-form`. A carried explicit refusal is replaced by the outer profile's retrieval identity/refusal when the depth branch fires.

**Smallest fix:** carry the original child step/path in the node data and prefer it during allocation, including sets and compound keys; never infer it from printed text or an ordinal fallback. Reuse one id/refusal transfer operation for all replacement cuts and derive any requery form from that same retained path. Add carried-node cases with compound keys, set members, pre-existing paths, and a refusal under an outer requery id.

### 4. The final check does not enforce B or report the authorized smallest-face exception

**Evidence:** `value.clj:838–852` (`diff:1316–1330`) converts B once, but compares emitted length only with `charged`. It never checks `charged` or emitted length against `allowance`. `fit-string` explicitly returns an over-share floor at lines 485–489; collections can raise the local share at line 596 or return an over-share cut at line 621. These can be legitimate minimum representations, but no diagnostic distinguishes that case from allocator overrun. The landing expressly acknowledges that omission.

The new exception is also not the named, path-bearing allocator error required by §3: it has operation/expected/offending fields, no declared error schema, no path, and unqualified nested `:allowance/:charged/:emitted` keys. The broad catch at lines 762–776 still converts arbitrary faults to an ad hoc layer/message face using the independently clipped Throwable floor. It can return a large terminal face irrespective of its assigned share; charging it accurately does not prove budget compliance.

**Smallest fix:** carry explicit minimum-representation evidence with allocation results and perform the final emitted-length comparison against the original character allowance. Over B must yield the declared insufficient-floor-budget diagnostic only when that minimum cannot fit; other overages must be a declared allocator defect naming path, allowance, charge and actual size. Preserve the real failure through the existing error owner rather than treating a message-only face as successful allocation. Do not add a clipping retry.

### 5. The compact face removes refusal evidence from callers that never receive the legend

**Evidence:** `print.cljc:477–481` (`diff:346–361`) drops each elision's refusal. Only `value/prepare` appends a legend, and only to its AI text (`value.clj:841–843`, `diff:1319–1321`), after `emit-both`. The same prepared Hiccup has no legend. The root profile, not the actually retained cuts, supplies the legend's refusal at lines 833–836; carried cuts can have different custody.

The schema still directly declares `seon.print/render-elision-ai` as an elision renderer (`resources/seon/schemas/seon.print.edn:348`). A direct invocation on a refusal-bearing elision now says neither how to requery nor why requery is unavailable. Likewise, the admitted-receipt reader `src/seon/eval/drive.clj:135` emits nodes directly and reads their compact face back as data, so refusal information formerly present in that derived value disappears. Neither caller is listed in the landing's conversion holds. This is separate from the known transcript/web assertion changes.

**Smallest fix:** compose compact cuts and their retrieval legend at the shared owning emission boundary, including the Hiccup representation, and convert the standalone renderer/receipt callers in the same cut. Derive the legend from the actual retained custody; where refusals differ, preserve their association with cuts instead of claiming one outer refusal explains all of them. Keep one charged legend, not one fresh budget per caller.

### Remaining P1 blockers and static counterexamples

**P1-A — lazy members and host collections still execute before affordability.** `normalize` returns every `coll?` value as live (`value.clj:552–554`), including a lazy sequence. `level` then uses `map-indexed`, `take` and `mapv` (`:619, :631, :646`). A numeric cap bounds yielded members, not the work to obtain even one member: `(filter (constantly false) (range))` never yields a first element. Rendering it alone or inside a vector can hang during measurement. The non-AI branch explicitly calls `level` with `n=nil` and `Long/MAX_VALUE` (`:692–693`), so an ordinary infinite sequence is fully realized there.

Host keys are not reliably opaque either. `opaque?` calls `leaf-node` to classify a non-Clojure collection (`value.clj:634`), and `key-node` also calls it (`:596`). `leaf-node` requests `admit/admit-value` with `:seon.sci.admit/unbounded? true` and a no-op interrupt (`:522–531`). The unchanged admission owner explicitly traverses `java.util.Map`, `java.util.Set` and `java.util.Collection` (`src/seon/sci/admit.clj:329–350`). A host collection with a nonterminating iterator therefore enters an unbounded walk simply to decide whether it is opaque. Catching `Exception` does not stop this work, and propagating OOM does not preserve the shared JVM.

**Required fix:** classify untrusted lazy/host values without admission, iteration, custom printing or other user code, before normalization/measurement on every output path. Use the existing opaque node. A bound on the number of returned elements is not a termination guarantee for a lazy source.

**P1-B — whole compound ordering and scalar key printing defeat the budget.** `level` constructs ordering descriptors for unordered members before `key-node` (`value.clj:626–637`). `print/order-key` recursively visits every element of counted sequences and every key/value of maps and sorts all members of nested maps/sets (`print.cljc:461–468`). Thus the supplied 100,000-element vector-key case traverses the entire key to order it before discovering whether any of it fits. A deeply nested finite key can exhaust the stack here. `key-node` repeats full nested map/set ordering at `value.clj:576–581`; its room counter only limits the subsequent walk. Admitted map keys and set members are first fully rebuilt through `admit/semantic-value` (`:615–616`), whose unchanged implementation traverses the complete node (`src/seon/sci/admit.clj:584–624`) and constructs maps/sets (`:571–582`). This work is also outside the allowance.

For `(array-map a-five-megabyte-string 1)`, `key-node`'s leaf branch calls `print/text-cost` on the entire string (`value.clj:596`); only `:598` checks the limit. `print/text-cost` prints the full literal (`print.cljc:939–949`). The string-value guard in `fit-string` does not protect this branch. Large numeric/symbol/keyword scalar faces similarly have no bounded encoding check. `measure` also calls `str` on scalar-node payloads before its shallow whole-level cost check (`value.clj:730–737`); a scalar-face classification alone is not a bounded-size proof.

**Required fix:** perform bounded key/leaf admission before deriving content-based order or semantic paths. Reject the whole entry when its key cannot be safely represented within the allowance. Reuse that bounded representation for ordering and pricing; do not derive it by recursively sorting/rebuilding the rejected key. Apply raw-length rejection to string keys as well as string values. Verify the remaining scalar encoders and opaque classification explicitly.

**P1-C — keys can still be hashed, and paths can still print forever.** The new identity-membership guard is correct at `value.clj:627`, but `:639` still passes the original `k` to `attribute-value`. That unchanged callee does `(get-in database [:schema attribute])` at `src/seon/render/value.clj:390–391`. With an ordinary hash-map schema and a lazy key in an `array-map`, that lookup hashes the key again. The path replacement does not change `k`. Guard the schema lookup itself by the declared attribute type.

Separately, consider `(array-map [(range)] long-text)`, constructed without hashing the vector key. The outer vector is counted, so `opaque?` at `value.clj:634` leaves it intact as the child path step (`:636, :641`). `key-node` can render its inner lazy sequence opaquely (`:573–575`), but that safe key node is not the path. Pricing the child's string cut (`:740–741`, then `fit-string :494–497`) prints the original path through `print/render-elision-ai` (`print.cljc:499–506`) and its unlimited `literal`. That realizes the infinite range. A large finite compound key or set member similarly makes cut evidence arbitrarily large. Set steps and already carried paths bypass the top-level map-key guard altogether.

`print/legend-facts` adds another raw traversal: `(tree-seq coll? seq node)` at `print.cljc:908` descends into metadata payloads, including paths and requery forms, rather than only declared node children. An otherwise opaque rendered key can therefore leave dangerous content in a node path for the legend scan to realize.

**Required fix:** establish that every coordinate and emitted metadata value is safely finite before storing or pricing it; a counted outer container is insufficient. Retain an actual safe coordinate or cut at its safe ancestor with an explicit retrieval limitation. Traverse only structural print-node children to discover cuts. Never replace an original key with a class symbol while continuing to advertise a requery through that symbol: `print/value-at` uses actual lookup keys (unchanged `src/seon/print.cljc:403–409`), so `#object[Class]` is a display description, not a reconstructible coordinate.

**P1-D — custody and existing paths are preserved too late or only for collection-tail cuts.** A carried string/truncated-string node with its own refusal under an outer requery id reaches `fit-string` using the outer profile (`value.clj:697–702, :833–837`). `custody` is only applied to the trailing collection cut, not that node. The replacement cut can therefore lose the refusal and acquire an invalid outer identity. Likewise, root measurement is always called with `[]` (`:908`), even when a producer node already names an original path. `value-node`'s late `update` (`:859–860`) cannot repair a cut whose non-nil path and requery form were already constructed from the wrong coordinate. Preserving the original path on an unchanged node does not preserve it on its replacement.

**Required fix:** select the node's effective path and custody before measurement and cut construction, once for every node type and root/child entry. Keep the same values through string, depth, whole-subtree and allocation cuts. Cover a directly carried string refusal and a root producer node with a pre-existing path, not only collection-tail elisions.

**P1-E — local error handling and named budget errors remain incomplete.** `floor-tree` normalizes and measures before entering `value-node` (`value.clj:907–909`). `level` normalizes candidates (`:635–646`), and `allocate-level` measures all candidates before invoking their member wrapper (`:785–802`). A producer/accessor/encoding exception there either escapes the root or is caught as the enclosing collection's failure, rather than that member's diagnostic. Narrowing the catch is correct, but does not cover the new producer/measurement boundaries.

The two new budget schemas are structurally identical (`resources/seon/schemas/seon.print.edn:295–306`); both diagnostics come from `budget-error`, declared only as `:seon.error/base`, with the same operation/layer and fields (`value.clj:881–888`). Message prose distinguishes the branches, but the declared shapes do not distinguish the two named alternatives. The diagnostic always names root `[]`, including a descendant accounting fault. Further, the smallest-face comparison uses the full speculative legend reservation (`:899–904, :916`), whereas actual emission selects only used legend facts (`print.cljc:904–913`); that comparison alone is not proof of the minimum actual emitted representation.

**Required fix:** put safe normalization/measurement within the owning member failure boundary and retain full causes. Give the two error alternatives distinguishable declared content through the error owner, with the responsible path, and compare the actual minimum face plus its required legend facts against B. These are producer/accounting corrections, not a clipping retry.

**P1-F — a nil inside a compound key silently changes the displayed key.** `key-node` tests `(if-some [member (first members)] ...)` at `value.clj:582–583`. For a sequence key whose next element is nil, it takes the completion branch even though the sequence has remaining elements. Thus `(array-map [nil 1] :value)` can emit the key as `[]`; `[1 nil 2]` becomes `[1]`. The returned whole-key node passes the final cost check at `:597–598`, so this is silent data corruption rather than a whole-entry elision. No runtime execution is needed to establish the branch result.

**Required fix:** distinguish an exhausted sequence from a nil-valued first element by testing the sequence itself. Preserve nil members in nested vector/list/set keys and verify displayed keys retain their original values.

### Safety conclusion and integration boundary

The requested universal safety property is **falsified statically**: there are remaining routes to hash an infinite key, realize lazy members/host iterators, walk/sort whole unaffordable compound keys, print huge string keys, and print or traverse an infinite value embedded in a path. **Every path step is not guaranteed finite.** The current hostile-shape test’s lazy-key case covers only a top-level lazy key, and its time assertion runs only after rendering returns; it cannot bound a nonterminating call (`test/seon/render/value_test.clj:1100–1113`, new-side test hunk). Do not repeat these probes in the shared JVM on the strength of that test.

Retain the shallow-measure/allocation separation and common emitter. Fix P1-A through P1-F at those owners, then obtain independent static review before root-authorized runtime proof in an environment that cannot take down the shared JVM. ### Universal safety: concrete remaining paths

1. **A standard cyclic Throwable bypasses the rule before the allocator starts.** `normalize` calls `Throwable->map` at `value.clj:564`, before `classify`. The dependency implementation loops through `.getCause` until nil, without a visited check: `reference-code/clojure/src/clj/clojure/core_print.clj:494–497`, revision `3bc2b3e91fdff462620d84bbdfd40379d9c562e5`. Two Throwables whose causes point to each other therefore never reach classification or affordability. It also materializes the cause chain and root frames before B (`:499–501`). This is a new route through the changed normalizer, not merely the deferred old `floor` implementation. An accessor that never returns is another limit a catch cannot fix. Under the root rule, an arbitrary Throwable must remain opaque until an explicitly safe Throwable projection owns its acquisition; do not use eager `Throwable->map` as that projection.

2. **Classifying an outer persistent collection does not authorize printing its descendants.** `level/finish` permits a traversable component value into `attribute-value` (`value.clj:699–700`). In the unchanged callee, a cardinality-many component set with equal numeric positions is rebuilt with a comparator whose tie-break is `(compare (pr-str left) (pr-str right))` (`:401–418`). A finite sorted set of two maps, initially ordered only by their distinct finite ids, carrying equal `:example/position` numbers and lazy payloads can be constructed without hashing or forcing those payloads; use `(filter (constantly false) (range))` as a payload. Sorting prints an entire member, forcing the non-yielding lazy payload before any child measure. The position discovery also sorts all first-member keys by `str` (`:409`) without classifying them. Reference-many conversion builds a new set at `:423`, potentially hashing nested values. The keyword guard protects the attribute lookup only. Move attribute projection into the settled child boundary and make its ordering/projection consume safe declared fields; a second guard on the outer collection is insufficient.

3. **Carried coordinates and retrieval forms are still an unbounded printing channel.** A carried string node with `:seon.render.data/path [(range)]` passes that path into `fit-string` through `settle` (`value.clj:732–735, :789–794`). Its smallest cut is priced through `print/text-cost`, then `render-elision-ai`, then unlimited `literal` (`print.cljc:938–950, :500–506, :11–21`). That prints the infinite step. The declared path is a vector of arbitrary values (`resources/seon/schemas/seon.render.data.edn:7–9`), so its schema does not establish finite descendants. Likewise `:seon.print/requery-id` admits arbitrary values and `requery-form` accepts a seq as source (`resources/seon/schemas/seon.print.edn:316–319`; `print.cljc:470–481, :1056–1058`): a lazy source remains embedded in emitted evidence. An existing elision can retain its own unsafe form even when no replacement cut is built. Structural-only legend scanning closes one traversal; it does not sanitize the emitter's metadata.

   There is an earlier public entrance too: `prepare` makes the supplied cursor path a vector and calls `node-id` before allocation (`value.clj:1067–1069`); `node-id` hashes `[agent root-address path]` (`:262`). The unchanged identity printer uses unlimited `pr-str` (`src/seon/id.clj:29–38`). A vector containing an infinite path step is therefore printed before the new classifier can see it. `path-url` and breadcrumbs also print paths (`value.clj:272, :1039`). Choose safe finite coordinates and custody once at entry, retain them thereafter, and refuse unsafe retrieval at the safe ancestor. Do not recursively traverse a lazy value to validate its finiteness.

4. **Scalar is still a type category, not a bounded literal.** A pre-existing multi-megabyte symbol, keyword or big integer is fully encoded by `bounded-node` at `value.clj:620`; `print/text-cost:946` calls unlimited `literal`. The root/first-level scalar routes do the same (`value.clj:801–802, :831–832, :842`). `number?` and `instance? java.util.Date` also include host subclasses (`:522–523`), not just known inert literal implementations. This is not a proof against user printing/accessors. For strings, two huge keys with a long common prefix enter content comparison at `level:690, :709–713` before their length-rejection at `:695`; comparing can inspect the whole prefix despite tiny B. Use a bounded emitter-owned literal representation first; derive order and paths from that representation. Unknown host scalar implementations must follow the opaque rule.

5. **The bounded key walk is not bounded by room at entry.** `bounded-node/walk` always enters a nested collection even when `room` is already negative (`value.clj:610–631`). For admitted collections, `some` at `:628` scans the complete children sequence to locate an elision before the bounded loop. Its returned collection cost also subtracts local room from the *outer* `limit` (`:643`) rather than that call's initial room, overcharging nested containers; this can reject a finite affordable key. Do not retain this as a second recursive pricing algorithm beside `measure`.

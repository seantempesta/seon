# Landing: delete C3, the supplied-default plan mirror (lane delete-c3-supplied-default-opus, 2026-09-26)

Plans for supplied defaults are now built from the compiled Malli contracts in Malli's registry and the snapshot's admitted rows. `contract-arities` reads them with `mr/schema` (`reference-code/malli/src/malli/registry.cljc:97`), splits them with `m/-function-schema-arities` and `m/-function-info` (`core.cljc`), and follows named maps with `m/deref-all` (`core.cljc:2837`). The contract-transaction cache stamp is deleted. The plan cache is now keyed by the snapshot derivation it read. `supplied-map-entries` no longer runs its own join: it reads the entries the planner fills.

## Broken or unproven first

- **Not run: tests.** Following the lane rules, root runs them (list below). The new regression `a-redefined-contract-replaces-its-held-plan` has not been run. It re-transacts only `sample/target`'s fixture row with a new spec. It assumes `program-fn-row` returns a map carrying `:seon.fn/sym`, which I checked by reading `test_support.clj:824`, not by running it.
- **Not published or adopted.** Default still runs the old Vars; hook publication does not publish (`bin/seon-hook:12`). The schema change edits the `:seon.call-preparation/plan` form and removes two entries, `contract-t` and `basis-t`. This is not a key retirement: the `:seon.call-preparation/contract-t` key stays declared but unused, so adoption never needs the A/B retirement. Its removal is a later two-step cleanup. Root adopts `src/seon/call_preparation.clj` and `resources/seon/schemas/seon.call-preparation.edn` together.
- **`test/seon/schema/datahike_parity.edn`** (not mine) snapshots old schema forms, including the plan's `contract-t`. It is already weeks stale; I did not touch it.
- **Two behaviours changed, both on purpose:**
  1. `supplied-map-entries` now counts only entries of *admitted* (coherent) rows, the same set preparation fills. Before, it also counted incoherent rows. Across default's 2,196 contracts the answers are identical.
  2. `plan-for` returns nil for an identity with no compiled contract. Before, it returned an empty plan when a function entity existed without a contract. `db.clj`'s arity verdict then reports that callee's declared arities as its prepared arities, instead of `[]`. It only asks about callees already outside their declared bounds, so the verdict does not change.
- A slip, recorded: one command in this session ran `git checkout -p` with stdin from `/dev/null`. It hit EOF at its first prompt and discarded nothing. I checked afterwards that `git status` and the foreign edits (`script/seon/dev/mcp.clj` root-run-form, `src/seon/cluster/reply.clj` code-sources, `resources/seon/schemas/seon.agent.edn` segmenter, the one-repl doc) were intact.

- Net lines: `src/seon/call_preparation.clj` +79 −178 (**net −99**; 1,331 → 1,232). The +79 is under the audit's 80-line ceiling for additions. `resources/seon/schemas/seon.call-preparation.edn` +0 −2. `test/seon/call_preparation_test.clj` +34 −6 (one new regression, one pinned refusal operation updated, one comment).
- Audit §11 names that no longer exist: `by-fingerprint` became `by-schema-key` in C4 (6 lines, kept). `named-entry-facts` and `argument-validators` were already folded into `argument-facts` / `plan-for` by C4.
- **The plan cache key:** a held plan is valid while `current`'s `prepared-symbols` object is identical to the one it was compiled against. That object is new on every snapshot derivation. The snapshot memo derives again on any change to an attribute it reads (`snapshot-read-attributes` ⊇ `:seon.fn/spec`, `:seon.fn/source`, `:seon.schema/form` and the row attributes; REPL-checked). An unrelated commit hands back the same object, which the existing test `an-unrelated-commit-reads-the-held-snapshot` asserts. This is "memoize functions of immutable values": no db read, no tx stamp.
- **Race guard:** a plan is held only when compiled at the snapshot's own basis (`(= (db/basis-t database) checked-through-t)`). A thread holding an older database than the adopted snapshot gets a plan for its own value, and that plan is never held.
- Rejected alternative: carrying the contracts map inside the snapshot. It made the plan a pure function of the snapshot, but every armed call taking a snapshot (`plan`, `prepare`, `supply`) would then validate a 2,196-entry `[:map-of …]`: **70 µs per validation**, measured. The database's carried projection already holds the same map, identical across unrelated commits.

## REPL evidence (default pid 76020, JVM mode, scratch namespace `lane.c3-scratch`, removed after use)

The final source was copied into `lane.c3-scratch`, with `register-core-predicate!` and `schema.edn/load!` stripped so no default registry or Var was touched. It was loaded with `load-file` from the scratchpad in 81 ms. The scratch copy is unarmed, so values were validated explicitly against the edited schema forms read from the resource file.

- **Equivalence on real data:** for all 2,196 contracted identities in default's carried projection, the old and new `plan-for` gave 0 diffs after stripping the removed `contract-t`/`basis-t` and comparing validator counts. 847 plans are non-empty and there are 0 nil plans. The old and new `supplied-map-entries` gave 0 diffs (312 non-empty). The old and new `prepared-symbols` are equal.
- **Validity:** every new plan validates against the edited `:seon.call-preparation/plan` form. The snapshot validates against `:seon.call-preparation/snapshot`. Every `supplied-map-entries` output validates against its declared output. Each touched function schema compiles against the live registry.
- **Cache:** two `plan` calls on one snapshot return the identical object. With a snapshot checked past the database's basis, the plan is answered and not held.
- **Unreadable graph:** on a history-less, schema-less in-memory store, both `plan-for` and `supplied-map-entries` return `:seon.db/invalid-read` with `:seon.db/refused-read-operation seon.db/q`. The test pin moves from `seon.db/datoms`, because the deleted `contract-transaction` was the first read.
- **Timings:** the outer call was unarmed and inner calls stayed armed, in both old and new:

| Probe | Old | New |
|---|---:|---:|
| `plan-for` cold (per identity, over 2,196) | 468–510 µs | 195–215 µs |
| `supplied-map-entries` (per identity) | 192–255 µs | 141–180 µs |
| `plan` warm hit | 85–167 ns | 105–106 ns |

  The warm hit is noise-level against the ~8.5 µs hook: at most +21 ns, well under the 50 ms rule, though the percentage swings with the old measurement. Armed `contract-arities` costs 72 µs, of which 70 µs is its own `[:map-of …]` output validation. That cost is unchanged by this cut and belongs to C4/instrumentation.
- The probe forms are in this session's MCP history. The key forms were the three equivalence and timing lets in the scratch namespace, iterating `(keys (:seon.schema.projection/function-contracts (seon.db/carried-projection (seon.db/db (seon.cluster.boot/connection "default")))))`.

### Model errors, ranked by the symptoms each produces

**ME-1. "Did the agent define this Var?" and "Does the agent keep this Var across turns?" are one SCI generation stamp.**
- Symptoms: required dependency Vars dropped at the next turn (fix-agent-path Defect 2); then, after 38ab16d95
  stamped the copies, `(require '[malli.core :as m])` refused as a change to ≈300 `malli.core` Vars
  (smoke); "library Vars seen as program changes" (root's list).
- Deciders today:
  - `seon.sci.eval/turn-interns` (eval.clj:494): generation-owned Vars = this form's definitions.
  - `program-definitions` / `program-change` / `admit-program-change!` (eval.clj:571, 614, ~956): every
    generation-owned function Var needs an analyzed row, or `unindexed-change`.
  - `regenerate-agent-context!` (eval.clj:3085–3116): carries only generation-owned Vars.
  - `load-host-namespace` (eval.clj:249–275): stamps library copies to satisfy the carrier, which lies to
    the definition authority.
- One owner:
  - Authorship is the SCI `def` event, the generation stamp SCI itself writes (`evaluator.cljc:25-49`).
  - Carriage is "the agent's namespace state that its base does not have".
- Smallest change:
  - Delete the stamp in `load-host-namespace`.
  - `regenerate-agent-context!` also carries a Var whose path the base it forked from never had.
  - Nothing else decides either question.

**ME-2. An error value's `:seon.error/operation` is read as "the function that returned this value".**
- The operation names the boundary that raised or recorded the error, not a return:
  - `seon.sci.eval/evaluate` never returns an error. It returns `:seon.sci.eval/evaluation`.
  - `seon.sci.kernel/failure-value` declares `:seon.error/base`, which `named-alternatives` removes by
    construction.
- Symptoms: the "Contract finding: … none of its declared error alternatives matches it." line on every agent
  exception (`(/ 1 0)`, `(inc "a")`, `ex-info`), on every definition refusal (`unindexed-change`,
  `multiple-declarations`, `declaration-absent`), and on instrument refusals (`identity-names`). This is
  dogfood #14's "trailing Contract finding line".
- Deciders:
  - `seon.render/declared-pairs` error branch (render.clj:514–524) plus `seon.error/render-undeclared-ai|html`
    (error.clj:1907–1928), added in e7c4deb4c.
  - The real owner already exists: the armed output contract (`seon.instrument/compiled-wrapper`, Malli
    `-instrument :scope #{:output}`) refuses an undeclared return AT the producer, in both dials (8542c8131).
- Smallest change: delete the render-time finding (both renderers and the branch). Errors render through their
  satisfied alternative's pair, else the base pair.
- **This reverses a design ruling (e7c4deb4c), so root confirms.** The law "Decide at the authority" is the
  justification: the producer's armed output check is that authority.

**ME-3. Contracts are read from two different values: authored source (symbols) and evaluated Var metadata
(bare functions). The refusal builder inverts the second as if it were the first.**
- Symptoms:
  - "the refusal could not be built" for every contract with `[:fn some.ns/pred]` whose wrapper was compiled
    from Var metadata: 72 `[:fn …]` sites in src, 30 of them `clojure.core/ifn?`.
  - Dogfood-author #5: `inst?` is refused unquoted (metadata holds a fn) and quoted (`canonical-definition`
    gets `(quote inst?)`).
- Deciders:
  - `seon.instrument/compiled-wrapper` (instrument.clj:580–596) compiles `authored`, which is
    `(mi/-schema var)` (instrument.clj:852), i.e. evaluated `defn` metadata where `clojure.core/ifn?` has
    already become the fn.
  - `seon.instrument/predicate-callable` (instrument.clj:415–421) derefs the Var.
  - `seon.schema/canonical-definition` (schema.clj:597–611) documents itself as the inverse of evaluated
    metadata ("Evaluating Clojure metadata resolves predicate symbols to callable roots") but inverts only
    Vars and identical binding values.
  - `boundary-refusal` → `expected-shape` (instrument.clj:542–578) runs that inverse on every input/output
    refusal.
- One owner: the declared contract is the authored form (the row's `:seon.fn/spec`, the projection registry).
  The predicate is its Var.
- Smallest change, both in files this lane does not hold, so both go to root as patches:
  - make the inverse total over what evaluation produces: a fn identical to a bound Var's root reads back as
    that Var's symbol;
  - `predicate-callable` answers the Var, not its root.

  The larger alternative, arming from registry forms only, is listed for the Astra comparison.

**ME-4. "What SCI can interpret" is a copied list in the indexer, not the interpreter's configuration.**
- Symptoms:
  - Dogfood-author #4: `(java.util.Date.)` evaluates, then every later call refuses "Host-bound … load its
    source files", and on pid 19859 raises a branch error each run.
  - "Host-bound classification of `(java.util.Date.)`" (root's list).
- Deciders:
  - `seon.fn/host-bound-callers` (fn.clj:1051–1054) checks `sci.opts/default-classes` plus a hand
    `Throwable/Error` exception.
  - The interpreter itself has been `:classes {:allow :all}` since a88a1167 (eval.clj:392; fork `interop.cljc`
    `host-class-opts`).
- One owner: the SCI context's class config. What stays genuinely host-bound is only what SCI cannot interpret:
  - `reify`, `proxy`, `definterface`, `import`, `deftype`, `defrecord` definitions;
  - JVM macros from uninterpreted namespaces.
- Smallest change: delete the java-class clause and its Throwable special case. `unrestrict-sci` asked for
  this in its root-runs step 2.

**ME-5. A branch's change is computed against the JVM's loaded program, not against the branch's fork point.**
- Symptoms: dogfood #1, where a branch forked before an adoption refuses every form with "Host-bound
  declaration … must change through the loaded source files".
- Deciders:
  - `overridden-row?` (eval.clj:1615–1620) compares with `::loaded-database`.
  - `install-row!` host-row/unbound refusals (eval.clj:1695–1735).
- Owner: the branch's diff from its fork commit (Datahike branch lineage, `versioning.cljc`).
- **Not attempted here.** It is a cross-owner design (acquisition and adoption). It is listed for root.

**ME-6. Checks run effects in the agent's live custody instead of a fork.**
- Symptoms:
  - Dogfood-author #3: the auto-check and gate bodies write junk notes into the live branch.
  - Dogfood #3: a branch test member inherits custody.
  - Dogfood #6: a test world has no agent row.
- Deciders: the auto-check and gate runners (`seon.test`, `my.test`), which are not in this lane's files.
- Owner: the test world as a `d/with` or fork of the caller's commit. **Listed for root.**

**ME-7. Analysis runs at a different granularity and order than evaluation.**
- Symptoms:
  - Dogfood #11/#22: an alias required earlier in a batch leaves the run unsettled.
  - Dogfood #12: `(do (in-ns …) (defn …))`.
  - Dogfood #17: `register!` works only at top level.
  - Dogfood #20: name-order install, where acquisition installs a namespace's rows by `sort-by first`
    (eval.clj ~2832) and analyzes each body against a partial namespace.
- Owner: the evaluation sequence. A REPL reads and evaluates one form at a time, and a namespace installs in
  source order.
- **Not attempted here** (acquisition redesign). Listed.

**ME-8. A failed run is not settled with its cause.**
- Symptoms:
  - Dogfood #4 (fixed b96d6e684).
  - The sorted-map wedge: `seon.schema/valid-candidate-value?` throws ClassCastException on symbol-keyed sorted
    maps, and the run stays open.
  - Dogfood #21: sticky `::unavailable-execution`.
  - Dogfood #22.
- Owner: the run settlement's `finally`.
- Not attempted here.

**Direct defect, not a model error: `seon.fn/identity-names` contract `[:sequential :int]` vs callers passing
sets.**
- The callers:
  - `call-reach`: `(named seed-callers)` and `(named reaching)` are sets (fn.clj:1881–1897);
  - `reverse-closure`: `(functions callers)` is a set (fn.clj:1923).
- It came from today's call-reach change, which ran without its reaching tests. Every contracted `defn` reaches
  it through the gate, so no contracted function could install anywhere.
- Fix: the helper declares the set of entities it names; the one sequential caller passes a set.

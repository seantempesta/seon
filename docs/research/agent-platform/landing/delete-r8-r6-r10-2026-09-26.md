## Landed: R10 partial, render once (`5c88d5110`, `src/seon/test/runner.clj` +31/−26, net +5)

Before this change, each failing assertion rendered expected/actual three times: once in
`failure-report`, again in `capture-event!`'s `failure-message`, and again when `report-event!`
printed `failure-message`. `message-text` also ran three times. Now `capture-and-report-event!`
builds the `failure-report` once per failing event. That one report feeds the stored evidence, the
identity and the gate-log text. `failure-message` lays out the report's already-rendered fields and
now declares a contract, `[:=> [:cat :map :map :seon.test.failure/report] :string]`.
`report-error!`, `report-event!` and `capture-event!` take the report as an argument. Deleted
paths: the two re-rendering calls to `report-value` inside `failure-message` and the per-event
`failure-report` inside `capture-event!`. No definitions were deleted, so the result is net +5
lines. No test calls the changed arities; tests reach this code through
`capture-and-report-event!`, whose signature is unchanged.

REPL evidence (jvm, default; scratch namespace `tmp.r10-runner` holds the five new forms, interning
default's other runner functions; nothing of default's was redefined):
- Five edge cases compared old `failure-message` with the new layout-from-report under
  `*testing-contexts*`: nil expected, message with no operands, Throwable actual, non-string
  message, empty message. All `:same? true`.
- A real `clojure.test/test-vars` run of a probe test (a `testing` failure, a pass, a thrown
  ex-info), old vs new `capture-and-report-event!`: same gate-log output, same counters
  `{:error 1 :fail 1}`, same captured results (identities, reports, `failure-message`). Every
  stored report validates against `:seon.test.failure/report` in the live projection.
- Timing: five failures on a 300-map vector took old 43.6 / 43.5 / 43.1 ms and new
  15.3 / 15.3 / 22.6 ms, with identical output. One `failure-report` costs 6.3 ms; the old
  `failure-message` cost 8.7 ms each time it ran; the new layout costs 0.02 ms.
- Scratch copies run unarmed, so real values were validated explicitly: reports against
  `:seon.test.failure/report`, output string.

## Landed: R6 (`src/seon/cluster.clj` +9/−71, `test/seon/cluster/mcp_test.clj` +25/−83)

`mcp-projection-error` (20), plus the `exception-summary-value` branches in `mcp-project`, for

`{:seon.probe/k 1}`, cause, phase, trace) in 12.5 ms, blob-backed at 9,223 bytes, retrievable by
digest. The summary took 2.3 ms because it stores nothing. The difference is the ordinary
blob put for any value over `:seon.config.eval.result/blob-threshold`.

Tests converted in the same commit. Deleted `jvm-nil-deref-is-a-flat-error-value`,
`jvm-ex-info-projects-its-message-class-and-first-party-frame` and the flat-summary scenario,
including its retired "10× smaller than the envelope" assumption. They are replaced by the
lifecycle scenario `jvm-exceptions-keep-the-whole-cause`. It asserts that a small exception stays
inline, that every via link's message, class and ex-data is present, that the root cause is the
value's `:cause`, and that an oversized cause pages by digest at `[:cause]`. On default, the same
ordinary path returned inline, `[{:seon.probe/member 1} nil]` data per link; an oversized
5,000-char cause returned windowed, retrievable, with a 72-char page and total 5,000. The five
`seon.dev.mcp` error schemas stay (no schema retirement in this cut); retiring them is the

## Atom audit R9 (profile snapshots): H24 falsified; H25/H26 landed (`098efab50`, +10/−8)

H24 ("immutable map with LongAdder identity keys") is false. A Clojure map compares Number keys
by value (`clojure.lang.Util/equiv` → `Numbers/equal`), and LongAdder is a Number. On default,
`(= (LongAdder.) (LongAdder.))` is `true`, and a persistent map over the 2,001 live cells held
only 1,715 keys. Its keys also rehash as they count. The snapshot therefore stays an
`IdentityHashMap`; the docstring now records why. H25/H26 landed: the per-cell values are
immutable `[calls nanos]` vectors and the missing default is `[0 0]`, replacing `long-array`
cells. Deleted: two `long-array` constructions and four `aget` reads.

REPL evidence (jvm, default; scratch fns only): the identity snapshot covers all 2,001 cells.
Growth read through the vector layout matches the array layout over the same snapshot (same
members). Call counts differ only by the armed `cells`/`adder?` calls made between the two
readings. `begin` costs 0.20 ms (array) and 0.55 ms (vector) for 2,001 cells, about 0.35 ms
extra per profiled operation. It is well under the 50 ms rule but above 20% relative; root should
decide whether that is acceptable for immutability, or revert.

## Atom audit R4 (supplied defaults): A010 landed; A008/A009 stopped

**A010 landed (`5f98ca9b3`, +25/−28).** `prepare`'s `(volatile! nil)` refusal is gone. Each
reduction returns `(reduced refusal)` at the first refusal, and a stopped reduction's value is
the refusal map rather than the argument vector. Behavior change: the old code kept calling later
suppliers after a refusal and returned the last one; the new code runs no later supplier and
returns the first. REPL evidence (jvm, default; new `prepare` in scratch namespace `tmp.r4-cp`,
all other call-preparation functions interned from default): 600 cases (the first 120 prepared
symbols × `[] [nil] [{}] [nil nil] [{} nil]`), plus 150 map-entry cases over 30 of the 313
entry-bearing plans (142 optional entries). Every case produced the same shape. That covers
inserted `datahike.db.DB` by schema name, a caller's `nil` kept (caller wins), and the refusal
`:seon.call-preparation/unavailable-key :seon.agent/id`, which is expected: the probe environment
holds no agent. The run took 111 ms for 600 cases. Not proven here: the armed contract on the new
body, and a case where an optional entry is actually filled or omitted. Those need
`seon.call-preparation-test`.

**A008/A009 (the call-state atom): stopped, for two reasons.**
1. *Consumers are outside this file.* `state`/`install`/`carrier` feed
   `sci/eval.clj:3415,3475` (`install`) and `sci/kernel.clj:642` / `sci/eval.clj:293` (`hook`).
   `state?`/`state-generator` back `:seon.call-preparation/state` in
   `seon.call-preparation.edn:217-219`, which `seon.render.edn:1,44,51` reuses as its
   `:seon.render/cache` type. The audit itself says to remove state/install plumbing only once
   the consumers are converted (R1/R2/R5 coordination).
2. *The direct replacement regresses the hot path.* The hook runs on every SCI Var call (about
   8.5 µs). Measured on default (jvm, 20,000 iterations each, unarmed originals): the atom path
   `current-snapshot` costs 0.50 µs per call; the pure memo path `snapshot` costs 2.94 µs. That is
   +2.4 µs per call, about +28%, over the 20% rule. The cost is armed internals and key building:
   `snapshot-revision-key` 594 ns and `snapshot-memo` 626 ns armed, against
   `committed-value-identity` 37 ns and a commit-key LRU hit 31 ns. A viable design keys the
   projection-held memo by commit identity first, calls its internals unarmed, and holds plans in
   a projection-held LRU keyed by the snapshot's revision key plus symbol. It needs the SCI hook
   (degraded on default now) to prove cost and behavior.

Source-level correctness finding for A009, not reproduced: `current-snapshot` uses the held
snapshot whenever its `checked-through-t >= (basis-t database)`. A caller holding an OLDER
database value, or a branch connection with a lower basis sharing one cluster context's
call-state, therefore gets the newer program's snapshot and plans. The audit names this case
("a newer basis is not a valid answer for an older captured database"). The pure memo design
fixes it.

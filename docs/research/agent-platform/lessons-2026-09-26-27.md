## 1. Restart-to-find-out churn and boot failures

More than ten default JVMs were booted in the window (pids 59671, 70849, 89341, 12212, 17853, 20656, 25122, 29853,
32187, 34618, 51535 and others appear in landings), and root ran ten focused test lists (`tests-0627a` … `-j`).
Many restarts existed only to learn whether HEAD booted. HEAD failed to boot at least these times:

## 2. The default OOM

At 22:12Z default died of heap exhaustion. http-kit's error path called `printStackTrace` on an instrument
refusal whose offending request held the agent roster atom; printing through the atom walked every agent's world,
toward 2^31 characters. Fixed in `fac32e9c4`: an atom, delay or promise in an error prints as `#object[Class 0xhash]`
and is never printed through.

The same class appeared three more times:
- clojure.test messages printed whole worlds (`OutOfMemoryError` in `core_print` in host-test and accretion-test,
  red-triage 1); bounded test messages in `b1229d1a3`.
- `printed-bytes` in refusal-test wrote `(pr value writer)` into the harness's captured output (`556cd021d`).
- The operator's start reply carried ~310 KB of stored test runs (`fd3eda0d1`).

After two OOMs root imposed a load cap: one bounded probe per lane, no loops, no whole-store sweeps, no test
requests from lanes (investigation preamble). The law: nothing prints unbounded outside the floor printer; errors
name places, never print through them.

## 3. Test-world contention and central test runs

- **Install-gate recursion.** One `bin/test-check --ns seon.cluster.host-test` drove default to 10.2–10.5 GB of
  10.24 GB: 24 virtual threads each held a nested `with-database` world through `gate-function-install →
  run-candidate-test! → hosted-run!`, and live Datoms went 3.77 M → 20.3 M in 40 s. The gate selected the test
  because it *quoted* the function's symbol (`host_test.clj:305`); ruling: call reach, never symbol mentions
  ([inv-heap-stuck-members](landing/inv-heap-stuck-members-opus-2026-09-26.md)).
- **The member-unfinished wedge.** `9fc60b979` made test admission cluster-global to stop that nesting. Then one
  web-test member started with 690 ms of its 120 s bound left, outlived it, and every later request on the cluster
  was refused `:seon.test/member-unfinished`. `e6b5470e8`: an unexited member holds only its own test.
- **A lane killed its own client** with a self-matching `pkill -f` (inv-heap-stuck-members, broken item 2).
- **The save gate could not prove checkout paths.** Under the law that every JVM runs a committed archive, a lane's
  uncommitted edit cannot reach the JVM that would test it (task `d0c5aed54`). Lanes therefore prove statically,
  commit, and report RESET NEEDED with exact tests.
- **Root ran tests centrally.** Ten focused lists (`tmp/orchestrator/tests-0627a` … `-j`), each triaged from stored
  `:seon.test.run`/`:seon.test.member` rows. The web-test red count went 18 → 40 → 86 → 14 across lists d–h: the
  spike was the required-only supply `2f2b51861`, repaired by `a6ec14a8c` (render entry points pass their database).

The law: root runs one focused list per batched restart and returns each red to its owner; assigned agents start
no test requests; an unexited body blocks only its own work.

## 9. What worked

- **Astra review rounds converged.** konserve deferred sync: ACCEPT-AFTER-FIXES (`05b2d0f5f`) → fixes → adopted
  (`9fd4d9d50`). Contracts-out-of-the-projection went through three re-reviews (`a760a6d08`, `ba711c08c`) to a
  stored-facts check of 2,358/2,358 equal. Derive-once and the eval-path audit came back REVISE with corrected
  orders that root adopted. Astra's audit of the day's landings (`afb449f0c`) caught the custody test artifact
  (F2) and a batched-transaction flaw in `ab87961d5` (F1).
- **Evidence-based red triage from stored runs.** Two read-only triages sorted 72 and 85 reds into
  NEW/STALE-TEST/FIXTURE/TIMEBOUND/PRE-EXISTING/UNKNOWN, each naming its commit or the missing evidence, and each
  list's reds were routed to owners the same hour.
- **Measured performance wins**, summarized in the table above: konserve flush policy, Malli's armed path, the
  history-free program-change check, the shared node cache (`fc0ff40b9`), boot arming against the published
  commit (`23a08e4ad`) and program classes cached per commit (`52f35ed2b`).
- **Patches for held files.** Lanes wrote patches under `tmp/<lane>/` for files other lanes held; root applied
  them. The two mis-applied hunks (section 1) are the argument for linting the archive before committing.

## Law changes this note produced (AGENTS.md `f227f4dd4`)

How to think (measure before believing); How to work §5 (convert every caller, including quoted symbols and error
operations; lint and compile from a `git archive` with `--cache false`) and §6 (no restart to find out); boot reads
the configuration it applied; identities minted by their owner; admission judges writes, not reads; attribute
lists derived from schemas; places print as identities; nothing prints unbounded outside the floor; harness-prepared
deterministic tests with no Var redefinition or JVM-global identity; centrally run focused lists; held files take
patches; recursive deletion stays in your own root.

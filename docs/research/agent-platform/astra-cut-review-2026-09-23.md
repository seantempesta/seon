## Findings that change the queue

1. **The dead census is unsafe as deletion authority.** `fn/analyzer.clj:221` memoizes `manifest-roots`; `sci/kernel.clj:96` delays `new-guard`; `config.clj:556` calls `settings-projection`; `db.clj:125,130` calls `fresh-connection`; `cluster/store.clj:124` calls `fresh-file-lock`; `cluster/boot.clj:393` delays `install-uncaught-handler!`; `print.cljc:179,183,187` uses `distinct-generated-nodes` in generators. Deleting these breaks load or later execution. The index gap is already scheduled in the ledger; do not open a duplicate defect.
2. **R2's stated prerequisite is false.** `db.clj:4304-4343` classifies failures, constructs an observation, throws under panic, or returns it. That catch does not commit the fault and wake its responsible agent. It cannot justify removing the writer's sole diagnostic on the assertion that durable recording already happens there. `cluster/store.clj:609-617` also prints a caught panic and continues; retaining full `Throwable->map` there does not satisfy the loud-panic/delivery policy.
3. **R3 omits the wake route and reverses the safe retirement order.** Live registrations: `eval/drive.clj:63`, `sci/eval.clj:2434`, `schedule.clj:799`, **`cluster/wake.clj:506`**. The failed registration must be retired before a fault transaction can trigger it again. Unlisten-by-key alone can remove a newer registration. Preserve identity-sensitive retirement and committed-write completion; the current generic fork fix and Seon's policy are different concerns.
4. **R7 is not a dead-code revert set.** `datahike/query.cljc:4671,4688,4775-4779` reaches single-flight on ordinary queries. `writer.cljc:263` calls `committed-report/offer-committed!`. No direct Seon call to a public host API does not establish that the shared machinery is unused. Historical reverts overlap later cache correctness/retention fixes.
5. **R6 is not a 25-line `seek`/`take` substitution.** `datahike/index_page.cljc:14,45,78,91,114` implements validation, temporal order restoration, resolved prefixes, cursor identity and added/retracted distinction, reverse seeks, prefix termination, lookahead and weight bounds. These are observable current guarantees.
6. **L3 is ordered after the first namespace agents.** README §7, “Priority to namespace agents” (`README.md:408`), explicitly rules this. Free files and a general desire for cuts do not override it. The ledger independently marks L3 held. Shrink-schema S3's “predicates belong to the fork” also conflicts with S9's removal of that very fork behavior.
7. **Already changed is not remaining work.** L1 commits removed the bootstrap driver and many named definitions; schema/edn already uses `cache/lookup-or-miss` (`:379-385`); oversight no longer scans the instance registry (`oversight.clj:38` onward); source already calls three-argument `fn/report-identities` (`source.clj:321`, dirty `fn.clj:3303`). S2's load-start ordering is present in dirty `dev_cache.clj:108-115`; S11's beta4 rebase is in history. Do not spend their deletion estimates again.

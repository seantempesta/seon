# Registered predicates resolve in the evaluating context

Independent Astra plan, 2026-10-14; source HEAD `e5dd2abd5`. Status: proposed; no implementation.

Today declarations become a Malli registry, whose compiled schemas retain predicate callables; SCI arming replaces only inline predicates. Make the existing SCI acquisition owner supply one context-local projection to every consumer, and use Malli's existing reverse dependency closure when a predicate first changes from compiled to interpreted.

## Ownership and composition

**`seon.sci.eval` owns resolution.** Keep the immutable resolved projection in the context's existing `:seon.sci.kernel/program-snapshot`, under `:seon.schema/projection`; carry that value through the evaluation request. This is context custody, not cluster program state: initialize/copy it at context acquisition/fork and replace it when acquisition changes predicate bindings. Never send it to `seon.sci.eval/advance-context-projection!`, `seon.env/advance-projection!`, connection metadata, or a cluster projection cache. The current shared environment remains the compiled declaration basis. Audit snapshot replacement and fork construction together so neither drops the value nor carries an unrelated context's resolution.

Inputs are the declaration projection, the context's interpreted definitions (including affected callers), and predicate symbols from registered declarations **and the current authored contract**. Resolve interpreted predicates to their SCI Vars; retain JVM Vars for compiled predicates. Include newly defined branch-only predicates before contract admission, even when the base projection has no binding. Use the existing `:seon.schema/predicate-functions` shape; no new registry, resolver protocol, atom, or ambient dynamic Var.

`seon.sci.arm/arming-projection`, `seon.sci.eval/arm-contract!`, `seon.turn.batch/write-entity`, contract instrumentation, and explicit branch validation receive this same projection. The recording/writer request carries it as an evaluation input for declaration admission and contract facts; it is never installed as a writer-global projection. Run context-dependent validation inside the explicit request's SCI context, including any writer thread handoff. Compiled host function wrappers keep their compiled projection; asking the writer to validate a branch declaration with a supplied projection is distinct from replacing those wrappers. This preserves the branch-only predicate admission test.

Malli owns compilation: `malli.registry/lazy-registry` plus `malli.registry/composite-registry`, sealed by `malli.registry/simple-registry` in `seon.schema/projection-registry`. `malli.core/-fn-schema` evaluates its child once and retains that callable; `malli.core/validator` therefore cannot discover a replacement binding by itself. Extend `seon.schema/projection-with-declarations` so changed predicate bindings seed the existing schema and function reverse closure. Recompile that closure, including inline-only contracts, and replace its contract products; unrelated registry entries remain identical. A retained contract-product cache must never supply a product compiled with the old binding. Full-build equivalence is the proof.

Dependency pins examined: Malli `dd13ff81139159778edb0a67b491eccc0baa991d`; SCI `eb3290d5c5ed72133ae1947492ecd324413868ed`. `sci.core/fork` preserves Var identity with contextual bindings; `sci.lang.Var` invocation dereferences that binding. No per-call symbol resolution is needed.

## Redefinition, deletion, and cost

At `seon.sci.arm/arm!`, finish `seon.sci.eval/interpret-affected!` before the next expression: intersect the newly interpreted symbols with predicate usage, derive the local projection, then re-arm **already interpreted consumers** of the affected contracts. Include the function just armed and definitions earlier in this request, not only committed database rows. Reuse `seon.instrument/wrap-interpreted`, which unwraps its original and preserves the profiling cell. Compiled ordinary callers still follow existing interpretation policy; host-bound wrappers remain compiled.

This re-arm is necessary on the first JVM-Var → SCI-Var transition. Later root changes use the same SCI Var and existing validators see them without recompilation. A new Var after unmap/redefinition, declaration removal, or return to a compiled binding is another binding change and uses the same closure. Tests must exercise inherited wrappers after a fork: an SCI Var alone is not a context boundary; the evaluation's explicit context selects its root.

Delete both `context-predicates` merges and the function itself when every consumer uses the resolved projection. Keep `runtime-predicate` for compiled resolution. `register-core-predicate!` remains its existing load-time assertion; deleting unrelated registration machinery is outside this slice. Do not install the failed patch's cluster-shared projection or add call-time `get-ctx` resolution.

Main retains compiled Vars and its existing projection: **zero added predicate dispatch/recompilation work**, not a promise of zero request latency. Branches with no predicate transition likewise derive nothing. Transition work is predicate-use discovery plus the reached schema/contract closure and affected installed wrappers. The simplest implementation scans declaration predicate usage once per binding transition; that is O(population + reached closure), not O(closure). The existing `::declaration-predicates` cache is only a symbol→Var map, not a reverse-use index. Add a content-derived reverse-use map only if measured transition cost justifies it; never scan per call or per armed function. Later validation adds SCI Var dereference and predicate execution only. No performance gain is yet proven.

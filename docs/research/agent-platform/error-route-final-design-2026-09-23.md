# One error route: final design

**Decision:** retain `seon.fault/fault!`, grown from `commit-fault!`, but replace draft B’s step wrapper plus residual channel recorder with one Flow-native reporting hook. Reuse the existing committer for acknowledged batching; do not add a second accumulator or throwable registry. This is a proposal, not an installed guarantee.

## Evidence and verdict

Read AGENTS.md end to end, the plan, draft `a7ffa4be0`, all four `error-route-inspiration-*-2026-09-23.md` notes and the complete swallowed-errors census. The optional `flow-usage-audit-2026-09-23.md` was absent. Source observations were made against HEAD `c9bcbfaf0` plus the shared working tree; foreign edits were neither loaded nor changed.

Dependency pins (gitlinks): core.async `dc35f3e0d7bc2eef502e77982f48641f025c8051`; Datahike `fbd1ad2d10fb1261ef7092737a02801537c16e70`; Clojure `b18d3adc5b5f4d5d0ccea966203fb67a614d5c3d`; clj-kondo `57252e07975710aa579b24f0d1b2b1e04195caa2`. Below, **Flow** means `reference-code/core.async/src/main/clojure/clojure/core/async/flow/impl.clj`; other abbreviated paths are introduced explicitly.

1. **B as written does not meet every requirement.** Flow’s sliding-100 error channel drops before any consumer sees the error (Flow:102). The wrapper misses output dispatch, compute timeout and outer-loop failures (Flow:259,307,317), as well as channel transducers (Flow:105). Keeping a counted-dropping route for those failures still loses their individual causes. A count/digest is not their durable error fact (`src/seon/flow.clj:966-997`).
2. **Draining promptly is insufficient.** A synchronous consumer cannot undo upstream eviction; an unbuffered channel alone acknowledges receipt, not commitment. A maintained-fork hook in Flow’s existing catches supplies the failure map and receives a terminal/continue decision before recurrence (Flow:312-322). That removes Seon’s duplicate step catch and preserves Flow’s full pid/cid/message context.
3. **B adds avoidable mechanisms.** Keep `error/recording`, `commit-call`, signature and occurrence identity (`src/seon/error.clj:151-177,1365-1549`). Move, do not copy, `cluster/commit-fault!` (`src/seon/cluster.clj:2966-3067`) and the committer (`src/seon/flow.clj:1005-1079`). Delete its `seen-signatures`, drop recorder and local dial readers. A process-global weak throwable set plus a separate burst map is unnecessary; WeakHashMap also uses equality, not guaranteed identity for arbitrary Throwable subclasses.
4. **The cache defect gates this design.** Draft P4 measured 1,099.9 ms inside `commit-call`, versus 26.1 ms outside and 1.2 ms applying expanded transaction data (`one-error-route-design-2026-09-23.md:99-113`). The projection-holder miss is a supported hypothesis, not a completed profile. `error.clj:1398-1411` scans declared schemas; `src/seon/schema.clj:397-416` recomputes when the holder is absent. Fix and measure it FIRST: otherwise every first fault synchronously blocks for about a second, and batching merely conceals the defect.

## One required namespace and exact boundary

```clojure
(require '[seon.fault :as fault])
(catch Throwable failure
  (fault/fault! world failure
    {:seon.error/layer :seon.boot/request
     :seon.error/operation 'seon.cluster.boot/request!}))
```

`world` is the already-held environment: explicit connection, cluster and process identity, plus the cluster’s existing committer handle. No registry lookup or ambient projection. Throwable calls use the declared exception schema; a core-error VALUE additionally supplies `:seon.error/declared-schema`. Optional context is agent, turn, graph/proc, input and reproduction form. Agent mistakes return their declared flat error directly and never enter this route.

`fault!` has a complete contract: environment × (Throwable or recorder-owned error base) × named open context → named `:seon.fault/recorded`; panic throws. Returning boundaries explicitly admit that result in their output union. A Flow adapter discards the recorded result and tells Flow to retain pre-step state with no outputs; it never substitutes an error map for `[state outputs]`.

All policy lives in `seon.fault`: `policy(mode, committed?)` returns `:record` only for `[:record true]`, otherwise `:panic`. The writer acquires the cluster’s effective dial at the admitted transaction basis; absent, invalid or unreadable configuration panics. The committed receipt carries that observed decision. No stale environment dial and no other policy reader. Invalid input still prevents entry; invalid output still refuses in production—`:record` does not authorize executing past a contract failure.

Sequence: preserve cause → prepare through `seon.error` → commit occurrence and required wake atomically → observe committed outcome → apply policy. Recipient selection remains writer-owned: namespace steward, otherwise configured root; attribution identifies the affected agent without automatically making it responsible. Missing recipient refuses and panics. Existing fallthrough to nobody at `error.clj:1460-1465` is removed.

Record-once means **once per propagation**, not once per object lifetime. A panic wraps the original as its real cause and carries the completed recording receipt (store/branch, occurrence identity and commit evidence). An enclosing boundary recognizes that receipt, including through cause-preserving wrappers, and propagates it without another count/write. An arbitrary `:seon.error/id` alone proves nothing. Reusing the original Throwable in a later independent failure counts again. No global weak-set lifetime, cause-wide suppression or cross-cluster suppression.

Low-level namespaces required by the route handle declared cases or propagate; they must not require it cyclically. Flow receives the callback as construction input from the cluster owner; `seon.fault` may use Flow’s generic construction API without Flow requiring `seon.fault`. Bootstrap uses the same recording implementation directly until the committer exists; committer failure never enqueues itself.

## Flow is the execution owner

Extend the pinned fork with an optional error-handler in graph/proc construction. All existing step/output and outer/control catches call it with the existing failure map, on the proc’s I/O control thread. The hook calls `fault!`; a recorded result permits continuation, a panic is a terminal disposition. Handler failure exits that reporting path directly, never recatches and reports itself. Startup/initialization failures call the same adapter from the graph-start boundary and rethrow. Preserve Var invocation for reload (`src/seon/flow.clj:132-149`).

Under panic, stop admitting work to the affected graph, record its failure identity, exit the failing proc and request sibling-proc stop through existing Flow control. The supervisor observes actual completion; the failing proc never joins itself. `flow/stop` sends control and closes channels; it is NOT an exit proof (Flow:174-183). A timed-out compute Future can still run (Flow:259-260): mark it failed with exit pending, retain resources and deny overlapping work until its real exit. Keep the JVM, REPL and other graphs available.

**Smallest viable constraint:** reject channel `:xform` in Seon graph definitions and express transformations as ordinary Flow steps. The source search found no `:xform`, `:in-opts` or `:out-opts` under `src/seon`; admission must enforce this, not depend on that search. Channel exception handlers run during buffer mutation under the channel mutex (`reference-code/core.async/src/main/clojure/clojure/core/async/impl/channels.clj:78-94,283-300`); do not transact, wait for a committer or stop a graph there. Supporting arbitrary channel transducers requires the larger dependency change priced below.

The error channel and monitor taps become observations of already-handled failures, permitted to slide. Remove counted dropping from the authoritative path. Expand Flow use by putting remaining long-lived background loops under its lifecycle; short foreign callbacks and subprocess boundaries use the same `fault!` adapter. Do not create another scheduler or reporting executor.

## Fingerprint, evidence and cheap writes

Accrete D13’s one signature: retain layer, operation, declared schema, expected key/shape and path; replace the single throwable-class/frame component with the ordered cause classes and ordered first-party `[normalized-class method source-file]` frames, excluding line numbers. Preserve full lines, messages and ex-data as evidence. No message-based classification or second identity. This distinguishes different inner causes hidden by one wrapper, but may split one bug by caller path; compare both keys over real faults before rollout, without claiming measured superiority.

Normalize generated names structurally: scan raw class characters at `$` boundaries; for a generated segment `fn__`, `reify__` or `eval` followed ONLY by nonempty ASCII digits, replace the digits with a fixed token. Preserve the enclosing namespace/function and ordinary digits in user names. Resolve genuine declared names against program rows first; ambiguous names stay unchanged. Compiler generation is explicit (`reference-code/clojure/src/jvm/clojure/lang/Compiler.java:4552-4568,7761,8545`). Use `Compiler/demunge` for display after normalization; it itself uses a regex internally (`:3450-3467`), so this does not claim a regex-free dependency. The Seon scanner needs no production regex or permission. Do not use `String.split` (regex), or strip every `--` suffix as `src/seon/error/refusal.clj:35-36` does.

Use the grouping function’s admitted semantic definition digest as an input only when intentionally changing grouping semantics; never a whole-program commit key. Retained signatures remain historical observations. Key first-party membership and schema-derived products by the declarations/revisions they read. Datahike already supplies the shared cache mechanism (`reference-code/datahike/src/datahike/schema_cache.cljc:7-29`); repair reuse there/at the owning derivation, not with a new connection-side atom. A fault-data transaction must cause zero program/schema recomputations; a changed relevant declaration must invalidate precisely its dependents.

**Chain correction:** F0’s chain is outermost-to-root (`src/seon/error/refusal.clj:74-88`), not root-first as the draft says. The schema calls it evidence, not a stored attribute (`resources/seon/schemas/seon.error.edn:282`). Its absence on the error row alone therefore does not prove loss. Verify round-trip from occurrence evidence/blob; ensure Flow’s `::flow/ex` enters the constructor (`error.clj:100-101,550-558`). Keep the complete cause and suppressed recording failures in the live exception; declare durable evidence and explicit elisions through the existing admission/blob owner, without storing arbitrary result objects.

## Burst accounting without a second route

Retain one committer per cluster and its lifecycle, moving its policy into `seon.fault`. Its state holds only pending observations and waiting callers, not a mirror of database counts. Group by **occurrence identity**, which includes signature plus agent/turn or process (`error.clj:1525-1529`), never fingerprint alone. Backpressure at declared capacity; no eviction, synthetic replacement or unbounded pending puts.

A new occurrence or reopening commits immediately with evidence and wake. Concurrent repeats merge their deltas; flush the whole pending batch at a real Flow timer event, initially a proposed 100 ms window, or sooner on capacity/stop. All repeat callers await the commit acknowledgement before returning or throwing their policy result. Each transaction increments the existing no-history count by the batch delta and updates last-at; retain first-at, avoid reasserting diagnostics (`resources/seon/schemas/seon.error.occurrence.edn:2-5`; current waste at `error.clj:1412-1471`). Decide new/reopened state and count inside `commit-call`, not by a caller pre-read.

This buys roughly ten repeat-only batches/second per cluster under sustained load, across all signatures, with up to 100 ms intentional repeat latency plus commit time; first/new identities can add writes. Those are design bounds, not measured performance. Exact durable counts and immediate nonblocking returns cannot both be promised. The draft’s return-before-flush scheme loses pending counts on crash, and “next repeat” flushing does not bound their age. Here a crash may lose only unacknowledged operations; never report their counts as committed. Flush/stop failure panics; a write timeout means outcome unknown, no retry or overlapping replacement write.

## Visibility, acknowledgement and database-down path

Reuse `seon.problems/error-signatures` (`src/seon/problems.clj:109-128`) for the shared open-panic projection. Declare the occurrence’s observed panic mode and latest committed occurrence transaction as observations, not another error taxonomy. Compare transaction evidence with settlement evidence on the same branch; never compare a wall-clock `last-at` directly with a transaction id.

Every MCP response includes open panics for the selected world, including normal eval results; the failing tool call sets `isError`. Status, REPL query and every namespace-page banner use the same derivation. Each entry gives signature/occurrence, committed count, operation, root class/message, source location, affected graph, basis and an exact `explain` query for chain, admitted input and reproduction form. Reads/rendering do not transact; cache the projection on its actual read dependencies. Missing database evidence says unavailable, never an empty healthy list.

Acknowledgement links the error to a real issue and accountable agent using existing `:seon.error/issue` and issue facts (`resources/seon/schemas/seon.error.edn:284-286`). It does **not** hide it from another agent’s MCP responses. Collapse acknowledged entries to a short open count plus identifiers. Only settlement’s positive, current regression/detector evidence resolves the issue (`resources/seon/schemas/seon.issue.edn:38`); do not add an independently writable resolved flag. A later committed occurrence reopens and wakes once. Include the reopening transaction in message identity: today `[signature recipient]` (`error.clj:1355`) can upsert an already-handled message and fail to wake again.

The atomic wake fact is durable delivery work; it is not proof that the recipient ran. Install the ordinary listener before deriving unanswered wakes; observe its delivery event in regressions. Datahike settles the transaction promise before listener callbacks and logs callback failures (`reference-code/datahike/src/datahike/writer.cljc:379-412`). Wrap Seon-owned listener callbacks at their boundary so failures reach this route; never await a same-writer transaction from its transaction function. Failed-graph wakes remain visible pending work and escalate to the functioning root route.

If normalization, recording, wake construction or commitment fails, **panic in both modes**, including production. Preserve original plus full recording failure, mark the affected graph failed, fail waiting callers and expose the live Throwable through the reachable REPL/status failure observation. No recursive recording attempt, fallback database, journal or retry loop. A REPL evaluation sets its own `*e`; a background thread cannot set another session’s `*e`, so expose the retained graph/committer failure explicitly. Emit a full emergency diagnostic to stderr as well; print-only is not the outcome. If the store cannot be read, MCP reports that failure directly instead of querying open panics recursively.

Backstops: install/chainsafe-remove the process default uncaught handler once; use explicitly supplied custody where known, process failure otherwise. Wire http-kit and SSE exception callbacks, listener callbacks, Future/task completion consumption and checked subprocess exits. Futures capture exceptions, so the uncaught handler is not universal. The committer’s own terminal failure takes the emergency panic path and completes every pending waiter exceptionally; it never feeds its own inbox. Low-level declared interrupts pass through to the lifecycle owner; unexpected cancellation/storage bounds cannot become silent success.

## Call-site law, conversion and enforcement

A catch handles a **declared case**, propagates the original (or `ex-info` with that cause), or invokes `fault!` at its owning boundary. No log-and-default, message-only map, unchecked fault offer, or local dial read. Flow steps may handle declared domain cases; the draft’s blanket ban on every step catch is too strong. Unhandled exceptions propagate into Flow’s single reporting hook. Handling a case means its actual semantics and declared output, not merely calling something named `diagnostic`.

Implement a clj-kondo `:analyze-call` hook on `clojure.core/try`, returning the original node while registering findings for catch paths. Hook dispatch precedes normal call analysis (`reference-code/clj-kondo/src/clj_kondo/impl/analyzer.clj:3595-3639`); report exact ranges with `hooks-api/reg-finding!` (`reference-code/clj-kondo/src/clj_kondo/hooks_api.clj:96-99`). Validate the special-form hook on the pinned binary before integration. Resolve aliases, inspect every branch’s terminal form and cause argument, and flag local dial reads globally outside the owner. A route call followed by `nil` is still a violation. Check declared handling against the function’s output contract and require otherwise-rethrow for broad catches. Static syntax cannot prove arbitrary helper semantics: unknown helper paths require explicit reviewed declaration/evidence, not an automatic pass. Hook errors fail the syntax check.

Conversion order, extending fix-schedule row 0 and the census rules (`swallowed-errors-census-2026-09-23.md:73-156`):
1. Fix/profile P4 and verify F0 evidence round-trip; prove cache reuse and incremental schema adoption on a live branch. Then land the Flow hook, moved route/committer, policy, delivery, terminal state and public caller/schema retirement as one loadable slice. Remove the old panic printer and dial readers in that slice.
2. Commit ONE rewrite-clj conversion script for R-MSG: preserve the throwable and choose declared handling versus propagation/route from explicit owner inputs; generate qualified operation symbols. Script lists unresolved world bindings for manual decisions. Fix R-HELPER at its approximately 17 producers; R-DIAG needs only proof that F0 retains the evidence.
3. Script R-LOG replacements across hook sites (full Throwable data and nonzero failure); classify R-DISCARD/R-PRED once, then apply the declared-class/deleted-try rules in one scripted sweep. Never replace every Throwable catch with Exception and call that handling. Convert R-OFFER to the route; distinguish legitimately losable wake signals. Hand-fix R-CAUSE, R-EXDATA and timeout sentinels.
4. Delete obsolete B4 machinery with its owner; convert surviving R-UNKNOWN-STR into typed unavailable evidence. Run syntax/hook lint and a load after each scripted set, inspect only residue. Enforce zero unexplained census violations. Keep file ownership disjoint; no source changes are made by this document.

Regressions, one per behavior class: (a) declared mistakes stay local, nested unexpected causes survive recording, and propagated receipts count once; (b) more than 100 distinct concurrent Flow failures preserve every identity, compute/output/control/start failures reach the route, and channel xforms refuse; (c) concurrent repeated occurrences conserve exact acknowledged counts with bounded batch writes, isolated agents/branches stay separate, stop flushes and unknown commits never retry; (d) every dial/recipient case, missing dial, value-shaped faults and missing root; (e) panic stops only its graph with actual-exit evidence, while sibling graph and REPL answer; (f) database/normalizer/committer/listener failure in BOTH modes exposes both causes without recursion; (g) all MCP/status/page surfaces show, acknowledge, resolve and reopen with a fresh wake; (h) relevant schema change invalidates once, unrelated fault writes cause zero reconstruction, record CPU/wall/allocation and retained memory; (i) fingerprint survives line/generated-id changes, distinguishes inner causes, preserves legitimate numeric names, and lint rejects every forbidden branch. Use canonical branch fixtures, real SCI and armed contracts; run focused installed `seon.test/run` requests, never a lane `bin/test` gate.

## Three priced options

1. **Simplest viable constraint:** native Flow hook, no channel xforms, acknowledged batching, existing D13, cache fix and full visibility/panic/enforcement. **Estimate 3–4 engineer-days plus 2–3 days census conversion.** Guarantees durable acknowledged counts, reduced burst writes and one policy; gives up stable grouping across line/generated-name changes and finer discrimination of wrapped causes. Keep full evidence even when grouped together.
2. **Recommended — the design above:** same constrained Flow seam, acknowledged committer batching, improved D13, reused issue/visibility owners, cache prerequisite and census conversion. **Estimate 4–6 engineer-days including focused proof, plus 2–3 days conversion; P4 repair may add 1–2 days if its hypothesis is false.** Meets the stated guarantees without knowingly losable repeat counts; gives up immediate repeat returns and channel transducers. Prices are scope estimates, not measured execution times.
3. **Unrestricted Flow channels:** option 2 plus a maintained dependency change that propagates transducer failures after channel locks release, preserves callback completion and supplies the same acknowledged terminal route. **Estimate option 2 plus 2–4 engineer-days and dependency concurrency regressions.** Retains channel-xform expressiveness; gives up the smaller fork surface and adds lock/lifecycle proof risk. No extra error router or fallback store.

## Platform defects first

These are wrong values, re-run effects and slowness.

1. **Cluster configuration is read unscoped: any cluster's row answers.** This is a wrong value.
   - **Where:** `seon.turn/max-episode-runs` (turn.clj:2887-2890) reads `[?config :seon.config/cluster _]
     [?config :seon.config.run/max-episode-runs ?value]` with `:find ?value .`.
   - **Effect:** on a branch that holds more than one cluster's config row, the answer is an arbitrary one of them. Every
     fixture branch holds at least two: the probe on default found `#{["default" 100]}`, and each fixture adds its own. So
     does any cluster branch forked from a cluster that already has a config row.
   - **Observed twice:**
     - agent-test `episode-cap-refusal-test` caps at 3, but the derivation used default's 100. Work derived, no deferred
       trigger was recorded, and problems were empty (:1595-:1614).
     - turn-test `generated-opening-preserves-one-provider-turn-budget` got `turns-left` 100 where 1 was seeded (:3298).
   - **Same class, 12 more sites:** bootstrap.clj:132, issue.clj:1491, render/transcript.clj:1169, repl.clj:72,
     render/web.clj:2032, blob.clj:72, problems.clj:367, test/runner.clj:1253, turn.clj:72 and turn.clj:4421
     (blob-threshold), and cluster/message.clj:681-685.
   - **The message.clj case refuses:** `send-call` counts distinct `max-chain` values across all clusters and refuses
     "Messaging requires one configured chain bound" when two clusters' values differ.
   - **Owner fix:** read each dial through `seon.config/effective` of the agent's own cluster. The agent row's cluster
     reaches its `:seon.cluster/config`. Do not query the attribute store-wide.
   - **Needs an owner design before any edit,** because it touches turn.clj and eight other owners.
2. **A source submission always starts in the agent's assigned namespace, so `in-ns` never carries over between runs.**
   This is a wrong value.
   - **Cause:** `seon.cluster.agent/submit-source-in-projection` (agent.clj:688-750) resolves `namespace-name` to the
     agent's namespace when the caller names none. It then always passes
     `:seon.turn/starting-ns [:seon.ns/name namespace-name]` in the run request. `seon.turn/system-run-plan`
     (turn.clj:778-780) prefers a requested namespace over `previous-ending-namespace`, which 85b459845 (09-26 10:06, "a run
     starts where the agent's previous run ended") added. So that rule never applies to submissions: MCP SCI runs, host
     runs and evaluate-source.
   - **Observed:** agent-test `a-run-defining-with-an-alias…` :481 got `"my.agents.alias-batch"`, where `"alias.batch"`
     was expected.
   - The unconditional starting-ns in the submission predates 85b459845 (ae0e54841, 09-09). The new rule was never wired
     to this entrance.
   - **Fix:** pass `:seon.turn/starting-ns` only when the caller supplied one. Segment the sources in the namespace the
     writer will choose: the previous ending namespace, else the assigned one. An omitted optional input stays absent.
   - **Doc conflict:** the MCP `eval_clj` tool text says "The run starts in root's own namespace (the run writer refuses
     another)". Root should rule which one is wanted and correct the other in the same slice.

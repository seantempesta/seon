# Mutable-holder audit

Seon currently carries derived program/schema/render answers, live resources, and observations in separate mutable holders. The principal Clojure cut is to derive answers from captured immutable inputs, keep execution state in its existing owner, and retain mutation only at an actual callback, concurrency, or foreign API boundary.

**The live system was faulted before this audit.** `bin/seon status` and MCP `runtime_status` reported one open `seon.db/loaded-builder` fault, 59 failed tests, and no unanswered Flow procs. Its program was the archive `data/source/2c9d6aa3b4af79a579a2fe748a90596d163663ab`, with working-tree hook publication off. The fault says a boot reservation `java.lang.Object` reached a map-only input at `db.clj:1542`. These are observations of that installed archive, not proof about the newer checkout. A later read-only MCP probe returned its value but reported the selected cluster degraded and its error window unknown (“No live connection holds this branch”). No restart, adoption, test gate, provider call, or foreign-lane intervention was attempted.

The highest-value removals are the SCI program/private-binding mirrors, the mutable cache inside another cache in test reach, supplied-default snapshot/plan state, and render cache bookkeeping. They are not equally safe. Local folds and dead collectors can go first. Context identity, actual exit, failed installation, callback observation, and browser drain must survive the larger cuts.

## Scope and accounting

Read `AGENTS.md` end to end, including the 2026-09-26 law: “Atoms are a smell … state lives in its owner's value … an atom needs a stated reason no owner holds it.” Read the data-oriented Clojure, REPL, Datahike and Flow skills; inspected the architecture and B2 context/execution specification and the turn PRD's §§13–15. Existing B2 proposals are targets, not installed APIs. Several skill line anchors are historical: for example `base-ctx` is at `sci/eval.clj:3153` here, not `:2475`; `fork-for-turn` is at `:2960`, not `:2287`. Add **one higher-order atom constructor** (`call_preparation.clj:64`) and **12 `core.cache.wrapped` factories**. There are **zero Clojure agent allocations**: `test.clj:193` calls a locally bound transaction constructor named `agent`, while `turn.clj:5519,5542` are strings. These three false-positive lines explain the 132-line broad search result. Host collections, primitive cells, mutable fields and output accumulators are inventoried separately below. `test/` is outside this assignment, but the test code living under `src/` and `script/` is included.

Each numbered constructor has its own verdict. In the tables, **R/W** means the readers and writers named in that row; **D** answers whether immutable inputs determine the state. A `KEEP` always names why the usual database, proc, context or local-loop owner cannot replace that holder at this seam. `DELETE` removes a derived/dead holder, not the behavior it supports; a library cache may still internally use an atom. `MOVE` names the destination value. `COLOCATE` joins a concern with named siblings. No recommendation means “replace atom with volatile” by itself.

**Line estimates are prospective net first-party source/script deletions**, including removal of holder plumbing and replacement code, not counts of `atom` tokens. `0` is intentional when a move improves ownership without an established shrink. A range printed once for a group is charged once; `in A…` refers to that same budget. Tests, schema declarations and large B2 retirements not directly supported by this inventory are excluded. No runtime speedup or memory reduction is inferred from an atom count.

## Why several tempting moves are wrong

1. **Facts versus runtime truth.** A function row, agent row, branch pointer or open-turn row does not prove a Var was installed, a graph is live, an interpreter is usable or a thread exited. Delete mirrors of declarations; keep installation/execution outcomes at their runtime owner. This is why A053 and actual-exit observations cannot become simple database reads.
2. **A read trace versus a query result.** One immutable DB can support many programs that perform different reads. D can return native evidence, but the arbitrary execution boundary still needs to collect it. A035–A037 are a normal fold; A030/A034/A040–A044/A109 are callback sinks until the common evaluation return includes their observation.
3. **Connection-adjacent derivation.** A009, A050, A095/A096 and C09 should not be mutable “latest” answers beside Datahike. A prior held database must keep its own answer even after another transaction. Use immutable input identity/content/revisions, D notification, and actual parent history. C03–C06 demonstrate the acceptable bounded dependency-cache form.
4. **Thread handoff.** Putting a watchdog subject in `::flow/state` does not make a blocked proc answer. Keep one execution observation accessible outside it. A090/H05 must retain the monitor that prevents late interrupt hitting the now-idle/reused thread. H12–H17 are already colocated in one arm value, with different synchronization needs; merging all primitive counters into a map atom would add per-entry allocation without an ownership gain.
5. **Pure memoization versus effects.** C12 stores the result of fault recording in a cache. That is a second idempotence authority. The writer must decide whether a named occurrence was already recorded; eviction and process restart cannot be part of that decision. Likewise never put filesystem deletion, provider reads or blob staging inside a cache miss function.
6. **Local accumulation is not automatically a defect.** Volatiles in an explicit traversal often disappear in a fold. A foreign Writer/InputStream/reader API can require mutable callback state, and a transient/StringBuilder as the single fold accumulator already has the local owner the law asks for.

### Cost and proof obligations

- Folds visit the same finite nodes in **O(n)** time and output/traversal space. Never materialize a whole directory tree or history to remove a volatile; fold each DirectoryStream inside its resource scope.
- Cache first computation costs its reached input size; a content-valid hit should cost a library lookup, not another whole-program traversal. Count misses. Commit IDs identify DB values; content/revision keys permit reuse across irrelevant transactions. Do not recreate a mutable last-seen basis.
- One lifecycle value makes one decision atomic; it does not turn cancellation into exit, remove external watchdog access or justify per-call database transactions. Keep online telemetry at its wrapper/arm owner.
- Each source cut needs its focused installed request through the agent entrance on its assigned branch, then publication/adoption/arming proof. Root owns affected/platform/bulk completion. Record parent/change timing, memory observations and cache misses; address the repository's 20%/50 ms regression threshold. This document claims no runtime improvement.

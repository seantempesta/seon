# Design review — trial-astra-specs

Reviewed 2026-10-07, checkout HEAD `33fb994f24c91d846e873edc6a547ed5e7d22b3d`. Read-only review; no MCP, JVM operations, tests, lint, contract compilation, commits, or tracked-file edits. This report is the only file written. Citations are checkout-relative `file:line`; ranges describe inspected code, not live installation. All runtime behavior, bootability, adoption, costs, and proposed test outcomes remain **UNVERIFIED in this review**. The lane notes' measurements are reported evidence, not measurements repeated here.

**Verdict:** both directions are sound, but neither spec is ready to implement as written. Errors S1 is a sound completed step. The errors constructor/recorder transition and the loop's settlement/lifecycle interfaces need design corrections before further slices. A small turn-free loop is feasible; the successful fold probe does not prove its writer, replies, cancellation, or prompt construction.

Owner decisions in errors §9 and loop §7 take precedence over older conventions: retain the type key and two carriers; remove fault folding/copy/escalation; do not restore turns, system-turn execution, prompt capture, raw replies, or backfill. The corrections below preserve those decisions.

## Errors

### What is right

The explicit type key, local `:multi` alternatives for functions returning errors, base contract at generic boundaries, one constructor, and ordinary `ex-info` transport are appropriate (`docs/seon/specs/errors.md:16-18,51-71,294-304`). Malli already supplies dispatch validation and explain data (`reference-code/malli/src/malli/core.cljc:1896-1905,2688-2703`). Its instrumentation report hook and `malli.error` replace the bespoke violation sentences, arity reconstruction, and spelling algorithm; keep Seon's world supply, private-function arming, attribution, and fault custody. `malli.instrument` alone does not implement those: its collector uses public Vars (`reference-code/malli/src/malli/instrument.clj:47-57`).

The lane's 52 throwable sites and 120 literal maps do **not** invalidate the one-map design. They invalidate the proposed mechanical sweep and show that construction, boundary conversion, schema tightening, and recording cannot be ordered as specified (`tmp/errors/s1-s2-notes.md:33-65`).

### Findings, ranked

**E1 — HIGH: S2 removes the representation before its consumers and storage can accept the replacement.**

S2 makes type/message required and stops supplying `:at`/`:layer`; S3 changes structural recognition; S6 changes persistence (`docs/seon/specs/errors.md:259-267`). These are dependent changes. Today recognition uses all three old members (`src/seon/error/refusal.clj:717-722,818-827`), the signature incorporates layer (`src/seon/error.clj:153-180`), and fault facts require time, layer, and declared-schema (`resources/seon/schemas/seon.error.edn:114-133,300-324`). Throwable-consuming `diagnostic` also supplies chain, frame, class, and message (`src/seon/error/refusal.clj:692-711`). Deleting it first loses evidence or refuses calls. The lane is correct.

Correct design: complete producer typing first, retaining the current representation during that preparatory migration; then cut the base, predicates, record shape, signature, and their readers together. Classify each ambiguous producer by its actual failure branch, not by guessing a type from a broad output union. Q3 permits a base boundary; it does not authorize stamping every unclassified domain error as base. Include raw literals and stored/pulled values, not just `diagnostic` calls. Errors has **no reset ruling** analogous to loop Q2: specify adoption/migration of existing fault identities, references, occurrence components, and stored evidence before removing old required fields. Do not infer permission to discard faults from the loop's disposable-evaluation decision.

**E2 — HIGH: the claimed validation of thrown variants does not exist.**

The constructor returns only base, `fail!` throws without returning, and Q3 explicitly allows boundaries to accept base (`docs/seon/specs/errors.md:93-108,298`). Therefore neither producer output instrumentation nor the boundary base contract checks a thrown variant's required members or even whether its type names a registered variant. Malli validates the output only after `(apply f args)` returns (`reference-code/malli/src/malli/core.cljc:2236-2240`). A malformed `(fail! :my.fs/not-found-error ... {})` can cross with no path; T7 tests only the returning carrier (`docs/seon/specs/errors.md:284-285`).

Correct design: state the validation authority for **both** carriers. The smallest common authority is one compiled named-variant check in the one constructor, using Malli's cached explainer, before either returning or throwing; returning functions still restrict their permitted alternatives through their output `:multi`. Keep the generic boundary contract broad. This need not retain today's construction-refusal framework: a small, explicitly declared malformed-error diagnostic can carry the attempted data. The error-reporting primitive must remain buildable when the registry itself fails; do not recursively explain a broken refusal while reporting it. Also verify that a permissive success alternative cannot swallow an error before the `:multi` is checked.

**E3 — HIGH: §5's report adapter loses failures and attribution.**

`contract-error` chooses output/value only for invalid-output and input/args for everything else (`docs/seon/specs/errors.md:174-182`). A guard report contains `:guard`, `:args`, and `:value`; its checked value is `[args value]`. An invalid-schema-at-call report contains the failing `:arm` and original `:exception`; explaining that schema again can throw the same failure (`reference-code/malli/src/malli/core.cljc:2219-2225,2232-2240`). The proposal drops that exception and can replace a deadline with a reporter failure. The current wrapper deliberately handles this case and propagates an evaluation interrupt (`src/seon/instrument.clj:858-915`).

It also deletes the attribution producer while claiming `producer` stays unchanged. That reader recognizes `:seon.instrument/fn` and `:seon.instrument/arm`, not the new Malli type key (`src/seon/error/refusal.clj:562-570,618-636`); the current report captures the actual armed producer/caller digests (`src/seon/instrument.clj:733-754`). Merely keeping `caller-frame` loses “input blames caller; output/guard blame callee” and the version that ran.

Correct design: a small `case` over native report kinds: input→args, output→value, guard→[args value], arity→reported arity/arities, schema-at-call→arm/schema/exception without re-explanation. Preserve interruption as the bound. Adapt attribution to the new fields in the same slice; capture execution digests at the report, not after a reload. Keep explanation data and short messages separate; `pr-str (humanize ...)` at construction (`errors.md:178`) bypasses the value printer and duplicates potentially large evidence. Use Malli's enrichment functions on the refusal path and print only at the edge.

**E4 — HIGH: `Throwable->map` is not the total, whole-chain replacement promised.**

The spec deletes the traversal and optionally appends only the root's suppressed failures (`docs/seon/specs/errors.md:73-78,130-158,261-262`). Clojure's implementation follows `.getCause` without a seen set and ignores suppressed exceptions (`reference-code/clojure/src/clj/clojure/core_print.clj:484-501`). The existing code terminates cycles (`src/seon/error/refusal.clj:181-190`), and a current regression explicitly exercises both a cycle and suppression on the **outer** exception, whose suppressed exception has its own cause (`test/seon/error/refusal_test.clj:218-245`). `fault!` also attaches stop/recording failures as suppressed (`src/seon/fault.clj:443-453`). Those are real duties, not hypothetical restrictions.

Correct design: retain a small identity-aware traversal of cause and suppressed edges and project native class/message/ex-data/frame values once per throwable. Use Clojure's frame conversion and native accessors; do not rebuild a stack classifier twice. If native `Throwable->map` is retained for ordinary cases, it must never be called on a cyclic cause chain. Move the chain schema and every consumer together: current links require `:seon.error/throwable-class`, while the proposal emits `:type` (`resources/seon/schemas/seon.error.edn:271-283`). Preserve receipt detection across the new shape. The proposed deletion also removes helpers still called by `first-party-frame?`/`frame-function` (`src/seon/error/refusal.clj:143-179`); keeping their names does not make that cut loadable.

**E5 — HIGH: the minimal fault row does not yet implement Q5's opening and resolution semantics.**

Q5 requires one message per opening and resolution by digest **plus a green run** (`docs/seon/specs/errors.md:301-302`). Yet §6 says keep `resolution` conditionally, while deleting its occurrence store and task creation path (`errors.md:228-237`). Current `resolution` reads occurrence components and their latest producer digest, follows task proof, and also resolves on digest change alone when no task exists (`src/seon/error.clj:1162-1219`). The deleted `producer-task` supplies the fault→task relation (`src/seon/error.clj:1270-1289`). Neither that query nor its weaker no-task rule can remain unchanged.

Correct design: in one writer transaction, inspect the previous row's latest observed digest and proof, decide whether this occurrence opens a new notification, increment count, update latest occurrence/digest, and retain the first evidence blob. Name the proof query against the relevant current program and completed green run; absence of proof stays unresolved. Keep/create the task relation through its canonical owner if task proof is the chosen mechanism, without rebuilding steward/escalation. Decide destination and validate it in the same world at the writer; root must be reachable there when the causing agent is absent. Do not restore the branch copy forbidden by Q5. Define the record receipt separately from the error map and return it on repeats too, so every caller sees its own fault even though only an opening sends a message.

One concrete trap: the sketch calls one-argument `id/id`, which produces 12 characters, while `:seon.error/signature` requires 64 (`errors.md:220`; `src/seon/id.clj:108-119`; `resources/seon/schemas/seon.error.edn:268`). Use the existing explicit 64-character signature derivation. Datahike's writer seam is verified in source: `:db.fn/call` receives the in-transaction database (`reference-code/datahike/src/datahike/db/transaction.cljc:1172-1173`). No separate counter, lock, or occurrence queue is needed.

**E6 — MEDIUM: reference conversion and evidence retention are underspecified and partly falsely attributed to the existing helper.**

§1 says `references` turns large values into class/size and that only variant fields can hold a world (`docs/seon/specs/errors.md:80-84`). The actual helper performs identity projection, traverses map values/vectors/sets, skips sequences/records, and does **not** do the size reduction; `bounded-cost` is separate (`src/seon/error/refusal.clj:300-334,336-405`). Base `:problems` can plainly contain a connection or lazy offending value, and an existing typed map recovered from `ex-data` bypasses the new constructor. Converting only selected fields is not a complete evidence boundary. Class/size alone also cannot retrieve a large value; a blob of that label does not recover the original.

Correct design: explicitly separate the live error value, identity-only world references, durable evidence/blob references, and the printer budget. Declare variant fields in the representation the constructor actually returns. Cover arbitrary exception data and all evidence-bearing members, without dereferencing places or eagerly realizing unbounded sequences. Reuse the existing blob and value-printer owners; do not add a second clipping walker or claim `references` supplies bounds it does not. Bound safety and large/lazy evidence behavior are **UNVERIFIED** for the proposed constructor.

**E7 — MEDIUM: the filesystem example reintroduces value-propagation ladders inside the producer.**

§2 correctly says deep detection can throw and the answering tool catches once, but table row 3 instead changes deep path checks to return maps and removes their catch (`docs/seon/specs/errors.md:110-119`). The existing code consumes `parent-access` as a directory/name/streams map and then performs IO (`src/seon/fs/jvm.clj:488-503`). A returned refusal there is not a terminal tool answer; it is destructured as success. This is a design contradiction, not a request to preserve `flat-error`.

Correct design: deep filesystem checks call the shared `fail!`; the tool's single boundary returns only its declared domain variants and converts declared host IO failures. Unexpected core failures propagate to the entrant. Do not use a catch that returns *any* typed exception at every tool: a Malli output violation is a core defect, not automatically a member of that tool's error union.

### Corrected errors slices and concrete edits

The current S2/S3/S6 order cannot be asserted to boot; no boot proof was performed here. A dependency-respecting order is:

1. Keep landed S1 (`33fb994f2`). It moved readers and stamps together; no reason to redo it.
2. Inventory and type all remaining producers in small owner-complete groups. Preserve the old constructor signature/base/storage until callers have a declared target type; add named variants where needed. Do not introduce a second public constructor just to split commits.
3. Change chain extraction, its schemas, every chain/receipt reader, and throwable-consuming call sites together. Preserve the outer domain type when the producer deliberately translates an exception.
4. Prepare the simplified recorder/proof/delivery implementation and required schema additions; keep it out of the active path until the representation cut. Tighten no old row prematurely. Prove the chosen fault-data migration on existing data.
5. Cut constructor signature, all callers, required base keys, structural predicates, recorder, signature/fact schema and readers as **one dependency-complete cut**. This is not credibly “225 sites by script”; enumerate the literal and ambiguous cases first. If too large, split earlier preparatory slices, not this compatibility boundary. Native chain/report changes must be available before this cut.
6. Change instrumentation and attribution together using E3's report matrix; then convert throwing read APIs with all their callers/contracts in each slice. Keep deliberate verdict-returning validators as values. Move the constructor into `seon.error` only after its load-cycle consumers have an explicit dependency-safe path (Q7).
7. Delete obsolete rendering and occurrence machinery; retain behavior regressions, replacing assertions about removed representations.

## Agent loop

### What is right

One synchronous Flow transform, no open run entity, evaluations as independent agent refs, writer-assigned ordering, failed-call accounting, and live task/inbox reads fit the owner decisions (`docs/seon/specs/agent-loop.md:9-20,24-46,277-287`). A provider call is useful durable data; it need not be the identity of an execution state machine. The lane's turn-free fold result supports this (`tmp/agent-loop/s1-notes.md:16-25`). Keep the shared reader/evaluator and SCI context owner; do not implement another evaluator in `seon.agent.loop`. SCI already supplies `fork`, `intern`, and evaluation (`reference-code/sci/src/sci/core.cljc:260-271,320-361`).

The lane's ordinal/handle finding is a missing identity distinction, not a reason to allocate ordinals early. Its receipt-writer finding disproves “reuse unchanged.” Its fault-window finding identifies a missing delivery duty, not a reason to retain fault folding after errors Q5.

### Findings, ranked

**L1 — HIGH: the proposed pass has no complete input/output seam to the evaluator and writer.**

§2 claims reuse of `evaluate-sources`, `evaluation-facts`, and `turn.batch/settle` (`docs/seon/specs/agent-loop.md:88-109,113-125`). The pass omits acquired SCI context and local first ordinal; the evaluator consumes both and mints handles before settlement (`src/seon/turn.clj:4883-4936`). The old caller acquires/preserves the context and reports unbound handles (`src/seon/turn.clj:5084-5106`; `src/seon/sci/eval.clj:2842-2893`). `evaluation-facts` still produces a run/ordinal-shaped settle request (`src/seon/turn.clj:97-117`); `receipt-settle-call` requires a run and a started receipt (`:1437-1489`). `turn.batch/settle` constructs its own old recording tx and does not publish staged blobs (`src/seon/turn/batch.clj:632-648,683-725`). Finally, `turn.batch/reply` takes a **batch**, not the `commit` passed in the sketch (`:770-794`). Calling it with a commit loses evaluations.

Correct design: before evaluation mint a pass identity through `seon.id`, with local indices for `id/evaluation(pass-id,index)` and handles. At the writer assign the separate per-agent ordinal; never recompute evaluation IDs from it. Acquire the retained branch execution/context and pass world, namespace, limits, profile and local index explicitly. Adapt the existing settlement owner to accept complete new receipt rows plus entrant transaction data and staged blobs; it must return the settled batch and committed evaluation identities/report. The caller answers from that batch, even on refusal. Generalize/extract the existing projection in place; do not copy private receipt helpers into loop.clj. Preserve test-world settlement custody (`src/seon/turn/world.clj:70-75,129-134`) and accepted-row installation (`src/seon/turn.clj:5215-5244`).

**L2 — HIGH: deleting the backstop does not make reply delivery or host execution total.**

The unbounded MCP await is justified by three limits (`docs/seon/specs/agent-loop.md:132-142`), but the new pass has no catch/finally to answer/close a submitted reply. Current `step` explicitly supplies both (`src/seon/turn.clj:6013-6036`). Flow catches transform exceptions and sends them to its error channel; it neither answers this private reply port nor guarantees another wake (`reference-code/core.async/src/main/clojure/clojure/core/async/flow/impl.clj:301-320`). Removing the catch can hang MCP on an ordinary context or writer error.

Provider timeout, per-form SCI limit, and call count also do not bound queue admission, context derivation, host JVM evaluation, or a host call ignoring interruption. The SCI owner names that limitation (`src/seon/sci/kernel.clj:353-357`). `disarm!` currently joins under the very dial being deleted and retains ownership on non-exit (`src/seon/cluster/agent.clj:1492-1506,1535-1578`). Flow `stop` is only a command/channel close (`reference-code/core.async/src/main/clojure/clojure/core/async/flow/impl.clj:174-182`).

Correct design: keep exactly the three **loop policy** bounds, remove the loop permit/watchdog, but specify terminal delivery on success/refusal/throw/cancel, queued-request closure, thread interruption, and actual executor exit before release. Carry the caller's existing lifecycle deadline into shutdown and retain the execution while exit is unknown; do not add a fourth loop dial. Name dependency bounds separately. No finite whole-pass bound may be claimed for arbitrary host code. Uninterruptible work cannot free custody merely because a caller stopped waiting. Preserve the small `turn-step` interrupt/clear protocol (`src/seon/cluster/agent.clj:511-557`) until its replacement proves the same behavior.

**L3 — HIGH: “nothing written before settlement” and T8's unchanged database are false for the retained evaluation path.**

The spec states those guarantees at `docs/seon/specs/agent-loop.md:92,127-130,267`. A form can perform a durable database write immediately; the next call must see it. An existing regression deliberately runs `my.agent/settings!` with the settle stage removed and observes that write (`test/seon/turn_test.clj:2434-2449`). `db/transact!` is a real commit (`src/seon/db.clj:5893-5922`), and the fold records faults as well (`src/seon/batch.clj:614-624`). “In-memory fold” describes accumulated declarations, not arbitrary effects. Owner-authorized loss of a reply cannot roll back a message, task, filesystem operation, or remote request already performed.

There is a second unsafe gap: treating every unsuccessful settlement as a definite refusal and writing the call alone can duplicate accounting. `db/transact!` can return outcome-unknown while its queued transaction may still commit (`src/seon/db.clj:5917-5922`). Revalidation and retry are safe only for a known rejected transaction, not unknown acknowledgement.

Correct design: promise one transaction for **loop-owned settlement facts**, with no prewritten loop intent. Effects retain their own existing durability. Crash loses unacknowledged evaluation/reply bookkeeping, not completed effects; a repeat may repeat an effect unless that effect's owner supplies idempotence. Limit unchanged-database T8 to a pure fixture and add an effect-before-interruption case. Distinguish committed / definitely refused / outcome unknown; never re-evaluate on settlement retry, and retain ownership/reconcile the original writer attempt on unknown outcome before another settlement or call-only write.

**L4 — HIGH: dropping fault windows without replacing their consumers loses the MCP fault observation.**

The deletion list removes fault windows, and §2.1 names no equivalent (`docs/seon/specs/agent-loop.md:111-130,192`). Errors §6 promises messages plus receipts, but only openings send a message. Current settlement saves faults on the last evaluation (`src/seon/turn.clj:3443-3475`); transcript consumes those refs (`src/seon/render/transcript.clj:336-371`); MCP explicitly reads that same observation (`src/seon/cluster/agent.clj:852-870`; `src/seon/mcp.clj:215-225`). A repeated fault has a new receipt even when it sends no new message. “Faults arrive as messages” alone does not preserve it. `turn.batch/reply` also currently converts diagnostics to message strings (`src/seon/turn/batch.clj:787-794`), so using it unchanged does not deliver errors §6's full map/receipt.

Correct design: explicitly carry the fold's diagnostic/fault receipts and post-evaluation installation/settlement faults into the terminal reply. Store direct evaluation/call associations where historical observation needs them; the IDs exist before evaluation under L1. Render those refs for both MCP and history. Faults without evaluations still arrive via call/reply and opening message. This can **delete** the temporal fault-window query instead of rebuilding it. Errors Q5 deletes repeat folding and branch copy; do not carry `folded-tx` into the final design. During migration, do not drop already-owned repeat state before the old recorder retires. Blob publication, measurements, and installation are separate duties, not substitutes for fault delivery.

**L5 — HIGH: the work/provider sketch drops existing admission policy and contradicts its own cap test.**

The new pass unconditionally invokes `ai/complete` when `work` exists (`docs/seon/specs/agent-loop.md:81-84`). The old loop enforces `no-provider` before that call (`src/seon/turn.clj:4547,4567-4569`); `ai/complete` checks credentials/request data but does not enforce no-provider (`src/seon/ai.clj:1289-1329`). The S1 brief itself relies on overriding default's no-provider (`agent-loop.md:232-239`). Without preserving the guard, switching the graph can send requests from a deliberately disabled cluster.

Also `wake-ts` uses newest **listened** wake as answer work (`agent-loop.md:53-61`). Existing declarations distinguish a wake that refills the cap from one that opens a model call: schedule fires explicitly do not open one (`resources/seon/schemas/seon.schedule.fire.edn:7-13`; `src/seon/cluster/wake.clj:156-174`; `src/seon/turn.clj:2645-2660`). Keep that distinction in the single wake scan. Finally T1 says “at the cap a fresh wake is nil” (`agent-loop.md:254-255`); a fresh **outside** wake is precisely what resets the cap. Specify inside vs outside there and default the no-outside-wake anchor to zero, as `outside-wake-t` already does.

Correct design: work derives newest eligible unanswered wake, newest outside listened anchor, disposition and call count; provider admission separately respects effective no-provider and request-supplied fixture transport. Disabled provider must neither spend calls nor self-spin. This does not add a bound or restore episode entities.

**L6 — HIGH: the activation order creates mixed writers/readers and is not a bootable behavioral migration.**

S2 replaces the proc before S3 converts submissions and S4 converts readers (`docs/seon/specs/agent-loop.md:240-246`). Existing submissions carry staged reply/source/run data and namespace overrides (`src/seon/cluster/agent.clj:745-771`; `src/seon/mcp.clj:231-239`); JVM mode has a distinct recording request (`src/seon/mcp.clj:255-287`). Existing MCP/transcript reads still require run refs (`src/seon/cluster/agent.clj:859-870`). Thus new writes can become invisible before S4; old test/JVM writes lack the new agent refs and ordinal bookkeeping. Keeping system-turn functions loadable does not make their call dependencies optional when S5 deletes named helpers.

S1's claimed ownership is also impossible as scoped: it must adapt the shared writer/evaluator, move a wake helper, and change calibration, beyond new namespace/test/schema files allowed by Q8 (`agent-loop.md:230-239,286-287`; `tmp/agent-loop/s1-notes.md:42-58`). Do not silently widen that lane's ownership or copy functions to avoid it.

Correct design: owner-complete preparatory slices supply the common writer/projection/entrant seams while the old graph remains active. The new S1 can develop its isolated pure work/context/pass functions in its authorized files against those seams. Activate proc, submissions, JVM/test recording, minimal observation readers, bootstrap wake and agent render attachment together at the final cut. Complete new readers before the Q2 reset; root then resets default once after S4, with no backfill or second historical reader. Do not run the old loop against freshly reset/new-only evaluations. Migrate the cap dial and stored config values with consumers/defaults; deleting its declaration alone does not rename database facts. Boot/adoption of this cut remains **UNVERIFIED**.

**L7 — MEDIUM: the context cache omits inputs, and basis alone does not prove the advertised reconstruction.**

The inbox cache key is `[::inbox agent-id]`, but its closure captures `answered-t` pulled outside the derivation (`docs/seon/specs/agent-loop.md:150-152`). `health/derived` keys only the reads it captures plus the supplied derivation name (`src/seon/health.clj:73-87,113-134`). If the inbox function does not itself read answered-t, its change is invisible to that cache; answered messages may remain. Include the cursor in the key or read it inside the derivation.

Evaluation caching by `[id loaded-identity profile-id]` assumes no other reads (`agent-loop.md:155-167`). `repl/entity-emission` resolves namespace and renderer refs against its database (`src/seon/repl.clj:496-515`); such refs may be swept/changed without a JVM reload. Either pull immutable observed names into the unit's content key or capture those dependencies. Pass the viewing world explicitly, not through global loaded identity alone. The sketch also passes rendered strings where `prompt/select` requires history-unit maps (`src/seon/repl.clj:576-582`; `src/seon/cluster/prompt.clj:321-327`).

Q2 appropriately avoids old-row backfill. For new calls, reconstruction from basis must additionally hold rendering code, effective profile/settings, calibration, and selection policy constant; a character count is only a measurement and equal length is not equality (T5, `agent-loop.md:262`). Keep no prompt capture, per the ruling, but document the precise reconstruction limit and compare exact sent/rebuilt text in the fixture. Historical database retention sufficient for every referenced basis is **UNVERIFIED**. The warm cost claim also omits `sort-by` O(N log N), repricing all text and composition; reuse of N cache entries does not make that work constant.

**L8 — MEDIUM: the prompt budget applies to history but not the prompt.**

`context` selects history with the full budget and then prepends live task/inbox text and appends a frame (`docs/seon/specs/agent-loop.md:158-160,180-181`). `prompt/select` budgets only its own composed history/elision (`src/seon/cluster/prompt.clj:302-334`). A large live task/message set can exceed the provider window even when history fits; the current selector may also retain one newest oversized unit (`:331`). This is not solved by checking the configured budget against a model descriptor.

Correct design: put identity, task, inbox, history and frame under one composition budget, reserve mandatory units explicitly, and report omissions/requery or an unsendable prompt when even required units do not fit. Do not silently clip stored evaluations. Use the existing pricing/selection owner and explicit effective model/profile/calibration. This is a selection correction, not a new tokenizer or prompt cache.

**L9 — MEDIUM: “reply to the newest wake message” confuses notification with the request being completed.**

§2.1 chooses the sender of the newest wake (`docs/seon/specs/agent-loop.md:122-124`). Under errors Q5, faults are messages from an internal sender; a fault arriving while an agent works can become that newest message. Completion can then reply to root/the fault sender rather than the delegator. Multiple requests and continuation passes also need a stable, explicit selection rule. Current `message/reply` takes a selected trigger and suppresses reply-to-a-reply loops by following `caused-by` (`src/seon/cluster/message.clj:86-117,125-134`); it cannot infer which request the pass meant to complete.

More seriously, the errors cut removes temporal associations and starts writing `fault-signatures`, but the loop spec converts transcript/MCP readers only at its later cut (`agent-loop.md:274-281,316-323`). Current transcript queries `:seon.cluster.eval/faults` and occurrence-shaped facts (`src/seon/render/transcript.clj:348-371`); MCP reads that transcript through `run-observation` (`src/seon/cluster/agent.clj:852-870`). ### E2 — HIGH — The task-home row does not yet supply its message or proof world

This is a new design gap introduced by choosing task-home storage, correctly left open as Q-E1 (`errors.md:380`; revision notes Q-E1).

At `errors.md:257-273`, one transaction at root's task home creates the fault, task and a message to the failing agent. But messages are written on the **recipient's branch**, where it reads and is woken (`src/seon/cluster/message.clj:835-875`). Wake listeners are connection-local (`reference-code/datahike/src/datahike/core.cljc:200-210`), and `wake/route!` routes datoms from that connection (`src/seon/cluster/wake.clj:528-560`). A message at root's home is not automatically in a branch agent's inbox or the branch database used by `loop/work`. A channel wake alone cannot make that missing fact readable.

The proposed message content is the error **map**, while `:seon.message/content` is a nonempty **string** (`resources/seon/schemas/seon.message.edn:137`). P2 does not declare a new message payload or change that schema. Datahike's transaction function supplies one in-transaction database, not a distributed transaction (`reference-code/datahike/src/datahike/db/transaction.cljc:1172-1173`).

Resolution also needs an explicit program/evidence world. `seon.test/verified?` checks evidence in its supplied database and does not itself enforce “after latest-at” (`src/seon/test.clj:1547-1577`). Branch proof is currently collected on the branch, then copied as proposal references including branch/commit/run/program to the home (`src/my/program.clj:437-458`). The new row omits branch/proof basis while comparing a branch failure's digest against “current” at the home. That can compare different programs or find no branch test run.

**Edit — errors §6 Opening/Resolution → replace** the assumed home transaction/destination with an explicit custody contract after Q-E1 is ruled: “the row/task/message are committed at X; the recipient's work/inbox reads X using Y; proof names the tested branch/commit, current producer and completed run, with nonempty proofs and time checked explicitly.” Add the data-message schema and its render/reader conversion to the cut. If the owner retains one home transaction, reuse task-home reads and the existing routing owner; do not silently add branch copies, a delivery queue or a second commit. Until this is settled, P3's writer and the cut are blocked **by missing design**, not by other lanes.

### L1 — HIGH — The pass sketch does not deliver its declared result or failure accounting

`agent-loop.md:83-111` has four concrete contradictions:

- Line 105 threads the entire `{:outcome … :batch …}` result into `turn.batch/reply`, despite line 148 declaring that envelope. The function requires `:seon.batch/batch` and reads its entries (`src/seon/turn/batch.clj:770-788`). It must receive the settled batch.
- `some->>` guards `settled`, not `reply`. A normal model pass has no submission reply port, so it calls `async/put!` on nil after committing, before rewaking. `put!` delegates to the supplied port (`reference-code/core.async/src/main/clojure/clojure/core/async.clj:234-237`).
- Database acquisition/admission are outside `try/finally`; a failure there can leave a submission unanswered. A context throw jumps past call construction/settlement, contrary to the counted-error promise and T15 (`agent-loop.md:118-120,353`). No code in the catch records a call or a receipt; `caught` only builds an error (`errors.md:149-160`).
- The catch cannot see the already evaluated batch. An installation, recording or settlement throw replaces held values with one error map. Current `settle-evaluated!` expressly preserves values beside a later failure (`src/seon/turn.clj:3614-3640`); `seon.batch/settled-into` likewise keeps entries (`src/seon/batch.clj:627-632`). Faults detected after the main commit also cannot retroactively appear in its receipt list without an explicit attachment write.

Flow sends escaped exceptions to its error channel and resumes its loop; it does not fulfill those application duties (`reference-code/core.async/src/main/clojure/clojure/core/async/flow/impl.clj:301-322`).

**Edit — loop §2 pass → replace** the sketch with a small composition whose request/reply is bound before the outer `try`, whose admitted model pass has a call identity before context acquisition, whose context/provider failures become call data before settlement, and whose post-evaluation stages return the held batch plus diagnostics. Deliver `(turn.batch/reply (:batch settled))` only under `(when reply …)`; then rewake according to the outcome. Record once before delivering its receipt. Specify how a post-commit installation fault is durably linked to the existing evaluation/call without rerunning forms or their transaction.

Name acquisition's returned context **and** unbound-result diagnostic; `fork-for-turn` returns both (`src/seon/sci/eval.clj:2875-2893`). Carry request reader/evaluator/start-namespace values through the existing fold so JVM mode remains JVM mode (`src/seon/mcp.clj:255-275`), rather than routing every request through the SCI-only sample. nREPL's explicit read/eval arguments are the relevant library pattern (`reference-code/nrepl/src/clojure/nrepl/middleware/interruptible_eval.clj:80-86`).

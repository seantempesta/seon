## Projection acquisition still under investigation

carried-projection misses on changed declaration attribute revisions. declaration-content-key reads every projection attribute; load-projection joins every schema/contract row, projection-admissions joins every identity, and projection-from-entities reconstructs all population maps. Compilation reuse does not make these reads incremental. Datahike's revision context tells which attributes changed, not which identities. Its since view filters attribute ranges; its diff-sorted is a linear merge. The final report already holds exact changed datoms, but speculative and committed contexts have different revisions, and batched reports expose the last committed value, so blindly promoting a report-local candidate would be incorrect. No such shortcut is installed.

Existing tasks: seon.schema/a-declaration-write-reloads-the-whole-projection and seon.schema/a-function-contract-changes-the-schema-projection. The latter's contracts-out design is a coordinated target, not an installed API.

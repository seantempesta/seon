# Live trial 1 — the issue loop on `default`, 2026-09-17

The first live trial of the target loop (plan README "The target loop", A, and
H slice 1) on the development cluster `default` (pid 94566, booted
2026-09-17T05:02:01Z, adopted, Juniper seeded; repository HEAD `812c6ab21`,
branch `steward-platform`). Owner's goal, verbatim: "live agent testing with
running tests to prove they've completed their goal."

**Verdict up front: the loop did not reach a provider attempt.** Detection,
generation, test attachment, worker creation and opening composition all worked
exactly as designed. The worker's turn proc then died on every pass over an
unresolvable schema key, and every observation an operator has kept reporting
health. No provider call was made, so **nothing was spent** — zero attempts,
zero tokens, zero dollars.

Every step below ran through `mcp__seon__eval_clj` in `jvm` mode with explicit
custody `(seon.operator/connection "default")`. Nothing was stopped, started,
reset, reforked or adopted.

test-instrumentation hook var rather than an ordinary function;
`initialize-contracts!` was rejected for having three call sites where a

## 3. Required tests, then start

A generated issue carries no `:seon.issue/tests`, so its done condition is the
detector no longer naming it — which the owner's goal explicitly rules out. One
reaching test was attached first, making the tests the deciding facts
(`seon.issue/tests-done-query`: every test green **and**
`seon.test/verified?` on its current reach digest):

```clojure
(seon.issue/tests! {:seon.db/connection conn :seon.agent/id "root"
                    :seon.issue/id "9b2c2e7bd6d2"
                    :seon.issue/tests #{[:seon.test/sym "seon.test.runner-test/initialization-acquires-one-projection"]}})
```

That test was already green (8 passes, 0 fail, 0 error, run `03d8fb86eb0b` at
basis-t 536870921) but **`verified?` false** — stale reach digest — so the
worker genuinely has to re-run it after publishing the contract. The check form
changed exactly as designed:


(A vector arity was refused first — `:seon.issue/tests` is a set. The refusal

## 6. Verdict

- **Did the worker land a contract?** No. `:seon.fn/spec` on
  `seon.test.arm/arm-contracts!` is still absent; no definition was admitted.
- **Did settlement run the required tests and derive completion?** Never
  reached. The done-query wiring is correct and was verified statically: tests
  attached → `check-form` became `(my.test/check {:seon.test/changed […]})`,
  and `seon.issue/done?` would require that test green **and** `verified?` on
  the current reach digest, which it is not today.
- **What did the agent get wrong?** Nothing — the agent never ran. This trial
  produced no evidence about model behaviour at all.
- **What did the platform get wrong?** Below.

## 7. Defects

1. **[blocker]** [An agent turn proc dies on every pass over an unresolvable
   schema key, and every observation still reads
   healthy](../../../seon/issues/an-agent-turn-proc-dies-on-every-pass-and-oversight-still-reports-it-armed.md)
   — filed. Two halves: the projection split that throws, and the silence that
   let it run for 14 minutes looking idle. `runtime_status` shows only plumbing
   procs, `flow-status` shows the agent armed with a rising mailbox count, the
   mailbox→turn conn is `(sliding-buffer 1)` so every wake is accepted and
   dropped, and the issue reads `open` with its budget intact. The silence is
   the defect that survives the reset.
2. **[friction]** [A throwable-shaped fault keeps no inline evidence at any
   plausible
   bound](../../../seon/issues/a-throwable-fault-keeps-no-inline-evidence-at-any-plausible-bound.md)
   — existing note, updated with today's live confirmation and one correction:
   the note claimed the typed cause survives on the fact as
   `:seon.error/kind`. It did not. The fault reads
   `:seon.error/kind :seon.error/unclassified` with **no `:seon.error/message`
   datom**, because the `ex-data` that classifies it was exactly the part
   ablated (`:seon.error/capped? true`, `:seon.sci.admit/reason :over-bound`,
   `:seon.sci.admit/bytes 7806` against `:seon.error/data-size 33582`). The
   failing key lived only in the blob.
3. **[observation, already owned]** `seon.issue/generate!` and the detector
   family take and store `:seon.fn/sym` / `:seon.issue/detector` as **strings**.
   Owned by the reset batch's symbol retype; no new note.
4. **[observation]** `seon.issue/render-ai` prints the title, status, remaining
   turns and done condition, but not `:seon.issue/problem`. Harmless today —
   the plan block carries the problem into the opening — but the issue block
   alone is not enough to work from if the plan block ever moves.
5. **[shared-tree residue, not mine]** `bin/hook_probe_1.clj` (39 bytes,
   untracked, written 10:27 local) is a deliberate broken-syntax hook probe left
   by another session. It makes the edit hook block on every later write-capable
   MCP evaluation with a syntax refusal for a file the caller never touched. It
   was preserved, not deleted; its owner should sweep it.

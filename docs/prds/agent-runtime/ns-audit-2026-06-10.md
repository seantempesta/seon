# Namespace audit — the pod `:client` build (2026-06-10)

Read-only audit for the context-v3 reorg
([[context-v3-code-first-2026-06-10]], PRD §10 decisions in
[[cljs-finish-clj-pivot-plan-2026-06-09]]). Goal: every namespace compiled
into the agent's runtime gets an explicit place — language layer, toolbelt,
internal, web-ui, dev — or gets flagged for deletion/relocation. Bar:
"everything that's there is important and needed."

## Method (what "compiled into the runtime" means here)

- **Authoritative loaded set** = the require list embedded in
  `out/client/main.js` (current watcher output, current tree): **61
  `seon.*` namespaces** — 44 production + 17 test namespaces pulled in via
  the `seon.dev.test-preload` `:devtools :preloads` slot.
- The `.shadow-cljs/builds/client/dev/out/cljs-runtime/` cache is a
  SUPERSET (87 entries) containing stale artifacts of deleted sources
  (`seon.web.broadcast`, `seon.web.sse`, `seon.handlers.retro_stamp`,
  `seon.pod_disk_conn_test`, `seon.gym.driver`, old test names) — those
  are NOT loaded and need no action beyond knowing they're stale.
- Source paths (deps mode — shadow's `:source-paths` is ignored): `src` +
  `test` + `guest-cljs/src` + `resources` via the `:cljs` alias.
  `guest-cljs/src/seon/client_runtime/*` (8 nses) is on the classpath but
  required by NO `:client` namespace — wasm-guest era, rides only the
  retired `:guest-agent`/`:v0-probe` builds.
- Live-store cross-check (read-only CLJS REPL, pod conn, 2026-06-10): 69
  `:seon.ns/name` rows = the build namespaces above ∪ keyword-only attr
  namespaces (`:seon.message`, `:seon.turn`, `:seon.ctx`, …) ∪ agent rows
  (`:kb.workout`, `:probetest.workout`, `:seon.db-split-proof`). Zero
  `seon.agent.<id>` home-ns rows (matches the PRD's unit-1 evidence).
- Tree caveat: the todo-wiring lane moved `seon.todo` →
  **`seon.agent.todo`** (`src/seon/agent/todo.cljs` +
  `test/seon/agent/todo_test.cljs`) WHILE this audit ran. Rows below
  reflect the tree at audit time; `seon.fs`/`seon.search` are NOT yet
  renamed.

Classes: **language** (root, shown) · **toolbelt** (`seon.agent.*`,
shown) · **internal** (hidden; rename to `*.internal` or under an
internal parent where the name lies) · **web-ui** (hidden today; future
own-process reader per PRD §7.10) · **dev** (dev/test tooling) ·
**DELETE** · **DECIDE**.

## (a) DELETE list — evidence

1. **`konserve-sqlite-cljs.core`** — zero requires in `src`/`test`, no
   deps.edn/shadow reference, untouched since 2026-05-16 (the very first
   `:client` commit). The cluster store is konserve `:file` behind DIS;
   SQLite-wasm was an abandoned storage experiment.
2. **`seon.wasm-smoke` + `seon.wasm-eval-smoke`** (+ shadow builds
   `:smoke`, `:eval-smoke`, and the `:bootstrap` build's wasm framing in
   comments) — "NO WASM" is in CLAUDE.md's settled list. Only the two
   wasm builds reference them. Delete the nses and the build entries.
3. **`seon.web.page`** — `serve-root!` (web/serve.cljs:156-166) redirects
   `/` to `/agents` precisely because this shell never worked; zero
   requirers; the 06-09 touch was a mechanical sweep of an already-dead
   file.
4. **`seon.ui.markdown`** — zero requirers since its 2026-05-20 demo
   commit; never compiled into any build (absent even from the dev
   cache).
5. **Stale shadow cache only (no source — no action, listed so nobody
   re-audits them):** `seon.web.broadcast`, `seon.web.sse`,
   `seon.handlers.retro-stamp`, `seon.pod-disk-conn-test` — sources
   already deleted; artifacts linger in `.shadow-cljs/builds/client/`.
6. **Leaning-delete but filed under DECIDE:** `seon.agents`, `seon.code`,
   `seon.dev.wire-sync`, `guest-cljs/` tree, `seon.dev.node-agent` —
   each has a one-line rescue story; see (c).

## (c) DECIDE list — with recommendations

- **d1 `seon.agents` (15k + 12k test).** The `*ctx*` ALS per-agent-state
  substrate from atom-state-system-2026-05-26. Zero production callers —
  `run-as-agent` is called by nothing; only `seon.agents-test` keeps it
  compiled. The tx-context ALS that production actually uses lives in
  `seon.db.internal`. Recommendation: **DELETE** (with its test and the
  preload line); git has history, and re-introducing it when a real
  per-agent runtime knob appears is cheap. Counter-case: one Node process
  per agent is the stated target, which makes per-agent ALS state even
  less necessary.
- **d2 `seon.code` (12.7k + tests).** "Gate for agent-authored source" —
  a pure `check` predicate the eval pipeline never calls (verified: no
  src requirer). Recommendation: **DELETE** unless the user still wants a
  source gate before eval; if kept, it must be WIRED (an unwired safety
  gate is worse than none — it reads as protection that doesn't exist).
  Deleting also deletes `seon.code-test` and edits
  `seon.eval.detect-tee-test`'s stray require.
- **d3 `seon.inspect` (6.4k).** Genuinely ambiguous: docstring is
  agent-facing ("what am I seeing right now?", defaults to
  `current-agent-id`), but its only production consumer is the inspector
  UI. Recommendation: **toolbelt** (`seon.agent.inspect`) — an agent that
  can preview its own next render is squarely "tools", and it's small
  and clean (map-in/map-out). The web UI keeps requiring it; fine.
- **d4 `seon.test.runner` (35k).** Agents are TAUGHT to run confidence
  tests; `run!` is part of their working vocabulary, but 35k is heavy
  and most of it is event-capture plumbing. Recommendation: **toolbelt
  via split** — `seon.agent.test` face (`run!`, `record-run!`) +
  `seon.agent.test.internal` for the reporter machinery; do it when the
  V3-A split pattern reaches it, classify internal until then (agents
  reach it by taught call, not by reading source).
- **d5 `seon.log` `tail`.** Agents read pod events via `tail` /
  `seon.fs`. Recommendation: keep `seon.log` internal; if gym scoring
  shows agents need log access taught, expose a thin
  `seon.agent.log/tail` face later. Don't pre-build it.
- **d6 `seon.dev.node-agent`.** Production wire-node imports it for ONE
  fn (`agent-id`). Recommendation: inline that fn into wire-node, then
  either keep node-agent as dev probe tooling or delete it with the
  multi-runtime-probe era.
- **d7 `guest-cljs/` tree + `seon.dev.wire-sync` + `:guest-agent` /
  `:v0-probe` / `:cljs-guest` builds/alias.** The wasm-guest stack the
  lane-merge superseded. Recommendation: **DELETE the lot** in one
  commit (git has history) — but this is a settled-direction call the
  user should bless because it deletes the Track-2 unit-2.1 oracle.
  KEEP `seon.dev.replica-probe` + `seon.dev.replica-peer` + their JVM
  aliases regardless: they are the two committed DIS regression
  harnesses the architecture leans on.

## (d) Build-hygiene findings

1. **Production code under `seon.dev.*`:** `seon.client → seon.store.wire
   → seon.dev.wire-node → seon.dev.cbor + seon.dev.node-agent`. Three
   "dev" nses load in every pod boot. Rename per (b); after that,
   `seon.dev.*` is uniformly dev-tooling and the name classifies.
2. **Preload surface is intentional and correctly scoped** — 17 test nses
   ride `:devtools :preloads` (zero release cost) and double as the
   exemplar test siblings + the boot indexer's deftest roster. No change.
   One wart: `seon.agent-context-test` requires `seon.agent.todo-test`
   directly (test→test require) to keep it in the pod build — fine, but
   worth a comment so nobody "cleans" it.
3. **`guest-cljs/src` is on EVERY build's classpath** (deps-mode `:cljs`
   alias) though nothing in `:client` requires it — harmless today,
   removable with d7.
4. **Orphan sources compile nowhere** (`seon.ui.markdown`,
   `seon.web.page`, `konserve-sqlite-cljs.core`, wasm smokes) — they
   cost nothing at runtime but each one is a future agent's wrong
   exemplar; delete per (a).
5. **`src/seon/ui/html_test.cljc`** — test file under `src/`; it matches
   the `:test` build's `-test$` regex so it RUNS, but it sits on the
   production source path. Move to `test/`.
6. **Stale `.shadow-cljs` cache artifacts** of deleted nses — cosmetic;
   a `bin/seon restart cljs-watch` after the deletes, or ignore.

## (e) Impact on the V3-C classifier's temporary exclusion set

The audit confirms the exclusion set stays EXACTLY the PRD's list of
not-yet-split relevant roots and nothing else needs adding:

- Rule 4 (not in `relevant-roots` ⇒ internal) already covers every
  plumbing ns in this audit with no list maintenance: handlers, render,
  warn, log, error, instrument, platform, analyzer-info, deepseek,
  agent-view, store.wire, web/ui, client, indexing.
- After the (b) renames, `relevant-roots` ≈ `seon.db`, `seon.schema`,
  `seon.repl` + the `seon.agent.*` toolbelt + `my.*` — i.e. the names
  carry the classification; the only residue is the PRD's transition
  exclusion set (`seon.agent`, `seon.eval`, `seon.schema`, `seon.warn`,
  `seon.render`, `seon.client`), each of which dies when its `.internal`
  sibling lands (the death-condition test).
- Deleting the (a)+(c) dead nses removes 6 namespaces (~90k chars of
  source) from the index entirely, so the classifier never even sees
  them.

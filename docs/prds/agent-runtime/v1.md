# Seon agent REPL — v1 spec

The minimum subset to get the agent running against deepseek with
session-survival + observability + program-graph discovery.
Iteration target, not perfection.

> **This spec is a DRAFT.** It is the agreed-upon shape, not a
> contract carved in stone. When you implement a section and reality
> doesn't match — datahike doesn't behave as documented, cljs.js
> does something we didn't anticipate, the `*tx-context*` dynvar
> doesn't propagate through Promise chains, the detect-and-tee
> can't extract a defn name from some legal Clojure form — **STOP
> and surface the mismatch to Sean.** Do not paper over it with
> coercions or workarounds. The spec is a hypothesis; the REPL is
> the oracle (CLAUDE.md "Slow Is Fast"). See §11 below for the
> specific assumptions that need REPL-verification before
> implementation commits.

**V1 ships:**

- The full causality graph (`:seon.agent` / `:seon.session` /
  `:seon.turn` / `:seon.message` / `:seon.eval`).
- The program graph **minus tests**: `:seon.fn`, `:seon.schema`,
  `:seon.ns` entities (substrate AND agent code), plus the
  detect-and-tee step in `eval-batch!` and the `bootstrap.edn`
  emission that seeds substrate program entities on first boot.
  This is the discovery surface — without it, the agent has no way
  to see what functions / schemas / namespaces exist beyond what
  fits in the system-section cheat-sheet.
- Composable render layout via `:seon.agent/ctx` → `:seon.ctx`
  entities + composer dispatch.
- Inline `:seon.turn/prompt-text` for playback (v2 swaps in the blob
  subsystem).
- Tx-meta causality bundle auto-propagated via `seon.db/with-tx-context` + `seon.db/current-tx-context` (AsyncLocalStorage-backed; safe under concurrent agents).
- 6 default sections (system / messages / current-ns / warnings /
  recent-evals / prompt).
- One warning predicate (slow-eval) — proves the mechanism. v2 adds
  untested-fn + failing-test predicates when the test entity lands.
- Eval pipeline with detect-and-tee, partial-success semantics,
  undeclared-var surfacing.
- Boot: preconditions, analyzer-cache load, bootstrap phase
  (substrate seeds), resume phase (walk program-graph entities),
  start-session.

**V1 deliberately defers** (full designs survive in [v2.md](v2.md),
preserved in detail — not lost):

- `:seon.test` entity + auto-run via `d/listen!` + agent test
  helpers + `untested-fn` / `failing-test` warning predicates.
- The content-addressed `:seon.blob` subsystem (v1 stores
  `:seon.turn/prompt-text` inline as a string instead — known
  compromise of the three-tier rule).
- `:malli/schema` required gate on defns + accretive-schema-redef
  rule.
- `:seon.message/important?` + `mark-important!`.
- `forget!` / `forget-ns!` curation verbs.
- `:db/noHistory` per-attr opt-outs on high-churn scalars.
- D8 reference-graph attrs (`:seon.fn/refs` etc.) — empty in V0
  anyway, defer until analyzer walk exists.
- `seon.render` per-entity-specificity dispatch.
- `related-ns-section`, Tufte profiling, context-budget enforcement.

V1 → v2 is a **clean break**: different schemas, fresh database. No
backfill or migration tooling. Spend iteration speed in v1; clean up
in v2.

## 1. What v1 delivers

### Goal

A long-running agent loop where:

- The agent sees a structured, always-current rendered context each
  turn.
- The forms it eval'd survive restart, by replaying successful evals
  in tx order on the next boot.
- Every turn — what the LLM saw, what it said, what got eval'd —
  lands in the database as a connected graph. One pull on a turn
  reconstructs it.
- The defaults are simple enough for the agent to read once and
  internalize.

### Context is `fn(DB)`, not an accumulated log

The rendered prompt the LLM sees each turn is **derived freshly from
current DB state** by running the section fns. It is not a
transcript that grows; it is a projection. Defaults are bounded
(N=50 messages, N=20 evals); the agent can rewrite any section fn
to retune.

The agent's `:seon.agent/ctx` is a cardinality-many ref vector of
`:seon.ctx` entities — section layout is data. Customization is
transacting different `:seon.ctx/fn` symbols or different priorities
(see §5).

### Three storage tiers — the rule survives

> *Only put data in the datahike schema that the agent's rendered
> context surfaces.*

| Tier | Purpose | v1 examples |
|---|---|---|
| **DB datoms** | Small, indexed projections the renderer reads | `:seon.eval/source`, `:seon.eval/result-edn` (truncated 2 KB), `:seon.message/content`, `:seon.turn/prompt-text` |
| **Future blobs** *(v2)* | Persistent full content for cross-session playback | (deferred — see v2.md for the full design) |
| **GlobalThis stash** — volatile, dies with the pod | Per-session live values that don't serialize cleanly | `(result <eval-id>)` for raw JS objects / Promises / fns |

**V1 puts `:seon.turn/prompt-text` directly on the turn entity as a
string** (~20–50 KB per turn). This violates the principle for a
known reason: shipping a full content-addressed blob subsystem is
infrastructure work that's not on the v1 critical path. The design
debt is accepted, documented, and queued for v2 (see v2.md
§"Blob storage — content-addressed archival") which will migrate
this attribute to a blob ref.

`:seon.eval/result-blob` and the `seon.blob` namespace do NOT exist
in v1. Eval results show as truncated `:seon.eval/result-edn` for
display; full live values are reachable via `(result <eval-id>)`
within the session and lost on restart.

### Map args + smart defaults — discoverable from the spec

Optional configuration on Seon-facing functions goes through a map
argument; **every optional key is fully namespaced** (CLAUDE.md
"Data Rules"); **every optional key has a default listed in the spec
directly**. Three override channels:

1. Call-time arg overrides spec default:
   `(seon.agent/messages {:seon.agent/n 10})`.
2. Entity-data on the relevant section overrides spec default:
   stick `:seon.agent/n 10` on the section's ctx entity, the
   section fn reads it.
3. Spec default is the last resort.

Call-time wins over entity-data wins over spec default.

### Hard rules (eval-batch enforces; failures land as `:ok? false`)

V1 ships ONE hard rule and one structural rule:

1. **Forms must be parseable.** rewrite-clj parses; on failure we
   record an `:ok? false` eval entry with `:kind :read` and continue
   to the next balanced top-level form.
2. **Datahike attribute schemas are mostly append-only** (inherent
   to datahike; under `:schema-flexibility :write`, `:db/valueType`
   is immutable and `:db/unique` cannot be removed). Treat the v1
   attribute schema as non-negotiable; extensions add new attrs.

**Cut from v1, moved to v2:**

- `:malli/schema` required on every defn (the `seon.code/check`
  gate). Reason: without the program graph in v1, there's no
  systematic enforcement surface and the friction-vs-value tradeoff
  is wrong for iteration speed. v2.md §"Hard rules" specs the gate.
- Schema redefinitions must be accretive against existing data.
  Reason: same as above — no program-graph persistence means no
  accumulated data to protect; datahike's own
  `find-invalid-schema-updates` catches the worst cases at the DB
  layer. v2.md §"Hard rules" specs the predicate.
- Soft-rule warnings (untested fns, slow evals, `(def …)` outside
  defn). Reason: the entire warnings tile defers. v2.md §"Warnings
  tile" specs all three predicates in detail.

## 2. Data model

Single database. Three logical layers in v1.

1. **Causality graph** — who, in which session, on which turn,
   said or did what. Forward-ref component chain:
   `:seon.agent` → `:seon.session` → `:seon.turn` → `:seon.message`
   and `:seon.eval`.
2. **Program graph** — code the agent has written + substrate code
   it can discover. `:seon.ns` / `:seon.fn` / `:seon.schema`
   entities; child→parent refs from fn/schema to ns; reverse-ref
   pulls do namespace-scoped discovery in one step.
3. **Render layout** — `:seon.agent/ctx` is a vector of `:seon.ctx`
   section entities. The composer reads them in priority order.

V1 does NOT ship `:seon.test` (test entity defers to v2 with the
auto-run story; agent-written `(deftest …)` forms still eval into
cljs.test runtime as live state). V1 also does NOT ship the
content-addressed `:seon.blob` subsystem (inline
`:seon.turn/prompt-text` instead). Both have full design intact in
[v2.md](v2.md).

All three layers share the same database and the same tx-meta
causality bundle (see §2.3).

### 2.1 Causality graph

```clojure
;; Agent — identity + liveness + ctx layout. Transient counters
;; (turn-count etc.) live on the session below, not here.
::seon.agent/id           [:string {:min 12 :max 12 :seon.db/identity true}]
::seon.agent/state        [:enum :idle :running]
::seon.agent/current-ns   :keyword {:optional true}
::seon.agent/sessions     [:vector :seon.db/ref {:seon.db/component true}]   ; → :seon.session
::seon.agent/ctx          [:vector :seon.db/ref {:seon.db/component true}]   ; → :seon.ctx

;; Session — one pod run from boot to halt.
::seon.session/id               [:string {:min 12 :max 12 :seon.db/identity true}]
::seon.session/at               :inst
::seon.session/turn-count       :long
::seon.session/turns-since-user :long
::seon.session/turns            [:vector :seon.db/ref {:seon.db/component true}]   ; → :seon.turn

;; Turn — one full render → LLM → parse → eval-batch cycle.
;; :prompt-text is the literal rendered context the LLM saw, inline
;; as a string in v1. Will move to :seon.turn/prompt-blob (ref → :seon.blob)
;; in v2 when the blob subsystem ships.
::seon.turn/id          [:string {:min 12 :max 12 :seon.db/identity true}]
::seon.turn/index       :long
::seon.turn/at          :inst
::seon.turn/status      [:enum :running :done :error]
::seon.turn/prompt-text :string {:optional true}                            ; v1: inline string. v2: prompt-blob ref.
::seon.turn/messages    [:vector :seon.db/ref {:seon.db/component true}]    ; → :seon.message
::seon.turn/evals       [:vector :seon.db/ref {:seon.db/component true}]    ; → :seon.eval

;; Message — one user/assistant/system message attached to a turn.
::seon.message/id      [:string {:min 12 :max 12 :seon.db/identity true}]
::seon.message/role    [:enum :user :assistant :system]
::seon.message/content :string
::seon.message/at      :inst

;; Eval — one form's read/eval/result. The eval entity IS the tx
;; entity (via tx-meta {:seon.db/eval-id <id>}). :source is the
;; full form text — load-bearing for resume-via-replay.
::seon.eval/id          [:string {:min 12 :max 12 :seon.db/identity true}]
::seon.eval/at          :inst                                               ; before eval starts
::seon.eval/duration-ms :long                                               ; wall clock incl. auto-await
::seon.eval/ns          :keyword                                            ; ns the form LEFT the agent in
::seon.eval/narration   :string {:optional true}                            ; leading ;; comments
::seon.eval/source      :string                                             ; form text — load-bearing
::seon.eval/ok?         :boolean
::seon.eval/result-edn  :string {:optional true}                            ; pr-str, truncated to 2 KB
::seon.eval/error       :string {:optional true}                            ; flattened error map (:seon.error/data)

;; Ctx — one section in the agent's render layout. Component-owned
;; by the agent, cardinality-many. Reshaping the layout = transact
;; different ctx entities into :seon.agent/ctx.
::seon.ctx/name     :keyword
::seon.ctx/priority :long
::seon.ctx/fn       :symbol                                                 ; ns-qualified, e.g. 'seon.agent/system-section

```

**Cut from causality graph in v1:**

- `:seon.eval/result-blob` (ref to `:seon.blob`) — no blob subsystem
  in v1. Big results survive only via globalThis stash for the
  session.
- `:seon.message/important?` — no message pinning in v1. v2.md
  §"Message importance" specs the attr + `mark-important!` helper.

**One pull walks the whole agent:**

```clojure
(d/pull db
  '[*
    {:seon.agent/sessions
     [* {:seon.session/turns
         [* {:seon.turn/messages [*]
             :seon.turn/evals    [*]}]}]}
    {:seon.agent/ctx [*]}]
  [:seon.agent/id "AbCdEfGh1234"])

```

Components inline (not `{:db/id N}` placeholders). One pull, no
joins. The agent learns this on day one in `system-section`.

### 2.2 Program graph

The code the agent has access to — substrate fns/schemas/nses
shipped in the pod, plus the agent's own defns/schemas/nses
accumulated across sessions — lives as a queryable graph. Without
this layer the agent's only way to discover what functions exist is
to scroll the eval log; substrate functions (compiled in, never
eval'd by the agent) wouldn't be visible at all.

```clojure
;; Namespaces — one entity per substrate or agent-defined ns.
;; The full (ns …) form is the :source so resume can re-eval it.
::seon.ns/name    [:keyword {:seon.db/identity true}]   ; :seon.trading.signals
::seon.ns/source  :string                               ; "(ns seon.trading.signals (:require ...))"

;; Functions
::seon.fn/sym     [:string {:seon.db/identity true}]    ; "seon.trading/analyze"
::seon.fn/ns      :seon.db/ref                          ; → :seon.ns (plain ref — child→parent)
::seon.fn/source  :string                               ; current source text

;; Schemas
::seon.schema/key     [:keyword {:seon.db/identity true}]
::seon.schema/ns      :seon.db/ref                      ; → :seon.ns
::seon.schema/source  :string                           ; full register! call text
```

**No `:seon.test` in v1.** Tests as a first-class entity (with
`:target`, `:last-passed-at`, `:last-failure-summary`, etc.) and the
auto-run-on-defn-change machinery (`d/listen!` hook) defer to v2.
The agent can still write `(deftest …)` forms in v1 — they eval
into cljs.test as live state — but nothing persists across restart
except the source on `:seon.eval/source`, and there's no `:seon.test`
entity to query, no auto-run on redefine, and no failing-test
warning predicate. v2.md §"Test entity and auto-run" specs the
full design.

**No `:seon.fn/refs` / `:seon.fn/input-spec` / `:seon.fn/output-spec`
in v1** either (D8). The analyzer walk that would populate them
isn't wired up in V0; the attrs would be empty. v2.md §"Reference-
graph attrs" specs the design + the AST walk that feeds them.

**Why ns refs are plain (not component)** — a function does not own
its namespace; if it did, retracting the function would
cascade-retract the namespace. `:seon.fn/ns` is a child-to-parent
forward ref. The parent (ns) owns the children via reverse-ref
pulls.

#### Detect-and-tee in `eval-batch!`

When a form's head is `defn` / `schema/register!` / `(ns …)`, the
per-form loop transacts a matching program-graph entity in the
**same tx** as the eval entity. Both share `:tx-meta {:seon.db/eval-id <id>}`
via the `seon.db/with-tx-context` scope, so the eval entity IS the
tx that wrote the program-graph datom.

Detection uses `rewrite-clj.parser/parse-string` on
`:seon.eval/source` (not regex; not analyzer state) — peek the
form head, extract the symbol being defined, build the tee map:

```clojure
(defn detect-and-tee
  "Returns extra tx-data to merge with the eval entity transact,
   OR nil if the form doesn't create a program-graph entity."
  [form-source ns]
  (let [head (-> form-source rewrite-clj.parser/parse-string
                 :children first :children first :value)]
    (case head
      defn              [{:seon.fn/sym    (str ns "/" (extract-defn-name form-source))
                          :seon.fn/ns     [:seon.ns/name ns]
                          :seon.fn/source form-source}]
      schema/register!  [{:seon.schema/key    (extract-schema-key form-source)
                          :seon.schema/ns     [:seon.ns/name ns]
                          :seon.schema/source form-source}]
      ns                [{:seon.ns/name   (extract-ns-name form-source)
                          :seon.ns/source form-source}]
      nil)))
```

The eval entity and the program-graph entity share a tx; either
both land or neither does. On `defn` redefinition, the
identity-attr upsert replaces `:seon.fn/source` with the new text;
history retains the prior version.

**Substrate seeding via `bootstrap.edn`.** The substrate's own
fns/schemas/nses (`seon.agent/system-section`,
`seon.agent/messages`, `seon.db/transact!`, etc.) need to be in the
program graph from boot — they were never eval'd by the agent.
Build-time emission (D10) produces `resources/seon/bootstrap.edn`,
an ordered vector of entity maps the bootstrap phase transacts on
first DB init. See §7.3.

#### Discovery via reverse-ref pulls

Everything an ns owns is one pull from the ns entity:

```clojure
(d/pull db
  '[:seon.ns/source
    {:seon.fn/_ns     [:seon.fn/sym :seon.fn/source]
     :seon.schema/_ns [:seon.schema/key :seon.schema/source]}]
  [:seon.ns/name :seon.agent])
```

This is exactly what `current-ns-section` (§5.2) uses. The `_ns`
prefix is the reverse-ref selector; datahike handles it natively.

For "what's the entire surface I can call?" the agent walks all
nses + their fns:

```clojure
(d/q '[:find ?ns ?sym
       :where [?n :seon.ns/name ?ns]
              [?f :seon.fn/ns ?n]
              [?f :seon.fn/sym ?sym]]
     db)
```

### 2.3 Tx-meta — every tx is forensically traceable

Datahike's `:tx-meta` writes each map key as a datom on the
transaction entity. V1 carries the **full causality bundle** on
every tx, automatically, through the
`seon.db/with-tx-context` / `seon.db/current-tx-context` pair:

```clojure
;; All tx-meta attrs MUST be registered before the first tx fires.
;; Datahike flush-tx-meta (db/transaction.cljc:634) rejects
;; unregistered keys at write time.

::seon.db/agent-id         [:string {:min 12 :max 12}]          ; who
::seon.db/session-id       [:string {:min 12 :max 12}]          ; in which session
::seon.db/turn-id          [:string {:min 12 :max 12}]          ; which turn
::seon.db/eval-id          [:string {:min 12 :max 12}] {:optional true}  ; which form (absent for non-eval txs)
::seon.db/origin           [:enum :user :agent :system :replay] ; what initiated this tx
::seon.db/replay?          :boolean {:optional true}            ; true during resume-phase replay
::seon.db/resume-marker?   :boolean {:optional true}            ; true on the first tx of a resume phase

```

`:seon.eval/test` (tx-meta attr for test-run tagging) is NOT in v1
— see v2.md §"Test entity and auto-run" for the full design.

**Auto-propagation.** `seon.eval/eval-batch!` establishes the
bundle via `(seon.db/with-tx-context {:seon.db/agent-id … …} f)`
around each form's eval; `seon.db/transact!` reads
`(seon.db/current-tx-context)` and deep-merges into every tx's
`:tx-meta`. No manual plumbing at transact call sites. Conflict
rule: an explicit `:seon.db/opts {:tx-meta {…}}` on the transact
call wins per-key; the context fills any unset keys.

**Why not a `^:dynamic` Var?** CLJS `binding` uses `set!`/restore
against a single global slot — it is not fiber-local across async
yields. Two `^:async` fns each binding the same var across
overlapping `(await …)` points clobber each other (see
[[research/impl-finding-tx-context-promise-2026-05-22]] Probe 13).
v1 supports concurrent agents in one pod, so a fiber-local
primitive is required. Implementation is Node
`AsyncLocalStorage` (`node:async_hooks`) wrapped behind the two
fns above. The agent-visible API does not change — agents call
`(seon.db/transact! …)` and the bundle auto-merges. Phase 3
(WASM cutover) needs an ALS-equivalent for wasm-rquickjs; tracked
as a separate D13-WASM probe.

**Tx-meta datoms ONLY persist when `:keep-history? true`** on the
conn. The boot preconditions assert this (§7.1).

**The eval-IS-tx mechanic.** Pulling `[:seon.eval/id "K9p…"]` returns
the eval entity AND every tx-meta datom on it. `(d/q '[:find ?e ?a ?v ?op
:in $ ?tx :where [?e ?a ?v ?tx ?op]] (d/history db)
[:seon.eval/id "K9p…"])` returns the datoms that eval wrote.

### 2.4 Pull patterns the agent learns day one

These three idioms cover most of what the agent ever asks. They
appear in `system-section` (§5.2) so the agent reads them on every
turn.

```clojure
;; 1. Your own causality graph — sessions, turns, messages, evals.
(d/pull db
  '[* {:seon.agent/sessions
       [* {:seon.session/turns
           [* {:seon.turn/messages [*]
               :seon.turn/evals    [*]}]}]}]
  [:seon.agent/id (seon.agent/id)])

;; 2. Recent evals in the current ns — your "what have I written here?" query.
(d/q '[:find (pull ?e [:seon.eval/source :seon.eval/ns :seon.eval/at])
       :in $ ?ns
       :where [?e :seon.eval/ns ?ns]
              [?e :seon.eval/ok? true]]
     db (seon.agent/current-ns))

;; 3. What an eval wrote (the eval IS the tx).
(d/q '[:find ?e ?a ?v ?op
       :in $ ?tx
       :where [?e ?a ?v ?tx ?op]]
     (d/history db) [:seon.eval/id "K9p2x4nB7q"])

```

The four primitives behind these (wildcard `*`, ref recursion via
nested maps, datalog joins, the 5-tuple datom pattern `[?e ?a ?v ?tx ?op]`)
cover essentially every query the agent will ever need.

### 2.5 What's NOT in v1's DB (and where the design lives)

- **`:seon.test` entity + auto-run.** Agent can write `(deftest …)`
  forms which eval into cljs.test runtime; nothing persists across
  restart except the source on `:seon.eval/source`. No test entity,
  no `(seon.agent/test ...)` helpers, no `d/listen!` auto-run hook,
  no `:seon.eval/test` tx-meta. **Full design in v2.md §"Test entity
  and auto-run".**
- **`:seon.fn/refs` / `input-spec` / `output-spec`** (D8) — the
  AST-walk-populated reference-graph attrs. Empty in V0 anyway.
  **Full design in v2.md §"Reference-graph attrs".**
- **`untested-fn` and `failing-test` warning predicates.** Both
  need the test entity. V1 ships `slow-eval` only. **Full design
  for the other two in v2.md §"Warnings tile".**
- **`:seon.blob` content-addressed archival.** No blob subsystem.
  `:seon.turn/prompt-text` is inline; `:seon.eval/result-blob`
  doesn't exist. **Full design in v2.md §"Blob storage —
  content-addressed archival".**
- **`:db/noHistory` per-attr opt-outs.** Whole conn is
  `:keep-history? true`; high-churn scalars (`turn-count`, `state`)
  accumulate history rows. **Full design in v2.md §"History
  pruning".**
- **`:seon.message/important?` + `mark-important!`.** No message
  pinning. **Full design in v2.md §"Message importance".**
- **`:malli/schema` required gate + accretive-schema-redef rule.**
  Hard rules 2 and 3 from the original spec, deferred. **Full
  design in v2.md §"Hard rules".**
- **`forget!` / `forget-ns!` curation verbs.** Defer until the
  agent has accumulated cruft worth purging. **Full design in
  v2.md §"Curation verbs".**

## 3. ID conventions

One generator, one shape. Generator lives in `seon.agent` next to
the entities it mints IDs for; the shape is inlined at each identity
attr's registration. (Earlier drafts factored the shape into a
named `:seon.id/id` schema in its own `seon.id` namespace — the
indirection was a 5-line generator + a redundant `id/id` keyword
that paid nothing back. Collapsed 2026-05-22 under the "no stupid
shit" rule.)

```clojure
;; seon.agent

(defn new-id!
  "12-char base62 id. 8-char epoch-ms prefix + 4-char random suffix.
   Lex-sorts by creation time because the base62 alphabet 0…9A…Za…z
   is lex-equivalent to ASCII byte order. 62^8 ≈ 2.2 × 10^14 covers
   epoch-ms past year ~9090."
  [] ...)

;; Each identity attr inlines the 12-char shape. `{:seon.db/identity
;; true}` on the Malli property map signals the bridge to declare
;; `:db/unique :db.unique/identity` on the datahike side.
(schema/register! :seon.agent/id
                  [:string {:min 12 :max 12 :seon.db/identity true}])
(schema/register! :seon.session/id
                  [:string {:min 12 :max 12 :seon.db/identity true}])
(schema/register! :seon.turn/id
                  [:string {:min 12 :max 12 :seon.db/identity true}])
(schema/register! :seon.message/id
                  [:string {:min 12 :max 12 :seon.db/identity true}])
(schema/register! :seon.eval/id
                  [:string {:min 12 :max 12 :seon.db/identity true}])
```

The agent's home namespace is `seon.agent.<id>` — e.g.
`seon.agent.AbCdEfGh1234`.

> **Default-agent transitional note (V0 holdover).** The default
> agent boots with id `"seon"` (4 chars), which fails the strict
> 12-char Malli constraint. While `default-id` remains a literal,
> `:seon.agent/id` is registered loose (`:string`) on the Malli
> side. Tightening to the 12-char shape pairs with the default-id
> refactor — see Phase C2 in the implementation log.

**Entity references in transacts:** lookup refs of the form
`[:seon.agent/id "AbCdEfGh1234"]`. Identity-attr values are strings;
references are vectors.

**Function references in symbol slots** (`:seon.ctx/fn`): fully-qualified
Clojure **symbols**, e.g. `'seon.agent/system-section`. Stored as
`:symbol`. Resolved at call time.

## 4. Eval pipeline

### 4.1 Parse

Use `rewrite-clj.parser/parse-string-all`, which parses Clojure
source as a tree of nodes that **includes** whitespace and `:comment`
nodes alongside form nodes. Walk the top-level children, filter
whitespace, get an ordered vector:

```clojure
[{:kind :comment :text "## Plan"}
 {:kind :comment :text "Schema first, then the function."}
 {:kind :form    :form  '(schema/register! ::ticker :string) :source "(schema/register! ::ticker :string)"}
 {:kind :comment :text "Now the analyzer:"}
 {:kind :form    :form  '(defn analyze …) :source "(defn analyze …)"}]

```

**Bare symbols are forms.** They eval like any other expression.

**`parse-forms` returns the raw, unpaired vector — comments and forms
as siblings.** The example above IS the output shape. `parse-forms` is
a pure substrate primitive: source-string in, ordered vector of
`{:kind :comment :text}` and `{:kind :form :form :source}` maps out.
It does NOT attach comments to forms.

- `:kind :comment` — one entry per `;`/`;;` line. `:text` is the
  comment content with the leading `;` (and one optional leading
  space) stripped. Consecutive comment lines are separate entries,
  in source order.
- `:kind :form` — `:source` is the original source string (preserves
  whitespace, metadata syntax, etc.); `:form` is the reader-evaluated
  value of `:source` (call `cljs.tools.reader/read-string` on
  `:source` — what `eval-batch!` would otherwise re-parse anyway).

**The pairer lives in `eval-batch!`, not `parse-forms`.** The per-form
loop walks the raw vector and, for each `:form` entry, joins the
preceding consecutive `:comment` entries' `:text` (newline-separated)
into the eval entity's `:seon.eval/narration`. A run of `:comment`
entries with no following `:form` becomes a single thinking-only
eval entry (`:source ""`, narration populated, `:ok? true`).

**Markdown lives inside `;;` comments.** Multi-line markdown is
multiple `;;` lines in a row — the pairer description above is what
turns those into one narration block on the next form.

**Parse failure recovery (D9):** if rewrite-clj throws on a chunk,
record an `:ok? false` eval entry with `:kind :read`, advance to
the next balanced top-level boundary, continue.

### 4.2 Per-form loop

The per-form work runs inside a `seon.db/with-tx-context` scope
(§2.3) that carries the full causality bundle. `with-tx-context`
is AsyncLocalStorage-backed; the bundle survives `(await …)`
points inside the wrapped fn AND any nested `^:async` calls,
without clobbering concurrent agents' contexts.

```clojure
(seon.db/with-tx-context
  {:seon.db/agent-id   (seon.agent/id)
   :seon.db/session-id session-id
   :seon.db/turn-id    turn-id
   :seon.db/eval-id    eval-id
   :seon.db/origin     :agent}
  (fn []
    (binding [seon.agent/*id* (seon.agent/id)]
      ;; form eval + record-eval! run here
      ...)))

```

For each parsed form:

1. **Mint an eval-id** (`seon.agent/new-id!`) and snap a start timestamp.
2. **Enter the `with-tx-context` scope** as above. `seon.agent/*id*`
   stays a plain dynvar — only `*tx-context*` (which has to survive
   awaits) uses the ALS primitive.
3. **Eval** the parsed form in the agent's current ns. On success
   capture `:ok? true` + raw result. On failure (compile / runtime
   / timeout / unbound-symbol) capture `:ok? false` + the flattened
   error map (`:seon.error/data`).
4. **Capture `:seon.eval/ns`** as the ending ns returned by
   `cljs.js/eval-str`. If it differs from `:seon.agent/current-ns`,
   the agent-entity upsert is part of the same transact below.
5. **Compute `:seon.eval/duration-ms`** = `(- (js/Date.now) start)`.
6. **Render the result for display.**

   ```clojure
   (let [full-edn (pr-str raw-result)
         display  (seon.agent/truncate-edn full-edn)]
     {:seon.eval/result-edn display})

   ```
   The full untruncated EDN does NOT get persisted in v1 (no blob
   layer). The raw value lives in globalThis via
   `(seon.eval/stash-result-raw! eval-id raw-result)`, reachable as
   `(result <eval-id>)` within the session.
7. **Detect-and-tee program-graph entities.** Inspect the parsed
   form head via rewrite-clj. If it's `defn` / `schema/register!`
   / `(ns …)`, build the matching `:seon.fn` / `:seon.schema` /
   `:seon.ns` entity map (see §2.2 for the detection logic). The
   tee map gets merged with the eval entity's tx-data so they
   share the tx and the `:seon.db/eval-id` tx-meta. `(deftest …)`
   forms are NOT tee'd in v1 — the test entity defers to v2.
8. **One transact per form.** The eval entity, the program-graph
   entity (if any), the agent-entity ns upsert (if changed), AND
   the append onto the current turn's `:seon.turn/evals` vector all
   go in a single `d/transact!` call. Tx-meta carries the causality
   bundle (auto). The eval entity IS the tx.
9. **Independent transacts per form.** A failure on form 5 doesn't
   roll back forms 1–4. Tx-context unbinds when the per-form block
   exits.

After every entry is processed, the harness re-renders for the
next turn (§5.3).

### 4.3 Undeclared-var surfacing

`seon.eval/raw-eval` installs a
`cljs.analyzer/*cljs-warning-handlers*` binding that throws on
`:undeclared-var` / `:undeclared-ns` / `:undeclared-ns-form`. Bare
prose like `Let me read` would otherwise silently tokenize into
`nil`-valued evals; this makes it a loud `:ok? false`.

### 4.4 Partial-success semantics

If the agent sends 10 forms and 9 succeed, the DB keeps 9 successes.
Read failures and eval failures both land as `:seon.eval` entries
with `:ok? false` and a structured `:error` payload. No rollback
machinery anywhere.

## 5. Rendering

### 5.1 Section entities + composer

A section is an entity in `:seon.agent/ctx` (component, cardinality-many).
Presence of these attrs makes something a section:

```clojure
{:seon.ctx/name      :current-ns
 :seon.ctx/priority  30
 :seon.ctx/fn        'seon.agent/current-ns-section}

```

The `:seon.ctx/fn` slot holds a **fully-qualified symbol**. At
render time the composer resolves it via
`seon.agent/resolve-symbol` (globalThis walker + late-bound
compile-state) and calls the function with the render input map.

**Contract:**

- **Return value is always a string.** Empty string = section
  omitted (no double newlines).
- **The function decides its own internal structure.** Multiple DB
  queries, sort/group, branch on input — anything.
- **Symbol misses fall through to pretty-print.** If a slot points
  at a symbol that doesn't resolve, the composer renders the section
  entity itself via `pretty-ai`. The render never crashes.

### 5.2 The six default sections

V1 ships six default sections, all in `seon.agent`. Each has a
**smart default** for how much it shows — listed in the table so
the agent knows what to expect. Override via call-time arg
(`(seon.agent/messages {:seon.agent/n 10})`) or via entity-data on
the section (`:seon.agent/n 10` on the ctx entity).

| Name | Priority | Symbol | Default | Purpose |
|---|---|---|---|---|
| `:system` | 10 | `'seon.agent/system-section` | fixed | Who-am-I, what's-now, discovery cheat-sheet |
| `:messages` | 20 | `'seon.agent/messages-section` | last 50 messages | Recent user/assistant conversation |
| `:current-ns` | 30 | `'seon.agent/current-ns-section` | full source of every entity in the current ns | Code in the agent's current ns (substrate + agent-written) |
| `:warnings` | 40 | `'seon.agent/warnings-section` | every registered predicate's output | Active warnings (v1 ships only the `slow-eval` predicate) |
| `:recent-evals` | 50 | `'seon.agent/recent-evals-section` | last 20 evals of current session | REPL scrollback |
| `:prompt` | 99 | `'seon.agent/prompt-section` | one line | `:current.ns=> ; turn N` — always present |

V1 does NOT ship `related-ns-section` (requires D8 reference-graph
attrs) and ships `warnings-section` with **only one predicate**
(`slow-eval-warning` — works on `:seon.eval/duration-ms` alone).
The `untested-fn-warning` and `failing-test-warning` predicates
need the `:seon.test` entity and ship in v2.

```clojure
;; --- All section fns live in seon.agent. ---
;; Each takes :seon.render/system-input {:seon.db/db db :seon.agent/id id}
;; and returns a string. Empty string omits the section.

(defn system-section
  [{:seon.db/keys [db] :seon.agent/keys [id]}]
  (let [agent (d/pull db '[:seon.agent/id :seon.agent/current-ns] [:seon.agent/id id])
        ns    (or (:seon.agent/current-ns agent) (seon.agent/home-ns id))
        now   (.toISOString (js/Date.))]
    (str "<system agent=\"" id "\" ns=\"" ns "\">\n"
         "  Now: " now "  (pod tz: " (host-timezone) ")\n"
         "\n"
         "  Walk your own state:\n"
         "    (seon.agent/root-pull)       ; you + sessions + turns + messages + evals + ctx\n"
         "    (seon.agent/messages)        ; current session's messages — default {:seon.agent/n 50}\n"
         "    (seon.agent/evals)           ; current session's evals — default {:seon.agent/n 20}\n"
         "    (seon.agent/current-turn)    ; this turn's entity\n"
         "    (result <eval-id>)           ; full live result of a prior eval (this session)\n"
         "\n"
         "  See your code in the current ns:\n"
         "    (d/pull db '[:seon.ns/source\n"
         "                 {:seon.fn/_ns [*] :seon.schema/_ns [*]}]\n"
         "                [:seon.ns/name (seon.agent/current-ns)])\n"
         "\n"
         "  Tune your context:\n"
         "    (seon.agent/ctx)             ; your section layout\n"
         "    (seon.agent/update-ctx! f)   ; reshape (swap fn, change priority, etc.)\n"
         "    (seon.agent/reset-ctx!)      ; restore substrate defaults\n"
         "</system>")))

(defn messages-section
  "Last N messages from the current session. Defaults to {:seon.agent/n 50}.
   Override via call arg or the ctx entity's :seon.agent/n attr."
  [{:seon.db/keys [db] :seon.agent/keys [id ctx-entity]}]
  (let [n (or (:seon.agent/n ctx-entity) 50)]
    (if-let [msgs (seq (seon.agent/messages {:seon.agent/n n :seon.agent/id id}))]
      (str "<messages>\n"
           (str/join "\n" (map format-message-row msgs))
           "\n</messages>")
      "")))

(defn current-ns-section
  "Every entity owned by the current ns. ONE pull via reverse-ref
   subpatterns on the program-graph entities. Substrate-defined and
   agent-written entities both appear here."
  [{:seon.db/keys [db] :seon.agent/keys [id]}]
  (let [agent (d/pull db '[:seon.agent/current-ns] [:seon.agent/id id])
        ns    (or (:seon.agent/current-ns agent) (seon.agent/home-ns id))
        owned (d/pull db
                '[:seon.ns/source
                  {:seon.schema/_ns [:seon.schema/source]
                   :seon.fn/_ns     [:seon.fn/source]}]
                [:seon.ns/name ns])
        parts (concat
                (when-let [src (:seon.ns/source owned)] [src])
                (map :seon.schema/source (:seon.schema/_ns owned))
                (map :seon.fn/source     (:seon.fn/_ns owned)))]
    (if (seq parts)
      (str "<current-namespace name=\"" ns "\">\n"
           (str/join "\n\n" parts)
           "\n</current-namespace>")
      "")))

(defn warnings-section
  "Run every registered warning predicate. Each returns nil or a seq
   of {:seon.warning/severity :seon.warning/text} maps. Sort by
   severity descending (:error first)."
  [input]
  (let [preds (registered-warning-predicates)
        ws    (->> (for [p preds, w (p input) :when w] w)
                   (sort-by (fn [{sev :seon.warning/severity}]
                              ({:error 0 :warn 1 :info 2} sev 3))))]
    (if (seq ws)
      (str "<warnings>\n"
           (str/join "\n" (map :seon.warning/text ws))
           "\n</warnings>")
      "")))

;; V1's one default warning predicate. Works on :seon.eval/duration-ms
;; alone — no test entity, no program-graph traversal needed.
;; Agent registers more via (seon.agent/register-warning! 'my.ns/my-pred).
(def slow-eval-threshold-ms 500)

(defn slow-eval-warning
  [_input]
  (for [e (seon.agent/evals {:seon.agent/n 20})
        :when (> (or (:seon.eval/duration-ms e) 0) slow-eval-threshold-ms)]
    {:seon.warning/severity :info
     :seon.warning/text
     (str "slow eval " (:seon.eval/id e)
          " took " (:seon.eval/duration-ms e) "ms")}))

(defn recent-evals-section
  "Last N evals in the current session (default {:seon.agent/n 20}), oldest-first."
  [{:seon.agent/keys [id ctx-entity]}]
  (let [n     (or (:seon.agent/n ctx-entity) 20)
        evals (seon.agent/evals {:seon.agent/n n :seon.agent/id id})]
    (if (seq evals)
      (str "<recent-evals>\n"
           (str/join "\n\n" (map format-eval-row evals))
           "\n</recent-evals>")
      "")))

(defn prompt-section
  "Trailing `:current.ns=> ; turn N` line. Always present."
  [{:seon.db/keys [db] :seon.agent/keys [id]}]
  (let [agent (d/pull db
                '[:seon.agent/current-ns
                  {:seon.agent/sessions [:seon.session/turn-count]}]
                [:seon.agent/id id])
        ns    (or (:seon.agent/current-ns agent) (seon.agent/home-ns id))
        turn  (-> agent :seon.agent/sessions last :seon.session/turn-count (or 0))]
    (str ns "=>  ; turn " turn)))

```

`extract-sym` peeks the form head (`defn`, `schema/register!`,
`deftest`, `def`) and returns the symbol being defined; on
anything else, returns the form text verbatim so the dedupe map
keeps it as a distinct entry. ~15 lines, rewrite-clj-based, no
analyzer state needed.

**XML wrappers** around structural sections give LLMs clean
start/end markers.

### 5.3 The composer

The composer is the function pointed at by the agent's
`:seon.render/ai` slot (default `seon.agent/ctx`). It pulls the
agent's `:seon.agent/ctx` (components inline, so no second query),
sorts by priority, resolves each `:seon.ctx/fn` symbol, calls it,
joins the strings — and **writes the rendered output to
`:seon.turn/prompt-text`** on the current turn entity.

```clojure
(defn assemble-ctx
  {:malli/schema [:=> [:cat :seon.render/system-input] :seon.render/ai-response]}
  [{:seon.db/keys [db] :seon.agent/keys [id]}]
  (let [agent    (d/pull db
                   '[:seon.agent/id
                     {:seon.agent/ctx [:seon.ctx/name :seon.ctx/priority :seon.ctx/fn]}]
                   [:seon.agent/id id])
        sections (sort-by :seon.ctx/priority (:seon.agent/ctx agent))
        ctx-in   {:seon.db/db db :seon.agent/id id :seon.agent/ctx-entity nil}
        text     (->> sections
                      (map (fn [section]
                             (let [f (seon.agent/resolve-symbol (:seon.ctx/fn section))]
                               (if f
                                 (f (assoc ctx-in :seon.agent/ctx-entity section))
                                 (str (pretty-ai section))))))
                      (remove str/blank?)
                      (str/join "\n\n"))]
    {:seon.render/text   text
     :seon.turn/prompt-text text}))

```

The harness attaches `:seon.turn/prompt-text` to the open turn (§6.1).

Each section fn receives the section entity as
`:seon.agent/ctx-entity` in the input map, so it can read any
agent-attached config keys (e.g. `:seon.agent/n` for sizing).

**V2 will replace `:seon.turn/prompt-text` with `:seon.turn/prompt-blob`** —
see v2.md §"Blob storage" for the migration story and content-
addressed storage design.

### 5.4 Customization

Two levers:

1. **Change what a section returns.** Write a new section fn in the
   agent's home ns, transact a different `:seon.ctx/fn` symbol on
   the section entity. Or change `:seon.ctx/priority`. Or add a
   new ctx entity to `:seon.agent/ctx`.
2. **Override the composer.** Rare; only when the agent wants a
   completely different top-level layout. Transact a different
   `:seon.render/ai` symbol on the agent entity.

Replacing a default section requires retract-then-add (cardinality-
many ref attrs accumulate on upsert):

```clojure
(let [old-id (-> (d/pull @!conn
                   '[{:seon.agent/ctx [:db/id :seon.ctx/name]}]
                   [:seon.agent/id (seon.agent/id)])
                 :seon.agent/ctx
                 (->> (filter #(= :recent-evals (:seon.ctx/name %))))
                 first :db/id)]
  (seon.db/transact!
    {:seon.db/tx-data
     [[:db/retractEntity old-id]
      {:seon.agent/id (seon.agent/id)
       :seon.agent/ctx
       [{:seon.ctx/name :recent-evals
         :seon.ctx/priority 50
         :seon.ctx/fn (symbol (str "seon.agent." (seon.agent/id))
                              "compact-recent-evals")}]}]}))

```

Because `:seon.agent/ctx` is `:db/isComponent true`, the retracted
ctx entity is cascade-retracted.

#### What v1 does NOT extend — the HTML surface

V1's section composer is the **AI surface only**. Each `:seon.ctx`
entity carries one `:seon.ctx/fn` symbol; the fn returns
`{:seon.render/text "..."}`; the composer joins those strings into
`:seon.turn/prompt-text` for the LLM.

The user-visible UI in v1 stays on the same V0 footing the broadcast
pipeline already uses: **one whole-tile `:seon.render/html` symbol
per agent entity** (`seon.web.broadcast` resolves it on every DB tx,
emits a `datastar-patch-elements` SSE event to all open
connections). The agent customizes their UI by transacting a
different symbol into that slot — same per-agent ownership rule as
the AI surface, same dispatch mechanism (`html-render`), but no
per-section composability yet.

This is deliberate. V1's job is "agent runs against deepseek and
survives restart"; the AI surface earns the per-section composer
because the LLM prompt is the load-bearing artifact. The HTML
mirror waits until v2 — and crucially **does not add a new
`:seon.ctx/*` slot**. V2 extends the existing section fn's return
map with an additional optional `:seon.render/hiccup` key alongside
`:seon.render/text`. One section, one fn, multiple output surfaces.
See v2.md "Per-section HTML composer."

**Day-one debug view.** A two-line use of the existing slot gives
you a verbatim mirror of what the LLM is seeing right now:

```clojure
;; In seon.render.default (or any agent home ns)
(defn raw-prompt-view
  {:malli/schema [:=> [:cat :seon.render/system-input]
                  :seon.render/html-response]}
  [{:seon.db/keys [db] :seon.agent/keys [id]}]
  (let [turn (latest-open-turn db id)]
    {:seon.render/hiccup
     [:div {:id (str "agent-" id)}
      [:pre {:class "text-xs"} (:seon.turn/prompt-text turn)]]}))

;; Then transact:
(seon.db/transact!
  {:seon.db/tx-data
   [{:seon.agent/id (seon.agent/id)
     :seon.render/html 'seon.render.default/raw-prompt-view}]})
```

The broadcast listener picks it up on the next tx. Every browser
already connected to the pod's loopback (and every Tauri webview
pointed there) sees the same view simultaneously — the multi-view
fan-out is already wired.

### 5.5 Recovery — `reset-ctx!`

If the agent borks their ctx (a custom section fn throws, returns
non-string, returns nothing useful), reset is one verb:

```clojure
(seon.agent/reset-ctx!)
;; equivalent to:
(let [agent-id (seon.agent/id)
      defaults (seon.agent/substrate-default-ctx)]   ; the 5 default ctx maps
  (seon.db/transact!
    {:seon.db/tx-data
     [[:db/retract [:seon.agent/id agent-id] :seon.agent/ctx]
      {:seon.agent/id agent-id :seon.agent/ctx defaults}]}))

```

The retract first kills the existing ctx entities (component
cascade); the add re-creates the substrate defaults. One verb, one
mechanism.

## 6. The agent loop

V1 ships two loop entry points in `seon.agent`. The agent never
needs to call them — the runtime calls them — but they're public so
tests and the REPL can invoke them.

### 6.1 `run-turn!`

One turn = ensure session → render prompt (sync) → open turn (with
prompt-text attached) → ask LLM → eval-batch → close turn (with
assistant message folded in). The whole pipeline runs inside one
outer `seon.db/with-tx-context` scope so every transact auto-tags
with the causality bundle — no manual `:seon.db/opts {:tx-meta …}`
plumbing at any call site.

Decomposition: three `defn ^:async` helpers + one bracketing
combinator + a thin orchestrator.

- **`ensure-session!`** — return the agent's current session,
  opening one if none exists. Idempotent within a pod run.
- **`render-prompt`** — sync. Resolve the agent's `:seon.render/ai`
  symbol (default `'seon.agent/assemble-ctx`) and call it. Returns
  the prompt string.
- **`with-turn!`** — opens the turn with prompt-text attached and
  flips agent state to `:running`; awaits a body thunk; on success
  closes the turn with `:status :done` (folding in any
  `:seon.turn/messages` the body returned) and flips state to
  `:idle`; on throw, flips to `:status :error` and re-throws. Net:
  one open-tx + one close-tx, regardless of how many writes the
  body needs.
- **`ask-and-eval!`** — body of `with-turn!`: LLM call → parse →
  `eval-batch!`. Returns
  `{:seon.turn/messages [<assistant>] :seon.agent/eval-count n-ok}`.
  `with-turn!` reads both keys: messages fold into the close-tx,
  eval-count flows to the caller for the loop's stop policy.

```clojure
(defn ^:async run-turn!
  "v1.md §6.1 — one full turn end-to-end. Map-in / map-out."
  [{:seon.agent/keys [id llm-fn compile-state]}]
  (let [session    (await (ensure-session! id))
        session-id (:seon.session/id session)
        turn-id    (new-id!)
        prompt     (render-prompt id)]
    (try
      (let [result (await
                     (db/with-tx-context
                       {:seon.db/agent-id   id
                        :seon.db/session-id session-id
                        :seon.db/turn-id    turn-id
                        :seon.db/origin     :system}
                       (fn []
                         (with-turn!
                           {:seon.agent/id              id
                            :seon.session/id-of-session session-id
                            :seon.turn/id-of-turn       turn-id
                            :seon.turn/prompt-text      prompt}
                           #(ask-and-eval! {:seon.agent/id            id
                                            :seon.agent/llm-fn        llm-fn
                                            :seon.agent/compile-state compile-state
                                            :seon.turn/id-of-turn     turn-id
                                            :seon.turn/prompt-text    prompt})))))
            n-ok (or (:seon.agent/eval-count result) 0)]
        (assoc (db/pull {:seon.db/pull-pattern
                         '[* {:seon.turn/messages [*]
                              :seon.turn/evals    [*]}]
                         :seon.db/ref [:seon.turn/id turn-id]})
               :seon.agent/eval-count n-ok))
      (catch :default e
        ;; Catastrophic path (LLM throw, eval-engine crash). Restore
        ;; :idle so the loop isn't wedged. `with-turn!` already
        ;; flipped the turn to :status :error before re-throwing.
        (try
          (await (db/transact! {:seon.db/tx-data
                                [{:seon.agent/id id
                                  :seon.agent/state :idle}]}))
          (catch :default _ nil))
        {:seon.turn/status :error
         :seon.error/data (str e)}))))
```

**Why two transacts per turn, not four.** v1.md drafts of `run-turn!`
sketched four explicit `db/transact!` calls (open turn, persist
prompt-text, record assistant message, close turn) plus the per-form
txs inside `eval-batch!`. The combinator collapses two pairs:

- **Render-before-open + fold prompt-text into open-tx.** The
  composer is sync; it reads agent + session + previous turns, not
  the new turn. Compose first, then open with `:seon.turn/prompt-text`
  already attached.
- **Fold assistant message into close-tx.** `ask-and-eval!` returns
  `{:seon.turn/messages [<assistant>]}`; `with-turn!`'s close-tx
  upserts the turn with `:status :done` AND those messages.

The eval-batch's N per-form txs remain — each form is its own
transaction so partial-failure preserves earlier successes (v1.md
§4.4).

**No manual `:tx-meta`.** Every transact inside the `with-tx-context`
scope picks up `agent-id` + `session-id` + `turn-id` + `origin :system`
automatically via `seon.db/transact!`'s `merge-tx-context-into-opts`.
Eval-batch! opens an inner `with-tx-context` scope that adds
`eval-id` per form; ALS merge means per-form txs carry the full
bundle.

**Return shape.** One pull with `[* {:seon.turn/messages [*]
:seon.turn/evals [*]}]` returns the turn entity with its component
children inlined — satisfies v1.md §9 acceptance criterion 11 ("one
pull on `:seon.turn/id` returns prompt-text + messages + evals").
`:seon.agent/eval-count` is the eval-batch's `:seon.eval/n-ok` count.

```clojure
;; Helper signatures (full bodies in src/seon/agent.cljs):

(defn ^:async ensure-session!
  [agent-id]
  (or (current-session agent-id)
      (await (start-session! agent-id))))

(defn render-prompt
  [agent-id]
  (let [ent   (db/entity {:seon.db/ref [:seon.agent/id agent-id]})
        sym   (:seon.render/ai ent 'seon.agent/assemble-ctx)
        input (ai-render-input sym @db/*conn* agent-id ent)]
    (or (:seon.render/text (render/ai-render sym input)) "")))

(defn ^:async with-turn!
  [{:seon.agent/keys [id]
    :seon.session/keys [id-of-session]
    :seon.turn/keys [id-of-turn prompt-text]}
   body-fn]
  ;; open-tx: turn appears as :status :running with prompt-text attached
  ;; await (body-fn) -> map containing :seon.turn/messages
  ;; close-tx: :status :done, fold in :seon.turn/messages
  ;; on throw: close-tx with :status :error, re-throw
  ...)

(defn ^:async ask-and-eval!
  [{:seon.agent/keys [id llm-fn compile-state]
    :seon.turn/keys  [id-of-turn prompt-text]}]
  ;; await llm-fn, parse-forms, await eval-batch!, build return map
  ...)
```

### 6.2 `run-agentic-loop!`

Multi-turn driver. Calls `run-turn!` repeatedly until a stop policy
fires. Default policies (configurable):

- Stop when the last turn's assistant message contained zero forms.
- Stop when `:seon.session/turns-since-user` exceeds a cap (default
  20).
- Stop when a `:user`-role message lands on the session.

### 6.3 Playback — "show me turn N"

Because the harness wrote `:seon.turn/prompt-text`, the assistant
`:seon.message`, and every `:seon.eval` as components of the same
turn entity, **one pull reconstructs everything**:

```clojure
(d/pull db
  '[:seon.turn/id :seon.turn/index :seon.turn/at :seon.turn/status
    :seon.turn/prompt-text
    {:seon.turn/messages [:seon.message/role :seon.message/content :seon.message/at]
     :seon.turn/evals    [*]}]
  [:seon.turn/id "T1aaaaa1111"])

```

The prompt text is right there as a string. Walk `:seon.turn/evals`
for everything the LLM said in response (parsed) and the results
each form produced.

**V2 will return `:seon.turn/prompt-blob` instead of inline
`:prompt-text`** — see v2.md §"Blob storage" for the migration.

## 7. Boot

```text
boot:
  assert-preconditions!      ; :keep-history? + tx-meta attrs registered
  init-bootstrap!            ; cljs.core analyzer-cache load
  if database-empty?         ; first boot only
    bootstrap-phase!         ; transact substrate :seon.ns / :seon.fn / :seon.schema from bootstrap.edn
  resume-phase!              ; walk program-graph entities + re-eval :source
  start-session!             ; create :seon.session for this pod run
  render-initial-context!    ; first turn for the agent

```

### 7.1 Preconditions — fail loud, fail early

Two preconditions MUST hold before any agent-eval happens.

**1. `:keep-history? true` on the agent conn.** Tx-meta datoms only
persist when history is on. Without it, the causality-bundle
mechanic silently degrades.

```clojure
(when-not (:keep-history? (d/get-config @!conn))
  (throw (ex-info "Agent conn opened with :keep-history? false."
                  {:kind :seon.boot/precondition-failed})))

```

**2. tx-meta schema attrs are registered.** Datahike rejects
unregistered keys at write time. The bootstrap must register
`:seon.db/agent-id`, `:seon.db/session-id`, `:seon.db/turn-id`,
`:seon.db/eval-id`, `:seon.db/origin`, `:seon.db/replay?`, and
`:seon.db/resume-marker?` BEFORE the first tx-meta-carrying tx
fires.

### 7.2 Analyzer-cache load

Before any agent form can be evaluated, the bootstrap-CLJS
compile-state needs `:cljs.analyzer/namespaces 'cljs.core` populated
with cljs.core's defs. `seon.eval/init-bootstrap!` walks
`out/bootstrap/ana/*.transit.json` and loads each via
`cljs.js/load-analysis-cache!`. After init,
`(count (:defs (get-in @compile-state [:cljs.analyzer/namespaces 'cljs.core])))`
should return ~980.

`!compile-state` is the single shared atom at `seon.repl/!compile-state`,
version-stamped via `seon.eval/init-version` so hot-reloads of
`seon.eval` rotate the cache. (KI-2/5 fixed 2026-05-22.)

### 7.3 Bootstrap phase (runs only when DB is empty)

The substrate seeds the program graph from a build-time artifact:
an ordered vector of entity maps emitted at substrate build time as
`resources/seon/bootstrap.edn`. The bootstrap phase transacts this
file on first boot so substrate fns/schemas/nses are discoverable
from the program graph before the agent has done anything.

```clojure
;; resources/seon/bootstrap.edn (shape; ordered for single-transact)
[{:seon.ns/name :seon.agent
  :seon.ns/source "(ns seon.agent (:require [seon.db :as db] [seon.schema :as schema]))"}
 ...
 {:seon.schema/key :seon.render/ai
  :seon.schema/ns  [:seon.ns/name :seon.render]
  :seon.schema/source "(schema/register! ::ai :string)"}
 ...
 {:seon.fn/sym    "seon.agent/system-section"
  :seon.fn/ns     [:seon.ns/name :seon.agent]
  :seon.fn/source "(defn system-section ...)"}
 ...]
```

The bootstrap is a single `(d/transact! conn bootstrap.edn-content
:tx-meta {:seon.db/origin :system})`. Datahike resolves intra-tx
lookup refs (`:seon.fn/ns [:seon.ns/name :seon.agent]`) inside the
transaction, so dependency order in the vector is enough — no
multi-pass logic.

**Emission rig** (D10): a build-time script
(`bin/emit-bootstrap`) reads the substrate's source files,
parses each `(ns …)` / `(defn …)` / `(schema/register! …)` form
with rewrite-clj, and writes the ordered entity vector. ~80 lines
of Clojure. Lives in `bin/` so it can be invoked from `clj -M`
during substrate build.

**Tests are NOT in bootstrap.edn** — no `:seon.test` entity in v1.
When v2 adds the test entity, the emitter extends to include
`(deftest …)` forms.

After bootstrap the database is the system. Subsequent boots skip
this phase (the database isn't empty).

### 7.4 Resume phase — re-eval program-graph entities in tx order

> **⚠️ Design is queued behind a research pass (2026-05-23).** The
> sketch below is the v1 spec, but the Platform agent paused before
> implementing it — the "tx-id is topological by construction"
> argument is plausible but underverified for our specific datahike
> config (`:keep-history? true`), CLJS bootstrap analyzer state on
> re-eval, cross-namespace dependency ordering, and schema-registry
> timing edge cases. **Do NOT implement from this sketch alone.**
>
> Open questions + dispatch instructions:
> [`research/resume-design-questions-2026-05-23.md`](research/resume-design-questions-2026-05-23.md).
> Findings (when written) will land at
> `research/resume-findings-<date>.md` and supersede this section's
> sketch.

Restore runtime state by walking `:seon.ns` / `:seon.fn` /
`:seon.schema` entities sorted by tx-id and re-evaling each
`:source`.

**No dep DAG, no analyzer walk.** Datahike tx-ids are strictly
monotonic, and an entity can only reference another via lookup-ref
if the referenced entity already exists at write time. So creation
order IS a valid topological order by construction.

Replay runs inside `(seon.db/with-tx-context {:seon.db/origin :replay
:seon.db/replay? true} …)` so every datom written during resume is
distinguishable from agent-action datoms.

```clojure
(defn resume!
  []
  (seon.db/with-tx-context
    {:seon.db/origin   :replay
     :seon.db/replay?  true}
    (fn []
      ;; Pull each entity kind in tx order, then walk all together.
      (let [entities (d/q '[:find ?e ?source ?tx
                            :where (or [?e :seon.ns/source ?source ?tx]
                                       [?e :seon.fn/source ?source ?tx]
                                       [?e :seon.schema/source ?source ?tx])]
                          @!conn)]
        (doseq [[_eid source _tx] (sort-by #(nth % 2) entities)]
          (seon.eval/raw-eval source))))))
```

If an eval throws during replay, record a new `:seon.eval` entry
with `:ok? false` and `:replay? true` (visible in the warnings-tile
next-turn, but doesn't block resume). The original program-graph
entity stays unchanged; the agent decides whether to fix or
`forget!` (v2) it.

**Last-write-wins.** Identity-attr upserts mean the latest
`:seon.fn/source` value is the current one — resume re-evals the
latest version. Earlier versions remain in history; observer can
walk them via `d/as-of`.

**Resume latency** is O(distinct program entities), not O(all
successful evals). After 1000 evals defining 100 fns + 20 schemas,
resume processes ~120 entities (1–2 seconds) instead of ~1000
(5–15 seconds).

Eval log itself is NOT replayed — only program-graph entities.
Scratch evals (`(+ 1 2)`) don't re-run on boot.

### 7.5 Start-session

After resume, create the `:seon.session` entity for this pod run
and append to `:seon.agent/sessions`:

```clojure
(seon.db/transact!
  {:seon.db/tx-data
   [{:seon.agent/id <agent-id>
     :seon.agent/sessions [{:seon.session/id (seon.agent/new-id!)
                            :seon.session/at (js/Date.)
                            :seon.session/turn-count 0
                            :seon.session/turns-since-user 0}]}]
   :seon.db/opts {:tx-meta {:seon.db/origin :system
                            :seon.db/resume-marker? true
                            :seon.db/agent-id <agent-id>}}})

```

## 8. Namespace map

Six namespaces. (Earlier drafts split ID generation into `seon.id`;
collapsed into `seon.agent` 2026-05-22 — a five-line generator + a
single registered schema don't earn their own namespace.)

|---|---|

## 9. MVP scope

### Acceptance criteria

A fresh agent session can:

1. See a default-rendered context with the 5 sections present
   (empty sections suppressed), including current pod-time + the
   discovery cheat-sheet in the system tile.
2. Eval a multi-form batch including a `schema/register!`, `defn`,
   and `deftest`. See each form's `:duration-ms` rendered next to
   its eval-id. **No program-graph entities are created** — the
   sources persist on `:seon.eval/source` only.
3. Submit a response with `;;` multi-line markdown between forms;
   see the comments captured as `:seon.eval/narration`. Trailing
   `;;` lands as a thinking-only eval entry.
4. Eval a bare symbol that resolves; see its value. Eval a bare
   symbol that doesn't resolve; see the unbound-symbol error in the
   eval log.
5. **Partial success:** send 10 forms where one fails; see 9
   successes persisted and 1 error reported.
6. `(in-ns 'seon.foo)` mid-batch; subsequent forms land in
   `seon.foo`; `:seon.agent/current-ns` updated; next-turn
   `current-ns-section` shows only forms in `seon.foo`.
7. Rewrite the `recent-evals-section` fn to a compact one-line
   format; see it applied on the next turn.
8. Break a section function (typo in fn body); see `pretty-ai`
   engage for that section.
9. `(seon.agent/reset-ctx!)`; see substrate defaults restored.
10. Restart the pod; see all successful evals replayed in tx order;
    see `seon.trading/analyze` (or whatever) a live var again; see
    prior sessions retained in `:seon.agent/sessions`; see a new
    `:seon.session` opened for the current run.
11. **Playback:** from an observer (not the agent), `(d/pull db '[*
    {:seon.turn/messages [*] :seon.turn/evals [*]}] [:seon.turn/id
    "T..."])` returns the literal prompt-text the LLM saw + the
    assistant message + every eval the turn produced. One pull.

**Cut from acceptance criteria (deferred):**

- Targeted test auto-run on defn change (criterion #8 in the
  original list). Defers with the test entity.
- "Forget a function and see dependents flagged" (criterion #10).
  Defers with `forget!`.
- Full literal-prompt playback via blob content-addressing (v1
  achieves the equivalent via inline `:seon.turn/prompt-text`).

### Out of scope (defer to v2 or v3)

See [v2.md](v2.md) and [v3.md](v3.md). Each deferred feature has
its full design preserved there — v1 is a starting line, not a
ceiling.

## 10. Worked example — one turn end-to-end

Agent boots fresh (empty DB). After preconditions + analyzer-cache
load + start-session, turn 0 begins. The rendered context the LLM
sees:

```text
<system agent="AbCdEfGh1234" ns=":seon.agent.AbCdEfGh1234">
  Now: 2026-05-22T14:35:00.000Z  (pod tz: America/Los_Angeles)
  [discovery cheat-sheet …]
</system>

<recent-evals>
</recent-evals>

:seon.agent.AbCdEfGh1234=>  ; turn 0

```

(Messages, current-ns, recent-evals tiles are all empty.)

LLM replies:

```clojure
;; Let me set up a trading namespace
(ns seon.trading
  (:require [seon.db :as db]))

(defn analyze
  [{:keys [ticker]}]
  {:signal :hold})

(analyze {:ticker "AAPL"})

```

`eval-batch!` parses and per-form-loops. Each form's eval runs
inside a `with-tx-context` scope carrying
`agent-id, session-id, turn-id, eval-id`, all auto-tagging txs. Three `:seon.eval` entries are written, and
detect-and-tee writes two program-graph entities in the matching
txs:

- `(ns seon.trading ...)` — `:seon.eval` (`:ok? true`,
  `:ns :seon.trading`) + `:seon.ns` (`:seon.ns/name :seon.trading`,
  `:seon.ns/source "(ns seon.trading ...)"`). Both share the tx
  (same `:seon.db/eval-id`).
- `(defn analyze ...)` — `:seon.eval` + `:seon.fn` (`:sym
  "seon.trading/analyze"`, `:ns [:seon.ns/name :seon.trading]`,
  `:source "(defn analyze ...)"`). Same tx.
- `(analyze {:ticker "AAPL"})` — `:seon.eval` only (`:result-edn
  "{:signal :hold}"`). No program-graph entity (it's an
  expression, not a definition).

After eval-batch, `:seon.agent/current-ns` is upserted to
`:seon.trading`. Composer re-renders for turn 1:

```text
<system …>…</system>

<current-namespace name=":seon.trading">
(ns seon.trading (:require [seon.db :as db]))

(defn analyze
  [{:keys [ticker]}]
  {:signal :hold})
</current-namespace>

<recent-evals>
;; Let me set up a trading namespace
> (ns seon.trading (:require [seon.db :as db]))
nil                                    ; # K9p2x4nB7q  2ms

> (defn analyze [{:keys [ticker]}] {:signal :hold})
#'seon.trading/analyze                 ; # L4m9p1xA3v  1ms

> (analyze {:ticker "AAPL"})
{:signal :hold}                        ; # M2q7w0vB9x  0ms
</recent-evals>

:seon.trading=>  ; turn 1

```

The turn-1 prompt-text is written inline on the turn entity. The
eval entities from turn 0 are component'd off `:seon.turn/evals`
on the turn 0 entity. Pulling the turn 0 entity from an observer
process reconstructs the entire turn — prompt + assistant message +
all 4 evals + each eval's tx-meta bundle.

**Pod restart:** resume-phase walks the program-graph entities
sorted by tx-id (`:seon.ns/name :seon.trading` then
`:seon.fn/sym "seon.trading/analyze"`), re-evals each `:source`.
After resume, `seon.trading` is loaded and
`seon.trading/analyze` is a live var again. The expression-only
eval `(analyze {:ticker "AAPL"})` is NOT replayed (no program-graph
entity → not walked). A new session opens. The agent's next turn
sees turn 0 in `:seon.agent/sessions` (prior session's turns
retained, with prompt-text intact for playback) and
`current-ns-section` shows the same `:seon.trading` contents via
one reverse-ref pull.

## 11. Implementation protocol — REPL-verify before committing

V1's design has three assumptions that are load-bearing but
unverified against the actual runtime. Before writing the
production code for any feature that depends on them, **build the
smallest REPL probe that exercises the assumption and confirm it
holds**. If it doesn't, surface the mismatch to Sean before
inventing a workaround — the spec may need to change.

These are not optional; getting any one wrong silently breaks
playback or persistence.

### Risk 1: `*tx-context*` propagation through Promise chains — RESOLVED 2026-05-22

> **Status: resolved.** 14 REPL probes ran on the V0 pod. Findings:
> CLJS `binding` macroexpands to `(set! var :new)` + `(try …
> (finally (set! var orig)))` against a single global slot — works
> for single-binder cases but silently clobbers across overlapping
> awaits when two `^:async` fns each bind the same var. v1 supports
> concurrent agents, so the dynvar-only approach is unsafe.
> **Mechanism switched to Node `AsyncLocalStorage`** (probe 14
> verified fiber-local isolation under the same adversarial
> interleaving that broke the dynvar). Full transcript and
> reproducers in
> [[research/impl-finding-tx-context-promise-2026-05-22]].
> Phase 2.5 ships `seon.db/with-tx-context` + `current-tx-context`
> as the wrapper. v1.md §2.3 / §4.2 / §7.4 updated to match.
> Original risk text retained below for archaeology.

**The assumption (original):** `seon.eval/eval-batch!` binds
`seon.db/*tx-context*` at the top of the per-form loop;
`seon.db/transact!` reads it and merges into `:tx-meta`. The
expectation is that every transact under that binding inherits the
causality bundle, including transacts inside `.then` callbacks of
Promises the form returns.

**Why it might not hold:** CLJS dynvar bindings are fiber-local in
Node — they propagate naturally through synchronous call chains and
through `await` (with `^:async/await` codegen) but NOT
automatically across `(.then promise callback)` boundaries. A form
like `(.then (some-async-call) (fn [...] (seon.db/transact! ...)))`
might see `*tx-context*` as unbound inside the callback. Every tx
written by that callback would lose the causality bundle —
playback would silently lose those datoms' lineage.

**REPL probe (15 minutes):**

```clojure
;; In the V0 pod
(require '[seon.db :as db])
(def ^:dynamic *probe* nil)

(binding [*probe* :outer]
  (-> (js/Promise.resolve)
      (.then (fn [_]
               {:in-callback *probe*
                :outer-saw *probe*}))))
;; If in-callback is :outer, propagation works.
;; If in-callback is nil, propagation is broken — we need
;; explicit-arg threading OR an atom-backed scope token.
```

**If broken:** the per-form loop can't rely on `binding`. Options:
(a) re-bind explicitly inside every callback the agent emits (not
viable — the agent's code is arbitrary), (b) thread the bundle as
an explicit arg through `seon.db/transact!` and skip the dynvar
entirely (changes the API surface), (c) atom-backed scope token
with explicit push/pop in the per-form loop. Pick one with Sean
before implementing.

This is D13 for the WASM boundary; verify on Node first.

### Risk 2: rewrite-clj defn-name extraction across all legal shapes

**The assumption:** `detect-and-tee` (§2.2) extracts the symbol
being defined from a parsed `(defn name ...)` form. The simple
case is trivial.

**Why it might not hold:** Clojure's `defn` accepts several
shapes; the extractor has to handle all of them or land
inconsistent program-graph entries.

```clojure
(defn analyze [x] ...)                              ; canonical
(defn analyze "docstring" [x] ...)                  ; with docstring
(defn analyze {:malli/schema [...]} [x] ...)        ; with attr-map
(defn analyze "docstring" {:malli/schema [...]} [x] ...) ; with both
(defn analyze                                       ; multi-arity
  ([x] ...)
  ([x y] ...))
(defn- internal-helper [x] ...)                     ; defn-
(def analyze (fn [x] ...))                          ; this is NOT a defn — should NOT tee
(defn ^:private analyze [x] ...)                    ; metadata on name
(defn ^{:malli/schema [...]} analyze [x] ...)       ; metadata map on name
```

Same problem for `schema/register!`:

```clojure
(schema/register! ::ticker :string)                 ; canonical
(schema/register! :seon.trading/ticker :string)     ; un-aliased keyword
(let [k ::ticker] (schema/register! k :string))     ; computed key — should NOT tee with constant
(seon.schema/register! ::ticker :string)            ; full ns alias
```

**REPL probe (30 minutes):** write the extractor, build a test
corpus of ~15 forms covering the above shapes, run the extractor
on each, assert the expected (or expected-nil) symbol comes out.
Commit the corpus as `test/seon/eval/detect_tee_test.cljs` before
production use.

**If shapes don't extract cleanly:** the safe default is to skip
teeing (return nil) when the head shape is ambiguous, NOT to
guess. A `defn` we couldn't extract a name from goes through eval
normally; nothing lands in the program graph. The agent gets a
warning ("eval succeeded but program-graph extraction failed for
form X — re-state in canonical shape if you want it in the graph").

### Risk 3: `bootstrap.edn` intra-tx lookup-ref resolution

**The assumption:** `(d/transact! conn [{:seon.fn/sym "..." :seon.fn/ns [:seon.ns/name :seon.agent]} ...])`
resolves the `[:seon.ns/name :seon.agent]` lookup-ref against the
`:seon.ns` entity being transacted in the SAME tx (which appears
earlier in the vector). Datahike's docs say this works; verify
against the version we're actually running.

**Why it might not hold:** intra-tx lookup-ref resolution has
edge cases in some Datomic-flavored stores. If `:seon.ns` entities
must exist BEFORE the transact that references them, the
emitter has to either (a) split bootstrap into two transacts (ns
first, then fn/schema), or (b) use tempids consistently across
the entity vector.

**REPL probe (10 minutes):**

```clojure
(require '[datahike.api :as d])
(def conn (d/create-database {:store {:backend :mem} :keep-history? true}))
(d/transact! conn
  [{:db/ident :seon.ns/name   :db/valueType :db.type/keyword :db/unique :db.unique/identity :db/cardinality :db.cardinality/one}
   {:db/ident :seon.fn/sym    :db/valueType :db.type/string  :db/unique :db.unique/identity :db/cardinality :db.cardinality/one}
   {:db/ident :seon.fn/ns     :db/valueType :db.type/ref     :db/cardinality :db.cardinality/one}])

(d/transact! conn
  [{:seon.ns/name :seon.trading}
   {:seon.fn/sym "seon.trading/analyze"
    :seon.fn/ns [:seon.ns/name :seon.trading]}])
;; If this succeeds and pulling the fn shows :seon.fn/ns resolved
;; to the ns entity, we're good. If it throws "lookup-ref not
;; found," bootstrap.edn needs restructuring.
```

**If broken:** emitter splits into multiple transacts in dependency
order: (1) all `:seon.ns` entities, (2) all `:seon.schema` entities
referencing nses, (3) all `:seon.fn` entities. Trivial change to
the emitter; the spec stays unchanged.

### Other things likely to bite (lower confidence, but worth a probe)

- **`:db/isComponent` cascade depth.** Retracting an agent should
  cascade through 5 levels (agent → sessions → turns →
  messages/evals). Verify the cascade actually traverses that deep
  and doesn't hit an internal limit.
- **`d/listen!` callback ordering vs. tx commit.** V1 doesn't ship
  any listeners (D4 auto-run is v2), but the spec assumes
  `tx-data` in the callback reflects committed state. Confirm
  before v2 wires up the test auto-run hook.
- **`:seon.eval/at` epoch-ms vs `:db/txInstant` inst.** Two
  different timestamp shapes; rendering code must pick the right
  one for the right purpose. Spot-check renderer code.

### Reporting protocol

When a REPL probe reveals a mismatch, write a short note to
`docs/prds/agent-runtime/research/impl-finding-<topic>-<date>.md`
with: the assumption, the probe, the actual result, and the
options for proceeding. Surface to Sean BEFORE writing production
code that depends on the broken assumption.

# M2 findings — self-hosted CLJS eval under wasmtime

What actually shipped (vs. [[wasm-spike-2026-05-20]]'s design plan).
Captured 2026-05-21 while it's fresh. Six landmines and the
workarounds; reproducer command at the end.

## Status

- ✅ Arbitrary CLJS eval works inside wasmtime + wasm-rquickjs.
  `(+ 1 2)`, `(reduce + (range 10))`, `(defn sq [n] (* n n)) (sq 7)`,
  `(ns other) (defn hi [] "hi")` all evaluate correctly via the
  WIT-exported `eval-form` function.
- ✅ `^:async` / `(await ...)` (CLJS 1.12.145 native) survives the
  compile path. `(defn ^:async add [a b] (let [x (await ...) y
  (await ...)] (+ x y)))` resolves to a real Promise that wstd's
  block_on drives to completion. The microtask-queue path the memory
  note `reference_cljs_async_await` called out as load-bearing for
  WASM works.
- ✅ Datahike-cljs loads under wasm-rquickjs (M1 result confirmed
  again here — the eval-smoke bundle includes the full datahike
  dep graph and namespace-load no longer hangs).
- ✅ Bootstrap-CLJS (shadow.cljs.bootstrap.node + cljs.js + the
  generated `out/bootstrap/` analysis cache) runs cleanly inside
  QuickJS via `goog.globalEval(s)` (= `(0,eval)(s)`).

The path from "agent emits CLJS form" to "form runs inside the
WIT-typed pod boundary" is end-to-end functional. M2 is done.

## Landmines and workarounds

### 1. The `:bootstrap` shadow build doesn't ship cljs.js

`shadow-cljs.edn`'s `:bootstrap` build only emits `cljs.core` +
`cljs.core$macros` analysis caches. `cljs.js` (the in-runtime
compiler itself) has to live in the HOST bundle, not the bootstrap
artifacts. We pull it in via `(:require [cljs.js :as cljs])` from
the eval-smoke entry namespace at `src/seon/wasm_eval_smoke.cljs:27`.

Confirmed convention against shadow-cljs's own bootstrap-on-node
example (`/Users/sean/src/shadow-cljs/shadow-cljs.edn:489-507`).

### 2. Shadow-cljs's `:node-script` IIFE hides `goog` / `cljs` / `shadow`

shadow-cljs `:target :node-script` AND `:node-library` both wrap
their release output in an IIFE (or UMD factory). `goog`, `cljs`,
`shadow` end up as closure-locals — invisible to bootstrap-loaded
JS, which `shadow.cljs.bootstrap.node/execute-load!`
(`/Users/sean/src/shadow-cljs/src/main/shadow/cljs/bootstrap/node.cljs:57`)
runs via `goog.globalEval` in **global** scope, where it references
`cljs.core.X` and `goog.provide(...)` by name.

`:compiler-options :output-wrapper false` does NOT fix this — that
flag only controls Closure's own wrapper, not shadow's per-target
wrapper. Confirmed by reading shadow-cljs source
(`build/node.clj:68-77`) and via experiment (rebuilt + still failed).

**Fix:** raw `js*` hoists at the top of `init-bootstrap!`
(`src/seon/wasm_eval_smoke.cljs:55-58`):

```clojure
(js* "(typeof goog !== 'undefined') && (globalThis.goog = goog)")
(js* "(typeof cljs !== 'undefined') && (globalThis.cljs = cljs)")
(js* "(typeof shadow !== 'undefined') && (globalThis.shadow = shadow)")

```

These execute INSIDE the IIFE where the closure-locals exist, then
expose them on globalThis. Bootstrap-loaded JS (running globally)
now resolves them. Dev builds emit `global.$CLJS = global` for the
same purpose at `node.clj:152`; release builds don't.

Filed as an upstream papercut — a `:node-iife? false` option in
shadow-cljs's `node/configure` would let us drop the hoist.

### 3. Bootstrap host bundle must use `:optimizations :simple`

`:advanced` renames `cljs.core` → `g.q.r` (or whatever Closure
picks). Bootstrap-loaded JS expects the unmunged dotted names. Per
Heller's bootstrap blog + the shadow-cljs user guide, `:simple` is
the canonical setting. Configured at
`shadow-cljs.edn:eval-smoke:compiler-options`.

### 4. `__dirname` is not a Node-runtime global under wasm-rquickjs

`shadow.cljs.bootstrap.node`'s top-level `defonce` calls
`(path/resolve js/__dirname "bootstrap")` even though we pass `:path
"bootstrap"` explicitly later. The defonce evaluates at namespace-
load time and throws before our init code runs.

**Fix:** a prelude module loaded BEFORE `seon/main` in the ESM
graph. `pod-host/wasm-tauri/seon-prelude.mjs` sets
`globalThis.__dirname` + `__filename` to sentinel strings. The shim
imports prelude first, main second, so ES module dependency-graph
ordering guarantees the globals exist before the bundle loads.

Inline `globalThis.X = ...` at the top of `eval-smoke.mjs` does NOT
work — ES imports are hoisted above top-level statements. The
prelude has to be a separate module.

### 5. wasm-rquickjs `--js <file>` doesn't inline the imported bundle

Reading the wasm-rquickjs source
(`~/.cargo/registry/src/.../wasm-rquickjs-0.2.4/src/lib.rs:474-498`):
`copy_js_modules` copies the entry file verbatim to
`<output>/src/bundle_script_module.js`. Relative imports inside that
file are NOT inlined — they get resolved at QuickJS runtime through
the resolver chain, where they hit a virtual `file:///__wasm_rquickjs_virtual__/`
base URL and fail.

**Fix:** use `--js-modules name=path` to embed additional files as
named virtual modules:

```bash
wasm-rquickjs generate-wrapper-crate \
  --js-modules "bundle/script_module=$ROOT/eval-smoke.mjs" \
  --js-modules "seon/prelude=$ROOT/seon-prelude.mjs" \
  --js-modules "seon/main=$SEON_ROOT/out/eval-smoke/main.js" \
  --wit src-wit-eval-smoke --output eval-smoke-build --world eval-smoke

```

Then in `eval-smoke.mjs`: `import 'seon/prelude'; import 'seon/main';`
— resolved by the BuiltinLoader against the embedded modules. The
2.1MB seon bundle ships INSIDE the .wasm component; no runtime WASI
filesystem access needed to find it.

### 6. Default cargo features pull in WASI imports stock wasmtime doesn't supply

`wasm-rquickjs`'s `default = ["normal"]` Cargo feature includes
`logging` (→ `wasi:logging/logging` import) and `fetch` (→
`wasi:http/types`). Stock `wasmtime run` doesn't bind
`wasi:logging/logging`; the component fails to instantiate.

**Fix:** at the cargo step, `--no-default-features
--features="lite,node-http,crypto,zlib,encoding"`. This is `normal`
minus `logging`. Console.* calls inside the bundle become silent
under wasmtime CLI (acceptable for the smoke; the real Tauri host
provides `wasi:logging`). And at runtime, `-S http=y` enables
wasmtime's wasi-http impl for the remaining wasi:http import that
`node-http` pulls in.

Both flags wired into
`pod-host/wasm-tauri/build-eval-smoke`.

## Runtime semantics — eval state persists per-instance

`wasmtime run --invoke eval-form("...")` spawns a FRESH component
instance per call. The defonce'd `!compile-state` and
`!current-ns` reset every time. The smoke's `eval-form!` therefore
auto-inits bootstrap on first form
(`src/seon/wasm_eval_smoke.cljs:72-77`).

REPL-style multi-call persistence is for a long-running embedding
(Tauri host, or `wasmtime serve`), not the CLI's one-shot mode.
Single-form smoke is fine for confidence runs; for batched test
runs we'd add an `eval-batch` export taking multi-form source.

## Promise auto-unwrap

`cljs.js/eval-str` returns the form's value to its callback
synchronously. If the form is `^:async`, the value IS a Promise,
not the resolved value. `eval-form!` awaits Promise return values
(`src/seon/wasm_eval_smoke.cljs:92-99`) so the agent sees the
resolved value through the WIT export. Same shape as V0 pod's
`seon.eval/maybe-await-value`.

## Reproducer

```bash
cd pod-host/wasm-tauri
./build-eval-smoke
# ✓ "ok" from init-bootstrap
# ✓ "{:ok true, :value-edn \"3\", :ns cljs.user}" from eval-form("(+ 1 2)")

```

To eval custom forms:

```bash
wasmtime run -S http=y \
  --dir /Users/sean/src/seon/out/bootstrap::bootstrap \
  --invoke 'eval-form("(reduce + (range 10))")' \
  pod-build/target/wasm32-wasip2/release/seon_eval_smoke.wasm
# => "{:ok true, :value-edn \"45\", :ns cljs.user}"

```

## What's next (post-M2)

- `eval-batch` WIT export for multi-form runs in one instance.
- Wizer pre-init (wasm-rquickjs has an `optimize` subcommand) for
  faster startup — bootstrap-CLJS init is the largest cold-start
  cost, and wizer can snapshot the post-init heap.
- Lift the eval-form export into the full `seon-pod` WIT world
  (`pod-host/wasm-tauri/src-wit/seon-pod.wit:200`) once a Tauri
  host is driving it.

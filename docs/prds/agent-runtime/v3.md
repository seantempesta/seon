# Seon agent REPL — v3 (deferred from v2)

One-line stubs for v3 features. Flesh out when v2 is shipped and v3
is being actively scoped.

## What v3 adds (one-line bullets)

- **Cross-agent collaboration**: multiple agents share program-graph
  entities (the spec's "no ownership boundary" rule applies; v3
  adds the coordination primitives). Includes "who is editing what"
  signals, conflict warnings on simultaneous edits, agent-to-agent
  message passing.
- **D1 — older-DB-on-newer-runtime upgrade**: ritual for opening a
  DB written by substrate version V with runtime version V'. Includes:
  replay-with-overwrite for substrate fns the agent had customized,
  re-bootstrap of new substrate entries not present, warnings for
  conflicts. Substrate attribute schema treated as immutable across
  versions; extensions add new attrs.
- **D12 — blob GC / retention**: sweep design — retract blob metadata
  and delete file when no entity refs the hash. Plus per-blob TTL on
  ingest (e.g. agent says "this paper is needed for 30 days, then
  archive"). Distinct from `:db.purge/*` (destructive, GDPR) — this
  is operational housekeeping.
- **Cross-pod blob sharing**: `seon.blob/*config*` knob to point
  bytes at a shared backend (S3, NFS, a centralized
  content-addressed store). Content addressing makes the sharing
  safe by construction. Datahike metadata still per-pod.
- **Multi-DB queries**: leverage datahike's `:in $1 $2` to query
  across multiple agent DBs (e.g. "find every fn called `analyze`
  across all agent DBs"). Read-only.
- **Branching / `d/branch!`**: per-feature DB branches for the agent
  to experiment without polluting main. `d/merge-db!` for review +
  merge.
- **Distributed sessions**: a session that spans multiple pods (e.g.
  a long research session across multiple checkpoints). Requires
  cross-pod session-id reconciliation.
- **Replay UI**: a dedicated viewer (browser-side) that walks
  `:seon.agent/sessions` → `:seon.session/turns` and shows each
  turn's prompt-blob + assistant message + evals as a transcript.
  V1 has the data; v3 has the viewer.
- **Agent-driven schema migration**: when the agent wants to rename
  a kind, the substrate provides a `seon.schema/migrate!` verb that
  copy-transacts under the new attr and retracts the old in one tx.
  Subject to D1's rules.

## Dependency notes

- Cross-agent collab **requires** v1 (single-agent works correctly
  first).
- D1 **requires** v2 + bootstrap.edn topo emission (D10) to be
  stable.
- D12 **requires** v1 blob storage in production long enough to
  measure actual growth rates.
- Replay UI **can** ship before v3 (v1 has the data); listing here
  because the UI design benefits from multi-session and cross-agent
  use cases being settled.

When v3 is actively scoped, split into a real spec per v1's
structure.

# The context is a render of the database

The entire agent context is generated by walking data in the database and rendering it. There is no hand-maintained rendering code that gets repeatedly poked at. Every element an agent sees — a message, an eval, a todo, a namespace, the inventory, the soul, an arbitrary pulled blob — is the same thing: a **renderable**, a domain entity rendered by its schema, with two views (`:seon.render/ai` for the model, `:seon.render/html` for the human). One recursive walker turns renderables into both views. New ways to show something are new render fns, not new mechanisms. The whole context — every section, in order — is itself one ROOT renderable.

## Overview

The context is a projection of the database, and the unit is the renderable. It is **all database queries**, because everything is indexed: the namespaces section queries `:seon.ns/source`, the inventory queries `store-inventory`, the transcript queries messages + evals, the todos query todos. The agent's deeper lesson, stated plainly: *everything around you is data — the sections, your messages, your todos, even how things are drawn. You adapt to your human by writing schemas and functions: register a schema, write a render fn, point a renderable at it, transact. Your environment is yours to shape.*

The load-bearing constraints that fall out:

- **One recursive walker, two views.** No fn re-implements the walk. A section is a renderable whose render fn produces its child renderables and renders each via an injected recursion handle.
- **No `:kind`, no stored render id/at/ordinal/churn.** Type is the schema, established by attribute presence; the handle is the entity's own id; time is the `:db/txInstant` the store stamps; order is a static `:seon.ctx/priority`.
- **Three render systems exist today and must collapse into one, not add a third** (see Implementation): the section composer (`seon.ctx`), the entity renderer (`seon.render`), and the six `seon.handlers.*` per-kind renderers.
- **Two correctness fixes ride along** outside the render files: the inline-backtick form-extractor (`seon.repl.internal`) and `result/<id>` cross-turn deref (`seon.eval`).
- **The whole context is a ROOT renderable** whose children are the ordered top-level sections; there is NO bespoke composer.
- **Overriding a renderer = upserting a SYMBOL, no ceremony.** There is no `register-renderer!` fn — it does not exist in `src/` and is not part of this design.
- **The agent loop lives in a sibling doc.** The loop, its state model, the DB-reactive wake, the stop policy, and the derived activity log are specified in `agent-loop.md`. This doc keeps only what RENDERING needs (the transcript event query, the message→todo render half).
- **Byte-stable prefix is the universal caching discipline.** Anthropic also needs manual `cache_control` breakpoints our code owns; OpenAI/DeepSeek and Gemini-implicit cache for free on a byte-identical prefix.

## The renderable

A renderable is just a domain entity. It carries OPTIONAL render-control attrs; its identity and time are its OWN data, never duplicated into render-specific attrs.

```clojure
;; ── render-CONTROL attrs — all OPTIONAL; ANY entity may carry them ──────────
;; A renderable is a DOMAIN ENTITY rendered by its schema — no stored "kind",
;; no :seon.render/renderable wrapper. We store NO render id, NO render
;; timestamp, NO ordinal, NO churn attr:
;;   • HANDLE  = the entity's OWN id (:seon.agent.message/id, :seon.eval/id,
;;               a section's :seon.ctx/name) — derived by `renderable-id`.
;;   • TIME    = the :db/txInstant the store auto-stamps on every datom
;;               (UNIVERSAL — works for any entity, no per-kind attr needed) —
;;               derived by `renderable-inst`.
;;   • ORDINAL = the render-time INDEX in the time-sort ("events 0–15"); never
;;               stored.
;;   • ORDER   = static :seon.ctx/priority; there is no churn attr.
(schema/register! :seon.render/ai   [:or :string :symbol])           ;; SLOT (text):  verbatim string OR fn-symbol — EXISTS
(schema/register! :seon.render/html :seon.render.live-tile/content)  ;; SLOT (hiccup): shallow-hiccup value OR fn-symbol — EXISTS, shared shape
(schema/register! :seon.ctx/priority :int)                           ;; static section order: stable low → volatile high — EXISTS
(schema/register! :seon.render/clip
  [:or :int
       [:map [:seon.render/ai   {:optional true} :int]
             [:seon.render/html {:optional true} :int]]
       [:enum :none]])                                               ;; per-item / per-view clip override — namespaced keys
(schema/register! :seon.render/hidden? :boolean)                     ;; self-prune: drop from render, keep the row
(schema/register! :seon.render/children
  [:vector {:seon.db/component true} :seon.db/ref])                  ;; OPTIONAL authored nesting; DERIVED sections query their children instead
```

`:seon.render/html` references the canonical shallow-hiccup shape `:seon.render.live-tile/content` (registered once, shared with the live tile — no inline duplication). Arbitrarily-nested hiccup is NOT a Malli schema: a recursive seqex trips `:malli.core/potentially-recursive-seqex` inside instrumented fns, which is why a `:seon.render/hiccup` schema is not used. Deep validity is checked at the render boundary by the plain fn `seon.render.live-tile/valid-hiccup?`.

Most renderables are DERIVED — a projection of domain rows, reactive, nothing to clear. Only genuinely authored ones are stored (the soul doc, an agent's custom section).

### Render fns are schema metadata — there is no renderer registry

The render fn IS just a quoted SYMBOL, declared as metadata on the schema's `:map` properties (`:seon.render/ai` / `:seon.render/html`), stored verbatim. `schema/register!` decomposes it into `:seon.schema` DB datoms (`:seon.schema/render-fn` / `:seon.schema/render-html-fn`), resolved at render time via `eval/lookup-value`. There is no second registry and no `register-renderer!` fn — that is a ghost from a superseded, rejected design that lives only in stale docs; it does not exist in `src/`. Both override paths reduce to "upsert a symbol" (see "Overriding a renderer").

The attrs that store a kind's render fn (`src/seon/schema.cljc:158-161`):

```clojure
(swap! *schemas assoc :seon.schema/render-fn :symbol)        ; the :seon.render/ai symbol
(swap! *schemas assoc :seon.schema/render-html-fn :symbol)   ; the :seon.render/html symbol
```

A renderable kind declares its renderers inline in the `:map` schema's props (live example, `src/seon/agent.cljs:254-257`):

```clojure
(schema/register! :seon.eval
  [:map {:seon.db/entity   true
         :seon.render/ai   'seon.handlers.eval/render-ai      ; quoted symbol, schema metadata
         :seon.render/html 'seon.handlers.eval/render-html}
   [:seon.eval/id     :seon.eval/id]
   ...])
```

At boot, `schema/all-entity-schemas-tx-data` → `entity-schema-tx-data` per kind (`schema.cljc:502-533`) pulls the symbols out of the props and emits datoms; one `:seon.schema` row per kind, identity-keyed on `:seon.schema/key`. Dispatch is 100% symbol-driven — no fn objects are ever stored (they can't survive the form round-trip; platform-law comment at `render.cljs:122-126`).

## The recursive render

`render` is the whole system. It takes a view (`:seon.render/ai` or `:seon.render/html`), the injected context, and a node; returns a String (ai) or hiccup (html). It injects a `:seon.render/render` handle bound to the same view so a section renders its children through the same dispatch — never re-walking.

```clojure
;; ── handle + time, DERIVED (never stored render attrs) ──────────────────────
(def render-control-attrs
  [:seon.render/ai :seon.render/html :seon.render/clip
   :seon.render/hidden? :seon.render/children :seon.ctx/priority])

(defn renderable-id
  "A node's stable HANDLE — its own identity attr (dispatch by presence), or a
   section's name. Shown in the transcript so the agent can reference / override
   it. Never a stored :seon.render/id."
  [node]
  (or (:seon.agent.message/id node)
      (:seon.eval/id node)
      (:seon.agent.todo/id node)
      (:seon.ctx/name node)))

(defn renderable-inst
  "A node's TIME for sorting + relative display — the :db/txInstant the store
   stamped when the row was first asserted (UNIVERSAL; no per-kind :at attr).
   The events query joins it in once for the whole list (below); this is the
   per-node fallback for an arbitrary pulled entity."
  [db node]
  (ffirst (db/query {:seon.db/db db
                     :seon.db/query '[:find (min ?t) :in $ ?e :where
                                      [?e _ _ ?tx] [?tx :db/txInstant ?t]]
                     :seon.db/args [(:db/id node)]})))

;; ── slot resolution: explicit → schema-default → generic-default ────────────
(defn- resolve-slot
  "The render fn for `node` in `view`.
     1. read the slot; a DB-STORED slot is EDN — decode first
        (db/decode-edn-value, as render.cljs:311-312 / ctx.cljs:1583-1587 do);
     2. string → verbatim; shallow-hiccup vector → verbatim;
     3. fn-symbol → the fn. An AGENT-authored symbol is invoked SCI-BOUNDED
        (a runaway agent fn must not freeze the single-threaded pod);
        a core symbol calls direct (fast, trusted);
     4. absent → the renderer registered on the entity-SCHEMA the node satisfies
        (dispatch by attribute presence, most-required-attrs wins);
     5. none → the GENERIC default (any data → Clojure / a data-tree)."
  [view node]
  (let [slot (db/decode-edn-value view (get node view))]
    (cond
      (string? slot) (fn [_] slot)
      (vector? slot) (fn [_] slot)
      (symbol? slot) (if (render-sci/agent-authored-sym? slot)
                       (fn [in] (render-sci/invoke-bounded slot in))   ;; bounded
                       (seval/lookup-value slot))                      ;; core — direct
      :else (or (schema-default-renderer view node)
                (generic-default-renderer view)))))

(defn render
  "Render ONE node in `view`, recursively + guarded. The fn receives the full
   injected context PLUS the node and a view-bound recursion handle."
  [view ctx node]
  (if (:seon.render/hidden? node)
    (when (= view :seon.render/ai)
      (str ";; (1 pruned — " (renderable-id node) "; (seon.agent/unprune! …) to restore)"))
    (let [f  (resolve-slot view node)
          in (assoc ctx :seon.render/node   node
                        :seon.render/render #(render view ctx %))]   ;; ← view-bound recursion
      (try (f in)
           (catch :default e
             (if (= view :seon.render/ai)
               (str ";; ⚠ [" (renderable-id node) "] render failed: " (ex-message e))
               [:div.render-error "⚠ " (str (renderable-id node)) " — " (ex-message e)]))))))
```

The injected context (`ctx`) is the existing input, extended:

```clojure
{:seon.db/db        db                ;; query/pull inside any render fn
 :seon.agent/id     "QMn-2606240137"
 :seon.agent/entity {…pulled once…}   ;; focused pull, not [*] (no session inlining)
 :seon.ai/model     "deepseek-…"
 :seon.render/node  <the node>        ;; the renderable being rendered
 :seon.render/render <fn child→view>} ;; the recursion handle (added per-call)
```

### Section, leaf, and generic-default renderers

There is one section model: a section is a renderable whose render fn produces its CHILD renderables — from a QUERY (the transcript, the inventory) or from an authored `:seon.render/children` vector — and renders each through the injected `:seon.render/render` handle. Brackets (ai) / `<details>` card (html) are the section renderer's own output, so it self-demarcates at any depth.

```clojure
(def message-renderers   ;; schema-default for a node HAS-ing :seon.agent.message/content
  {:seon.render/ai
   (fn [{{:seon.agent.message/keys [from to content] :as node} :seon.render/node}]
     (let [id (renderable-id node)]
       (if to (str ";;; ▶ to "   (who (first to)) " [" id "] " (pr-str content))
              (str ";;; ◀ from " (who from)       " [" id "] " (pr-str content)))))
   :seon.render/html
   (fn [{{:seon.agent.message/keys [from to content] :as node} :seon.render/node}]
     [:div.msg {:data-id (renderable-id node) :class (if to "outbound" "inbound")}
      [:span.who (if to (str "▶ " (who (first to))) (str "◀ " (who from)))]
      [:span.content content]])})

;; GENERIC DEFAULT — renders ANY structure when there is no slot and no schema
;; match. AI: readable Clojure. HTML: a recursive collapsible data-tree. This is
;; what makes "all data that enters the system is viewable by both" true for free.
(defn- generic-default-renderer [view]
  (case view
    :seon.render/ai   (fn [{:seon.render/keys [node]}]
                        (str ";; " (renderable-id node) "\n"
                             (with-out-str (cljs.pprint/pprint
                                             (apply dissoc node render-control-attrs)))))
    :seon.render/html (fn [{:seon.render/keys [node render]}]
                        (data-tree node render))))   ;; maps→k/v rows, vectors→indexed, recurse via render
```

## Overriding a renderer

The agent (or a third party) refines a view by upserting a SYMBOL. There is no `register-renderer!` and no second registry. The schema props are the one store; `resolve-slot` step 4 reads them. Two paths, both "upsert a symbol":

**(a) Per-ENTITY view** — transact a render slot onto that specific entity. `entity-render-slot` (`render.cljs:310-312`) checks the per-entity attr first, so it WINS over the kind default:

```clojure
;; point ONE renderable's view at a fn the agent wrote:
(seon.db/transact! {:seon.db/tx-data [{:seon.eval/id "evK-2606240138"
                                       :seon.render/html 'my.agent.QMn/pretty-eval-card}]})
```

**(b) Per-KIND default** — set `:seon.render/ai` / `:seon.render/html` as `:map` props on the kind's schema via `schema/register!` (the canonical path — `register!` decomposes them into the `:seon.schema/render-fn` / `:seon.schema/render-html-fn` datoms that `resolve-slot` step 4 reads). `:seon.schema/key` is the identity attr, so re-registering upserts the row — redefine = upsert, no override/reconcile:

```clojure
;; change the default renderer for every node of a kind:
(schema/register! :seon.agent.message
  [:map {:seon.db/entity   true
         :seon.render/ai   'my.agent.QMn/my-message-ai
         :seon.render/html 'my.agent.QMn/my-message-html}
   [:seon.agent.message/id :seon.agent.message/id]
   ...])
```

A direct datom upsert onto the `:seon.schema` row works at render time too, but the in-memory `*schemas` props then disagree with the DB until the next `register!` and won't survive a re-index from source — prefer the `register!` path.

## The context is a root renderable (no composer)

There is NO bespoke composer. The whole context is a ROOT renderable `{:seon.ctx/name :context}` whose children are the ordered top-level sections. Producing the prompt is just rendering the root per view:

```clojure
(defn context-root
  "The ROOT renderable. Its children = the core section renderables UNIONed with
   the agent's :seon.agent/ctx overrides (override-by-id) and any derived rows,
   sorted by static :seon.ctx/priority (no churn). This subsumes the old
   merge-sections override-by-name. The transcript is one such child; its OWN
   children come from a QUERY (one model)."
  [ctx]
  {:seon.ctx/name        :context
   :seon.render/children (->> (top-level-renderables ctx)        ;; core ∪ agent ctx ∪ derived
                              (sort-by :seon.ctx/priority))})    ;; STATIC order

;; producing the prompt is rendering the root per view — no assemble-context,
;; no merge-sections, no render-section*:
(render :seon.render/ai   ctx (context-root ctx))   ;; the assembled LLM prompt (String)
(render :seon.render/html ctx (context-root ctx))   ;; the inspector right pane (hiccup)
```

The root's `:seon.render/ai` is the section renderer: it renders each child via the injected `:seon.render/render` handle and joins with a fixed delimiter; each child section emits its own `;;; ┌─ <name> ─` / `;;; └─ end <name> ─` bracket (ai) and `<details>` card (html). This DELETES `assemble-context`, `merge-sections`, `render-section`, and `render-section-html`. The cache breakpoints are a thin POST-step on the rendered `:ai` string (see Caching).

The transcript child, for example:

```clojure
{:seon.ctx/name :transcript :seon.ctx/priority 80    ;; near the bottom (volatile), above todos
 :seon.render/ai 'seon.ctx.transcript/transcript-section
 :seon.render/clip :none}                            ;; no turn clipping yet
;; transcript-section: query messages + evals (one datalog join to :db/txInstant
;; gives each event its time), sort by that instant, (map render …) via the
;; injected handle, join to a String. Turns are markers interleaved by time,
;; not containers. No stored :seon.render/children for this derived section.
```

## Section ordering

Sections are ordered by a static `:seon.ctx/priority` (low = top/stable, high = bottom/volatile). Within a section, items sort by time (`:db/txInstant`). Churn is maximized at the BOTTOM so the stable prefix caches; the cache breakpoint falls at the stable→volatile transition. There is no churn attr and no dynamic reordering, because re-sorting sections by when-they-changed busts the cache every turn — that is the trap. Ordering is static, not by recency.

| Priority | Section | Source (all DB queries) | Why here |
|----------|---------|-------------------------|----------|
| ~5 | **soul** (identity) | `SOUL.md` via `doc-section` | static; its own section if present; cache-bust on edit accepted |
| ~8 | **AGENTS.md** (operating instructions) | `AGENTS.md` via `doc-section` | static; its own section if present (absent today → no section) |
| ~20 | **:system** — environment orientation + standing teachings + COMMON DB OPS | `system-text` (in-place rewrite) | static; under soul, above namespaces |
| ~30 | **whitelisted namespaces** — real source | `:seon.ns/source` / `:seon.fn/source` | clean + self-explaining; heavy fns behind `.internal` |
| ~80 | **transcript** — time-ordered events | messages + evals, sort by `:db/txInstant` | most volatile |
| ~85 | **inventory** — stored-data map | `store-inventory` (data kinds only) | BELOW the transcript so a single inventory change can't invalidate the transcript cache prefix |
| ~90 | **todos** — with relative age | todos | small + PROMINENT (below transcript, per design) |
| ~99 | **repl prompt** | the readline anchor (the one live `now`) | last |

The numbers are tunable from drive + cache-hit metrics; the ORDER is the decision. Inventory sits BELOW the transcript: a single inventory change (a new data kind appears, a count ticks) must not invalidate the transcript's cached prefix, so inventory rides in the volatile tail beneath the transcript rather than above it.

Within the namespaces section: oldest → newest (most-mutable / the agent's own just-created ns LAST). This is the live behavior (`namespaces.cljs:275`, sort by the `:seon.ns/name` datom's tx). It is a STABLE order — a ns only moves when actually edited (a one-time bust), not a per-turn reshuffle — so editing your own ns busts only its block + below, while every older/stable ns block ABOVE it stays cached.

The transcript is APPEND-ONLY and mostly CACHED. New events append at the bottom; everything already written is byte-identical to last turn (times are fixed — nothing recomputes from `now`). With a breakpoint near the transcript tail, next turn the cache hits on the entire prior prefix — stable sections AND all older transcript turns — so only THIS turn's new events plus the bottom current-time line cost tokens. Read-heavy turns are nearly free.

## Caching (provider-agnostic)

The render is ordered stable→volatile by `:seon.ctx/priority` (soul → `:system` → namespaces = the cacheable prefix; entity-less, transcript, inventory, warnings, todos = volatile), and the prefix is **byte-stable render-to-render**: the append-only transcript is byte-identical except its newest appended events, every event/todo time renders from a fixed `:db/txInstant` (absolute or inter-event delta), all collections are `sort-by`'d before joining, joins and the in-band `stable-boundary` delimiter are fixed strings, and locale/timezone are pinned (`sv-SE`/`host-timezone`) — so the *only* per-render byte change is the newest events plus the single current-time line in the bottom readline (the one `(js/Date.)` that touches displayed text; `transcript.cljs:255`).

**Byte-stability is the single UNIVERSAL requirement** that makes caching work across all three providers (the claude-api prompt-caching reference: *"Prompt caching is a prefix match. Any change anywhere in the prefix invalidates everything after it."*):

- **OpenAI / DeepSeek (automatic, IMPLICIT):** auto-cache any byte-identical prefix ≥1024 tokens in 128-token increments. **Zero caching code** — `openai_compat.cljs` (`request-params`, lines 171-207) builds a plain `{:role "system" … }` + `{:role "user" … }` pair with no `cache_control`, correctly. DeepSeek (the pod's real default adapter) implements the same automatic prefix caching — the byte-stability discipline pays off on the live default.
- **Gemini (automatic, IMPLICIT on 2.5+):** caches a reused `systemInstruction`/prefix if byte-identical. Note the scope: `gemini.clj` is the `user/ask` / `user/search` / `review-code` developer/research tool (raw `hato.client`), NOT an agent-turn adapter — there is no Gemini agent adapter in the loop today. `review-code` (lines 525-608) is the in-repo proof of the pattern: it puts static `::conventions` into `:systemInstruction` precisely so repeated reviews hit the cache, and reads `:cachedContentTokenCount` (line 582). A future Gemini agent adapter needs nothing beyond byte-stability.
- **Anthropic (MANUAL — OUR code owns it):** caches NOTHING without explicit `cache_control {:type "ephemeral"}` breakpoints; render order is `tools → system → messages`. Byte-stability is the *precondition*; the breakpoints are *also* required (without them you pay the 1.25× write premium every turn and read nothing). `anthropic.cljs` (`request-params`, 120-169) calls `ctx/split-context` (line 139), then builds `:system` as a block array with `cache_control` on TWO blocks (34-50 docstring: "2 of the 4 allowed"): block 1 = `(ai/effective-system-prompt request)` (the soul, always cached), block 2 = `stable-text` through `:namespaces` (conditionally cached via `split?`, line 160, which requires both halves non-blank). The volatile tail rides in `:messages` (line 163), uncached. The breakpoint on block 2 caches `tools + system + stable-ctx` as one prefix.

### The open Anthropic win — a third breakpoint on the transcript prefix

The append-only transcript is the LARGEST byte-stable part of a long session and today rides entirely uncached in the user message. Anthropic allows 4 breakpoints; we use 2. The recommended layout (3 of 4, within the limit):

```
[block: soul/system-prompt]            ← cache_control (breakpoint 1)  — today
[block: stable-ctx (thru :namespaces)] ← cache_control (breakpoint 2)  — today
--- volatile tail starts ---
[transcript MINUS its newest turn(s)]  ← cache_control (breakpoint 3)  — NEW
[newest turn + the bottom `now` line]  ← no breakpoint, rides uncached
```

Breakpoint 3 moves the prior transcript prefix from full-price re-processing to a cache read each turn; only the new turn + the bottom `now` line are full-price. It requires `split-context` to expose a transcript/newest-tail cut and `request-params` to emit the user message as a block array `[{:type "text" :text transcript-prefix :cache_control …} {:type "text" :text newest-tail}]`. The transcript renders as ONE big text block, so Anthropic's 20-block lookback window is a non-issue as currently structured (if a future refactor splits it into per-turn blocks, add an intermediate breakpoint every ~15 blocks). Opus 4.x has a 4096-token minimum — a short prefix silently won't cache (`anthropic.cljs:48-50` already flags this). This third breakpoint is a LATE optimization, gated on the simple version working; ship 2, tune to 3 live.

**The single discipline that serves all three: keep the prefix byte-stable.** Get it right → OpenAI + Gemini cache for free and Anthropic's breakpoints read; get it wrong (one stray `now`, one unsorted query, one drifting join) → all three silently miss (automatic providers with no error; Anthropic by paying the write premium for a cache nobody reads). Verify with `usage.cache_read_input_tokens` (>0 on call 2). When testing the Anthropic cache, use HAIKU to keep the cost low, and verify the per-model cache MINIMUM (a prefix shorter than the model's minimum silently won't cache — no error, just a miss).

**Caching works OUT-OF-THE-BOX for ALL consumers, including a third party.** Byte-stability makes it automatic for OpenAI/DeepSeek and Gemini-implicit (zero consumer config — they cache any byte-identical prefix on their own), and the Anthropic `cache_control` breakpoints are owned by OUR adapter (`anthropic.cljs`), not the consumer. So a third-party consumer building on seon gets caching for free across every provider with NO setup — they neither configure the implicit providers nor place Anthropic breakpoints; the discipline lives entirely in seon's render + adapter.

### Two byte-stability follow-up flags (not fixed by this spec)

1. `transcript.cljs:110` — `clock`'s `(or inst (js/Date.))` fallback is a latent foot-gun: it is dead today (every call site passes a stored `:at` — lines 161, 173) but would silently inject a live timestamp into transcript-body text if ever passed nil. Consider an assertion/guard instead of a silent live-clock default.
2. The soul/system-prompt cache block (`anthropic.cljs:157-159`) is sourced from `effective-system-prompt` (a LIVE `SOUL.md`/`AGENTS.md` read), NOT from the ctx string — so it is byte-stable by a SEPARATE mechanism than the `:db/txInstant` rule and is not subject to that discipline. Note this seam so a future SOUL.md-templating change doesn't silently break the first breakpoint.

## Time and the as-of cache-diff

Time awareness holds, but every rendered time is BYTE-STABLE except one. THE RULE: no render fn calls `now` to produce displayed text — anywhere — EXCEPT the single current-local-time line in the repl prompt (the very bottom). A timestamp only changes between renders if computed relative to `now`; computed from FIXED data it is byte-identical however many times it renders.

- **Every event/todo/section time is derived from its own `:db/txInstant`** — rendered EITHER as the actual clock time (`14:30`) OR as an inter-event delta between consecutive PAST events (`+3m later`). Both are fixed → byte-stable → cached. (Actual-vs-delta is a format choice, picked at the live drive.)
- **The ONLY moving value is the current local time, in the repl prompt at the bottom** (below the last cache breakpoint — busting there is free). The user-waiting signal is computed ONCE there (e.g. "your user last messaged 4m ago — current time HH:MM"), by comparing the user's last-message `:db/txInstant` (fixed) to `now`. There is NO inline `⏳ waiting N` sprinkled through the transcript — that would call `now` per-line and bust the whole transcript every turn.

### Verifying the prefix + precise breakpoints — the as-of diff

Because the context is a PURE render of the db and datahike is bitemporal, we reproduce ANY past context for free — we never store contexts. Store ONE value, `:seon.agent/context-rendered-tx` (the db basis-tx at the last render — a deterministic tx id, NOT a wall clock), and re-render the old prefix on demand:

```clojure
;; last turn's prefix vs this turn's — the byte-divergence point is EXACTLY where
;; the cacheable prefix ends. The prefix is a pure fn of the db value (the only
;; live `now` is the bottom readline, below the prefix), so as-of reproduces
;; last turn's prefix byte-for-byte:
(render :seon.render/ai ctx
        (context-root (assoc ctx :seon.db/db (seon.db/as-of db last-render-tx))))
```

Two uses:

- **Verification (cheap — wire early):** diff context(now) against context(as-of last-render-tx); it must diverge ONLY at the expected append point. Divergence HIGHER up is a non-determinism bug (an unsorted query, set-iteration order, a stray `now`) — caught automatically instead of as a silent cache miss. This is the executable check for the byte-stability rule.
- **Precise Anthropic breakpoint (optimization — late):** place the `cache_control` breakpoint exactly at the divergence point rather than a fixed priority boundary, maximizing the cached prefix. Moot for OpenAI/Gemini (auto).

Storage-free: one stored tx + an `as-of` re-render on demand — no saved before/after blobs. `as-of` is verified live (Pre-impl check 1); the re-render calls the thin `seon.db/as-of` wrapper (never `datahike.api` directly outside `src/seon/db/`).

## The message ↔ todo safety net (render half)

The agent loop, its state model, the DB-reactive wake, the stop policy, the ACTIVITY LOG, the `:seon.agent.message/handled?` removal, the dormant handler registry, and the inbound-predicate dedup all live in `agent-loop.md`. This doc keeps only the RENDER half of the message↔todo safety net.

The transcript is a time-ordered event query (a render concern — see "The context is a root renderable"). For inbound user messages, the persistent task surface is a TODO renderable: one todo per inbound `:human` message, each rendering its transactable id + relative age. "Addressed" is DERIVED from the linked todo's COMPLETION — there is no stored "handled" flag in the render path; a render fn never inspects a wake/handled attr, only the todo's done-state. The todo carries a SHORT clipped preview + a `:seon.agent.todo/message` back-ref (the full message is one `(db/pull '[*] [:seon.agent.message/id id])` away), never a full copy. (The auto-todo WRITE itself is message-intake — independent of render — owned by `agent-loop.md`; this doc only renders the todo.)

### Auto-todo per inbound user message (render view)

The todo renderable carries a CLIPPED preview, not a full copy, and links back to its message via `:seon.agent.todo/message` (one direction; the reverse is free via VAET). The todo is framed as a memory aid, not an obligation.

The natural turn pattern: mark a message-todo complete AND do other work AND (often) spawn sub-todos from what the user said — all in ONE turn. The todo API + docstrings teach this. The done-signal is the todo's completion, not a destroyed message.

The agent loop + activity log: see `agent-loop.md`.

### First-turn planning bootstrap

The first-turn planning bootstrap is a dynamic renderable, shown only when there is fresh unaddressed work (open `:human` message-todos), and rendered BELOW the inbound task lines so a fresh agent with a pending task acts rather than greets.

## Non-goals / guardrails

- No parallel systems. The converters ABSORB `seon.handlers.*` and REPLACE the `seon.ctx.*` string-builders; `context-root` REPLACES the composer fns; originals deleted in the same patch. Three rendering layers today must become one.
- There is NO `register-renderer!` and NO second renderer registry — overriding a renderer is upserting a SYMBOL onto the entity (per-view) or the schema (per-kind, via `register!`).
- There is NO bespoke composer — the context is a ROOT renderable.
- The agent loop, the wake, the stop policy, the activity log, and the `:seon.agent.message/handled?` removal are specified in `agent-loop.md` — not duplicated here.
- Agent-authored render fns are ALWAYS SCI-bounded; never call agent code direct in the render path.
- Reactive by default; store only authored content; no stored render id/at/ordinal/churn.
- The whitelist is universal; no section grows unboundedly.
- Don't conflate `:seon.ai/context-window` (input) with `::max-tokens` (output).
- Self-prune is a property, never a second registry.
- Keep the prefix byte-stable — the universal caching discipline.
- Keep the readline last — it must be the final bytes so the model's reply is the next REPL input. The transcript is the most volatile cacheable section; the small volatile tail below it (inventory, todos) then the readline follow.
- Clipping is renderable-map data (`:seon.render/clip`): global default / per-view (`:seon.render/ai` vs `:html`) / per-item override; `:none` = full. A clipped node always shows its id (full value one `pull` away).
- No transcript clipping yet; window-pressure recourse deferred. Until the agent manages its own context, the transcript renders ALL turns (`:seon.render/clip :none`); the sliding window over the transcript comes later. For now only a soft warning fires.
- Token estimation lives in `seon.tokens` (`chars-per-token` = 4); no tokenizer dep.

## Appendix — evidence base + biggest risks

### Biggest risks

- **A THIRD render system.** Converters written fresh BESIDE `seon.handlers.*` AND `seon.ctx.*` → three layers. Converters must absorb handlers.* and replace the string-builders, originals deleted same patch.
- **A second renderer registry.** Override must UPSERT a symbol onto the entity / schema (the one store `resolve-slot` reads), never a parallel registry. There is no `register-renderer!`.
- **A bespoke composer reappearing.** The context is the ROOT renderable; `assemble-context`/`merge-sections`/`render-section*` are DELETED, not refactored in place.
- **The static-priority boundary becoming a parallel cache mechanism.** The static `:seon.ctx/priority` transition must FEED the one existing `stable-boundary`/`split-context` (consumed by `anthropic.cljs:139-163`), not introduce a second split — else cache-control breaks or double-counts.
- **A runaway agent render fn freezing the pod.** Any agent-authored `:ai`/`:html` slot fn must go through `seon.render.sci/invoke-bounded`.
- **P1 render-only without the parser/deref fixes.** A faithful flat event log still shreds inline-backtick prose into junk "eval" renderables and still fails `result/<id>` deref. The `seon.repl.internal` + `seon.eval` fixes are P1 dependencies.
- **P4 half-landed.** The persistent-task safety net needs the inbound write hook (specified in `agent-loop.md`) AND the open-todos render (here) to land together; render-only loses tasks. The "addressed" signal must derive from todo completion — never reintroduce a stored handled flag.
- **Self-prune as a second registry.** A hidden-renderables atom/table instead of a `:seon.render/hidden?` property is the banned parallel system.
- **Half-migrated budgets / max-tokens confusion.** Migrate all three char budgets to tokens together; never conflate `:seon.ai/context-window` (input) with `::max-tokens` (output).
- **Orphan-arm rot.** The `:seon.render/text` tolerance arms (`render.cljs:106-113, 468-490`) flagged "delete with the V4 composer rewrite" — THIS is that rewrite; left undeleted they become permanent dead parallel-key tolerance.
- **Activity-log: history IS reachable.** datahike `history`/`as-of`/`since` resolve and work on the pod's local db value (verified live, Pre-impl check 1) — derive the activity-log via the thin `seon.db/as-of`/`history`/`since` wrappers; never stamp a parallel stored log.

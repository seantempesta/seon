# Stage 1.5 graduation matrix reconciliation (2026-07-21)

## Decision

Stage 1.5 has no demonstrated source defect but is not graduated. The pure projection, dispatch,
transport, authorization, `/data`, eval-disclosure, and plan-consumer cells
have focused proof. The plan migration and bounded transcript live blockers are
also closed. What remains is one frozen-revision integration run that exercises
the real value route and both real value owners through paging and retirement,
then verifies the two web consumers in a real browser plus server-side SSE.

No new source unit is justified by this reconciliation. The shortest path is
to run the missing live falsifiers, close or update the three retained value
issues with that evidence, and only then count the complete CLJS checkpoint as
the Stage 1.5 graduation gate.

## Shortest ordered remaining runbook

1. Freeze every source owner and record the exact Git head, Datahike pin,
   artifact digest, default database value, process generations, route catalog,
   and clean/allowed-untracked status. Abort if source inputs or process
   generations change before the final observation.
2. Run the smallest focused Stage 1.5 owner set once: schema, render value,
   render block, execution, execution host, value route/server, eval handler,
   and plan. Then run one non-overlapping complete `bin/test-cljs`. Any failure,
   warning newly attributable to Stage 1.5, or changed artifact digest aborts
   the live count.
3. Create one fresh Bun-owned agent and one fresh JVM-hosted agent. In each
   owner, evaluate a large counter-backed nested value with an admitted scalar
   map path, a display-only projected key, and at least two sequence pages.
   Record managed eval ids and the immutable database value that pins each
   owner.
4. Through ordinary HTTP, request page zero and a nonzero page for both evals.
   Record stable root ids, response bytes, exact touched-item counts, cursor or
   offset, and one honest tail sentinel. Refuse an over-limit request and prove
   zero additional touches. Request one eval through the other agent and a
   nonexistent eval; require byte-identical 404 and zero sends.
5. Retire each real owner through its normal lifecycle. Re-request the same
   eval paths and require status-200 unavailable/recompute projections, no
   replacement runtime, retry, stored-result parse, or queue residue. Exercise
   one controlled transport failure and require 503 without morphing the
   previously rendered subtree.
6. In an agent-owned browser tab, exercise the agent page: valid, invalid, and
   shape-only badges; zero-request explanation hover; custom/as-data switch;
   nested paging on the same subtree; projected-key absence of controls; live
   eval disclosure; and retired-value unavailable state. Capture console and
   network evidence.
7. On `/data`, drill one entity through the same renderer and route. Require
   matching badges/hover/paging, no raw EDN `<pre>`, no execution send, and the
   same immutable database value through feed acquisition and projection.
8. In one fresh agent turn, issue representative scalar, tuple, collection,
   and relation `db/query` calls and require correct follow-up use of each
   unchanged Datahike result shape based on its compact recorded/rendered
   explanation. Treat a lucky answer without the explanation in the rendered
   context as insufficient evidence.
9. In parallel with browser observations, use a server-side identity SSE
   client and pod logs to record `datastar-patch-elements`, feed open, and
   broadcast. Confirm stable `#app-view` identity across the drill and feed
   morphs. Then verify default readiness and the frozen source/artifact digest.
10. Update and archive only the issues whose complete acceptance is now
   proven, regenerate `bin/issues-index`, and record the final suite/live
   evidence in the roadmap. Stage 1.5 graduates only after every row above is
   proven against this one revision.

## Abort conditions

- Any source, dependency pin, build output, or artifact digest changes after
  freeze.
- A source-editing lane still owns a file included in the artifact.
- Default admission, writer, pod, route catalog, or selected execution owner is
  not ready at the recorded generation.
- A branch or isolated agent cannot be closed without uncertain ownership.
- A page is accepted without counter-backed work evidence, or a rejection
  performs lookup, execution send, descent, or realization.
- A retired eval is served by a fresh owner, persisted EDN, or raw-value
  fallback.
- Browser-only observation is used as SSE proof, or SSE alone is used as DOM,
  hover, network, or console proof.
- The browser bridge's long-lived-feed limitation is mistaken for a product
  failure; use the mandated server-side client before classifying it.
- Any of the four named open issues is archived before its remaining live or
  behavioral acceptance is observed.

## Graduation judgment

The earliest unsettled contract is not another renderer or route source
change. It is the integrated live owner-retirement and browser crossing on one
frozen artifact. The final Stage 1.5 gate is therefore: focused owners green,
full CLJS green, real Bun and JVM paging plus retirement green, HTTP
authorization/work bounds green, agent and `/data` browser interactions green,
and server-side SSE/log evidence green without source or generation drift.

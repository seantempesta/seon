## Creating a New PRD

**Fast method:**
```bash
cp -r docs/prds/_example-feature docs/prds/your-feature-name
rm docs/prds/your-feature-name/README.md
```

**Manual method:**
```bash
mkdir -p docs/prds/your-feature-name/research
touch docs/prds/your-feature-name/{prd,decisions,notes}.md
```

## File Purposes

| File | Required? | Purpose |
|------|-----------|---------|
| `prd.md` | Yes | Main specification (goals, constraints, success criteria) |
| `decisions.md` | Optional | Why decisions were made (rationale, alternatives, trade-offs) |
| `notes.md` | Optional | Implementation learnings (gotchas, patterns, tips) |
| `research/` | Optional | Exploration findings (spikes, evaluations, benchmarks) |

**Rule of thumb:** Simple features might only need `prd.md`. Complex features benefit from all files.

## Agent Workflow

1. **Exploration** (1-2h) - Read PRD, study resources, understand problem
2. **Research** (2-4h) - Spike solutions, test assumptions, document findings in `research/`
3. **Implementation** (main work) - Build incrementally, REPL-verify, update `decisions.md` and `notes.md`
4. **Validation** - Run tests, verify success criteria, update docs

## Key Principles

1. **PRDs are guidance, not gospel** - Pivot if approach doesn't work, document why
2. **Document as you go** - Don't wait until the end
3. **Capture the "why"** - Decisions and learnings are more valuable than requirements
4. **Adapt to complexity** - Simple features need less, complex features need more
5. **REPL-verify everything** - `(integrant.repl/reset)` not `require :reload`

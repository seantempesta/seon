# Seon agent REPL — v2 spec (deferred from v1)

V2 picks up everything v1 explicitly deferred to keep iteration speed
high. The designs below were worked out as part of the v1 design
pass; they're preserved here in full detail (not collapsed to
one-liners) so the next implementor doesn't have to re-derive them.

**V1 → v2 transition: clean break.** New schemas, new database
if needed. No backfill migration tooling — v1 sessions stay
playable as-is; v2-onward sessions get the new shape from day one.

## What v2 adds

1. [Test entity and auto-run](#test-entity-and-auto-run) — `:seon.test`
   schema, `(seon.agent/test ...)` agent helpers, `d/listen!`-based
   auto-run, `:seon.eval/test` tx-meta. Detect-and-tee in
   `eval-batch!` extends to recognize `(deftest …)` forms.
2. [Warnings tile — additional predicates](#warnings-tile) —
   `untested-fn-warning` and `failing-test-warning` (both need the
   `:seon.test` entity). The `warnings-section` itself + the
   `slow-eval-warning` predicate already ship in v1.
3. [Blob storage — content-addressed archival](#blob-storage--content-addressed-archival) —
   `:seon.blob` entity, on-disk zstd, hex fanout, `put!`/`get`/`ref-by`
   API. Replaces v1's inline `:seon.turn/prompt-text` with
   `:seon.turn/prompt-blob`.
4. [Hard rules — defn schema gate + accretive schema redefs](#hard-rules) —
   `seon.code/check` gating + spec-violation predicate.
5. [Message importance + pinning](#message-importance) —
   `:seon.message/important?` + `(seon.agent/mark-important! id)`.
6. [Curation verbs](#curation-verbs) — `seon.eval/forget!`,
   `forget-ns!`.
7. [History pruning](#history-pruning) — `:db/noHistory` per-attr
   opt-outs on high-churn agent scalars.
8. [Reference-graph attrs (D8)](#reference-graph-attrs) —
   `:seon.fn/refs`, `:seon.fn/input-spec`, `:seon.fn/output-spec`.
9. [Per-entity Malli-specificity dispatch (`seon.render`)](#per-entity-dispatch) —
   section fns can `(render entity)` and get the most specific
   renderer for the shape.
10. [Per-section HTML composer](#per-section-html-composer) —
    section fns grow their return map with `:seon.render/hiccup`
    alongside v1's `:seon.render/text`; HTML composer walks the
    same `:seon.ctx` entities. **No new `:seon.ctx` slot.** Six
    default sections in `seon.render.default` grow hiccup output.
11. [Related-ns-section](#related-ns-section) — signature-only
    digest of namespaces the current ns references. Requires D8.
12. [Tufte profiling + perf-section](#tufte-profiling) — opt-in
    deep profiling layered on v1's always-on `:duration-ms`.
13. [Context token budgeting + visibility](#context-token-budgeting) —
    per-section `:max-pct`/`:max-tokens`, composer enforcement, rendered
    `<ctx-budget>` footer.

**Already in v1, NOT v2:**

- Program graph entities (`:seon.fn`, `:seon.schema`, `:seon.ns`)
  — full schema + detect-and-tee + reverse-ref discovery shipped
  in v1. V2 adds only the `:seon.test` entity (see #1 above) and
  the D8 reference-graph attrs (#8) on top.
- `bootstrap.edn` emission rig (D10) — substrate seed file
  emitted at build time by `bin/emit-bootstrap`. v1 ships this.
- Resume via program-graph walk — v1 already walks `:seon.ns` /
  `:seon.fn` / `:seon.schema` entities in tx order on boot.
- `warnings-section` mechanism + slow-eval predicate — v1 ships
  the tile and the one duration-based predicate.

Each section below specs the feature in enough detail that a fresh
implementor can build it without re-asking design questions. Where
relevant, the "migration from v1" notes describe how to add the
feature without breaking v1 contracts.

## Program graph entities — extension only

The program graph (`:seon.ns`, `:seon.fn`, `:seon.schema` + their
detect-and-tee + reverse-ref discovery) **ships in v1**. See
[v1.md §2.2](v1.md#22-program-graph) for the full schema and
detection logic.

V2 extends the program graph in two ways:

1. **Adds the `:seon.test` entity** with full attrs (see
   [Test entity and auto-run](#test-entity-and-auto-run) below).
   Detect-and-tee extends to recognize `(deftest …)` forms.
2. **Adds the D8 reference-graph attrs** (`:seon.fn/refs`,
   `:seon.fn/input-spec`, `:seon.fn/output-spec`) — see
   [Reference-graph attrs](#reference-graph-attrs) below.

Everything else about program-graph modeling (ns is parent, fn/schema
hold child→parent refs, detect-and-tee writes in the same tx as the
eval entity under `:seon.db/eval-id` tx-meta) is already in v1.

## Test entity and auto-run

Tests as first-class entities + automatic re-runs when their target
fn changes.

### Schema

```clojure
;; Test — projection only per the three-tier rule.
;; Full event sequence lives on the agent ns via globalThis stash,
;; reached by (result <run-id>).
::seon.test/sym                   [:string {:seon.db/identity true}]
::seon.test/ns                    :seon.db/ref            ; → :seon.ns
::seon.test/target                :seon.db/ref            ; → :seon.fn
::seon.test/source                :string
::seon.test/last-passed-at        :inst   {:optional true}
::seon.test/last-failed-at        :inst   {:optional true}
::seon.test/last-failure-summary  :string {:optional true}   ; ≤200 chars
::seon.test/last-run-id           :seon.id/id {:optional true} ; pointer into globalThis stash

```

A test is "passing" when `:last-passed-at` is more recent than
`:last-failed-at` (or `:last-failed-at` is absent). No status enum.

### Tx-meta attr for test-run txs

```clojure
::seon.eval/test  :seon.db/ref {:optional true}    ; on test-run txs: → :seon.test

```

"Latest pass" for test T:

```clojure
(d/q '[:find (max ?tx) .
       :in $ ?test
       :where [?tx :seon.eval/test ?test]
              [?tx :seon.eval/ok? true]]
     (d/history db) [:seon.test/sym "seon.trading/analyze-test"])

```

### Agent surface

```clojure
(seon.agent/test 'analyze)        ; run tests targeting fn 'seon.<ns>/analyze
(seon.agent/test 'analyze-test)   ; run one specific test by name
(seon.agent/tests)                ; run all tests in current ns
(seon.agent/tests {:seon.ns/name 'seon.foo})    ; run all tests in a specific ns

```

All return a Promise resolving to the run result. Internally wraps
`seon.test.runner/run-and-record!` (shipped on the platform track
2026-05-22); the agent doesn't call the runner directly.

### Auto-run on defn change via `d/listen!`

A `d/listen!` registered on the agent conn watches for `:seon.fn`
asserts. When a fn entity is asserted (via detect-and-tee on a
defn), the listener queries tests targeting that fn (reverse ref
via `:seon.test/target`) and calls
`seon.test.runner/run-and-record!` for each.

```clojure
(d/listen! @!conn :auto-run-tests
  (fn [{:keys [tx-data db-after]}]
    (let [fn-asserts (->> tx-data
                          (filter (fn [[_ a _ _ added?]]
                                    (and added? (= a :seon.fn/sym)))))]
      (doseq [[fn-eid _ _ _ _] fn-asserts]
        (let [tests (d/q '[:find [?t ...]
                           :in $ ?fn
                           :where [?t :seon.test/target ?fn]]
                         db-after fn-eid)]
          (doseq [test-eid tests]
            (seon.test.runner/run-and-record!
              {:seon.test.runner/vars [(test-sym->var (d/pull db-after '[:seon.test/sym] test-eid))]})))))))

```

The listener callback runs after commit (datahike
`writer.cljc:130`), so the agent never sees stale state. The
test-run tx carries `:tx-meta {:seon.eval/test [:seon.test/sym
"..."]}` for the latest-pass query above.

### Failing-test warning predicate

Default warning predicate registered with `warnings-section` (see
below):

```clojure
(defn failing-test-warning
  [{:seon.db/keys [db]}]
  (let [;; Find tests whose latest run was a failure
        failing (d/q '[:find ?sym ?summary
                       :where [?t :seon.test/sym ?sym]
                              [?t :seon.test/last-failed-at ?failed]
                              [?t :seon.test/last-failure-summary ?summary]
                              (or-join [?t ?failed]
                                [(missing? $ ?t :seon.test/last-passed-at)]
                                (and [?t :seon.test/last-passed-at ?passed]
                                     [(< ?passed ?failed)]))]
                     db)]
    (for [[sym summary] failing]
      {:seon.warning/severity :warn
       :seon.warning/text     (str "test " sym " failing: " summary)})))

```

### Untested-fn warning predicate

```clojure
(defn untested-fn-warning
  [{:seon.db/keys [db] :seon.agent/keys [id]}]
  (let [current-ns (or (:seon.agent/current-ns
                         (d/pull db '[:seon.agent/current-ns] [:seon.agent/id id]))
                       (seon.agent/home-ns id))
        untested (d/q '[:find ?sym
                        :in $ ?ns
                        :where [?fn :seon.fn/sym ?sym]
                               [?fn :seon.fn/ns ?ns]
                               (not [?test :seon.test/target ?fn])]
                      db [:seon.ns/name current-ns])]
    (for [[sym] untested]
      {:seon.warning/severity :info
       :seon.warning/text     (str sym " has no test")})))

```

## Warnings tile — additional predicates

The `warnings-section` mechanism + the `slow-eval-warning` predicate
ship in v1 (see [v1.md §5.2](v1.md#52-the-six-default-sections)).
V2 adds two more predicates that depend on the `:seon.test` entity:

| Predicate | Severity | Triggers when | Data source |
|---|---|---|---|
| `failing-test-warning` | `:warn` | `:seon.test/last-failed-at` > `:last-passed-at` (or `:last-passed-at` absent) | `:seon.test/*` projection attrs |
| `untested-fn-warning` | `:info` | `:seon.fn` entity has no `:seon.test/target` pointing at it | program graph reverse-ref query |

Implementation:

```clojure
(defn failing-test-warning
  [{:seon.db/keys [db]}]
  (let [failing (d/q '[:find ?sym ?summary
                       :where [?t :seon.test/sym ?sym]
                              [?t :seon.test/last-failed-at ?failed]
                              [?t :seon.test/last-failure-summary ?summary]
                              (or-join [?t ?failed]
                                [(missing? $ ?t :seon.test/last-passed-at)]
                                (and [?t :seon.test/last-passed-at ?passed]
                                     [(< ?passed ?failed)]))]
                     db)]
    (for [[sym summary] failing]
      {:seon.warning/severity :warn
       :seon.warning/text     (str "test " sym " failing: " summary)})))

(defn untested-fn-warning
  [{:seon.db/keys [db] :seon.agent/keys [id]}]
  (let [current-ns (or (:seon.agent/current-ns
                         (d/pull db '[:seon.agent/current-ns] [:seon.agent/id id]))
                       (seon.agent/home-ns id))
        untested (d/q '[:find ?sym
                        :in $ ?ns
                        :where [?fn :seon.fn/sym ?sym]
                               [?fn :seon.fn/ns ?ns]
                               (not [?test :seon.test/target ?fn])]
                      db [:seon.ns/name current-ns])]
    (for [[sym] untested]
      {:seon.warning/severity :info
       :seon.warning/text     (str sym " has no test")})))
```

Both registered via the existing v1 `(seon.agent/register-warning!
'seon.agent/failing-test-warning)` pattern at substrate boot.

## Blob storage — content-addressed archival

Big content (rendered turn prompts, full eval results, ingested
docs) gets a dedicated subsystem. The three-tier storage rule is
fully restored: DB has only the projection (hash + metadata); bytes
live on disk.

### Schema

```clojure
;; Metadata in datahike — small, indexed, queryable.
::seon.blob/hash    [:string {:seon.db/identity true}]   ; sha256 hex (44-char base64url alt)
::seon.blob/size    :long                                ; bytes uncompressed
::seon.blob/mime    :string {:optional true}             ; "text/plain" / "application/edn" / "application/pdf" / etc.
::seon.blob/at      :inst                                ; first-write timestamp

```

### On-disk layout

Bytes at `<pod-data>/blobs/<hash[:2]>/<hash>.zst`, zstd-compressed.

**Hex fanout rationale:** the first 2 hex chars of the SHA-256
hash give 256 dirs. At realistic blob counts (10K – 1M blobs total
per pod over a long agent lifetime), the fanout keeps any single
directory under ~5K files. Filesystem perf stays linear; no
performance cliff at high blob counts.

**Zstd compression:** LLM prompts compress 4–10× because of repeated
boilerplate (system-section text is nearly identical turn-to-turn).
Storage cost is roughly bytes_uncompressed / 6 in practice.

### API

```clojure
(seon.blob/put! {:seon.blob/content "..." :seon.blob/mime "text/plain"})
;; => hash string. Idempotent on duplicates: if a blob with this
;; hash already exists, the file is NOT rewritten and the metadata
;; entity is NOT re-transacted; the existing hash is returned.

(seon.blob/get hash)
;; => decompressed content (or string when mime is text/*). Throws
;; if the on-disk file is missing — DB metadata and disk are
;; intended to be in sync; "metadata without bytes" is an error to
;; surface, not paper over.

(seon.blob/ref-by hash)   ; => [:seon.blob/hash "..."] lookup ref ready for transact

```

### Where v2 uses it

#### Turn prompt-blob — replaces v1's inline `:seon.turn/prompt-text`

V1 stored the rendered prompt inline as `:seon.turn/prompt-text :string`
(~20–50 KB per turn × thousands of turns = real DB growth that hurts).
V2 replaces with:

```clojure
::seon.turn/prompt-blob :seon.db/ref {:optional true}    ; → :seon.blob

```

Composer change:

```clojure
;; v1 (inline)
{:seon.render/text text :seon.turn/prompt-text text}

;; v2 (blob)
{:seon.render/text text
 :seon.turn/prompt-blob (seon.blob/ref-by
                          (seon.blob/put! {:seon.blob/content text
                                           :seon.blob/mime    "text/plain"}))}

```

Playback pull shifts from `:seon.turn/prompt-text` (inline string) to
walking `:seon.turn/prompt-blob` → `(seon.blob/get hash)`.

Because v1 → v2 is a clean break, this isn't a migration; v2 just
starts fresh with the blob-ref shape.

#### Eval result-blob — full result when truncation clips

```clojure
::seon.eval/result-blob :seon.db/ref {:optional true}    ; → :seon.blob

```

Written in the per-form loop when `pr-str` produces a string longer
than the 2 KB truncation cap:

```clojure
(let [full-edn (pr-str raw-result)
      display  (seon.agent/truncate-edn full-edn)]
  (cond-> {:seon.eval/result-edn display}
    (not= full-edn display)
    (assoc :seon.eval/result-blob
           (seon.blob/ref-by
             (seon.blob/put! {:seon.blob/content full-edn
                              :seon.blob/mime    "application/edn"})))))

```

The agent's renderer still shows the truncated `:result-edn`; the
blob is for the observer / playback layer.

#### Agent ingest of large docs

The same primitive is the right tool for the agent's own data work
(processing a 50-page PDF, ingesting a scraped web page, etc.).
Content-addressed by hash, dedupe is automatic.

```clojure
(let [hash (seon.blob/put! {:seon.blob/content pdf-bytes
                            :seon.blob/mime    "application/pdf"})]
  (seon.db/transact!
    {:seon.db/tx-data [{:my.research/paper-id "arxiv-2401.12345"
                        :my.research/source-blob [:seon.blob/hash hash]
                        :my.research/title "..."
                        :my.research/sections [...]}]}))

```

### Three-tier storage rule, fully restored

V2 restores the principle v1 had to compromise on (inline prompt-text):

| Tier | Purpose | v2 examples |
|---|---|---|
| **DB datoms** | Small, indexed projections the renderer reads | `:seon.eval/result-edn` (truncated), `:seon.test/last-failure-summary`, `:seon.message/content` |
| **Blobs** | Persistent full content for cross-session playback / observer | `:seon.turn/prompt-blob`, `:seon.eval/result-blob`, agent-ingested docs |
| **GlobalThis stash** | Volatile per-session live values | `(result <eval-id>)` for raw JS objects, `(result <run-id>)` for test runs |

### Cross-track touchpoint

The pod's CLJS calls `seon.fs/write!` / `seon.fs/read` against the
blob subtree. The `seon:fs/sandbox` WIT interface
(`pod-host/wasm-tauri/src-wit/seon-pod.wit`) needs to expose
read+write to `<pod-data>/blobs/` as a preopened directory. Already
planned in principle by Platform Phase 7; v2 makes it concrete.

### Not in v2

GC / retention. Sweep design — retract metadata + delete file when
no entity refs the hash — deferred to v3 along with per-blob TTL
and cross-pod sharing (S3-backed `seon.blob/*config*`).

## Hard rules

V1 ships only "forms must be parseable" + "datahike append-only."
V2 adds two more.

### Hard rule 2 — Functions must have `:malli/schema`

```clojure
(defn check
  "Structural gate. Reject defns without :malli/schema metadata.
   Returns {:ok? true} or {:ok? false :error \"...\"}."
  [form-source]
  (let [parsed (rewrite-clj.parser/parse-string form-source)
        head (-> parsed :children first :children first :value)]
    (if (= 'defn head)
      (let [meta-map (extract-meta-map parsed)]
        (if (contains? meta-map :malli/schema)
          {:ok? true}
          {:ok? false :error "defn missing :malli/schema metadata"}))
      {:ok? true})))

```

Wired into `eval-batch!` between parse and eval. Rejection lands as
an `:ok? false` eval entry with `:kind :malli-required`.

Already implemented in `src/seon/code.cljc` (Clojure side); v2 wires
the same check into the CLJS eval pipeline.

### Hard rule 3 — Schema redefinitions must be accretive against persisted data

```clojure
(defn check-schema-redefine
  "If (schema/register! ::foo new) would invalidate existing
   [?e ::foo _] datoms, reject with a warning naming the affected
   entities. Accretive changes (add optional key, loosen constraint,
   widen union) go through. Datahike's own find-invalid-schema-updates
   catches valueType / unique changes at the DB layer; this is the
   data-side check."
  [schema-key new-schema db]
  ;; Walk existing datoms with this attr; validate each against the new schema.
  ;; If any fail, return :ok? false with a sample of affected entities.
  ...)

```

Wired into eval-batch's detect-and-tee path: when the form is a
`schema/register!`, run the accretive-check before the transact.
On failure, the eval lands as `:ok? false` with `:kind :schema-non-accretive`.

`seon.schema/unregister!` is the explicit escape hatch — removes the
attr from the registry; existing datoms remain in the DB but lose
validation.

## Message importance

```clojure
::seon.message/important?  :boolean {:optional true}    ; sticky-show in messages tile

```

The `messages-section` (in v1) currently shows last N messages.
V2 adds an "always-show" overlay:

```clojure
(defn messages-section
  [{:seon.db/keys [db] :seon.agent/keys [id ctx-entity]}]
  (let [n         (or (:seon.agent/n ctx-entity) 50)
        recent    (seon.agent/messages {:seon.agent/n n :seon.agent/id id})
        important (seon.agent/messages {:seon.agent/important-only? true :seon.agent/id id})
        merged    (->> (concat important recent)
                       (distinct-by :seon.message/id)
                       (sort-by :seon.message/at))]
    (if (seq merged)
      (str "<messages>\n"
           (str/join "\n" (map format-message-row merged))
           "\n</messages>")
      "")))

```

Agent helper:

```clojure
(seon.agent/mark-important! <message-id>)
;; transacts :seon.message/important? true on the message entity

(seon.agent/unmark-important! <message-id>)
;; retracts :seon.message/important?

```

Use case: pin a user instruction ("for this session, always check
unit tests before claiming done") so it stays visible past the
N=50 recency window.

## Curation verbs

V2 adds `seon.eval/forget!` and `forget-ns!` for the agent's "curate
without accumulating cruft" workflow.

### `forget!` — retract one entity by symbol

```clojure
(seon.eval/forget! 'seon.trading/analyze)
;; 1. Look up entity by identity attr ([:seon.fn/sym "seon.trading/analyze"]).
;; 2. [:db/retractEntity ...] under :tx-meta {:seon.db/eval-id <id>}.
;; 3. ns-unmap the runtime var.
;; 4. Surface dependents (entities whose source references the
;;    forgotten symbol) as warnings on the next render.

```

The retract tx carries the causality bundle via `*tx-context*`.
History retains the retraction; pulling at-as-of an earlier tx
shows the entity as it was.

### `forget-ns!` — retract a whole namespace

```clojure
(seon.eval/forget-ns! :seon.trading)
;; Explicit query for all entities pointing at the ns ref, multi-retract
;; in one tx:
(let [ns-id [:seon.ns/name :seon.trading]
      refs  (d/q '[:find [?e ...]
                   :in $ ?ns
                   :where (or [?e :seon.fn/ns ?ns]
                              [?e :seon.schema/ns ?ns]
                              [?e :seon.test/ns ?ns])]
                 @!conn ns-id)]
  (seon.db/transact!
    {:seon.db/tx-data
     (conj (mapv #(vector :db/retractEntity %) refs)
           [:db/retractEntity ns-id])}))

```

Not a component-cascade — child entities (`:seon.fn`, `:seon.schema`,
`:seon.test`) don't OWN the namespace, so the spec uses explicit
multi-retract.

### D6 — explicit `remove-spec` / `remove-fn` / `remove-test`

Per-kind verbs with clear errors when dependents remain. E.g.
`remove-fn` errors if any `:seon.test/target` points at the fn;
agent has to explicitly chain (or override with `:force? true`).
Per-kind clarity prevents accidental cascades.

## History pruning

`:db/noHistory true` per-attr opt-outs on high-churn agent scalars.
With `:keep-history? true` on the whole conn (v1 precondition), the
history index accumulates retraction datoms for every state change.
For attrs like `:seon.agent/state` (flips `:idle ↔ :running` every
turn), that's per-turn growth forever.

Apply via `:seon.db/no-history?` bridge property (translates to
datahike's `:db/noHistory true` in the schema bridge at
`db/datahike/schema.clj`):

```clojure
;; Add these props to v2 schema registrations
(schema/register! :seon.agent/state
  [:enum :idle :running] {:seon.db/no-history? true})
(schema/register! :seon.agent/current-ns
  :keyword {:optional true :seon.db/no-history? true})
(schema/register! :seon.session/turn-count
  :long {:seon.db/no-history? true})
(schema/register! :seon.session/turns-since-user
  :long {:seon.db/no-history? true})

```

Bridge work: add `:seon.db/no-history?` handler to
`seon-db-props->db-props` in `src/seon/db/datahike/schema.clj`
(~107-114), translating to `:db/noHistory true`.

## Reference-graph attrs

D8 — explicit refs between fns, fns and schemas, tests and fns.

```clojure
::seon.fn/refs         [:vector :seon.db/ref]   ; → other :seon.fn this fn calls
::seon.fn/input-spec   :seon.db/ref             ; → :seon.schema
::seon.fn/output-spec  :seon.db/ref             ; → :seon.schema

```

Populated by detect-and-tee in `eval-batch!`: when teeing a `:seon.fn`
entity, walk the parsed AST extracting var references. Use
cljs.analyzer's compile-state which already has the AST per defn
(`(get-in @compile-state [:cljs.analyzer/namespaces ns :defs fn :body])`)
— no separate walk needed.

### Enables

- **Transitive test auto-run.** Currently (in the simple D4 hook),
  re-running tests fires only when a fn IS the target. With
  `:seon.fn/refs`, we can also fire tests targeting any fn that
  calls the changed fn (transitively).
- **`related-ns-section`.** "Namespaces the current ns references."
  Walk `:seon.fn/refs` from fns in current-ns, group by target ns,
  signature-only.
- **"Who depends on X?"** Reverse-ref pull on `:seon.fn/refs` from
  any fn entity.

## Per-entity dispatch

A `seon.render` namespace + a Malli-specificity dispatch system.
Section fns can `(render entity)` and get the most specific renderer
for whatever shape `entity` has. Strictly additive — section fns
still return strings.

The CLJ side of seon already has this
(`src/seon/render.clj` — `find-renderer` at L133, `resolve-renderer`
at L202, `namespace-proximity` tiebreak at L112). V2 lifts that
dispatch into the CLJS pod.

```clojure
;; Renderers are fns with :malli/schema output matching :seon.render/ai
(defn ^{:malli/schema [:=> [:cat [:map [:seon.trading/ticker :string]]] :seon.render/ai]}
       render-ticker
  [{:seon.trading/keys [ticker]}]
  (str "<ticker symbol=\"" ticker "\"/>"))

;; Section fns call (render entity) and dispatch finds render-ticker
;; based on input keys + ns proximity.

```

## Per-section HTML composer

V1 ships per-section composability on the AI surface only — section
fns return `{:seon.render/text "..."}` and the composer joins those
strings into `:seon.turn/prompt-text` for the LLM. The HTML surface
in v1 stays whole-tile: one `:seon.render/html` symbol per agent
entity, resolved by the broadcast pipeline on every DB tx.

**V2 mirrors the AI composer on the HTML side without adding a new
`:seon.ctx` slot.** A section IS its fn; the section's fn return
shape grows additional `:seon.render/*` keys. One section, one fn,
multiple output surfaces. Each composer reads the key it cares
about; sections that don't support a given surface just don't
include that key.

### Section return shape

```clojure
;; Already in v1 — single-key instance:
(schema/register! :seon.render/ai-response
  [:map [:seon.render/text :string]])

;; V2 generalizes to a multi-surface response. Existing v1 returns
;; are a valid subset (text only); v2 fns add :hiccup, future fns
;; add :canvas.
(schema/register! :seon.render/section-response
  [:map
   [:seon.render/text   {:optional true} :string]
   [:seon.render/hiccup {:optional true} :any]
   [:seon.render/canvas {:optional true} :seon.render/canvas]])

;; A section fn that supports text + html on the same call:
(defn recent-evals-section
  {:malli/schema [:=> [:cat :seon.render/system-input]
                  :seon.render/section-response]}
  [{:seon.db/keys [db] :seon.agent/keys [id]}]
  (let [evals (recent-evals db id 20)]
    {:seon.render/text   (format-evals-text   evals)
     :seon.render/hiccup (format-evals-hiccup evals)}))
```

A section can return one key, two, or three. The AI composer reads
`:seon.render/text`; the HTML composer reads `:seon.render/hiccup`;
when Canvas lands, the canvas composer reads `:seon.render/canvas`.
**A section that omits a surface's key just skips on that composer.**

The `:seon.ctx` entity schema does **not** change from v1.

### Forward compat with v1

V1 section fns return `{:seon.render/text "..."}`. That's already
the single-key instance of the v2 return shape — **zero schema
change to `:seon.ctx`, zero data migration.** V1 agents that boot
against v2 substrate keep working: their sections compose text-only
on the LLM side and hit the HTML fallback (below) on the UI side.

### HTML composer

```clojure
(defn ctx-html
  "Walks :seon.agent/ctx in priority order. For each section, calls
   :seon.ctx/fn once, reads :seon.render/hiccup if present, otherwise
   falls back to wrapping :seon.render/text in <pre>. Assembles
   whole-tile hiccup."
  {:malli/schema [:=> [:cat :seon.render/system-input]
                  :seon.render/html-response]}
  [{:seon.db/keys [db] :seon.agent/keys [id] :as input}]
  (let [sections (->> (pull-ctx db id)
                      (sort-by :seon.ctx/priority))
        children (keep (fn [{:seon.ctx/keys [name fn]}]
                         (let [resp ((render/resolve-symbol fn) input)]
                           (or (:seon.render/hiccup resp)
                               (when-let [text (:seon.render/text resp)]
                                 [:section {:data-ctx-section
                                            (clojure.core/name name)}
                                  [:pre {:class "text-xs whitespace-pre-wrap"}
                                   text]]))))
                       sections)]
    {:seon.render/hiccup
     (into [:div {:id (str "agent-" id)}] children)}))
```

Each section's call is independent — one section throwing doesn't
take down the tile (composer wraps each call in try/catch and emits
an error fragment in that section's place, same isolation rule
`broadcast.cljs` uses for whole-tile errors today).

The fallback (no `:seon.render/hiccup` → wrap `:seon.render/text`
in `<pre>`) **IS the day-one debug view from v1.md §5.4**, applied
automatically per-section. An agent that hasn't extended any
section fn to return hiccup still sees usable per-section UI —
same sections the LLM sees, each in its own labeled block.

### Six default sections grow HTML output

The v1 default sections (`system`, `messages`, `current-ns`,
`warnings`, `recent-evals`, `prompt`) ship in v2 substrate
returning **both** `:seon.render/text` and `:seon.render/hiccup`
from the same fn. The text branch is unchanged from v1; the hiccup
branch is new.

| Section | Hiccup shape |
|---|---|
| `system` | Static block: home-ns, agent-id, install order |
| `messages` | Scrollable list of user/assistant bubbles |
| `current-ns` | Linked symbol list (anchors to ns view) |
| `warnings` | Severity-colored list |
| `recent-evals` | Eval rows with collapsible source/result |
| `prompt` | Open prompt text (or empty if no open turn) |

### Customization

To add HTML to a section the agent had been rendering text-only:
edit the section fn to additionally return `:seon.render/hiccup` in
its response map. No schema change, no new ctx entity, no
retract-then-add.

```clojure
;; Before — text only
(defn my-section [input]
  {:seon.render/text "..."})

;; After — text + html
(defn my-section [input]
  {:seon.render/text   "..."
   :seon.render/hiccup [:section "..."]})
```

The HTML composer reads the new key on the next render tick.

### Per-agent ownership preserved

The composer is whole-tile from the broadcast listener's
perspective — `seon.web.broadcast` resolves the agent's
`:seon.render/html` slot and calls it once per tx. The default v2
substrate sets that slot to `'seon.render.default/ctx-html`; the
per-section walking happens inside `ctx-html`. Agents that want a
completely different layout (drop the section model entirely,
hand-write the tile) override the `:seon.render/html` slot
directly, same v1 escape hatch.

Multi-agent + multi-view is unchanged — same SSE fan-out, same
morph-by-id, same per-agent tile. Nothing about adding the HTML
composer changes the broadcast pipeline or the `:seon.ctx`
schema.

### Canvas as the third surface — same pattern

When the dynamic-context-and-canvas PRD graduates from research,
sections grow `:seon.render/canvas` in the same return map. The
canvas composer mirrors `ctx-html`: walk sections, collect command
lists from `:seon.render/canvas` keys, assemble into a whole-tile
draw program, broadcast over a dedicated SSE event type the webview
JS replays into a `<canvas>` element. **No new schema slot, no new
section model, no `:seon.ctx/canvas-fn`** — just one more optional
key in the return shape.

## Related-ns-section

```clojure
(defn related-ns-section
  "Symbols from namespaces referenced by the current ns. Signature-only."
  [{:seon.db/keys [db] :seon.agent/keys [id]}]
  (let [current-ns (or (:seon.agent/current-ns
                         (d/pull db '[:seon.agent/current-ns] [:seon.agent/id id]))
                       (seon.agent/home-ns id))
        ;; Walk :seon.fn/refs from current ns's fns to other nses
        related (compute-related-ns db current-ns)
        rows    (for [other (sort related)
                      fn-row (->> (d/pull db
                                    '[{:seon.fn/_ns [:seon.fn/sym]}]
                                    [:seon.ns/name other])
                                  :seon.fn/_ns)]
                  (str "  " (:seon.fn/sym fn-row)))]
    (if (seq rows)
      (str "<related-namespaces>\n" (str/join "\n" rows) "\n</related-namespaces>")
      "")))

```

Default section priority 25 (between `messages` 20 and `current-ns` 30).
Requires `:seon.fn/refs` (above).

## Tufte profiling

V1 ships always-on `:duration-ms` per eval (cheap; two `Date.now()`
calls). V2 adds **opt-in deep profiling** via Tufte.

The hook point is the existing `:seon.dev/instrumentation` Integrant
layer that wraps every `:malli/schema`-annotated public fn for
runtime validation; when profiling is enabled, the same wrapper
additionally wraps each fn with `(taoensso.tufte/p ::ns/name body)`.

```clojure
;; Enable for a window
(seon.perf/set-enabled! true)
;; ... do work ...
(seon.perf/set-enabled! false)
(seon.perf/last-stats)   ; accumulated tufte/PStats

;; Or scope-locally
(seon.perf/with-profiling
  (assemble-ctx input))
;; => {:value <result> :stats #tufte/PStats {...}}

```

### `perf-section`

```clojure
(defn perf-section
  [_input]
  (let [stats (seon.perf/last-stats)]
    (if stats
      (str "<perf>\n"
           (tufte/format-pstats stats {:columns [:n :sum :mean :p90]})
           "\n</perf>")
      "")))

```

Off by default. Agent transacts a `:perf` ctx entity when they're
optimizing; removes it when they're not.

## Context token budgeting

Per-section budgets + composer enforcement + rendered token-usage footer.

### Schema additions

```clojure
::seon.agent/context-budget  :long {:optional true}      ; total token budget; default 8000
::seon.ctx/max-pct           :double {:optional true}    ; % of total-budget (0.0–1.0)
::seon.ctx/max-tokens        :long   {:optional true}    ; absolute cap; takes precedence over max-pct
::seon.turn/ctx-budget       [:map-of :keyword :long] {:optional true}
                             ; {:section-name token-count, ..., :_total N, :_budget N}

```

### Composer becomes budget-enforcing

Section fns receive budget as an extra arg:

```clojure
(defn section-fn [ctx-in budget] ...)   ; budget = long, or nil for unlimited

```

The section is responsible for fitting; composer tail-cuts as a
safety net if the fn ignores its budget. Per-section truncate
policy is fn-internal (recent-evals drops oldest, current-ns
switches to signatures-only, messages drops oldest non-important,
etc.).

### Token-usage footer

Rendered at the end of every prompt:

```text
<ctx-budget>
  :system           312 tokens   3.9%  (budget 800)
  :messages        1284 tokens  16.1%  (budget 1600)
  :current-ns      2401 tokens  30.0%  (budget 2400)   ← overshoot
  :recent-evals    1872 tokens  23.4%  (budget 2000)
  :warnings          45 tokens   0.6%  (budget 800)
  :prompt            20 tokens   0.2%  (budget 400)
  total            5934 tokens  74.2% of 8000 budget
</ctx-budget>

```

The footer data ALSO persists on `:seon.turn/ctx-budget` so observers
can index "which turns were context-pressured."

### Token counting

Cheap approximation: `(quot (count text) 4)` (~4 chars per token for
English / Clojure source). The approximation drifts ~10% which is
fine for budget-policy decisions. v3 may swap in `js-tiktoken` if
drift matters.

### Helpers

```clojure
(seon.agent/set-budget!       {:seon.ctx/name :recent-evals :seon.ctx/max-pct 0.15})
(seon.agent/set-total-budget! 16000)   ; override :seon.agent/context-budget

```

## Dependency notes

- D4 transitive hardening **requires** `:seon.fn/refs` (this doc above).
- `seon.render` per-entity dispatch **requires** `:seon.fn/refs` to find
  candidate renderers via Malli output-spec.
- Per-section HTML composer is **independent**; only depends on
  the v1 `:seon.ctx` schema + the broadcast pipeline both already
  shipping. Can ship before or after per-entity dispatch.
- `related-ns-section` **requires** `:seon.fn/refs`.
- Auto-run test on defn change **requires** test entity + program graph
  and `d/listen!` (all in this doc).
- Budget enforcement is independent; can ship in any order.
- Blob storage is independent; can ship in any order.
- Forget verbs **require** program graph (entities to retract).

## What v2 explicitly does NOT ship (defers to v3)

- Cross-agent collaboration (multi-agent shared DB protocols).
- Older-DB-on-newer-runtime upgrade (D1) — v2 → v3 is also a clean
  break unless we explicitly invest in migration tooling.
- Blob GC / retention (D12).
- Cross-pod blob sharing (S3-backed `seon.blob/*config*`).
- Replay UI (browser-side transcript walker).

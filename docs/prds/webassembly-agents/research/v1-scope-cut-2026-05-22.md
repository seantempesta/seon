# v1 scope-cut — final shape — 2026-05-22

Outcome of the scope-cut conversation. v1 ships the minimum needed to
get an agent loop running against deepseek with persistence-across-
restart. v2/v3 are clean breaks — different schemas, different
database if needed. No backward-compat machinery between versions.

## TL;DR

- **Persistence by eval replay.** No program graph entities in v1.
  `:seon.eval/source` carries the form text; resume walks successful
  evals in tx order and re-evals each. Accepts that 1000 turns of
  history replays 1000 forms to rebuild ~100 live entities on boot.
  Trade simplicity for runtime cost; v2 can do it differently.
- **Composable ctx via `:seon.ctx` entities in DB.** Keep the full
  composer dispatch surface — sections are entities, `:seon.agent/ctx`
  is a multi-ref, composer reads them in priority order, resolves
  `:seon.ctx/fn`, joins strings. This is the agent's primary
  customization surface.
- **6 default sections in v1:** `system`, `messages`, `current-ns`,
  `warnings`, `recent-evals`, `prompt`. `current-ns` uses
  `cljs.analyzer` compile-state, not program-graph entities.
  `warnings` uses causality-graph-only predicates, not test/program
  data.
- **No blobs in v1.** No `:seon.turn/prompt-blob`, no
  `:seon.eval/result-blob`. Literal-prompt playback defers to v2.
  Results are truncated 2KB on the eval entity; no overflow store.
- **No test entity, no auto-run, no agent test helpers.** Defers to
  v2 alongside the program graph.
- **No `forget!`, no `:important?`, no `:db/noHistory` per attr, no
  `:malli/schema` gate, no slow-eval predicate.** All v2.
- **v2 can be a clean break.** Different schemas, different conn.
  We're optimizing for "get the agent running and iterate," not for
  smooth migration.

## What v1 ships — the agreed shape

### Causality graph schema (the spine)

```clojure
;; Shared id schema.
::seon.id/id  [:string {:min 12 :max 12}]   ; 12-char base62

;; Agent — root of one agent's lived history.
::seon.agent/id           [::seon.id/id {:seon.db/identity true}]
::seon.agent/state        [:enum :idle :running]
::seon.agent/current-ns   :keyword {:optional true}
::seon.agent/sessions     [:vector :seon.db/ref {:seon.db/component true}]   ; → :seon.session
::seon.agent/ctx          [:vector :seon.db/ref {:seon.db/component true}]   ; → :seon.ctx

;; Session — one pod run.
::seon.session/id               [::seon.id/id {:seon.db/identity true}]
::seon.session/at               :inst
::seon.session/turn-count       :long
::seon.session/turns-since-user :long
::seon.session/turns            [:vector :seon.db/ref {:seon.db/component true}]   ; → :seon.turn

;; Turn — render → LLM → parse → eval-batch cycle.
::seon.turn/id       [::seon.id/id {:seon.db/identity true}]
::seon.turn/index    :long
::seon.turn/at       :inst
::seon.turn/status   [:enum :running :done :error]
::seon.turn/messages [:vector :seon.db/ref {:seon.db/component true}]    ; → :seon.message
::seon.turn/evals    [:vector :seon.db/ref {:seon.db/component true}]    ; → :seon.eval
;; NO :seon.turn/prompt-blob in v1.

;; Message — user/assistant/system.
::seon.message/id      [::seon.id/id {:seon.db/identity true}]
::seon.message/role    [:enum :user :assistant :system]
::seon.message/content :string
::seon.message/at      :inst
;; NO :seon.message/important? in v1.

;; Eval — the load-bearing entity. Source is here; resume replays from here.
::seon.eval/id          [::seon.id/id {:seon.db/identity true}]
::seon.eval/at          :inst
::seon.eval/duration-ms :long
::seon.eval/ns          :keyword                                ; ns the form left the agent in
::seon.eval/narration   :string {:optional true}                ; ;; comments before the form
::seon.eval/source      :string                                 ; the form text
::seon.eval/ok?         :boolean
::seon.eval/result-edn  :string {:optional true}                ; truncated 2KB
::seon.eval/error       :string {:optional true}                ; flattened :seon.error/data
;; NO :seon.eval/result-blob in v1.
```

### Composable ctx schema (kept in full)

```clojure
::seon.ctx/name     :keyword
::seon.ctx/priority :long
::seon.ctx/fn       :symbol     ; ns-qualified — e.g. 'seon.agent/system-section
```

Composer: pulls `:seon.agent/ctx` (components inline), sorts by
`:seon.ctx/priority`, resolves each `:seon.ctx/fn` via
`seon.agent/resolve-symbol`, calls each fn with
`{:seon.db/db db :seon.agent/id id :seon.agent/ctx-entity section}`,
joins non-empty strings with `\n\n`. Symbol misses fall through to
`pretty-ai`. Empty string suppresses the section.

The composer does NOT persist a prompt-blob in v1 (no blobs).

### Tx-meta causality bundle

```clojure
;; Auto-propagated via seon.db/*tx-context* dynvar.
::seon.db/agent-id       ::seon.id/id
::seon.db/session-id     ::seon.id/id
::seon.db/turn-id        ::seon.id/id
::seon.db/eval-id        ::seon.id/id {:optional true}
::seon.db/origin         [:enum :user :agent :system :replay]
::seon.db/replay?        :boolean {:optional true}
::seon.db/resume-marker? :boolean {:optional true}
```

Every tx in an eval scope carries the bundle; `seon.db/transact!`
merges from the dynvar into `:tx-meta` automatically. Agent conn
opens with `:keep-history? true`; boot precondition asserts this.

### Entities and attrs explicitly NOT in v1

- `:seon.fn`, `:seon.schema`, `:seon.ns`, `:seon.test` — whole program graph deferred.
- `:seon.blob`, `:seon.turn/prompt-blob`, `:seon.eval/result-blob` — whole blob layer deferred.
- `:seon.message/important?` + `mark-important!` — deferred.
- `:seon.eval/test` tx-meta — deferred with tests.
- `:db/noHistory` per-attr opt-out — deferred (history-on for whole conn).
- Detect-and-tee for `defn`/`schema/register!`/`deftest`/`ns` — deferred.
- `:malli/schema` required gate via `seon.code/check` — deferred.
- Schema-accretive rule enforcement at eval time — deferred.

## The 6 default sections

All 6 live in `seon.agent`.

| Name | Priority | Symbol | Data source |
|---|---|---|---|
| `system` | 10 | `'seon.agent/system-section` | static — who-am-i, time, discovery cheat-sheet |
| `messages` | 20 | `'seon.agent/messages-section` | last 50 messages in current session |
| `current-ns` | 30 | `'seon.agent/current-ns-section` | `cljs.analyzer` compile-state for current ns |
| `warnings` | 40 | `'seon.agent/warnings-section` | causality-graph-only predicates (see below) |
| `recent-evals` | 50 | `'seon.agent/recent-evals-section` | last 20 evals in current session |
| `prompt` | 99 | `'seon.agent/prompt-section` | one-line `current.ns=> ; turn N` |

### `current-ns-section` — uses `cljs.analyzer` compile-state

Implementation sketch:

```clojure
(defn current-ns-section
  [{:seon.db/keys [db] :seon.agent/keys [id]}]
  (let [ns       (or (:seon.agent/current-ns
                       (d/pull db '[:seon.agent/current-ns] [:seon.agent/id id]))
                     (seon.agent/home-ns id))
        defs     (get-in @seon.repl/!compile-state
                         [:cljs.analyzer/namespaces ns :defs])]
    (if (seq defs)
      (str "<current-namespace name=\"" ns "\">\n"
           (->> defs
                (sort-by key)
                (map (fn [[sym info]]
                       (format-def-row sym info)))   ; show arglists, doc, schema
                (str/join "\n"))
           "\n</current-namespace>")
      "")))
```

Shows the agent: "in `seon.trading` you have these defs with these
signatures." No source code in this section — source is in
`recent-evals`. Trivial to implement: data is already in
`@!compile-state` in memory.

### `warnings-section` — three default predicates

All powered by causality graph alone; no program graph needed.

| Predicate | Source | Output when triggered |
|---|---|---|
| `recent-errors-warning` | last 3 `:seon.eval/ok? false` evals this session | "Turn N: <error msg>" |
| `long-session-warning` | `:seon.session/turns-since-user > 15` | "20 turns since user input — loop will stop at 20" |
| `no-forms-last-turn-warning` | last assistant message had 0 parsed forms | "Last turn was prose-only; did you mean to eval?" |

Section format:

```clojure
(defn warnings-section
  [input]
  (let [warnings (concat (recent-errors-warning input)
                         (long-session-warning input)
                         (no-forms-last-turn-warning input))]
    (if (seq warnings)
      (str "<warnings>\n"
           (str/join "\n" (map :seon.warning/text warnings))
           "\n</warnings>")
      "")))
```

Agent can register their own predicates in v2 when there's actual
data to derive from. v1 ships these three baked in.

## Boot sequence in v1

```text
boot:
  assert-preconditions!      ; :keep-history? + tx-meta attrs registered
  init-bootstrap!            ; cljs.core analyzer-cache load
  ensure-agent!              ; create :seon.agent entity if absent, with 6 default :seon.ctx sections
  resume-phase!              ; replay successful :seon.eval entries in tx order
  start-session!             ; create :seon.session for this pod run
  render-initial-context!    ; first turn
```

### Preconditions (kept from v1.md)

1. `:keep-history? true` on the agent conn.
2. tx-meta schema attrs registered before first transact.

### Resume phase — eval replay (the simplification)

```clojure
;; Walk successful evals in tx order; re-eval each in its recorded ns.
(let [evals (d/q '[:find ?e ?src ?ns ?tx
                   :where
                   [?e :seon.eval/ok? true ?tx]
                   [?e :seon.eval/source ?src]
                   [?e :seon.eval/ns ?ns]]
                 (d/db conn))]
  (doseq [[_ src ns _] (sort-by #(nth % 3) evals)]
    (binding [seon.db/*tx-context* {:seon.db/origin :replay
                                    :seon.db/replay? true
                                    :seon.db/agent-id agent-id}]
      (try (seon.eval/raw-eval src {:ns ns})
           (catch :default e
             ;; Failed replay → new :ok? false eval entry with :replay? true.
             ;; Agent sees it in next render; nothing is retracted.
             (seon.eval/record-replay-failure! src ns e))))))
```

Trade-off accepted: replaying a long history of forms on boot to
rebuild a small live state is wasteful. v1 takes the hit for
implementation simplicity. v2 likely introduces snapshots, a real
program graph, or both.

`run-turn!` is the unit (was `run-turn-once!` in V0 — rename

## Acceptance criteria — v1

Revised from the original 14. Items match what v1 actually delivers:

1. Default rendered context shows 6 sections (empty ones suppressed),
   with current pod-time and discovery cheat-sheet in `system`.
2. Eval a multi-form batch including `schema/register!`, `defn`,
   `deftest`. Each form lands as an `:seon.eval` entry with
   `:duration-ms`, `:source`, `:ns`. The `(defn ...)` becomes a live
   var via `cljs.js`; the `(schema/register! ...)` registers in
   Malli; the `(deftest ...)` registers in cljs.test. **No
   `:seon.fn`/`:seon.schema`/`:seon.test` entities** in the DB.
3. Multi-line `;;` markdown between forms lands as
   `:seon.eval/narration` on the next form. Trailing `;;` after the
   last form lands as a thinking-only eval entry.
4. Bare symbol that resolves: see value. Bare symbol that doesn't:
   see unbound-symbol error via `*cljs-warning-handlers*`.
5. Partial success: 10 forms, 1 fails → 9 successes persisted, 1
   error reported.
6. `(in-ns 'seon.foo)` mid-batch; subsequent forms land in
   `seon.foo`; `:seon.agent/current-ns` updates; next-turn render
   focuses on `seon.foo`.
7. Agent calls `(cljs.test/run-tests 'seon.foo)` directly. Test
   results appear in the eval result; no auto-run, no warnings tile
   integration. (Tests-as-feedback story is v2.)
8. Rewrite a section function (transact a different `:seon.ctx/fn`
   symbol on the section entity). See the new rendering on the next
   turn.
9. `(seon.agent/reset-ctx!)` restores the 6 substrate defaults.
10. Restart the pod. All prior successful evals replay in tx order;
    `seon.trading/analyze` is a live var again. Prior sessions'
    turns retained in `:seon.agent/sessions`. New `:seon.session`
    opens for current pod run.
11. Causality-graph playback: `(d/pull db '[* {:seon.turn/messages
    [*] :seon.turn/evals [*]}] [:seon.turn/id "T..."])` returns
    everything the LLM said + every form that ran. **Literal-prompt
    playback is NOT in v1** — composer doesn't persist
    `:seon.turn/prompt-blob`.

Acceptance lost vs. original v1.md: auto-test-on-redefine, test
status surfaces, `forget!`, break-section-fn-pretty-ai-engages,
literal-prompt observer playback. All v2+.

## What v2/v3 inherit

**v2 is a clean break.** Different schemas allowed, possibly a new
database. No backfill migration from v1 sessions.

Candidate v2 features (none commit v1 to anything):

- Program graph (`:seon.fn`, `:seon.schema`, `:seon.ns`, `:seon.test`)
  with detect-and-tee. Resume via program graph instead of eval
  replay.
- Test entity + `d/listen!` auto-run + `seon.agent/test` helpers +
  warnings predicate for untested fns / failing tests.
- `seon.blob` content-addressed archival. `:seon.turn/prompt-blob` +
  `:seon.eval/result-blob` for full playback. Blob dir into the WIT
  fs allowlist.
- `:malli/schema` required gate via `seon.code/check`.
- Schema-accretive enforcement at eval time.
- `:seon.message/important?` + `mark-important!`.
- `seon.eval/forget!` + `forget-ns!`.
- `:db/noHistory true` on high-churn agent scalars.
- `slow-eval-warning` + agent-registered warning predicates.
- Token-budget enforcement + per-section truncation + ctx-budget
  footer.
- `seon.render` namespace + per-entity Malli-specificity dispatch.

**v3 inherits from v2** — cross-agent collab, older-DB-newer-runtime
upgrades, blob GC, cross-pod blob sharing.

### Gemini's three open questions to Sean (verbatim)

> 1. **Eval Replay for Resume Phase**: Instead of building and maintaining a persistent program graph (`:seon.fn`, `:seon.schema`, `:seon.ns`) with AST "detect-and-tee" logic, we can achieve survival-across-restart by simply replaying successful `:seon.eval` forms chronologically on boot.
>    * *Trade-off*: Replaying a large history of forms on startup could introduce a 5-15 second boot delay after 1,000+ turns, but it reduces the codebase surface area by more than 50% immediately. **Is this startup latency acceptable for V1?**
> 2. **Hardcoded Context Layout**: Deferring the `:seon.ctx` section entities and configuration to v2. The composer will instead render a static list of the default sections (`:system`, `:messages`, `:recent-evals`, `:prompt`). **Do you agree with hardcoding the section layout for the initial release?**
> 3. **Malli Schema Gate**: We propose deferring the requirement that functions must have `:malli/schema` (gated by `seon.code/check` at eval-time) to v2. **Is it acceptable to allow standard Clojure definitions without schema validation in v1?**

### Sean's resolutions (summary)

1. **Eval replay: YES** for v1 (accepts the inefficiency for simplicity).
2. **Hardcoded layout: NO** — keep `:seon.ctx` entities + composer dispatch. Composable ctx is a v1 surface.
3. **Malli gate: YES, defer to v2** — `seon.code/check` not wired in v1.

Additional resolutions from the cut conversation:

- `current-ns-section` kept in v1; data source is `cljs.analyzer` compile-state, not program graph.
- `warnings-section` kept in v1; predicates are causality-graph-only (recent errors, long session, no-forms-last-turn) — no test/program data.
- Blobs deferred entirely (no `:seon.turn/prompt-blob`, no `:seon.eval/result-blob`). Literal-prompt playback is v2.
- `:seon.message/important?` deferred.
- `forget!`/`forget-ns!` deferred.
- `:db/noHistory` per-attr deferred (conn-level history-on suffices).
- Tests deferred (no entity, no auto-run, no agent helpers).
- v1 → v2 transitions can be clean breaks. No backfill migration tooling.
- `run-turn-once!` renamed to `run-turn!` everywhere in cleanup pass.

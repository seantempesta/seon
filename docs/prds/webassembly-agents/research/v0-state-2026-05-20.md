# V0 CLJS pod — state snapshot (2026-05-20)

Branch: `webassembly-agents`. This doc captures what the seon CLJS pod
**is** at the end of Phase 1 hardening, immediately before the Phase 3
WASM-Tauri build starts. Update this file whenever the substrate shape
changes.

## What the pod is

A long-running Node process that hosts:

- Agent loop with REPL-style eval (`seon.eval` + bootstrap-CLJS)
- In-memory datahike-cljs database with idents + schema for `:seon.agent/*`, `:seon.message/*`, `:seon.eval/*`, `:seon.log/*`, `:seon.render/*`
- HTTP+SSE server on a loopback port (default 7890)
- DeepSeek HTTP client (`seon.ai.deepseek`)
- Default-deny filesystem capability (`seon.fs`)
- Per-form wall-clock eval timeout (`seon.eval/!timeout-ms`, default 10s; override via `seon.eval/budget`)
- Per-call DeepSeek HTTP timeout (`seon.ai.deepseek/!timeout-ms`, default 60s)
- Tx-listener broadcast to SSE clients (`seon.web.broadcast`)
- Hot-reload hygiene on listeners (re-recompiling broadcast or agent doesn't double-fire)

## Security posture (read carefully)

**The CLJS-layer sandbox is NOT a security boundary.** Every guard in
the pod lives in JavaScript that `cljs.js` eval can read and mutate:

- `seon.fs/!config` allowlist — bypassable via `(reset! seon.fs/!config ...)` or `(js/require "node:fs")`
- `seon.eval/!timeout-ms` — bypassable via `(reset! seon.eval/!timeout-ms 0)`
- `seon.ai.deepseek/!timeout-ms` — same

What this layer DOES catch:

- LLM emitting an absolute path with `..` traversal → `seon.fs` normalizes via `path.resolve` and denies
- LLM calling `seon.fs/write-file` against a path outside `:seon.fs/allowed-roots` → deny envelope
- A form that hangs on a never-resolving Promise → timeout-sentinel kicks the auto-await, agent loop continues
- A DeepSeek API hang → AbortController fires, turn fails cleanly

What it does NOT catch:

- LLM that decides to call `(js/require "node:fs/promises")` and `unlink` your home dir
- LLM that resets the timeout atom to 0 and infinite-loops the event loop
- LLM that uses `(js/require "child_process")` to spawn `rm -rf /`

The fix is the WIT-typed boundary at the Rust host (Phase 3 —
`docs/seon/pod/wasm-spike-2026-05-20.md`). Until that ships, the pod is
"trusted code"-grade, not "agent-code"-grade.

## Configuration knobs

| Knob | How | Default |
|---|---|---|
| `:seon.fs/allowed-roots` | `(seon.fs/configure! {...})` or `SEON_FS_ROOT` env | `[]` (deny-all) |
| `:seon.fs/read-only?` | same; or `SEON_FS_READ_ONLY=1` env | `false` (unless env set) |
| Eval timeout (default) | `(seon.eval/set-timeout-ms! n)` or `(reset! seon.eval/!timeout-ms n)` | 10000 |
| Eval timeout (one form) | `(seon.eval/budget 60000 (slow-op))` | falls back to default |
| DeepSeek timeout | `(seon.ai.deepseek/set-timeout-ms! n)` | 60000 |
| HTTP server port | `SEON_PORT` env | 7890 (0 = ephemeral) |
| Port file location | `SEON_PORT_FILE` env | `tmp/seon-port` |
| Auto-boot agent | `SEON_NO_AUTO_BOOT=1` skips it | unset (boots by default) |
| LLM choice | `DEEPSEEK_API_KEY` env present → real LLM; absent → stub | stub |

## Not in this pod (and why)

- **No consumer-product code.** No `:seon.note/*` schema, no markdown
  walkers, no "the user's wiki" framing. Removed 2026-05-20 (commit
  `21724b3`) because seon is the substrate, not a demo.
- **No JVM seat coupling.** The CLJS pod doesn't talk to the older
  `src/seon/*.clj` substrate. Those files still exist (paused
  Datalevin/Integrant work) but aren't loaded by the CLJS build.
- **No worker_thread sandbox.** Originally Phase 2 plan, but skipped:
  worker_threads gives bounded blast radius but isn't a real security
  boundary per Node docs. WASM-Tauri (Phase 3) is the destination;
  worker_threads would be wasted intermediate work.

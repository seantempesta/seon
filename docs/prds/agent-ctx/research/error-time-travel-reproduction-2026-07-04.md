# Error time-travel + reproduction — datahike as-of over the wire

Grounding research for the error-blame proposal
([[error-blame-strict-gate-2026-07-03]]): can we restore the DB to the
exact point an error occurred and reproduce the failure? Every claim
below is cited to actual source (fork at `reference-code/datahike`,
seon at `src/seon`).

## TL;DR

1. `as-of`/`since` take a db value + a time-point (int tx-id **or** Date) and
   return a pure wrapper record (`AsOfDB`/`SinceDB`); `history` takes just a db.
   The int time-point is the **tx entity id** (≥ `tx0` = `0x20000000` =
   536870912); datahike has no separate basis-t — `:max-tx` IS the tx eid, and
   that is exactly what `seon.db/basis-t` and `:seon.agent.turn/rendered-as-of`
   store, so the stored int plugs straight into `as-of`.
2. History is ON everywhere active: wire-server store `:keep-history? true`
   (`server/store.clj:120`), pod peer config (`store/wire.cljs:149`), and a
   boot precondition that THROWS if it's off (`db/internal.cljs:1432`).
   `:db/noHistory` per-attr opt-out exists in the fork but seon never sets it.
   GC sweeps stale branch roots only — temporal index keys are marked
   reachable; only explicit `:db/purge` tx ops erase history, and seon never
   issues them.
3. The pod constructs as-of views **locally**: `d/as-of` is
   referentially-transparent (sync alias in CLJS), and `seon.db` already
   exposes `as-of`/`since`/`history`/`basis-t`/`origin-t` — proven by a pod
   test and already prescribed by `seon.ai/resolved-config`'s docstring. No
   wire round-trip needed.
4. Reproduction recipe: `(db/as-of (:seon.agent.turn/rendered-as-of turn))` →
   re-render via `seon.agent.inspect/turn` or re-invoke the fn. Gaps: the
   malli envelope stores only the FAILING arg (`got-edn`), not the full arg
   vector; errors outside a turn carry no captured basis-t today.
5. `cljs.stacktrace` (.cljc, in the pod's cljs dep) parses V8/Node stack
   strings into `{:file :function :line :column}` frame maps with no source
   maps; `seon.error/->map` currently stores the raw string truncated to 4 kb.

## 1. Time-travel API surface

### The public fns and their signatures

`datahike.api` is generated by the `emit-api` macro from
`datahike.api.specification/api-specification`
(`reference-code/datahike/src/datahike/api.cljc:58-83`). The temporal
entries (`api/specification.cljc:467-505`):

```clojure
history
{:args [:=> [:cat :datahike/SDB] :any]
 ...
 :doc "Returns full historical state of database including all assertions and retractions."
 :impl datahike.api.impl/history}

since
{:args [:=> [:cat :datahike/SDB types/time-point?] :datahike/SDB]
 ...
 :doc "Returns database state since given time point (Date or transaction ID). Contains only datoms added since that point."
 :impl datahike.api.impl/since}

as-of
{:args [:=> [:cat :datahike/SDB types/time-point?] :datahike/SDB]
 ...
 :doc "Returns database state at given time point (Date or transaction ID)."
 :impl datahike.api.impl/as-of}
```

All three are `:referentially-transparent? true`, which matters for CLJS
(§3): the emit macro aliases them straight to the impl — plain sync values,
no Promise (`api.cljc:15-18` and `:76-79`).

### The time-point argument

`datahike.api.types/time-point?`
(`reference-code/datahike/src/datahike/api/types.cljc:142-146`):

```clojure
(def time-point?
  "Time point - transaction ID (int) or Date."
  [:or :int
   [:fn {:error/message "must be a Date"}
    date?]])
```

Two forms only — an int **tx entity id** or a `java.util.Date`/`js/Date`
(NOT a "basis-t" distinct from the tx eid; see below). The impl
(`reference-code/datahike/src/datahike/api/impl.cljc:131-171`):

```clojure
(defn since [db time-point]
  (if (dbi/-temporal-index? db)
    (SinceDB. db time-point)
    (log/raise "since is only allowed on temporal indexed databases." ...)))

(defn as-of [db time-point]
  ...
  (if (dbi/-temporal-index? db)
    (if (int? time-point)
      (if (<= const/tx0 time-point)
        (AsOfDB. db time-point)
        (log/raise (str "Invalid transaction ID. Must be bigger than " const/tx0 ".") ...))
      (AsOfDB. db time-point))
    (log/raise "as-of is only allowed on temporal indexed databases." ...)))

(defn history [db]
  (if (dbi/-temporal-index? db)
    (HistoricalDB. db)
    (log/raise "history is only allowed on temporal indexed databases." ...)))
```

So: the return is a **wrapper record over the input db value** — no I/O, no
copying. An int below `tx0` raises. The read semantics live in the
predicates (`reference-code/datahike/src/datahike/db.cljc:142-152`):

```clojure
(defn- as-of-pred
  "Create an as-of predicate, *including* the time-point"
  [time-point]
  (if (date? time-point)
    (fn [^Datom d] (date<= (.-v d) time-point))     ; Date ⇒ compare txInstant
    (fn [^Datom d] (<= (dd/datom-tx d) time-point)))) ; int ⇒ compare tx eid

(defn- since-pred
  "Create a since predicate, *excluding* the time-point. ..."
  [time-point]
  (complement (as-of-pred time-point)))
```

`as-of` is **inclusive** of the time-point; `since` is exclusive. The
`AsOfDB` record wires the predicate in at `db.cljc:585-591`
(`(-time-point [db] (.-time-point db))` … `(as-of-pred (.-time-point db))`).

### basis-t vs tx eid — the 0x20000000 offset

`reference-code/datahike/src/datahike/constants.cljc:3-5`:

```clojure
(def ^:const e0   0x00000000)
(def ^:const tx0  0x20000000)   ; = 536870912
(def ^:const emax 0x7FFFFFFF)
```

Datahike (unlike Datomic) exposes **no separate basis-t** — the coordinate
everyone carries is the tx entity id itself, held on the db value as
`:max-tx`:

- `DB` record field + protocol: `(-max-tx [db] (.-max-tx db))`
  (`db.cljc:302`, `:336`); the temporal wrappers delegate to the origin db
  (`db.cljc:507`, `:578`, `:650`).
- Each tx allocates `(inc (:max-tx db-before))`
  (`reference-code/datahike/src/datahike/db/transaction.cljc:53-54`).

**Seon's "basis-t" is this `:max-tx` value** —
`seon.db/basis-t` is literally `(dbi/-max-tx db)`
(`src/seon/db.cljs:1104-1113`), and `origin-t` is `tx0` re-exported
(`src/seon/db.cljs:1100-1102`). So the int stored in
`:seon.agent.turn/rendered-as-of` (captured as `(db/basis-t db)` at turn
open, `src/seon/agent/turn.cljs:544`) is already a valid `as-of`
time-point, no offset arithmetic needed. If you ever need Datomic-style
"t", it would be `(- tx-eid tx0)` — nothing in seon or datahike wants that.

### How the tx-report exposes the tx id

`TxReport` is `(defrecord TxReport [db-before db-after tx-data tempids
tx-meta])` (`db.cljc:130`). Three equivalent reads of the committed tx id:

- `(:max-tx (:db-after report))` — the id just committed
  (`transaction.cljc:1154` bumps it in `:db-after`).
- `(:db/current-tx (:tempids report))` — the tempid mapping
  (`transaction.cljc:1153`).
- `(datom-tx d)` of any datom in `:tx-data`.

Seon's `transact!` success envelope already surfaces it as `::db/tx`:
`src/seon/db/internal.cljs:1341` — `::db/tx (:max-tx (:db-after report))`,
schema `[::tx :int]` at `src/seon/db.cljs:166`. So every write already
returns an `as-of`-ready coordinate.

## 2. History prerequisites

### What `keep-history? true` does, and `:db/noHistory`

With history on, every assert/retract also lands in the temporal indexes
(`temporal-eavt`/`temporal-aevt`/`temporal-avet` — `DB` record fields,
`db.cljc:302`), which is what the temporal wrappers read. Per-attr opt-out
exists: `:db/noHistory` is a legal schema attribute
(`reference-code/datahike/src/datahike/schema.cljc:65`, `:120`), checked at
every datom transaction:

```clojure
;; transaction.cljc:378 (and again :475)
keep-history? (and (dbi/-keep-history? db) (not (dbu/no-history? db a-ident)))
```

with `no-history?` = `(is-attr? db attr :db/noHistory)`
(`reference-code/datahike/src/datahike/db/utils.cljc:48-50`). It is
queryable like any schema attr. **Seon never sets it** — `grep -rn noHistory
src/` returns nothing; the `seon.schema` malli→datahike bridge has no
noHistory mapping. Every seon attr keeps full history.

### Our store config — history is ON

- **Wire-server (the sole writer, all cluster/session DBs):**
  `src/seon/server/store.clj:117-121`:

  ```clojure
  (def ^:private base-cfg
    {:keep-history?      true
     :schema-flexibility :write})
  ```

  Every db config goes through `config-for` which `(assoc base-cfg :store …)`
  (`store.clj:125-148`), consumed by the registry's ensure-db
  (`src/seon/server/registry.clj:200`, `:356`). So the default cluster store
  at `data/clusters/default/store` — and every ephemeral bench cluster — is
  temporal.
- **Pod peer config (the read side of the same store):**
  `src/seon/store/wire.cljs:149` — `:keep-history? true`.
- **Enforced at boot:** `seon.db`'s precondition check throws if the conn was
  opened without history (`src/seon/db/internal.cljs:1432-1440`):

  ```clojure
  (when-not (:keep-history? (:config @c))
    (throw (ex-info "seon.db: agent conn opened with `:keep-history? false`. ..." ...)))
  ```

- The only `:keep-history? false` sites are the **paused JVM main-app track**
  (`src/seon/db/datahike/flow.clj:162`) and an embed preflight scratch db
  (`src/seon/embed/preflight.clj:126`) — neither is the cluster store.

### GC / purge — does anything erase history?

Two distinct mechanisms in the fork; neither threatens us today:

- **`datahike.gc/gc-storage!`** (`reference-code/datahike/src/datahike/gc.cljc`)
  is a konserve-blob sweep: it walks branch heads, marks reachable keys —
  **explicitly including** `temporal-eavt-key temporal-avet-key
  temporal-aevt-key` (`gc.cljc:27`, `:46-48`) — and sweeps only unreachable
  (stale-root) blobs. GC does not delete history datoms. Seon never calls it
  anyway (only a comment mention in `src/seon/embed.clj:232`).
- **Purge tx ops** are the real history-erasers and exist in the fork:
  `:db/purge`, `:db.purge/entity`, `:db.purge/attribute`,
  `:db.history.purge/before`
  (`reference-code/datahike/src/datahike/db/transaction.cljc:774-779`;
  dispatch at `:983`, requires `(dbi/-keep-history? db)`). They only run when
  explicitly transacted — `grep -rn purge src/` shows seon never issues one.

**Conclusion: an error's basis-t remains restorable indefinitely on the
cluster store, unless someone runs `bin/seon cluster reset` (store wipe) or
introduces purge/noHistory later.**

## 3. as-of over our wire

### How the pod gets a db value

The pod is a datahike-cljs **peer** on the JVM's file store
(`src/seon/store/wire.cljs:1-40`, the ns docstring):

> READS are local + sync: the `:seon-wire` writer below reports
> `-streaming?` false, which flips `deref-conn` into follow-the-store mode —
> every `@conn` re-reads the branch root from konserve and reconstitutes a
> fresh db value with lazy LRU node fetch (connector.cljc:69-78).

So `@conn` (via `internal/resolve-conn`, `src/seon/db/internal.cljs:849-861`)
yields an ordinary datahike db value whose index nodes fetch lazily from the
shared file store.

### as-of is a pure local wrapper — and it works in the fork's CLJS build

Three independent confirmations:

1. **The API emits a sync CLJS alias.** `as-of`/`since`/`history` are
   `:referentially-transparent? true` (§1), so in CLJS the emit macro
   defs them straight to `datahike.api.impl/…` — plain values, no channel,
   no Promise (`api.cljc:64`, `:76-79`; the ns docstring names `as-of` and
   `history` in the "pure" list, `api.cljc:15-18`).
2. **The records have CLJS branches.** `AsOfDB` is a `defrecord-updatable`
   with explicit `:cljs` protocol impls (`db.cljc:538-557`, e.g. the
   `js/Error` unsupported-op stubs), same for `HistoricalDB`/`SinceDB`;
   `api.cljc:49` `:refer`s them in the CLJS branch. The fork's excluded
   upstream CLJS is **tests** (channel tests — memory note
   `project_datahike_fork_sync_2026_06_18`), not the temporal read path.
3. **A pod test proves it end-to-end**, including a fork-specific fix:
   `test/seon/db_test.cljs:696-741`
   (`as-of-entity+aggregate-see-the-past-frame`) transacts at t1, mutates at
   t2, then reads `(db/as-of head t1)` via entity-by-lookup-ref AND an
   aggregate ref-join query — the comment at `:722-723` notes this exact
   shape used to throw `"-lookup is not supported on AsOfDB"` **before the
   fork fix**.

### What seon.db already exposes (pod-side)

All of it, already shipped (`src/seon/db.cljs:1035-1113`):

- `history` (0/1-arity, db defaults to `@*conn*`) — `db.cljs:1047-1063`
- `as-of` (`([t])` / `([db t])`) — `db.cljs:1065-1078`, delegating to
  `d/as-of`
- `since` — `db.cljs:1080-1092`
- `origin-t` (= `dconst/tx0`) — `db.cljs:1100-1102`
- `basis-t` (= `dbi/-max-tx`) — `db.cljs:1104-1113`

And a live consumer already exists: `seon.ai/resolved-config`'s docstring
prescribes the exact composition (`src/seon/ai.cljs:509-514`):

```clojure
(resolved-config
  {:seon.db/db    (db/as-of db (:seon.agent.turn/rendered-as-of turn))
   :seon.agent/id agent-id})
```

**Answer: an as-of query does NOT need to go JVM-side.** The pod wraps its
own lazily-fetched db value locally; temporal index nodes stream from the
same konserve store on demand. The wire REPL (7891) works too — same store,
same `datahike.api` — but it is a convenience, not a requirement.

## 4. Reproduction recipe

Given an error datom carrying `{basis-t, agent-id, fn-sym + args (malli
envelope) or eval form}`:

### (a) Obtain the db value as-of that basis-t

```clojure
;; pod-side (agent eval, inspector, or a test) — *conn* already bound
(def frozen (seon.db/as-of basis-t))          ; 1-arity ⇒ @*conn* rewound
;; or against a db you already hold:
(def frozen (seon.db/as-of db basis-t))
```

`basis-t` is valid iff `>= seon.db/origin-t` (`tx0`; `api/impl.cljc:161-163`
raises below it). For a turn-scoped error the coordinate is the turn's
`:seon.agent.turn/rendered-as-of` (`src/seon/agent/turn.cljs:84`, captured
at `:544`); joining error→turn is the tx-meta provenance stamp
(`:seon.db/turn-id` on the error datom's own tx, `turn.cljs:551-554`).

JVM-side equivalent over the wire REPL 7891 (same store, `datahike.api`
directly):

```clojure
(require '[datahike.api :as d])
(def conn (d/connect <cluster cfg>))      ; the registry already holds it
(def frozen (d/as-of @conn basis-t))
```

### (b) Re-render / re-invoke against it

Re-render the exact context the model saw — `seon.agent.inspect/turn` /
`turn-diff` are the shipped replay path (the ONE capture path, per
`src/seon/agent/CLAUDE.md`), and `ctx-preview` renders through the same
`render-context` the real prompt used. For a raw re-render:

```clojure
;; the render fns take :seon.db/db — pass the frozen value
(seon.agent.ctx/render-context {:seon.agent/id agent-id :seon.db/db frozen})
```

Re-invoke a failing fn from the malli instrumentation envelope
(`src/seon/error/instrument.cljc:63-82`: `:seon.error.malli/fn-sym`
`:symbol`, `:seon.error.malli/got-edn` `:string`,
`:seon.error.malli/arg-index` `:int`, all riding in `:seon.error/data`):

```clojure
(let [f    @(resolve fn-sym)                      ; or the sci/eval resolution path
      arg  (cljs.reader/read-string got-edn)]     ; round-trips: pr-str-readable stubs fn-objects
  (f (assoc-in original-args [arg-index] arg)))   ; ← see gap 1
```

For an eval-form error: the form is in the turn's eval log
(`:seon.agent.turn/evals`, `turn.cljs:102`); re-eval through `seon.eval`
against the frozen frame.

### Gaps (flagged)

1. **The malli envelope stores only the FAILING arg, not the full arg
   vector.** `:seon.error.malli/got-edn` + `arg-index`
   (`error/instrument.cljc:71`, `:79`) capture the one offending value
   (truncated, fn-objects stubbed via `pr-str-readable`,
   `error/instrument.cljc:98-115`). Full re-invocation needs all args — if
   the blame proposal wants push-button repro, the envelope needs a
   `:seon.error.malli/args-edn` (bounded) or the repro path goes through the
   eval form instead.
2. **Errors outside a turn have no captured basis-t.** Only turns persist
   `rendered-as-of`; a `:core`-blamed error in a listener, boot path, or SSE
   handler would need the error datom to stamp `(db/basis-t)` itself at the
   catch site (cheap — it is `(dbi/-max-tx db)`, no I/O). Recommend making
   basis-t part of the error-datom shape, not derived from the turn join.
3. **Frozen ≠ identical for side effects.** `as-of` gives read/render
   fidelity; you cannot transact "into the past" (writes go to the conn, and
   the wrapper records reject mutation — e.g. `db.cljc:556-569` unsupported
   ops). Reproducing a WRITE-path failure end-to-end needs a scratch cluster
   (`bin/seon cluster create`), seeded from the frozen reads.
4. **Repro fidelity depends on §2 holding** — no purge, no noHistory, no
   `cluster reset` between capture and replay. All true today; worth a
   standing assertion if the error surface becomes load-bearing.

## 5. EDN stack traces

### cljs.stacktrace — yes, structured V8/Node parsing without source maps

`reference-code/clojurescript/src/main/cljs/cljs/stacktrace.cljc` — a
**`.cljc`** ns (CLJS branch requires only `goog.string`,
`stacktrace.cljc:9-15`), so it is available to the pod build (it ships in
the ClojureScript jar; nothing JVM-only in the parse path).

`parse-stacktrace` is a multimethod on `(:ua-product err)`
(`stacktrace.cljc:17-31`); the Node parser (`stacktrace.cljc:389-420`)
consumes raw V8 `"    at fn (file:line:col)"` lines with plain string ops —
**no source maps involved**:

```clojure
(defmethod parse-stacktrace :nodejs
  [repl-env st err {:keys [output-dir] :as opts}]
  ...
  {:file     ...
   :function function
   :line     (parse-source-loc-info line-part)
   :column   (parse-source-loc-info col-part)})
```

Frame shape: `{:file string :function string|nil :line int|nil :column
int|nil}`, vector of frames, blank/non-`at` lines dropped, `repl:` frames
skipped. Worked example in the source comment (`stacktrace.cljc:422-438`).
Call shape for us:

```clojure
(cljs.stacktrace/parse-stacktrace {} stack-str {:ua-product :nodejs} {:output-dir "out"})
```

Caveats: (a) frames name **compiled-JS** coords (`out/client/…js` lines) —
mapping back to `.cljs` lines is the separate `mapped-stacktrace` step,
which DOES need source-map data (`stacktrace.cljc:440+`); the raw parse is
still enough for the blame discriminator ("are the frames `my.*` or
`seon.*`?" — the munged `$`-separated function names carry the ns). (b) the
`:chrome` parser (`stacktrace.cljc:136`) handles the same V8 format with
URL-shaped files, but `:nodejs` is the right dispatch for the pod.

### What seon.error does with `:seon.error/stack` today

Raw string only, truncated: `src/seon/error.cljs:63` —
`(some-> (.-stack e) (subs 0 (min 4096 (count (.-stack e)))))`, attached at
`:73` as `:seon.error/stack` (documented as "`.-stack`, truncated to ~4kb",
`error.cljs:15`). No parsing, no frames. Upgrading to EDN frames is a pure
addition inside `->map` (or a derived render-time parse — derive-don't-store
argues for parsing at the section fn, keeping the stored blob raw).

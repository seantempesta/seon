# Independent review of the agent record and turn loop, r3

**Verdict: simplify the ownership model; do not implement r3 as written.** It duplicates the wake claim, omits the zero-evaluation failure state, and mistakes schema leaf definitions for installed database attributes. Its proposed deletion of observations outruns its evidence that those observations can be reconstructed.

Scope: [AGENTS.md](AGENTS.md), the [r3 PRD](docs/prds/context-generation/plan/agent-record-and-turn-loop-prd-2026-09-07.md), and all five named research authorities were read end to end: [run loop](docs/prds/context-generation/research/run-loop-unpacked-2026-09-07.md), [branches/SCI/wakes](docs/prds/context-generation/research/cluster-branch-sci-wake-model-2026-09-07.md), [evaluation/cache census](docs/prds/context-generation/research/eval-points-and-caches-census-2026-09-07.md), [REPL/record audit](docs/prds/context-generation/research/audit-repl-and-record-2026-09-07.md), and [evaluation merge](docs/prds/context-generation/research/evaluation-merge-landing-2026-09-07.md). ## Questions 7–9 first

**7. No: several KEEP rows are mirrors; several DELETE rows remove evidence that survives the no-resume decision.** Delete the second wake edge, the agent/evaluations back-edge, and the proposed plan wrapper. Keep an observable interruption on the turn, including when it has no evaluations; derive interrupted evaluation displays from that turn. Delete the process stamp only with boot-before-arm recovery and one-open-turn admission enforced at the writer. The complete row audit and deletion/proof matrix below distinguish representation changes from deliberately retired behavior.

**8. No resume is right, and is already the ordinary-turn rule.** `src/seon/cluster/work.clj:36–56` and `src/seon/cluster/run.clj:2053–2088` already close interrupted ordinary turns. The generated-prefix exception is what changes. Consider two forms: the first transacts data or completes an external effect; the second dies before batch settlement. The first effect can survive while both evaluation results, captured output, deferred messages, and admitted program changes remain uncommitted. No query recovers the exact executed prefix from the frozen forms. Durable effect records remain independently recoverable (`resources/seon/schemas/seon.effect.edn:22–57`); deferred delivery belongs to terminal settlement (run-loop research §5.6, lines 587–589).

**Keep freeze for forensic source, not for an execution guarantee.** Open consumes the wake; no-resume prevents restarting that turn. Freeze preserves the reply and intended forms across a subsequent crash. Removing freeze and storing reply/results together is a valid two-commit policy only if losing that evidence is accepted. It does not undo already committed effects. R3's “terminal facts absent = not yet evaluated” (line 256) is false: it means **no durable outcome is recorded**. Boot cannot name “the evaluation that was cut” when settlement batches all outcomes. Render the uncertainty, not an invented execution position.

**9. A turn referencing the wake is enough; that reference IS the stored claim.** Keep `:seon.turn/wake`; delete `:seon.wake/turn`. Today's `unanswered-triggers` already derives unansweredness from the absence of a run→trigger edge (`src/seon/cluster/work.clj:604–635`), and `open-trigger-call` rechecks it inside the writer (`src/seon/cluster/loop.clj:1179–1198`). A permit cannot remember an answered wake after closure or restart. Preserve the edge, its transaction-time uniqueness check, and the answering turn's identity for as long as the wake exists. Otherwise retention makes old work pending again. Ledger 70 already chooses the claim **from** the handling run (lines 1051–1058).

## Blockers — the design is wrong here

**B1. §4a is not a complete installable schema.** The evaluation and attempt families have no `:map` carrying `:seon.db/attributes true`; none of their proposed leaves has an independent database-declaration property. `:seon.wake/turn` is likewise undeclared as a stored attribute. The compiler admits map entries or explicitly marked leaves (`src/seon/schema/form.cljc:9–15,66–93`); schema properties have a separate path (`src/seon/schema/datahike.clj:304–322`). Referring to a component does not declare its children's attributes. There is also no evaluation identity declaration: the sentence “(turn, ordinal) is the identity” creates no uniqueness constraint. Finally, `:seon.db/commit-id` is not a registry alias at this commit; the current stored opening commit uses `:uuid` (`resources/seon/schemas/seon.cluster.run.edn:36`). These defects contradict PRD lines 202 and 285. Preserve the boot-installability proofs, not just leaf schemas.

**B2. The turn can die without an evaluation; r3 cannot say so.** Crash after open and before freeze produces no evaluation to stamp. A provider failure or an empty/unreadable reply also needs a terminal path. R3's open turn plus zero evaluations selects neither the evaluation arm nor a defined failure arm (lines 325–335). “Frozen = has evaluations” fails for an empty freeze. Existing recovery explicitly keeps a turn interruption for this case (`src/seon/cluster/run.clj:2064–2067`); `recovery-marks-a-run-that-settled-no-receipt` proves it. Keep turn interruption/error provenance and close prompt/provider/reader failures through the same terminal owner. Source absence is not a diagnosis. Derive frozen evidence from a recorded reply/refusal, or keep the continuation in the current call; no phase counter is needed.

**B3. The permit is not the writer's one-open-turn fence.** `turn-step` acquires the permit (`src/seon/cluster/agent.clj:583–601`), but `submit-source!` commits a system run before offering the graph a wake (`:727–734,788–814`). The existing writer refuses a second run for the agent (`src/seon/cluster/run.clj:513–546`). Deleting the pointer is correct; deleting that refusal is not. Replace its lookup with a query for an existing open turn **inside open-call**, and route every opener through it. This also answers the proposed “every turn is a model call”: system source is a supported path and §4a itself retains system authorship. Removing generated openings does not remove source submissions.

**B4. One settlement per identity does not imply one execution.** After evaluation, a refused terminal transaction leaves no terminal outcome. Re-entering r3's first arm executes the same side effects again before its eventual settlement is refused. The identity fence runs at creation/settlement, too late to undo execution. Today's refusal path closes the run atomically with failure outcomes (`src/seon/cluster/loop.clj:730–775`); failure to record even that is loud (`:827–834`). Keep that terminal/fault boundary and stop failed work from re-entering. Delete the line “also crash resume” in §7; preserve `refused-terminal-program-transactions-settle-and-do-not-refire`, not just a uniqueness test.

**B5. Basis plus profile is not today's complete projection input.** Rendering invokes the supplied live SCI context and its projection (`src/seon/render.clj:725–757`); a profile can be explicitly supplied rather than derived from the historical database (`:68–91`). Reusing a database value after replacing a renderer changes the bytes. The current prompt also projects the opening transaction's database (`src/seon/cluster/loop.clj:1375`), while `opening-commit-id` records the pre-open database (`src/seon/cluster/run.clj:376–397,550–556`). A UUID commit is loaded with Datahike `commit-as-db`, not `as-of` (`reference-code/datahike/src/datahike/versioning.cljc:457–488`; `resources/seon/schemas/seon.db.edn:198` admits only inst/int time points).

The PRD's idea is that a prompt is a reproducible query result. Restated: store all its immutable inputs instead of another copy of its output. That works only after the projection uses the selected historical program, schema, profile, and data exclusively. Until that exists, retain the actual prompt bytes or their content-addressed blob plus the provider digest; delete redundant contribution accounting separately. “Render twice now” does not prove historical reproduction after reload, restart, retention, or failover.

**B6. One recipient ref does not define a repeatable wake event.** R3 names `:seon.schedule/agent`, but the current schedule entity is a recurrence definition (`resources/seon/schemas/seon.schedule.edn:1–8`); nominal firings have distinct identities and a transactional claim (`src/seon/schedule.clj:237–258,303–346`). Claiming the schedule once consumes every later firing. Route a firing entity. Two distinct source entities in one transaction are safe if the next pass drains remaining work, as today's self-wake does (`src/seon/cluster/agent.clj:619–628`). One entity with source refs to two agents is unsafe with a global item claim: the first turn suppresses the second. Declare the simple constraint **one immutable event entity, one recipient**, or scope the claim by recipient and source. R3 declares neither.

The catalog also omits the existing completed-effect source (`src/seon/cluster/wake.clj:93,236–246`; `src/seon/cluster/work.clj:509`). A budget refill must wake an agent whose items were already pending; subscribing only to new recipient assertions misses it. New sources require an event identity, eligibility/order semantics, declared recipient shape, and atomic admission. The generic listener can stay unchanged; schema flags alone do not supply these facts.

**B7. One database value for an entire turn changes evaluation semantics.** A form can transact and its next form can query that transaction. `evaluate-sources` deliberately distinguishes a fixed preview snapshot from ordinary evaluation's current connection value (`src/seon/cluster/loop.clj:1538–1576`). Passing the opening database through every form makes the second read stale. Carry one database value per pure derivation; take transaction reports' `db-after` where applicable and preserve current reads at effect/evaluation boundaries. Delete repeated derivations, not the observations that make read-after-write work. The promised “20 of 21” deletions is not a proved invariant.

**B8. A byte bound is not an execution bound, and a print node is not necessarily a restorable value.** A lazy sequence can block while realizing its first element, before any byte is emitted. Existing admission checks the SCI interrupt at every node because native lazy realization bypasses interpreted function entrances (`src/seon/sci/admit.clj:395–410`). It currently builds a node before serializing it (`:650–653`): measuring the finished string cannot replace that protection. Stream bounded serialization under the existing evaluation/host-call bounds; account for traversal before bytes and nested unsupported values. Preserve identity-only admission (`:162–171`) and reject any handle whose descendants are not faithfully recoverable. Removing lossy storage windows is good; simply removing caps does not establish §5's “under it stored faithfully.”

## Simplifications — delete more, without deleting the evidence

The PRD treats the agent record as stored data whose components render directly. Another angle is simpler: **the agent declares identity, assignment, budget, and authored plan facts; turns consume events; evaluations belong to turns; the record is a query over those facts.** A convenient one-hop *rendered* value does not require another stored ownership edge.

Recommended execution shape: writer admits one open turn and consumes one event; current call projects and calls the provider; freeze records the reply and admitted forms; one fork evaluates them; one terminal owner records outcomes and closes. Boot closes old opens before arming. Current-call failures use that same terminal owner. There is no general “find unfinished work and execute it” arm. Attempts require a separate durability decision described below. This keeps the PRD's idea while deleting its duplicate claim, history back-edge, plan wrapper, resume selection, and per-evaluation recovery stamps.

## Questions 1–6, with the remaining decisions

**1. Derivable data and missing crash data:** the inventories above answer every proposed stored attribute. The largest deletions are agent/evals, plan wrapper, inverse claim and evaluation recovery stamps. Missing data is zero-evaluation turn interruption/failure, installed evaluation identity, retained attempt outcome/provenance where promised, and the historical projection inputs or actual sent bytes. Freeze records intention; neither it nor an identity records an exact executed prefix.

Even `closed-at` can be removed by defining closure entirely from recorded reply completion, evaluation outcomes, turn failure/interruption and early-stop dispositions. That refactor replaces one explicit closure fact with a compound rule across those cases; retain the simpler closure fact here. Conversely, keeping both turn and evaluation interruption timestamps adds no information under r3's boot-only stamping rule. The zero-evaluation recovery test, not a preference for a particular schema key, decides where the surviving interruption belongs.

**2. Open extension:** yes for new producers conforming to one event→one recipient and the shared admission/order policy; no for arbitrary ref attributes. Distinct events in one transaction coalesce signals safely only with derive-after-listen, boot priming and drain/self-wake. One entity addressing two agents needs a different claim key. Schema installation and allowance refills must reconsider existing pending facts. Keep completed effects in the source population. These are source/admission obligations, not new loop branches (B6).

**3. Commit minimum:** r3 itself says three commits at lines 332–336; the question's “two-write turn” omits open. Freeze cannot ride open before the model response exists. Deferring open until the response also defers durable wake consumption and allowance admission; one permit does not fix restart evidence or other submission threads. For an already supplied source reply, open+freeze can share a transaction, as `submit-source!` already does. For model turns, retain open→freeze→settle unless the owner explicitly chooses to lose pre-settlement reply evidence. Attempts observed before a crash require recording before the next risky operation; there is no universally correct three-commit count for multiple provider attempts.

**4. Counter:** keep `turns-left` as the one explicit allowance under the proposed policy. “Turns since the last human message” is today's episode heuristic, not a derivation of grants from faults, schedules or agents (`src/seon/cluster/work.clj:394–469`). A different pure accounting model stores explicit grants and derives remaining = granted − admitted turns; it removes decrement storage but adds grant facts and a query. It is not automatically simpler. Whatever model wins, positive allowance and consumption belong in the same writer admission; refill must publish readiness for already-pending work.

**5. Byte identity:** the concrete falsifier is an omitted input, the supplied live renderer/SCI projection and optional supplied profile (B5). `history` explicitly consumes those inputs (`src/seon/render/walk.clj:799–829`). `canonical-edn` normalizes print bindings, not map/set order (`src/seon/sci/admit.clj:544–554`); that is not evidence that repeated rendering of the same immutable input changes order. Entity-ID handles are stable within the same database (`:533–542`), and stored timestamps stay constant. No proven clock/hash/entity-ID instability is claimed here. Test historical reconstruction after a renderer change and on a fresh context, with the actual sent-request digest; keep a failing/absent reconstruction visible. A provider-request digest must specify whether it covers context text or the complete request, including failover additions/settings.

**6. Overcomplication:** direct stored mirrors substitute for a cheap record query; wake has two booleans and two claim directions; per-evaluation recovery duplicates turn recovery; a new plan wrapper duplicates existing ownership; and the universal snapshot rule introduces stale-read semantics to save dereferences. Conversely, r3 oversimplifies observations: attempts, errors and empty turns need real terminal evidence. Keep one admission owner, one freeze owner and one terminal owner, not a general unfinished-work executor. This preserves the PRD's record-first design with fewer stored relationships and fewer executable states.

## Frictions and agreement

**Frictions.** §1 calls two writes unavoidable, §7 correctly counts three, and §9 again says two. Separate mandatory event admission from the optional forensic freeze. “Opened/closed timestamps are the bound” is false; retain the completion backstop (`src/seon/cluster/agent.clj:583–584`). “All attempts move unchanged” and “every turn is a model call” are also false as documented above. Do not rename existing `seon.print` facts just to collect everything under `seon.eval`. Keep the existing `seon.eval` diagnostics when accreting the evaluation entity. Do not equate authored `defn` source with every ordinary saved closure/atom. These are concrete scope decisions, not mechanical deletions.

**Agreement.** One evaluation entity per admitted form is right and already landed. Ordinary turns must never resume after process loss. Claim refs are better than retracting recipient edges. Namespace assignment is not identity. History should derive from stored source and outcomes; handles should name the evaluation's own identity and never silently bind a partial value. A single byte storage policy and AI-only elision are a better target once bounded faithful serialization is real. The smartest version of this design keeps fewer edges, preserves uncertainty honestly, and lets the writer decide admission exactly once.

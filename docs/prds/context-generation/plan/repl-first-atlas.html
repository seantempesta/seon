Datahike's own grammar · reference-code/datalog-parser/src/datalog/parser/pull.cljc · datahike/query.cljc

One rule decides q versus pull, and the agent learns it from its own screen

The walk never chooses by taste. A forward ref edge from an entity you already hold is a pull with a nested selector. A reverse edge, a collection, or an aggregate is a q, usually with pull inside :find so rows come back whole. "What changed" is the same read at two bases through diff. Every generated entry is one of these, so the agent sees each idiom used on its own data before it needs it.

whenidiomthe form (real)grammar it relies on
  • Selectors carry identities. A generated selector puts the identity attribute on every ref leaf ({:seon.ns/requires [:seon.ns/name]}), so every handle in the transcript is a lookup ref the agent can pull next. A bare [*] hands back {:db/id N} and teaches nothing; the walk never emits it.
  • Collection-first. One q explains all N (or counts them); instance pulls are dig-ins the agent types. Fifty maintenance requests are a count and a newest timestamp, not fifty rows.
  • Recursion is Datahike's. {:seon.ns/requires 2} walks two levels; {:attr ...} is unbounded; :ns/_attr reverses. Verified live 2026-09-03.
  • since is a trap for "what changed in what I saw". A since view holds only newer datoms, so lookup refs to older entities fail inside it (measured). diff reads at both bases; since stays a tool for "is anything newer at all".
  • Writes are the same shape. A map with an identity attribute upserts; [:db/retract e a v] pops; [:db.fn/call f …] is a transition function for writes that must decide at the writer.

  CTX -->|"per run: sci/fork + the agent's defs restored from :seon.def"| TURN["the agent's turn ctx (+ result/id bindings from its evals)"]
  TURN -->|"settlement writes facts"| CLB
  EDIT["file edit"] -->|"edit hook: kondo → same-identity upserts"| CUR
  CLB -->|"generator: walk → forms → evals → render"| OUT["the agent's context (/ai) · the page (/html)"]
  • Yes, the SCI context loads from the database: acquire! (sci/eval.clj:1267) builds it from namespace source facts and program rows; contracts wrap from the :seon.fn/spec fact; the agent's defs restore from :seon.def rows.
  • Schemas are facts: the Malli form on a schema row is the database declaration; identity, ref, component and cardinality derive from it (schema/datahike.clj:221-262); an agent-declared schema settles through the run loop with accretion allowed and breaking redefinition refused (run.clj:1436-1460).
  • Existing clusters keep their forked program until destructively reforked; the edit hook only republishes :current-src.

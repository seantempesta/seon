# Lane m4-n1: stop is a join (N1 slice 1)

**What the system already does, and the smallest composition (AGENTS "Think like a principal
Clojure developer").**

1. **What Flow already does.**
   - Flow runs each proc loop as one task on the supplied `:io-exec`.
   - A throw from a stop transition is absorbed by the loop's outer catch, and the loop then parks
     forever (`impl.clj:181,317-320`, read in `reference-code/core.async` `dc35f3e0d`).
   - The JDK executor's `awaitTermination` is the join. REPL: `(start-graph! {:procs {} :conns []})`
     → `flow/stop` → `join-graph!` returned nil with `isTerminated` true in 0.42 ms.
2. **The smallest composition.** No new mechanism: one executor per graph through the existing
   `:io-exec` seam, and one catch at the seam every proc already passes through (`var-process`).

## Algorithmic analysis (before code)

- **Seam.** Flow's `:io-exec` (`reference-code/core.async` `dc35f3e0d`, `flow.clj:100-103`,
  `impl.clj:29-36,262,323`). Each proc loop is one task on the supplied executor, and it returns
  only after its stop transition (`impl.clj:209-217,321-322`). The join is the JDK:
  `ExecutorService.shutdown` then `awaitTermination`. There is no core.async fork, as ruled.
- **Costs.**
  - Graph start adds one `newThreadPerTaskExecutor`, O(1). A thread-per-task executor holds no pool.
  - Stop is `flow/stop` plus `.shutdown` plus one `awaitTermination`, proportional to the graph's
    procs.
  - `disarm-agents!` takes one deadline across all phases. Each await gets the time left, so the
    total wait is bounded by the deadline, not by the sum of the phases (`seon.await` accepts
    `:seon.await/deadline-nanos`).
  - The restart refusal is one `.isShutdown`/`.isTerminated` read, O(1).
  - Nothing is proportional to the program or the store.
- **Measured.** An idle graph's `flow/stop` plus `join-graph!` took **0.42 ms** on default
  (probe below).
- **Simplest alternative.** B1's core.async fork that exposes each loop's `Future`. It was rejected
  (owner ruling): the executor seam already gives the join with no fork.

## What landed

- `seon.flow/start-graph!` gives every graph its own virtual-thread executor via `:io-exec`, with
  the graph's projection bound in the thread factory. The graph is returned with its `::executor`.
- New `seon.flow/join-graph!`: `.shutdown`, then `awaitTermination` through `seon.await/await!`
  under the caller's deadline. It returns nil, or the typed timeout.
  - `seon.await/await!` spends `:seon.await/deadline-nanos` when the caller supplies one.
  - `disarm!`, `disarm-agents!`, `stop-work-launcher!` and `stop-error-fanout!` join through it
    under ONE deadline.
- `arm!` refuses with `:seon.agent/graph-exited` while the previous graph's executor is shut down
  but not terminated. Once it has terminated, `arm!` finishes the teardown and arms a fresh graph.

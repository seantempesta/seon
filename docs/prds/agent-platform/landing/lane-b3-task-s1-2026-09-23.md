# B3 task family in place — S1 and S2

## Design and cost, stated before code

| Operation | Before | After | Proportional to |
|---|---|---|---|
| start (`create-tx`) | agent creation + a plan step component carrying a `done-query` | agent creation only | one issue pull + one agent creation |
| settle (`plan/settle-call`) | open plan steps, each `done-query-result` round-tripping to `issue/done-query` → `done?`; exhaustion skipped for an agent without steps | open plan steps (none for a worker) + `issue/settle-call`: one agent → open issue join, then `done?` on that one issue, then `exhaust-tx` | the closing agent's one open issue and its tests |
| `done?` detector branch | the whole detector population (12–34 ms measured by the spec) | the detector bound to the one subject | one subject (S2) |
| `generate!` | detector population computed twice, the second time inside the serialized writer | computed once outside the writer; the writer checks per-subject upserts only | the population once, the changed findings in the writer (S2) |
| transcript objective / stall | agent → plan → steps pull | reverse ref `:seon.issue/_agent` | the agent's issues (0 or 1) |

Simplest alternative considered: keep the plan step and change nothing (the round trip through
`seon.plan` stays a second settlement path; rejected by the spec §2). The reverse ref needs no new
function (`of-agent` rejected by the spec §2).

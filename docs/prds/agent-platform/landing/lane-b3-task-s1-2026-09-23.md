# B3 task family in place — S1 and S2

## Design and cost, stated before code

| Operation | Before | After | Proportional to |
|---|---|---|---|
| start (`create-tx`) | agent creation + a plan step component carrying a `done-query` | agent creation only | one issue pull + one agent creation |
| settle (`plan/settle-call`) | open plan steps, each `done-query-result` round-tripping to `issue/done-query` → `done?`; exhaustion skipped for an agent without steps | open plan steps (none for a worker) + `issue/settle-call`: one agent → open issue join, then `done?` on that one issue, then `exhaust-tx` | the closing agent's one open issue and its tests |
| `done?` detector branch | the whole detector population (12–34 ms measured by the spec) | the detector bound to the one subject | one subject (S2) |
| `generate!` | detector population computed twice, the second time inside the serialized writer | computed once outside the writer; the writer checks per-subject upserts only | the population once, the changed findings in the writer (S2) |
| transcript objective / stall | agent → plan → steps pull | reverse ref `:seon.issue/_agent` | the agent's issues (0 or 1) |

Simplest alternative considered: keep the plan step and change nothing (the round trip through
`seon.plan` stays a second settlement path; rejected by the spec §2). The reverse ref needs no new
function (`of-agent` rejected by the spec §2).

## S2 — the population once, outside the writer; a minted authored id

Changed: `src/seon/issue.clj`, `test/seon/issue_settlement_test.clj`,
`resources/seon/schemas/seon.issue.edn` (the `:seon.issue/id` description only).

- `generate` derives the detector population once, outside the writer, and returns one
  `[:db.fn/call #'generate-subject-call row]` per finding that changes the database (the
  `generate!` second whole-population computation inside the writer, `[:db.fn/call #'generate
  request]`, is deleted). `generate-subject-call` re-reads only that subject's held issue in the
  writer: new → opens; held → the generator's facts, prose only when absent; `:resolved` →
  resolves a held issue, and nothing for one deleted meanwhile.
- `generate!`'s catch returns only a declared issue refusal (`:seon.error/layer
  :seon.issue/request`, thrown by `refuse!`); any other `ExceptionInfo` is rethrown whole
  (class, message, data, cause chain, frames). Before: every `ExceptionInfo` became its ex-data.
- `done?` passes the issue's one subject (`:seon.fn/sym`) to the detector through
  `detector-rows` (`scope` = `select-keys` of root and sym; a detector with no scope keeps its
  one-argument call). **Subject-local cost needs `src/seon/issue/detect.clj`, which is not in
  this lane's paths**: the patch is `tmp/b3-task-s1/detect-subject.patch` (`declarations` binds
  `?sym` when given, the three detector contracts accept the optional `:seon.fn/sym`; `git apply
  --check` clean; clj-kondo 0 errors; +9/−14 lines). Until it lands the detector ignores the extra
  key (open map) and `done?` stays correct at population cost (43 ms measured). `carrying`,
  `bodiless-symbols` and `shared-form-symbols` remain attribute-wide scans after the patch.
- `add-tx` mints `(id/id)` once inside the writer under tempid `"authored"`; `add!` reads the id
  from the report's `:tempids`. The title never derives the id; the unreachable
  `already-exists-error` leaves `add!`'s union.
- Net: src +80 / −74 (+6); test +6 / −2; resource ±1.

# Lane cut-l2 — `db.clj` shrink-db slices

**What the system already does here.** `seon.db/q` hands Datahike's result to a Seon decode
walk that rebuilds every row even when no find element is EDN-encoded (REPL: of `q`'s
0.97 ms over 4,805 rows, `decode-query-result` is 0.89 ms, raw `d/q` 0.003 ms); `q`, `pull`,
`pull-many` and `datoms` carry Malli `:fn` guards that re-parse arguments the body (or
Datahike) already refuses; `arity-mismatches` re-implements `arity-verdict` line for line.
**The smallest composition.** Return Datahike's result when the find clause holds no
encoded variable and no `pull`; delete the guards; one `pull-with` dispatch; one
`arity-verdict` taking the snapshot as a function.

Paths: `src/seon/db.clj`, `test/seon/db_test.clj`, this note.

## Upstream seams checked (reference-code/datahike at `c79cd03a`, fork audit 410b5daba)

- Datahike has no value codec; the decode is Seon's alone. Find elements come from the
  upstream datalog parser (`datalog.parser.impl.proto/find-elements`, `Pull` record).
- `pull`/`q`/`datoms` refusals: Datahike throws on a bad index (`No matching clause`), bad
  components (`datahike.db.utils` 179 `Bad entity attribute`), and `seon.db`'s bodies already
  refuse every argument shape the guards refused (table below). Upstream behaviour.
- Nothing here builds on `:cache-context`, attribute revisions or `q-with-evidence`
  (fork-only); the existing `q-with-evidence` call is unchanged.

## Guard table (REPL, JVM, read-only, `malli.instrument/-f->original` of each Var)

| `(datoms db {:index :eavt} 1)` | false | invalid read, Datahike "No matching clause" |

## Slice 8 refuted (kept the pre-flight)

`tmp/cut-l2/preflight_probe.clj` on a throwaway branch compares `transact!` with the
pre-flight against the same pipeline without it. Datahike refuses an unknown attribute
(`validate-attr-ident`, `db/utils.cljc:189`) and a storage-type mismatch (`validate-val`,
`db/transaction.cljc:51`) before `:datahike/validate-report` runs, so the final report never
sees them. Without the pre-flight both get Datahike's bare message: no registered
candidates, no Fix, no submission path. Missing required keys and unowned rows are refused
identically either way (final report). The premise of shrink-db row Q is false for these two
classes, so the slice does not land.

## Dead definitions

`call-without-custody` and `deletion-error`: no src/test/resource caller and no indexed
caller (`:seon.fn/calls`/`:references` query on default). `fresh-connection` is **not**
dead: `connection-generator` and `database-value-generator` call it (the indexed rows miss
calls from a `def`).

# Lane m4-n3: the listener failure path, loud and non-recursive

Extends `plan/lane-flow-owns-running-machinery.md` §N3 and "The dependency
between N1–N4 and the error route"; M4 step 0 (`seon.fault/fault!`, `83bac0e78`,
`dec332d42`); the write bound (`805da372d`).

## Design (written before code)

**Seam (fork `131ca636`, verified at the line):** `reference-code/datahike/src/datahike/writer.cljc`
`notify-listeners!` (was `:382-391`) catches each callback's Throwable and only
`log/error`s it; `transact!` `:398-419` and `merge-db!` `:429-444` capture the
listener snapshot `(some-> (:listeners (meta connection)) deref)` and deliver
the promise BEFORE notifying. The registry is the `:listeners` atom in the
connection's meta (`connector.cljc:102`), swapped by `core.cljc:200-218`.
The connection's meta is its `:wrapped-atom`'s meta (`connector.cljc:46`), so
`alter-meta!` on that atom is the install path; no new fork API.

**Change.** Fork: `notify-listeners!` takes the connection; on a callback
Throwable with a `:listener-failure` handler in the meta it retires the key by
identity (`swap-vals!`, removes only while `(identical? (get m k) callback)`),
then calls the handler with `{:listener-key :callback :exception :tx-report
:retired?}`. With no handler it logs as before and keeps the registration
(upstream behaviour). Seon: `seon.cluster.store/listen-failures!` installs the
handler capturing the cluster's environment; `listener-failed!` wraps the
cause in an `ex-info` naming the listener key, retirement outcome, commit id
and basis-t and calls `fault/fault!` once. Its panic (stored, or not stored
when the write failed) is the declared case: both throwables printed whole to
stderr, return, so Datahike notifies the remaining listeners. `boot.clj`
installs it once the environment exists (granted hunk). `wake/route!`'s own
catch and `deliver!`'s fault-channel `offer!` are deleted: a refused delivery
throws into Datahike. `wake/unlisten!`'s `(catch Throwable _ nil)` became the
declared released-connection case (`db/connection?`).

**Placement.** The handler cannot live in `wake.clj`: `seon.fault` →
`seon.error` → `seon.render.value` → `seon.cluster.wake` is a cycle. The
connection-custody owner `seon.cluster.store` is outside `seon.fault`'s
closure (checked by a transitive require walk), and `boot.clj` already
requires it, so the boot hunk adds no require.

**Cost.** Success path: unchanged (one `try` frame per callback). Failure:
one `swap-vals!` on the listener map (O(listeners), a handful) plus one
`fault!` — the measured M4 cost, proportional to the failure's evidence and
its signature's rows (71-215 ms in M4's note), never the program or store.
Termination: the retired callback cannot see the fault's own commit; callbacks
already in captured snapshots may fail once more each, and those dedupe to
the same occurrence (count increment).

**Simplest alternative considered.** A Seon-side wrapper around each callback
that catches, retires itself by identity and calls `fault!` — no fork change.
Rejected: it keeps a catch at every registration site (the plan deletes the
router's), and a Datahike-side failure outside Seon's wrapper stays a log line.
The fork seam is 30 lines and covers every listener on the connection.

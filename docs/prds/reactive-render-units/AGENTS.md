# Reactive render units — working context

This PRD owns one runtime-observed render-unit engine for root, ordinary agent,
canvas/context surfaces, debug, and `/data`. Read [[roadmap]], architecture UI
and context, the `datastar-web-ui` skill, and the closest source authorities
before research or code. Use `data-oriented-clojure` before the plan and
`datahike` for every read/cursor assumption.

Begin with an exact dependency ledger for Datahike indexes/listeners, SCI,
ClojureScript/Shadow analyzer behavior, Datastar/idiomorph, Hiccup rendering,
gzip/SSE, token estimation, and any proposed bounded cache. Record selected
versions/SHAs, `reference-code/` paths, and idiomatic current call sites. The
existing runtime-reliability cache, routing, allocation, and root audits are
inputs, not authority over current source.

Runtime-observed reads are correctness authority. Declared source keywords may
rank focus/recency candidates but never veto a captured dependency. One unit
coordinate owns activation, captured reads/results, serialized output,
identical-output suppression, and final-consumer cleanup. Do not add a page-
specific transition, second feed, renderer-authored cache API, database value
in a cache key/value, stored subscription entity, or JVM cache.

Active-unit single-entry reuse is plain process-local data. A bounded recent
LRU is allowed only after measured reopen/cross-subscription value and must be
owned behind this one engine. Closed details do no query, SCI, Hiccup,
serialization, or token work.

Research belongs in `research/`; current source/gap/order and graduation proof
belong in [[roadmap]]. Default-cluster proof precedes any ACME coordination.

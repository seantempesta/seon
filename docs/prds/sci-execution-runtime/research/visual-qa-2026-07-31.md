# Visual QA of the rendered surfaces — 2026-07-31

An independent look, with eyes on the actual pixels and the actual prompt
bytes, at what Seon's surfaces and agent context look like on real data.

## Method

Cluster `visual-qa` booted from `ef8cc6f77` (own operator root, port 7758).
Three agents: `root` (pre-existing), `scout` (nursery agent, namespace
`my.agents.scout`), `flowkeeper` (assigned to the real namespace
`seon.flow`). Two messages posted through `POST /agent/{id}/message`; root
messaged scout, scout replied — five real runs against DeepSeek, with real
receipts, evals, faults and transcript facts.

Screenshots: Chrome headless, 1440x900 and 375x812, in `tmp/visual-qa/`
(gitignored; filenames cited below are the evidence names). Contexts captured
verbatim through `seon.render/walk` under
`seon.render/call-with-walk-context`, committed beside this document in
`visual-qa-2026-07-31/`.

### What every page looks like

`/`, `/ns/seon.flow` and `/agent/{id}` are the same renderer. The entire
above-the-fold is the shared cluster entity and the config entity, printed as
a generic key/value drill: `:db/id 4438`, `{} 5 keys`, and 27 rows of
`:seon.config.ai.retry/*`. `/` and `/agent/scout` differ, in the first 900
pixels, by exactly one word ("root" versus "scout"). The agent's own
transcript is thousands of pixels below the fold.

The page chrome is one line reading `agentdebug` — two nav links with no
separator, no title, no agent identity except a raw `[:seon.cluster.agent/id
"scout"]` printed as body text. There is no message form anywhere on the
page, so a human cannot talk to an agent from the UI at all.

The loudest visual elements on the page are red error cards. Twenty-one of
them, all carrying `data-error-kind=":seon.render.walk/elided"` — a normal
bounded-walk notice styled as a failure.

### The debug view

The two panes are the right idea: `:seon.render/ai` on the left,
`:seon.render/html` on the right, over the same walk. Both are unusable as
rendered. The left pane neither wraps nor scrolls, so every line is clipped
mid-word at the pane boundary. The right pane is squeezed into a narrow
column where table cells reflow to two characters (`:db` / `/id`,
`visual-` / `qa`). The left pane is also not byte-exact: it drops the walk
header line and prints maps with a different `*print-namespace-maps*` setting
than the agent's own capture. (Token bar absence is expected and not filed.)

### Live behaviour — verified negative

With `GET /feed/scout` held open for 20 s and a message committed during the
window, the stream delivered **zero bytes** — not even the initial paint.
A plain re-GET of `/agent/scout` after the same commit does show the new
fact, so the commit landed and only the live path is dead. The debug feed
(`/feed/scout?debug=true`) streamed 71,558 bytes over five
`datastar-patch-elements` events, so the transport works; the agent page's
producer is empty. Root cause, at the REPL:
`seon.render.block/membership` returns `[]` for every agent, so
`seon.render.web/page-of` returns `{}`.

## Reading these as a prompt engineer

**The header is clear.** `;; (seon.render/walk {:root …, :depth 2}) => root=…
basis=… depth=2` tells the agent what produced the text and how to widen it,
and the closing `;; REPL state namespace=… basis=… time=…` closes the frame.
That part is good and should survive any redesign.

**The `;; path=… depth=… provenance=…` labels are noise.** They are often
longer than the unit they label, they name an addressing scheme the agent is
never taught to use (`[:seon.render.walk/neighbours 4 :seon.render.walk/
neighbours 3]` is not something an agent can pass to anything), and they
interrupt the reading flow between every pair of units.

**The ordering is not sensible.** It is neither depth-first, breadth-first,
nor recency-ordered. Scout's depth sequence runs `3,3,…,2,2,1,2,2,0,2,2,1,…`;
the agent's own state sits in the middle; the config entity precedes the
message it was just sent. Nothing in the output expresses "this is new, this
is why you woke up".

**The transcript branch reads badly.** It arrives last, after everything has
already been said once, and repeats it: the same form appears as a run-form
unit, as a receipt unit, and again inside a `(comment …)` transcript entry
carrying the source string a third time. It also duplicates its own elision
note (`;; transcript/elided 3` immediately followed by `;; 3 older transcript
entries elided by the token budget.`).

**Would I know what to do?** Barely, and only because the instruction
paragraph is good. It is undermined by naming `my.message/send!`, which does
not exist — scout followed it, got lint-refused, and spent its entire second
turn recovering. Everything else the agent needs (its namespace, its unread
message, its last result) is present but has to be excavated.

## The five improvements, ranked by impact

1. **Fix the instruction text.** One character (`send!` → `send`) plus a
   correct arity in the example. It currently costs every new agent a full
   paid turn. Derive the example's symbols from the program graph so it
   cannot drift again.
   → `getting-started-instruction-names-a-nonexistent-function.md`

2. **Render an assigned namespace's functions.** The distance-1 branch emits
   definitions only when the `ns` form is literally bare, so every agent
   assigned to real code sees an empty workspace. This makes namespace
   assignment — the whole point of `flowkeeper` — inert.
   → `assigned-namespace-renders-none-of-its-functions.md`

3. **Cut the noise floor: elisions, path labels, and echoed captures.**
   42-86 opening lines of `elided connections at the requested distance cap`,
   one machine label per unit, and the previous prompt quoted back verbatim
   inside `:seon.context.capture/prompt` (2310 → 5290 tokens across two
   turns). State the frontier once; drop the labels; stop walking capture,
   attempt and transaction entities into the prompt.
   → `walk-elisions-render-as-error-cards.md`,
   `context-captures-re-enter-the-next-prompt.md`

4. **Order by relevance and say each fact once.** Own state and newest
   unread work first, instructions and toolkit next, history last — and one
   rendering per fact instead of the current three to five.
   → `walk-output-is-unordered-and-repeats-itself.md`

5. **Give the raw entities a family render or omit them.** Transaction rows
   (`{:db/id 536870940, :db/txInstant …}`), `:seon.ai.attempt` rows, and the
   config entity are printed as generic data prose in both the prompt and the
   page. They are the bulk of the visible garbage and none of it is
   actionable by an agent.

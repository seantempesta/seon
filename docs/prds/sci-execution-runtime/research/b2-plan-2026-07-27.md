# B2 implementation plan — config→facts, schema EDN, and the shared bootstrap ancestor (2026-07-27)

This is the PLAN for the B2 rung, written for the orchestrator to review and
fix before it authors sealed contracts. It contains no production code
changes. Every claim is grounded in `file:line` from the quarry, from
`reference-code/`, or from an executable probe committed under `tmp/b2-probe/`
whose output is pasted below.

**The one-sentence answer to the rung's hardest question:** a Datahike `:file`
store directory CAN be cloned to a new path and opened as a distinct store, but
only after its `:db` branch head's stored `[:config :store :id]` is rewritten —
otherwise `d/connect` refuses with `:store-identity-mismatch`
(`reference-code/datahike/src/datahike/connector.cljc:160-169`). Measured:
clone + re-identify + connect = **68 ms** for a 15,000-datom ancestor, against
**2,261 ms** to create and re-transact the same rows — a 33× fork.

## 2. The decisive experiments

### 2.1 A cloned store refuses to open under a path-derived id

`ensure-stored-config-consistency` compares the stored `[:store :id]` against
the connect-time `[:store :id]` and raises when both are present and differ
(`reference-code/datahike/src/datahike/connector.cljc:160-169`). The rest of
`:store` — including `:path` — is deliberately excluded from the comparison
(`connector.cljc:171-174`). B1 derives `:id` from the canonical path
(`src/seon/cluster/store.clj:139-140`), so a clone at a new path always
mismatches.

```
== 2. stored config of A (what the clone carries) ==
{:ok {:backend :file, :path ".../stores/a", :id #uuid "f35ddf4e-...-6b9a47e82812"}}

== 4. connect B with PATH-DERIVED id (B1's datahike-configuration) ==
{:err "Store identity mismatch: connecting to wrong database.",
 :type :store-identity-mismatch,
 :data {:stored-id #uuid "f35ddf4e-...", :connect-id #uuid "769a5e15-..."}}
```

### 2.2 `:allow-unsafe-config` is NOT the fix — it poisons the store

Setting the flag skips the whole check, but the flag then rides the live
config into the next commit's stored `:config`
(`reference-code/datahike/src/datahike/writing.cljc:48-70` persists the db's
`config`), so every later flag-free connect fails a *different* way:

```
== 6. connect B with path-derived id + :allow-unsafe-config true, transact, release ==
{:ok {:stored-store {...}, :stored-unsafe true}}

== 7. reconnect B WITHOUT the flag ==
{:err "Configuration does not match stored configuration...",
 :type :config-does-not-match-stored-db,
 :data {:diff (nil {:allow-unsafe-config true} {...})}}
```

**Verdict: reject.** It converts a one-time fork problem into a permanent
config asymmetry.

### 2.3 Konserve-level re-identify works, is durable, and is fast

Rewriting `[:config :store :id]` (and, for honesty, `[:config :store :path]`)
in the `:db` branch head with one `k/get` + `k/assoc` before the first
`d/connect` makes the clone an ordinary store. Reads, writes, history, and
plain reopen all behave:

```
== 8. clone A -> C, konserve-level re-identify, then PLAIN connect ==
{:ok {:facts-before 1, :facts-after 2}}
== 9. reopen C plainly again (durability of the re-identify) ==
{:ok {:facts 2}}
```

At scale (5,000 indexed functions = 15,000 datoms, 3.2 MB on disk):

```
ancestor build ms: 2527.0   datoms: 15000   on-disk bytes: 3200271
FORK  clone-ms: 52.3  reidentify-ms: 13.8  connect-ms: 1.5  query-ms: 189.5
      fns-found: 5000  after-write: 5001  history-visible: 5001
FORK  total-to-usable-ms: 67.6
REOPEN fork ms: 14.0  fns: 5001
ANCESTOR after fork, fns: 5000        <- ancestor untouched (O2 holds)
RETRANSACT create+load ms: 2260.9     <- the alternative we are replacing
```

### 2.4 A shared `:id` across two paths refuses loudly (so it is not an option)

If the ancestor's id were simply reused, two clusters in one JVM would collide
on Datahike's `[store-id branch]` connection id
(`reference-code/datahike/src/datahike/store.cljc:50-61`). Probe 10 confirms
the second open is refused, not silently aliased:

```
== 10. two stores, SAME :id, different paths, both open in one JVM ==
{:err "Configuration does not match existing connections.",
 :type :config-does-not-match-existing-connections}
```

Good news for safety; fatal for a shared-id design. **Re-identify is mandatory,
not optional.**

### 2.5 "Converged = zero writes" cannot mean "transact an empty plan"

This is the result that shapes the config contract. Datahike commits a
transaction entity even for empty tx-data, and even when a `[:db.fn/call …]`
returns no operations:

```
after write : {:t 536870914, :datoms 11}
empty tx-data -> {:t 536870915, :datoms 12}  same-as-before? false   (report tx-data count: 1)
db.fn/call -> [] -> {:t 536870916, :datoms 13}  same-as-after-write? false
re-assert identical value -> {:t 536870917, :datoms 14}
```

Two consequences:

1. **The converged check must happen BEFORE any transact.** `reconcile!`
   computes its plan purely against a database value; an empty plan returns
   `{::converged? true ::operations 0}` and issues **no transaction at all**.
2. Re-asserting an identical value writes no *domain* datom (13→14 is only the
   tx's `:db/txInstant`), so per-attribute equality diffing is partly free —
   but the transaction is not. The acceptance measure is "basis transaction
   `:t` is unchanged after a converged re-apply", which is directly
   observable.

## 4. Data model sketch

### 4.1 Bootstrap phase (pre-store, closed, already exists)

`:seon.boot/config` in `src/seon/cluster.clj:67-74` — five keys, closed. B2 adds
**one** key, and only because the fork must happen before the store opens:

```clojure
; the ancestor store to fork when this cluster's store does not exist;
; absent = create an empty store (the ancestor build itself, and tests)
[:seon.boot/ancestor-dir {:optional true} [:string {:min 1}]]
```

A `--config <path>` manifest path is a *launch argument*, not a bootstrap
config key: it is consumed once by `bin/seon start` and never read again
(runtime reads the database).

### 4.2 Database phase — the config singleton

One entity per store, identified by the cluster name so the upsert handle is a
real identity attribute rather than a magic sentinel:

```clojure
:seon.config/cluster    [:string {:min 1 :seon.db/identity true}]
:seon.config/applied-manifest-digest [:re "[0-9a-f]{64}"]   ; provenance, not a gate
```

Every dial is its own attribute on that entity, each with its own registered
schema — the pattern quarried from `src-old/seon/config/resolve.cljc:98-103`
("register once, reference everywhere"), which is right and survives. The dial
population itself starts near-empty in B2: the honest list today is
`seon.flow`'s 60 registrations (`src/seon/flow.clj`) plus
`:seon.config/on-core-error`. **B2 does not port State A's 39
`operational-keys`** (`src-old/seon/config/resolve.cljc:542-580`); those name
transport, UDS, executor and pod machinery that no longer exists.

### 4.3 Ancestor facts (written by the build, read by every fork)

```clojure
:seon.ancestor/digest   [:re "[0-9a-f]{64}"]   ; identity of the indexed inputs
:seon.ancestor/built-at :inst
```

These ride in the ancestor store itself, so a forked cluster can answer "what
was I born from?" as a query with no file read.

### 4.4 What is deliberately NOT an attribute

- no `:seon.config/converged?` — converged is a computed comparison, never
  stored;
- no `:seon.ancestor/forked?` boolean — B1's `:seon.store/created?` plus the
  ancestor digest fact already carry it;
- no applied-manifest *file*. State A's `publish-applied-manifest!` /
  `delete-applied-manifest!` (`script/seon/dev/cluster.clj:505`) is a second
  state authority beside the database. **Dead.**

## 5. The shared bootstrap ancestor

### 5.1 Identity — a digest of the inputs, not of an artifact

State A keyed the template by `(application-digest, cluster-name)`
(`script/seon/dev/cluster.clj:43-56`). Both halves are baggage:

- the *application digest* came from the AOT/Shadow artifact chain, which the
  2026-07-27 build ruling condemns and which does not exist in dev;
- the *cluster name* was needed only because State A derived the store id from
  the database name (`src-old/seon/db/backend.clj:105-109`), so a template had
  to be built per name. Re-identify removes that coupling entirely.

**Proposed:** `ancestor-digest` = SHA-256 over the sorted sequence of
`[resource-path, sha256(source-bytes)]` for every indexed `.clj`/`.cljc` under
`src/`, plus every `src/seon/schema/*.edn`. Pure, cheap (the indexer already
computes per-file digests — `script/seon/dev/program_indexer.clj:40-47,75-91`),
and true in dev with no build artifact. Ancestor path:
`data/ancestors/<digest>/store`, a sibling of `data/clusters/`.

### 5.2 Build half

One deliberate command (`bin/seon build-ancestor`, or `bin/seon start`'s
first-run path):

1. compute `ancestor-digest`; if `data/ancestors/<digest>/store` exists, stop —
   this is the whole cache;
2. open a store at `data/ancestors/<digest>/.build-<uuid>/store` through B1's
   `open-store!` (so the flock and genesis verification are the same one
   mechanism);
3. transact, in order: the schema population from `src/seon/schema/*.edn`
   (§6), the program-graph rows from the indexer, the ancestor facts (§4.3);
4. `release-store!`;
5. atomic `Files/move` of `.build-<uuid>` to `<digest>` — quarried directly
   from `script/seon/dev/cluster.clj:69-90`, which already builds into a
   `.tmp` sibling and atomic-moves. A killed build leaves an orphan
   `.build-*` directory and nothing else; the digest directory only ever
   appears complete.

What lands in the ancestor: `:seon.schema` rows, `:seon.ns`/`:seon.fn` rows,
`:seon.test` rows, ancestor facts. **Not** config facts — config is per-cluster
and reconciles after the fork (§7), so one ancestor serves every cluster and
every manifest.

### 5.3 Fork half — the exact mechanism

```
acquire flock on <cluster>/store.lock          (B1's, unchanged, still FIRST)
  store dir absent?
    yes and ancestor given -> clone  <ancestor>/store -> <cluster>/.store.<uuid>.tmp
                              reidentify! <cluster>/.store.<uuid>.tmp
                              atomic move -> <cluster>/store
    yes and no ancestor    -> d/create-database        (B1's existing path)
    no                     -> genesis check / connect  (B1's existing path)
```

- **Clone** is `/bin/cp -cR` on macOS (APFS copy-on-write) and
  `cp --reflink=auto -a` on Linux, exactly
  `script/seon/dev/cluster.clj:58-66`. Adopt the shape, adopt the refusal when
  the OS is neither ("An at-rest template database cannot be cloned on this
  host") — but **change the refusal into a fallback to `create-database` +
  re-transact**, because a fork failure must not make the system unstartable
  on an unrecognised host. Owner call flagged in §11.
- **`reidentify!`** is one `k/get :db` / `k/assoc :db` pair on the cloned
  directory, setting `[:config :store :id]` and `[:config :store :path]` to
  the target's values (proven §2.3, 13.8 ms). It runs BEFORE any `d/connect`
  and before the directory takes its final name.
- **Temp-then-move** means the mis-identified intermediate state never exists
  at the real path, so `open-store!` can never encounter a store carrying a
  foreign id. That is what makes the crash walk clean (§10).

### 5.4 Resume half

A restarted cluster has its own complete store: the store directory exists, so
the fork branch is never entered and the ancestor is never consulted. This
needs **no new detection** — it is B1's existing existence check
(`src/seon/cluster/store.clj:244-253`), and B1 already reports the outcome as
`:seon.store/created?`. The ancestor is consulted exactly once in a cluster's
life.

A cluster forked from a *stale* ancestor (source has changed since) keeps
running against its own facts; refreshing is a cluster RESET (L18: clusters
always reset, never migrate), which deletes the store and forks the current
ancestor. That is the same operation as first boot — one mechanism.

## 6. Schema EDN + the one admission gate

### 6.1 What `register!` already does (do not rebuild it)

`src/seon/schema.cljc:739-812` already enforces that a schema form is
**readable EDN that round-trips** (`:seon.schema/unreadable-form`,
`:seon.schema/non-round-tripping-form`), rejects nilable value schemas
(`internal/assert-non-nilable-value-schema!`), and runs
`assert-complete-contract!` against the whole candidate population, so
declaration order cannot change acceptance. `build-projection`
(`schema.cljc:828-851`) validates the complete population and derives the
dependency indexes and entity catalog. The registry facade
(`schema.cljc:341-352`) and `activate!` (`schema.cljc:1551-1562`) are the one
publication point.

**Because forms are already EDN-only by construction, moving them to `.edn`
files is a relocation of the same values, not a new format.**

### 6.2 What the EDN loader must add

| Requirement (from the sealed ruling) | Why `register!` does not cover it | Design |
|---|---|---|
| duplicate attribute refused ACROSS files | `register!` ends in `(update-candidate-forms! assoc k v)` (`schema.cljc:811`) — a silent overwrite | the loader merges file-by-file and refuses on a key already contributed by another file, naming both files |
| all references resolve | `build-projection` does this for the population it is given | the loader hands `build-projection` the WHOLE merged population once, not per file |
| every `[:fn]` names a registered core predicate | today a missing predicate degrades through `runtime-predicate` returning nil | a post-merge check over `predicate-symbols-in` against `core-predicate-functions`; refuses with the symbol and the file that used it |
| generative-honesty lint | not present anywhere in fresh `src/` | port the static rules from `research/malli-generative-patterns-2026-07-26.md:42,682-729`: every `[:fn …]` carries `:gen/schema` or `:gen/gen`; no bare `:fn`, `fn?`, or dishonest override |
| one gate shared with agents' `register!` | `register!` is the agent producer already | make the gate ONE function, `seon.schema.edn/admit`, called by the loader over a merged population and by `register!` over `(assoc population k v)` |

### 6.3 Load ordering — the one real hazard

`[:fn 'seon.flow/executor?]` and friends bind through
`register-core-predicate!` in code (`src/seon/cluster.clj:112`,
`src/seon/cluster/store.clj:84-87`). If the EDN loads before those namespaces,
the `[:fn]` check fails. Resolution: **the `[:fn]` check runs at ACTIVATION,
not at load.** The boot sequence becomes: load namespaces (predicates register)
→ `schema.edn/load!` (merge + duplicate refusal) → `schema/activate!` (full
population validation, including the `[:fn]` and honesty checks). This is
strictly better than today's load-order-sensitive per-`register!` assertion and
should be named in the contract.

Classpath enumeration of `seon/schema/*.edn` must handle both a `file:` URL
(dev, source classpath) and a `jar:` URL (publish). ~15 lines over
`(.getResources (clojure.lang.RT/baseLoader) "seon/schema")`. Risk row in §11.

### 6.4 The conversion list — every `register!` in fresh `src/`

| File | `register!` | `register-core-predicate!` | verdict |
|---|---|---|---|
| `src/seon/flow.clj` | 60 | 6 | convert forms → `src/seon/schema/flow.edn`; predicates stay |
| `src/seon/cluster/run.cljc` | 25 | 0 | → `src/seon/schema/run.edn` (the N2 conversion the sealed ruling defers to B2) |
| `src/seon/cluster.clj` | 11 | 1 | → `src/seon/schema/boot.edn`; `socket-server?` stays |
| `src/seon/cluster/store.clj` | 3 | 2 | → `src/seon/schema/store.edn`; `connection?`/`file-lock?` stay |
| `src/seon/schema.cljc` | 10 | 2 | **STAY IN CODE** — these are the registry's own bootstrap shapes; the loader cannot use schemas it has not loaded yet |
| `src/seon/schema/internal.cljc` | 5 | 0 | **STAY IN CODE** — same reason |
| `src/seon/schema/datahike.cljc` | 1 | 0 | **STAY IN CODE** — same reason |

Totals: **115 `register!`, 11 `register-core-predicate!`**; 99 forms move,
16 stay as the registry's own bootstrap. That exception is *computed*, not a
hand list: it is exactly the schemas the `seon.schema.*` namespaces themselves
need to validate an EDN file. Name that rule in the contract so it does not
decay into an allowlist.

## 7. Config reconciliation

### 7.1 The algorithm, quarried

`src-old/seon/runtime/state.cljs` is the prior art and its core is right
(docstring, `state.cljs:1-13`): the managed slice is defined by **provenance,
not a taxonomy**; reconcile takes no "kind" argument and runs no id-attr
registry loop; it operates in attribute space. Concretely
(`state.cljs:263-344`):

1. every desired entity map carries exactly ONE `:db.unique/identity`
   attribute — the upsert handle; zero or two is refused, not guessed
   (`state.cljs:61-70`);
2. the current managed population is enumerated by the first-assertion
   transaction's process being in the managed scope, plus explicitly adopted
   identities (`state.cljs:282-296`);
3. per entity, the exact diff: attributes present-in-one-and-not-the-other, or
   present in both and unequal, are retracted (`:db.fn/retractAttribute`) and
   the desired values re-asserted (`state.cljs:226-261`);
4. managed entities whose identity is absent from the desired population are
   `:db.fn/retractEntity`'d (`state.cljs:332-343`);
5. a desired identity already owned by an entity OUTSIDE the managed scope is
   a refusal, never a silent adoption (`state.cljs:302-321`).

### 7.2 What changes

| Old | New | Why |
|---|---|---|
| `^:async`, `<!`, wire query members (`state.cljs:414-462`) | plain synchronous Clojure over a database value | O1: reads are a pointer into an immutable value |
| `max-reconcile-attempts 3` + full-head staleness retry (`state.cljs:72,510-514`) | **deleted**: the plan recompiles inside the writer via `[:db.fn/call #'reconcile-call request]` | the N2 idiom (`src/seon/cluster/run.cljc:307`); there is no stale basis inside the serial writer |
| `db/decode-edn-value` per attribute (`state.cljs:111`) | deleted | that was the wire codec's inverse; nothing crosses a wire |
| `:seon.db/managed-scope` as a caller argument | the ONE core process identity B2 owns | one producer today; a scope argument is a generality nobody uses |
| response is `{::ok? true ::changed? … ::operations … ::attempts …}` | `{::converged? bool ::operations int}` (no `::attempts`, no `::ok?` — refusals throw at this layer, per B0/B1's house style) | §2.5 makes `::converged?` the load-bearing fact |

### 7.3 The converged=zero-writes contract

```
plan  = (reconcile/plan db request)     ; pure, no transaction
empty? -> {::converged? true ::operations 0}       ; ZERO transactions issued
else   -> (d/transact conn {:tx-data [[:db.fn/call #'reconcile-call request]]})
          {::converged? false ::operations (count …)}
```

The acceptance measure is observable and cheap: **`(:max-tx (d/db conn))` is
identical before and after a converged re-apply** (§2.5 shows why any
transaction, even empty, would break it).

### 7.4 Provenance scoping and drift repair

Provenance is Datahike transaction metadata, already the house mechanism
(`:seon.db/user` / `:seon.db/process`). The managed scope for config is one
process identity. Note the quality review's B2 input: `seon.schema`'s
`core-process-identities` (`src/seon/schema.cljc:261-265`) is a three-element
hand list and violates L17. **Computed replacement proposed:** a transaction is
core-provenance iff its `:seon.db/process` entity was itself asserted by the
ancestor build or by a transaction that is already core-provenance — i.e.
core-ness is inherited from the ancestor's genesis rather than matched against
a literal set. This needs its own falsifier and is the one piece of B2 I am
least confident in; see §11.

Drift repair is not a separate feature: a hand-edited fact simply appears in
the current population and diverges from desired, so the next explicit apply
retracts and re-asserts it. Nothing detects drift; reconcile just converges.

### 7.5 The defaults document

`bin/seon start` with no `--config` uses the shipped default manifest, which is
THE defaults document: complete, explicit, every constant with units and
calibration provenance. `(or x 60000)` stays banned. A user manifest declares
only overrides. This is the s3 ruling verbatim and needs no new mechanism —
but note it means B2 must WRITE that default manifest, and today the honest
dial population is `seon.flow`'s 60 plus `:seon.config/on-core-error`, not
State A's 39 transport/executor keys.

## 8. Port manifest

Default verdict is `dead`; a rung that ports more than it sheds is suspect.

| Piece | Verdict | Why |
|---|---|---|
| `clone-command` + `clone-tree!` (`script/seon/dev/cluster.clj:58-90`) | **adopt** | correct on both platforms, temp-then-atomic-move, bounded error diagnostic. Copy the shape into `seon.cluster.ancestor`, drop the `babashka.fs`/`babashka.process` dependency |
| `template-database-path` keyed by `(application-digest, cluster-name)` (`cluster.clj:43-56`) | **rewrite** | both key halves are operator baggage (§5.1); re-identify removes the cluster-name half, the build split removes the artifact half |

## 10. Falsifiers for the rung

1. **Fork is near-instant and correct.** Build an ancestor; start clusters `a`
   and `b` side by side in ONE JVM; both open, both see every ancestor fact,
   both accept writes, neither sees the other's writes, and the ancestor is
   byte-identical afterwards. Fork-to-usable under 250 ms (measured 68 ms at
   15,000 datoms).
2. **Restart resumes, never re-forks.** Stop cluster `a`, corrupt/remove the
   ancestor directory, restart `a` — it opens from its own store.
3. **Converged re-apply is zero writes.** Apply the default manifest twice;
   `(:max-tx (d/db conn))` is identical after the second apply.
4. **Drift repairs.** Transact a wrong dial value directly; re-apply; the fact
   is back and `::operations` is non-zero.
5. **Duplicate attribute refuses.** Two EDN files declaring one key fail
   `load!` naming both files.
6. **A `[:fn]` without a registered predicate refuses at activation**, with the
   symbol named.
7. **Crash walk**: `kill -9` a child JVM at each row of §9 and prove the "next
   boot" column, in the style of B1's `test/seon/cluster/store_child.clj`.
8. **Generative property** over reconcile: for any generated (current,
   desired) pair, applying the plan yields a database whose managed population
   equals desired exactly, and re-planning yields the empty plan (convergence
   in one step is the property; two-step convergence is a bug).

## 11. Risks and open questions, ranked

1. **The `core-process-identities` replacement (§7.4) is the weakest part of
   this plan.** A computed core-provenance rule that is *inherited from the
   ancestor's genesis* is elegant but unproven; the fallback is to keep the
   literal set for B2 with an explicit issue, because a wrong answer here means
   agent-authored schemas get core strictness. **Recommend: keep the literal
   set in B2, file the computed rule as its own bounded unit.** Owner call.
2. **Store-id derivation.** B1 derives `:id` from the canonical path
   (`store.clj:139-140`); State A derived it from the database name
   (`src-old/seon/db/backend.clj:105-109`). Path-derived means a cluster
   directory that is MOVED will not open until re-identified; name-derived
   means it opens anywhere but two copies of one cluster name in one JVM
   collide (loudly — §2.4). **Recommend: keep B1's path-derived rule and make
   `reidentify!` public**, which serves the move/copy case in one call. Owner
   call, because it is a taste decision about what a store's identity *means*.
3. **Clone on an unrecognised OS.** State A refused
   (`cluster.clj:91-97`). Refusing makes the system unstartable on a host
   without `cp -c`/`--reflink`; falling back to create+re-transact makes first
   boot slow but always works. **Recommend: fall back, loudly.** Owner call.
4. **Classpath enumeration of `seon/schema/*.edn` in a jar.** Dev is a source
   classpath and trivially works; the publish build must be proven. Mitigation:
   the runtime normally reads schema FACTS from the forked store, so the jar
   path matters only for `(schema/reload!)` and the ancestor build — both of
   which run from source. Low risk, but it must be stated rather than assumed.
5. **Ancestor digest scope.** Digesting every `src/**.clj{,c}` plus the schema
   EDN means any source edit invalidates the ancestor and the next *fresh
   cluster* pays one rebuild (2.5 s at today's size). Running clusters are
   unaffected (hot reload). Acceptable, but the number grows with the corpus
   and should be measured again at N5.
6. **The re-identified head diverges from its content-addressed commit
   record.** `reidentify!` rewrites the mutable `:db` head; the immutable
   commit blob keyed by `cid` still carries the ancestor's `:config`
   (`writing.cljc:707-709` writes the `cid` blob and the `:db` head from the
   same value). Nothing in the read path consulted it
   in the probe (history worked, 5,001 rows), but a future audit/commit-graph
   feature could notice. Cheap mitigation: also rewrite the `cid`-keyed blob.
   Flagged, not solved.
7. **B1 is sealed and green; B2 revises it.** `open-store!` gains an optional
   ancestor and its argument becomes a map. That is an orchestrator-authored
   contract revision, not a lane's local decision, and `store_test.clj` +
   `store_child.clj` move with it.
8. **`:seon.boot/ancestor-dir` enters the closed bootstrap schema.** The rung's
   own rule is that a key the database could own does not belong in bootstrap.
   This one genuinely cannot: it is consumed to CREATE the database. Worth an
   explicit sentence in the contract so the next reader does not read it as
   drift.

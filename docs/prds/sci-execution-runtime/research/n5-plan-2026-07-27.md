# N5 — corpus round trip: implementation plan

N5 closes one contract:

```text
agent-authored defn
  → admitted :seon.fn facts connected to existing :seon.ns facts
  → contract and schema rows admitted by seon.schema
  → one committed transaction report
  → re-derive projection and installable forms from :db-after
  → sci.lang.Var in an agent ctx
  → invocation through the armed evaluator
  → seon.sci.admit/admit
```

The smallest N5 accepts one literal, fully contracted `defn` or `defn-`.
Namespace declarations and schema registrations are separate durable forms
with their own identities. A definition publication neither fabricates nor
rewrites either. The database program graph is the authority; schema
projections and SCI contexts are disposable derivations.

## 3. Ownership boundary

N5 extends landed owners; it does not create parallel ones.

| Owner | Responsibility |
|---|---|
| `seon.schema` | admit candidate schema/function contracts, build `projection-from-rows`, derive direct function dependencies and admission provenance |
| small program-fact owner, name pending decision 1 | pure `defn` analysis, exact publication transaction data, namespace/function row queries, deterministic installable forms |
| N3 armed evaluator, exact namespace pending decision 5 | fork the `ctx`, install forms, resolve/type-check the SCI var, evaluate calls, and pass the result to `seon.sci.admit/admit` |
| `seon.cluster/populate-ancestor!` | retain its three ordered transactions and add analyzed core program rows to the third transaction |

N5 adds no schema declaration merely for function-to-schema dependencies.
It also adds no ordinary-value predicate, projection, receipt codec,
diagnostic family, process/user request fields, work/message rows, or trigger
metadata.

The pure boundary is:

```clojure
(analyze-defn
 {:seon.program/source source
  :seon.program/namespace-row committed-namespace-row
  :seon.program/schema-projection projection})
→ {:seon.program/function-row ...
   :seon.program/function-contract ...
   :seon.program/direct-schema-keys #{...}}

(publication-tx-data
 db
 {:seon.program/analysis analysis})
→ ordinary transaction data or classified ex-data

(acquire-program
 {:seon.program/database-value db
  :seon.program/namespace namespace-symbol})
→ {:seon.program/namespace-row ...
   :seon.program/function-rows [...]
   :seon.program/projection-input ...}

(installable-forms acquired projection)
→ [namespace-form declare-form definition-form ...]
```

`publication-tx-data` is suitable for `:db.fn/call`. Authorship comes from the
outer transaction's `:seon.db/user` and `:seon.db/process`; the publication
request does not duplicate them. `:seon.db/trigger` is used only on the
run-opening transaction (`src/seon/schema/provenance.edn:17-25`).

## 4. Data model

### 4.1 Durable function

A durable function is the entity with `:seon.fn/sym`; it has no `:type` or
`:kind`.

| Attribute or connection | Requirement |
|---|---|
| `:seon.fn/sym` | required identity string; qualified symbol rendered as a string |
| `:seon.fn/ns` | required ref to an existing `:seon.ns/name` entity |
| `:seon.fn/source` | required exact accepted single-form source |
| `:seon.fn/source-fingerprint` | required deterministic digest selected in decision 6 |
| `:seon.fn/spec` | required canonical EDN string of the complete function schema |
| `:seon.fn/arglists`, `:seon.fn/doc`, `:seon.fn/private?` | optional, derived from the accepted literal form |

These shapes are already registered at
`src/seon/schema.cljc:501-515,530-546`. N5 does **not** store
`:seon.fn/schema-refs`. Direct function dependencies are derived from compiled
contracts at `src/seon/schema.cljc:1094-1109` and explicitly remain projection
data rather than durable state (`:181-202`).

N5 never writes `:seon.fn/fn-var?`, `:seon.fn/schema-error`,
`:seon.fn/created-at`, installed/callable flags, execution placement,
generation, or owner-agent fields. Function authorship and time are read from
the source datom's asserting transaction.

Although the canonical `:seon.fn` entity map makes `:seon.fn/spec` optional for
historical/core compatibility (`src/seon/schema.cljc:530-546`), the N5
publication constructor requires it. Missing, unparsable, unresolved,
non-function, `:any`, `:some`, `:nil`, or `[:maybe ...]` contracts produce a
user-input refusal before transaction data exists.

### 4.2 Namespace row

`:seon.ns/name` is the identity and `:seon.ns/source` is required
(`src/seon/schema.cljc:520-525,556-564`). A function publication receives the
complete committed namespace row. It:

- refuses when that row is missing;
- checks that the unqualified function name resolves under that identity;
- connects `:seon.fn/ns` to the existing entity; and
- never creates, rewrites, or “improves” namespace source or require edges.

The namespace-declaration producer owns `:seon.ns/source` and
`:seon.ns/require-edges`. It parses the one accepted `ns` form once and commits
both projections. Definition analysis cannot derive those facts because its
input contains no `ns` declaration. Decision 2 seals whether missing namespaces
are always refused or may be created by an explicit earlier namespace form.

### 4.3 Schema rows and contracts

`:seon.schema/key` is the identity, `:seon.schema/form` is the canonical EDN
string, and `:seon.schema/ns` is an optional connection
(`src/seon/schema.cljc:490-493,547-555`). Agent-authored schema facts follow one
path:

1. a separate `schema/register!` evaluation runs inside
   `schema/begin-registration-delta` /
   `schema/call-with-registration-delta`
   (`src/seon/schema.cljc:1716-1735`);
2. `seon.schema.edn/admit` validates the candidate using the same gate as
   classpath `load!` (`src/seon/schema/edn.clj:173-191,268-297`);
3. the terminal transaction commits changed canonical `:seon.schema` rows with
   asserting-transaction provenance;
4. `schema/projection-from-rows` rebuilds the complete projection from schema,
   function-contract, and function-source query rows
   (`src/seon/schema.cljc:1470-1593`); and
5. `schema/activate-projection!` publishes only that already validated
   projection (`:1650-1664`).

A later definition references those committed keys in `:seon.fn/spec`.
`projection-from-rows` both derives admission from each asserting transaction
and computes direct function dependencies. No dependency connection is stored.
The existing `:seon.schema/created-at` field remains unchanged until decision 3;
N5 does not infer a migration from the function-row policy.

## 5. Round-trip contract

### 5.1 Source string → analyzed function facts: pure

`analyze-defn` parses with SCI and accepts exactly one top-level literal
`defn`/`defn-`. Its explicit inputs are the source string, the existing
namespace row, and the database-derived schema projection. It:

1. refuses a qualified declared name;
2. extracts the accepted metadata grammar selected in decision 3;
3. requires a complete literal `:malli/schema`;
4. validates that contract through the `seon.schema` projection;
5. reads direct schema keys from the projection's derived function
   dependencies;
6. returns only the function row, contract, and diagnostics needed to explain
   a refusal.

It does not evaluate, query a connection, fabricate namespace/schema rows,
inspect host Vars, diff analyzer state, mutate a registry, or walk a call graph.

### 5.2 Analyzed facts → transaction data: pure

`publication-tx-data` receives Datahike's mid-transaction database value and
the analysis. It verifies the namespace still exists unchanged, refuses
duplicate desired identities and entities carrying conflicting identity
attributes, and emits an identity upsert plus explicit retractions for optional
function attributes omitted by redefinition. Identity-upsert and transaction
function behavior are grounded at
`reference-code/datahike/src/datahike/db/transaction.cljc:935-985,1142-1143`;
the first-party duplicate refusal precedent is
`src/seon/reconcile.cljc:304-312`.

The N3 terminal transaction contains the successful receipt and function
transaction data. Schema and namespace facts were committed by their own
earlier forms; the function does not claim to author them. A refusal yields no
function transaction data and the outer run loop records the flat agent error.

### 5.3 Facts → projection and installable forms: pure

`acquire-program` queries one explicit database value for:

- the exact namespace row and its require connections;
- all function rows connected through `:seon.fn/ns`; and
- schema/function-contract/function-source triples including asserting
  transaction entity IDs in the shape required by
  `schema/projection-from-rows`.

It delegates contract parsing, provenance admission, and dependency derivation
to `schema/projection-from-rows`; it does not repeat them. `installable-forms`
returns:

1. the stored namespace form;
2. one `(declare ...)` with unqualified function names sorted by qualified
   symbol; and
3. exact stored definition forms sorted by `:seon.fn/sym`.

Required namespaces follow stored require edges and SCI `:load-fn`.
Declaration-first installation handles same-namespace forward references
without storing call edges. Reading the exact stored forms for evaluation is
not a second program graph builder.

### 5.4 Install into a `ctx`: the one effectful edge

The N3 evaluator owner selected in decision 5:

1. arms the one `:interrupt-fn`;
2. forks a process base in which the target program namespace is absent;
3. evaluates the deterministic installable forms;
4. resolves the requested symbol;
5. asserts `(instance? sci.lang.Var value)` and the exact
   `(sci/var->symbol value)`;
6. evaluates the next agent call form in that same armed `ctx`; and
7. calls `seon.sci.admit/admit` **before disarming**, returning only its
   projection and existing diagnostics.

The SCI var class is established at
`reference-code/sci/src/sci/lang.cljc:71-92`; `sci/var->symbol` and
`sci/resolve` are at `reference-code/sci/src/sci/core.cljc:676-685`. Host
`@var` invocation may be a dependency probe, but it is not the guarded-call
proof. `fork` guarantees isolation only for new vars
(`reference-code/sci/src/sci/core.cljc:318-323`), so the base-namespace
precondition is tested rather than generalized.

## 6. Basis, provenance, and boot

```text
form N begins with db-N
  → armed evaluation
  → terminal transaction commits receipt + function delta
  → report-N exposes db-after
  → form N+1 queries report-N.db-after
  → projection-from-rows
  → install into a fresh agent ctx
  → armed invocation
  → seon.sci.admit/admit
```

No function obtains an ambient connection. The program graph is cluster-shared
(`docs/seon/architecture/architecture.md:81-86`); acquisition has no author
filter. The asserting transaction carries `:seon.db/user` and
`:seon.db/process`. Trust is derived from ancestor history, not from a literal
process allow-list (`src/seon/schema.cljc:321-373`).

`populate-ancestor!` already performs three ordered transactions:

1. install derived Datahike attribute declarations;
2. assert the core process entity; and
3. assert canonical rows with `:seon.db/process` transaction metadata
   (`src/seon/cluster.clj:309-334`, landed in `eda73bead`).

N5 preserves that ordering. The third transaction is extended with
deterministically analyzed core namespace/function rows and the same core
transaction metadata; it does not replace a “schema-only producer.” The
ancestor seal occurs after population, so process identity exists before rows
whose admission is later derived from history.

## 7. Crash walk

| Kill point | Durable state | Recovery |
|---|---|---|
| before or during pure analysis | no N5 facts | discard invocation-local data |
| after definition installation, before terminal transaction | running receipt only | N3 boot marks it interrupted; do not republish or re-execute |
| while Datahike applies terminal transaction | all or nothing | either running receipt remains or receipt plus complete function delta commits |
| after commit, before projection activation | complete facts | reopen and call `projection-from-rows`; activation is disposable |
| while materializing a namespace | complete facts | discard the `ctx`; query and install again |
| while invoking or admitting its result | N3 running receipt identifies the ordinal | boot marks interrupted; no form/effect is refired |
| after terminal receipt | complete facts and admitted result | ordinary reopen path |

Recovery never replays eval history (`plan/README.md:295-308`). Re-derivation
evaluates only the admitted namespace and definition forms from program facts,
not the original arbitrary eval stream.

## 8. Sealed-suite sketch

All falsifiers are recurring `bin/test`-discovered tests. Unit/property tests
use a database created **inside** each trial and release it in `finally`. A
trial database ID is a deterministic encoding of suite seed, property name,
trial index, and generated namespace; no `random-uuid` occurs in a property
body. Every schema key, namespace, and symbol collection is explicitly sorted
before transaction data or installable forms are compared.

### 8.1 Worked round trip and refusals

The worked test precommits a real namespace row and admitted schema rows,
publishes a contracted function with the successful terminal, takes that
report's `:db-after`, creates a fresh agent `ctx`, asserts the resolved value is
a `sci.lang.Var` with the expected `sci/var->symbol`, evaluates the call through
the armed evaluator, and asserts the `seon.sci.admit/admit` result. A second
agent `ctx` repeats the call without author filtering.

Table-driven falsifiers:

| Input | Refusal/assertion |
|---|---|
| missing namespace row | definition refuses; no namespace stub or function row |
| missing, non-function, unresolved, or banned-`:any` contract | one-gate refusal; no function row |
| dishonest `[:fn]` schema without generator | `schema.edn/admit` refusal; projection/facts unchanged |
| duplicate desired function identity | duplicate refusal; no partial facts |
| target entity with conflicting identity attribute | collision refusal; population unchanged |
| two forms, `def`, `do`, qualified name, computed metadata, unreadable source | grammar refusal; no callable facts |
| optional doc/privacy removed on redefine | explicit retract; no stale value |
| target namespace already present in process base | materialization refusal; base remains unchanged |
| resolved value is not `sci.lang.Var` or symbol differs | core-fault result; no host deref/invocation fallback |

### 8.2 Generated definition round trip

Run at least 100 trials with seed `20260727`. Generate the complete accepted
metadata grammar from decision 3, safe namespace/function symbols, concrete
registered map or positional contracts, pure structural bodies (`+`, `-`,
`*`, comparison, `if`, and collection construction), arguments, and a pure
Clojure oracle. Each trial independently asserts:

- analyzed identity and projection-derived direct schema keys match the model;
- exactly one preexisting namespace identity and one function identity exist;
- stored source/contract equal the canonical accepted values;
- installable forms are deterministically sorted;
- resolution yields `sci.lang.Var` and the expected `sci/var->symbol`;
- armed evaluator invocation followed by `admit` equals the oracle; and
- the process base does not resolve the newly created var.

Failure output includes seed, size, deterministic database ID, source, schema
forms, transaction report, projection input, acquired rows, and shrunk check.

### 8.3 Reopen property

Seed `20260728` publishes and redefines a generated function, discards all
contexts, releases (but does not delete) the per-trial database, reconnects,
rebuilds `projection-from-rows`, initializes a fresh process base, materializes,
and calls. It asserts latest behavior, prior source in Datahike history, and
zero eval-row reads.

This is an in-process resource-reopen property. It deliberately does **not**
claim to prove process loss.

### 8.4 Reset-boundary and real process-loss interaction test

The sealed suite includes a recurring child-JVM interaction test, not a manual
transcript:

1. derive an isolated cluster/database path under repository `tmp/` from fixed
   seed `20260729`;
2. launch a child JVM through the maintained test/operator entry point and wait
   for its explicit readiness event;
3. reset/populate the ancestor, then assert attribute → process → canonical
   row ordering and core transaction provenance;
4. precommit namespace/schema forms, publish a function, and call it;
5. send `SIGKILL` to that **child JVM**, wait on its process-exit completion,
   and assert the parent test JVM remains alive;
6. launch a new child JVM against the same durable database;
7. wait for readiness, assert dangling work is marked interrupted, rebuild the
   projection and SCI base from facts, and call the function; and
8. assert no eval-history replay and clean up the isolated child/database.

There are no sleeps or polling deadlines. Process readiness and exit are
events; a time limit is only a loud test-harness backstop whose firing fails
the test as a bug. This one test is the recurring reset/ancestor/process-loss
falsifier required for graduation. A live default-cluster transcript may be
recorded as extra evidence, but cannot substitute for it.

## 11. Owner decisions required before seal

### Decision 1 — fresh owner and ruled names

**Option A (recommended):** keep top-level `seon.fn` / `seon.ns` /
`seon.schema` / `seon.test`; extend `seon.schema` only for its existing
projection, and put fact analysis/query/installable-form derivation in one
small `seon.program` owner. Reconcile the stale pending rename in architecture.

**Option B:** move the complete program-row/projection surface under
`seon.schema`. This reduces namespaces but mixes schema compilation with source
and namespace materialization. **Option C:** perform the pending `seon.code.*`
rename first; this aligns the present architecture prose but expands N5 into a
cross-tree rename.

### Decision 2 — namespace declaration and missing-row policy

**Option A (recommended):** an explicit namespace-declaration form owns source
and require edges; a function refuses unless its namespace row already exists
and never rewrites it. This makes every input honest and prevents fabricated
stubs. **Option B:** definition publication creates a minimal missing row; this
is convenient but recreates two namespace producers and loses real require
data. **Option C:** accept namespace plus function as a closed batch; this is
atomic but adds a second batching grammar above N3.

### Decision 3 — literal metadata grammar and schema-row time

**Option A (recommended):** accept `:malli/schema` only in the literal attr map
immediately following the function symbol; reject symbol metadata for N5.
Generate that one position exhaustively. Preserve existing
`:seon.schema/created-at` for agent rows until a separate migration removes it.
This is narrow and compatible but less idiomatic than merged Clojure metadata.

**Option B:** implement Clojure's full symbol-metadata plus attr-map merge
semantics and generate every position; this is familiar but enlarges the
parser oracle. Independently removing `:seon.schema/created-at` now would
eliminate stored time but makes N5 own a migration unrelated to callability.

### Decision 4 — `ctx` base collision and private visibility

**Option A (recommended):** process bases contain no agent program namespaces;
materialization refuses if one is already present. `defn-` remains callable
only from forms evaluated in its own namespace, matching Clojure visibility.
This stays within SCI's actual new-var isolation guarantee. **Option B:** allow
linked existing namespaces and overwrite roots; this may mutate shared state
because `fork` is only a copied env atom. **Option C:** make private functions
cross-agent callable by qualified symbol; this improves reach but breaks the
meaning of `defn-`.

### Decision 5 — armed evaluator owner and callable proof

**Option A (recommended):** N3's fresh run-loop evaluator owns installation and
invocation; if it adopts the name `seon.sci.eval`, replace the old namespace in
place. The proof is `sci.lang.Var` + `sci/var->symbol` + evaluation of the next
agent form + `seon.sci.admit/admit`. **Option B:** land a separate
`seon.program.runtime`; this isolates N5 but creates a second SCI invocation
door. **Option C:** revive old `seon.sci.eval` unchanged; this is fastest but
ports retained-context and old receipt behavior.

### Decision 6 — deterministic identities, fingerprint, and refusal keys

**Option A (recommended):** SHA-256 of UTF-8 exact accepted source;
fully namespaced `:seon.program/*` request/refusal keys; deterministic test
database IDs derived from seed/property/trial/generated namespace; sort every
identity collection. This is portable and reproducible. **Option B:** hash a
canonical reprint; semantically equivalent formatting collides, but exact
authored source can no longer be verified. **Option C:** random database IDs;
easy isolation, but violates replayable property evidence.

### Decision 7 — cross-agent redefinition

**Option A (recommended):** identity upsert is unconditional after admission;
the asserting transaction records authorship/history, and no process/user
fields appear in the request. This keeps the graph cluster-shared. **Option B:**
require an explicit replace flag when the asserting user differs; this catches
accidents but introduces an ownership/lock policy. **Option C:** refuse all
cross-agent replacement; safest locally, but contradicts shared collaborative
program facts.

## 12. Graduation evidence

N5 graduates only when:

- every agent-authored durable defn has a complete admitted contract and an
  existing namespace connection;
- direct function dependencies exist only in the database-derived projection;
- the successful terminal and complete function delta share one transaction;
- form 2 and another agent call form 1 from the preceding `:db-after`;
- resolved values are proven `sci.lang.Var` values and behavioral calls run
  through the armed evaluator and `seon.sci.admit/admit`;
- fixed-seed generated/reopen properties use deterministic per-trial databases;
- the recurring reset-boundary test kills and replaces a real child JVM, then
  calls from facts without eval-history replay;
- ancestor rows retain history-derived core provenance and established
  transaction ordering; and
- the explicit quarry deletion inventory is gone or has the exact
  owner-approved adoption disposition.

# N5 — corpus round trip: implementation plan

N5 closes one contract:

```text
agent-authored defn
  → admitted :seon.fn / :seon.ns / :seon.schema facts
  → committed transaction report
  → acquisition from :db-after at one basis
  → SCI var in a fresh ctx
  → callable through the one guarded evaluation edge

```

This is an authoring plan, not a source contract. The orchestrator authors the
sealed schemas, function contracts, crash walk, and tests from it; an
implementation lane then makes those tests green without weakening them.

The smallest N5 is deliberately narrower than the old corpus machinery. It
accepts one literal `defn` or `defn-`, makes its contract and namespace
connections durable in the same transaction as the successful eval receipt,
and materializes that namespace from the transaction report's `:db-after` for
the next form. It does not retain an interpreter session, replay eval history,
or build another source graph.

## 2. Quarry verdict

### 2.1 What worked

The old tee got several important invariants right:

- It made the successful eval receipt and every accepted program row one
  transaction. The comment states the eval's transaction is the transaction
  that wrote the program fact
  (`fbc6b28b5^:src/seon/eval.cljs:1828-1845`), and `record-eval!` puts receipt
  terminalization and accepted tee rows in one `d/transact`
  (`:2866-2878,2967-2983`).
- It used the established identities—`:seon.fn/sym`, `:seon.ns/name`, and
  `:seon.schema/key`—so redefinition was an upsert and temporal history
  retained prior values (`:1838-1845`).
- It adopted a strict persistence boundary: exactly one literal `defn` or
  `defn-`; a bare `def`, `do` wrapper, or multi-form source remained scratch
  (`:1926-1969`). That restriction is what makes namespace materialization
  safe: installing a definition does not rerun an arbitrary effectful form.
- It learned that refs to not-yet-present namespace rows must be created in the
  same transaction. The previous lookup-ref form could fail the whole eval
  transaction; nested-map upsert fixed both function and schema namespace
  connections (`:2288-2294,2371-2415`).
- It learned that omitted cardinality-one attributes do not retract prior
  values. Removing a function contract required explicit retraction
  (`:2450-2470`).
- Its later authority pass built the complete candidate schema/function
  projection before commit and converted a bad candidate into a user-input
  refusal (`:3465-3555`). N5 keeps that admission-before-commit ordering.

The old database reconciler also contains a useful pure shape: acquire one
immutable database value, compute exact changed rows and retractions, then
transact only that data (`src-old/seon/db/program.clj:119-194,215-317`).
N5 keeps the pure-plan boundary, but not the complete-population reconciler
around every agent form.

### 2.2 What was brittle

The old system needed repairs because it had several producers and several
ways to infer the same graph:

- The pod compile-time producer walked the ClojureScript analyzer's transitive
  require closure (`src-old/seon/client/indexing.clj:27-63`), then runtime
  indexing read vars, source files, and line metadata
  (`src-old/seon/client.cljs:1024-1102`).
- A second downstream producer scanned source text for `defn` forms with its
  own string/comment/parenthesis walk (`src-old/seon/client.cljs:1197-1254`)
  and deduplicated those rows against var-derived rows
  (`:1271-1287,1355-1363`).
- Namespace rows sometimes stored real source and sometimes a fabricated
  `(ns x)` stub according to a presentation rule
  (`src-old/seon/client.cljs:892-939`). Program truth and prompt-density policy
  were therefore coupled.
- The eval tee detected definitions by diffing compiler state, then added a
  special body-only-redefinition rescue because analyzer metadata could remain
  unchanged (`fbc6b28b5^:src/seon/eval.cljs:2295-2309`). It separately parsed
  the source head to distinguish `defn` from `deftest` because analyzer test
  metadata was ambiguous (`:2310-2335`).
- Direct call/read/write edges were built by a separate custom form walker
  (`src-old/seon/program/edge.cljc:91-465,480-516`) and then stored with
  replace-all transaction data (`:527-585`). That was a second program graph
  builder beside the compiler/analyzer state.
- Invalid function schemas could become a durable row with
  `:seon.fn/schema-error` and no contract
  (`fbc6b28b5^:src/seon/eval.cljs:2339-2389`). N5's settled rule is stronger:
  a durable defn without a valid complete `:malli/schema` is unrepresentable.
- Resume required acquisition caches, projection publication state, and
  retry/recompile choreography (`fbc6b28b5^:src/seon/eval.cljs:3387-3649`).
  Those mechanisms existed because process state and database truth could
  diverge.

These are scars to design away, not code to port. The target says the core
source, eval log, and analyzer state are views of one program graph
(`docs/seon/architecture/architecture.md:499-510`), and a function written by
one agent is resolved by another from committed facts rather than by replaying
the author's eval (`docs/seon/architecture/context.md:287-298`).

## 3. Proposed owning surface

N5 needs one new program owner and one extension of the already-surviving SCI
owner:

| Owner | Pure or effectful | Responsibility |
|---|---|---|
| `seon.program` | pure except for Datahike queries over an explicit database value | analyze one definition, compile the exact publication transaction, acquire one namespace at a basis, and turn acquired facts into SCI-installable source |
| `seon.sci.eval` | the one effectful edge | create/fork the guarded SCI `ctx`, install the acquired namespace, resolve the SCI var, and evaluate the next form |
| `src/seon/schema/program.edn` | data | any N5-owned schema declarations, especially the function-to-schema ref connection |
| `test/seon/program_test.clj` | proof | examples plus the sealed properties in §9 |

Do not add a program registry, context cache, replay namespace, or corpus
session. A database value and an SCI `ctx` are the only inputs whose names come
from the dependencies themselves.

The proposed public pure functions use one namespaced map in/out:

```clojure
(analyze-defn
 {:seon.program/source source
  :seon.program/current-ns current-ns
  :seon.program/schema-forms schema-forms})
→ {:seon.program/function-row ...
   :seon.program/namespace-row ...
   :seon.program/schema-rows [...]
   :seon.program/function-contract ...
   :seon.program/schema-keys #{...}}

(publish-call
 db
 {:seon.program/analysis analysis
  :seon.program/process process-ref
  :seon.program/user user-ref})
→ exact transaction data or a classified refusal

(acquire-namespace
 db
 {:seon.program/namespace namespace-symbol})
→ ordinary namespace, function, and directly referenced schema facts

(installable-source acquired)
→ one deterministic source string

```

`publish-call` is the function passed to `[:db.fn/call #'publish-call
request]`. It is pure over the mid-transaction database value and returns
transaction data. The outer N3 boundary catches Datahike refusal and returns a
flat error value.

## 4. Data model

### 4.1 A stored function is attributes plus connections

A durable definition entity is found by the presence of `:seon.fn/sym`; it has
no `:type` or `:kind`.

Required attributes and connections:

| Attribute | Shape | Meaning |
|---|---|---|
| `:seon.fn/sym` | existing identity string (`src/seon/schema.cljc:438`) | fully qualified symbol, derived from current namespace plus the defn's unqualified name |
| `:seon.fn/ns` | existing ref (`:439`) | connection to the owning `:seon.ns/name` entity |
| `:seon.fn/source` | existing string (`:440`) | exact accepted single definition source |
| `:seon.fn/source-fingerprint` | existing string (`:441`) | deterministic content fingerprint of the exact source |
| `:seon.fn/spec` | existing string (`:446`), **required by N5** | canonical EDN string of the complete `:malli/schema` function contract |
| `:seon.fn/schema-refs` | **new**, `[:set :seon.db/ref]` | direct connections to global `:seon.schema/key` rows referenced by the contract |

Optional derived metadata may use the already registered `:seon.fn/arglists`,
`:seon.fn/doc`, `:seon.fn/private?`, and `:seon.fn/read-attrs`
(`src/seon/schema.cljc:443-452`) only when the pure source analysis produces
them. The minimal round trip does not need `:seon.fn/read-attrs`.

N5 deliberately writes none of these:

- `:seon.fn/fn-var?`: a row admitted only from `defn`/`defn-` already implies
  that fact.
- `:seon.fn/schema-error`: invalid or absent contracts are refused before
  commit, not stored as half-valid functions.
- `:seon.fn/created-at`: time and authorship are derived from the asserting
  transaction's `:db/txInstant`, `:seon.db/user`, and `:seon.db/process`.
- an execution tier, installed flag, generation counter, callable flag, or
  owner agent: callability is derived from accepted facts; the program graph
  is cluster-shared.

The existing `:seon.fn` entity map makes `spec` optional
(`src/seon/schema.cljc:467-483`) because it also describes historical/core
rows. The N5 **publication request** is the stricter boundary: a durable
agent-authored function cannot be built without `:seon.fn/spec`. Do not loosen
the settled canonical row shape merely to express this producer-specific
requirement.

### 4.2 Namespace identity

The namespace entity is anchored by the existing
`:seon.ns/name` symbol identity (`src/seon/schema.cljc:457`) and carries
`:seon.ns/source` (`:458`). For N5, that source is a real canonical namespace
declaration, never a presentation stub. `:seon.fn/ns` points to it.

Namespace require edges remain the dependency's load-order data. N5 does not
infer them with another graph walker. When the accepted namespace declaration
contains `:require`, its parsed declaration is the one source for both
`:seon.ns/source` and the existing `:seon.ns/require-edges` connection
(`src/seon/schema.cljc:461-462`). N5's minimal generated property can use a
namespace with no external requires.

### 4.3 Schema facts are global

A schema is found by `:seon.schema/key`, the existing keyword identity
(`src/seon/schema.cljc:427`). Its canonical form is stored as the full EDN
string in `:seon.schema/form` (`:429`; producer at
`src/seon/schema.cljc:1772-1792`). Its optional `:seon.schema/ns` ref is an
editorial/code-ownership connection, not containment.

Schemas are never embedded in function or namespace entities. The function
stores only direct refs to global schema rows. Reverse lookup is a Datalog
query over `:seon.fn/schema-refs`; transitive schema dependency remains a
derived walk using `schema/direct-references` and the active projection
(`src/seon/schema.cljc:180-225`). Storing the transitive closure would create
derived state that must be repaired after every schema redefinition.

### 4.4 Contract admission and schema registration

Every durable defn must carry metadata whose `:malli/schema` is:

- readable and round-tripping EDN;
- a complete function schema;
- free of `:any`, `:some`, `:nil`, and `[:maybe X]` on Seon-authored data;
- resolvable against the complete candidate schema population; and
- connected to every non-built-in schema key it directly references.

Agent `schema/register!` forms are not a second schema path:

1. `schema/begin-registration-delta` creates an isolated candidate population
   (`src/seon/schema.cljc:1651-1657`).
2. The form runs with `schema/call-with-registration-delta`, which marks the
   admission source `:agent` (`:1659-1670`).
3. `schema.edn/admit` validates the complete candidate through the same gate as
   loaded EDN (`src/seon/schema/edn.clj:250-294`).
4. The terminal transaction commits the changed canonical
   `:seon.schema` rows together with the eval receipt.
5. Only after that commit does `schema/activate-projection!` publish the exact
   admitted projection in process (`src/seon/schema.cljc:1585-1599`).

If any step before the transaction refuses, neither candidate process state
nor schema facts change. If the transaction refuses, the isolated delta is
discarded. This closes the old partial-publication class without a compensating
rollback.

## 5. Pure round-trip contracts

### 5.1 Source string → analyzed facts

`analyze-defn` is pure. It:

1. parses with SCI's parser;
2. requires exactly one top-level `defn` or `defn-`;
3. requires an unqualified symbol name and derives the qualified symbol from
   `current-ns`;
4. reads doc, arglists, privacy, and the literal `:malli/schema` from the same
   parsed form;
5. admits the contract against the complete schema candidate;
6. derives the direct referenced schema keys from that admitted contract; and
7. returns ordinary function/namespace/schema row maps.

It does not eval, query a connection, read a file, inspect a host Var, diff an
analyzer atom, or mutate the schema registry.

`defn` metadata must itself be ordinary EDN. This prevents install-time
metadata expressions from becoming a hidden effect when durable definitions
are materialized later.

### 5.2 Analyzed facts → exact transaction data

`publish-call` runs inside Datahike's transaction through `:db.fn/call`. It:

- refuses duplicate identities within the desired rows, following
  `seon.reconcile/plan`'s `::duplicate-identity` precedent
  (`src/seon/reconcile.cljc:304-312`);
- refuses an existing entity that carries more than one program identity
  attribute among `:seon.fn/sym`, `:seon.ns/name`, and `:seon.schema/key`;
- permits a later transaction to redefine the same `:seon.fn/sym` or
  `:seon.schema/key` when the complete candidate population still admits;
- explicitly retracts optional prior attributes omitted by an accepted
  redefinition; and
- returns only ordinary transaction data.

Function publication and the terminal eval receipt enter one `d/transact`.
There is no window where the transcript says the definition succeeded but the
program graph lacks it.

### 5.3 Facts → SCI-installable source

`acquire-namespace` is a pure query over the exact database value passed by the
run-loop reduce. It obtains:

- the one `:seon.ns/name` row and its require connections;
- all `:seon.fn` rows whose `:seon.fn/ns` ref points to it;
- the directly referenced `:seon.schema` rows; and
- enough asserting-transaction provenance to apply admission policy without
  storing provenance projections on domain entities.

`installable-source` then produces deterministic source:

1. the real namespace declaration;
2. one `(declare ...)` containing the acquired function names in sorted symbol
   order; and
3. each exact accepted `:seon.fn/source` in sorted `:seon.fn/sym` order.

The declaration makes same-namespace forward references independent of row
iteration order. Cross-namespace order follows the stored namespace require
edges and SCI's `:load-fn`; N5 does not invent a call graph merely to order
definitions.

This is the same SCI parser in the producer and consumer. Parsing the stored
source during installation is necessary to evaluate it, but it does not create
a second graph: all identities, refs, contracts, and load order come from
facts.

### 5.4 Install into a `ctx`: the one effectful edge

`seon.sci.eval`:

1. starts the one time-limit `:interrupt-fn`;
2. forks the process base with `sci/fork`;
3. installs the acquired namespace source in that fork;
4. resolves the requested symbol with `sci/resolve`;
5. proves the result is an SCI var whose root is callable; and
6. evaluates the next agent form in the same guarded fork.

No function body is invoked during installation. Calls happen only while the
guard is armed. `:load-fn` handles a missing required namespace, but does not
solve a bare symbol in the already-present current namespace; explicit
materialization from the previous transaction's `:db-after` does
(`research/capability-ledger-2026-07-26.md:194-215`).

## 6. Basis and visibility contract

N3 reduces forms over transaction reports. N5 strengthens that reduce:

```text
form N starts from db-N
  → guarded eval
  → terminal transaction commits receipt + accepted program delta
  → report-N contains db-after
  → form N+1 acquires current namespace from report-N.db-after
  → fresh guarded SCI fork installs those facts
  → form N+1 resolves the new bare symbol

```

The basis is explicit data, never an ambient connection dereference. This
provides read-your-own-writes inside one reply and makes the exact same path
work for another agent or a reopened cluster.

The program graph is cluster-shared by ruling
(`docs/seon/architecture/architecture.md:81-86`). There is no author-agent
filter on acquisition. Authorship remains queryable from the source datom's
asserting transaction.

## 7. SCI probe

The critical install-order assumption was probed against the selected SCI
checkout:

```clojure
(let [ctx  (sci/init {:interrupt-fn (fn [])})
      fork (sci/fork ctx)
      _    (sci/eval-string*
            fork
            "(ns my.n5)
             (declare b)
             (defn a {:malli/schema [:=> [:cat] :int]} [] (b))
             (defn b [] 42)")
      v    (sci/resolve fork 'my.n5/a)]
  {:callable? (ifn? @v)
   :value (@v)
   :original-sees? (some? (sci/resolve ctx 'my.n5/a))
   :symbol (sci/var->symbol v)})

```

Result on 2026-07-27:

```clojure
{:callable? true
 :value 42
 :original-sees? false
 :symbol my.n5/a}

```

The probe confirms three dependency claims: deterministic declaration-first
installation supports forward references, `sci/resolve` returns the installed
var, and `fork` isolates new vars from the process base exactly as SCI documents
at `reference-code/sci/src/sci/core.cljc:318-323`.

## 8. Crash walk

| Kill point | Durable state left | Recovery |
|---|---|---|
| before source analysis | no receipt or program facts | the run still owns the unexecuted ordinal; N3 follows its existing run contract |
| after pure analysis or staged schema delta, before eval | no program facts; only invocation-local values | discard them; nothing needs rollback |
| after the definition installed in the current eval fork, before terminal transaction | running receipt only; no program facts | boot marks the dangling receipt `:interrupted`; nothing republishes or re-executes that ordinal |
| while the terminal transaction is applying | all-or-nothing by Datahike | either the running receipt remains, or receipt plus complete program delta are committed |
| after commit, before process projection activation | complete program facts and terminal receipt | reopen/acquire from the committed database value and rebuild the disposable schema projection and SCI namespace |
| after projection activation, before next form | same complete facts | next form ignores retained process state and re-derives from the previous report's `:db-after` |
| while installing facts into a fresh SCI fork | complete facts; fork is disposable | discard fork and materialize again; installation evaluates only admitted definition forms, never an effectful eval form |
| while invoking the callable | N3's running receipt identifies this ordinal | process recovery marks it `:interrupted`; no form or effect is refired |

This is consistent with the settled crash model: recovery reopens facts and
marks dangling receipts interrupted; it never re-executes an agent form
(`plan/README.md:295-308`). Namespace materialization is not eval-history
replay. It reconstructs callable definitions whose strict admission grammar
contains no top-level effect.

## 9. Sealed suite sketch

All tests live in `test/seon/program_test.clj` and run through `bin/test`.
Every database trial creates its own `:memory` configuration and connection,
installs only the declared N5 attributes, and releases/deletes it in `finally`
as in `test/seon/cluster/run_test.clj:29-65`.

### 9.1 Worked round trip

One example proves the actual rung:

1. install the schema population;
2. evaluate a valid specced `defn` in form 1;
3. commit its receipt, namespace, function, and referenced schema rows;
4. take that transaction report's `:db-after`;
5. create a fresh SCI fork, materialize the namespace from those facts;
6. evaluate a bare call in form 2; and
7. assert the returned value plus the exact durable rows.

The test must also create a second fresh SCI fork representing another agent,
acquire the same basis without author filtering, and call the same function.

### 9.2 Generated definition round trip

Use `tc/quick-check` with fixed seed `20260727`, at least 100 trials, and a
fresh database **inside** `prop/for-all`. Generate:

- safe namespace and function symbols;
- map-in/map-out or named positional contracts using registered concrete
  schemas;
- total pure bodies from a small structural expression grammar
  (`+`, `-`, `*`, comparisons, `if`, collection construction); and
- arguments plus a pure Clojure oracle result.

For each trial, assert independently:

- analyzed identities and direct schema refs equal the model;
- exactly one namespace and one function identity exist after commit;
- stored source and contract are byte-equal to the accepted values;
- a fresh fork from acquired facts resolves a callable SCI var;
- invocation equals the pure oracle; and
- the parent base `ctx` does not see the trial var.

On failure, print seed, size, source, schema forms, transaction result,
acquired rows, and the complete shrunk check.

### 9.3 Refusal classes

One table-driven test per failure class:

| Falsifier | Expected result | Durable assertion |
|---|---|---|
| missing `:malli/schema` | `:user-input` refusal | no `:seon.fn/sym` row; receipt is error, not success |
| contract contains banned `:any` or unresolved key | admission refusal from the one gate | no schema or function delta |
| dishonest `[:fn]` registration without generator | `schema.edn/admit` refusal | candidate projection and facts unchanged |
| two desired function rows with one `:seon.fn/sym` | duplicate-identity refusal | neither row commits |
| target entity already carries a conflicting program identity attribute | collision refusal | entity and program populations unchanged |
| source has two top-level forms, `def`, `do`, qualified name, or unreadable syntax | strict-definition refusal | no callable/program facts |
| redefinition removes an optional doc/private/ref connection | accepted update with explicit retract | old value is absent, not stale |

Expected refusals assert the deepest classifiable ex-data and independently
assert that the database value did not change. They never match exception
messages.

### 9.4 Re-derive after reopen

A fixed-seed state-transition property performs:

1. publish a generated definition;
2. discard every SCI `ctx`;
3. release the connection without deleting the database;
4. reconnect to the same per-trial database;
5. acquire at the reopened database value;
6. initialize a new process base and materialize the namespace; and
7. invoke the function.

The oracle is the generated pure body result. The test must not read or replay
eval rows to rebuild code. It should additionally prove a redefinition before
reopen yields only the latest callable behavior while Datahike history still
contains the prior source datom.

Use a second fixed seed, `20260728`, so the reopen surface is independently
replayable.

## 12. Open questions for the orchestrator

### Q1 — direct or transitive function-to-schema refs?

**Option A — direct refs only (recommended).** Store only schema keys appearing
directly in the function contract. Derive transitive schema dependencies with
the active projection.

- Advantage: no derived closure to repair; one source of truth.
- Cost: relevance queries needing transitive shapes perform a bounded graph
  walk.

**Option B — store the transitive closure.** Each function connects to every
reachable schema.

- Advantage: one Datalog join answers broad relevance.
- Cost: every schema change must rewrite dependent function rows; this is
  derived state and recreates reconciliation machinery.

### Q2 — how much top-level syntax is durable in N5?

**Option A — one literal `defn`/`defn-` or one `schema/register!` per form
(recommended).** N3 already commits per form, so schema registrations and
definitions compose across consecutive transaction reports.

- Advantage: the crash boundary and identity are unambiguous; materialization
  cannot refire arbitrary effects.
- Cost: an agent cannot publish a schema and function in one textual form.

**Option B — admit a closed multi-form publication batch.** The batch grammar
allows only registrations followed by definitions and commits them together.

- Advantage: schema plus function can be atomic as an authoring unit.
- Cost: introduces a second batching grammar atop N3's per-form receipts and
  complicates shrink/recovery behavior.

### Q3 — deterministic declarations or stored call edges for install order?

**Option A — `(declare ...)` plus sorted definition source (recommended for
N5).** Namespace require edges order namespaces; declarations make
same-namespace forward references independent of row order.

- Advantage: proves the round trip without adopting the old custom edge
  analyzer.
- Cost: it does not yet supply the call graph needed by later affected-test
  selection.

**Option B — store direct call edges now and topologically order definitions.**

- Advantage: begins N6's function-level test-selection graph.
- Cost: expands N5 into analyzer design and risks porting
  `src-old/seon/program/edge.cljc` before its replacement contract is settled.

### Q4 — cross-agent redefinition policy

Should a redefinition by a different agent require an explicit publication
option?

**Option A — identity upsert is the operation (recommended).** Any admitted
later transaction may redefine a shared function; authorship and history remain
queryable from transactions.

- Advantage: matches the owner ruling that an override is a later transaction
  on the same program facts and keeps the graph cluster-shared.
- Cost: accidental symbol reuse is destructive to current behavior, though
  temporally reversible.

**Option B — require an explicit replace flag when the asserting user differs.**

- Advantage: catches accidental cross-agent symbol collisions.
- Cost: stores or derives an ownership policy that ordinary Clojure namespaces
  do not have and may turn collaboration into a lock protocol.

The plan recommends A for all four questions because it is the smallest
construction that satisfies the settled N5 falsifier and deletes the most old
machinery.

## 13. Graduation evidence

N5 is complete only when all of these are true:

- a valid agent-authored defn cannot commit without a complete admitted
  `:malli/schema`;
- the successful eval receipt and all resulting function, namespace, and
  schema facts share one transaction;
- form 2 calls form 1 from the preceding transaction report's `:db-after` in a
  fresh SCI fork;
- another agent and a reopened process call the same function from facts;
- no eval history, retained `ctx`, analyzer atom, source-file scan, or second
  program graph participates;
- refusal and collision tests prove zero partial facts;
- both sealed properties pass at their fixed seeds with one database per
  trial; and
- a live default-cluster transcript plus datoms proves the round trip across a
  process restart.

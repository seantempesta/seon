# N3 — the run loop as a flow proc: implementation plan

This is the authoring plan for the N3 rung (plan README §3, "N3 —
`seon.cluster.loop`: the run loop as a flow proc"). It is not the contract
package: the orchestrator authors the sealed schemas, `:=>` contracts,
crash walk, and generative properties from this plan, then delegates
implementation. Everything below is grounded on read source or a probe run
today; every uncertain dependency claim was falsified in the REPL rather
than remembered.

Four probes were written and run for this plan. They are project-local and
repeatable:

```sh
clojure -M:test tmp/n3-listen-probe.clj      # A: listen semantics (wedges by design at Q4)
clojure -M:test tmp/n3-listen-probe-b.clj    # B: listener cost, refusals, :db-after
clojure -Sdeps '{:deps {org.babashka/sci {:local/root "reference-code/sci"}}}' \
  -M:test tmp/n3-parse-probe.clj             # C: SCI reader as the reply splitter
clojure -M:test tmp/n3-refusal-probe.clj     # D: the refusal cause chain

```

Their transcripts are quoted inline where they carry a decision, and
collected in §12.

## 2. What the quarry actually teaches

The old loop worked. Its scars, from the source and from
`git log --oneline -- src-old/seon/agent/driver.clj` (23 commits,
`c45616a38` "Replace phase driver with synchronous form fold" through
`4dbaeda0e` "Wake JVM driver on inbound agent messages"):

**Kept ideas.**

- The fold is right: running receipt → eval at the previous step's
  `:db-after` → terminal receipt (`driver.clj:229-327`). L5 forces form
  granularity and the old code honors it.
- A rejected result transaction is followed by a terminal *error* receipt
  carrying no agent value, so a bad value can neither wedge the run nor be
  retried forever (`driver.clj:310-327`). This is the single most
  load-bearing defensive shape in the file and N3 keeps it verbatim in
  spirit.
- Custody is CAS + epoch + lease facts, and resume is a query for the first
  ordinal without a terminal receipt (`driver.clj:149-158`). N2 already owns
  both.
- Lifecycle is **values the driver interprets**, not effects
  (`lifecycle.cljc:41-56`, consumed at `driver.clj:77-113`). That is
  already the target shape from the 2026-07-24 corollary; it survives.
- L8 is written into the code as a comment at the one place it matters:
  `driver.clj:986-988` — *"Wake attributes must not be committed by work
  this wake starts."* The wake pattern is `:seon.agent.message/to`, and the
  loop commits run/turn/eval attributes. That disjointness is the whole
  defence against the measured 7.0 → 124.8 commits/run blow-up.

**Deliberately discarded.**

- `scan!` / `scanning?` / `scan-requested?` / `in-flight-message-ids` /
  `in-flight-run-ids` (`driver.clj:915-981`) — five pieces of mutable
  process state implementing "one scan at a time, and re-scan if a wake
  arrived while scanning". A single flow proc with one input channel *is*
  that mechanism; the re-scan is one `offer!` back into the proc's own wake
  channel (§4). Roughly 70 lines of concurrency bookkeeping delete.
- `*await-lease!*` (`driver.clj:439-450`) — a virtual thread sleeping to a
  lease deadline. Under O2 (one live write connection per store, flock-
  enforced at `src/seon/cluster/store.clj`) a run is held either by *this*
  process or by a *dead* one. A dead holder is discovered at boot by N2's
  `recover-tx`, not by a timer. **N3 arms no lease clock at all.** This is
  the L7-compliant answer and it deletes the file's only sleep.
- The turn entity and `:seon.agent.turn.timing/*` rows
  (`driver.clj:620-635,877-903`) — thirteen timing datoms per turn. Ruled
  subsumed ("Turn phases: receipts subsume", README 2026-07-26 s2). N3
  writes **no turn entity**; durations live on eval receipts and on flow
  report events. This is the rung's largest data-model shed.
- `db.host/listen!` (`src-old/seon/db/host.clj:310-397`, ~90 lines) plus its
  UDS interest reader loop, reconnect backoff, and pending-request table —
  entirely a process-boundary artifact. O1 co-location deletes all of it;
  the replacement is `d/listen` (§5).
- `seon.repl.parse` (1,517 lines) — replaced by ~20 lines over SCI's own
  reader (§7, proven by probe C).
- The allocation dance: `allocate!`, `allocated-transact!`, `open-run!`,
  `open-turn!` (`driver.clj:396-418,531-576`) — writer-side id allocation
  for message/run/turn. N2 already uses caller-supplied string identities
  with `:seon.db/identity`; N3 does the same and the allocator is dead.

### 3.2 Data model — what N3 adds

N2 registered 17 attributes. **N3's target is +4, and every one must be
queried by something in the rung.**

The trigger. N3 needs one thing to wake on that the loop itself does not
commit (L8). The smallest honest trigger is an inbound message:

```
:seon.cluster.message/id      [:string {:min 1 :seon.db/identity true}]
:seon.cluster.message/to      :seon.db/ref     ; the wake attribute
:seon.cluster.message/content [:string {:min 1}]
:seon.cluster.message/at      :inst

```

The run's connection to its trigger is N2's existing `::agent` plus a new
`:seon.cluster.run/cause` ref — **but only if something queries it.** The
"already answered" query (has a run been opened for this message?) does
need it, so it earns its place; that is +5, not +4. If the orchestrator can
derive answered-ness from the agent pointer alone, drop `cause` and the
count is +4.

**Explicitly NOT added**, each with the reason:

| candidate | why not |
|---|---|
| a turn entity | receipts subsume it (README 2026-07-26 s2) |
| `:seon.agent.turn.timing/*` | derived from receipt durations and flow reports |
| a model-attempt receipt | see §9.1 — the crash model makes it unnecessary under the recommended sequencing |
| `:seon.eval/narration`, `:seon.eval/total`, `:seon.eval/ns` | the old driver wrote all three (`driver.clj:263-272`); nothing reads them. `total` is `(count forms)`, a derivation |
| a wake/dirty flag | the wake is a channel value; facts hold the work |
| `:seon.cluster.run/result` | the completion message content already carries it |

**Metric-2 observation for the rung review, not an N3 change:** under O2,
`::lease-until` is queried by nothing except `claimed?`/`expired?`, and
`expired?` can only be true for a *dead* process — which `recover-tx`
already detects from `::live-processes`. The lease may be a projection twin
of process liveness. Do not touch it in N3 (N2 is sealed and green); raise
it at the N3 review with this evidence.

## 4. The proc topology

### 4.1 One proc, and it is an ordinary `flow/process`

The flow-per-cluster research recommends a custom `flow.spi/ProcLauncher`
for the run loop
(`research/flow-per-cluster-2026-07-27.md:375-383`), while the
flow-dynamic-update research calls the existing custom `database-proc`
"the strongest simplification candidate… keep the custom SPI launcher only
if current-fact ping plus nonblocking downstream delivery cannot be
expressed through `flow/process`"
(`research/flow-dynamic-update-2026-07-27.md:336-345`).

**Verdict: ordinary `flow/process`.** The same flow-per-cluster document
supplies the resolution three paragraphs earlier: `::flow/in-ports` are
real channel objects returned in initial state which Flow adds to the
proc's own read set — "the source-supported seam for a run-loop proc to
select a database-interest wake channel"
(`flow-per-cluster-2026-07-27.md:236-244`;
`reference-code/core.async/src/main/clojure/clojure/core/async/flow.clj:219-232`;
`flow/impl.clj:263-269`). Taking it buys Flow's own control priority,
addressed pause/resume/ping, error reporting, and the
continue-with-pre-step-state rule (`flow/impl.clj:281-320`) instead of
reimplementing ~90 lines of them, which is exactly what
`src/seon/flow.clj:948-1036` does today.

The in-house precedent is already green: `fault-committer-proc`
(`src/seon/flow.clj:583-619`) is an ordinary `flow/process` whose entire
input is an externally created channel handed over through
`::flow/in-ports`. N3's run loop is the same shape.

Consequence: **`seon.flow/database-proc` and its `addressed?`/`ping-map`/
`next-status` helpers (`src/seon/flow.clj:948-1036`) become dead** once N3
lands. Delete them in the same commit; the testbed suite that pins them
dies with them (the smaller-suite ruling).

### 4.2 The four step-fn arities

Constructed with a **Var** — `(flow/process #'run-loop-step {:workload :io})`
— so a transform-body edit hot-reloads with no graph rebuild
(`flow.clj:165-181`, proven at
`research/flow-dynamic-update-2026-07-27.md:163-192`). Note the limit
recorded there: an anonymous `flow/map->step` result does *not* reload.
Every other N3 launcher inherits the same rule.

```clojure
;; () -> description
{:workload :io                    ; the loop blocks on the model call
 :ins    {}                       ; the wake is an in-port, not a graph port
 :outs   {::turn-report "One completed turn, for observation only."}
 :ping-map-fn (fn [state] (select-keys state [::turns ::last-run-id ::busy?]))}

;; (args) -> initial state
;; args are captured in pdescs at create-flow; the cluster handle rides here.
{::flow/in-ports {::wake wake-channel}
 ::cluster       cluster-handle     ; connection, config facts, process id
 ::turns 0}

;; (state transition) -> state
;; ::flow/stop unlistens and delivers the proc-owned stopped event —
;; flow/stop is a command, not a join (flow/impl.clj:174-183).

;; (state input-id message) -> [state' output-map]
;; input-id is ::wake; message is an opaque wake value carrying nothing.

```

`:workload :io` is correct and load-bearing: `:compute` procs submit each
transform to `:compute` and wait (`flow.clj:272-286`), which would occupy a
bounded platform thread for the duration of a model call. The loop is `:io`
(may block, must not compute); the *eval* is the compute half and reaches
`:compute` through the existing work launcher (§4.4).

### 4.3 The transform: one wake, one pass, self-rewake

```
transform(state, ::wake, _msg):
  1. db := (d/db conn)                          ; one pinned value for the pass
  2. work := (next-work db process-id)          ; pure derivation, see below
  3. if work is nil -> [state nil]
  4. run one turn (§9) — synchronous, errors are values
  5. if (more-work? (d/db conn) process-id) -> (async/offer! wake-ch ::wake)
  6. [(update state ::turns inc) {::turn-report [report]}]

```

Step 5 replaces the old `scan-requested?` / `compareAndSet` dance
(`driver.clj:962-981`) with one `offer!` into the proc's own in-port. It
cannot recurse unboundedly: `offer!` on a `(sliding-buffer 1)` channel
coalesces, and the pass is only re-entered after the transform returns.

`next-work` is a pure function of a database value returning one of three
values, and it is the resume/derivation core of the rung:

| derived situation | action |
|---|---|
| an open run held by this process **with** a plan digest | resume the fold at the first ordinal lacking a terminal receipt |
| an open run held by this process **without** a plan digest | derive prompt, call the model, freeze the plan, fold (§9.1) |
| an unanswered trigger and the agent has no open run | open + claim, then as above |
| nothing | idle |

### 4.4 Where the guarded eval runs

The run-loop proc calls `seon.flow/submit!!` (`src/seon/flow.clj:517-551`)
once per form. That parks on the launcher's fixed-buffer channel
(backpressure) and runs the work on the bounded platform `:compute`
executor (parallelism) — the two jobs the deleted `Semaphore` used to
conflate (`unsettled.md:159-176`).

**One deadline discipline, not two.** `submit!!` derefs with
`::time-limit-ms` while `seon.sci.interrupt` arms the real limit. These are
not duplicates if they are named correctly: the `:interrupt-fn` is *the*
limit, and `submit!!`'s deref is a **backstop for a blocked host call**,
which is the one genuinely unobservable case (a thread inside a host call
never enters an interpreted fn body, so the interrupt-fn is never called —
L2/`:seon.eval/fn-entries` 12 reads as *blocked in a host call*). The
contract must therefore state: the submission backstop is strictly greater
than the interrupt time limit, and **its firing is a bug report**, surfaced
through the existing `::wedged?` accounting (`src/seon/flow.clj:539-546`),
never the primary failure path.

### 4.5 Concurrency, stated honestly

One run-loop proc per cluster means **turns are serial within a cluster**.
The model is 78.5% of a measured turn (L16), so N agents cost N × turn.
This is deliberate for N3: the falsifier is one real agent turn, and the
smallest block that composes wins.

The extension point is named now so it is not invented later: the pass
submits each turn to a bounded `:io` class on the *same* work launcher
rather than running it inline, with the concurrency a B2 config fact. Do
not build it in N3; do measure the ceiling at the N3 review so the
multi-agent decision is made against a number.

## 5. The wake design

### 5.1 The mechanism

`datahike.api/listen` → `datahike.core/listen!`
(`api/specification.cljc:1068-1082`), one listener key per cluster,
registered against the cluster's one connection at proc init and removed on
`::flow/stop`.

Probe A settled the four things the fresh system needed to know:

```text
:Q1-LISTENERS-META-PRESENT-ON-CONNECTED-CONN? true
:Q2-CALLER-THREAD main
:Q2-CALLBACK-THREADS [async-mixed-6 async-mixed-3]
:Q2-CALLBACK-VIRTUAL? [false false]
:Q3-REPORT-KEYS [:db-after :db-before :tempids :tx-data :tx-meta]
:Q3-ATTRS [#{:probe/id :db/txInstant :probe/n} #{:probe/note :probe/id :db/txInstant}]

```

`d/connect` (not just `conn-from-db`) yields a connection whose meta
carries the listeners atom — `Connection` delegates `IMeta` to its wrapped
atom (`reference-code/datahike/src/datahike/connector.cljc:44-45,102`). The
callback receives a full tx-report and runs on a core.async `:mixed`
platform thread, not the caller's.

### 5.2 The two hazards, both measured

**Hazard 1 — a throwing handler hangs the committing caller forever.**
`writer.cljc:362-386` fires listeners *inside* the transaction's go block
and *before* `(deliver p tx-report)`. Probe A's Q4 reproduced it: the
listener's exception escaped onto `async-mixed-6`, the deliver never
happened, and the probe JVM had to be killed.

```text
Exception in thread "async-mixed-6" clojure.lang.ExceptionInfo: listener blew up {}
	at datahike.writer$transact_BANG_$fn__58663$state_machine__7134__auto____58672$fn__58674.invoke(writer.cljc:385)

```

**Hazard 2 — a slow handler is on the committing caller's critical path.**
Probe B, an 800 ms listener:

```text
:Q6-TRIGGERING-TRANSACT-RETURNED-AFTER-MS 804
:Q6-SLOW-LISTENER-RAN-BEFORE-RETURN? true

```

Therefore the handler contract is absolute and belongs in the sealed
contract as a refusal case, not a comment:

```clojure
(fn [report]
  (try
    (when (wake? wake-attributes report)
      (async/offer! wake-channel ::wake))     ; offer!, never >!! and never park
    (catch Throwable t
      (async/offer! fault-channel (core-fault t)))))   ; offer! here too

```

Nothing else. No query, no derivation, no commit inside the handler. This
also settles the API doc's deadlock warning
(`api/specification.cljc:1076-1078`): N3 never transacts from a callback at
all, synchronously or otherwise.

### 5.3 The wake predicate, and its three traps

```clojure
(defn wake?
  [wake-attributes report]
  (boolean (some #(contains? wake-attributes (nth % 1)) (:tx-data report))))

```

- **`:db/txInstant` is in every tx-data** (probe A Q3). A predicate that
  looks for "any datom" wakes on every commit including its own. The
  attribute set is explicit and small.
- **L8 disjointness is a property, not a convention.** The wake set is
  `#{:seon.cluster.message/to}`. The loop commits `:seon.cluster.run/*`,
  `:seon.cluster.run.form/*`, `:seon.cluster.eval/*`,
  `:seon.cluster.agent/run`. A generative property must assert the two sets
  are disjoint — computed from the loop's own committed attributes, never a
  reviewed list (L17).
- **An unchanged value emits no datom, so it emits no wake.** Probe B's
  Q10 self-refire loop terminated at 3 rather than 5 because re-asserting
  `:probe/id "j"` produced no datom. A wake-worthy fact must be a genuinely
  new datom (a new entity, or a changed value). Naming a wake attribute
  whose value is idempotently re-asserted silently produces zero wakes.

Refusals do not wake: `writer.cljc:372` gates listener dispatch on
`(map? tx-report)`, and probe B confirmed
`:Q8-LISTENER-FIRED-ON-REFUSAL? false`. A refused transition therefore
cannot storm the loop.

### 5.4 Boot: the wake that is not a wake

A listener only fires on future commits. The pass that recovers work
committed before this process started is an explicit initial `offer!` after
`flow/resume` — the old code did exactly this with a bare `(scan-body!)`
after registering the listener (`driver.clj:989-990`). Keep the idea,
express it as one injected wake so there is one code path.

N2's `recover-tx` runs at boot before the proc resumes, so the loop never
observes a `:running` receipt from a dead process.

### 6.1 The one genuinely new piece: value admission (L3)

`evaluate` must gain the admission choke point §2b assigns to it. Today
`terminal-receipt-data` `pr-str`s unbounded and drops
`fn-entries`/`allocated-bytes` (`driver.clj:160-173`), and lazy values
escape the armed boundary unrealized (L3). Both are one operation inside
`evaluate`, before disarm:

1. deep-realize the value **inside** the armed boundary (so an infinite lazy
   sequence dies at the time limit rather than in the receipt writer);
2. project it to a bounded `result-edn` at that same point;
3. return `{::value realized ::result-edn bounded ::record record}` with
   `fn-entries` and `allocated-bytes` intact.

`ordinary-wire-value?` from §2b collapses into this one operation; there is
no second predicate. **This is the largest piece of genuinely new design in
N3 and the most likely place for it to overrun** — see §11.

`deps.edn`'s `:host` alias (`deps.edn:120`) into the default `:deps`. That
is the one build change N3 requires, and it is also what makes probe C's
reply splitter available.

## 7. Prompt, reply, and the model-call seam

### 7.1 Reply → ordered form sources

Probe C proved SCI's own reader does the whole job, with the correct
security posture, in ~20 lines:

```clojure
(let [rdr (sci/source-reader text)]
  (loop [acc []]
    (let [[form source] (sci/parse-next+string ctx rdr {:eof ::eof})]
      (if (= ::eof form) acc (recur (conj acc source))))))

```

```text
:SIMPLE      [(def a 1) (+ a 2)]
:STRINGS-WITH-PARENS [(println "a ) b") (inc 1)]
:EXACT-NESTED  ["(defn f [x]\n  (let [y (* x 2)]\n    {:y y}))" "(f 3)"]
:EXACT-COMMENTS [";; a note\n(def a 1)" "; trailing\n\n(inc a)"]
:READ-EVAL   [:refused EvalReader not allowed when *read-eval* is false.]
:UNKNOWN-TAG [:refused No reader function for tag foo/bar]
:UNBALANCED  [:refused EOF while reading, expected ) to match ( at [2,1]]
:EXACT-FENCED ["```clojure" "(def a 1)" "```"]

```

Four decisions fall out:

1. The D7 scar (`read-string` honouring `*read-eval*`) does not recur:
   SCI's reader refuses `#=` and unknown tags. **Nothing in N3 calls
   `clojure.core/read-string` or `read` on model text.**
2. Unbalanced input is an ordinary refusal with a position, not a hang →
   a flat error value that closes the run with a steering message.
3. Source fidelity is exact, and a leading comment attaches to the form it
   precedes. That is desirable: the stored form source is what the agent
   wrote.
4. **Fences must be stripped first** — backticks read as a symbol, so an
   unstripped fenced reply yields three "forms". This is the one piece of
   `seon.repl.parse` whose *idea* survives.

The splitter uses a throwaway `(sci/init {})` ctx: parsing is not
evaluation, so it needs neither the binding table nor the interrupt-fn.

### 7.2 The prompt

Pure function of a database value and an agent id, returning a string. For
N3 that is: the trigger's content, the agent's namespace, and the derived
interrupted-warning from N2's `interrupted-warning`
(`src/seon/cluster/run.cljc:159-194`) when a prior run was cut. Nothing is
stored. The context-block machinery is a later rung; do not reach for it.

The interrupted warning is the whole resume presentation — one derived
sentence, never per-eval markers (README s3 crash model). N3's falsifier
depends on it appearing.

### 7.3 The model-call seam

**What N3 needs now:** one function, one provider, one attempt.

```clojure
(seon.ai/complete
  {::endpoint "https://api.deepseek.com/chat/completions"
   ::model    "deepseek-..."
   ::api-key  "..."               ; from the environment at the leaf, never a datom
   ::system   "..."  ::prompt "..."
   ::timeout-ms 60000})
;; => {::text "..."} | {:seon.error/message ... :seon.error/kind :seon.ai/... }

```

Port: `src-old/seon/ai/openai_compat/core.cljc` — `request-params` (l.11)
and `parse-completion` (l.103) are pure and **adopt**; `src-old/seon/ai/http.clj`
`request!` (l.172) **adapts** down to one non-streaming JSON POST.

**Dead for N3, with the owning rung named:**

| old piece | why not now |
|---|---|
| `resolved-config-from-rows` (`ai/core.cljc:528`), `config-pull-pattern`, `agent-config-pull-pattern` | B2 config → facts owns provider descriptor rows |
| `seon.ai.provider` (347 lines), the two wire cores | one provider until a second is needed |
| `seon.ai.attempt` (75 lines of attribute registrations) | no attempt entity in N3 (§9.1) |
| the retry authority (`seon.agent.turn/call-llm!`) | **N3 has no retry.** One attempt, one deadline, failure is a flat error value that closes the run with an error the agent sees next wake |
| streaming, thinking modes, `seon.ai.tokens` | not on N3's falsifier |

The seam to B2 is exactly three facts: endpoint, model, and the *name* of
the environment variable holding the credential. N3 registers those three
attributes on the config singleton; B2 absorbs them into the provider
descriptor row without changing the call site. Credentials stay outside the
database and outside Git.

## 8. The refusal unwrap — and a correction to the open issue

`docs/seon/issues/transaction-refusal-loses-its-ex-data.md` concludes that
the refusing transition's data survives "only as printed text" and that
"Option 3 [fix the vendored fork] is the real fix." **That conclusion is
wrong.** The issue's probe inspected the top exception and exactly one
cause. Probe D walked the whole chain:

```text
:REFUSAL-CHAIN
 [{:class clojure.lang.ExceptionInfo, :ex-data {}}
  {:class java.util.concurrent.ExecutionException, :ex-data nil}
  {:class clojure.lang.ExceptionInfo,
   :ex-data {:seon.error/kind :probe/refused, :probe/rule :ineligible}}]

:CAS-CHAIN    [... {:ex-data {:error :transact/cas, :old #datahike/Datom [...], :expected 5, :new 7}}]
:SCHEMA-VIOLATION-CHAIN [... {:ex-data {:error :transact/schema, :value not-an-int, :attribute :probe/n, ...}}]
:ASYNC-REFUSAL-CHAIN    [... {:ex-data #:probe{:rule :async}}]

```

The transition's own `ex-data` is intact at the third link, and datahike's
own aborts are equally distinguishable *by value*. The mechanism is
`throwable-promise`'s deref (`reference-code/datahike/src/datahike/tools.cljc:93-107`)
wrapping the `ExecutionException` in a fresh `ex-info` with empty data — it
wraps, it does not discard. **No fork change is required.**

### 8.1 The design

One function, owned by the store owner the issue names:

```clojure
;; seon.cluster.store
(defn transact!
  "Commit tx-data. Returns the transaction report on success and a flat
  :seon.error value on refusal. NEVER throws — nothing throws into the
  run loop."
  [connection tx-data] ...)

```

Refusal classification is a pure function of the cause chain and is
unit-testable without a database:

```clojure
(defn refusal
  "The deepest non-empty ex-data in a throwable's cause chain, or nil."
  [throwable] ...)

```

Three outcomes, three shapes:

| outcome | returned value |
|---|---|
| committed | the transaction report |
| our transition refused | `{:seon.error/kind :seon.cluster.run/refused ::rule ... ::transition ... ::request ...}` — the transition's own map, verbatim, wrapped |
| datahike aborted (`:transact/cas`, `:transact/schema`, …) | `{:seon.error/kind :seon.db/rejected :seon.error/data {:error :transact/schema ...}}` |
| nothing classifiable | `{:seon.error/kind :seon.db/unknown-failure ...}` — and in dev this **panics** on the `:seon.config/on-core-error` dial (R41), because an unclassifiable transaction failure is a bug, not a condition |

That last row is the one that keeps this honest: the issue's real complaint
is that a green-for-the-wrong-reason test cannot tell a correct fence from
a typo. An unclassifiable failure must be loud, not absorbed.

## 9. The turn, and the crash walk

### 9.1 The one sequencing decision that needs a ruling

The old loop opened the run, opened a turn, called the model, then froze
the plan (`driver.clj:824-913`). A crash inside that window leaves an open,
claimed, **unplanned** run — the window holding 78.5% of a turn, and the
subject of the unowned issue `run-is-unrecoverable-before-its-plan-commits`.
N3 must resolve it. Two coherent options; the orchestrator or owner picks.

**Option A — open+claim early (recommended).** Open and claim the run on
wake, *then* derive the prompt, call the model, freeze the plan, fold.

- The agent-busy fence exists before the expensive part, so a second
  trigger during a model call cannot start a second turn.
- Recovery is one derived question: does the open run have a
  `::plan-digest`? No → re-derive the prompt and call the model again. Yes
  → resume at the first ordinal without a terminal receipt.
- The "unrecoverable" framing was never about the facts — it was the old
  recovery *query* requiring `:seon.agent.run/plan-digest`
  (`driver.clj:351-358`). Drop that clause and the window recovers.
- Honest cost: **one repeated model call per process crash mid-turn.** That
  is at-least-once for an external effect, which is L10's stated ceiling,
  and it re-executes no agent form and refires no agent-requested effect —
  the s3 crash model is intact.

**Option B — open+plan in one transaction.** Call the model *before* any
run exists, then commit open+claim+plan atomically.

- Makes the unplanned-open-run state unrepresentable, which is the
  construction-over-tests discipline in its purest form.
- Costs the early fence: two triggers for one agent both reach the model,
  and the loser's `open-call` refuses `::agent-already-running`. Under one
  serial run-loop proc per cluster that is only reachable across a crash,
  but the fence is genuinely weaker.
- Requires an N2 contract revision: `open-call` gains required `::process`,
  `::lease-until`, `::plan-digest`, `::sources`.

**Recommendation: A**, because the early fence is worth more than the
unrepresentability, and because A leaves N2 sealed and untouched. If the
owner prefers B, it is a small, well-understood N2 revision — but it should
be decided *before* implementation, not discovered during it.

### 9.2 The turn as a reduce

```
claim → derive prompt → model (:io) → split reply → freeze plan (N2 plan-tx)
      → reduce over ordered forms:
            running receipt
            → submit!! → guarded eval at the previous step's :db-after
            → terminal receipt + interpreted disposition, in ONE transaction
      → close (on :completed) or release (on :wait)

```

Two properties from the quarry that must survive into the contract:

- **The terminal transaction is one commit** carrying the receipt *and* the
  disposition's tx-data (`driver.clj:289-297`). Splitting them reintroduces
  a torn window.
- **A rejected terminal transaction is followed by a terminal error-receipt
  transaction containing no agent value** (`driver.clj:310-327`). Under the
  new `transact!` wrapper this is no longer a `catch` — it is a branch on a
  returned error value, which is strictly better.

### 9.3 Crash walk — kill at every loop position

The contract package carries this table; each row is a live falsifier
(`kill -9`, then reopen and observe).

| # | kill position | committed state at kill | what recovery must do | what the agent must see |
|---|---|---|---|---|
| 1 | after trigger commits, before wake is handled | trigger only | boot pass derives the trigger as unanswered | a normal first turn |
| 2 | after claim, before the model call | open run, claimed, no plan | `recover-tx` releases dead custody; next pass re-claims, re-derives, calls the model | a normal turn (no evidence a crash occurred) |
| 3 | during the model call | same as 2 | same as 2 | same as 2 — **one repeated paid call**, the L10 ceiling |
| 4 | after the model returns, before plan freeze | same as 2 | same as 2 | same as 2 |
| 5 | after plan freeze, before form 0's running receipt | run + plan-digest + forms | resume at ordinal 0 | nothing unusual; no form ran |
| 6 | after a running receipt, before the eval finishes | receipt `:running` | `recover-tx` → `:interrupted`; resume at the next ordinal | ONE derived warning: "interrupted at form N; later results missing" |
| 7 | after the eval, before the terminal transaction | receipt `:running` | as 6 — **the form's effect may have happened**; nothing refires | the same one warning |
| 8 | after a terminal receipt, mid-fold | k terminal receipts | resume at ordinal k | no warning; the fold continues |
| 9 | after the last terminal receipt, before close | all receipts terminal, run open | the pass finds no next form → close | the completion lands one wake later |
| 10 | after close | run closed | nothing | done |
| 11 | twice — kill during recovery itself | any of the above | `recover-tx` is idempotent; terminal receipts byte-untouched | as the single-kill row |
| 12 | kill with the wake channel non-empty | any | channel contents are discarded (`flow/impl.clj:174-183`); work is re-derived from facts | as the corresponding row |

Row 3 is the one that must be argued, not asserted, in the contract: it is
the deliberate at-least-once boundary, and it is the reason `fire-the-
missles!` safety comes from "the system never refires anything" and not
from an identity scheme.

Rows 6 and 7 are indistinguishable from the facts — that is correct and
intentional. The warning says "may have happened," which is exactly L10's
honest ceiling.

## 11. Risks, ranked

1. **The L3 admission point is the scope bomb (§6.1).** Deep-realizing an
   arbitrary agent value inside the armed boundary is the one genuinely new
   mechanism in the rung, and "bounded `pr-str`" hides real questions
   (records? Java objects? cyclic structures?). *Mitigation:* author C7 as
   its own sealed contract with an explicit total codec, and be willing to
   split it into its own rung if the lane hits friction. Do not let it
   grow inside `loop`.
2. **Serial turns per cluster (§4.5).** The final system gate wants live
   agents, plural, for an hour. One proc gives one turn at a time.
   *Mitigation:* the extension point is named; measure the ceiling at the
   N3 review and decide against a number, not a feeling.
3. **The §9.1 sequencing decision baked in silently.** A lane will pick one
   and it will be very hard to change afterwards. *Mitigation:* the
   orchestrator rules before authoring.
4. **The wake handler contract is easy to violate later.** It is four lines
   with two absolute prohibitions, and probe A shows violating one hangs a
   caller forever with no error. *Mitigation:* C3 as a property, and the
   prohibition in the namespace docstring with the `writer.cljc:384-386`
   citation.
5. **The model call is unbounded external I/O in an `:io` proc.** A hung
   HTTP call blocks the cluster's only run loop indefinitely. This is the
   legitimate deadline case (genuinely unobservable external state), but it
   must be an explicit request timeout on the HTTP client, not an ambient
   hope. *Mitigation:* C10 names it; the firing is an ordinary error value,
   not a bug report.
6. **SCI joining the default classpath (§6.2)** changes boot time, and B0's
   ten-second bound is asserted in-suite. *Mitigation:* re-measure the B0
   bound in the same commit that moves the dependency.
7. **Deleting `seon.flow/database-proc` touches a file another lane may
   hold.** *Mitigation:* orchestrator-owned, path-limited, at a lane-quiet
   point.
8. **`:seon.cluster.message/*` may collide with a later messaging design.**
   N3 needs a trigger, not a messaging system. *Mitigation:* four
   attributes, no delivery/ack/read semantics, and an explicit note that
   the messaging rung owns the shape.

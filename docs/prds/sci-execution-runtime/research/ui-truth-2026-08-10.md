# UI truth — every route walked live, 2026-08-10

## What this is

An independent verification walk of **every** route in
`src/seon/render/route.clj` against the live `default` cluster
(pid 31570, `http://127.0.0.1:7994`) on current HEAD, driven from a
**real browser** (Claude Browser MCP) plus `curl` for status and
timing. No production source was edited.

Grounding read END TO END before probing, as required:
`src/seon/render/route.clj`, `.agents/skills/datastar-web-ui/SKILL.md`,
and [transfer-prompt-2026-08-08.md](../plan/transfer-prompt-2026-08-08.md).

The routes were enumerated from the route table Var, never from memory.
All ten route entries are covered below.

## Headline

**The UI is functionally sound and visually broken.** Every route
returns 200 with real, correct content; the full live loop
(POST → agent turn → model reply → SSE morph → reconnect) is
PROVEN LIVE end to end. What is broken is *presentation and cost*:
699 value nodes on the root page render as unlabeled bare triangles
because no stylesheet rule for the print faces exists at all, core
namespace pages take 12–18 s, and the feed emits 200+ console warnings
per debug page load.

For the model-authoring drive specifically: **agent context renders
correctly and the message→reply→render loop works.** The drive can
proceed.

## The single worst finding — value nodes have no visible label

Every collapsed value node in every page renders as a **bare, unlabeled
disclosure triangle**. 699 of them on the root page alone.

`src/seon/print.cljc:158-159` emits the summary with the label in an
**attribute only**, with no child text:

```clojure
[:summary {:class "seon-print-summary"
           :data-seon-summary (::summary node)}]
```

A live DOM sample shows the label is genuinely present and genuinely
invisible:

```html
<summary class="seon-print-summary" data-seon-summary="{} 9 keys"></summary>
```

The intent is clearly that CSS surfaces it via `content: attr(data-seon-summary)`.
**That rule does not exist.** Measured in the browser:

```text
getComputedStyle(summary,'::before').content  =>  "none"
getComputedStyle(summary,'::after').content   =>  "none"
matched rules for .seon-print-summary         =>  []   (zero)
```

And confirmed in the tree — neither the source nor the built stylesheet
has ever carried these rules:

```text
rg -l "seon-print" resources/            => NONE
rg -l "seon-render-unavailable" resources/ => NONE
```

So this is not a stale build. The print-face DOM contract
(`seon-print-summary`, `seon-print-content`, `seon-print-node`,
`seon-render-unavailable`) was **never styled at all**. The same gap
explains the `seon-print-table` face, which emits its content span with
`:hidden "hidden"` (`print.cljc:147`) expecting CSS that is not there.

Filed: [print-faces-have-no-stylesheet-so-values-render-as-bare-triangles.md](../../../seon/issues/print-faces-have-no-stylesheet-so-values-render-as-bare-triangles.md)

## Other defects found

### Feed patches target elements the page does not have

Loading `/ns/my.agents.root/debug` produces **200+**
`PatchElementsNoTargetsFound` warnings from `datastar.js`. The render
proc publishes complete-page block patches whose element ids exist on
the normal namespace layout but not on the two-pane debug layout, so
every one of them is computed, serialized, sent over the wire, and
discarded by the client.

This is wasted work on the one `:io` render proc and a wall of noise
that would bury a real console error.

Filed: [debug-pages-receive-block-patches-for-elements-they-do-not-have.md](../../../seon/issues/debug-pages-receive-block-patches-for-elements-they-do-not-have.md)

This is very likely the same declaration-population fallback already
priced in the `/data` note (the fallback wall fires on every eval in
this cluster, observed directly during this walk). Recorded against
that note rather than duplicated.

### Ugly output observed (standing order)

- **Model reasoning is rendered into the page.** Raw chain-of-thought
  appears as the visible `<summary>` label of session entries:
  `We need answer as agent in Seon cluster. Need inspect current run
  instruction. We have pending messages with errors: …`. This is the
  model's scratch reasoning, verbatim, as the primary visible text of a
  block on the root page.
- **`renderer unavailable`** ×33 on `/`, all at
  `data-walk-path=[:seon.render.walk/neighbours N :seon.render.walk/neighbours 0]`
  — i.e. consistently at depth-2 neighbour position 0.
- **Truncated maps with a bare ellipsis**:
  `#:seon.cluster.message{:about "maintenance-error/…", ...}` — the
  `...` carries no count and no requery path, unlike the good elision
  values elsewhere.
- **The MCP error face for a missing connection returns a map as a
  vector of pairs**: `[["seon.error/kind" …] ["seon.error/message" …]]`
  rather than a map, in the `eval_clj` envelope.
- **`DECLARATION POPULATION FALLBACK` wall** fires on ordinary evals
  (already filed).

## What is genuinely in good shape

Calibration, not just alarm — these were verified, not assumed:

- **The whole live loop works.** A message POSTed to `/agent/root/message`
  produced a real agent turn, a real model reply, and rendered the reply
  into the page. The probe asked for the literal string `PONG-V1`; the
  page now contains `PONG-V1`. This is the end-to-end path the
  model-authoring drive needs.
- **SSE morphs are live and correct**, and reconnect serves current
  state without replaying in-flight partials — exactly the documented
  contract.
- **Route aliasing is exactly as documented**: `/` ≡ `/ns/my.agents.root`
  and `/agent/root/debug` ≡ `/ns/my.agents.root/debug`, byte-identical.
- **404s are correct** for unknown namespaces and unknown agents.
- **Static assets serve in under 2 ms** with zero console errors.
- **The debug page's two panes both work** — the AI pane carries 61 KB
  of real agent context. The claim from commit `80ae69ad1` holds.
- **`No recorded context capture exists for this agent.`** is a good,
  honest refusal face — it names exactly what is missing.

## Verdict for the model-authoring drive

**Proceed.** Agent context renders correctly (61 KB of real depth-2
context in the AI projection), the message→turn→reply→render loop is
proven live on current HEAD, and reconnect is safe. Every defect found
is presentational or cost, not correctness — none of them can corrupt
or hide what the model authors.

The one caveat for a human *watching* the drive: the page will be hard
to read, because value nodes show as unlabeled triangles until the
print-face stylesheet exists.

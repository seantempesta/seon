# N4 implementation plan — `seon.cluster.render`, the in-process render pipeline

This is the implementation PLAN for the N4 rung. It EXTENDS
`jvm-render-design-2026-07-26.md` rather than re-deriving it; §2 records
exactly which of that audit's conclusions the O14 dissolution overturned and
which survive. The orchestrator authors the sealed contracts; §9 lists the
contract candidates and §10 the crash-walk rows they must carry.

## 0. Verdict in one paragraph

N4 is buildable as ruled, and the ruling is the SIMPLER design: dissolving the
web-render process deletes the transport question that forced the prior audit
to recommend storing a rendered snapshot. In-process, "one authored evaluation
for 32 tabs" and "restart = one re-render per pinned canvas" are both satisfied
by ONE registration holding its last complete value in memory — no result
attribute, no no-history facet, no derive-vs-store conflict. Four things,
however, are not free and must be sealed before a lane starts: (1) a Datahike
listener callback runs ON the writer's commit path and directly stalls every
transacting caller — MEASURED below, §4.1 — so the wake must be a non-blocking
`put!` and nothing else; (2) the guarded eval still returns lazy values and
disarms the interrupt in `finally`, so authored code escapes containment
(§4.4); (3) per-tab fan-out CANNOT be flow topology, because a flow graph's
conns are fixed at `create-flow` while tabs arrive at runtime (§5.3); and
(4) "bounded writes" is still false below the SDK — http-kit's pending socket
list is unbounded and unobservable, and no userspace bound exists without a
fork (§6.4). Items 1–3 are design decisions inside N4. Item 4 is a ranked risk
with a decision the owner must take (§11, R1).

## 2. What O14's dissolution overturns in the prior audit

The prior audit's central recommendation — commit the rendered snapshot as a
cardinality-one no-history fact — was justified ONLY by durable cross-process
handoff and zero-evaluation reconnect
(`research/jvm-render-design-2026-07-26.md:49-65,320-361`). Merging web-render
into the cluster JVM removes the first justification entirely and reduces the
second to a process-restart question.

| Prior audit conclusion | Status under O14 | Why |
|---|---|---|
| Commit the complete snapshot to a new no-history attribute (`:320-361`) | **DEAD** | There is no second process to hand it to. Restart re-renders once per pinned canvas — the ruling's own words (`plan/README.md:155-156`). Storing it would now be a pure derive-don't-store violation with zero compensating benefit. |
| "Do not overwrite `:seon.render.canvas/content`" (`:336-338`) | **SURVIVES** | The pin stays the authored program. `src-old/seon/render/canvas.cljc:343-372` reads it as symbol-or-literal. |
| One active registration per pinned canvas, regardless of tab count (`:363-375`) | **SURVIVES, and is now the whole design** | It is what makes 32 tabs cost one evaluation without any stored fact. |
| Deep realization inside the armed boundary (`:406-418`) | **SURVIVES, unchanged and mandatory** | Process merge makes it MORE urgent: authored lazy realization now happens in the same JVM as the writer. |
| Fault path with retained `fn-entries`/`allocated-bytes` (`:420-452`) | **SURVIVES** | Second half of the N4 falsifier: "the agent learns why" (`plan/README.md:746`). |
| http-kit's unbounded pending queue (`:35-42,164`) | **SURVIVES, unchanged** | The transport is the same library. Issue `http-kit-streaming-writes-have-an-unbounded-socket-queue` stays open. |
| The `:mixed` classification table (`:455-474`) | **SURVIVES, and contradicts the ruling's `:io` label** | See §5.5. |
| Attribute-only interest fan-out (`:159`, issue `attribute-only-feed-interest-recomputes-unrelated-agent-views`) | **SURVIVES and CANNOT be fixed in N4** | Confirmed at the source: `query-dependency-plan` returns per-source ATTRIBUTE sets only (`reference-code/datahike/src/datahike/query.cljc:2877-2903`). ## 4. The render-unit data model

### 4.1 The wake is the hard constraint — MEASURED

`d/listen`'s callback is invoked from `datahike.writer`'s commit path at
`reference-code/datahike/src/datahike/writer.cljc:384-385`, inside the same
`go` block that delivers the transacting caller's promise at `:386`. Datahike's
own API doc warns that synchronous writer operations inside the callback
deadlock (`reference-code/datahike/src/datahike/api/specification.cljc:1077`).

The probe (`tmp/n4_listen_probe.clj`, run `clojure -M:dev
tmp/n4_listen_probe.clj`, JDK 26.0.1, Datahike at the vendored local root,
`:memory` backend) makes the cost exact:

```
:caller-thread  main
:listener       [{:thread async-mixed-1}]
:transact2-ms   1503      ; listener does (Thread/sleep 1500)
:transact3-ms   1504      ; the NEXT transaction pays it again
```

A listener that takes 1.5 s adds 1.5 s to EVERY subsequent `d/transact`, on
core.async's shared `:mixed` executor. This is a stronger constraint than the
prior audit's thread-classification table stated.

**Sealed invariant:** the render wake callback performs exactly one
`(async/put! wake-chan event)` on a `(sliding-buffer 1)`-fronted channel and
returns. It never queries, never renders, never blocks, never transacts. A
contract test asserts the callback's own wall time and that a saturated wake
channel does not extend transaction latency.

### 4.2 What flows on the wake channel

Datahike's report is `{:db-before :db-after :tx-data :tempids :tx-meta}` with
`:db-after` a real `datahike.db.DB` (probe `tmp/n4_report_probe.clj`). Its
basis is `:max-tx` (`536870913` in the probe), and `:t` is **nil** — `:t` was a
`seon.db` facade projection, not Datahike's name. The nucleus talks Datahike:
**`:max-tx` is the basis**, and `src-old/seon/reactive.cljc:110-118`'s
`newer-database` is ported with that one substitution (port verdict `adapt`,
§8).

The wake value is the whole report. The pipeline derives changed attributes
from `:tx-data` (each datom's attribute) exactly as the old writer did at the
interest index, and matches them against each registration's recorded interest
set.

### 4.3 The render unit — DERIVED, never registered

A **render unit** is the addressable thing a tab subscribes to and a
registration owns. Its identity is a value, not an entity:

```clojure
;; the identity — a closed ordinary value, the mult/tap and tab-route key
[:seon.render.unit/canvas  <agent-id>]   ; focal, pinned by
                                          ; :seon.render.canvas/content
[:seon.render.unit/surface <agent-id> <surface-key>]  ; a context render
```

Two constructors only — canvas and surface — because the ruling admits no
third surface noun (`plan/README.md:213-217`).

**No new database attribute is registered by N4.** The set of live render
units is DERIVED by query: an agent with a `:seon.render.canvas/content` fact
has a canvas unit. This is the whole point of O14's dissolution, and it is the
rung's contribution to metric 2, "the data model tightens"
(`plan/README.md:562-566`): N4 adds ZERO attributes.

### 4.4 The unit VALUE — and the containment hole that must close first

One completed render is an ordinary closed map produced by the render proc:

```clojure
{:seon.render/unit      <unit identity>
 :seon.render/basis     <:max-tx of the database value rendered at>
 :seon.render/ai        <string>                 ; optional projection
 :seon.render/html      <admitted hiccup>        ; optional projection
 :seon.render/evidence  <attribute set | :all>   ; interest for the next wake
 :seon.render/diagnostic <the :seon.eval record> ; always present
 :seon.error/…}                                   ; flat error value on failure
```

Both projection keys are optional and at least one must be present: an
html-only widget and an ai-only context block are both legal, which is exactly
how `src-old/seon/agent/ctx.cljc:1677-1689` already treats the pair.

The value is only trustworthy if it is deeply realized INSIDE the armed
interrupt. Today it is not: `src-old/seon/sci/eval.clj:250` returns
`(sci/eval-form evaluation-ctx form)` raw and `:262` disarms with `(stop!)` in
`finally`. A `LazySeq` of hiccup children therefore realizes — running authored
code — after containment ends; the prior audit measured one authored callback
firing outside the boundary
(`research/jvm-render-design-2026-07-26.md:547-551`).

**Sequencing note for the orchestrator:** the fix belongs at the ONE choke
point in `seon.sci.eval`, and `seon.sci.eval` is adopted by N3
(`plan/README.md:697-703,725-737`). If N3 lands without admission, N4 extends
`seon.sci.eval` in place — it must never add a second walker in
`seon.cluster.render`. Recommend the N3 contract package own admission and N4
depend on it.

Admission, per the prior audit's five requirements
(`research/jvm-render-design-2026-07-26.md:408-414`): walk every collection
including lazy seqs; force delayed closures while armed; enforce depth/item/
string caps during the walk; reject host objects as a flat agent error; return
a persistent value.

## 5. Pipeline topology

```
 d/listen callback  ──put!──▶  wake-chan (sliding-buffer 1, per registration set)
   [writer commit path;                │
    O(1), non-blocking]                ▼
                            ┌──────────────────────────┐
                            │ scheduler proc  (:mixed) │  registration memory:
                            │ pure registration/wake,  │  interest, dirty-at,
                            │ due?, settle windows     │  last-value, basis
                            └───────────┬──────────────┘
                                        │ one due unit at a time
                                        ▼
                            ┌──────────────────────────┐
                            │ render proc   (:compute) │  ONE seon.sci.eval
                            │ guarded eval + admission │  per due unit
                            └───────────┬──────────────┘
                                        │ completed unit value
                                        ▼
                            ┌──────────────────────────┐
                            │ equality gate            │  = against last-value
                            │ (in scheduler, pure)     │  in registration memory
                            └───────────┬──────────────┘
                       unequal only     │
             ┌──────────────────────────┴──────────────────┐
             ▼ (ai projection)                             ▼ (html projection)
    N3 prompt derivation                        fanout owner: mult per unit
    reads the same registration                          │
    value at a basis (§9)                    tap: (sliding-buffer 1) per TAB
                                                          │
                                              per-tab writer (:mixed vthread)
                                                          │
                                            datastar/patch-elements! → 1 SSE
```

### 5.1 Which parts are flow, and which are not

- The scheduler and render procs are ordinary `flow/process` procs in the
  cluster's per-cluster graph (`research/flow-per-cluster-2026-07-27.md:9-33`).
  The render proc is declared `:compute`; flow runs a `:compute` proc's loop on
  `:io` and submits each transform separately to `:compute`
  (`.../flow/impl.clj:243-270`, cited via
  `research/flow-per-cluster-2026-07-27.md:99-104`).
- The per-tab fan-out is **NOT** flow topology. See §5.3.

### 5.2 Why the scheduler is a proc and not the timer thread

`src-old/seon/reactive.cljc:83-91` runs a single-threaded
`seon-reactive-settle` scheduled executor whose callback calls
`start-evaluation!` at `:197-220`, and the CLJ branch computes the whole render
synchronously at `:547-556`. The timer thread thus BECOMES the render worker —
the defect the prior audit named
(`research/jvm-render-design-2026-07-26.md:200-208,463`). In N4 the timer only
publishes readiness onto the scheduler proc's input; the scheduler only decides;
the render proc only computes. This is also the plan's standing rule that a
constant must stand in for an observable event where one exists
(`plan/README.md` runtime contracts; `CLAUDE.md` "Timeouts and magic numbers").

### 5.3 Per-tab fan-out cannot be flow — proven at the source

`create-flow` validates and closes over a FIXED conn map
(`.../flow/impl.clj:38-70`), and `start` allocates every channel and every
`mult` from that map: `needs-mult?` is computed once at `:113-115` and the
mults are built once at `:135-140`. There is no API to add a conn to a running
graph. Tabs arrive and leave at runtime.

Therefore the fan-out owner is an ordinary component holding, per render unit,
`(async/mult out-ch)` plus `(async/tap m (async/chan (async/sliding-buffer 1)))`
per tab, untapped on disconnect. `src/seon/flow.clj:645-714` is the existing
in-repo precedent for exactly this pattern — owning a mult and dynamic taps
alongside a started graph — and should be the shape the lane follows, not a
new invention.

### 5.4 Streamed reply partials ride the same pipeline

The ruling retires the coalesced no-history fact
(`plan/README.md:156-157`). Concretely, `:seon.ai.attempt/partial-text` —
registered `[:string {:seon.db/no-history? true}]` at
`src-old/seon/ai/attempt.cljc:29-30`, a member of the attempt entity at `:65`,
and published on the `:seon.config.model-stream/partial-publish-settle-ms`
cadence (`src-old/seon/ai/core.cljc:361`) — is DELETED, not ported.

Replacement: the model-call proc coalesces partials in its own step state and
emits a presentation update directly onto the render pipeline, addressed to the
transcript render unit, bypassing the guarded eval (nothing authored runs — it
is the model's own text). The scheduler treats it as a second input class that
marks a unit due; everything downstream — equality gate, mult, per-tab tap,
writer — is unchanged. The transcript's durable fact remains the settled reply,
committed once, as today.

This deletes one attribute, one config dial, one facet use, and the
partial-text row that is the WORKED EXAMPLE in the attribute-only-interest
issue — a metric-2 and metric-3 win
(`plan/README.md:562-572`).

### 5.5 Workload tags — the ruling's `:io` label is imprecise

`reference-code/core.async/src/main/clojure/clojure/core/async.clj:515-519`:
`:io` "may do blocking I/O but must not do extended computation"; `:compute`
"must not ever block"; `:mixed` "anything else". The per-tab writer takes from
a channel (blocks) AND builds the SSE frame, optionally gzipping it (computes).
That is `:mixed` by definition, matching the prior audit's table
(`research/jvm-render-design-2026-07-26.md:462`).

Recommendation: the sealed contract says `:mixed` for the tab writer and the
scheduler, `:compute` for the render proc. The orchestrator should note the
correction in the plan README's O14 text so the two do not drift.

## 6. The http-kit / SSE seam, in SDK vocabulary

### 6.1 Server

One `org.httpkit.server/run-server` in the cluster JVM, bound to loopback, with
a bounded `:worker-pool` and `:max-body`, exactly as
`src-old/seon/web/server.clj:304-311` already does. Port is dynamic and
published to the per-cluster advertisement that B0 already writes
(`src/seon/cluster.clj:272-276`) — not a new port file.

### 6.2 One SSE connection per tab

`starfederation.datastar.clojure.adapter.http-kit/->sse-response` with the
option keys the adapter exposes at
`.../adapter/http_kit.clj:9-20`: `on-open`, `on-close`, `on-exception`,
`write-profile` (`basic-profile` / `gzip-profile` / the buffered variants).
`on-open` receives the SSE generator, `on-close` receives it plus http-kit's
status code (`.../adapter/http_kit.clj:55-80`).

Per tab, `on-open` (a) taps the unit's mult with a fresh
`(sliding-buffer 1)` channel, (b) starts one virtual thread that loops
take → `starfederation.datastar.clojure.api/patch-elements!`, and (c)
unconditionally writes the registration's current value if one exists —
"reconnect = repaint". `on-close` untaps, closes the tap channel, and
interrupts the writer. `src-old/seon/web/feed.clj:90-158` is the working shape
for all of this and is the plan's `adapt` source.

### 6.3 Patch vocabulary

`patch-elements!` with no options uses the SDK's default `outer` patch mode
(`.../clojure/api.clj:222-224,268-285`), which is what a complete morph of one
element wants. The element id IS the render unit's DOM identity; the shell
places the feed opener OUTSIDE the morphed element, the lesson recorded at
`src-old/seon/web/datastar.cljs:611-620` — a `data-init` inside the morphed
element is stripped by the first whole-element morph. `src-old/seon/web/data.clj:86-106`
is the minimal working shell and is the `adapt` source for it.

Not used by N4: `patch-signals!`, `execute-script!`, `remove-element!`. Adding
them is a later decision, not a rung requirement.

### 6.4 "Bounded writes" — what is true and what is not

Bounded IN SEON: at most one un-sent value per tab, because the tap is
`(sliding-buffer 1)`; `.clear`-then-`.offer` in
`src-old/seon/web/feed.clj:22-25` is the same semantics expressed by hand, and
made the configured `::mailbox-depth` structurally unreachable — delete that
dial, do not port it.

NOT bounded below the SDK. `SSEGenerator.send-event!`
(`.../adapter/http_kit/impl.cljc:74-88`) calls `hk-server/send!`, which reaches
`AsyncChannel.send` — returning `true` after handing buffers to the write path,
never a completion (`reference-code/http-kit/src/java/org/httpkit/server/AsyncChannel.java:251-293`).
`HttpServer.tryWrite` appends the unwritten remainder to
`atta.toWrites` at `:378-385` and appends every later send while any write is
pending at `:395-399`. `toWrites` is `final LinkedList<ByteBuffer>`, package
private, with no accessor (`ServerAtta.java:6-7`; the only readers are inside
`HttpServer.java:332-350`). There is no signal a userspace writer can consult
and no completion to await.

Consequences the plan states plainly rather than papering over:

- a paused-read tab accumulates complete morph frames on the JVM heap;
- `send-event!` returning `false` only tells us the connection is already
  closed — it is not backpressure;
- no arrangement of core.async buffers fixes this, because the unbounded queue
  is downstream of every channel we own.

Options, ranked in §11 R1.

## 7. Equality suppression and registration memory

### 7.1 The memory

One process-local atom per cluster holding `{unit → registration}`. Legitimate
under the atoms rule: this is invocation-local coordination over derived
presentation state, and nothing in it is durable
(`CLAUDE.md` "The database, not atoms, owns important durable state").

```clojure
{:seon.render/unit        <unit identity>
 :seon.render/last-value  <the completed unit value, or absent>
 :seon.render/basis       <:max-tx it was rendered at>
 :seon.render/interest    <attribute set | :all>
 :seon.render/pending     <newest pending database value, or absent>
 :seon.render/dirty-at    <monotonic ms, or absent>
 :seon.render/active      <evaluation id, or absent>}
```

Absent keys, never stored nil (`CLAUDE.md` data-oriented rules).

### 7.2 The transitions, ported as pure functions

Five ideas in `src-old/seon/reactive.cljc` are genuinely good and survive as
pure functions of (registration, event, now):

| Idea | Old site | Port verdict |
|---|---|---|
| newest-pending replacement (a slow render never queues bases) | `:110-118`, `:252-290` | `adapt` — `:t` → `:max-tx` |
| settle window bounded by max latency: `due-at = min(dirty-at + max-latency, now + settle)` | `:192-195` | `adopt` as a pure fn |
| one active evaluation per registration; the newest pending wins | `:504-556` | `adapt` — the proc replaces the direct call |
| equality suppression against the previously DELIVERED value | `:486-492` | `adopt` |
| evidence signature drives interest re-installation only when it CHANGED | `:120-129`, `:496-501` | `adopt` |

Everything else — the consumer registry, `observe!`/`unobserve!`, the ready
promise, the failure-evidence suppression, the Promise branches — is `dead`
(§8). In the merged process there is exactly one consumer of a registration
(the fan-out owner), so multi-consumer normalization is machinery for a problem
that no longer exists.

### 7.3 What suppression compares

`=` on the whole completed unit value MINUS `:seon.render/basis` and
`:seon.render/diagnostic`. Those two change on every render by construction; a
naive whole-value `=` would suppress nothing and send a morph per commit.
Comparing the projections only is the semantics the falsifier needs.

Instrumentation, following `src/seon/flow.clj:553-581`'s counted-dropping-buffer
precedent: per unit, count evaluations started, evaluations completed,
suppressed-equal results, newest-pending replacements, and per tab, tap drops.

## 9. The ai-projection consumer seam

The `ai` projection has NO channel, NO tap, and NO writer. This asymmetry is
the point of "two projections on one unit": the html projection is PUSHED to a
socket because a browser cannot ask; the ai projection is PULLED by prompt
derivation because an agent asks exactly when it builds a turn.

Seam contract, for N3 to consume:

```clojure
(defn ai-projection
  "Return the current `:seon.render/ai` string for one render unit at a basis,
   rendering it if the registration has no value at or after `basis`."
  {:malli/schema [:=> [:cat :seon.render/unit :seon.render/basis]
                  [:or :string :seon.error/value]]}
  ...)
```

Three properties the sealed contract must pin:

1. **One value, two readers.** A unit rendered for a tab is NOT rendered again
   for the prompt at the same basis. The registration's `last-value` serves
   both. This is the strongest argument for keeping ONE registration per unit
   rather than separate ai/html registrations.
2. **The prompt never waits on a socket.** If no tab is connected, the unit has
   no registration; `ai-projection` renders once, synchronously, through the
   same guarded eval, and seeds the registration. Prompt derivation must not
   depend on a tab existing.
3. **Errors are values.** A failed render yields the flat `:seon.error` value
   into the prompt as legible text — never a throw into the run loop
   (`plan/README.md:590-598`).

`src-old/seon/agent/ctx.cljc:1677-1689` and `:1820-1855` show the old
consumer: a block is agent-visible exactly when it carries `:seon.render/ai`.
That predicate survives; the machinery around it does not.

## 10. Sealed-contract candidates

The orchestrator authors these; each is one package of schemas + `:malli/schema`
stubs + generative properties (`plan/handbook.md:33-45`).

| # | Contract | Core generative property |
|---|---|---|
| C1 | `seon.render` unit identity + unit value | Round-trip: every generated unit value has at least one projection; projection selection is total and never throws. |
| C2 | `registration/wake`, `due?`, `begin`, `settle`, `release` | Over generated wake/commit/settle interleavings: at most one active evaluation per unit; the value rendered is always at the NEWEST basis seen before `begin`; `due-at` never exceeds `dirty-at + max-latency`. |
| C3 | Equality suppression | For any sequence of renders, the number of values reaching the mult equals the number of PROJECTION changes — basis and diagnostic churn alone never emit. |
| C4 | Wake non-blocking (the §4.1 invariant) | Callback wall time is bounded and independent of pipeline state; a saturated wake channel does not extend transaction latency. **Crash-walk required.** |
| C5 | Admission (deep realization + caps) — owned by `seon.sci.eval` | No authored code executes after `stop!`; every returned value is persistent; caps are enforced during the walk, not after. |
| C6 | Tab lifecycle: tap → write → untap | Over generated connect/disconnect/slow-reader interleavings: taps and untaps balance; no tab retains more than one un-sent value; a disconnect never affects another tab or the registration. **Crash-walk required.** |
| C7 | Render fault → agent-visible diagnostic | A timed-out renderer yields a flat error value carrying `:seon.eval/fn-entries`, `:seon.eval/duration-ms`, `:seon.eval/outcome`; the derived agent text distinguishes high-entry spin from low-entry host blockage. |

C4 and C6 are the identity/custody-shaped contracts of this rung and must carry
the crash-walk table before sealing — the handbook's explicit lesson from the
contract that shipped two defects (`plan/handbook.md:38-41`).

## 12. Risks, ranked

**R1 — http-kit's unbounded pending queue (blocker-severity, unchanged).**
Issue `docs/seon/issues/http-kit-streaming-writes-have-an-unbounded-socket-queue.md`
already states the acceptance criteria. Options:

1. *Measure and accept, with the number recorded.* Commit a paused-read SSE
   probe (the issue's own acceptance test) and report heap growth per morph per
   stalled tab. Cheap; leaves the claim "bounded writes" partly false but
   HONEST and quantified.
2. *Fork http-kit minimally.* `reference-code/http-kit` is currently a vendored
   UPSTREAM submodule (`70432d3`, remote `http-kit/http-kit`), and the
   coordinate resolves from Maven through `sdk-http-kit/deps.edn:2-3`. A
   minimal, upstreamable change adds a pending-bytes accessor on `AsyncChannel`
   and an optional per-channel cap that closes the socket loudly when crossed.
   The repo already maintains forks of Datahike, konserve, and shadow-cljs, so
   this is in-idiom — but it means forking, repointing `dev.data-star.clojure/http-kit`'s
   transitive dep with `:override-deps`, and owning the fork.
3. *Do nothing.* Rejected: it makes the ruling's "bounded writes" false with no
   measurement behind it.

Recommendation: option 1 INSIDE N4 (the probe is a sealed acceptance item under
C6), option 2 as a named follow-on the measurement either justifies or
retires. Do not let it gate the rung.

**R2 — the admission hole is a containment defect, not an optimization.**
Until `seon.sci.eval` realizes deeply inside the armed interrupt, authored code
runs unbounded in the same JVM as the writer — strictly worse than under the
process split, because there is no longer a process wall. If N3 has not landed
admission when N4 starts, N4's FIRST commit is that fix. Do not build the
pipeline on top of it.

**R3 — attribute-only interest fan-out cannot be fixed in N4.**
`query-dependency-plan` returns per-source attribute sets and nothing else
(`reference-code/datahike/src/datahike/query.cljc:2877-2903`). Two agents' units
reading one attribute both wake. In-process this is cheaper than it was (no
serialization before suppression, no gzip per connection), but it is still
avoidable work. Keep issue
`attribute-only-feed-interest-recomputes-unrelated-agent-views` open; the fix is
a Datahike plan change (carry bound entity constraints), not a Seon change. §5.4
removes its worked example by deleting partial-text, which is a real reduction
in exposure.

**R4 — the wake callback is a shared-fate hazard.** §4.1 measured a listener
directly extending every transaction. One careless future edit inside that
callback degrades the whole writer. Mitigation is structural, not vigilance:
the callback closes over ONE channel and the contract test measures its wall
time (C4). Consider making the callback a `defn` in `registration` with no
access to the connection at all, so a blocking call is not expressible.

**R5 — flow topology is static; the fan-out owner is a hand-built component.**
Real but bounded: `src/seon/flow.clj:645-714` already does this and is tested.
The risk is a lane inventing a second pattern; the spec must name that
precedent as the shape to follow.

**R6 — "one authored evaluation for 32 tabs" is only true while the
registration lives.** With demand-scoped release (§11's row 2), a full
disconnect/reconnect cycle re-renders once. That is the ruling's intent and the
falsifier as written measures simultaneity, not reconnect. State it in the
contract so nobody later reads the falsifier as promising zero-evaluation
reconnect — that promise died with the stored snapshot.

## 13. Falsifier and acceptance

The rung's falsifier (`plan/README.md:746`), made executable:

1. **32 tabs → one authored evaluation.** Boot a throwaway cluster, pin one
   authored canvas, open 32 real SSE connections, commit one matching datom.
   Assert: registration evaluation count `= 1`; all 32 sockets receive one
   `datastar-patch-elements` event with identical bytes; the cluster stays
   healthy. Reuse the prior audit's harness shape
   (`bench/jvm_render_design_mockup.clj`, conditions at
   `jvm-render-design-2026-07-26.md:498-521`) against the real nucleus.
2. **The loop canvas costs one bounded eval and the agent learns why.** Pin
   `(loop [] (recur))`. Assert: one evaluation, terminating at the configured
   time limit; all tabs receive the error view; a flat `:seon.error` value
   carries `fn-entries`/`duration-ms`/`outcome`; the next agent turn's prompt
   contains the derived spin-versus-blocked sentence; the JVM serves a
   subsequent request normally.
3. **Suppression is real.** Commit N unrelated datoms matching the interest but
   not changing the projections: zero events reach any tab; the suppressed
   counter equals N.
4. **Reconnect = repaint.** Close all tabs, reopen one: it receives the current
   view unconditionally, with no torn or partial morph.
5. **Slow reader isolation + the R1 measurement.** One paused-read tab, 31
   healthy: the healthy tabs' latency is unaffected; record the paused tab's
   http-kit heap growth per morph as the R1 number.
6. **The wake never taxes the writer** (C4): transaction p50/p95 with the
   render pipeline running and 32 tabs connected is indistinguishable from the
   same workload with it stopped.

Rung-review metrics (`plan/README.md:555-572`): blocks compose — N5 uses only
`seon.render`'s public contract; the data model tightens — N4 registers ZERO new
attributes and DELETES `:seon.ai.attempt/partial-text` plus two config dials;
the codebase shrinks — report nucleus lines added against `src-old` lines
retired per §8.

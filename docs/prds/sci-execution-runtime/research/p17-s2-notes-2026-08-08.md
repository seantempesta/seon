the blocker issue, the P17 slice plan, the whole of

## The premise S1 handed over was false, and it was the whole blocker

S1's "The finding S2 most needs" says the hook fires only for a
`sci.lang.Var` callee and then reassures: *"Production is FINE:
`seon.sci.eval/forwarding-host-var` installs every loaded first-party
function as `sci/new-var`."*

It does not. `bind-first-party-namespaces!`
(`src/seon/sci/eval.clj:944-955`) wraps a host Var in a forwarder **only when
some namespace row REFERS that symbol**; every other first-party function is
installed as its raw `clojure.lang.Var`. Measured on an acquired cluster
context:

| callee | class | `sci.impl.utils/var?` |
|---|---|---|
| `seon.cluster/ensure-entity!` | `clojure.lang.Var` | false |
| `seon.db/pull` | `clojure.lang.Var` | false |
| `my.message/send` | `clojure.lang.Var` | false |
| `clojure.core/map` | `sci.lang.Var` | true |

So even with the state installed and a correct plan compiled, the arc's
`ensure-entity!` call still failed with the identical
`Wrong number of args (2)`. **Installing the state was necessary and not
sufficient**; the second half of the blocker was structural and invisible to
S1's probe precisely because that probe bound forwarders the way production
does not.

The class: *a binding path that hands sci a bare host Var silently opts that
function out of call preparation, and the symptom is indistinguishable from
the hook not being installed.* Killed at the fork, where the branch lives —
`identity-bearing-var?` accepts either kind, since both carry the `:ns`/`:name`
identity a hook keys on. `reference-code/sci` branch `seon-env-hook`,
commit `6ee57c9`, with `host-var-callee-is-prepared-test` beside the existing
hook tests. Fork gate: **394 tests / 1472 assertions, 0 failures** (baseline at
`f934044` was 393/1470). The superproject pin IS bumped in this lane's commit,
because first-party source now requires it.

The Seon-side mirror of the same lesson: `probe-ctx` in
`test/seon/call_preparation_test.clj` now binds **raw** `#'var`s. Binding
forwarders there would make every assertion pass while every real first-party
call stayed unprepared.

### Derivation is now ruling 2's model, not the draft's

S1 shipped the r2 draft's omitted-subset combinatorics
(`subsets-of-size` over every subset of the slots), which ruling 2
**overrules**. Each fixed arity now derives AT MOST ONE shorter shape: the
arity minus ALL its suppliable slots. A three-argument arity with two slots
answers for counts 3 and 1; count 2 — a single-slot omission — is deliberately
not a call shape, because nothing says which slot was meant.

### The predicate dispatch is the row's own schema, not a hand-written one

Where a declared arity and a derived shape land on the same supplied count
(the `pull` shape), the collision is settled at call time by the **leading
omitted slot's declared value schema**, already compiled per acquisition into
`:seon.call-preparation/validators`. That is Datahike's `db?`/`connection?`
reached through the declaration rather than a second predicate table, so
ruling #41's leave-off-the-database shortcut survives the general planner with
no per-function knowledge anywhere. Only a LEADING omitted slot is decidable —
the ruling says "the predicate on the first argument" — and every other
collision falls through to the declared arity, which always wins.

### The hot-path gate

The hook is armed on every call in the cluster, so the empty-plan path is the
one that decides whether the seam is affordable. Without a gate, `plan` ran an
aggregating Datalog query for **every** callee including `clojure.core/+`,
because a nil plan was never cached. The snapshot therefore carries
`:seon.call-preparation/prepared-symbols`, derived by the same query set the
plan is compiled from, at the same basis. A callee absent from it returns after
one set lookup. The set is a conservative SUPERSET by construction (a required
key whose value shape matches while its keyword does not): over-including costs
one cached empty plan, under-including would silently skip preparation.

Second fence: the per-identity contract transaction is re-read **at most once
per basis**, not once per call. A redefinition necessarily commits, so a
database value already verified against cannot hide a newer contract.

### The mandatory empty-plan benchmark

Script: [`p17-s2-probes/empty_plan_hot_path.clj`](p17-s2-probes/empty_plan_hot_path.clj)
(the command is in its docstring). 2M iterations per site after a 200k warmup,
results consumed; one session, one fixture database, three raw host-Var callee
sites; 117 identities in the gate.

| site | ns/call |
|---|---|
| baseline — no hook on the context | 17 |
| **empty-plan — hook installed, callee not in the gate** | **243** |
| prepared — one positional slot supplied | 606 |

Component breakdown, measured separately (`tmp/p17s2_breakdown.clj`), calling
the hook directly with no sci node around it — **156 ns total**:

| component | ns |
|---|---|
| `env/of` | 10 |
| `seon.db/db` (connection deref) | 33 |
| snapshot basis comparison | 30 |
| `callee-identity` (Var meta → `:seon.fn/sym` string) | 52 |
| whole hook, empty plan | 156 |

Read the ordering, not the absolute values (sibling lanes were loading the
machine). Two honest observations:

1. The ~87 ns between the direct 156 and the embedded 243 is sci's own
   hook-consultation node — W3 measured 115 ns for a **no-op** hook on a loaded
   machine, so our real gated hook costs about what consulting any hook costs.
   That is ruling 8's premise holding.
2. `callee-identity` at 52 ns is a third of the hook's own work, all of it
   `meta` plus a string concat per call. A per-Var identity memo would remove
   most of it. NOT done here: it is a new cache with its own staleness
   question, for ~50 ns, and ruling 8 says simple hook form. Recorded as a
   priced option, not a defect.

### The live proof — the arc's exact failing call

Own operator root `tmp/p17-s2`, own cluster forked from a fresh
`current-src` publication (commit `6a770e04-…`, digest `892e22f7…`), the
shared `default` root untouched and read-only throughout. Driven through
`eval_clj` in DOOR mode, which evaluates against the cluster's live shared
SCI ctx — the same seam the issue used to reproduce the failure.

```clojure
(seon.cluster/ensure-entity! "91331-1786187358712"
  {:seon.cluster.agent/id "inventory"
   :seon.ns/name 'arc.inventory
   :seon.cluster/name "s3"})
```

Before this slice, on the shared cluster, verbatim:
`Wrong number of args (2) passed to: seon.cluster/ensure-entity!`

After, on `s3`:

```clojure
{:seon.cluster.agent/id "inventory", :seon.ns/name arc.inventory,
 :seon.cluster/name "s3", :seon.cluster.run/id "bootstrap:inventory"}
```

and the agent is committed —
`(seon.db/q '[:find [?id ...] :where [?a :seon.cluster.agent/id ?id]])`
returns `["inventory" "root"]`. **The first production call preparation.**
The two-argument call carried no connection; the plan inserted it at index 0
from the environment riding the ctx.

## A second defect the unblocking exposed

With preparation working, `ensure-entity!` got past the arity and failed
INSIDE its body:

```text
seon.db/pull violated its contract (invalid-input):
  {:value nil, :message "must be an immutable Datahike database value"}
```

Root cause, confirmed by probe: **`seon.db/transact!` returns a different
SHAPE depending on a dynamic var** (`src/seon/db.clj:1199-1205`) — Datahike's
exact report to a system caller, and the agent-facing projection whenever
`seon.db/*conn*` is bound. That projection carries `:tx`, `:datahike/commit-id`,
`:seon.db/datom-count`, `:tx-data` and `:tempids`, and **no `:db-after`**.
`ensure-entity!` read `(:db-after transaction-result)`, so it worked at boot
and handed `nil` to `pull` the moment an agent called it. Nothing could observe
that until call preparation made the call reachable at all.

Fixed at the caller: read the database back from the connection, whose current
value is at or after the commit just made. The CLASS — a return shape
conditioned on a dynamic var — is the same shape ruling 2 is deleting
everywhere else, and it has at least one more latent site
(`src/seon/cluster.clj:1978` treats `(:db-after result)` as "committed?", which
is false for every agent-side call). Filed as its own issue; it is S4/seon.db
territory, not this slice's owner.

## Ugly output observed (standing order)

1. **The declaration-population fallback wall is worse, not better.** A single
   `eval_clj` door probe emitted `DECLARATION POPULATION FALLBACK ×10` twice
   before its result; `bin/test` interleaves the same lines into test output;
   one test emitted `×100`. Every lane keeps reporting this. It is now loud
   enough to bury a real signal, which is the exact failure mode the
   diagnostics rule names.
2. **A contract violation's rendered face prints its problems TWICE** — once
   as `:seon.error/message` prose and again as `:seon.instrument/problems`, a
   fully expanded `#:seon.print{:face ...}` tree with `:items`, `:entries` and
   nested `:face` maps for what amounts to two short sentences. The expanded
   tree was roughly 8× the size of the message it restated, and it is the part
   an agent must read past to reach `:seon.instrument/args`.
3. **`:seon.instrument/args "[nil]"`** on a three-argument call. Whatever it
   means, it is not the arguments, and it sent this lane looking for a
   one-argument `pull` that does not exist. An args rendering that drops
   arguments is worse than none.
4. `clojure.test/report is not a multimethod, some reporting functions have
   been disabled.` printed mid-suite by `bin/test` — noise with no owner named
   and no action implied.

## Token observations

No explosion. A compiled plan for a three-arity function is a few hundred
bytes; the snapshot holds two rows plus the gate, and the gate is 117 short
strings (~4 KB) on a full cluster — held once per cluster, never rendered.
The `:seon.print` expansion in observation 2 above is the only place this
lane saw an agent-visible value cost more tokens than its content.

## Deliberately not done

- The **variadic rest tail** stays indexed and never auto-filled: a variadic
  arity derives no shorter shape, so an elided call reaches the callee's own
  arity error rather than a typed refusal. r2 asks for an explicit
  unsupported value there; it is not in this slice's acceptance subset and
  needs its own face.
- A ctx with an environment but **no connection** passes arguments through
  untouched rather than returning the unavailable face, because with no
  custody there is no cluster to plan against. r2 anticipates this ("a healthy
  agent cluster necessarily has database custody") and the unavailable face is
  proved through a supplier that cannot produce.
- The `seon.db` bespoke-elision deletion and the current-reader sweep are S4.
- `(doc f)` rendering derived call shapes is S3.

# Repository rot audit — 2026-08-02

## Verdict

The fresh runtime is substantially cleaner than its surrounding reader
closure. Default and `:test` classpaths do not contain `src-old/` or
`test-old/`, and fresh `src/`, `test/`, and `script/` do not require quarry
namespaces. The dangerous rot is transitive:

- active-looking build, benchmark, evaluation, and documentation readers
  still make deleted pod/CLJS/writer mechanisms look live;
- high-trust architecture, reference, AGENTS, and skill authorities teach
  facts the current runtime has overturned;
- tests and schema rows manufacture readers for prototype or deleted fresh
  mechanisms; and
- the open-issue ledger itself retained resolved problems and stale
  destinations after a large landing night.

The highest-risk fresh defect is not documentary: production store/export
cleanup and several tests reintroduced the exact `file-seq` recursive-delete
shape that followed symlinks and deleted 55 tracked paths on 2026-07-29.

This audit changed no production source, schema, config, skill, architecture,
or reference file. Its authored changes are issue notes, issue lifecycle/index
triage, and this report. Concurrent fix waves changed some cited doc/skill
owners while the audit ran; those files were frozen out of re-audit until
their commits settled.

## Surviving reader chains

### Root Shadow/CLJS closure — whole chain is rot

The chain is:

```text
active extra-source and third-party docs
  → examples/third-party-override
  → deps.edn :cljs
  → shadow-cljs.edn pod/self-host builds
  → externs/node_fs.js + deleted CLJS namespace roots
  → Inspect source-admission lock/tests and ACME composition
```

The apparent readers do not make the build live. The docs teach a disabled
runtime, the example requires old-only `seon.demo`, Shadow names deleted build
roots, and Inspect pins paths rather than executing a successful fresh build.
Delete outer instructions/admission rows first, then example/config/alias and
externs in the same cut wave.

### `package.json` — split verdict

`bin/css` is genuinely live. It invokes `@tailwindcss/cli`; `input.css` reads
Tailwind and the typography plugin, scans fresh source, and the current render
work uses the result. Preserve a reproducible CSS install/build.

The `client:*` scripts, Shadow, fake IndexedDB, websocket, browser/pod, and
Node SDK dependency closure have no fresh runtime reader. A live CSS command
is not a reason to retain the pod's entire package graph.

### Inspect container entrypoint — whole chain is rot

```text
Inspect TB/TB2/SWE-bench catalog and adapters
  → inject /seon-entrypoint and mock readiness/door behavior
  → docker/seon-entrypoint
  → old-only seon.db.server + deleted out/client/main.js
  → writer socket, config/system.edn, grants, /agents/run
```

No recurring gate boots this against fresh `src/`. Replace only genuinely
needed benchmark arms with the current artifact/operator and a real turn
proof; otherwise delete from the outside inward.

### Parser/oracle chain — whole chain is rot

```text
Diffusion + Inspect scorers + ACME gym + segmenter docs
  → bin/oracle-server / bin/test-parser
  → old-only seon.repl.parse[-test] + seon.diffusion.grammar
  → missing worker-oracle-eval self-host bundle
```

Both root tools fail before work. Current reply reading belongs to
`seon.sci.reader`; consumer-specific diffusion evaluation belongs downstream.

### Writer artifact — distinct old JVM closure

```text
third-party setup + build tasks
  → deps :writer/:host/:writer-test
  → src-old + test-old
  → seon.db.server / seon.host / seon.web.server
  → AOT/AppCDS/DatabaseServerMain uberjar
```

This closure remains executable independently of Shadow and therefore needs a
separate cut. Fresh operator strings naming the old processes are detection-
only readers used to report/reap old deployments; they do not load the old
namespaces.

## Fresh source, schema, and config

### Dead source closures

The static-render cutover left `seon.render.root`, `seon.oversight`, four
unselected static functions in `seon.render.agent`, and two stale helpers in
`seon.context` with only test/CSS/comment readers. The 20 ms oversight defect
filed by the concurrent quality sweep was superseded: repairing timing in a
namespace with no production/schema reader would preserve a dead mechanism.

The tail of `seon.flow` is a second coherent dead closure. Its own docstrings
say fake/prototype/fixture/simulated; tests and schema rows keep it green, while
real agents execute through per-agent graphs. `capacity-observer-proc`, the
work launcher, fault committer, and fan-out are genuinely live and outside the
cut.

`seon.cluster.export` is different: it is complete and tested, but unattached.
The operator exposes no command and no production namespace calls it. The
decision is binary—attach one observed operator capability or delete it—not
"keep tested code around."

### Schema reachability

The five readerless rows are:

- `:seon.cluster.loop/evaluation` — superseded by
  `:seon.sci.eval/evaluation`;
- `:seon.render.data/window` — superseded by
  `:seon.render.value/window`;
- `:seon.render.block/band` — its contribution reader was deleted;
- `:seon.render/literal` — the runtime predicate owns the concept directly;
- `:seon.flow/future` — generator-only, with no requesting contract.

The sweep deliberately retained schemas a text-only search would falsely call
dead: program AST/arity and test-result entity maps, agent context-link
families, database-attribute maps, and dynamically derived AI wire settings.

### Config calibration

All 40 shipped/default dials are admitted and have current consumers. The
failure is the third authority in tests: two live dials were added without
updating `application-ledger`/`applied`.

A separate live reader chain survived the lease deletion:
`test/seon/ai_test.clj:187-193` asserts the shipped retry schedule is below a
60-second "RUN LEASE," and `config/default.edn:232-240` repeats the 60-second
deadline rationale. Run leases are deleted and the same manifest ships a
180,000 ms provider deadline. The retry values may be reasonable; their named
authority and regression are not.

### `seon.render.value` supplied lead

The `seon.schema` require is not unused on the JVM:
`node-id` calls `schema/sha-256`. It is unused only on the CLJS branch because
the require is unconditional while the call is reader-conditional. The honest
cleanup is a CLJ-only require, not deletion of the live digest owner.

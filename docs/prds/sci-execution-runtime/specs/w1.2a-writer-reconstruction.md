## Goal

`bin/seon config apply <path>` detects boot-critical changes and
replaces the JVM writer seamlessly: operator-supervised stop/relaunch
(`clean-or-force!` → `ensure!`), a NARROW pod pause (not the
destructive quiesce), automatic pod session/listener recovery, and a
post-apply equality proof. Scope: the two currently ENFORCED keys —
`:seon.config.database.writer/jvm-heap-mb`,
`:seon.config.database.executor/selected-processors`. Changed keys
still marked `:carried` DECLINE reconstruction with a steering error
naming W1.5 (reject-with-error-value, never silently proceed). W1.5
then adds enforcement surfaces; W1.2b graduates all keys.

## Design decisions (settled; stop and report if source contradicts them)

1. **Immutable generation-named envelopes.** `select-manifest` writes
   `launch-envelope-<generation>.edn` and never overwrites the launched
   envelope (today it clobbers `launch-envelope.edn` pre-diff —
   `script/seon/dev/config.clj:177-185`). The process record already
   pins its exact envelope path (`tmp/seon-operator/processes/writer.edn`)
   — the diff is loaded-generation envelope vs candidate, per-key over
   `config.resolve/operational-keys` (the `envelope-divergences` shape,
   `src/seon/config/resolve.cljc:1072-1083`). Keep a stable-named
   pointer (symlink or copy) only if something reads the fixed path
   today — check and report.
2. **Single resolution, typed handoff.** The operator resolves ONCE
   under the stack lock (today resolution happens before the lock —
   `script/seon/dev/cli.clj:373-379` — fix that) and the apply POST
   carries the resolved values: manifest + envelope + generation as one
   typed payload (schema'd). The pod STOPS re-reading Aero on apply
   (`src/seon/web/serve.cljs:497-520`, `src/seon/config.cljs:704-735`
   rewire to consume the payload). This kills the divergent-hardware
   bug (operator observes real FD limit; pod hardcodes 1024 —
   `src/seon/config.cljs:658-665`).
3. **Narrow writer-replacement phase, strengthened in place.** The pod
   runtime lifecycle (`seon.client`) gains a writer-replacement phase:
   close EXECUTABLE admission + drain admitted agent work (reuse the
   quiesce machinery's drain — `src/seon/client.cljs:2512-2575` — but
   do NOT stop the sci host, do NOT detach projection, do NOT close
   runtime ownership), then after the replacement writer is ready the
   pod reopens its database session through the EXISTING reconnect
   machinery (`src/seon/db.cljs:495-592` — reconnect, listener
   restore, resynchronization; strengthen, never duplicate), runs the
   launch equality proof (`prove-launch-configuration!` — currently
   only at startup, `src/seon/client.cljs:2125-2138`), and reopens
   admission. This is ONE phase inside the existing lifecycle owner —
   not a second lifecycle path. If listener restoration fails,
   readiness fails loudly (steering error), not silently.
4. **Route admission.** The apply/replacement control route must
   remain reachable while executable admission is closed
   (`src/seon/web/router.cljs:273-284`) — an operator-control route
   class, not a blanket exemption; follow the router's existing
   route-class vocabulary.
5. **Operator owns the sequence**: lock → resolve → diff → if
   boot-critical: pod enter-replacement-phase → `clean-or-force!` stop
   of `writer-id` only (`script/seon/dev/process.clj:1816-1844`) →
   `ensure!` new spec (`:2094-2122`, new `-Xmx` from the new envelope)
   → readiness (port file + connectable socket, `:648-656`) → pod
   resume + equality proof → publish applied manifest ONLY after the
   proof succeeds. Non-boot-critical changes keep today's fact
   reconciliation path unchanged.
6. **Fix the selected-processors override**:
   `resolve-operational-values` must consult a manifest override for
   selected processors instead of always taking observed hardware
   (`src/seon/config/resolve.cljc:865-870`) — clamp to observed cores,
   reject nonsense with a steering error.
7. **The sci host is untouched**: its pool discards dead members and
   lazily reconnects to the replacement socket (W0.4 behavior —
   `src/seon/host/context.clj:319-364,386-440,463-481`). Do not add a
   host-side notification mechanism in this unit; in-flight host DB
   calls during the window settle as the pool's existing bounded
   errors/retries. Same-request-id write recovery across the swap is
   the durable guarantee (`src/seon/db/writer.clj:1287-1454`).

GOAL — `writer-call!` dispatches over a small retained pool instead of one
locked channel; a slow or deadlined call no longer blocks every other host
database round-trip:
1. Pool members are retained physical connections opened on demand up to the
   pool cap, each performing the existing ensure-database + resolve-head
   handshake on open (both idempotent; the exact calls context.clj already
   makes). Keep the session an ordinary map + process-local atoms — this is
   genuinely process-local state.
2. One in-flight call per member. A caller takes a free member or waits
   bounded; on wait-timeout return a steering `:seon/error` value naming the
   pool state — never throw into the agent loop, never queue unbounded.
3. Per-call deadline: on deadline expiry, close THAT member only and replace
   it with a fresh connect+handshake. Deadlined WRITE requests are retried
   once with the SAME request-id through another member (probe §2b proves
   exact-once recovery); deadlined reads return a steering error value.
4. Pool size default = the executor's own derivation `(max 1 (dec
   processors))`, bound to ONE named var whose docstring marks it for the W1
   config-fact relocation (same pattern W0.5 used for writer defaults). No
   bare numeric literals; the wait-timeout and per-call deadline defaults get
   the same named-var + W1-note treatment.
5. First-call EOF on a fresh member = at-capacity steering error (grounding
   3), distinct from the reconnect-once path for a stale retained channel.
6. Interests: the host registers NO listen interests today — do not build
   re-registration machinery; leave one comment noting the recipe's rule
   (pin interests to a designated member) for whoever adds listen.
7. `close-session!` closes every member. No second session/pool mechanism:
   strengthen `writer-session` in place; every existing `writer-call!` caller
   keeps working unchanged.

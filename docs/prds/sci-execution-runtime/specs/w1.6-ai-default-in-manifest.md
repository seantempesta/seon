# W1.6 — the cluster-default model selection is manifest-declared

## Goal (owner-identified gap, 2026-07-22)

The `:seon.ai/config` row (cluster default provider/model/base-url/
api-key-env/thinking — the NON-SECRET selection) is seeded from
`SEON_AI_PROVIDER`/`SEON_AI_MODEL` env at first boot and changed only
by live transacts; the manifest never declares it, though it DOES
declare `:seon.config/model-variants`. Result: the cluster default is
database archaeology, invisible to `config apply`, drifts silently
(it drifted to Muse; today it was live-switched back to DeepSeek),
and a cluster reset re-seeds from env rather than declared intent.
This violates the standing config rulings (one explicitly selected
manifest reconciles its declared subset into facts; runtime reads the
database, never env).

1. **Admit the cluster-default AI selection into the manifest** as a
   declared section (follow the manifest's existing shape vocabulary —
   read how model-variants declare the same fields; one obvious home
   is a sibling of `:seon.config/model-variants`). Secrets stay out:
   `api-key-env` names an env var, never a key value.
2. **Reconcile it** through the SAME `seon.runtime.state/reconcile!`
   path the config singleton/routes/skills already use (one
   mechanism): declared → the `:seon.ai/config` row upserts; absent
   declaration = no reconciliation (the standard absent-key semantics
   — existing databases keep their facts; this is not a shim, it is
   the config contract). `config apply` with a declared selection
   repairs drift and writes nothing when converged.
3. **Declare DeepSeek in `config/system.edn`** (provider :deepseek,
   model "deepseek-chat", base-url https://api.deepseek.com,
   api-key-env DEEPSEEK_API_KEY) so the default cluster's intent is
   finally written down.
4. **Env seeding**: with the manifest declaring, the env-var first-boot
   seeding path becomes reachable only for manifests that stay silent.
   Do not delete it in this unit (other manifests/acme may rely on
   it) — but make the resolution order explicit and documented in the
   owning docstring: declared manifest value > existing database fact >
   env first-boot seed. Report where the env path is still load-bearing
   so its retirement can be queued honestly.

## Falsifiers

- Fresh-context reconcile: applying system.edn onto a database whose
  row differs (e.g. Muse) repairs it to the declared DeepSeek;
  converged apply reports zero operations for the row.
- Absent declaration: a manifest without the section leaves an
  existing row untouched.
- Per-agent overlays and model-variants unaffected (they already
  work — prove no regression).

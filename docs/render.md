# Render: what a person or a model reads

Every view, the model's context included, is a render: the one value printer (`seon.print`), or a render function declared on the value's schema (``:seon.render/html``). A render answers hiccup, and the page and the model read the same hiccup, exactly as it was returned: there is no second face for the model (owner, 2026-10-26: "don't leave anything out I want the agent to understand problems with the rendering functions"). Nothing else shapes output, and nothing clips.

**It's like React, or Reagent.** A render is a component: a plain function of its props and its children, Reagent's form, `(fn [opts & children] result)` (owner, 2026-10-23: "It's all just functions and results"; 2026-10-26, the call shape: [components](#components)). A render of one value takes it as its one child, `(fn [opts v] result)`. Its props are optional: `:as`, the room it is shown in (`:inline`, one line in a chat stream or a table cell; `:block`, a full panel, the default; `:tile`, compact and live; `:row`, a row of a page's list), `:budget`, its tokens, and `:handle`, the form its cuts read the rest through. A component that does not care about a prop ignores it. Its result is hiccup, which the page shows and the model reads. A schema declares the component of its values (`{:seon.render/html sym}`), and ```seon.render/html``` finds it in O(1) by the value's schema (the producer's `:schema`, the value's metadata, an error map's type, or an identity attribute: `seon.render/schema-of`); a value with none takes the default component, the one printer (```seon.render/print-html```), which takes the same props and auto-renders: wherever a value inside the printed one has a render of its own, the printer shows that render in its place, one line (`seon.print/print-value`'s `:render`: a call of its render in the hiccup, the value in one line in the text), in its one pass (`seon.render-cost-test/the-printer-renders-nested-values-in-one-pass`: 19 contracted calls a nested value, linear). Inside hiccup, a vector headed by a function is a component call, as in Reagent: `[task-row {:as :inline} task]` is written as what `(task-row {:as :inline} task)` answers, itself expanded the same way, by the one serializer (`seon.web.html/html`); a keyword head is an HTML element. The render proc is the reconciliation, one level up: a page's parts (its units) render again only when their input value changed, and only the bytes that changed are sent (`seon.render-cost-test/render-calls-are-one-pass-over-their-nodes`: nested calls serialize in one pass, linear in their nodes).

## No clipping

A cut never drops silently. It says what it omitted and how to read the rest. Storage keeps the exact value (an error's message, a running form, a provider's HTTP body travel whole); renders budget it. There is no `clip`, no `subs` for display, no `take n` without its count, and no stylesheet clip (`text-overflow: ellipsis`, `line-clamp`, `overflow: hidden` on text): the render's budget is the clamp.


## Prose, and the one string cutter

Text is cut one way, inside a value or shown as itself: the printer's string cutter (`seon.print.select/break-at`) ends the shown part after a line break in its room's second half, else after a space in its final quarter, else at the room, and the cut says `…+N chars in M more lines` and the form that reads exactly the rest (`seon.print.emit/cut-words`). A string in a printed value reads `"its prefix"…+7279 chars in 88 more lines (subs result/h3 19523)`. A keyword or symbol longer than `:seon.config.render.agent/max-name` cuts the same way, its printed text read as `str`: `:nnn…+44 chars (subs (str result/h1) 257)`. Source text is code, not a string: its producer marks it (```seon.print/code```, plain data `{:seon.print/code text}` that a record stores and reads back as it is, recognized by ```seon.print.select/code?```: a form's `:form/src`, a red proof's `:source`, an assertion as written, a cited var's definition head), and the printer prints it verbatim at its place, comments and quotes as written, every later line indented to where it stands, so a map holding it still reads as Clojure (`:source (deftest f-test …)`); cut, its cut reads `(subs (:seon.print/code (get-in result/e3 [:source])) 1200)`. The printer never guesses code from a string's text (owner, 2026-10-25: agents should see Clojure as it is in files or the REPL). A cited var on the screen is its definition's head (```seon.reader/definition-head```: name, docstring, attribute map and arglist as written, the body `…)` with `(source sym)`), a cited namespace its `ns` head and its public names (```seon.docs/cited-code```), a var with no recorded source a `declare` with its arglists and doc as comments, and a cited task, wiki section or file its address and lead as `;;` prose, then the form that reads it whole (`(my.agent/help "docs/render.md#one-printer")`, a task's `(:seon.task/plan (seon.task/task (seon.agent/db) "ns/name"))`): all of it code, never a view map in the page. `seon.print/prose` shows text as itself (unquoted) under a token budget, sized as the printer sizes (`:seon.config.ai/chars-per-token-prior` characters a token, `seon.print.select/estimate`, the one sizer: the history budget and the scripted model's usage count with it too): whole when it fits, else that same cut; given a source form that answers the whole text, the cut names `(subs source offset)` (with `:one-line?`, the offset is still the source's). On the page, `seon.render.ui/prose` links the cut to the page that shows the whole, or carries the whole in the cut's title; a printed value's cut names its result handle (`result/h3 at its REPL`).

A cut is read as its text, where it stands: the printer answers no list of its cuts. Decided by blind scoring on production-shaped values (`notes/printer-eval/README.md`): Haiku readers answered every question about a cut value from the inline cut alone (100%, 60 answers), and ranked it first in 30 of 30 three-way comparisons against the same text with a closing "left out" list (repeats every cut, up to 2.9x the tokens) or with footnote markers; prose's cut words beat the bare `…+N` in 18 of 22 pairs (the unit and the line count tell a reader how much it is missing), and prose's break beat a cut at the last line end, which can spend most of the room on nothing (47 of 256 tokens shown in one case).


## A value on the page is its structure

The page draws a value from its data, the model reads it as text, and both come from one selection: `seon.print.emit`'s hiccup fold reads the same operation stream the layout reads, so the text is unchanged by what the page shows (owner, 2026-10-25: "We can do more complex representations of values there"). A map is a grid of key and value rows, folded as any collection is (a map of scalars, or the value printed, not at all). Two or more maps in a vector sharing two or more keys are a `<table>`, a column per key and a row per map (`seon.print.emit/table`). Text marked as itself is drawn as itself: code, `{:seon.print/code s}` (`seon.print/code`), verbatim in `<pre><code>` and highlighted as Clojure by highlight.js (served at `/highlight.js` from `:seon.config.web/public-dir`): one observer in the page's shell (`seon.render.ui/shell`) highlights each `code.language-clojure` (`seon.print.emit/highlight`) as it arrives and again when a patch morphs a row back to its plain text, so a per-element init, which a morph of unchanged attributes never re-runs, is not used; each mutation batch costs one scan of the page's code elements, and a screen eval opened under its turn carries the same `eval-eN` anchor; prose, `{:seon.print/prose s}`, a paragraph; both print verbatim and unquoted, and a cut of either reads its rest through its key, `(subs (:seon.print/prose (get-in result/e3 [:plan])) 1200)`. A page an agent built is the value's own `:seon.render/html` key, a render already made, and renders as that hiccup wherever the value sits (`seon.render/nested`). A handle, `result/e12`, links to its eval's row, whose id is `eval-e12`, open or not. In the conversation an eval is one collapsed line (`.seon-eval`, ```seon.render.ui/eval-item```, the 2026-10-24 mockup's `▸ (form) · 12 ms`): the prose beside it, its code's first line, its time and its handle, opening to the eval's own render (```seon.render.ui/evaluation```: its code and its value); the agents are a column beside it on a wide screen and a strip of chips above it on a narrow one; prose (a model's reply, a message) reads in the system's text face (`--font-prose`), code and data in mono. A cut opens where it stands: its marker is a button whose click posts `/open` with its row's id and the form the cut prints, `(drop 1 (get-in result/e157 [:value :proofs]))`, and the row renders what that form reads from the record (`seon.print/read-rest`, the operators continuations are made of), so the page shows a cut's rest as the model would read it, under that form as the button that closes it (a button, not a `<details>`: the row's re-render would close a details, whose toggle would post the close); the form is read once, at the edge (`seon.web/open-form`), and a row renders again only when its set of opened cuts changes (its component key). An evaluation's row renders its response's value this way, its cost and the functions it called beside it; a value not held as data (`:printed`) shows as it was printed. `seon.print-test/a-map-is-key-and-value-rows`, `maps-sharing-keys-are-a-table`, `code-and-prose-read-as-themselves`; `seon.render-test/an-eval-row-renders-its-value-as-structure`, `a-page-an-agent-built-renders-nested`.

## A render is a value, printed once

A view that chooses what to show makes a value, never text: an array map of what matters, in its order, and the one printer prints it once at the reader's budget. Nothing is cut before the printer: a long list is the printer's cut, which says what it left. Where a list's whole lives elsewhere, the value carries the form that reads it as data (`:all-in (seon.task/runs (deref (:conn sys)))`). It replaces the bounded lists (a list cut to a config key's first items with a `+N more` line, deleted with their keys) and the per-field budgets that cut each part before the printer (clipping audit, 2026-10-25).

A render's budget, when its env names none, is config too: `:seon.config.render/value-budget` for a value and `:seon.config.render/root-context-budget` for root's context (root's page's hiccup, printed by the render proc).
## The page

Every page is the render of a ctx through the one walk (```seon.render/walker```), laid out in root's chrome (```seon.render.ui/page-chrome```: the agents list, the head, the task's list, the conversation, the tiles), each placed component a unit whose input is its revision (owner, 2026-10-26: "There is only one context rendering system and it needs to be built from the parts"; 2026-10-25: the web UI finished from notes/archive/design-agent-view-2026-10-24.md §5 and the mockup of 4624f2f4f, not redesigned).

- **A location is a ctx.** `/` is root's: root's ctx (```seon.ctx/build``` of root's entity on main, advanced by ```seon.ctx/advance``` on each move of main) drawn by ```seon.render.ui/root-ctx``` (```seon.render.proc/root-walk```). `/agent/{id}` is the agent of that id in root's boot (its key, `seon.task/agent-key`: ids start again each boot), its own walk of its ctx. Any other location is a `:seon.render/no-location` (`seon.render.proc/location`).
- **Root's page** is the render of root's ctx: its agents list (root, then each agent its ctx holds), its head (```seon.render.ui/root```), its evals as collapsed lines, and its tiles: root's process (```seon.render.ui/process-tile```), main's open problems (`seon.problems/health`) and main's runs. Root's process (the writer's, the fork server's and the store's numbers, each proc's defects and the newest events, ```seon.render.proc/process-value```) is root's own data, part of root's ctx (`:process`) beside its db pull, never written (root's ruling, 2026-10-27): the render proc assocs it in when it changed and frames the walk, so only the tile that reads it runs again.
- **The input is at the top**: an agent's REPL, messages, interrupt and release (```seon.render.ui/agent-input```), root's spawn and evaluate-in-every-agent (```seon.render.ui/root-input```), each a UI call of root's request table ([dashboard](dashboard.md#callbacks-are-data)).
- **Two faces, one toggle.** The top bar toggles a page to what its model reads (owner, 2026-10-26). An agent's is `/agent/{id}/debug`, each turn's request as recorded (```seon.render.ui/sent-request```), each row a unit drawn when its input (its turn, whether it is open) changes; root has no model turn, so `/root/debug` is what root reads: its page's hiccup, printed once a pass by the render proc (its `:context`, the text `/context.txt` serves), drawn by ```seon.render.ui/root-context``` and never computed for the page (`seon.render-test/roots-context-is-its-debug-page`).
- **An agent's view is the render of its ctx, its components** ([components](#components)). render-ctx, the layout, the render `:seon.render/render-ctx` declares (```seon.render.ui/render-ctx```), reads ctx through a tracking view and places components in the page's three lists: the task's (the task, each var its plan cites, what is related, what its newest turn observed, the run, the keys the agent added), the conversation (its evals, the run's turns and messages, in the order each was written: the transaction of its identity datom, since some ids are content-derived) and the tiles (each eval whose value has a render of its own). The agent draws its own render, by its own renders, when root's render proc asks (```seon.repl/render-ctx```, the `:render` op, which first takes the facts main holds of its own entities, such as an eval a reader opened); root lays its components out with root's agents list beside them, so a component whose output changed is sent and a new one in its list is an append. An agent with no process is drawn by root from its branch with the same walk (```seon.render/draw```), the page saying so. `seon.render-test/a-page-is-its-components`, `a-new-member-is-an-append`, `a-handle-links-to-its-eval`; `seon.agent-test/a-parked-agent-draws-its-parts-and-a-gone-one-answers-at-once`.
- **Only what is on screen is rendered.** A page shows what its ctx holds, each collection its pattern's window (`:seon.config.ctx/window`, newest first). The debug page renders its newest `:seon.config.render.list/history` turns; its end (```seon.render.ui/more```) counts the older ones and, when it scrolls into view, posts `/more` (Datastar's `data-on-intersect`), and the render proc renders as many more (an event, never a poll).
## Components

A component is a call in hiccup, `[f opts & children]` (Reagent's form), of a render whose opts declare what it reads: `:seon.ctx/ctx`, ctx as a tracking view ([reactive renders](#reactive-renders)), or `:seon.db/db`, the branch's db, read under `d/with-reads`. The walk (```seon.render/render!```, ```seon.render/frame!```) fills those keys in, runs the render in its reaction, and draws its output with its root element's id its key (```seon.render/key-id```: its render's name and its children's keys, an entity's eid, a var's name). One cache holds each component's reaction, args, output and db reads, in the process whose page it is (the agent's walk, held in its state). A component runs again when its children are not `=` to last time's, when a change of ctx reaches a path it read, or when a transaction's datoms touch its db reads; otherwise it is skipped, and a run whose output is `=` to the last one's changes nothing. A frame drains the components a change queued in mount order, parents first, after the ratom flush: one frame a commit. Each component's runs are counted by its render's var (```seon.render/ledger```: ran with a new output, ran with the same, skipped, and the bytes its runs allocated). A call of a render that declares neither is not a component: it stays a call in the hiccup, the page's writer expands it and the model reads it as the call. A component whose render throws draws its error's render in its place, a `:seon.render/component-defect` (a [failure point](failure-points.md)); every other component draws. `seon.render-test/a-component-re-runs-on-what-it-read`; `seon.context-test/a-db-component-runs-again-on-what-it-read`, `a-cited-var-redefined-shows-in-the-next-view`, `the-task-draws-what-it-needs`; cost `seon.render-cost-test/a-change-costs-its-components`: a change draws its components, flat in the page (137 contracted calls, about 100 KB from 100 to 4,000 evals), beside ctx's diff, which walks every key of the collection it changed.

Each view renders on its own (```seon.render.proc/view-pass```, a [failure point](failure-points.md)): a view whose render throws is that error as its page, a `:seon.render/view-defect`, and every other view of the pass renders (`seon.render-test/a-view-that-throws-answers-its-page-with-the-error`).

## One rendering system, drawn from the data

There is one rendering system, and the data describes the page (owner, 2026-10-26: "There is only one context rendering system and it needs to be built from the parts"): an agent's record is a name chain, an agent has a conversation of turns, each turn holds the agent's prose and its evals, each eval has a response ([vocabulary](vocabulary.md)), and the page and the model's request are both renders of that record through ctx, whose [pull pattern](ctx.md#the-pattern) (`:seon.ctx/pattern`, data an agent edits by `swap!`) says which of it is drawn. Nothing about a page is stored beside the data it shows: what exists only when rendered, such as the functions a plan cites or the sections an embedding search relates, is a render that declares `:seon.db/db`, and the db ranges it read are what invalidate it. The screen, the page as the model reads it, ends what the model is sent each turn ([the model's context](#the-models-context-a-cached-prefix-then-the-turn)).

It is re-frame's model, which is Reagent's, which is React's memo, proven in production Clojure: one immutable value (`@ctx`) is the app-db, a transaction patches it, and a component is a pure function of its slice, run again only when its slice changed and passing nothing on when its output is `=` to before. Immutability makes "did my input change" a pointer check (`identical?` 1 µs; `=` on 1 MB 0.2 ms), so nothing is guessed and no render knows the data's shape. A render is a function and the data it renders, never a registered object: to make one cheaper, hand it a smaller slice, with nothing to invalidate by hand. The one addition is that the source is a database, not an atom, hence `d/with-reads` for renders that query. Measured on a live agent, a new eval rebuilt 2 entities in 0.23 ms and reused 19 of 22 render calls by identity, against 102 entities and 0 of 191 for a fresh build (28-35 ms); a patch's cost grows with the transaction, not with ctx.

## Reactive renders

A render reads ctx as Reagent's components read a ratom: ```seon.ratom``` is reagent.ratom ported (`RAtom`, `Reaction`, `run-in-reaction`, `flush!`, `dispose!`; Reagent's own tests, `seon.ratom-test`), with the cursor inferred (owner, 2026-10-26: "I'd rather infer the cursor than require it"). A render declaring `:seon.ctx/ctx` gets a tracking view of ctx: a map that delegates to the real value and records each path it looks up, a map's presence (shallow), a value read whole (deep), or a node iterated (its key set and direct values), as Vue 3's reactive proxy and MobX's observable map do. The printer and the page's writer take the real value (```seon.ratom/unwrap```, ```seon.ratom/realize```), each such read whole. A source read through views has one watch: its reset! (ctx's patch) runs its diff once (```seon.ctx/changes```) and reaches only the reactions whose read paths a changed path reaches, by index (```seon.ratom/source-changed```). Reagent's scheduler (requestAnimationFrame) is the commit on the server: the queued reactions run at a non-reactive deref and once a frame. `seon.ratom-test/inferred-paths`, `a-view-is-a-map`.

The frame is the one part with no value behind it: the document (`seon.web/page-doc`), its head and scripts (`seon.render.ui/shell`). It is fixed hiccup, the same on every page, served once with the page.

## Tailwind

The page is laid out by Tailwind's classes in each render's hiccup, responsive at every width, with no hand-written stylesheet (owner, 2026-10-23: "I want responsive html and css so why not tailwind?"). `resources/public/css/input.css` holds every directive, token and source glob (Tailwind v4, CSS-first, no config file): `source(none)` with an explicit `@source` over `src/**/*.clj` (automatic detection walked the reference-code tree: v1 measured 42 s against 1 s), the Phosphor theme's tokens (dark, light when the system asks), a base layer for semantic hiccup and the one printer's classes, and a safelist of the utilities an agent may use, since a render an agent defines at its REPL is in no scanned file: the common layout, spacing, type, list, border and theme-color utilities, responsive where layout is (117 KB, 16 KB gzipped; a rebuild on each agent render's classes was the alternative, priced and not taken). `bin/build css` (a step of `bin/build seon`, and so of the `:build` effect after merges) runs Tailwind's standalone binary, pinned by version and checksum and fetched once into `target/tailwind/`, into `target/css/app.css` (`:seon.config.web/stylesheet`, served at `/app.css` and read per request); its stamp is the digest of `input.css` and the scanned sources, so unchanged inputs regenerate nothing (68 ms when they changed, v1's port of its `bin/css`). Add a class to a render, or a token or safelist entry to `input.css`, and build: the stylesheet regenerates.

### Style

A component's root element carries one class, its render's name, and its render's var states its Tailwind classes; the page's html adds them, and what the model reads holds the name only (owner, 2026-10-26: "make it so the fully printed hiccup is compact and everything earns it's spot"; DECISIONS, compact hiccup). The walk gives each component's root its key as id and its render's name as class (``seon.render/render!``), in place of any class the render gave its root. A render states its style as `:seon.render/style` on its var, literal text in `src/` (so the `@source` scan above builds it), its descendants by Tailwind's arbitrary variants (`[&>h2]:uppercase`); render-ctx's components share a panel's and a tile's (``seon.render.ui/task-data``, ``seon.render.ui/eval-tile``). When a unit's html is written, ``seon.render/styled`` appends each drawn render's style to its root's class: the style of every render on the page, gathered by reference from the renders the walk drew, never spelled in the tree. Semantic classes a render uses inside (`seon-prose`, `muted`, `err`, the printer's own) stay, styled once in `input.css`. On a4's first page (15 components) the class text fell 355 -> 194 chars, 9,171 -> 9,094 tokens (`seon.ctx-test/a-component-is-styled-by-its-renders-name`).

## Tiles are data; the context reads the page's derivations

Each fact the page and root's context both show has one producer they share:
- **A lifecycle is declared once, on its enum's schema,** and read through one reader, `seon.contract/properties` (an enum's members, in order: `seon.contract/enum-values`):
  - `:seon.agent/status` carries its live, stopped and gone sets (`seon.root/gone-statuses`, read by root, the web, the server and the check harness; `seon.render.ui/live`);
  - `:seon.run/status` its finished, judged and failed sets, read once, by `seon.task` (`seon.task/finished`, `judged`, `failed`; with `seon.task/done?`, a task's done on a db, and `seon.task/running`, the running runs by one index seek), which the reconciler, problems, the render UI and the server require (`seon.main-test/a-runs-lifecycle-is-read-once`);
  - `:seon.task/state` a task's observed states with each state's meaning (its `:seon.status/title`, read with `seon.contract/properties`). A task's state is derived once, from the reconciler's index (`seon.reconcile/task-state`), which every reader of a task's state calls.

  A new status is one enum entry. Not this: a status set typed out at each site that asks.
- **How an agent is:** `seon.render.ui/shown-status` and `seon.render.ui/ended-as`; its newest events are the stream's own words (`seon.render.ui/event-detail`); a cost verdict's lines are `seon.cost/verdict-lines`. The writer, the fork server and main are root's process (```seon.render.proc/process-value```), drawn by ```seon.render.ui/process-tile```.
- **Runs, merges and evaluations:** a test run's words are `seon.render.ui/run-words` and its redness `seon.proofs/red?`; a merge is its run's end (`:seon.run/status` `:merged`, shown on its task's row); an evaluation is one render, ```seon.render.ui/evaluation```, for its entity, its record and a reply item.
- **Errors:** an error or failure shown reads `:seon.error/message` of the one error map ([errors](errors.md#errors)), never a second `{:error "text"}` shape.
- **Numbers:** root's view numbers (p50s, transactions per commit) are `seon.root/view-numbers`, read by `seon.root/state` and the render proc alike.
- One-line text in a row or the context is `seon.print/line`. A root function called from the page is recorded on main by the render proc when root answers it (origin `:ui`), with that answer ([dashboard](dashboard.md)).


## Health is what flows

Nothing is pinged and nothing runs on a beat. A render pass happens on an event, an api answer or a tab's request. What is wrong has one producer, what is recorded or derived from main's facts: root's page reads root's defects (its process tile) and main's open problems (`seon.problems/health`: [health](health.md)), never re-derive them from the live view; root records an agent's death (`seon.root/end-agent`), and a refused spawn, or a red test run or refused merge of an agent with no task (a task's run records its own), as it folds it into the agent's view (`seon.root/set-agent`). A value only a ping carried is its owner's to emit when it changes. `bin/check idle` proves an idle root with a tab open steps nothing, and that a spawn and a commit still reach the tab.


## The model's context: a cached prefix, then the turn

A model request sends what does not change first, so the provider serves it from its prefix cache, and sends nothing twice.

The request is a render of the agent's record (notes/archive/design-agent-view-2026-10-24.md §3, owner 2026-10-24): each record's part of the conversation is provider-neutral messages (an eval, ```seon.context/eval-messages```: its assistant message with the reply's prose, its reasoning as returned and the eval call, then its tool message, the response as printed; anyone else's eval, one user message; a message fact, ```seon.context/message-messages```), and ```seon.context/request``` composes the agent's request from them in one order; the one provider format function, ```seon.model/wire-messages```, turns it into the wire shape (a reply's calls folded into one assistant message; reasoning sent back unless `:seon.config.ai/replay-reasoning` is false, which a config with thinking on refuses at load):
1. **The help page** ([agent](agent.md)) as the system message: the same bytes for every agent and every turn (`seon.context/help-text`).
2. **The page, at each model turn** (```seon.context/world```): the agent's page as its model reads it, its task's list (```seon.context/page```, drawn by the walk: the task, each var its plan cites, related, its newest turn's status, the run; each component's hiccup exactly as its render returned it, by its element id), whole at the session's first turn and after that what changed of it since the turn before, `{:page {component-id hiccup} :ctx {path [old new]}}`: the components whose hiccup changed, by key, and ctx's diff (```seon.ctx/diff```), every path that changed. Each is re-derived from the branch at its turn's commit, so it is stored nowhere ([:page a c0 c1] in `:seon.turn/sent`), and it sits at its turn's place in the transcript, so every earlier one stays in the cached prefix.
3. **The conversation**, append-only: the run's records in tx order (```seon.context/records```: the agent's evals of the run, the user's among them, and the messages the run took), each by its own render, printed once when it is first sent and reused by its id after (```seon.context/printed-run```, kept in the agent's state per run: a record's message is a function of it and the records before it, which never change, so a turn prints only its new records and every older message is the same bytes, and the provider's cache holds; proof `seon.context-cost-test/a-turn-prints-its-new-records-flat-in-the-history`). Within `:seon.config.render/history-budget` (```seon.context/kept```) the newest records are whole, older ones collapsed (the result its handle and its value in one line, the record's `:line`; sent as `[:line id]`), the oldest left out and counted. The two cuts only advance: when what is sent passes the budget, the oldest whole records collapse until the whole ones fit in half of it, then, if all is still over half, the oldest collapsed are left out until it fits, so between those jumps each request is the one before and what was added; a cut never starts inside a reply. A cut recomputed each turn moved back and forth past the budget: a resumed run (35-39k tokens a request) shared only its first two parts, 962 tokens, on 22 of 28 turns, and the provider served 23% of 1.1M tokens from its cache.

A response is `{:handle :value :out :err :ex :ms :ticks :bytes}`, each key only when present (`seon.repl/response`): one per eval call, its forms run in order and stopped by the first exception, printed by the one printer under its handle, the var `e` plus the eval's id in the `result` namespace (`seon.print/response-text`), which holds it. Its record keeps the response whole, its value as data when it is plain data (```seon.db/plain?```, stored once under its content key when large), else the response as it printed then and the value's type (```seon.repl/record-details```); nothing printed for a reader is stored, so a record is the same whatever came before it. When the conversation sends it, a value or output an earlier record of the run showed prints as the form that reads it there (`(:value result/e12)`), and its ref names that fold (`[:eval id {:value result/e12}]`), so the debug page prints the same bytes from the record and the ref alone. An eval of code the run ran before, answered the same, prints whole with that one's handle beside it (`:same-as result/e12`, its ref `[:eval id {:same-as result/e12}]`, ```seon.context/printed-run```): the agent is told on the answer it reads that it asked again, where a fold showed it only the earlier one's form, and no count of repeats decides anything (the live runs of 2026-10-25: 9 of 39 repeats followed a folded answer, each to a record the request still sent whole). A reply with prose and no call ends the turn, and the run waits for the user (tool_choice auto: DeepSeek refuses `required` with thinking on).

So each request starts with the whole of the one before (`seon.context-test/the-request-is-a-conversation-of-evals-and-the-page`, `seon.context-test/the-prefix-stays-byte-identical-across-turns`), and the plan, its references and its sections go out once a request (`seon.context-test/each-section-is-sent-once-per-request`). Not this: the block sent twice a request, or a note that edits an earlier message, which breaks the prefix for every later turn. v1 measured the same split live: stable run sections of about 8.5k tokens, turn sections of about 0.75k, 85-91% cache hits. Measured through the server on three open tasks (printer estimate, `:seon.config.ai/chars-per-token-prior`): the help page is 2,132 tokens, the same for every agent; the run sections 1,639-1,887 (the references 2.1-2.4 KB); the turn sections 45-76 before any proof has run. A first request is 3.9k tokens, 54% of it shared by every agent; each later turn adds its scrollback and about 60 tokens of turn sections, so with 2k tokens of scrollback a turn sends about 2.1k uncached tokens and the cached prefix is 65% of the second request and 79% of the fourth. What the provider served from its cache is recorded on each turn (`:seon.turn/cache-hit-tokens`, `:seon.turn/cache-miss-tokens`, by `seon.turn/usage`), absent when it did not say.

DeepSeek's prefix cache ([its guide](https://api-docs.deepseek.com/guides/kv_cache)) serves a request only from a stored prefix unit it fully matches. Units are made at the end of each request's input and output, at prefixes several requests share (found lazily: the third request hits what two earlier ones shared), and at fixed intervals inside a long input; the cache is best effort, takes seconds to build, and is dropped hours to days after its last use. Since each request drops the one before's last message, the newest scrollback turn sits on no unit boundary and hits only through the shared-prefix units. Once the scrollback passes `:seon.config.render/history-budget`, the history cut (`seon.context/request`) drops the oldest kept record on every turn, so the message after the run sections changes each request and from then on the whole scrollback misses the cache.

A short cache hit is a problem. Each turn compares its request with the one before in its run (```seon.turn/cache-miss```): the leading messages both hold equal are the prefix the cache should serve, sized as the provider's own prompt count apportioned by the one sizer (```seon.context/messages-tokens```) and rounded down to the provider's block (`:seon.config.ai/cache-block-tokens`; DeepSeek's 128, measured: every recorded hit is a multiple of it). A hit more than one block short of that is a `:seon.turn/cache-miss` error the agent folds and sends with its next commit, counted under one signature in the `:eval` class (`seon.model-test/a-turn-whose-cache-misses-its-prefix-is-a-problem`). Measured 2026-10-25 on 100 turns of 6 runs: 75.6% of all prompt tokens hit the cache, 78.4% after each run's first turn; each hit was 0.87-1.12 of the prefix so sized, and none was short. Turn 1 shares only the system prompt and the task's data (turn 0's request after them is all screen, evaluated again each turn), so it hits about 900 tokens by design.

A reply cut at `:seon.config.ai/max-tokens` (`:seon.turn/finish` "length"; `seon.model/reply-of` keeps the cut text and the forgiving reader repairs it) is almost always a repetition loop, not long work. Over 370 deepseek-flash turns with thinking off and a 65,536-token bound, 66 (18%) ended "length" at 184k-415k characters, each repeating 2-47 distinct forms (typically one ``clojure.repl/source`` call 300+ times), every form evaluated (up to 4,206 in one turn); they spent 45% of all tokens and 168 of 181 model-minutes (median 151 s against 2 s for an ordinary turn). 18 of 33 first turns looped, so the loop is not only history fed back. The largest ordinary reply was 19,809 characters (about 5k tokens).

The field's evidence for this shape: SWE-agent (arXiv 2405.15793, SWE-bench Lite, 18.0% resolved) lost 3.0 points with full history instead of collapsing all but the last 5 observations, 5.3 with a whole-file viewer instead of 100 lines, 6.0 with iterative instead of summarized search and 1.7 with no demonstration, and its successes took a median of 12 steps against a mean of 21 for its failures. CodeAct (arXiv 2402.01030) found code as the one action up to 20% more successful in fewer turns; Seon's one `eval` tool is CodeAct ([model](model.md#one-tool-eval)). aider ranks a 1k-token map of symbols by references, and Manus calls the KV-cache hit rate the first metric and keeps its context append-only and deterministically serialized.


### The page is sent as what changed

The model reads its page as the person sees it (revision 4.2; the owner, 2026-10-26: "there are only two outputs too: @ctx returns data just like any repl eval and then we need to show the UI and the diffs to the ctx and the html at every turn as formal data"): whole at the session's first turn, then each turn what changed of it by component key, and ctx's diff at the paths no part draws. It replaced the screen, a set of forms evaluated before each request and recorded as evals (`(my.task/status)`, `(my.branch/changes)`, `(my.task/related)`), whose stored values were derived data and whose diff descended into a page's tiles. A cited var's edit is that var's part alone, and an unchanged page is `{}`.

Measured on a1 (the agent-view worktree's root, 2026-10-26): the page is 6,632 tokens over nine parts (the task 2,247, its four cited vars 2,869, related 822, proofs 314, verdict 206, run 107), drawn in 278 ms cold and 14 ms through the agent's memo; a cited var's redefinition changed two parts (that var's and related, whose call graph it moved), 1,283 tokens of diff; one turn's ctx diff touched five paths (the turn's four evals and the agent's counter), all told elsewhere, so its `[ctx]` is empty. The screen it replaced was 1,135-1,340 tokens at turn 0 and 363-1,208 as diffs (live-agents, 2026-10-25).

## How a value is printed

A value is printed in two passes, selection under one token budget and then layout, so its text and its hiccup come from one selection and every cut names the form that reads the rest.

```seon.print/print-value``` is the one entry: a value, a handle the cuts read through (``result/h3``, or a form), a budget in tokens (```seon.print/budgets```: a reply's, a part's, a form's and the context's, each a `:seon.config.render*` key), a depth and a width. ```seon.print.select/show``` selects: it allots the budget breadth before depth (every child of a collection shows before any one deepens), identity keys first, and builds a print-node tree whose cut nodes carry their continuation forms; a value whose metadata holds ``:seon.print/full`` prints whole, and ``:seon.print/budget`` raises its own budget. Rows are the exception to breadth: a collection whose members are rows (```seon.print.select/row-class```: maps, vectors or sets of one class, a sequence's strings, a map's values under keys that are not keywords) shows each whole in its order while it fits, then one cut that counts the rest and reads them (`…144 (drop 33 (get-in result/e1 [:value :classes :stale-section :rows]))`); a row at its least is a cut that shows nothing, so breadth over 177 of them printed 144 lines of `{…13 (get-in ..)}` (```seon.print.select/fill-rows```; `seon.print-test/rows-show-whole-then-one-cut`; no row past the cut is read, `seon.print-cost-test/printing-rows-costs-what-it-shows`). A keyword-keyed map is one record's attributes and keeps breadth. Members indent one column inside their opener at every depth (a flush deeper level read as its parent's); a namespace-lifted map's and an `#error`'s still indent from the group, not past `#:ns{` (task `seon.print/a-prefixed-collection-indents-its-members-past-its-opener`). ```seon.print.emit/emit-both``` lays the tree out as fipp does (begin, end, nest, line, text over one operation stream) and answers the text, and the hiccup the page's value panel shows when asked; fipp itself is only the layout's test oracle (`seon.print-test/the-layout-is-fipps`). Printing through fipp cost 45.4 KB and 16-17 µs per entry of a flat map, the printer 2.41 KB and 1.8 µs. Not this: Jolt's `clojure.pprint`, which would give that back. ```seon.print.select/estimate``` is the one sizer of tokens. `seon.print/text` (the printed text, or the error's message when even the first part does not fit), `seon.print/line` and `seon.print/prose` are the printer at a budget for text, a row and prose ([Prose](#prose-and-the-one-string-cutter), [A render is a value](#a-render-is-a-value-printed-once)).

## One printer

There is one value printer, `seon.print`, and nothing is cut before it. A value a person or a model reads is its schema's declared render (`seon.render`) or the printer's text; a value that is not text reaching the page's serializer (`seon.web.html/html`), a one-line row (`seon.print/line`) or prose (`seon.render.ui/prose`) is printed by the printer, never `str`. The REPL answers every value by the printer, as the data it is; an error map is printed whole (its message, fix, variant and where; Jolt's diagnostics are keys of the map, printed once, [errors](errors.md#an-eval-errors-diagnostics)), and the page draws it by its declared render. An evaluation on the page (`seon.render.ui/evaluation`) is its recorded value drawn from its data, the printer's hiccup under its handle ([A value on the page](#a-value-on-the-page-is-its-structure)); shown inline it is its record printed as its reply reads, so its cut is the printer's (whole rows, the form that reads the rest), never its reply's text cut again as prose; an MCP answer that root's REPL can answer again (an op's `:again` form in `seon.server/ops`, `seon_agents`) is printed under the reply budget with that form as its handle, not whole.

`seon.render-test/one-printer-and-no-cut-before-it` reads the compiler's facts (`:form/refs` of src imported, `seon.program/live-forms`; each var's form, and each method's): every var outside `seon.print` that references `pr-str`, `prn-str`, `print-str`, `with-out-str`, `pr`, `prn`, `printf` or `clojure.pprint`'s `pprint`, `pp`, `write` or `cl-format` is named below; every var of a display namespace (`my.*`, `seon.render.*`, `seon.web*`, `seon.context`, `seon.server`, `seon.cost`, `seon.repl`, `seon.agent`, `seon.problems`) that references `subs`, `take`, `take-last` or `drop-last` is named below; and every var outside them that calls the printer with a budget (`seon.print/text`, `line`, `prose`: a cut where a value is made) is named below. An unnamed one is red, and so is a name here that no longer does it. (`butlast` is left out: destructuring's expansion references it in every function. Not covered: `str`, `print`, `println` and `format` on data, and `first` or `drop` on rows shown, which the compiler's facts cannot tell from their use on data; review reads for them.)

### Printing beside the printer: the wire

Text for the wire, storage, a digest, a file, a URL, a command line or code to evaluate is `seon.edn/encode` (EDN that reads back, whole: no print limits), and only that var prints beside the printer:

- `seon.edn/encode`: EDN for storage and the wire, whole.
- `seon.context/eval-messages`, `seon.context/request`, `seon.context/parts-of`: the EDN envelope of a user message (`{:by .. :code .. :response ..}`, `{:history {:left-out n}}`) around a response the one printer already printed: the wire, not output.
- `seon.config/resolved`: the config keys a refused combination names, in its error message.
- `my.root/first-moves!`: the code text it sends an agent to evaluate (the call to `seon.judge/first-move` on a task id): code to evaluate, not output.

An agent's namespace refers `clojure.pprint`'s `pp` and `pprint` (`seon.agent/make-ns!`), as a plain Clojure REPL does (AGENTS §4, "what would a plain REPL do"); what they write reaches the model as the evaluation's `:out`, budgeted as prose. A check's console lines are the printer's whole text (`seon.main/shown`).

### Cut where a value is made

The places that cut a value where it is made, not in the printer, each with its reason.

- `seon.main/shown`: names a budget only to print whole (the value's ``:seon.print/full`` metadata).
- `seon.contract/problems`, `seon.task/file-declarations`: a refused value (a function's argument, a task file's entry) may be infinite, lazy or a host object, and travels on the wire as text, so its error keeps the printer's cut, which says what it omitted; the live value stays with the caller.

### Cuts in a display namespace that are not cuts of output

Uses of take, subs and the like in display code that choose what to find or read, not what to cut from output.

- `seon.render.ui/kname`, `seon.render.ui/dom-id`: a keyword's text without its colon.
- `seon.context/similar`: the top k of a search (`take` the config's `:seon.config.render/similar` of its ranking), and the forms that search further beside them: a search's answer, not a cut of output.
- `seon.context/related`: the top k of a search over the wiki's sections (`take` the config's `:seon.config.render/related` of its ranking, the cited ones left out), with the forms that read one whole and search further (`seon.context/related-view`): a search's answer, not a cut of output.
- `seon.agent/embed-written!`: the first `:seon.config.vector/texts` of the texts due go in one `:embed` request (`take`), the rest stay due for the next: a batch bound on work, not a cut of output.
- `my.agent/file-source`, `seon.repl/form-src`: a form's own text out of its file or its reply (`subs` at a reader's offsets).
- `my.root/task-files`: a task file's owning namespace from its file name (`subs` off the `.edn`).
- `seon.render.ui/utc-offset-ms`: parsing `:seon.config.web/utc-offset`.
- `seon.web/handler`, `seon.web/view-of`, `seon.server/mcp-reply`: parsing a request's path and a tool's name.
- `seon.context/near`: the whole line a repaired delimiter is on, the printer budgets it.
- `seon.render.proc/pass`: root's process keeps the newest `:seon.config.render.list/stream` events, and its tile (`seon.render.ui/process-tile`) draws the newest `:seon.config.render.list/history` of them: a window of data, as ctx's are.
- `seon.render.proc/debug-value`: the debug page renders the newest turns its tab has scrolled to (`:shown`, `:seon.config.render.list/history` at first, as many more each time its end scrolls into view); its end (`seon.render.ui/more`) counts the older ones, unrendered.
- `seon.render.ui/cited-of`: a cited var's tests, the newest `:seon.config.ctx/callers` deftests naming it by one query, are a window of data, as ctx's callers window is, never a cut of what is printed (the printer cuts the drawing); `(my.agent/callers 'v)` reads them all.

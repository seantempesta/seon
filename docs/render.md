# Render: what a person or a model reads

Every view, the model's context included, is a render: the one value printer (`seon.print`), or a render function declared on the value's schema (``:seon.render/html``). A render answers hiccup, and the page and the model read the same hiccup, exactly as it was returned: there is no second face for the model (owner, 2026-10-26: "don't leave anything out I want the agent to understand problems with the rendering functions"). Nothing else shapes output, and nothing clips.

**It's like React, or Reagent.** A render is a component: a plain function of its props and its children, Reagent's form, `(fn [opts & children] result)` (owner, 2026-10-23: "It's all just functions and results"; 2026-10-26, the call shape: [components](#components)). A render of one value takes it as its one child, `(fn [opts v] result)`. Its props are optional: `:as`, the room it is shown in (`:inline`, one line in a chat stream or a table cell; `:block`, a full panel, the default; `:tile`, compact and live; `:row`, a row of a page's list), `:budget`, its tokens, and `:handle`, the form its cuts read the rest through. A component that does not care about a prop ignores it. Its result is hiccup, which the page shows and the model reads. A schema declares the component of its values (`{:seon.render/html sym}`), and ```seon.render/html``` finds it in O(1) by the value's schema (the producer's `:schema`, the value's metadata, an error map's type when it holds every key an error holds (a map that only picks an error's keys is data), or an identity attribute: `seon.render/schema-of`); a value with none takes the default component, the one printer (```seon.render/print-html```), which takes the same props and auto-renders: wherever a value inside the printed one has a render of its own, the printer shows that render in its place, one line (`seon.print/print-value`'s `:render`: a call of its render in the hiccup, the value in one line in the text), in its one pass (`seon.render-cost-test/the-printer-renders-nested-values-in-one-pass`: 19 contracted calls a nested value, linear). Inside hiccup, a vector headed by a function is a component call, as in Reagent: `[task-row {:as :inline} task]` is written as what `(task-row {:as :inline} task)` answers, itself expanded the same way, by the one serializer (`seon.web.html/html`); a keyword head is an HTML element. The render proc is the reconciliation, one level up: a page's parts (its units) render again only when their input value changed, and only the bytes that changed are sent (`seon.render-cost-test/render-calls-are-one-pass-over-their-nodes`: nested calls serialize in one pass, linear in their nodes).

## No clipping

A cut never drops silently. It says what it omitted and how to read the rest. Storage keeps the exact value (an error's message, a running form, a provider's HTTP body travel whole); renders budget it. There is no `clip`, no `subs` for display, no `take n` without its count, and no stylesheet clip (`text-overflow: ellipsis`, `line-clamp`, `overflow: hidden` on text): the render's budget is the clamp.

## Prose, and the one string cutter

Text is cut one way, inside a value or shown as itself: the printer's string cutter (`seon.print.select/break-at`) ends the shown part after a line break in its room's second half, else after a space in its final quarter, else at the room, and the cut says `…+N chars in M more lines` and the form that reads exactly the rest (`seon.print.emit/cut-words`). A string in a printed value reads `"its prefix"…+7279 chars in 88 more lines (subs result/h3 19523)`. A keyword or symbol longer than `:seon.config.render.agent/max-name` cuts the same way, its printed text read as `str`: `:nnn…+44 chars (subs (str result/h1) 257)`. Source text is code, not a string: its producer marks it (```seon.print/code```, plain data `{:seon.print/code text}` that a record stores and reads back as it is, recognized by ```seon.print.select/code?```: a form's `:form/src`, a red proof's `:source`, an assertion as written, a cited var's definition head), and the printer prints it exactly as written wherever it stands, every line where it stands in its file and a string's newlines as newlines (`seon.print.emit/code-text`; the width estimate counts each character once, `seon.print.select/code-width`; a cut's "more lines" counts the text's newlines, as `subs` reads them): any slice of the shown text is the recorded text, so a reader copies it into `seon.repl/edit!` as it stands, and no layout indentation enters a string, so a map holding it still reads as Clojure. A nested definition's later lines start at column 0, not under its key: re-indented under its key, or with its docstring's newlines escaped, no line of it would match the recorded text, and an edit copied from it would not apply (`seon.print-test/code-prints-exactly-as-recorded`, `seon.repl-test/an-edit-copied-from-the-shown-source-applies`). Prose (```seon.print/prose```) is still indented to where it stands (`:source (deftest f-test …)`); cut, its cut reads `(subs (:seon.print/code (get-in result/e3 [:source])) 1200)`. The printer never guesses code from a string's text (owner, 2026-10-25: agents should see Clojure as it is in files or the REPL). A cited thing on the page is its cite drawn by its renders (```seon.render.ui/cite```, [an entity cites](references.md#an-entity-cites)): a section as Markdown, a var its source as code, each with the form that reads it whole (`(my.agent/help "docs/render.md#one-printer")`, `(clojure.repl/source sym)`). `seon.print/prose` shows text as itself (unquoted) under a token budget, sized as the printer sizes (`:seon.config.ai/chars-per-token-prior` characters a token, `seon.print.select/estimate`, the one sizer: the history budget and the scripted model's usage count with it too): whole when it fits, else that same cut; given a source form that answers the whole text, the cut names `(subs source offset)` (with `:one-line?`, the offset is still the source's). On the page, `seon.render.ui/prose` links the cut to the page that shows the whole, or carries the whole in the cut's title; a printed value's cut names its result handle (`result/h3 at its REPL`).

A cut is read as its text, where it stands: the printer answers no list of its cuts. Decided by blind scoring on production-shaped values (`docs/render.md`): Haiku readers answered every question about a cut value from the inline cut alone (100%, 60 answers), and ranked it first in 30 of 30 three-way comparisons against the same text with a closing "left out" list (repeats every cut, up to 2.9x the tokens) or with footnote markers; prose's cut words beat the bare `…+N` in 18 of 22 pairs (the unit and the line count tell a reader how much it is missing), and prose's break beat a cut at the last line end, which can spend most of the room on nothing (47 of 256 tokens shown in one case).

## A value on the page is its structure

The page draws a value from its data, the model reads it as text, and both come from one selection: `seon.print.emit`'s hiccup fold reads the same operation stream the layout reads, so the text is unchanged by what the page shows (owner, 2026-10-25: "We can do more complex representations of values there"). A map is a grid of key and value rows, folded as any collection is (a map of scalars, or the value printed, not at all). Two or more maps in a vector sharing two or more keys are a `<table>`, a column per key and a row per map (`seon.print.emit/table`). Text marked as itself is drawn as itself: code, `{:seon.print/code s}` (`seon.print/code`), verbatim in `<pre><code>` and highlighted as Clojure by highlight.js (served at `/highlight.js` from `:seon.config.web/public-dir`): one observer in the page's shell (`seon.render.ui/shell`) highlights each `code.language-clojure` (`seon.print.emit/highlight`) as it arrives and again when a patch morphs a row back to its plain text, so a per-element init, which a morph of unchanged attributes never re-runs, is not used; each mutation batch costs one scan of the page's code elements, and a screen eval opened under its turn carries the same `eval-eN` anchor; prose, `{:seon.print/prose s}`, a paragraph; both print verbatim and unquoted, and a cut of either reads its rest through its key, `(subs (:seon.print/prose (get-in result/e3 [:plan])) 1200)`. A page an agent built is the value's own `:seon.render/html` key, a render already made, and renders as that hiccup wherever the value sits (`seon.render/nested`). A handle, `result/e12`, links to its eval's row, whose id is `eval-e12`, open or not. In the conversation an eval is one collapsed line (`.seon-eval`, ```seon.render.ui/eval-item```, the 2026-10-24 mockup's `▸ (form) · 12 ms`): the prose beside it, its code's first line, its time and its handle, and what came of it (the error's message, or its value in one line), opening to the eval's own render (```seon.render.ui/evaluation```: its code and its value); the agents are a column beside it on a wide screen and a strip of chips above it on a narrow one; prose (a model's reply, a message) reads in the system's text face (`--font-prose`), code and data in mono. A cut opens where it stands: its marker is a button whose click posts `/open` with its row's id and the form the cut prints, `(drop 1 (get-in result/e157 [:value :proofs]))`, and the row renders what that form reads from the record (`seon.print/read-rest`, the operators continuations are made of), so the page shows a cut's rest as the model would read it, under that form as the button that closes it (a button, not a `<details>`: the row's re-render would close a details, whose toggle would post the close); the form is read once, at the edge (`seon.web/open-form`), and a row renders again only when its set of opened cuts changes (its component key). An evaluation's row renders its response's value this way, its cost and the functions it called beside it; a value not held as data (`:printed`) shows as it was printed. `seon.print-test/a-map-is-key-and-value-rows`, `maps-sharing-keys-are-a-table`, `code-and-prose-read-as-themselves`; `seon.render-test/an-eval-row-renders-its-value-as-structure`, `a-page-an-agent-built-renders-nested`.

## A render is a value, printed once

A view that chooses what to show makes a value, never text: an array map of what matters, in its order, and the one printer prints it once at the reader's budget. Nothing is cut before the printer: a long list is the printer's cut, which says what it left. Where a list's whole lives elsewhere, the value carries the form that reads it as data (`:all-in (seon.task/runs (deref (:conn sys)))`). It replaces the bounded lists (a list cut to a config key's first items with a `+N more` line, deleted with their keys) and the per-field budgets that cut each part before the printer (clipping audit, 2026-10-25).

A value too large or too host-bound to print whole declares a model render on its schema (`{:seon.render/model sym}`, ```seon.render/model-printed```), the one a part's model is made by ([a part answers data](#a-part-answers-data)): a function of opts and the value, `(f {} v)`, answering the value to show in its place, which the printer prints like any other (its cuts, its budget). The agent's process state is one (`:seon.agent/state`, ```seon.agent/state-summary```): a bare `(swap! seon.agent/state ...)` answered 42,000 characters, and answers each key with a scalar's value, a collection's count or a host object's type, and the form that reads it whole.

A render's budget, when its env names none, is config too: `:seon.config.render/value-budget` for a value and `:seon.config.render/root-context-budget` for root's context (root's page's hiccup, printed by the render proc).

## The page

Every page is the render of a ctx through the one walk (```seon.render/walker```), laid out in root's chrome (```seon.render.ui/page-chrome```: the agents list, the head, the task's list, the conversation, the tiles), each placed component a unit whose input is its revision (owner, 2026-10-26: "There is only one context rendering system and it needs to be built from the parts"; 2026-10-25: the web UI finished from docs/render.md and the mockup of 4624f2f4f, not redesigned).

- **A location is a ctx.** `/` is root's: root's ctx (```seon.ctx/build``` of root's entity on main, advanced by ```seon.ctx/advance``` on each move of main) drawn by ```seon.render.ui/root-ctx``` (```seon.render.proc/root-walk```). `/agent/{name}` is an agent, named by its id in root's boot (its key, `seon.task/agent-key`: ids start again each boot) or by its branch (`/agent/main/task-x`: the newest agent that worked it, so an agent of an earlier boot, ended or not, opens from the store; owner via root, 2026-10-28). Any other location is a `:seon.render/no-location` (`seon.render.proc/location`).
- **Root's page** is the render of root's ctx: its agents list (root, then each agent its ctx holds), its head (```seon.render.ui/root```), its evals as collapsed lines, and its tiles: root's process (```seon.render.ui/process-tile```), main's open problems (`seon.problems/health`) and main's runs. Root's process (the writer's, the fork server's and the store's numbers, each proc's defects and the newest events, ```seon.render.proc/process-value```) is root's own data, part of root's ctx (`:process`) beside its db pull, never written (root's ruling, 2026-10-27): the render proc assocs it in when it changed and flushes the walk, so only the tile that reads it runs again.
- **The input is at the top**: an agent's REPL, messages, interrupt and release (```seon.render.ui/agent-input```), root's spawn and evaluate-in-every-agent (```seon.render.ui/root-input```), each a UI call of root's request table ([dashboard](dashboard.md#callbacks-are-data)).
- **An agent's page is one layout, read by the model and the person** (owner, 2026-10-28: "Is there no rendered chat ui that is user facing and you're showing me the debug page?"; 2026-10-29: "build with both the context render and the web ui render in mind so we don't let one get out of sync with the other"). `/agent/{name}` is the render `:seon.render/render-ctx` declares (```seon.render.ui/render-ctx```), the layout of the agent's ctx: a chat column (`#c-rows`: each model turn as its reply in Markdown with its thinking folded, ```seon.render.ui/chat-turn```; each eval a line that opens to its value, a call of several forms showing its vector of values; each message a bubble; how the agent stands at the end), beside a side panel (`#p-task`: the task with each proof's status from the `:seon.test/*` facts its record holds, each var its plan cites, the namespaces the work touches, how its work stands ([how the work stands](#how-the-work-stands)), the run, its open problems, the keys the agent added), and the tiles. The head above them (```seon.render.ui/agent```) shows the agent's pid only while its process runs (```seon.task/newest-process``` has no end), never an ended process's. The side panel's parts are the parts the model is sent (```seon.context/page-lists```), the same components, so the two cannot drift (`seon.render-test/the-model-and-the-page-read-the-same-parts`). While the agent's process runs, the page is what it draws (```seon.repl/render-ctx```, asked by the render proc for a watched page); otherwise root draws it from the branch with the same walk. `/agent/{name}/debug` is not a second layout: it is `@ctx` printed, the agent's record as data by the one printer (```seon.render.ui/ctx```, the `:seon.ctx/ctx` render), drawn by root from its branch.
- **The chat reads as a chat** (owner, 2026-10-29: "a friendly chat window that my mom could use"). It opens with what was asked (```seon.render.ui/chat-ask```) and the run's start (`chat-start`); each model turn is one message (```seon.render.ui/chat-turn```): its reply as Markdown, its evals folded into one line (how many steps, how long, any that failed) that opens every step at once, each step its prose as Markdown, its time and its tokens, then its code and result whole, a failure the only mark (```seon.render.ui/eval-item```, its turn's by ```seon.render.ui/turn-evals```: a model's eval is the turn's written just before it); a footer with the turn and its request's tokens; the end a card from the run's end facts (`chat-end`). The agent's own loop eval is not drawn. Counts are tokens (```seon.print/tokens-text```), never characters. Every part of the side list answers data ([a part answers data](#a-part-answers-data)): the task, each thing its plan cites, related, the status, the run, its problems.
- **Three tabs.** The top bar shows a page's tabs (owner, 2026-10-26; renamed 2026-11-03): an agent's page (chat), `@ctx` (`/agent/{name}/debug`: each part of its task's list as a pair, what the model reads of it beside the part drawn, ```seon.render.ui/ctx-parts```, owner 2026-11-03: "the record is @ctx with each part that was rendered and the rendered part"; then its ctx printed; two columns, nothing placed beside it) and debug (`/agent/{name}/context`): the timeline of its requests as they went on the wire ([the debug page is the wire request](#the-debug-page-is-the-wire-request)).
- **An agent's view is the render of its ctx, its components** ([components](#components)). render-ctx, the layout, reads ctx through a tracking view and places components in the page's three lists: the task's (the task, each var its plan cites, the namespaces the work touches, how its work stands, the agent's run and turns, the keys the agent added), the conversation (its evals, turns and messages, in the order each was written: the transaction of its identity datom, since some ids are content-derived, then how the agent stands) and the tiles (each eval whose value has a render of its own). The agent draws its own render, by its own renders, when root's render proc asks (```seon.repl/render-ctx```, the `:render` op, which first takes the facts main holds of its own entities, such as an eval a reader opened); root lays its components out with root's agents list beside them, so a component whose output changed is sent and a new one in its list is an append (before the run's end line, placed after the row it follows). An agent with no process is drawn by root from its branch with the same walk (```seon.render/draw```), the page saying so. `seon.render-test/a-page-is-its-components`, `a-new-member-is-an-append`, `a-handle-links-to-its-eval`; `seon.agent-test/a-parked-agent-draws-its-parts-and-a-gone-one-answers-at-once`.
- **Only what is on screen is rendered.** A page shows what its ctx holds, its evals and turns whole and its messages the newest `:seon.config.ctx/window`, newest first. The debug page draws one request at a time, the one its view is on ([the debug page is the wire request](#the-debug-page-is-the-wire-request)).

### How the work stands

How an agent's work on its task stands is one value, ```seon.context/status```, a fact of its branch at a t (task seon.context/the-context-is-the-agents-evals-and-seons, R2b-1; owner, 2026-10-29: "Store information we need and it's presence means something"): each proof, of the task's plan accumulated over its needs (```seon.task/pulled-accumulated```), by its var as the agent's record pulls it, the task's and its needs' `:proved` (```seon.context/task-of```: the verdict, `:seon.test/status`, its failing assertions as data, `:seon.test/failures`, and its form; [verdicts are a cache](merging.md#verdicts-are-a-cache)), never read again from the db (`seon.render-test/the-status-proofs-are-what-the-record-pulled`); the done rule's reasons (```seon.reconcile/done-explain```) and each as what to do (`:refused`, with the form that does it), and what the branch's work did since its merge base, all from one diff of the branch against `:seon.agent/base-commit` (```seon.merge/content-datoms``` read once, the changes made from it): the functions without a contract, the problems it caused and the sections it made stale (```seon.problems/caused-split```), what its merge carries, and, for a task that merges itself, whether it can merge now; its unmerged entries; a test run that failed as a whole (`:seon.process/test-error`). It reads facts about the work only, never the conversation (its turns, evals and messages), so a turn's own record does not draw it again; turns left and a cut reply are the run's (```seon.render.ui/run-head```). What reads other commits stays the db's: the done rule's scan of every verdict the branch holds (a stray red, a regression), the diff against the merge base, and a red proof's callees (a join of them would hold their vars before the task's cites, which an entity held once would then lose: a cite's var needs its callers). The part that draws it, ```seon.render.ui/status```, is keyed by the agent, so a move of main draws it again only for a task that merges itself, and its element id never moves. Its readers take the one computation: the page and the model draw it (a [part that answers data](#a-part-answers-data)), and the turn's done check reads the same part's data from the agent's walk (```seon.repl/page-data```, ```seon.render/placed-data```). Before it, a turn computed the reasons itself and held them in its model call's basis, and the page drew them from that copy (stale after the run's end) and the branch's diff again in four views (`branch-views`); the diff is now read once a branch and t. A red test outside the task's proofs needs main's claims (regression or stray red), the reconciler's index: in an agent its own, advanced by what differs (```seon.agent/reconcile-index```), else one built cold (measured on a demo branch: 14.8M ticks, 70 MB), and only then. A red test main was red on too, at the branch's merge base (the base's verdicts, read only then), is main's red, neither a regression nor a stray red of the work. The rule reads the verdict alone, red before and red after: a test the work broke again in a second way, while main's own cause stands, is not the work's either; and a stray red is offered the form that registers it as a proof only when the branch wrote or changed that test (its source differs from the base's): a live session was told to register a test of main's that its environment failed (```seon.context-test/a-red-main-was-red-on-too-is-mains```).

Reading a request back (```seon.context/parts-of```, which the context page uses) draws each turn's parts once, at that turn's commit ([the page is sent as what changed](#the-page-is-sent-as-what-changed)).

## Components

A component is a call in hiccup, `[f opts & children]` (Reagent's form), of a render whose opts declare what it reads: `:seon.ctx/ctx`, ctx as a tracking view ([reactive renders](#reactive-renders)), or `:seon.db/db`, the branch's db, read under `d/with-reads`. The walk (```seon.render/render!```, ```seon.render/flush!```) fills those keys in, runs the render in its reaction, and draws its output with its root element's id its key (```seon.render/key-id```: its render's name and its children's keys, an entity's eid, a var's name). One cache holds each component's reaction, args, output and db reads, in the process whose page it is (the agent's walk, held in its state). A component runs again when its children are not `=` to last time's, when a change of ctx reaches a path it read, or when a transaction's datoms touch its db reads; otherwise it is skipped, and a run whose output is `=` to the last one's changes nothing. A flush (Reagent's batching flush) draws the components a change queued in mount order, parents first, after the ratom flush: one a commit, and the agent's page walk once a turn, given every datom its db moved by since it last drew (`seon.ctx/take-moved!`, ctx's own diff of each move). Each component's runs are counted by its render's var (```seon.render/ledger```: ran with a new output, ran with the same, skipped, and the bytes its runs allocated). A call of a render that declares neither is not a component: it stays a call in the hiccup, the page's writer expands it and the model reads it as the call. A component whose render throws draws its error's render in its place, a `:seon.render/component-defect` (a [failure point](failure-points.md)); every other component draws. `seon.render-test/a-component-re-runs-on-what-it-read`; `seon.context-test/a-db-component-runs-again-on-what-it-read`, `a-cited-var-redefined-shows-in-the-next-view`, `the-task-draws-what-it-needs`; cost `seon.render-cost-test/a-change-costs-its-components`: a change draws its components, flat in the page (137 contracted calls, about 100 KB from 100 to 4,000 evals), beside ctx's diff, which walks every key of the collection it changed.

### A part answers data

A component may answer data instead of hiccup: a value whose metadata names its schema (`:seon.render/schema`), a part (```seon.render/part```; owner, 2026-10-29: "I want the hiccup render to make the data we need to render the web ui and I similarly want the ai render to make the data we send to the model"). The walk runs and caches it as any component (its reaction, its db reads, its revision) and keeps the data; two renders are declared on its schema beside each other: `:seon.render/html`, the hiccup the page draws, and `:seon.render/model`, what the model is sent (```seon.render/model-declared```; none: the data itself), made only when a request asks for it and kept by the part's revision (```seon.render/model-of```), so the page never pays for it and a request reuses an unchanged part's. Both are functions of the one value, so the page and the model cannot drift and nothing is computed twice; a model render is given its opts, so a render may differ by model. The data stays data until the request prints it with every other part ([the page is sent as what changed](#the-page-is-sent-as-what-changed)), at the one printer. The first part is the status ([how the work stands](#how-the-work-stands)); the others answer hiccup and are sent as it until each moves (task seon.context/the-context-is-the-agents-evals-and-seons, "Parts answer data").

A component whose render answers nothing (nil: ```seon.render.ui/own-problems``` with no problem open) draws nothing: no element holds it and no part is placed for it, so the page shows none and the model is sent none (```seon.render/placed```; task seon.render/an-empty-part-draws-nothing). When it draws again, its part is placed in the layout's order like a new one.

A component that throws is a part too: its error map (`:seon.render/component-defect`: the render that threw, its message, and the thrown error's own data under `:seon.render/threw`, a contract's problems among them), which the page draws by the error's render and the model reads as the map it is, every other part drawn beside it (```seon.render/render!```; owner, 2026-10-29: "it's okay if some are errors just make sure it's visible to the agent"). An agent that breaks code its own page runs (the parser, a render) reads what broke where its part was.

The parts that answer data now, each one value the page draws by its `:seon.render/html` and the model reads as data:
- **The task** (```seon.render.ui/task-data```): the task as the agent's record pulls it, its needs with their `:proved` and its `:proved`, the cites left to their own parts, drawn by the task-fact's own renders (```seon.render.ui/task``` and ```seon.render.ui/task-model```): its plan accumulated over its joined needs (```seon.task/pulled-accumulated```), how its kind is worked, and, as `:to-prove`, each proof, its own and its needs', that `:proved` holds no form for, with what the plan says it should assert (a written one is the status's, with its verdict, source and calls: listing it here too repeated it). It declares `:seon.ctx/ctx` and no db (`seon.render-test/the-task-part-reads-only-what-ctx-holds`). A model render answers plain data, never a map naming its own schema: `select-keys` keeps a map's metadata, and a value that names the task-fact is printed by its model render again, without end. ```my.task/data``` answers more at the REPL, on demand (```seon.context/task-data```: the write set, the sections).
- **The agent's turn** (```seon.render.ui/run-head```): its turn of its cap and what its evals changed of the branch's program (`:changed`, ```seon.render.ui/changed```: the page reads turn 11 of 40 · 0 changes), the tokens its requests sent, a cut reply, and `:ns`, the namespace its REPL is in. Every eval's response carries that namespace as `:ns`, as nREPL's do (```seon.repl/eval-string```; the prompt lists it among a result's keys), and the eval's record writes it on the agent as `:seon.agent/ns` (```seon.repl/record-tx```: a datom only when it moved), which the part reads (```seon.context/current-ns```; the task's `:seon.task/ns`, where the REPL starts, before any), so it is a fact of the branch and the part redraws only on a move. A move into a namespace whose own var hides a REPL helper (`source`, `doc`, ...) answers `:helper-shadowed` naming the helper and the qualified one (```seon.repl/shadowed```), as Clojure warns when a definition replaces a referred var.
- **The namespaces the work touches** (```seon.render.ui/namespaces```, its data ```seon.context/namespaces-of```, drawn by ```seon.render.ui/namespaces-html```): a map by namespace name: the one the REPL is in (```seon.context/current-ns```: the task's own `:seon.task/ns`, where the REPL starts, until an `in-ns` moves it) first, so a task that cites and proves nothing yet draws its namespace and not `{}`, and the part follows the REPL, then those of what the task and its needs cite and of their proofs, once each (an own namespace also cited is listed once, first), each with its names the task cites or its proofs call (their forms' `:form/refs`, as `:proved` holds them) and `:ns-form`, the form that reads its ns form (its requires and aliases) and a line per definition (`(clojure.repl/source ns)`), so its requires are one read away. It reads the record alone, so it costs what it shows, never the namespace's size (`seon.context-cost-test/the-namespaces-part-costs-what-it-shows`): it lists the names the work touches, never every public name of the namespace. The namespace the REPL is in is the turn's (`:ns`, above). It is a map answered by name, never a vector (a vector is read as hiccup).
- **Each thing the task, its needs and the agent cite** (```seon.render.ui/cited```, the cite as ctx holds it, drawn by its schema's two renders, ```seon.render.ui/cite``` and ```seon.render.ui/cite-model```): a section as Markdown at its depth, a var with its source, doc, contract, tests and callers as its cite pulled them (at doc depth its source too when it is of the citing task's own namespaces, ```seon.render.ui/own-namespaces```), a schema key its form and `:change` (```my.schema/register!```), a namespace its doc ([an entity cites](references.md#an-entity-cites)). It declares `:seon.ctx/ctx` and no db: what it shows is what the pattern joined (`seon.render-test/a-cited-part-reads-only-what-ctx-holds`), and a section main changed redraws its part alone (`seon.context-test/a-cited-section-main-changed-is-its-part-alone`).
- **A proof's failures** (```seon.context/failures```): failing assertions that got the same value with the same message are one entry, `{:asserts [...] :got v}`, so nine assertions that threw one error are read once.

Each view renders on its own (```seon.render.proc/view-pass```, a [failure point](failure-points.md)): a view whose render throws is that error as its page, a `:seon.render/view-defect`, and every other view of the pass renders (`seon.render-test/a-view-that-throws-answers-its-page-with-the-error`).

### A search is a part

A search is data a context holds, a `:seon.search/search-fact` (its query, and `:seon.search/k` when it asks other than `:seon.config.render/search`) of a task or an agent, joined by their patterns beside their cites, so `@ctx` holds it and an agent changes or adds one with `swap!` as any member ([ctx](ctx.md)). Its component, ```seon.render.ui/searched```, reads the db and answers one compact hiccup, which the page shows and the model is sent as it is (owner, 2026-11-01: one render that the person and the model both see, not a data render beside the page's): its query searched by `seon.context/search` (words, meaning once the vector pipeline has embedded the query, the names it holds), a line a hit (a function's name and its doc's first sentence, a section's address and heading, a schema key) and, when hits were left out, how many and the call that answers them. A request's own search names it in its heading rather than repeating the plan the task part shows. A changed query redraws that part alone (`seon.ctx-test/a-search-is-a-member-a-swap-adds-and-changes`). What it was measured to find: [vector](vector.md#what-the-work-is-likely-to-need-as-an-eval).

## One rendering system, drawn from the data

There is one rendering system, and the data describes the page (owner, 2026-10-26: "There is only one context rendering system and it needs to be built from the parts"): an agent's record is a name chain, an agent has a conversation of turns, each turn holds the agent's prose and its evals, each eval has a response ([vocabulary](vocabulary.md)), and the page and the model's request are both renders of that record through ctx, whose [pull pattern](ctx.md#the-pattern) (`:seon.ctx/pattern`, data an agent edits by `swap!`) says which of it is drawn. Nothing about a page is stored beside the data it shows, and no render queries the db for what the pattern can join (owner, 2026-10-30: "Please stop building parallel systems ... No special treatment"): what a text cites is entities its write made, joined by the pull and drawn by their schema's renders ([an entity cites](references.md#an-entity-cites)); what exists only when rendered, such as the sections an embedding search relates, is a render that declares `:seon.db/db`, and the db ranges it read are what invalidate it. The model reads the same render: the page's parts beside the records, in each request ([the model's context](#the-models-context-a-cached-prefix-then-the-turn)).

It is re-frame's model, which is Reagent's, which is React's memo, proven in production Clojure: one immutable value (`@ctx`) is the app-db, a transaction patches it, and a component is a pure function of its slice, run again only when its slice changed and passing nothing on when its output is `=` to before. Immutability makes "did my input change" a pointer check (`identical?` 1 µs; `=` on 1 MB 0.2 ms), so nothing is guessed and no render knows the data's shape. A render is a function and the data it renders, never a registered object: to make one cheaper, hand it a smaller slice, with nothing to invalidate by hand. The one addition is that the source is a database, not an atom, hence `d/with-reads` for renders that query. Measured on a live agent, a new eval rebuilt 2 entities in 0.23 ms and reused 19 of 22 render calls by identity, against 102 entities and 0 of 191 for a fresh build (28-35 ms); a patch's cost grows with the transaction, not with ctx.

## Reactive renders

Your page and your model's context are renders of `@ctx`, and a render runs again only when a path it read changes: read the narrowest path you need, and give each member of a list its own component, so a change redraws what it reached and nothing else. Your page is one walk of your record; each turn's page message is what that walk redrew ([the page is sent as what changed](#the-page-is-sent-as-what-changed)). A rerun indexes only the reads it gained or lost (```seon.ratom/index-reads!``` from the reaction's `-update-watching`): one that read what it read before, a layout over every row rerun by one change, indexes nothing again (`seon.ratom-test/a-rerun-indexes-only-the-reads-it-gained-or-lost`; one eval added to a kept page at 100 evals: 37.7 MB to 13.0 MB). Its own body still reads every row it lists, so a layout that lists the session reruns at O(rows): give each list its own component.

**Writing one.** A render is a function `[opts & args]` answering hiccup; it is a component when its opts contract names `:seon.ctx/ctx` (it reads ctx) or `:seon.db/db` (it queries the branch's db), and the walk fills those keys in. A call `[#'f {} arg]` in a render's hiccup draws f there as a component of its own, keyed by f and its args (its root element's id is that key, `seon.render/key-id`, whatever id you gave it):

```clojure
(defn row "An eval's code." {:malli/schema [:=> [:cat [:map [:seon.ctx/ctx :map]] :int] :any]}
  [{c :seon.ctx/ctx} id] [:li (get-in c [:evals id :seon.eval/record :code])])
(defn page "The plan, then a row for each eval." {:malli/schema [:=> [:cat [:map [:seon.ctx/ctx :map]]] :any]}
  [{c :seon.ctx/ctx}] [:div [:p (get-in c [:task :seon.task/plan])] (into [:ol] (for [id (keys (:evals c))] [#'row {} id]))])
```

A flush (`seon.render/flush!`) answers each component it ran, `:miss` when its output is new and `:same` when it ran and answered what it did before (which passes nothing on: its parent and the page are untouched); a component it skipped is not named. A path that names nothing reads `nil` and draws it, with no error: check a render's output once. A render that throws draws its error in its place, a `:seon.render/component-defect` naming the render and the message, and every other component draws. To change your own page, register your render as the layout or one of its parts ([ctx](ctx.md#the-record-is-the-agents-work), [adding a datum and its render](ctx.md#adding-a-datum-and-its-render)). `seon.render-test/a-flush-answers-what-it-redrew`.

**Your page, changed at your REPL.** Your page is one walk of your record (`seon.repl/page-walk`), drawn once a turn, and each turn's page message is what that draw changed. Two levers move it, and the next turn shows the change:

```clojure
;; a part's render, read and redefined: the walk watches every render it drew, so its parts redraw
(clojure.repl/source seon.render.ui/own-problems)
(in-ns 'seon.render.ui)
(defn own-problems "…" {:malli/schema [:=> [:cat [:and :seon.render/opts [:map [:seon.db/db :seon.host/db]]] :int] :any]}
  [{db :seon.db/db} _aid] [:section [:h2 "problems"] [:p "what I want here"]])
(in-ns 'agent.a1)
;; what your plan cites, changed through ctx: the write derives what the new text cites (seon.agent/transact!),
;; so the cited part appears in the same turn
(swap! ctx update-in [:task :seon.task/plan] str " See `seon.print/text`.")
```

Each part names the render that drew it by its schema (a cite's: `:seon.cite/cite-fact`, drawn by ```seon.render.ui/cite``` and ```seon.render.ui/cite-model```) and the form that reads what it shows whole (`:read`), so a line you see leads to the function you redefine. `seon.render-test/a-redefined-render-redraws`, `seon.ctx-test/the-page-reads-every-write-since-it-was-drawn`.

**What a read costs**, measured in that test and in `seon.ratom-test/inferred-paths`: a render runs again when a change reaches what it read.
- `(get-in c [:task :seon.task/plan])`, `(:k m)`: that value changed, or something above it was replaced.
- `(contains? m :k)`, `(get m :k nf)`: the same as reading the value; a key's presence is not cheaper.
- `(count m)`, `(keys m)`, `(seq m)` of a collection: a member added, removed or replaced, never a change inside a member.
- `(for [[id e] evals] (:code (:seon.eval/record e)))`: any member's record; the same list with `[#'row {} id]` runs only the row whose eval changed.
- `seon.ratom/unwrap`, `seon.ratom/realize`, printing a value: anything below it.

ctx's diff (`seon.ctx/changes`) is by entity: a map holding `:db/id` is diffed key by key, and any other map is one value, replaced whole, so everything that read inside it runs again. `@ctx` is entities throughout; an atom you build by hand needs `:db/id` on its maps to be read as one. A db render (`:seon.db/db`) is run under `d/with-reads` and runs again when a transaction's datoms touch the ranges it read: pass those datoms to `flush!` (`seon.context-test/a-db-component-runs-again-on-what-it-read`).

**How it works.** ```seon.ratom``` is reagent.ratom ported (`RAtom`, `Reaction`, `run-in-reaction`, `flush!`, `dispose!`; Reagent's own tests, `seon.ratom-test`), with the cursor inferred (owner, 2026-10-26: "I'd rather infer the cursor than require it"). A render declaring `:seon.ctx/ctx` gets a tracking view of ctx: a map that delegates to the real value and records each path it looks up, a map's presence (shallow, reached by a change at or above its path), a value read whole (deep, reached by a change at, above or below it), or a node iterated (its key set and direct values), as Vue 3's reactive proxy and MobX's observable map do. The printer and the page's writer take the real value (`seon.ratom/unwrap`, `seon.ratom/realize`), each such read whole. A source read through views has one watch: its reset! (ctx's patch) runs its diff once (`seon.ctx/changes`) and reaches only the reactions whose read paths a changed path reaches, by index (`seon.ratom/source-changed`). Reagent's scheduler (requestAnimationFrame) is the commit on the server: the queued reactions run at a non-reactive deref and at each flush of the walk (`seon.render/flush!`). `seon.ratom-test/inferred-paths`, `a-view-is-a-map`.

The frame is the one part with no value behind it: the document (`seon.web/page-doc`), its head and scripts (`seon.render.ui/shell`). It is fixed hiccup, the same on every page, served once with the page.

## Tailwind

The page is laid out by Tailwind's classes in each render's hiccup, responsive at every width, with no hand-written stylesheet (owner, 2026-10-23: "I want responsive html and css so why not tailwind?"). `resources/public/css/input.css` holds every directive, token and source glob (Tailwind v4, CSS-first, no config file): `source(none)` with an explicit `@source` over `src/**/*.clj` (automatic detection walked the reference-code tree: v1 measured 42 s against 1 s), the Phosphor theme's tokens (dark, light when the system asks), a base layer for semantic hiccup and the one printer's classes, and a safelist of the utilities an agent may use, since a render an agent defines at its REPL is in no scanned file: the common layout, spacing, type, list, border and theme-color utilities, responsive where layout is (117 KB, 16 KB gzipped; a rebuild on each agent render's classes was the alternative, priced and not taken). `bin/build css` (a step of `bin/build seon`, and so of the `:build` effect after merges) runs Tailwind's standalone binary, pinned by version and checksum and fetched once into `target/tailwind/`, into `target/css/app.css` (`:seon.config.web/stylesheet`, served at `/app.css` and read per request); its stamp is the digest of `input.css` and the scanned sources, so unchanged inputs regenerate nothing (68 ms when they changed, v1's port of its `bin/css`). Add a class to a render, or a token or safelist entry to `input.css`, and build: the stylesheet regenerates.

### Style

A component's root element carries one class, its render's name, and its render's var states its Tailwind classes; the page's html adds them, and what the model reads holds the name only (owner, 2026-10-26: "make it so the fully printed hiccup is compact and everything earns it's spot"; DECISIONS, compact hiccup). The walk gives each component's root its key as id and its render's name as class (``seon.render/render!``), in place of any class the render gave its root. A render states its style as `:seon.render/style` on its var, literal text in `src/` (so the `@source` scan above builds it), its descendants by Tailwind's arbitrary variants (`[&>h2]:uppercase`); render-ctx's components share a panel's and a tile's (``seon.render.ui/task-data``, ``seon.render.ui/eval-tile``). When a unit's html is written, ``seon.render/styled`` appends each drawn render's style to its root's class: the style of every render on the page, gathered by reference from the renders the walk drew, never spelled in the tree. Semantic classes a render uses inside (`seon-prose`, `muted`, `err`, the printer's own) stay, styled once in `input.css`. On a4's first page (15 components) the class text fell 355 -> 194 chars, 9,171 -> 9,094 tokens (`seon.ctx-test/a-component-is-styled-by-its-renders-name`).

The walk replaces a component's root attributes with its render's `:seon.render/style`, so a class written on the root element of the hiccup is dropped: a bubble's classes go in its style. The model reads the same hiccup the page draws, so a plan's text stays verbatim, backticks included (parsing inline code spans turned the context's tests red; only fenced blocks are detected, by their marks).

## Tiles are data; the context reads the page's derivations

Each fact the page and root's context both show has one producer they share:

  - `:seon.run/status` its finished, judged and failed sets, read once, by `seon.task` (`seon.task/finished`, `judged`, `failed`; with `seon.task/done?`, a task's done on a db, and `seon.task/running`, the running runs by one index seek), which the reconciler, problems, the render UI and the server require (`seon.main-test/a-runs-lifecycle-is-read-once`);
  - `:seon.task/state` a task's observed states with each state's meaning (its `:seon.status/title`, read with `seon.contract/properties`). A task's state is derived once, from the reconciler's index (`seon.reconcile/task-state`), which every reader of a task's state calls.

  A new status is one enum entry. Not this: a status set typed out at each site that asks.
- **How an agent is:** `seon.render.ui/shown-status` and `seon.render.ui/ended-as`; its newest events are the stream's own words (`seon.render.ui/event-detail`); a cost verdict's lines are `seon.cost/verdict-lines`. - One-line text in a row or the context is `seon.print/line`. A root function called from the page is recorded on main by the render proc when root answers it (origin `:ui`), with that answer ([dashboard](dashboard.md)).

## Health is what flows

Nothing is pinged and nothing runs on a beat. A render pass happens on an event, an api answer or a tab's request. What is wrong has one producer, what is recorded or derived from main's facts: root's page reads root's defects (its process tile) and main's open problems (`seon.problems/health`: [health](health.md)), never re-derive them from the live view; root records an agent's death (`seon.root/end-agent`), and a refused spawn, or a red test run or refused merge of an agent with no task (a task's run records its own), as it folds it into the agent's view (`seon.root/set-agent`). A value only a ping carried is its owner's to emit when it changes. `bin/check idle` proves an idle root with a tab open steps nothing, and that a spawn and a commit still reach the tab.

## The model's context: a cached prefix, then the turn

A model request sends what does not change first, so the provider serves it from its prefix cache, and sends nothing twice.

The request is a render of the agent's record (docs/render.md, owner 2026-10-24): each record's part of the conversation is provider-neutral messages (an eval, ```seon.context/eval-messages```: its assistant message with the reply's prose, its reasoning as returned and the eval call, then its tool message, the response as printed; anyone else's eval, one user message; a message fact, ```seon.context/message-messages```), and ```seon.context/request``` composes the agent's request from them in one order; the one provider format function, ```seon.model/wire-messages```, turns it into the wire shape (a reply's calls folded into one assistant message; reasoning sent back unless `:seon.config.ai/replay-reasoning` is false, which a config with thinking on refuses at load):
1. **The help page** ([agent](agent.md)) as the system message: the same bytes for every agent and every turn (`seon.context/help-text`).
   **Example sessions**, when the agent's task names any (`:seon.task/examples`, refs to agents keyed `example/<id>`, loaded by `my.root/load-example!` from the EDN `seon.context/session-tx` writes): after the system message, each example (in key order) as a user message `<session id="example/<id>" kind="example" from="seon">` saying it is a finished session of another task, not the agent's, and the request it answered (Seon's framing in a user message, the one turn every provider renders in place: a system message after the first is moved to the front or refused by several), its records printed by `printed-run` exactly as the agent's own (`seon.context/example-messages`), and a user message `</session>`; then a user message `<session id="<session>" from="seon">` opens the agent's own session. Sent whole at the session's first request and part of the prefix after it; recorded as `[:example key t]` and `[:session id]` refs, so a replay (`parts-of`) draws the same bytes, and counted as `:examples` by `sent-split`. A task with none is sent what it always was (`seon.context-test/a-task-with-no-examples-reads-what-it-read-before`). The person's page draws the same evals with `seon.render.ui/evaluation` (`seon.render.ui/examples`, beside the page, not in the model's part of it).
2. **The page's parts** (```seon.context/request```): the agent's live walk's parts of its task's list (the task, each var its plan cites, how its work stands, the run; a part that answers data by its model render, any other component's hiccup as its render returned it, by its element id), as one user message: every part whole at the session's first request, after it the parts whose content differs from what the previous request sent (`{id hiccup}`, `nil` for one that left), none when none changed. [The page is sent as what changed](#the-page-is-sent-as-what-changed) says how.
3. **The conversation**, append-only: the session's records in tx order (```seon.context/records```: the agent's evals, the user's among them but not its own turn loop's, ```seon.context/loop-eval?```, the messages it took and its prose replies that called nothing), each by its own render, printed once when it is first sent and reused by its id after (```seon.context/printed-run```, a cache in the agent's state that may be dropped and printed again: a record's message is a function of that record alone (no fold, no answer marked as a repeat: DECISIONS 2026-10-29, nothing derived is held), so a turn prints only its new records and every older message is the same bytes, and the provider's cache holds; proof `seon.context-cost-test/a-turn-prints-its-new-records-flat-in-the-history`). All of it is sent, every turn, as a REPL keeps its scrollback (owner, 2026-10-28: no history budget): nothing is collapsed or left out, so each request is the one before and what was added. A run whose conversation passes the model's window (`:seon.ai.model/context-window-tokens`, 1,048,576 for DeepSeek's) gets the provider's error as a typed `:seon.model/provider-error`, which ends the turn as data ([failure points](failure-points.md)).

A response is the map ``:seon.eval/response`` declares, each key only when present (`seon.repl/response`; docs/prompt.md lists them for the model): one per eval call, its forms run in order and stopped by the first exception, its value one form's as Clojure answers it, or, for several top-level forms, `:forms` (how many ran) and `:value` the vector of their values, as a REPL prints each, printed by the one printer under its handle, the var `e` plus the eval's id in the `result` namespace (`seon.print/response-text`), which holds it. Its record keeps the response whole, its value as data when it is plain data (```seon.contract/plain?```, stored once under its content key when large), else the response as it printed then and the value's type (```seon.repl/record-details```); nothing printed for a reader is stored, so a record is the same whatever came before it: its text is a function of that record alone, and ```seon.context/printed-run``` only prints each new record once and reuses it by its id (its ref is `[:eval id]`). A reply with prose and no call ends the turn, and the run waits for the user (tool_choice auto: DeepSeek refuses `required` with thinking on).

So each request starts with the whole of the one before (`seon.context-test/the-request-is-a-conversation-of-evals-and-the-page`, `seon.context-test/the-prefix-stays-byte-identical-across-turns`), and the plan, its references and its sections go out once a request (`seon.context-test/each-section-is-told-once-on-the-page`). Not this: a part sent twice a request, or a note that edits an earlier message, which breaks the prefix for every later turn. v1 measured the same split live: stable run sections of about 8.5k tokens, turn sections of about 0.75k, 85-91% cache hits. Measured through the server on three open tasks (printer estimate, `:seon.config.ai/chars-per-token-prior`): the help page is 2,132 tokens, the same for every agent; the run sections 1,639-1,887 (the references 2.1-2.4 KB); the turn sections 45-76 before any proof has run. A first request is 3.9k tokens, 54% of it shared by every agent; each later turn adds its scrollback and about 60 tokens of turn sections, so with 2k tokens of scrollback a turn sends about 2.1k uncached tokens and the cached prefix is 65% of the second request and 79% of the fourth. What the provider served from its cache is recorded on each turn's model call (`:seon.model-call/cache-hit-tokens`, `:seon.model-call/cache-miss-tokens`, by `seon.turn/usage`; [the record is the agent's work](ctx.md#the-record-is-the-agents-work)), absent when it did not say.

DeepSeek's prefix cache ([its guide](https://api-docs.deepseek.com/guides/kv_cache)) serves a request only from a stored prefix unit it fully matches. Units are made at the end of each request's input and output, at prefixes several requests share (found lazily: the third request hits what two earlier ones shared), and at fixed intervals inside a long input; the cache is best effort, takes seconds to build, and is dropped hours to days after its last use. Since each request drops the one before's last message, the newest scrollback turn sits on no unit boundary and hits only through the shared-prefix units.

A short cache hit is a problem. Each turn compares its request with the one before in its run (```seon.turn/cache-miss```): the leading messages both hold equal are the prefix the cache should serve, sized as the provider's own prompt count apportioned by the one sizer (```seon.context/messages-tokens```) and rounded down to the provider's block (`:seon.config.ai/cache-block-tokens`; DeepSeek's 128, measured: every recorded hit is a multiple of it). A hit more than one block short of that is a `:seon.turn/cache-miss` error the agent folds and sends with its next commit, counted under one signature in the `:eval` class (`seon.model-test/a-turn-whose-cache-misses-its-prefix-is-a-problem`). Measured 2026-10-25 on 100 turns of 6 runs: 75.6% of all prompt tokens hit the cache, 78.4% after each run's first turn; each hit was 0.87-1.12 of the prefix so sized, and none was short. Turn 1 shares only the system prompt and the task's data (turn 0's request after them is all screen, evaluated again each turn), so it hits about 900 tokens by design.

A reply cut at `:seon.config.ai/max-tokens` (`:seon.turn/finish` "length"; `seon.model/reply-of` keeps the cut text and the forgiving reader repairs it) is almost always a repetition loop, not long work. Over 370 deepseek-flash turns with thinking off and a 65,536-token bound, 66 (18%) ended "length" at 184k-415k characters, each repeating 2-47 distinct forms (typically one ``clojure.repl/source`` call 300+ times), every form evaluated (up to 4,206 in one turn); they spent 45% of all tokens and 168 of 181 model-minutes (median 151 s against 2 s for an ordinary turn). 18 of 33 first turns looped, so the loop is not only history fed back. The largest ordinary reply was 19,809 characters (about 5k tokens).

The field's evidence for this shape: SWE-agent (arXiv 2405.15793, SWE-bench Lite, 18.0% resolved) lost 3.0 points with full history instead of collapsing all but the last 5 observations, 5.3 with a whole-file viewer instead of 100 lines, 6.0 with iterative instead of summarized search and 1.7 with no demonstration, and its successes took a median of 12 steps against a mean of 21 for its failures. CodeAct (arXiv 2402.01030) found code as the one action up to 20% more successful in fewer turns; Seon's one `eval` tool is CodeAct ([model](model.md#one-tool-eval)). aider ranks a 1k-token map of symbols by references, and Manus calls the KV-cache hit rate the first metric and keeps its context append-only and deterministically serialized.

**What grows a request is the conversation, not the page** (measured 2026-11-01 by re-rendering one recorded run's requests): the page is about 3k tokens and most turns add about 70 characters of it, while a request went from 5k tokens to 54k by turn 25, single eval answers (a source read, a whole namespace) running 16-27k characters. The field's best-replicated finding agrees: tool outputs were about 84% of a turn's tokens, and masking old ones while keeping the actions matched or beat summarizing them at about half the cost (JetBrains, arXiv 2508.21433; SWE-agent's last-5-observations, arXiv 2405.15793). Here an old eval's answer could become one line naming its handle (`result/eN`) and how to read it back, in steps of k turns so the prefix breaks once per k. That is an experiment for the evaluation (L1.5), not a change: the owner's ruling of 2026-10-28 sends the whole conversation.

### The page is sent as what changed

The model reads the parts of its page as the person sees them (the task, each var its plan cites, how its work stands, the run, its own problems: the components of the list `#p-task`, a part that answers data by its model render and any other by its hiccup exactly as its render returned it, by its element id; owner, 2026-10-26: "there are only two outputs too: @ctx returns data just like any repl eval and then we need to show the UI"). They come from the agent's live walk, the output the person's page shows (```seon.repl/page-hiccup```; the walk re-runs a part only where what it read changed, so a turn costs what changed), never drawn cold per turn: the cold draw (```seon.context/drawn-parts```, 35M ticks a page on Seon's own tasks) is for a request made with no live walk and for replay. A request sends one user message holding the parts that are new or changed since the request before, `{part-id hiccup}` and `nil` for a part that left; the session's first request, and one after the agent trimmed its context, sends every part whole, before the records; a request in which no part changed sends no message.

What a request sent of each part is a fact on its model call (task seon.context/the-context-is-the-agents-evals-and-seons, R1): `:seon.model-call/sent` holds `[:parts agent commit whole? ids call]`, the parts that message holds (replayed by drawing them at that commit, a read of history), and last `[:hashes {id hash}]`, the content hash of every part the model has after the request (the hash of the part's printed form; the walk's revision is per process). The next request compares the live parts with the previous model call's hashes, a db read with no state held in the process, so a process restarted on the branch sends exactly what changed since the last recorded request. Nothing derived is held for the request either: a process with no print of its run reads the previous request's refs back (```seon.context/parts-of```) and appends.

A part sent again answers what changed of it when its data is a map (the owner's ruling, 2026-10-30; ```seon.context/part-change```): `{:changed {key new-value} :gone [key]}` of its top-level keys, against the parts the request before drew (kept with this process's print of it, else drawn at that request's commit, as a replay draws them), so the status that moved one proof costs that proof, not the whole part again. A part that is no map, or that the request before did not send, is sent whole; the parts ref then names the earlier commit too, `[:parts agent commit whole? ids call was-commit]`, and a replay draws both (`seon.context-test/a-changed-part-is-sent-as-what-changed`).

The trim is the one place a request is not the previous one plus appends: the agent retracts evals from its record (`(swap! ctx update :evals dissoc ...)`), a record the previous request sent is gone from the agent's records, and the request is drawn whole (the system prompt, every part, the records that remain; `seon.context-test/a-trimmed-conversation-draws-the-request-whole`). A reply of prose with no call is the agent's assistant message in its history (`[:turn id]`; `seon.agent-test/a-prose-reply-stays-in-the-history`).

Measured 2026-10-29: the request build of a turn costs the same 9 contracted calls at 10, 100 and 1,000 earlier evals (`seon.context-cost-test/a-turns-request-costs-its-parts-flat-in-the-session`). Before, a turn drew the page at the commit before it and at its own (or took them from a cache in the agent's state), diffed them part by part and diffed ctx. Measured on a1 (2026-10-26) the page is 6,632 tokens over nine parts, and a cited var's redefinition changed two parts (1,283 tokens). Reading a request back draws each turn's parts once, at that turn's commit (`seon.context-cost-test/reading-a-request-back-draws-each-turns-parts-once`). A cold draw reads one list of the page, so ```seon.render/draw``` takes the lists to draw (`["#p-task"]`, ```seon.context/page-lists```): the layout's other lists (the conversation a person reads, the tiles) are not rendered, 2,974 calls and 10.2 MB at 80 evals and 40 messages against 572 and 4.5 MB (`seon.render-cost-test/drawing-one-list-costs-that-list-not-the-page`).

### A layout places its lists

A layout lays its page out as lists, and each list is a component of its own: a render whose var carries `:seon.render/list`, the id of the container element its output is (`seon.render.ui/task-list` is `"p-task"`, `conversation-list` `"c-rows"`, `tiles` `"p-tiles"`). Its root element keeps that id (every other component's root takes its key, `seon.render/key-id`), and the components directly in it are placed in it: ```seon.render/placed``` walks through a list component to its list, so the parts a reader takes (`placed-units`, `placed-hiccup`, `placed-data`) are the list's members, as when the list was an element of the layout. A reader of some lists walks only those (`placed` with sels), and a draw of some lists draws only those (`seon.render/draw` with sels: a list component none of them names is not drawn). What a layout must do: put each list in a list component that reads only what that list shows, so a change of one list's members reruns that list alone (an eval added reruns the conversation and the tiles, never the task's list, whose parts the model is sent); the layout itself reads only what it needs to place them (`seon.render.ui/render-ctx` reads the agent's id). Split 2026-11-03: what the model is sent and the person's page are the same bytes (every unit, part and message of three test sessions, recorded before and after).

### A page is a kept walk

A page root draws is a walk kept across moves, advanced by what each move changed: root's own (its root walk) and, for each agent a tab watches, one walk of its page on its branch, held with the branch's one read (`:branch-reads`) and disposed with it. `seon.render.proc/kept-walk` builds one (the ctx, `seon.ctx/build`, in a reactive atom, drawn once by its layout); `seon.render.proc/advance-walk!` moves it to a later value of its branch (the ctx patched by the datoms that moved, `seon.ctx/patch`, given when the caller knows them, else `seon.ctx/moved` diffs the two values, and those datoms flushed), so a move draws the components its change reached; `seon.render.proc/branch-walk!` is an agent's, at the same db nothing at all. An agent's chat drawn from its branch (no process to ask, or none that answered) and its @ctx read it. The debug page's turn to come draws the task's list cold (`seon.context/drawn-parts`): the kept walk would be flushed over the turn the request writes and back, two moves, measured dearer (41.2 MB against 37.3 at 100 evals). A move of a kept walk that adds a member reruns the lists whose members changed (an eval: the conversation and the tiles) and the components that read them, each a cheap hit per row, so it costs about 70 contracted calls and 0.095 MB per eval of the session (one eval added: 1,448 calls / 2.3 MB at 10 evals, 7,748 / 10.7 MB at 100, 21,748 / 30.5 MB at 300); the agent's own walk (seon.repl/page-hiccup) pays the same each eval.

### The debug page is the wire request

The debug page shows what a turn put on the wire, made again from its record, never a second render (owner, 2026-11-03: "I want debug to be what we would send to the model right now"; task seon.render/the-debug-page-is-the-wire-request). A turn records its basis (`:seon.model-call/basis`): the commit that holds the turn, the main and merge base it heard, and the run's model. Everything its request is made from is a fact of that commit. ```seon.context/wire-turn``` makes the request body again there: the messages (`seon.context/render`) under the provider (`seon.context/provider-of`), on the wire by `seon.model/request-body`. The turn itself calls `provider-of` at its basis, so the turn and its replay name one provider by construction (`seon.context-test/a-turns-wire-request-is-made-again-at-its-basis`: three turns, a change of the task's config between them, each made again byte for byte).

The page (```seon.render.ui/debug```) is a timeline of the branch's model calls: a button a turn, previous, next and latest (`/at`, the view's `:at` in the render proc). One request is drawn at a time (```seon.render.ui/debug-turn``` over ```seon.render.ui/debug-input```): each message of the body in order with its JSON fields as sent, content verbatim, beside a gutter of its role, the records that made it (`seon.context/wire-turn`'s `:sources`, by `seon.model/wire-groups`, the one fold of a reply's calls) and its size; a message made by a record the request before did not send is marked new; the envelope (every field but the messages) and, opened, the body's JSON whole. A chosen turn's input is its eid, so it is drawn once and never changes. Latest, while the run goes on, is the request the next model turn would send now: drawn at the branch's head with the turn it writes first, as `seon.turn/act!` draws it, again each time the branch moves, and only while a tab watches the view. Its draw keeps the print cache (`seon.context/wire-turn`'s `:printed`) with its unit, and the next draw is given it: a request reuses a cache whose first refs are the previous call's, so latest prints only the records since, and draws the task's list cold once at the head (```seon.context/drawn-parts``` draws that list alone), the call before's parts held in the cache (`seon.render-cost-test/drawing-latest-costs-one-request`: 24.6k calls and 39.5 MB at 100 evals, from 67k and 92.7 MB; what grows is the page's rows and the cold draw's ctx). A page of no units, before any model turn, is held with none and says so. The turn to come is drawn with what the branch records the agent heard of main: a move of main the agent has not taken yet shows in the request its next turn makes, which records it (`seon.turn/act!`'s main-base facts), not in latest before it. The kept print cache is the request's own messages, held while a tab watches the view and dropped with it. A turn chosen that is no request of the branch any more (the branch replaced) is said on the page, and latest is shown. What a tab chose of a view (the rows it scrolled to, the units it opened, the turn it stepped to) is one map, the view's `:tab` in the render proc, which decides a walk whole with the view's dbs: a step on a branch that no longer moves draws the turn chosen. A turn is to come while its run has written no end on the branch (```seon.render.ui/to-come?```, over `seon.reconcile/pull-end`); an ended run's latest is its newest turn.

## How a value is printed

A value is printed in two passes, selection under one token budget and then layout, so its text and its hiccup come from one selection and every cut names the form that reads the rest.

```seon.print/print-value``` is the one entry: a value, a handle the cuts read through (``result/h3``, or a form), a budget in tokens (```seon.print/budgets```: a reply's, a part's, a form's and the context's, each a `:seon.config.render*` key), a depth and a width. ```seon.print.select/show``` selects: it allots the budget breadth before depth (every child of a collection shows before any one deepens), identity keys first, and builds a print-node tree whose cut nodes carry their continuation forms; a value whose metadata holds ``:seon.print/full`` prints whole, and ``:seon.print/budget`` raises its own budget. Rows are the exception to breadth: a collection whose members are rows (```seon.print.select/row-class```: maps, vectors or sets of one class, a sequence's strings, a map's values under keys that are not keywords) shows each whole in its order while it fits, then one cut that counts the rest and reads them (`…144 (drop 33 (get-in result/e1 [:value :classes :stale-section :rows]))`); a row at its least is a cut that shows nothing, so breadth over 177 of them printed 144 lines of `{…13 (get-in ..)}` (```seon.print.select/fill-rows```; `seon.print-test/rows-show-whole-then-one-cut`; no row past the cut is read, `seon.print-cost-test/printing-rows-costs-what-it-shows`). A keyword-keyed map is one record's attributes and keeps breadth. Members indent one column inside their opener at every depth (a flush deeper level read as its parent's); a namespace-lifted map's and an `#error`'s still indent from the group, not past `#:ns{` (`seon.print-test/a-lifted-map-indents-its-keys-past-its-opener`). ```seon.print.emit/emit-both``` lays the tree out as fipp does (begin, end, nest, line, text over one operation stream) and answers the text, and the hiccup the page's value panel shows when asked; fipp itself is only the layout's test oracle (`seon.print-test/the-layout-is-fipps`). Printing through fipp cost 45.4 KB and 16-17 µs per entry of a flat map, the printer 2.41 KB and 1.8 µs. Not this: Jolt's `clojure.pprint`, which would give that back. ```seon.print.select/estimate``` is the one sizer of tokens. `seon.print/text` (the printed text, or the error's message when even the first part does not fit), `seon.print/line` and `seon.print/prose` are the printer at a budget for text, a row and prose ([Prose](#prose-and-the-one-string-cutter), [A render is a value](#a-render-is-a-value-printed-once)). A map of two or more keys of one namespace prints as `#:ns{:a 1, :b 2}` (Clojure's `*print-namespace-maps*`): ```seon.print.select/lifted-namespace``` decides it once, when the map is classified, over every key the map holds, so the selection charges the opener `#:ns{` and the unqualified keys it lays out, the emitter reads that decision (`:seon.print/lift`) and nests the members past the whole opener, and charge and layout agree by construction. A map whose shown keys share a namespace but whose cut keys do not is therefore printed qualified, not lifted (`seon.print-test/a-lifted-map-indents-its-keys-past-its-opener`).

## One printer

There is one value printer, `seon.print`, and nothing is cut before it. A value a person or a model reads is its schema's declared render (`seon.render`) or the printer's text; a value that is not text reaching the page's serializer (`seon.web.html/html`), a one-line row (`seon.print/line`) or prose (`seon.render.ui/prose`) is printed by the printer, never `str`. The REPL answers every value by the printer, as the data it is; an error map is printed whole (its message, fix, variant and where; Jolt's diagnostics are keys of the map, printed once, [errors](errors.md#an-eval-errors-diagnostics)), and the page draws it by its declared render. An evaluation on the page (`seon.render.ui/evaluation`) is its recorded value drawn from its data, the printer's hiccup under its handle ([A value on the page](#a-value-on-the-page-is-its-structure)); shown inline it is its record printed as its reply reads, so its cut is the printer's (whole rows, the form that reads the rest), never its reply's text cut again as prose; an MCP answer that root's REPL can answer again (an op's `:again` form in `seon.server/ops`, `seon_agents`) is printed under the reply budget with that form as its handle, not whole.

`seon.render-test/one-printer-and-no-cut-before-it` reads the compiler's facts (`:form/refs` of src imported, `seon.program/live-forms`; each var's form, and each method's): every var outside `seon.print` that references `pr-str`, `prn-str`, `print-str`, `with-out-str`, `pr`, `prn`, `printf` or `clojure.pprint`'s `pprint`, `pp`, `write` or `cl-format` is named below; every var of a display namespace (`my.*`, `seon.render.*`, `seon.web*`, `seon.context`, `seon.server`, `seon.cost`, `seon.repl`, `seon.agent`, `seon.problems`) that references `subs`, `take`, `take-last` or `drop-last` is named below; and every var outside them that calls the printer with a budget (`seon.print/text`, `line`, `prose`: a cut where a value is made) is named below. An unnamed one is red, and so is a name here that no longer does it. (`butlast` is left out: destructuring's expansion references it in every function. Not covered: `str`, `print`, `println` and `format` on data, and `first` or `drop` on rows shown, which the compiler's facts cannot tell from their use on data; review reads for them.)

### Printing beside the printer: the wire

Text for the wire, storage, a digest, a file, a URL, a command line or code to evaluate is `seon.edn/encode` (EDN that reads back, whole: no print limits), and only that var prints beside the printer:

- `seon.edn/encode`: EDN for storage and the wire, whole.
- `seon.context/eval-messages`: the EDN envelope of a user message (`{:by .. :code .. :response ..}`) around a response the one printer already printed: the wire, not output.
- `seon.context/request`: a part's content hash (`hasch/uuid` of the part's `pr-str`, since its hiccup holds the Vars of its components, which no content hash reads), recorded on the model call so the next request knows what the model has of it: a key, never output.
- `seon.context/search`: the call in its last hit's `:more` (`(my.agent/search q {opts})`, q and the options as `pr-str` writes them): code to evaluate that returns the hits it left out, not output.
- `my.schema/registration`: the part of a schema form that is no EDN, and where it is, in the invalid registration's message (`pr-str` of the value and its path, whole): the message tells the agent what to quote.
- `seon.config/resolved`: the config keys a refused combination names, in its error message.
- `my.root/first-moves!`: the code text it sends an agent to evaluate (the call to `seon.judge/first-move` on a task id): code to evaluate, not output.
- `seon.server/verdict-line`: the form in its `:handle` (`(seon.server/verdict @(:conn sys) run task)`, the run and task ids as `pr-str` writes them): code to evaluate that reads the whole verdict, not output; the line beside it is the one printer's.

An agent's namespace refers `clojure.pprint`'s `pp` and `pprint` (`seon.agent/make-ns!`), as a plain Clojure REPL does (AGENTS §4, "what would a plain REPL do"); what they write reaches the model as the evaluation's `:out`, budgeted as prose. What an eval prints to `*out*` and `*err*` is its `:out` and `:err` marked verbatim (`seon.print/code`, made in `seon.repl/eval-code`), as a REPL shows them, never a string literal: printed as one, a definition's `\(` would read `\\(`, and a reader copying it back as code would copy the escapes. A check's console lines are the printer's whole text (`seon.main/shown`).

### Cut where a value is made

The places that cut a value where it is made, not in the printer, each with its reason.

- `seon.main/shown`: names a budget only to print whole (the value's ``:seon.print/full`` metadata).
- `seon.contract/plainly`: what no store keeps (a live object, a lazy seq) at the error's constructor, as the printer's text under the part budget, since printing it whole might never end; plain data of any size is untouched.
- `seon.contract/kept`: root keeps no live value of another process's error ([errors](errors.md#an-error-keeps-data)); a value past the part budget is kept as the printer's cut (`print/prose` for a string, `print/text` marked code for the rest), which says what it omitted.
- `seon.contract/problems`, `seon.task/file-declarations`: a refused value (a function's argument, a task file's entry) may be infinite, lazy or a host object, and travels on the wire as text, so its error keeps the printer's cut, which says what it omitted; the live value stays with the caller.
- `seon.turn/tell-error!`: the error a turn threw (or the missing status) becomes its message's text where the message is made, printed whole (`:seon.print/full`), never cut: the agent reads all of it, as it reads any message.
- `seon.contract/first-problem`: the offending value in a contract error's message, `print/text` under 60 tokens (the part budget is for the error's `:value`, whole in `:seon.error/problems`): one line of where, what it got and what was expected, so the reader finds the first problem without opening the map.
- `seon.turn/take!`: a send's body that is not text (another agent's value) becomes its message fact's text where the message is made, printed whole (`:seon.print/full`), never cut: the message's body is text by its schema, and the fact is what every later reader reads.
- A test child's reports: a child process prints an assertion's expected and actual at its pipe, a process boundary, and the reports are kept as it sent them; `seon.proofs/failures` keeps every one, whole (owner, 2026-10-29: "do not put any artificial limits or cuts on agents context or evals"), the facts on its var entity hold that data (`:seon.test/failures`), and the one printer prints it where it is shown (the owner, 2026-10-29: "keep everything as data until it's at a print boundary").

### Cuts in a display namespace that are not cuts of output

Uses of take, subs and the like in display code that choose what to find or read, not what to cut from output.

- `my.schema/unknown-key`: a registered key's text without its colon, to name the nearest keys of a key no schema registers by Jolt's ranking: a lookup, not a cut of output.
- `seon.render.ui/kname`: a keyword's text without its colon.
- `seon.render.ui/markdown`, `seon.render.ui/task-title`: Markdown text split into its blocks by the offsets its parse (`seon.ref/scan`) gives (a fenced block's content and a list's items too), each kept as written; a name's first letter made capital: text rearranged, nothing left out.
- `seon.context/relevance`: the first `cap` of a search's scan of each kind's nearest (`take`), the pool it scores: a score's input, never shown.
- `seon.context/item-text`: a text for relevance's lexical feature (`seon.doc/terms`) (a schema's form printed to find its words, a token's characters `subs` out of its text): an input to a score, never shown.
- `seon.context/search`: a search's answer, its first `:k` hits (`take`) with a count of the rest and the form that returns them, that form printed as code to evaluate (`pr-str` of the query and its options): not a cut of output.
- `seon.context/neighbours`: the first `cap` of who names a var or key (`take`), a bounded read of the reference graph for a score (a var every form names would cost thousands of datoms): work bound, not output.
- `seon.agent/embed-written!`: the first `:seon.config.vector/texts` of the texts due go in one `:embed` request (`take`), the rest stay due for the next: a batch bound on work, not a cut of output.
- `my.agent/file-source`, `seon.repl/form-src`: a form's own text out of its file or its reply (`subs` at a reader's offsets).
- `my.agent/lines`: the lines a to b of a text the agent asked for (`sed -n`'s range, `drop` and `take` over its lines): a selection of data it named, not a cut of output.
- `seon.repl/do-parts`: a top-level form written `(do ...)` (its text opens with `(` and the token `do`, so a reader macro that expands to do is not one) as its inner forms, each the form the reader already returned, with its exact text and leading comments from the reader's own positions in the do's text (no pattern, no cut by text), each then evaluated as a top-level form as Clojure's compiler takes them: code read, not output.
- `seon.repl/edit!`: the offsets of the old text in a definition's recorded source (`subs` rebuilds the source around the change, `line-of` counts the lines before an offset): text rearranged, nothing left out; a refused edit names every line that could be meant.
- `seon.repl/unpaired-by-line`: a refused edit's unpaired delimiters, each with the line of the new text it is on, quoted whole (`pr-str` of one source line, `subs` for the text before an offset to count its lines): code text for the agent to find, nothing left out.
- `seon.problems/old-word-hits`: a line a spelling occurs in, cut out of the texts searched together (`subs` at the line's offsets) to be checked for its old words: a cut of data, not of output.
- `my.root/task-files`: a task file's owning namespace from its file name (`subs` off the `.edn`).
- `seon.render.ui/utc-offset-ms`: parsing `:seon.config.web/utc-offset`.
- `seon.web/handler`, `seon.web/view-of`, `seon.server/mcp-reply`: parsing a request's path and a tool's name.
- `seon.context/near`: the whole line a repaired delimiter is on, the printer budgets it.
- `seon.render.proc/pass`: root's process keeps the newest `:seon.config.render.list/stream` events, and its tile (`seon.render.ui/process-tile`) draws the newest `:seon.config.render.list/history` of them: a window of data, as ctx's are.

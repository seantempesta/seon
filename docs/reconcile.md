# The reconciler

The reconciler turns main's commits into what root does next, and a task holds how its work stands and ended: root decides once, when an agent ends, and stores the answer on the task.

## A task holds how its work ended

A task's attributes on main say how its work stands, and are written only by root, when it starts the work and when it judges the agent's end: `seon.reconcile/judgment` decides once, in `seon.reconcile/judge-tx`, and `seon.reconcile/actions` reads the stored answer and derives nothing.

- **How it stands** (```seon.task/outcome-tx``` and ```seon.task/move-tx```): `:seon.task/outcome` is a compare-and-swap guarded state: `:running` (an agent works it), `:parked` (its agent waits for a message, its process stays), `:told` (root told it a verdict and it waits for the next wake), `:cap` (it spent its agent's turns: [turn](turn.md#the-cap)), `:done` (accepted on its branch), `:ready` (a merge ready for the octopus merge), `:gate` (a merge whose process tests run first), `:merged`, `:behind` (a merge main moved under), `:dead` (its agent died), `:lost` (its process was gone), `:killed` (stopped for a cancel, a hold or a changed environment), `:refused` (root refused the start: [root](root.md#holders-and-refused-spawns)) and `:closed` (judged when its task no longer ran, or held for root). The schema's properties name the sets read through `seon.contract/properties`: ```seon.task/finished``` (`:done` `:merged`: the task is done), ```seon.task/judged``` (`:ready` `:gate`: root has the next step) and ```seon.task/failed``` (`:dead` `:lost`: a death).
- **Why**: `:seon.task/reason` (the agent's own words, or root's), `:seon.task/reasons` (what the done rule said was not done, [tasks](tasks.md#the-done-rule); the same again holds the task), `:seon.task/commit` and `:seon.task/commit-error` (the merges-branch commit holding the files a merge rewrote, or why it was refused). Only when they happen: `:seon.task/merged-t`, `error`, `deferred` and `deferred-results` (the process tests the change reaches, and the gate's run of them), `gate-unread`, `changed` (the program keys the branch changed), `unmerged`, `conflicts`, `task-conflicts`, `failures`, `costs` and `waste`.
- **What judging sets**: ```seon.task/outcome-tx``` sets the attributes the end measured and retracts every other judged one (```seon.task/judged-attrs```), so a task holds its last end and nothing older; the later steps (the octopus merge, the gate, the write-back) move the outcome with ```seon.task/move-tx```, which retracts nothing. A task's earlier states are its attributes' previous values (`d/history`): the count of times it was judged `:behind` is one such query.
- **A task's agent**: `:seon.task/agent` refs the agent working it (```seon.task/start-tx``` writes both with the outcome swap). The agent holds its environment (`:seon.agent/task` `branch` `model` `holder` `max-turns` `boot` `started-ms` `ended-ms` and `taken`, the count of messages root counted taken at the judging) on main, and its own end on its branch (`outcome` `reason` `ended-turn` `error` `waste`, written by ```seon.agent/write-end!```). A retry after a failure, a wake and a load are the same agent (the same key, `<boot>/<id>`), and an agent moves between a session's tasks.
- **The end is read once** (```seon.reconcile/pull-end```): root reads the agent's end from the branch only while the agent's turn is still the one the end names (`:seon.agent/ended-turn`), so a wake that ran turns and died silently has no end, and the task is judged dead. A flight (the chain of requests of one action) is keyed by task id.

Continuing a task is a person's act: a `:cap` task waits for `:seon.agent/max-turns` to be raised and the task released again (`my.root/run!`, which retracts the reasons); no message wakes it.

The pure decision, ```seon.reconcile/judgment```, is given the index and the measured facts (the agent's end, a death, the proof results, the contract gaps, the unmerged keys, what the work caused, how far behind main it was, how many times it was judged behind, the reasons last told) and answers the outcome, the done rule's reasons, a hold for root when the task is held, and a verdict when the agent is told. The cases, in order:

- a task no longer `:running` is `:closed`; a dead agent is `:dead` and held;
- a merge task the done rule refuses nothing is `:ready`, or `:gate` when its change reaches process tests (held when this root has no checkout to run them on), and a task of any other kind is `:done`;
- an agent that ended `:waiting` or `:cap` on a task that is no merge parks (`:parked`, or `:cap`): never a hold, its session waits ([turn](turn.md#parked));
- an end the done rule refuses (`:green` or `:red` by the agent's word, not done by root's facts) is told why: outcome `:told`, with a verdict message that wakes the session; the same reasons again hold the task. A verdict of `:behind` alone is `:behind`, told again until `:seon.config.merge/max-behind` judgments; a task a merge task follows is never judged behind, since the merge task merges main into the branch and the gate tests what it writes;
- every other reason holds the task ([tasks](tasks.md#a-refused-run-is-held-for-root)).

## The reconciler's index

The reconciler reads main through an index of its tasks, agents and root, kept current by each commit's datoms and listed only once: ```seon.reconcile/index```.

```seon.reconcile/empty-index``` is the index of a db with no tasks. ```seon.reconcile/observe``` takes the index and a commit's resolved datoms (`[op e a v]`) with the db after it, and re-reads only the entities the commit touched. ```seon.reconcile/index``` of a db lists it by observing every task, agent and root entity at once; given an earlier index and its db, it observes only the watched attributes' datoms that differ (`datoms-diff`, which skips the stored subtrees both share), so the cost is the watched datoms and what changed, never the program's. The sets `:live`, `:reap`, `:kill`, `:judge` and `:merging` hold task ids (`:kill` maps a task id to its reason). The watched agent attributes include `:seon.agent/boot` and `:seon.agent/taken`: one moving re-derives every task that names the agent. The fork server hands an agent main's index the same way ([processes](processes.md#the-fork-server)).

What is asked of it: ```seon.reconcile/done?``` (a task merged into its target, or accepted on its branch), and the quiet and write-back facts `seon.reconcile/quiescent` ([root](root.md#root-causes-at-quiescence)) and ```seon.reconcile/last-commit``` (the merges commit of the last merged task, the write-back's sha). ```seon.reconcile/hairy``` decides from measured facts that a merge is too hairy to keep resolving (more conflicts than the config key, a var main deleted that the proofs or the plan's cites name, more turns without green than the config key), so the merge agent stops early and the reconciler needs no more than the task's facts.

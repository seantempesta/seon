# Checks

A check is an end-to-end proof run on the built binary against a real root, its agents and a branch of one store, through the API agents, the server and the dashboard use. `bin/check` runs the steps, `bin/test` the deftests, and `bin/prove` only the ones with no green at their digest ([merging](merging.md#a-merge-runs-what-the-change-reaches)). `bin/check` with no argument runs the steps, `bin/check --steps DIR` those a directory names, `bin/check MODE` one mode of the binary, `bin/check 100` the full run. Each step works on a clone of the checks' own store (``target/check-store``), never a root's `runs/store`, and its log is kept in ``target/check/<time>/<step>.log``.

## Running steps by hand

`mkdir D; printf 'durable\nids\n' > D/steps; bin/check --steps D` runs those steps by their own bodies in `bin/check` (`u-<step>`), each on a clone of the seeded store, writing greens to `D/green`. `D/steps-binary` is the plan's answer to whether the selection needs the binary and the seeded store (```seon.proofs/step-needs-binary?```); a directory without it seeds and uses the binary. Never write an empty `steps-binary` by hand: a step that needs the store would run on none (task `seon.check/a-selection-derives-what-it-needs-from-its-steps`).

`bin/check MODE ARGS` runs one mode on its own branch `check-<mode>` of the checks' store, seeded first and dropped before and after. It equals a step only where the step's body is that one mode with no arguments (smoke, ids, durable); `laws`, `forks`, `health`, the `lmdb-*` steps, `window`, `orphan`, `resume` and the `e2e-*` steps have bodies of their own, and some steps pass arguments (`lifecycle 10`, `idle 2000`, `fx 20`, `drain 8`).

## Modes

A step is a mode of `target/seon`, except `laws` (`bin/laws`), `lmdb-kill`, `lmdb-lock` and `lmdb-crash` (native programs on LMDB envs of their own) and `forks` (`bin/forks`, [forks](forks.md#own-suites)). Its body runs over one harness that boots root and ends on `NAME OK` or `NAME FAILED` with its exit status (```seon.check/run-check```). The harness lives in `test/seon/check.clj`, outside src's count: the binary's main (```seon.main/-main```) serves `root` and `ports` itself and loads the driver from the checkout's source for every other mode, so the release binary holds only the program.

`bin/check` runs no binary built from another tree: `bin/build` records its tree (`target/seon.tree`, ```seon.fx/tree-id```), and a mismatch is refused with `MODE FAILED (stale binary)` (`seon.check-test/a-stale-binary-is-refused`). The tree excludes `:seon.config.source/tree-excludes`. A failed seed or drop prints its output and `MODE FAILED (seed)` or `(drop)` (`seon.check-test/a-failed-seed-says-failed`).

```seon.check/modes``` maps each mode to its function; ```seon.proofs/check-steps``` is the one list of steps, and `bin/check` fails a step it does not name. What they prove, each in its function's docstring:
- **laws and contracts**: `health` (`bin/test --health`: the problem classes the checkout caused since its merge base, ```seon.problems/caused-split```, [health](health.md#checks-are-callers-of-seon); keyed by the tree and the base's tree), `laws` (`bin/laws`, the whole tree), `contracts` (every platform function carries a contract), `mg-check` ([below](#the-generative-check-is-per-function)), `test-inputs` (a test reads no clock, random, environment or deadline its digest misses unless [clocks](clocks.md) names it), `instrument`, `config` (```seon.check/config-check```);
- **tests as an agent runs them**: `agent-tests` (```seon.check/agent-tests```): `:seon.config.proofs/agent-tests-sample` tests that reach no process, lowest digests first (```seon.proofs/agent-tests-sample```), run through one agent that has drawn its page ([a test child is a fork of a live agent](merging.md#a-test-child-is-a-fork-of-a-live-agent)); keyed by ```seon.proofs/agent-tests-digest```, with a cache of its own;
- **root and its procs**: `smoke` (three agents define, test, transact; one merges, one is killed mid-eval), `system` ([the root graph](root.md#the-root-graph)), `lifecycle` (every stop leaves exactly the declared threads), `drain` (every accepted request answered across a stop), `backpressure`, `hotreload`, `idle` (an idle root with a tab open steps nothing), `threads`, `problems` (every problem class provoked and read back, [errors](errors.md#problems)), `robust`, `record`, `fx`, `mcp` ([server](server.md#mcp)), `agent-checks` (`bin/agent-checks` on the step's root, [merging](merging.md#a-session-proves-through-root)), `vectors` ([vectors](vector.md));
- **the store and recovery**: `durable` and `window` (group commit across a kill, [storage](storage.md)), `ids` (two agents never issue one id twice), `orphan` (no agent outlives its root), `lmdb-kill`, `lmdb-lock` ([failure points](failure-points.md#lmdb-locks)), `lmdb-crash` ([failure points](failure-points.md#lmdb-crash-safety));
- **tasks end to end**: the `e2e-*` steps, `swarm` and `resume` ([below](#tasks-end-to-end));
- **scale**: `scale N` agents at once (```seon.check/scale```), red past `:seon.config.machine/memory-mb`.

A check indexes none of the checkout's task files: `bin/check` exports `SEON_TASKS` as an empty task dir, read through `:seon.config.root/tasks-dir`, since those tasks cite a program the checks' example store does not hold ([references](references.md#an-entity-cites)).

The checks' store is keyed by what the seed writes; a changed seed or a store past `:seon.config.proofs/check-store-max-bytes` is remade (```seon.check/remove-store-past!```). A store `SEON_STORE` names is the caller's: opened as given, never removed.

## Contracts, armed at definition

Every platform function carries a Malli function schema, checked on entry and exit. A contracted function is checked from its definition, because a release build direct-links and inlines definitions: ```seon.contract/defn``` and ```seon.contract/defn-``` hold the checked function when the attribute map has `:malli/schema`, and ```seon.contract/defchecked``` does the same for a function value (a Scheme procedure, an FFI binding). An arity error names the calls the var declares (`seon.contract-test/an-arity-error-names-the-calls-to-copy`).

A contract whose generated inputs grow fast bounds them on the schema (`{:gen/max 4}` on a collection): this narrows what the check draws, never what the contract accepts.

The schemas are data: ```seon.contract/forms``` is every named form ([config](config.md#the-file)), ```seon.contract/registry``` compiles each once, ```seon.contract/options``` is what every contract compiles against (so an agent's REPL that binds its branch's schemas compiles against those), and ```seon.contract/valid?``` checks a value. `:seon.config.contract/instrument` decides whether contracts are on (```seon.contract/on?```) and whether each eval writes its recording (```seon.contract/record?```).

**A private function's contract is checked on each call in tests only** ([decisions](decisions.md#private-helpers-tests-only-owner-2026-11-10)). A private function is wrapped at its definition like any other, so `contracts` and `mg-check` hold it, and its wrapper reads ```seon.contract/private-checked?``` per call. `:seon.config.contract/private-checked?` is true under `--profile scripted` (`bin/test`'s shards, test roots and their agents, `bin/check`'s binaries) and false otherwise; an agent's test child turns it on at its fork (```seon.contract/check-private!```), so an agent's proofs check them while its REPL does not (`seon.contract-test/a-private-contract-is-checked-in-tests-and-not-in-production`).

A function defined at the REPL, or one whose root is redefined, is armed afterwards: ```seon.contract/arm!``` arms one var (`:armed`, `:unchanged`, `:off`, `:uncontracted`, or the error of a contract that does not compile), ```seon.contract/instrument!``` every contracted var of some namespaces (in root before the fork server forks), ```seon.contract/armed?``` asks. ```seon.contract/function-var?``` says which vars need a contract, and ```seon.contract/uncontracted``` lists those without one, which the `contracts` step holds empty. A failure is the one error map (```seon.contract/error```, [errors](errors.md)); what a contract costs: [cost](cost.md#what-a-contract-costs).

## The generative check is per function

`mg-check` has no digest of its own: each pure contracted function is a key, `mg/<qualified-fn>` (```seon.proofs/mg-roots```), digested by its reach as a test is. A key is a contracted var in ```seon.proofs/pure-nss``` or ```seon.proofs/pure-fns``` (a host binding is never handed generated arguments, [failure points](failure-points.md#contracts-over-host-objects-are-proved-by-deftests-never-by-generation)) whose contract is not a proc's step-fn. A change re-checks that contract and its callers' contracts; the rest are reused ([verdicts](merging.md#verdicts-are-a-cache), under `steps/mg/<ns>/<name>/`).

- **They run in the test shards**, with no binary: ```seon.proofs/mg-run``` requires the namespace and calls `malli.generator/check` (100 cases). The plan deals the selected keys into the shards (```test-runner/deal-mg```). Each function draws from its own seed (```seon.proofs/seed``` of the function and its digest), and a failure names the seed and a form that reproduces it.
- **The registry has a key**, `mg/registry` (```seon.proofs/mg-registry```): no `[:fn pred]` schema lacks `:gen`. Its digest is the schema registry (```seon.proofs/mg-registry-digest```).
- **A function that does not generate** (a step-fn, a `such-that` argument) is green at its digest; a selected function no longer contracted is red.
- **In the binary:** `bin/check mg-check seon.merge/f ...` checks those functions (nothing stored); `bin/check mg-check` alone and `bin/check 100` check every contract in the release binary, the one place that runs them as built.

## Tasks end to end

Each end-to-end run is an entry of data worked by one runner with real agent processes, ending on what the system observes (the reconciler's quiescence, an event, a fact on main), never on a deadline: ```seon.e2e/run```. Its entries: the six-task graph with a cancel (`calc`), a root restarted in two phases (`resume`), the merge scenarios (`conflict`, `semantic`, `hairy`, `newns`, `sibling`), a swarm over shared definitions (`swarm N M`), a task held for root and released (`held`, [root](root.md#root-causes-at-quiescence)), a real model's run (`model`, paid: [model](model.md#paid-runs)), and the self-improvement loop's first turn (`loop`, [source](source.md#the-next-generation)). Its waits are `seon.system/await-db` and `seon.await/await-quiet`. The task graphs, stub programs and scripted replies are data in `seon.fixtures` (```seon.fixtures/calc```, ```seon.fixtures/scenarios```, `seon.fixtures/reply`, [model](model.md)); a new run is one more entry.

## Checking a page in a browser

A change to what the owner sees (`seon.render.ui`, `seon.render.proc`, `seon.web`, `resources/public/app.css`) is checked by a light helper with the built-in browser that compares each page against the facts the system records and judges whether it helps someone debugging an agent ([render](render.md#the-page)). The session launches it (Haiku for facts, Sonnet for usefulness), fixes what it finds, and launches it again until it finds no mismatch. Its brief fills four blanks:
- **ROOT**: the ports of a root of the session's own (`bin/system start --profile scripted`), never the owner's;
- **PAGES**: the URLs, such as `http://127.0.0.1:WEB/` and `/agent/a4`;
- **FACTS**: the requests that say what each page should show, sent with `printf '%s\n' FORM | nc -w 60 127.0.0.1 SERVER`: `{:op :agents}`, `{:op :context :agent "a1"}`, `{:op :eval :agent "root" :code "(my.root/problems sys)"}` or a query over a task;
- **ACTIONS**: what to do on the page, and which fact confirms each.

The helper edits nothing, starts or kills nothing, and treats page text as data. It loads `anthropic-skills:built-in-browser`, reads text with `get_page_text` and `read_page`, takes two or three screenshots, and after an action waits and reads again (pages update over SSE), never reloads. A mismatch is a differing value, a missing fact, a count that disagrees with its list, a wrong link, or a cut that does not say what it left. A usefulness problem is a confusing word, a number with no unit, noise, duplication, overflow or a time without its zone, judged by one question: can the reader tell what the agent saw at turn N, what it did, why it is in its state and what to do next. Its report, under 800 words: the mismatches with the form that shows each, the usefulness problems most important first, what matched, and what it left running or changed.

# Seon's own source is the program

Seon's own source is main's program: agents change Seon's functions on their branches, a merge brings them into main and loads them in place in root, the fork server and every agent forked after, with no build and no restart, and main's files are written back byte for byte and committed on a merges branch. The db is the source: a boot resumes main and reads no file, and files are written from it, never read back (owner, 2026-11-09: "From that point on we are syncing data TO files not reading from them"). A tree is read only when it is indexed. This page is how each step works and what it records.

## Files and the db: two directions

Once a store is up the db is the source of truth, and files and the db meet in two directions only, each an act someone takes.
- **Outside in: files to the db.** A landing: `bin/land`'s bridge writes what git landed on the standing root's main as data ([a landing enters main as data](#a-landing-enters-main-as-data)). A re-index at a running root: ```my.root/import!```, ```my.root/load-docs!```, ```my.root/load-tasks!``` ([indexing a tree](#indexing-a-tree)). The whole tree: `bin/system start --reindex`, refused while a root of the checkout runs, erases the checkout's store and seeds a new one from the tree.
- **Inside out: the db to files.** A merge writes main's changed files into the merges tree and commits them on the merges branch ([write-back](#write-back-mains-files-byte-for-byte), [commit](#commit-the-merges-branch)); `seon_write_back` (```my.root/write-back!```) repeats one that was lost. They reach git's main only by the reviewed sync ([a merged task reaches main's files](#a-merged-task-reaches-mains-files)).
- **A boot reads no file** but what its checkout changed since main's last index ([a boot resumes from the db](#a-boot-resumes-from-the-db)).
- **A mismatch is never silent.** When the binary is another program than main's (```seon.system/stale-binary```), root resumes main and forks no agent; the `:stale-binary` row shows on the problems tile ([health](health.md#a-stale-binary)), and root prints `ROOT STALE BINARY` before it listens, which `bin/system start` and `bin/update` end on. Each names the same acts (```seon.problems/stale-binary-acts```): `bin/system start --reindex`, a re-index then a restart, or `bin/system next` (`seon.system-test/a-root-on-a-binary-of-another-program-forks-no-agent`, `seon.render-test/a-stale-binary-is-on-the-problems-tile-with-its-acts`).
- **A main with no source fact is never refused:** a store no tree was indexed into holds no `:seon.system/source`, so nothing is compared.

## Import: the running generation's source as main's program

A tree's source becomes main's program when it is indexed: once into a new store (its seed), and again only when a person asks; the boot as a whole is [root](root.md#boot).

`bin/system start` with no store makes one and indexes the checkout into it (`:seon.config.source/root`, from `SEON_SOURCE_ROOT`, which `bin/system` sets to its checkout); with a store it resumes it. The dirs read are `:seon.config.source/dirs`: `src`, `test`, `resources/seon/schemas`, `resources/seon/config` and `bin`. The main tree's `config/local.edn` names `.worktrees/merges` as the root merges write into, so main's working copy stays the owner's. `bin/test`, `bin/check` and the roots tests take a branch of a seeded store. `bin/update` merges the merges branch into main, fast-forwards the write-back tree, updates submodules, builds and restarts root when it must ([a landing](#a-landing-enters-main-as-data)); it fails, never skips, when the write-back tree is missing.

An index reads the tree (```seon.fx/read-source```): its files and HEAD commit, each file form by form with its exact text, the whitespace and comments before each form (`:form/lead`) and the text after the last (`:ns/tail`). Jolt's compiler analyzes each form without running it, giving the account an agent's REPL records. Root's `:seon.system/source` fact records what happened (the tree, the digest of the files read, counts, ms, or the error).

### Another tree's program, analyzed beside this image

A process may build the program of another git tree than its own (`test-runner/program-db`, refreshed from the nearest kept tree with `seon.source/refresh-tx`), while its image holds this checkout's namespaces. So:
- a dependent whose file the change removes is never read from the old db's text;
- a namespace whose file the checkout lacks (```seon.source/in-checkout?```, judged by the checkout's files) is marked loaded once analyzed, so a later `require` of it answers from the analysis; `test-runner/keep-tree!` reads it again from the target tree;
- an `ns` form that points an alias at another namespace clears that alias first (```seon.source/analyze-form```);
- a namespace's docstring is its ns form's own, `:ns/doc` (`seon.program-test/a-namespace-holds-its-docstring`), and a definition's is its form's own (```seon.program/account```), never the image var's (`seon.program-test/a-file-analyzed-keeps-its-own-docstring`). Its contract and meta still read the live var when bound (`:var/meta`, by ```seon.program/def-meta```: a test is a var whose meta holds `:test`, a macro `:macro`); task `seon.program/another-trees-contract-is-its-own`.

What still fails is one image analyzing two programs: an old tree naming a var today's image lacks or holds private (`seon.source-test/a-renamed-alias-target-analyzes-beside-the-image`).

### Indexing a tree

An index takes what the tree changed. When the files read differently from main's last index (the fact's `:digest`), only the files that differ from the tree last indexed (`:tree`) are read and brought in (```seon.source/refresh-tx```), so what main merged and the tree never held stays main's; with no last tree, or one git cannot find, the whole tree replaces main's program in one transaction (```seon.source/replace-tx```, which is ```seon.source/import-tx``` against main without the imported namespaces' forms, retracting every program entity the import no longer makes). When they read the same, nothing is written. Data (tasks, agents, config, root facts) and the program of a namespace no file holds (an example program, an agent's namespace) are untouched; history keeps the old program. The digest is of what was read, files and pins, so uncommitted edits count.

A form whose macro reads files as it expands (`seon.config/schema-forms`, `seon.config/built-text`) holds what the macro read, so when a changed file is no namespace's, every file holding such a form is read again (```seon.source/file-reading-expansions```, from the forms naming one of `seon.program/file-readers`; `seon.source-test/a-refresh-reads-again-a-form-whose-macro-read-a-changed-file`).

There are two indexes, and nothing else reads the tree:
- **The seed** (```seon.system/seed-program!```, `bin/system seed STORE`, and the first boot of a main nothing was indexed into): ```seon.system/import-tree!``` while the indexer is the store's only process, then the wiki until it states nothing more (```seon.system/wiki-tx```), then the task files (```seon.system/task-files```, ```seon.task/load-tx```), written directly on the branch (`seon.system/seed!`).
- **A re-index**, a person's call on a running root: ```my.root/import!``` (relative paths read only those files), ```my.root/load-docs!```, ```my.root/load-tasks!```, through root's writer.

Both write what ```seon.system/import-of``` computes once from main and the read (`seon.source-test/a-boot-resumes-main-and-reads-no-file`, `seon.source-test/a-moved-tree-replaces-mains-program`).

A refresh reads only what a change reaches and writes only what changed. It reads a file's dependents again only when what they read of it was lost (```seon.source/interface```: each definition's name and meta, and the text of its ns form, macros, protocols, types and inline functions), so a body edit reads one file whatever requires it. Each form is compared with what main holds (```seon.program/account-diff-tx```): unchanged writes nothing, moved writes its order and lead, changed writes its facts and retracts the stale ones. The result equals `replace-tx` of the whole tree, and each phase's cost is flat in the program's size (```seon.source-test/a-fixed-change-costs-the-same-at-any-program-size```). A constant's value is not in the interface, so changing it does not re-read dependents. When main's merged forms and a tree's edit of the same function meet, the tree wins (task ``seon.source/the-trees-commit-merges-three-way``).

A file is analyzed against its own ns form, loaded or not: the ns form of a namespace whose lib the process has not loaded (`clojure.core/loaded-libs`) runs first, and files are analyzed in require order (```seon.source/load-order```). Running an ns form loads the libraries it requires, so a file whose libraries the binary cannot load does not import.

Indexed forms carry `:form/source true`: a binary built from the tree holds them compiled ([a merge loads in place](#a-merge-loads-in-place)). Schemas are program too: each schema resource is a file entity (`:file/path`, `:file/text`) and one `:schema/key` entity per entry, its form as EDN text; an entry is a branch's change when its form differs from the binary's (`seon.program/schema-changes`). Every resource imports and writes back byte for byte (`seon.source-test/import-then-write-back-is-a-zero-diff`).

The functions: ```seon.fx/read-source``` reads; ```seon.source/read-forms``` keeps each form's text and lead; ```seon.source/accounts``` analyzes through ```seon.source/analyze-form```; ```seon.source/text-tx``` and ```seon.source/import-tx``` write `:ns/file`, `:ns/tail`, `:form/lead` and `:form/source`; ```seon.source/schema-tx``` a schema resource; ```seon.source/file-ns``` and ```seon.source/source-files``` name what was imported. ```seon.program/load-diff!``` and ```seon.program/load-changes!``` skip the imported text.

### A boot resumes from the db

A boot opens main and resumes it, reading no file but those its checkout changed since main last indexed it ([below](#a-boot-catches-up-with-its-checkout)). In ```seon.system/boot!```, while root is the store's only process: the store opens; a main never indexed nor booted is seeded once (the wiki and task files always, the program when root has a source tree); main's config is held (```seon.program/hold-config!```) and its program digested (```seon.program/program-digest```); the fork server forks, builds each agent's schema registry from main's entries (`seon.fork-server/warm-start`) and loads main's test namespaces. Nothing is loaded into root's image: root runs the program its binary was built from, and its boot fact states it beside main's ([below](#the-binary-records-its-program)). What the binary needs that has no facts is baked in at build: the shipped config (```seon.config/built-text```), the system declaration (```seon.graph/built-text```, read by ```seon.graph/read-decl```) and `deps.edn`'s roots (`seon.fork-server/dev-classpath!`). Proofs: `seon.source-test/a-boot-resumes-main-and-reads-no-file`, `seon.system-test/a-boot-on-a-binary-of-another-program-holds-mains-config`, `seon.system-test/a-boot-reads-no-file-a-commit-broke`.

### A boot catches up with its checkout

Sessions edit a checkout's files from outside, so a boot of a root with a source tree that is not a seed catches main up (```seon.system/catch-up```, before main's program is digested). ```seon.fx/changed-since``` reads git's diff of the tree main last indexed against the files as they are, untracked files included, submodules left out (a pin is a build input, judged [below](#the-binary-records-its-program)). The changed files are indexed as a landing is (```seon.system/landed-tx```), in one transaction that moves the source fact to the tree as it is. Three kinds are left out and named, and the fact keeps its tree so the next boot reads them again: a file that does not read as its reader reads it (```seon.fx/unreadable```); task files ```seon.task/load-tx``` refuses; a file a merged task main holds unsynced also changed ([below](#a-merged-task-reaches-mains-files)).

Root prints `ROOT CAUGHT UP n files` and `ROOT CATCH-UP LEFT OUT path: why` before listening. When the catch-up reaches the binary's code or a build input (`ROOT STALE BINARY`), `bin/system start` builds and starts root again, once. `:seon.config.root/catch-up-on-boot` false resumes main reading no file; a test's root sets it so (```seon.test-store/start-args```). Proof: `seon.source-test/a-boot-catches-up-with-what-its-checkout-changed`.

### The binary records its program

`bin/build` records beside the binary the program of the tree it was built from (`target/seon.program`, by the binary's `built-program` mode, ```seon.system/built-program```): the tree indexed as a seed indexes it into a store the build keeps, and that index's ```seon.program/program-digest```. The kept index is the build's cache, never read by root: one store under `target/seon.index-<schema digest>` (```seon.db/kept-store!```), named by the code that made it (```seon.program/index-code```), so a change to that code indexes the tree again into a new store. A program digest is a function of the program alone, since every program entity's id is a content id ([storage](storage.md#ids)), so a seed and a build agree on it. The record also holds the git tree (`:tree`) and the ids of its forms (`:forms`): a process holds a form of main compiled only when its id is one of them (```seon.program/held?```), so a form main changed since the build is loaded over the binary's text, and ```seon.program/program-differs``` names it until it is (`seon.source-test/a-form-main-changed-is-loaded-over-the-binarys-text`).

At boot root reads the record once (```seon.program/binary-program```) and writes it on its source fact (```seon.system/booted-source```) beside the tree main was last brought to from outside, which only an import or a landing moves; what agents merged since is main's own and never a mismatch. Agents key their test results by the inputs of the files the boot read: `bin/system start` computes them (the binary's `inputs` mode, ```seon.fx/inputs```) into `runs/root-inputs.edn`, and the boot hands them on with the config in force (```seon.agent/test-inputs```), so agents share greens with every checkout of that tree (one digest whichever runner plans it is still a task, `seon.prove/one-digest-whichever-runner-plans-it`). A root under a test's starter keys by its binary's record. Proofs: `seon.system-test/what-agents-merged-into-main-is-no-stale-binary`, `seon.problems-test/a-root-on-a-stale-binary-is-a-problem`, `seon.source-test/a-builds-kept-index-holds-the-program-a-fresh-index-holds`.

**A binary is current for a tree** when what differs between the tree it was built from and that tree reaches none of the code root runs from its binary and none of what the build bakes in (```seon.system/binary-current```, the one rule for the build, the spawn refusal and the stale-binary row). What differs is git's changed paths (```seon.fx/tree-diff```, kept under `target/tree-diffs/`): a pin, `native/`, `deps.edn`, `bin/build`, `.gitmodules`, the schemas, the shipped config or `system.edn` is not current; a source file is not current when a form whose text changed (```seon.fx/tree-file```) defines a var of ```seon.program/root-reach```: the closure over main's reach graph from ```seon.program/root-roots``` (`seon.main/-main`, system.edn's procs and effects, the renders schema entries name, the config's symbols), never entering an agent's body (`seon.repl/run!`), which runs main's program from the db. A changed path no rule places is not current, nor is a binary that recorded no tree; a main with no source fact is. Tests, the wiki, task files and `bin/` scripts never make a binary stale (`seon.source-test/a-binary-is-current-for-a-tree-unless-what-differs-reaches-root`). Every reader asks this rule: `bin/test` builds only when the plan's `out/build` names why (```test-runner/build-text```); `bin/check` takes that `out/build`; ```seon.system/booted-source``` hands agents the inputs of main's tree when the binary is current for it. A prove's plan writes the tree's inputs beside the binary (`target/seon.inputs`), so a root booting on that tree runs no git ([machine](machine.md#processes)).

### A landing enters main as data

A Claude session's landing changes files in git, so it enters main through a temporary bridge until Seon agents write the system's updates themselves (owner, 2026-11-09: "this is a temporary system -- I want seon agents writing updates inside the system and pushing them to disk"). After `bin/land` moves main in git, root writes on main the facts of every changed text file (`bin/land`'s bridge, also `bin/land --bridge REPO OLD NEW PORT`: one root eval of ```seon.system/landed-tx```, which runs ```seon.system/changed-tx```, ```seon.source/refresh-tx```, ```seon.source/modes-tx```, ```seon.doc/load-tx``` and ```seon.task/load-tx``` as a seed does, and moves the source fact to the landed tree). No task, agent or judge takes part: the change was proved before git landed it. `bin/update` then brings main into the write-back tree, and the system keeps running when nothing calls for a restart (```my.root/landed!```, ```seon.system/restart-for```): the running binary is current for the landed tree and was not stale at boot, so the change already loaded in place and root writes its source fact again (`UPDATE OK: kept running on tree T`). Anything else builds and restarts root, saying why (`restart: ...`), and every agent of the old boot ends. A path with no facts (native code, `deps.edn`, `system.edn`, a gitlink) is a build input. Proofs: `seon.source-test/a-landing-keeps-the-system-running-only-when-nothing-calls-for-a-restart`, `seon.source-test/a-landing-through-the-bridge-is-a-zero-diff`.

### A program file

A file the program holds that is no namespace is one file entity (`:file/path`, `:file/text`, `:file/mode`), named by the allow-list `:seon.config.source/things`, a path pattern to a kind (```seon.config/file-kind```). A kind differs only by data (```seon.source/file-kinds```), so the import, the write-back and the merge's keys (```seon.merge/stated-content```) have no branch per kind:
- `:schema`: each entry `[:schema k]` ([schemas at the REPL](#schemas-at-the-repl)).
- `:config` (`resources/seon/config/default.edn`): each entry a `:config/key` entity holding `:config/form`, its value's exact text, keyed `[:config k]`, written back with every comment kept (```seon.source/config-text```; `seon.source-test/a-config-entry-writes-back-only-its-own-bytes`). A new key's entry holds no comment; its schema says what it means. What a process does with them: [config](config.md#a-process-holds-its-branchs-config).
- `:fixture` (`test/seon/*.edn`, ```seon.source/fixture-tx```): one entry, its text, which a test reads through ``my.branch/file``, never from disk.
- `:script` (`bin/*`): one entry `[:script path]`, its text and mode, listed under `:scripts` by ``(my.branch/changes)``; ```seon.source/script-tx``` derives `:seon.script/says` and `:seon.script/usage` from its lead comment, for reading (```seon.render.ui/script```).

An edit of a script or the config file goes to the branch ([agent](agent.md#changing-a-file); ```seon.source/edit-tx```); a new script comes in by the import. The disk does not move until the write-back.

Before a commit writes a file, ```seon.fx/git-commit``` reads it as its reader does (```seon.fx/unreadable```), and an edit of a script does the same: the config validates, EDN and Clojure read as their readers read them, a script passes its interpreter's syntax check. What does not read refuses the whole commit and names the file; the merged change stays on main with its task's `:seon.git/commit-failed` error until a later merge fixes it and ```my.root/write-back!``` writes it.

### A file that does not load

An index that meets a file it cannot load writes nothing and says which file and which commit last worked: ```seon.system/import-tree!``` and ```my.root/import!``` ask ```seon.system/unimportable``` first (each allow-listed file reads, ```seon.fx/unread-text```, and the config it would state validates, ```seon.program/config-refused```). A namespace's file that does not analyze takes the same path through ```seon.source/tx-of```. A boot reads no file, so a commit that broke one stops nothing (`seon.system-test/a-boot-reads-no-file-a-commit-broke`). A process's start reads only its `--config` layers ([config](config.md#a-process-holds-its-branchs-config)); a built-in config that does not validate refuses naming each key (`seon.source-test/a-branchs-config-is-its-own-and-reaches-the-next-process`).

## A merge loads in place

A merge of main runs at once where main's program runs: root's writer, the fork server (`seon.fork-server/server-step`, so every agent forked after inherits it compiled) and an agent merging main call ```seon.program/load-changes!``` with the commit's tx-data. It loads each live form the commit asserts except the binary's own text, and removes each definition left pointing to no form (`seon.source-test/a-form-imported-into-a-loaded-namespace-is-loaded-not-unmapped`). A restart loads main's every form but the binary's own (```seon.program/load-all!```); a resumed agent loads its branch's difference (```seon.program/load-diff!```), which reads only the datoms that differ (```seon.program/diff-plan```).

One load adds what a change reaches: the forms a changed macro expanded in (```seon.program/dependents```) and the forms whose contracts or code name a changed schema entry, loaded so their contracts re-arm (```seon.program/schema-dependents```). A protocol or record needs none on Jolt. A redefinition reaches the binary's compiled callers because a direct-linked call reads its var's linked binding, and a contracted definition is never spliced (`bin/check hotreload`). `bin/check loop` proves a merge in place on a clone.

### A process holds the tests only when it runs them

Root holds `test/` as program facts (reach digests, plans and task pages read them) and evaluates none of it: root's writer calls `seon.program/load-changes!` with `{:tests? false}`, leaving out every namespace read from a file outside `:seon.config.source/program-dirs` (```seon.program/test-nss```). Tests run in an agent's test child and in `bin/test`'s shards. The boot fork server loads them once at its start (```seon.fork-server/main```): a namespace whose live forms are all its file's as imported is loaded whole by `require` through Jolt's AOT cache (`JOLT_CACHE_DIR`, [shared build caches](#shared-build-caches)), any other form by form (```seon.program/required!```), then each commit's changes; load errors reach root as `:load-errors`. Every agent and test child forked from it inherits main's tests compiled, as shared pages ([cost](cost.md#how-we-measure)). `bin/build seon` warms the compile cache with them (```seon.check/warm-tests```). A form an import replaces is loaded wherever the process has seen it. Proofs: `seon.source-test/root-loads-the-program-and-leaves-test-namespaces-unevaluated`, `seon.agent-test/root-holds-no-test-code-and-its-agents-hold-mains-tests`.

## An agent changes code at its REPL

An agent changes the program by `in-ns` and `defn` at its REPL: each form it evaluates there is its branch's change. Redefining a macro also recompiles, in that process, every form that expanded it (```seon.program/reload-dependents!```; ```seon.repl-test/a-macros-redefinition-reaches-the-forms-that-expanded-it```). `(ns-unmap 'n 's)` removes a definition: the eval sees the var gone and retracts it on the branch (`:unmapped`, `seon.repl/unmapped`), refusing nothing. `require` and `load-file` load as in Clojure and record nothing. The agent's working directory is a scratch dir with no repository above it (`:seon.config.agent/cwd`, made by ```seon.fork-server/main```): editing source files is not how Seon develops.

## A form's account is the program's facts

A form's account is what the compiler said of one top-level form, and the program is these accounts as entities: a form entity (its exact text, namespace and place) and, for each definition it made (a var, a method, a protocol extension, a namespace), a pointer to it. Nothing reads a form's text to learn what it is.

An eval is accounted by what the analyzer saw and what the run did: ```seon.program/tap```, bound around the eval, collects each analyzed unit and each var's prior root (```seon.program/root-of```); ```seon.program/set-vars``` reads back the vars whose root changed; ```seon.program/account``` joins them, and answers nil for a form in a scratch namespace (```seon.program/scratch-ns?```: `user` or `^:scratch`) or one that changes nothing. It records calls of ```seon.program/banned``` vars (`seon.merge/mutations` reports them). A contract is stored as EDN text (```seon.edn/encode```, ```seon.edn/decode```) when ```seon.program/edn-value?``` holds, else as written.

Identities are content: ```seon.program/form-id``` is the namespace and hasch's hash of the exact text (with an occurrence number for a repeated text in a file); a method is its ```seon.program/method-key```, an extension its ```seon.program/impl-key```, and ```seon.program/pointer``` names the attribute by which each kind points to its form. ```seon.program/def-eid``` finds a definition's entity; ```seon.program/def-ref``` names it in a transaction (`seon.program/ns-tid`, `seon.program/form-tid`); ```seon.program/form-tx```, ```seon.program/def-tx```, ```seon.program/account-tx``` and ```seon.program/record-tx``` write a form, its definitions, an account and an eval's record. ```seon.program/meaning``` is what a definition says of itself that wiki text relies on (contract and docstring), and ```seon.program/meaning-changes``` answers, before a transaction, each var whose meaning changes and the sections citing it.

A form is live when it defines nothing or some definition still points to it (```seon.program/live?```); otherwise it is superseded. ```seon.program/form-row``` reads a form as the loader and the merge read it; ```seon.program/live-forms``` every live form. ```seon.program/attr-namespaces``` are the attributes that hold the program, which a commit must touch to move it ([merging](merging.md#the-test-service)). ```seon.source/defining-ids``` gives a file at an old commit the ids an account would give, without analysis, so a wiki baseline loads nothing.

## A var is private as the tree analyzed holds it

A file is analyzed against the running image's namespaces, aliases and macros, but whether it may name another namespace's var is the **tree's** answer, never the image var's. Analysis changes no var of the image: ```seon.source/tree-private``` is the analysis env's `:private?` (Jolt's `jolt.host/ctx-for-ns` asks it first): for a namespace the import's files define it answers by the defining form (`defn-` or `^:private`), for another program namespace by the tree's `:var/meta`, and nil for one the tree does not define (clojure.core, a library). The tree is every file the import read across all its rounds, not one round's (`seon.source-test/a-dependent-read-again-takes-the-privacy-of-every-file-the-refresh-read`, `seon.source-test/a-var-the-import-makes-public-may-be-named-by-a-later-file`). Analysis changes the image only where it must: a namespace's `ns` form and a macro's definition run.

## Tests run by reach

A test runs only when something it reaches changed since it was last green, in any checkout. ```seon.program/graph-index``` gives each test a reach digest of:
- its own form, its namespace's forms that define no var (the ns form, fixtures), and every live form their `:form/refs` reach (a var to the form that last defined it; a multimethod's methods and a protocol's extensions);
- every schema entry a reached contract names, and what that entry's form names on (the renders its properties declare: `seon.program-test/a-render-a-schema-entry-declares-is-in-its-tests-reach`);
- the checkout's inputs with no program facts (`:env`, ```seon.fx/inputs```) and the values of the config keys its reach reads (```seon.program/config-reads```, ```seon.fx/config-input```), below;
- the vars data names that root resolves by name (`seon.fx/declared-refs`: system.edn's procs);
- the whole tree only when what it reaches reads the checkout's files (```seon.program/file-readers```: `slurp`, `file-seq`, `io/resource`, `seon.fx/read-source`, `seon.doc/load-dir-tx`; ```seon.program/tree-readers```).

**A green records what its run read** (```seon.proofs/reads-key```): the functions it called (```seon.profile/reads```), and, until reads of config, files and schema are recorded as they happen, the reads besides code its reach digest takes (graph-index's `:reads`), each at its digest in the plan's reads index (```seon.program/reads-index```), beside the verdict as `reads.edn`. A later plan reuses the green while every read still has its digest, whatever else moved (```seon.proofs/read-digests```). `bin/test`'s plan hands its shards the reads index and each test's static reads (```test-runner/write-reads!```).

A test whose reach runs the binary does it only through `seon.test-store/binary-sh` and is digested by what it reaches. What the digest misses (a file or binary its forms do not name) is the full run's to catch (`bin/test --all`). A direct constructor call `(T. x)` reaches the type's methods (`seon.program-test/a-types-method-is-in-the-reach-of-what-constructs-it`); a literal name passed to `resolve`, `ns-resolve` or `requiring-resolve` is a reference (```seon.program/resolved```). A db that does not declare an attribute the graph reads holds none of its datoms, and its forms are read with none (`seon.program-test/a-base-cut-before-an-attribute-has-a-reach-graph`). bin/test's kept program store reuses a tree only under the same importer code, so no form keeps an edge an older importer missed.

**How a digest is computed** (Bazel's and Nix's action keys): forms and schema entries are a graph, and each strongly connected component (```seon.program/components```, Tarjan's) gets once a Merkle digest of its forms' own digests (each form's `:form/code`, [below](#what-a-test-takes-of-a-forms-text)) and the components it reaches, with whether it reads the tree or reaches a process (`:seon.config.source/process-vars`). One pass answers every test, O(forms + edges) (```seon.program-cost-test/the-reach-walk-is-one-pass-whatever-the-keys```); ```seon.program/reach-rows``` reads each attribute once over its index, never a form's text. The graph is a value (```seon.program/reach-graph```); a change to it is ```seon.program/reach-update```: the live forms the two values differ in (```seon.program/live-ids```), each re-edged only where its edges can have changed, and only the changed components and their ancestors re-folded, giving the digests a rebuild gives (```seon.program-test/an-update-gives-the-digests-a-rebuild-gives```). A schema entry added, changed or removed is the same update (```seon.program/schema-moves```, ```seon.program-test/a-schema-entry-added-changed-or-removed-is-updated-not-rebuilt```), as is a namespace gaining its first test; a namespace losing its last test still rebuilds.

**The graph holds its tests' index** (```seon.program/reach-indexed```, read with ```seon.program/index-of```), derived data regenerated whenever it is not held ([derived data](data-modeling.md#derived-data-is-a-cache-never-relied-on)). ```seon.program/reach-step``` keeps the answers a change cannot move and names the others `:stale`, so an updated graph answers only for the stale (```seon.program-cost-test/an-index-is-recomputed-for-what-moved-only```, ```seon.program-test/an-index-held-by-the-graph-moves-with-it```). The fork server holds main's graph with its index under an agent's inputs (```seon.fork-server/graph-at-fork```), so an agent's first turn finds its base's index made. bin/test keeps the last plan's graph beside its kept store (`reach-graph.fasl`, `test-runner/reach-graph-of`) and brings it current by `reach-update`.

**References and quoted names.** A form's `:form/refs` (```seon.program/unit-account```) are the vars its IR resolves, plus each qualified symbol a macro's template quotes and each macro the form calls (```seon.program/macro-uses```). Any other quoted name is data (```seon.program/quoted-names```, `:form/quoted`): a proc or render named in data, a form sent to another process. ```seon.doc/callers``` reads both. In a namespace that holds a test, quoted names are edges too, since a test hands names to what runs them (`(cost/proof {:of 'ns/f})`, an agent's eval; ```seon.program-test/a-name-a-test-hands-over-quoted-is-what-it-reaches```). A string constant holding a slash is read once as the code it may be (```seon.reader/read-text``` after ```seon.reader/forgive```), and its qualified names are quoted names; its qualified keywords count only when it opens with a paren (```seon.program-test/a-var-a-string-names-moves-the-test-holding-it```, ```seon.program-test/a-var-an-eval-string-names-moves-the-test-that-sends-it```). A name is recorded whether or not its namespace exists, so a form's facts are the same however the program was analyzed (```seon.program-test/a-quoted-name-is-data-whatever-the-process-analyzed```). A form's `:form/keywords` are the qualified keywords its constants and contracts name, so a key's readers are one AVET seek (```seon.doc/callers```, `(my.agent/callers :ns/key)`) and a changed schema re-arms the forms naming it (```seon.program/schema-dependents```).

**Processes.** A form using a process var or a binary var has an edge to the processes' entry vars (`:seon.config.source/process-entry`: `seon.turn/work!`, ```seon.repl/serve!```, and of ```seon.server/op-answer``` only the methods of the ops its requests send, its `:form/ops`), so a test that starts an agent is digested by what that process runs for it (```seon.program-test/a-test-that-starts-a-process-reaches-the-program-it-runs```). **A test that starts a root takes what root runs** ([decisions](decisions.md#a-test-that-starts-a-root-takes-what-root-runs-owner-2026-11-10)): ```seon.program/root-digest```, the digest of ```seon.program/root-forms```, the same reach ```seon.system/binary-current``` asks, never entering ```seon.program/agent-body```. A change to root's writer, reconciler, fork server or boot reruns every process test (```seon.program-test/a-change-to-what-root-runs-moves-every-test-that-starts-a-root```).

**Running.** `bin/test [NS ...]` (and `bin/prove`, which adds the `bin/check` steps) reads `:seon.config.source/dirs` as program facts, as root does (```test-runner/program-db```: ```seon.source/import-tx``` into an empty store, else the kept tree brought current by ```seon.source/refresh-tx```). A tree's branch exists only once its import committed, so a failed import leaves the store as it was, and a test namespace with no tests in the program db fails the plan by name (```seon.proofs-test/a-failed-import-leaves-no-branch```). It reuses every result recorded at its digest and runs the rest ([verdicts](merging.md#verdicts-are-a-cache), [merging](merging.md#a-merge-runs-what-the-change-reaches)). An agent holds main's whole suite, so a test namespace opens no store at load. Its run selects by the same digests: ```seon.agent/test-plan``` is `seon.proofs/plan` against the main it forked from: the task's proofs, plus every test whose digest moved, which is what `seon.reconcile/done-explain` reads. A test that reaches a process of its own runs only when named or a proof; the others are listed as deferred. A selected test green at its digest on root's main is reused, not run, since an agent's digests take its root's recorded inputs (```seon.agent-test/an-agents-greens-and-a-checkouts-are-one-store```). `(my.agent/prove)` runs the judge's selection at the agent's REPL (`seon.agent/run-tests-forked`, mode `:judge`).

### What a test takes of a form's text

A test's digest takes a form's code, not its comments, layout or docstring. ```seon.program/form-ids``` gives a form its id (its namespace and the hash of its exact text, which names the form) and its `:form/code`: the digest of its namespace and the form as the reader read it, encoded as EDN without `:line` and `:column`, gensym numbers renumbered by first appearance, a name's metadata kept, and the docstring after the name of a `def`, `defn`, `defn-`, `defmacro`, `defmulti`, `defprotocol` or `ns` form left out when more follows it ([decisions](decisions.md#the-test-system-runs-inside-seon-the-outside-is-thin-wrappers-owner-2026-11-10)). A form stored without `:form/code` is taken by its id (```seon.program-test/a-comment-or-whitespace-edit-moves-no-test```).

A test that reads the program's text takes the src class, `:seon.env/src`: one whose reach calls ```seon.test-store/kept-program-store``` or ```seon.contract/uncontracted```, or whose namespace calls `clojure.repl/doc` or names `:var/doc` or `:ns/doc` (```seon.program/reach-step```'s `:docs`). Two readers it cannot see stay the full run's: `(:doc (meta v))`, and a src function reading docstrings for a test. The src class is the checkout's files, so an agent's own edit does not move it.

A config key added is no input of a test that does not read it: a `:map`'s fields that are config keys are neither its edges nor its digest's (```seon.program/less-config-fields```); a key's own entry says whether the config map lists it (```seon.program/config-facts```), so removing it or editing its entry moves the tests that name it, and its value moves the tests that read it (```seon.program-test/a-config-key-added-moves-no-test-that-does-not-name-it```). A form of a test's namespace naming a whole-registry var (```seon.program/registry-walkers```) takes the schema class; one in src does not, and a whole-registry walk in src stays the full run's.

**File classes and pins.** `:env`, every test's input, is the files git sees that hold no program facts and no class of their own (native/, test fixtures) and the per-test tick bound (`:seon.config.agent/test-ticks`, `-floor`, `-factor`; a test's history is never in the digest, [merging](merging.md#a-tests-tick-budget)). `:config` is taken by what a reach reads, each entry one digest: the config in force key by key (place keys left out: ports, `:seon.config.agent/cwd`, `:seon.config.root/main`, `store-path`, `runs-dir`, `:seon.config.source/root`, `dirs`, `branch`, `generations-dir`), and a digest of each file class a reach reads (```seon.program/env-class-readers```; every class for a test that reads files or runs a process, the shipped config's read named in ```seon.program/env-readers```):
- `:seon.env/bin`: `bin/` and the checkout's root files git and the scripts read (`.gitmodules`, `.gitignore`, `.mcp.json`); a root `.md` file is `:seon.env/docs`, with `docs/`;
- `:seon.env/web` (web/, resources/public), `:seon.env/system` (system.edn), `:seon.env/deps` (deps.edn);
- `:seon.env/src`, above;
- `:seon.env/schemas` (resources/seon/schemas), taken by a reach that walks a db's whole schema: ```seon.reconcile/index```, ```seon.merge/content-datoms``` and ```seon.db/entity-index```, which chooses an entity's schema by the attributes it holds; `seon.config/baked-schema-forms` is not a reader of it;
- each pin but the runtime's (```seon.config/pin-class```: its files as they are), taken by the namespaces a reach references (```seon.program/config-reads```).

**The runtime's pins** (`:seon.config.source/runtime-pins`: Jolt and Chez) are in `:env`, so a bump moves every digest and reruns everything once (```seon.program-test/a-runtime-pin-moves-every-digest```). A schema key a form names as a literal keyword is an edge to its entry (```seon.program-test/a-schema-key-a-test-names-is-an-edge-to-its-entry```), so an entry's edit moves only the tests that reach it. A test reads what it or its process wrote (a root's log) through ```seon.test-store/output```, never a bare `slurp`. Proofs: ```seon.program-test/a-test-digest-takes-only-the-config-keys-it-reads```, ```seon.program-test/a-test-takes-only-the-file-classes-its-reach-reads```.

**What stays.** A test whose own namespace reads files takes the whole tree, so any tracked edit reruns it (about a hundred tests run in every prove for this). The clean answer is per-test read tracking (record the files a test opened, keep them with its verdict, check them at lookup); it is not built, and neither is a hand list of exempt readers. What the digest cannot see: a file read or a var resolved by a name built at run time, a config key or schema looked up by a computed key, a library used only through interop. The daily full run is the net.

### A result is a function of its digest

A green is reused forever, by any checkout or agent, so everything a result depends on is in its digest or out of the test.
- **Seeds.** A generative check draws from a seed derived from its digest (```seon.proofs/seed```, `:seon.config.proofs/seed-salt`; ```seon.proofs/test-seed```, bound by ```seon.proofs/run-tests!```; each mg-check contract by its own reach digest, [checks](checks.md#the-generative-check-is-per-function)), so a failure prints a reproducible seed. A randomized property test draws `:seon.config.proofs/seeds` seeds: one in an automatic run, five under `bin/test --all`.
- **Work, not time.** A cost proof is judged on ticks, bytes and calls (```seon.cost/exact```, [cost](cost.md)); CPU time is shown, never red.
- **Dependencies as they are.** A submodule with uncommitted edits is its class by content (```seon.fx/pin```); a clean one is its gitlink.
- **The tree held.** A shard stores results only if the tree is the plan's before and after its run.
- Still open: shard co-residency (a test leaving state behind), the kept stores in `target/`, the inherited environment, renders named by symbol in schemas, and deadlines and picked ports (which can only turn a result red).

## Schemas at the REPL

An agent changes a schema the way `defn` changes a function: `(my.schema/register! k form)` on its branch. ```my.schema/registration``` judges it against the whole population (the binary's forms with the branch's changes and this one): a form that is no EDN, does not compile, or declares an attribute Datahike cannot store is refused (`:seon.schema/registration-refused`), and nothing is written. Accepted, the entry is written on the branch, in its resource (for a new key, the resource holding most keys of its namespace), with its Datahike declaration, so the branch can store its facts at once. A key in a scratch namespace gets no resource and is no program.

The agent's REPL binds malli's dynamic registry to its branch's population before each form (`seon.repl/wrap-registry`, `seon.contract/options`), recompiled whole since a map compiled against an old key keeps it (about 5 ms), and reused while the branch's changes are equal. Every process loading a db's forms compiles them against that db's schemas (`seon.program/load-forms!`, `seon.agent/run-tests-here`). ```seon.program/schema-changes``` and ```seon.program/schema-registry``` derive the population; ```seon.contract/registry-of``` compiles it.

The merge carries an entry per key, `[:schema k]` -> `{:form text :file path}`: two branches changing different keys of one resource merge clean, one key changed two ways conflicts at its key. Applied to main, the Datahike declarations come in the same transaction (`seon.program/schema-declarations`), and the resource is written back like a namespace's file (`seon.merge-test/a-schema-entry-merges-per-key`).

A registration re-arms the functions the process holds whose contracts reach the changed key (`seon.program/rearm!`, by the reach closure): one armed by `seon.contract/arm!` over its kept raw root (`seon.contract/rearm!`), one armed by `seon.contract/defn` by evaluating its definition again. One that no longer compiles is named under `:seon.schema/rearm-errors`. A key no schema registers is answered with the nearest that do (`my.schema/unknown-key`), never nil.

## Write-back: main's files, byte for byte

```seon.source/file-text``` builds a namespace's file: its live forms in order, each after its lead, then its tail. A form recorded at a REPL has no lead, so a blank line goes before it; a redefinition takes the place and lead of the form it supersedes. Forms are written in load order (```seon.program/load-order```: each after the forms defining what it references, unless both came from the file in a working order), so a file loads fresh as the image ran, and a file already in order is written byte for byte (`seon.source-test/a-helper-recorded-after-its-user-is-written-before-it`, `seon.source-test/the-write-back-of-a-file-is-one-pass-over-its-forms`). With no merge, import then write-back is a zero diff (`seon.source-test/import-then-write-back-is-a-zero-diff`). After a merge only the files its changes touch are written (```seon.source/changed-files``` of what ```seon.writer/octopus-merge``` merged, on each member's answer as `:files`; ```seon.source/files``` builds them, ```seon.fx/write-file``` writes one). A changed wiki page is drawn from the store by ```seon.doc/files``` as ```seon.doc/markdown``` does (`seon.doc-test/a-loaded-page-draws-back-as-its-file`).

A schema resource is written entry by entry with rewrite-clj (```seon.source/schema-resource-text```, ```seon.source/schema-file-text```): each changed entry replaced in its old layout, each removed key deleted with its line, each new key appended; every other byte as it was (`seon.source-test/a-changed-schema-entry-rewrites-only-itself`).

## Commit: the merges branch

Main is the source of truth, and syncing it to disk is an act of its own. With `:seon.config.source/write-back-on-merge` true (the default) the reconciler (```seon.reconcile/reconciler-proc```) asks for the write-back after each octopus merge; with it false a merge writes no file, its task names what waits under `:not-on-disk`, and ```my.root/write-back!``` (`seon_write_back`) commits those files from main as it is now. A namespace made at a REPL takes a file by its name (```seon.source/namespace-path```). Files neither under `:seon.config.source/dirs` nor on the allow-list have no route; ```seon.fx/uncommitted``` shows them in ``(my.branch/changes)`` and `seon_done`'s answer.

The `:git` effect (```seon.fx/git-commit```) commits the files on the merges branch (`:seon.config.source/branch`) with a message naming each merged task (```seon.source/commit-message```), by git's plumbing (blobs with the modes main holds, ```seon.source/modes```; a tree; `commit-tree`; `update-ref` only from the head it read), so no working tree moves. A branch a worktree has checked out (the standing root's ``jolt/merges`` in `.worktrees/merges`) is committed through that worktree instead, so its files, index and HEAD move together, and a change of that tree's own refuses the commit (`seon.fx-test/a-write-back-onto-a-checked-out-branch-leaves-that-tree-clean`). Worktrees share git's refs, so a worktree's roots commit on `jolt/seon-merges-<worktree>` (`#seon/own-branch`). The sha is written on each merged task as `:seon.task/commit`; a failure is its `:seon.task/error`, a `:seon.git/commit-failed` naming the files (```seon.reconcile/commit-tx```), which quiescence names as a root cause (```seon.reconcile/root-causes```) and a later commit clears.

## A merged task reaches main's files

A merge commits on the merges branch, never on main, so a Seon agent's merged work reaches main's files only through a session's review (owner, 2026-11-10: "agents updating the db and then us reviewing and syncing to the file system"). Until then the task is an `:unsynced` problem: a merged task whose entry main's files still declare (```seon.problems/unsynced?```, its `:seon.task/declared`), naming the files its changes touch (```seon.problems/changed-paths```) and the act that syncs it. That act, ```my.root/sync!```, commits those files from main, with the task's entry removed from its task file (```seon.source/task-file-text```), onto `jolt/sync-<name>`, a new branch from git's main (```my.root/sync-req```), its message saying `Completes:` for each task. A session reviews that branch and lands it with `bin/land`, whose bridge retracts the entry and closes the row. A task made in the store with no file entry has no row (task `seon.reconcile/a-store-made-tasks-merge-reaches-mains-files`).

## What isn't in the program yet

What `:seon.config.source/dirs` names moves by branch, with the wiki beside it; a `spit` writes the disk, which a branch holds nothing of until an import (task `seon.source/seon-files-move-by-branch`).

## The next generation

A binary is a cold-start artifact, built only for what cannot load in place: a Jolt, Chez or dependency pin, `deps.edn`, native code. Root asks for it with ```my.root/build!```: the `:build` effect (```seon.fx/build```) makes `<:seon.config.source/generations-dir>/<sha>` a worktree detached at main's last merges commit (`bin/worktree --at`, its target/ cloned and the [compile caches shared](#shared-build-caches)) and runs `bin/build seon` there; root's `:seon.system/generation` fact records `{:commit :checkout :binary :ms}` or the error (also an `:effect` problem, `seon.error/asked-tx`). `bin/system next` asks root for ```my.root/next-generation``` (the tree and ```my.root/resume-args```, `--set` arguments for the same store, main and source on the new tree), stops root and starts that tree's `target/seon`. `bin/system start` with the resume args restarts the same binary on the same store. Either way main's merged forms load at boot. ```seon.reconcile/generation``` and ```my.root/generation``` read the fact; ```seon.e2e/loop-turn!``` is the loop `bin/check loop` runs on a clone, changing ```seon.generation/generation```. The next generation is checked where it is used, not in the suite; old generations' trees stay until the owner reclaims them.

## Dependencies

Fetching a library is an outside-world effect with one owner: the `:deps` effect, performed by ```seon.fx/resolve-deps```, which passes a deps map (``:mvn/version``, ``:git/sha`` or ``:local/root``) to Jolt's `jolt.deps/resolve-deps` and answers `{:value {:roots [...]}}` or `:seon.fx/unresolved` ([failure points](failure-points.md)). It writes only the shared caches under `HOME` (`.m2`, gitlibs, `.cpcache`), so a second resolve needs no network. The asker records the outcome and decides what to load; there is no `add-deps` at the REPL. Effect kinds are declared under `:fx` in `resources/seon/system.edn`, and `seon.fx/procs` makes their owners.

## Shared build caches

`bin/env` points Jolt's three compile caches at the main tree's ``target/cache/`` (found from git's common dir), so every worktree and generation shares them: `build` (`JOLT_BUILD_CACHE_DIR`), `runtime` (`JOLT_RUNTIME_CACHE_DIR`) and `aot` (`JOLT_CACHE_DIR`, one artifact per namespace keyed by its source, its requires' keys and what its compile read). No key holds a checkout's path: an AOT artifact's `.res` sidecar names the files and directories its compile read relative to the project root (Jolt ``jolt/cache-records-relative``), so two checkouts whose reads differ each miss once after the other builds, never loading the other's artifact. Entries are published by temp+rename, so concurrent builds are safe. `JOLT_CACHE_GENERATIONS` (4) runtimes are kept, and the AOT cache is kept under `JOLT_CACHE_MB`, read from `:seon.config.build/jolt-cache-mb`, least recently used first (Jolt's `aot-prune-to-budget!`; task `jolt.loader/the-cache-bound-is-tested-at-the-targets-size-before-release`). `bin/worktree` clones none of them, and `bin/cache-smoke` checks that every checkout names the same directories. An unchanged `bin/build seon` takes about 25 s with every unit a hit. `bin/env` also exports `JOLT_COMPILER_OPTIONS` (`{:image-fn-forms false}`): Seon writes no state image, so nothing registers fn literals' sources for one (task jolt.backend/image-registration-is-opt-in).

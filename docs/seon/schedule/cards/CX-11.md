# CX-11 The model's history shows each pass's test step

Ledger row CX-11 (group B/A). Spec: agent-loop.md §3.5 (each test request carries the eval request id, so its results
are recorded with that eval request; the next reply shows real results). Task: `seon.turn/a-model-pass-never-sees-its-test-step`
(CX-1 already shows the proofs' current status in the block; this card puts the step into the exchange, as the MCP
reply has it). Lane: Sonnet.

## What exists

`seon.turn/test-step` builds `:seon.turn.loop/tests` (`summary`) and offers it only on the MCP reply channel; nothing
links a test run to the call row that caused it (`seon.test.run` has no eval-request member). TX-0 stamps
`:seon.db.transaction/eval-request` on every transaction from the request map.

## What becomes true

The step's test requests pass the pass's call-row id as their eval request, so their recording transactions carry it
(TX-0). The exchange text of a model call row (CX-1's `model-context`) ends with the shown text of that pass's test
summary, derived from the runs whose transactions name the call row: the same `seon.turn/summary` data the MCP reply
shows, printed by `seon.sci.eval/shown-result`. Stored test facts do not change after recording, so the exchange stays
byte-identical across passes.

## Functions

- CHANGE `seon.turn/run-proofs`, `run-reaching`, `continue-queue`: pass the pass id as the request's eval request.
- ADD `seon.turn/step-of [database turn-id] → [:maybe :seon.turn.loop/test-summary]` reading those runs.
- CHANGE `seon.context/model-context`: append `(step-of …)`'s shown text to each model exchange that has one.

## Proof

`seon.cluster.turn-test/a-model-exchange-shows-its-test-step` (tagged `seon.turn/a-model-pass-never-sees-its-test-step`):
two fixture-model passes, the first a `defn` that leaves the proof red; the second request body's exchange for pass 1
contains the red proof's name under the step summary.

## Cost

One query per exchange over transactions naming it; follows the agent's test requests.

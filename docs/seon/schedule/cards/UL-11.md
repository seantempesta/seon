# UL-11: List the namespace cycles behind `requiring-resolve` (diagnosis)

Ledger row UL-11 (group T). Source: `clojure-way/clojure-way-opus-clojure-way.md` §2 item 12 and §3.1, research agenda
item 11. Model: Sonnet. No source change.

38 `defonce … (delay (requiring-resolve …))` cycle-breakers (e.g. `src/seon/db.clj:52-66`, `schema.clj:42-58`,
`repl.clj:27-32`, `render/value.clj:65-73`) and 114 `requiring-resolve` calls hide namespace edges from clj-kondo, the
reload order and the agents' `callers` reads.

## Work

1. One script (Babashka or a JVM `eval_clj` read of source, never loaded into default): with rewrite-clj or clj-kondo's
   analysis (`:var-usages` plus the literal symbol argument of each `requiring-resolve`), list every call as
   `{:from ns :to ns :var sym :file f :line n :cached? (inside a defonce delay)}`.
2. Join with the `:require` graph (clj-kondo `:namespace-usages`) and mark each edge that would close a cycle if it were
   a `:require`.
3. Per cycle, name the move that dissolves it: pass the function as an argument at the one call site, or move the
   shared function down into the namespace both require. Name the moved function and its new namespace.

## Output

`docs/research/agent-platform/2026-10-08/ns-cycles/ns-cycles.md` (table: cycle, edges with `file:line`, proposed move)
and the script beside it. Then one shrink row per cycle in the ledger (root adds them; this card does not edit the
ledger).

## Proof

The script runs from the checkout in under a minute and its table counts 38 cached breakers (or states the difference
from the census with each `file:line`).

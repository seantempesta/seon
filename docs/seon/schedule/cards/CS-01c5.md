# CS-01c5: Read a referenced doc section

Depends on: REF-1 (`seon.ref/document`). Group D. Model: Sonnet.

Owner: "We should also be able to reference docs via file refs and have those be pulled in for research." Every REPL
evaluation is its own context unit under the per-evaluation display budget and there is no block budget
(`review/owner-rulings.md`), so the block only lists a doc reference with its size (CS-01c3) and offers one read

## What is true at HEAD (probed on default, JVM mode)

- `my.fs/read` (`src/my/fs.clj:39`) reads a byte window of a working-tree file through `effect/request!` and the
  `seon.fs.jvm/read` capability, inside the declared `:seon.config.fs/roots` (`seon.fs.jvm/path-plan`,
  `src/seon/fs/jvm.clj:97`, refuses any other path). A doc reference names committed content instead: the loaded
  commit's source directory or a pinned extract, which is immutable, outside the working tree and outside those
  roots. Its unit is a Markdown section, not a byte window. So `my.fs/read` is not reused for the read; the new
  function sits beside it in `my.fs` and shares nothing but the namespace.
- `(seon.fs/source-directory)` (`src/seon/fs.clj:218`) is `data/source/6a244149d…`; it holds `AGENTS.md`,
  `docs/seon/architecture/README.md`, `.agents/skills/repl/SKILL.md` and `dependency-pins.txt`.
- `seon.test.cache/gitlink-digests` (`src/seon/test/cache.clj:178`) parses `dependency-pins.txt` and hashes each pin;
  `seon.test.cache/gitlink-pins` does not exist yet (probed: "No such var").
- Each pin is extracted at `data/source/pins/reference-code-<project>/<rev>/` (`script/seon/operator.clj:868`).

In `seon.ref`:

```clojure
(defn locate
  "A based path's file in the loaded commit, with its pin for a `reference-code/<project>` path, or nil."
  {:malli/schema [:=> [:cat :seon.ref/path] [:maybe :seon.ref/location]]}
  [path] ...)
```

Base = first segment. `reference-code`: project = second segment, `rev` =
`(get (seon.test.cache/gitlink-pins (seon.fs/source-directory)) (str "reference-code/" project))`, file =
`(io/file (.getParentFile (io/file (seon.fs/source-directory))) "pins" (str "reference-code-" project) rev rest)`.
Any other base: `(io/file (seon.fs/source-directory) path)`. A file that `.isFile` →
`{:seon.ref/file (.getPath file)}` plus `:seon.ref/pin {:seon.ref/project p :seon.ref/revision rev}` for a pin; else nil.
A path that normalizes outside its base (`..`) is nil.

```clojure
(defn section
  "The Markdown section `reference` names, with the headings below it and its size, or an error naming the nearest."
  {:malli/schema [:=> [:cat :seon.ref/reference-text] [:or :seon.ref/section :seon.ref/section-error]]}
  [reference] ...)
```

`reference` is the text an agent writes: `"docs/seon/architecture/README.md#boot"`, parsed with `java.net.URI`
(path and fragment). Body:

1. `locate` the path; nil → the error below with `:seon.ref/nearest` = the Markdown file names in the nearest
   existing parent directory (`.list`, sorted), never a recursive walk.
2. `text` = `slurp` of the file; `doc` = `(seon.ref/document text)` (REF-1; cached by content digest).
3. No anchor → the document: heading = the first level-1 heading's text (else the path), lines from the end of
   front matter to the end. Anchor → the heading whose `:seon.ref/anchor` equals it; its section runs from its line
   to the line before the next heading of the same or a higher level (smaller number), else to the end. No such
   heading → the error with `:seon.ref/nearest` = every heading's `{:seon.ref/anchor :seon.ref/heading}`, those
   sharing the longest prefix with the requested anchor first (`sort-by` on the common-prefix length, descending;
   then document order).
4. Section text = those source lines, `(str/join "\n" (subvec (str/split-lines text) (dec start) (dec end)))` (lines
   are 1-based, REF-1): the author's
   Markdown exactly, never re-rendered.
5. `:seon.ref/below` = the headings exactly one level deeper inside the section (the next level present), each with
   its anchor, heading text and tokens; the agent digs with the same function and that anchor.
6. Tokens: `(seon.ai.tokens/estimate section-text)`, and for each child its own span.

Errors return the installed constructor's value:
`(seon.error.refusal/diagnostic (java.util.Date.) :seon.ref/section 'seon.ref/section {…})`, with
`:seon.error/message` "No such file at this reference." or "No heading with this anchor.", `:seon.ref/path`,
`:seon.ref/anchor` when given, `:seon.ref/nearest`, plus `:seon.ref/section-missing :file | :heading`.

In `my.fs`:

```clojure
(defn section
  "The section of a referenced doc: its heading, Markdown text, the headings below it, its size and its pin.

  ## Examples

  (my.fs/section \"AGENTS.md#data-and-contracts\")
  (my.fs/section \"reference-code/malli/README.md#quickstart\")

  ## Errors

  A missing file or heading answers an error naming the nearest files or headings."
  {:malli/schema [:=> [:cat :seon.ref/reference-text] [:or :seon.ref/section :seon.ref/section-error]]}
  [reference]
  (ref/section reference))
```

Large sections are not cut here: the value goes to the value printer, which elides `:seon.ref/text` at a line end
with its dig form, and `:seon.ref/below` offers the smaller reads.

## Schemas (`seon.ref.edn`)

```clojure
:reference-text [:string {:min 1}]
:file :string
:project :string
:revision [:string {:min 40 :max 40}]
:pin [:map [:seon.ref/project :seon.ref/project] [:seon.ref/revision :seon.ref/revision]]
:location [:map [:seon.ref/file :seon.ref/file] [:seon.ref/pin {:optional true} :seon.ref/pin]]
:tokens [:int {:min 0}]
:child [:map [:seon.ref/anchor :seon.ref/anchor] [:seon.ref/heading :string] [:seon.ref/tokens :seon.ref/tokens]]
:section [:map [:seon.ref/path :seon.ref/path] [:seon.ref/anchor {:optional true} :seon.ref/anchor]
          [:seon.ref/heading :string] [:seon.ref/text :string] [:seon.ref/tokens :seon.ref/tokens]
          [:seon.ref/below [:vector :seon.ref/child]] [:seon.ref/pin {:optional true} :seon.ref/pin]]
:section-missing [:enum :file :heading]
:nearest [:vector [:or :string [:map [:seon.ref/anchor :seon.ref/anchor] [:seon.ref/heading :string]]]]
:section-error [:merge :seon.error/base
                [:map [:seon.ref/section-missing :seon.ref/section-missing] [:seon.ref/path :seon.ref/path]
                 [:seon.ref/anchor {:optional true} :seon.ref/anchor] [:seon.ref/nearest :seon.ref/nearest]]]
```

`:seon.ref/text` here is the section's Markdown; REF-1's `:seon.ref/text` on a source is the text read for
references. Both are the text being read; one key, one meaning ("a Markdown text").

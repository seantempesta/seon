# PB-10: The checked writer validates its report once

Ledger row PB-10 (group E). Tasks `seon.db/every-commit-validates-its-write-report-three-ways` and
`seon.db/hot-total-predicates-run-hundreds-of-millions-of-times` (`resources/seon/tasks/seon.db.edn:116-124`).
Source: `defn-why/defn-why.md` finding 7 (14 MB per `defn`: `write-owned-values-error` 6.8, `write-digest-error`
2.1, `write-report-error` 1.6; `transaction-report-datom?` 21 k calls for 157 datoms). Owner answer AU-Q12 option 1:
validate the final report once through Datahike's report hook, inside the slice that deletes the duplicate
normalization. Model: **Opus** (the writer). Host-bound: throwaway check; measure on the lane's branch first.

## What exists (verified at `1fcdbf47a`)

- Seon already uses Datahike's one final-report hook: `seon.db/prepared-write` sets
  `[:tx-meta :datahike/validate-report]` to `#(validate-write-report projection %)` (`src/seon/db.clj:5667`), which
  our Datahike fork calls once per commit (`validate-report`,
  `reference-code/datahike/src/datahike/db/transaction.cljc:1225-1235`, called at `:1297`; any non-nil value
  rejects). The three "ways" are not three hooks: `validate-write-report` (`db.clj:5411`) calls `write-report-error`
  (`:5324`), which calls `write-owned-values-error` (`:4153`) and `write-digest-error` (`:5273`), plus
  `retention-report-check`, `render-declaration-touched?`, `write-render-target-error`,
  `report-identity-attributes`, `written-declaration-identities` and the arity gate (`:4561`, `:4697`).
- **The cause of the 21 k calls.** Each of those private functions is armed, and each contract names
  `:seon.db/transaction-report` (`rg -c ":seon.db/transaction-report[] ]" src/seon/db.clj` finds 15 contracts), whose
  `:tx-data` is `[:vector :seon.db/transaction-report-datom]` (`resources/seon/schemas/seon.db.edn:295-309`) with the
  leaf `[:fn … seon.db/transaction-report-datom?]` (`:299-301`). Every armed call re-validates every datom of the
  report: the task's own number, a trivial 28-datom commit calling the predicate 560 times, is 20 armed report
  validations × 28 datoms. The leaf predicate is itself armed and profiled (the second task), so each element also
  pays a wrapper.

## Design (smallest composition)

Validate the whole report once, at the hook's entrance; below it, pass the value that was validated.

- `validate-write-report` keeps `:seon.db/transaction-report` in its contract: that is the one full validation per
  commit.
- Every private function called from it declares the report as a new name
  `:seon.db/checked-report` (in `seon.db.edn`):
  `[:map {:description "A transaction report validate-write-report already validated whole; below it, the shape only."} [:db-before :seon.db/database-value] [:db-after :seon.db/database-value] [:tx-data vector?] [:tempids {:optional true} map?] [:tx-meta {:optional true} map?]]`
  (Malli's built-in `vector?`/`map?` predicate schemas: O(1)). Read the current `:transaction-report` definition
  and keep every other member it declares, with the same O(1) shape.
- The leaf predicate is called raw in its schema: read how the projection resolves `seon.db/transaction-report-datom?`; if validation reaches the armed Var root, register and
  resolve the function's original (`mi/-f->original`) so a collection's elements pay no wrapper. If it already
  resolves the raw function, the count after the first change shows it; then this bullet is a no-op.
- AU-Q12's "duplicate normalization of submitted values": `write-value`, `write-many-values`,
  `write-attribute-error`, `write-map-error`, `write-entity-value` (`db.clj:3701-4075`) normalize each submitted
  value before the report exists, and `write-report-error`'s datom loop (`:5338-5360`) checks each asserted datom's
  value again against the same attribute plans. Measure which one refuses first on the existing refusal tests
  (`seon.db-test` write refusals); keep the report-side check (it sees transaction-function output too, "one final
  check for … all expanded transaction-function output") and delete the submitted-side walk that duplicates it, or
  report with numbers why both are needed. This deletion is the half AU-Q12 answered; the schema-name change above is
  PB-10 proper.

## Cost

Expected: report validation follows the datoms written once (plus the output contract), not datoms × armed calls.
Measured parent: 14 MB per `defn` (defn-why), 560 predicate calls for 28 datoms, `validate-write-report` 30 ms per
commit (the task). Done-when from the task: a trivial commit's validation under 5 ms and a `defn`'s under 30 ms;
report parent and change for both with `seon.profile/begin`/`explain`.

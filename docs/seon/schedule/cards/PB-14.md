# PB-14: Whole-program cache entries follow a change, not the program (diagnosis, Astra)

Ledger row PB-14 (group E). Source: `storage-audit/storage-audit-opus.md` finding 4 (waste row W-17). Model: Astra
(performance diagnosis), fixing what it finds in follow-up rows.

Each adoption adds one whole-program entry to `:seon.task/tasks-tx` (~10 MB; its key holds the whole forms map and
every task file's text, `src/seon/task.clj:243`), `:seon.fn/population-targets` (8.6 MB), `:seon.schema/projection`
(9.7 MB) and `:seon.cluster/derivation-world` (9.5 MB): 129 MB more in 4.5 minutes, and every change pays a
whole-program derivation (the over-bound `adopt-entities!`, `publish!`, `index!` rows).

## Work

1. On a throwaway root (never default's JVM), adopt one one-line change; record per `seon.cache` kind the entries,
   bytes, misses and load ms added (`seon.cache/status` before and after).
2. For each kind that added a whole-program entry: what its key holds, what its derivation reads, and what it should
   be keyed by to follow the change (a content digest of only the inputs the derivation reads, or an incremental
   update from the previous entry).
3. A table and one proposed fix row per owner (file, function, key, expected cost).

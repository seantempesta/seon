## Schema
In `seon.cluster.eval.edn`, beside `:ordinal` (`:59`):
```edn
:agent-ordinal [:tuple {:seon.db/unique true :seon.wake/context-inert true
                        :description "[agent-id n]: the evaluation's place in its agent's history, assigned once by the writer."}
                :seon.agent/id [:int {:min 1}]]
```
and `[:seon.cluster.eval/agent-ordinal {:optional true} :seon.cluster.eval/agent-ordinal]` in `:receipt` (`:61-`).
Bridge: `:tuple` → `:db.type/tuple` (`src/seon/schema/datahike.clj:143-146`), `:seon.db/unique` →
`:db.unique/value` (`:191`). First step: transact two equal tuples on a disposable branch and confirm the second
refuses (not yet probed, design-notes §6).

## Functions
- ADD `seon.db/last-agent-ordinal`
  `{:malli/schema [:=> [:cat :seon.db/database-value :seon.agent/id] [:int {:min 0}]]}` `[database agent-id]`.
  `(d/rseek-datoms database :avet :seon.cluster.eval/agent-ordinal [agent-id Long/MAX_VALUE])`
  (`reference-code/datahike/src/datahike/api/specification.cljc:794`), accept the first datom only when
  `(= :seon.cluster.eval/agent-ordinal (:a d))` and `(= agent-id (first (:v d)))`, answer `(second (:v d))`, else 0.
  The unchecked seek returns another agent's tuple or another attribute (design-notes §6, measured).
- CHANGE `seon.turn/receipt-settle-batch-call` (`src/seon/turn.clj:969`, contract unchanged): after its `mapcat`,
  read the agent id once (run → `:seon.turn/agent` → `:seon.agent/id`), `n0 (db/last-agent-ordinal database agent-id)`,
  and append `[:db/add [:seon.cluster.eval/id id] :seon.cluster.eval/agent-ordinal [agent-id (+ n0 i 1)]]` for the
  batch's evaluation ids in request order. Assign ONCE per batch call, never inside `receipt-settle-call` (`:1445`):
  inner calls share one database value and would duplicate numbers.
- CHANGE `seon.turn/record-evaluated-call` (`:1317`, contract unchanged): in its write branch only, the same
  assignment over `evaluations` in order; the identical-replay branch stays `[]`; `recorded-evaluation` (`:1249`)
  does not compare the ordinal.
- CHANGE `seon.eval/of-agent` (`src/seon/eval.clj:17`, contract unchanged): replace the four-clause query with
  `(d/index-range database {:attrid :seon.cluster.eval/agent-ordinal :start [agent-id 1] :end [agent-id Long/MAX_VALUE]})`
  (`specification.cljc:824`, `api/impl.cljc:295`), then `db/pull-many` with the caller's selector, in that order.
  `:t` comes from each evaluation's `:seon.cluster.eval/id` datom tx as today. Direct `datahike.api` is allowed here
  only through `seon.db`: add the index-range call inside `last-agent-ordinal`'s sibling
  `seon.db/agent-evaluation-ids [database agent-id] -> [:vector :int]` (contract
  `[:=> [:cat :seon.db/database-value :seon.agent/id] [:vector :int]]`), and `of-agent` calls it.

Library seams: `:db.fn/call` sees ops spliced before it (`reference-code/datahike/src/datahike/db/transaction.cljc:1055-1062`);
the serialized writer needs no lock.

## Proof
`seon.turn-test/evaluation-ordinals-follow-writer-order` (new). Table over: an agent whose id sorts before and one
after every other agent; one multi-form batch; two passes across SCI and JVM through `seon.mcp/call`; an identical
replay; a conflicting replay (refuses). Assert on data: `(map (comp second :seon.cluster.eval/agent-ordinal) (seon.eval/of-agent db id))`
equals `(range 1 (inc n))`; the replay adds no datom. Never timing.
Convert `seon.context-selection-test/selection-references-terminal-evaluations-in-writer-decided-order` into this
test's file only if S4-07b3 has not yet deleted that file (it is deleted there).

evaluations (index range + pull). Read measured composed cold ~5 ms / 6.8 MB at 200 exchanges; budget code H.

# CS-01c3: The block shows a referenced doc

Depends on: REF-1 (`seon.ref/references`), CS-01c5 (`seon.ref/section`, `my.fs/section`). Group D. Model: Sonnet.

A path that is not code is a relative reference whose first segment names its base: the checkout (`docs/…`,
`AGENTS.md`, `.agents/skills/…`) or `reference-code/<project>` at its pinned revision, with an optional `#heading`
anchor (`review/owner-rulings.md` "References"; `references/references.md`). One resolution covers both bases. The
block lists the reference (path, heading, pin, size in estimated tokens) and offers one read operation; it never
carries the content (no block budget: the agent pulls a section by evaluating the operation, CS-01c5).

## What is true at HEAD

- `:seon.task/must-read` holds symbols only (`seon.task.edn:11`, `:seon.program/edge-symbol`), so a path reaches the
  block as a code span or link in the intent: `` `reference-code/malli/README.md#quickstart` ``,
  `` `AGENTS.md#data-and-contracts` ``.
- After REF-1, `seon.ref/references` already reads such a span as `{:seon.ref/path … :seon.ref/anchor …}` (its first
  segment is an entry of `(seon.fs/source-directory)`: probed `AGENTS.md`, `docs/…`, `.agents/skills/…` and
  `dependency-pins.txt` exist there) and answers it `:unresolved` until this card.
- After CS-01c5, `seon.ref/section` answers the section with `:seon.ref/heading`, `:seon.ref/tokens`, optional
  `:seon.ref/pin`, or an error with `:seon.ref/section-missing :file | :heading`.

## Functions

```clojure
(defn- resolve-path
  "A based path with an optional anchor as a block entry: heading, size, pin and its one read operation, or a problem."
  {:malli/schema [:=> [:cat :seon.ref/candidate] [:or :seon.ref/resolved :seon.ref/problem]]}
  [{:seon.ref/keys [path anchor]}] ...)
```

Body: `reference` = `path` plus `"#" anchor` when present; `found` = `(section reference)`.
Section → `(-> found (dissoc :seon.ref/text :seon.ref/below) (assoc :seon.render/operations [(list 'my.fs/section reference)]))`.
Error with `:seon.ref/section-missing :file` → `{:seon.ref/problem-kind :unresolved :seon.ref/path path}`; `:heading`
→ `{:seon.ref/problem-kind :anchor-missing :seon.ref/path path :seon.ref/anchor anchor}`. The section's text is
computed and dropped: the size is the section's, and the parse is cached (REF-1), so resolving costs one file read.

`seon.ref/references` routes path candidates to `resolve-path` (REF-1 left that branch answering `:unresolved`).

## Schemas

Add the path members to `:seon.ref/resolved` (accretion; all optional, the name entries carry none of them):

```clojure

[:seon.ref/heading {:optional true} :string]
[:seon.ref/tokens {:optional true} :seon.ref/tokens]
[:seon.ref/pin {:optional true} :seon.ref/pin]
```

## Proof

``"Read `reference-code/malli/README.md#quickstart` and `AGENTS.md#data-and-contracts` first."``; assigned; block
through `seon.mcp/call`. Assert each entry's path and heading, a positive `:seon.ref/tokens`, a 40-character revision
on the first and no pin on the second, and that each operation's form, evaluated through the same call, answers a
`:seon.ref/section`. A second task naming `reference-code/malli/NO-SUCH.md` shows `:seon.ref/problem-kind :unresolved`;
a third naming `AGENTS.md#no-such-heading` shows `:anchor-missing`. (In a throwaway check JVM the source directory is
the candidate archive, which carries `AGENTS.md` and `dependency-pins.txt`.)

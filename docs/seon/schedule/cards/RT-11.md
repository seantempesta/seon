# RT-11 The automatic merge works root's held request; a stop stays on it

Ledger §3.28 RT-11 (group M; amends MA-12 and merge.md §5). Lane: Sonnet after MA-12.

## What becomes true
- With `:seon.config.merge/auto-merge` on, root's work derivation runs the schedule handler's `merge!` for a held
  merge request that has no merge run recorded before it opens a model turn for it (derived from the request:
  `:seon.merge/run` absent). A provider-less root merges; a model root gets a turn only for what stopped.
- A stop (unmerged identities, red tests, failed integrity) keeps the request held by root, its reasons on the request
  and in root's block. No message to root.
- A stop the merge flow cannot classify (unknown evidence, a norm over 10 s, a refusal outside the declared stop
  reasons) asks root (RT-7) about the request: the question's decision says what to do.

## Functions
- CHANGE MA-12's handler: iterate root's held requests (`seon.task/held`) instead of reading open requests separately
  (the listener on assignments, RT-1, is the "listen before deriving" registration).
- CHANGE `seon.turn/next-agent-work` (root only through data: a held request with no run while auto-merge is on
  derives no model turn).
- CHANGE merge.md §5 "Stop": the message is deleted (done in this landing's spec revision).

## Deleted
The stop message to root (merge.md §5).

## Proof
`seon.merge-policy-test/a-stopped-automatic-merge-stays-held-with-no-message` (new): a red reaching test stops an
automatic merge; root holds the request, its stop reasons are on it, root has no new message, and
`next-agent-work` for a provider-configured root answers `:open`; with no stop, root holds nothing.

## Cost
The handler's read is RT-3's `held`, O(held).

## Dependencies
MA-12, RT-3, RT-7, RT-9.

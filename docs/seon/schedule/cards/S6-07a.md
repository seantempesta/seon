# S6-07a Each agent gets its own stop deadline; a missed join is answered

Ledger row S6-07a (group B). agent-loop.md §3.8: "The caller's lifecycle deadline passes explicitly into `disarm!`
and `stop-graph!`, each agent with its own slice." Inventory: `docs/research/agent-platform/2026-10-08/inventory/q14-exit-deadline.md`
(I-Q14) §1-§3. Lane: Sonnet. Cited at HEAD `e7f120672` (I-Q14's lines: `cluster.clj:3490-3570`, `agent.clj:904-930`,
`:1465-1530`).

## Decisions (I-Q14 §3's open sub-questions, decided here)
1. **One shared start, every agent stopped first.** `seon.cluster/stop-flows!` first requests stop and interrupt
   of every agent (and the view and db<->flow), then joins each against the same deadline `start + bound`. A stuck agent
   no longer starves the others: they were all asked to stop at `start`, so their joins finish early; only the stuck
   one reaches the deadline. (Today each agent is stopped and joined in turn under one shared deadline,
   `cluster.clj:3557-3561`, I-Q14 finding 2.)
2. **Every caller passes a deadline.** `disarm!`'s `:seon.await/deadline-nanos` becomes required. Callers without one
   today (entrance B: `stop-owned-graphs!` `agent.clj:904-921`, `arm!` `:1269`, ~40 test sites) compute it with a new
   helper from the configured stop bound. The bound is a dial (owner: every limit is a dial) under a new name for the
   changed meaning: `:seon.config.agent/stop-time-limit-ms` (`[:int {:min 1 :seon.config/dial true}]`, shipped default
   the current backstop value from `config/default.edn`, `rg -n 'turn-completion-backstop-ms' config/default.edn`).
3. **A missed join is answered, never thrown.** `disarm!`'s contract becomes
   `[:=> [:cat :seon.agent/stop-request] [:or :nil :seon.await/timeout-error]]`; `stop-graph!` returns the
   `:seon.await/timeout-error` that `seon.flow/join-graph!` answers (`flow.clj:136`) instead of throwing
   `turn-completion-failure!`'s ex-info (`agent.clj:1402`, I-Q14 finding 3); `disarm!` records no fault (finding 4: the
   entrant boundary records). `stop-flows!` collects the first timeout and answers it after attempting every join.

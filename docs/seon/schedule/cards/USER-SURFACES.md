## Data and people

Sean is an ordinary agent, addressed by `:seon.agent/id`, with his own branch, SCI context, evaluations and messages. Survey is the agent he is talking to. Neither the route's recipient nor a missing sender means “the user.” A browser opens an explicit session; two conversations between Sean and Survey remain separate. The page is Sean's HTML layout render, supplied that session, and inter-renders Survey's own recorded data through its declared faces. It does not manufacture a second transcript or copy Survey's record onto Sean.

**Target schemas, not installed declarations.** Register these open maps in the owning schema population before bodies; compile with `malli.core/schema` and its cached `malli.core/validator`. Identity comes from `seon.id/id`. Relationships use `:seon.db/ref`; components declare their component schema. Session facts are ordinary data, never program merge inputs.

| Producer / schema | Members and consumers |
|---|---|
| New `seon.render.web/create-session!` → `:seon.session/session` | Required `:seon.session/id` (identity string), `:seon.session/user` and `:seon.session/agent` (peer refs to user and interlocutor), `:seon.session/layout` (qualified renderer symbol), `:seon.session/slots` (ordered vector of owned `:seon.slot/slot` refs); optional `:seon.session/pin` (peer ref to a recorded surface's source entity). Page, input adapter and canvas selector consume these facts. No agent-level viewing/pin mirror. |
| Session owner → `:seon.slot/slot` | Required `:seon.slot/key` (keyword, unique within session), `:seon.slot/select` and `:seon.slot/render` (qualified function symbols). Vector position is order; key is identity within the session and stays stable on reorder. A selector receives database + session identity, returns its named data schema; its render declares that same schema. No selector DSL or stored HTML. |
| `seon.cluster.message/delivery` → `:seon.message/message` | Add optional peer ref `:seon.message/session` for compatibility; session sends require it at their request producer. Existing `:seon.message/from`, `:seon.message/to`, content and `:seon.message/caused-by` retain meaning. | Page acquisition → new `:seon.session/render-request` | Immutable database, session id, viewing `:seon.agent/id`, existing render profile and SCI context; no connection/writer in selectors or renders. Resolve refs to the existing agent/message/evaluation schemas, not bespoke display copies. |

Session creation admits participants and ordered slots together. The writer validates the complete owning session on slot edits; required peer refs cannot silently disappear. Pin is optional: retracting it or its source returns to latest selection. Root's ordinary message delivery carries the referenced session and its owned slots with session messages so the complete value resolves on the recipient branch; the user's branch owns layout/pin changes. Delivered copies are historical message context, never another authority for the current layout. Legacy messages without a session stay legacy history, never guessed into a conversation.

## Rules, render pairs and owners

**Layout and batteries.** `seon.render.web/page-result` acquires the session and invokes the user agent's HTML face with it; the session's layout symbol is its explicit layout choice. Ship a default layout and editable slot data: conversation (session messages), canvas (latest surface or pin), task (interlocutor's task/step), evaluations (interlocutor's record), and input (reply form). Creating a session needs no authored UI code. New layout/selector/render functions are ordinary contracted program entities. Layout reads placement only; each slot owns its selector reads, including empty query results, and explicitly invokes the selected data's render. Reordering changes placement without invoking content renders. A view-opening operation uses the existing branch owner to fork the viewed head for the user; repaint/GET never switches their branch or overwrites earlier unmerged work.

**Inter-rendering.** Keep `seon.cluster.message/render-ai` / `seon.cluster.message/render-html` for messages and `seon.repl/render-ai` / `seon.repl/render-html` for evaluations. The message HTML face takes the viewer binding: the viewer's message is right-aligned with their name in **bold**; the other sender is left-aligned. The agent's reply is literally its message/evaluation data from its own record, passed to that record's render; a nested result uses its own schema pair. A session's proposed `seon.render.web/session-ai` / `seon.render.web/session-html` pair presents session configuration; the user agent's layout explicitly composes it. Slot data needs no bespoke pair: use ordinary value printing. In `seon.render/render-html`, absent HTML uses the selected AI face's data through `seon.render.value/render-html`; explicit HTML wins; with neither face, use the ordinary printer. Render once, print once; failed rendering retains the original value with its error.

**Canvas.** Its selector returns the latest session surface by the source data's most recent transaction, with source identity breaking ties, unless pinned. Candidates are the session's message/evaluation/data records through their HTML renders, not layout/control chrome; the selectors derive them from session messages and the participating agents' linked records. New chat can therefore become the canvas just as a data graph can. With no surface, the default layout offers the input. Recency comes from durable source data, never render time, cache insertion or `:seon.render.call/basis-transaction`; reload or eviction cannot make an old result newest. Pinning stores only the source ref, not rendered output.

**Reuse and delivery.** Call identity is `[session-id slot-key]`, scoped by cluster/branch/viewer. `seon.render/render-call` retains selector plus render read evidence; code, supplied input, profile and viewer identity participate in validity. `seon.db/read-evidence-current?` decides reuse after a wake; an unrelated commit does not re-render. Move calls, shared invocations and packages out of `:seon.render/cache`'s atom into weighed `seon.cache` kinds under `:seon.config.cache/max-bytes`, using `seon.cache/lookup`. `[session slot]` names the retained call, not sufficient content validity: immutable entries also identify their code/input/read evidence. Keep only cache references and delivery revision in the existing proc state; remove derived maps and per-call accumulation atoms. Eviction recomputes from facts, with no new cache or invalidation counter. `seon.render.web/render-pass` produces retained fragments with `seon.render.block/surface-id`; `seon.render.web/frame-bytes` sends Datastar patches for changed slots. Preserve `seon.render.web/join-package` and `seon.render.web/write-package!`: shared derivation, complete reconnect paint and drain-or-close delivery. Multiple slot patches may share one SSE event.

**Actions and sender.** Offered `:seon.render/operations` forms become labeled controls identified by `seon.id/digest`. Extend `seon.render.route/routes` with a session-qualified operation POST; resolve the digest from the offered render value, then submit that form through `seon.cluster.agent/submit-source!` as the session's user, on their checked-out branch. No second operation registry, evaluator or render-time effect. Input similarly submits `my.message/send` with session, recipient and optional caused-by; evaluation/calls belong to Sean, and root delivers to Survey (TASK-CHAIN I1). Correct `seon.render.web/inbound` / `seon.render.web/inbound-tx-meta` by recording the actual sender in `:seon.message/from` and `:seon.db/user`, not the recipient/service id. Root delivery preserves sender while recording its own process provenance. Replace `seon.render.web/received-response` and its hard-coded control with the offered `my.message/received!` form in the same slice. POST returns evaluation outcome/errors; the existing feed paints consequences.

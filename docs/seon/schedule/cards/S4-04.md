# S4-04 The agent holds its history; overflow refuses

Ledger row S4-04 (group B/D). Spec: agent-loop.md §3.4 "History" (the proc holds the assignment's exchanges as
values, appends each finished exchange, reads ordered history once at proc start or a new assignment) and the
window rule (prefix + history + block over the provider's window refuses; nothing is clipped). Lane: Sonnet.

## Files
`src/seon/turn.clj` (the model call site), `src/seon/cluster/agent.clj` (`turn-step` state),
`src/seon/cluster/prompt.clj` (one new function), `resources/seon/schemas/seon.cluster.prompt.edn`,
`test/seon/cluster/prompt_test.clj`.

## Functions
- ADD to the turn proc's state (`seon.cluster.agent/turn-step`, `src/seon/cluster/agent.clj:511`; state map holds
  `:seon.turn.loop/cluster`) the key `:seon.turn.loop/exchanges [:vector :seon.render.transcript/exchange]` and
  `:seon.turn.loop/exchanges-assignment :seon.task/assignment`. Filled by `seon.eval/exchanges` (S4-03) when absent
  or when the assignment differs; after a model pass commits, `conj` the finished exchange built from the values the
  pass already holds (never a reread).
- ADD `seon.cluster.prompt/window-check`
  `{:malli/schema [:=> [:cat [:int {:min 1}] :string [:vector :string] :string] [:or :nil :seon.cluster.prompt/over-window-error]]}`
  `[window-tokens prefix exchange-texts block]`: sums `seon.ai.tokens/estimate` over the parts; over the window
  answers the error map built by the installed error constructor with `:seon.ai.model/context-window-tokens` and
  `:seon.ai.tokens/estimate` as data. `window-tokens` is `:seon.ai.model/context-window-tokens`
  (`resources/seon/schemas/seon.ai.model.edn:10`).
- ADD schema `:seon.cluster.prompt/over-window-error` extending `:seon.error/base` in `seon.cluster.prompt.edn`.
- CHANGE the model call site (`src/seon/turn.clj` around `:4570-4646`): the user message text is
  `(str/join "\n" (map seon.render.transcript/exchange-text exchanges))` followed by the block (until CS-03a lands,
  the block is the existing rendered text). A `window-check` error closes the run as a refusal through the existing
  `fail!` path, before any provider call.

## Proof

`:seon.ai.model/context-window-tokens` 200 and history of 10 exchanges of ~2 KB: the pass answers the
over-window error as data, no provider request reached the HTTP fixture, and `(seon.eval/exchanges …)` still returns
all 10.

# RT-13 Give-back and the call cap move the assignment to the assigner

Ledger §3.28 RT-13 (group E, B for the cap arm; amends F7a and agent-loop.md §3.5). Lane: Sonnet.

## What becomes true
- `my.task/complete!` (give back, with its required reason) writes, in one home transaction, the reason on the
  assignment, the retraction of the agent's assignment and `assign-tx` of the same task to its assigner (the agent named
  by the assignment's transaction, `:seon.db.transaction/agent`, after TX-0; root for file tasks). The task's own
  proofs are still red, so the assignment is valid. No message.
- When every proof is already green, `assign-tx` refuses; the give-back instead asks the assigner (RT-7) about the
  task, since the situation is unplanned.
- The call cap (`:capped`) does the same move with reason `:capped` and keeps the agent and its branch: root's
  `assign!` of the task to the same agent and branch re-asserts the assignment with a new grant (AE-5), which is a new
  wake (AE-4) and a fresh call budget, so the agent resumes where it stopped. The cap is the count of call rows
  carrying the current grant, not calls since an outside wake (RESPEC R-8, answered by AE-5).

## Functions
- CHANGE `my.task/complete!` (F7a) and the cap's delivery in `seon.turn` (the `:capped` disposition's message).
- CHANGE agent-loop.md §3.5's two rows ("one message to the assigner", "the assigner, who is notified") in this
  landing's spec revision.

## Deleted
The give-back message (F7a) and the cap message to the assigner.

## Proof
`seon.task-ingestion-test/a-given-back-task-is-held-by-its-assigner` (new; F7a's test amended): after
`(my.task/complete! {:seon.task/reason "…"})` the agent holds nothing, root holds the task with the reason, root has no
new message. `seon.turn-work-test/a-capped-task-resumes-when-reassigned`: a capped agent holds nothing; root's
`assign!` to the same agent and branch makes `next-agent-work` `:open` on the same branch.

## Cost
One home transaction per give-back or cap, as the message cost before.

## Dependencies
F7a, RT-2, RT-3, RT-7 (fallback); CX-2 (no turn without a held task).

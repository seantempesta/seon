# CX-13 History starts at the current assignment

Ledger row CX-13 (group B; replaces S4-02a, owner Q1 answered: the assignment key as a value on the call row).
Spec: agent-loop.md §3.4 "History" (the assignment's exchanges). Needed once an agent receives a second task; a fresh
agent per task (the live runs) does not need it, hence its place last. Lane: Sonnet.

## What becomes true

A call row carries `:seon.turn/assignment` (the 12-character assignment key, a value: the assignment lives at the
task home, which an agent branch forked earlier does not hold), read once per pass where the world is built.
`seon.context/model-context` keeps only exchanges whose call row names the agent's current assignment.

## Functions

- ADD `seon.turn.world/assignment-key [connection agent-id branch] → [:or :nil :seon.task/assignment]`
  (`seon.task/assignment` on `seon.task/home-connection`).
- CHANGE `seon.turn.world/agent-world`, `jvm-world` and the model pass's world: assoc it when present; declare it
  optional in `:seon.batch/world`.
- CHANGE `seon.turn.batch/record-facts` and `seon.turn/open-call`: copy it onto the call row.
- CHANGE `model-context`: filter by it.

## Proof

`seon.cluster.turn-test/history-starts-at-the-current-assignment` (new): an agent with two fixture-model passes on
task A, then assigned task B: B's first request body holds none of A's forms; both rows name their assignment.

## Cost

One indexed read per pass (~1 ms class).

# RP-10 A model reply is an ordinary submission

Ledger row RP-10 (P14, ONE; group B). Design: `redo/pass-and-recording.md` §1 "Today's model path", §7 RP-10 ("The model
path already has the MCP submission path, which keeps no intent rows, so RP-10 needs nothing first"). Census: the
plan commit is one of the 7 per model eval request (`tx-census-opus.md` §2: `plan-call` 13 datoms;
`tx-census-astra.md`: order 6, 13 logical datoms, "carry into final transaction"). Lane: Sonnet. Cited at HEAD
`e7f120672`.

## What exists
`seon.turn/call-turn`'s `freeze!` (`src/seon/turn.clj:4499-4563`) segments the reply (`planned-sources` `:3044`),
stages it (`stage-reply!` `:69`), and commits an **intent**: `plan-tx` (`:474`) → `plan-call` (`:624`) →
`source-rows` (`:582`) write result-less evaluation rows; then `resume-turn` (`:5132`) reads them back
(`fold-evaluations` `:4278`) and the settlement commits again. The MCP path instead hands `resume-turn` an in-memory
submission (`:seon.turn.loop/submission`, built at `:6003-6007`; read at `:5193-5208`), whose evaluation rows exist
only in the one settlement (`with-submission` `:3512`).

## The change
`freeze!` builds a submission and calls `resume-turn` with it; nothing commits before the settlement. The run row
already exists (opened by `open-turn` before the provider call: RP-14 removes that commit later), so the submission
carries no open: its `:seon.db/tx-data` is the reply facts on the run row,
`[(merge {:db/id [:seon.turn/id run-id]} (dissoc staged-reply :seon.blob/staged-writes))]`, its
`:seon.blob/staged-writes` the staged reply's, its `:seon.turn/sources` the segmented sources (RP-11b replaces them by
the cursor), and its `:seon.ns/name` the agent's namespace.

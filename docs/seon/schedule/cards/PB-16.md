# PB-16: `build-projection` answers an unchanged population with a lookup

Ledger row PB-16 (group E; waste row W-21). Task `seon.schema/build-projection-walks-every-form-before-its-memo`
(`resources/seon/tasks/seon.schema.edn:77`). Source: `boot/boot-adopt-why.md` (lane boot-adopt-why, `1db511af9`).
Model: Opus (boot-critical: every write validates through a projection). Expected: a call over an unchanged
population costs a cache lookup; a changed one follows the changed declarations.

A boot onto an empty store allocates ~104.6 GB in 58 s (GC 1-2%: not the heap cap). 14.4 GB is
`seon.schema/predicate-symbols-in` (`src/seon/schema.clj:178`), about 15% of the run's CPU, reached from
`predicate-bindings` (`:2112-2127`), which `build-projection` (`:2303`) calls on **every** call **before**
`seon.cache/lookup ::projection` can answer (`:2341-2348`): the memo key contains the resolved bindings, so computing
the key walks every schema form and every function contract. Callers: `seon.db/validate-write-report` (11.7 GB, once
per write, `db.clj:5411,5435`), `seon.cluster/refresh-source!` (7.2 GB), `seon.cluster/accrete-schema-population!`
(6.5 GB), all under `seon.schema/call-with-projection` (`schema.clj:1126-1137`, 31.6 GB inclusive).

## Files

- `src/seon/schema.clj`

## Change

`build-projection`'s 3-arity (no supplied projection):

```clojure
(seon.cache/lookup ::projection
                   [forms function-contracts options (loaded-program-key)]
                   weigh
                   #(projection-build forms function-contracts
                                      (assoc options :seon.schema/predicate-functions
                                             (predicate-bindings forms function-contracts
                                                                 (:seon.schema/predicate-functions options {})))))
```

- The predicate walk moves **inside** the derivation, so a hit walks nothing. `forms` and `function-contracts` are
  the maps the caller already holds; Clojure caches a map's hash on the object, so a hit on the same maps costs one
  hash read and an `identical?`-fast equality.
- `(loaded-program-key)`: the bindings resolve loaded Vars (`runtime-predicate`), so a reload that changes a
  predicate's function must miss. Use the loaded program identity the evaluator already tracks
  (`seon.sci.eval/loaded-identity`, `sci/eval.clj:1017`; read its value shape and use the loaded commit id for the
  current root). If `seon.schema` cannot require `seon.sci.eval` (it would cycle), pass the key in `options` from the
  callers that hold it, as `:seon.schema/loaded-commit`, and add it to `:seon.schema/projection-options`.
- Nothing else changes; the supplied-projection branch (`:2337-2339`) is untouched.

## Proof

New `seon.schema-test/an-unchanged-population-builds-nothing`: build a projection over the packaged forms twice
(`schema.edn/packaged-forms`, as existing schema tests do); the second call answers `identical?` and
`seon.cache/status` shows one more `::projection` hit and no miss; then one changed form misses once. Existing
`seon.schema-test` stays green.

`--test seon.schema-test seon.db-test seon.cluster.boot-test`

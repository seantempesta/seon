# RP-12 Findings stored like any REPL result

Ledger row RP-12 (LR-REPAIR; group B plus the eval schema). Owner (2026-10-08 afternoon): Seon's own diagnostics are
like any REPL form result: the full value cached, the value printer's shown text stored (inline up to 4096 bytes, a
blob above: storage roles §3.17, SR-B, SR-D, SR-I). Lane: Sonnet. Cited at HEAD `e7f120672`.

## What is already true (no work)
Repairs are data (`:seon.cluster.eval/delimiter-repairs`, `[:vector [:tuple line kind text]]`, `4c3be3361`);
`:seon.cluster.eval/repairs` (the printed string) and `seon.turn/repair-text` are gone at HEAD (`rg` finds only the
task text in `resources/seon/tasks/seon.turn.edn:217`). Diagnostics get their handle in SR-I.

## What changes
1. **Findings are stored** on the evaluation of the form they belong to (RP-6a2's attribution), exactly as SR-I stores
   diagnostics: the full vector in the one cache under `(str evaluation-id "-f")` (SR-H's kind `:seon.repl/result`),
   its value-printer text by SR-B's rule (`seon.blob/inline-or-stage`, `src/seon/blob.clj:217`) as
   `:seon.cluster.eval/findings` (`:string`), `:seon.cluster.eval/findings-size` (`[:int {:min 0}]`),
   `:seon.cluster.eval/findings-blob` (`:seon.blob/digest`), staged writes joining the settlement's like the reply's.
   The reply prints the text beside the value (`:seon.repl/findings`) and the handle `result/e<id>-f`
   (`seon.sci.admit/result-handle`, `src/seon/sci/admit.clj:691`).
2. **Repairs attach per entry from the read step** (after RP-11): `record-facts`
   (`src/seon/turn/batch.clj:678`) takes each entry's `:seon.batch/repairs` from its read step (the cursor's step
   carries them, as `code-request` already does) into `:seon.cluster.eval/delimiter-repairs` via the existing
   `seon.turn/repair-data` shape (`src/seon/turn.clj:3008`; move it to `seon.turn.batch` if RP-11c deletes its file
   neighbour).

## Files
`resources/seon/schemas/seon.cluster.eval.edn`, `src/seon/turn/batch.clj` (`evaluation-record`, `record-facts`),
`src/seon/repl.clj` (prints the stored text and handle), `test/seon/repl_differential_p7_test.clj`.

## Functions
- CHANGE `seon.turn.batch/evaluation-record` (private, `:650`): add the findings facts (text or blob digest, size)
  when the entry has `:seon.batch/findings`, and put the vector in the cache with
  `(seon.cache/put! :seon.repl/result (str evaluation-id "-f") (* 4 (tokens/estimate text)) findings)` exactly as
  SR-I's card does for diagnostics.
- CHANGE `seon.turn.batch/record-facts` (`:678`): per entry repairs as above.
- CHANGE `seon.repl/response-entries` (`src/seon/repl.clj`, `:191`): when the emission holds stored findings text,
  `:seon.repl/findings` is that text (spliced, as `:seon.repl/diagnostics` is), not a re-print.

## Proof
`seon.repl-differential-p7-test/findings-pull-back-as-data-beside-their-form` (new): after RP-1's dangling unmap,
the evaluation row of the unmap form has `:seon.cluster.eval/findings` text, and evaluating `result/e<id>-f` in the next
call answers a vector whose first map has `:seon.program.finding/type :seon.program.finding/dangling`. The reader-fix
rows of `seon.repl-differential-reader-test` stay green (repairs).

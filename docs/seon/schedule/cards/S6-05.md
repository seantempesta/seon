# S6-05 A model eval request answers only the basis it presented

Ledger row S6-05 (group B). agent-loop.md §3.5: "A committed model reply advances answered to the basis its context
presented … The cap counts call rows at the writer against the outside wake whose anchor they consumed." CLAUDE.md:
"the answered basis is `:seon.agent/answered-t`". Census fold-in: the recording transaction carries
`:seon.db.transaction/basis-t` (TX-0), the presented basis for a model eval request. Lane: Sonnet. Cited at HEAD
`e7f120672`.

## What exists
- `seon.turn/latest-answering-turn-t` (`src/seon/turn.clj:2908-2933`): the answered basis is the **opening**
  transaction of the latest model turn with an accepted reply (an all-history query over the agent's turns). It relies
  on the open commit RP-14a deletes.
- `seon.turn/spent-runs` (`:2649-2675`): the cap counts the agent's turns since its latest outside wake by two
  history queries over turn ids, attempts, reply sizes and `:seon.turn/closed-tx`.

## Change
- **Answered.** The model recording writes `[:db/add [:seon.agent/id agent-id] :seon.agent/answered-t presented-t]`
  in its own transaction (through EN-2's `call-facts`/entities), where `presented-t` is the basis the context
  presented (the `basis` `evaluate-sources` already takes for a model eval request, `turn.clj:4940`; TX-0 puts the
  same value on the transaction). Only a model eval request with an accepted reply writes it; MCP and test eval requests
  never do. Schema: `seon.agent.edn` gains
  `:answered-t [:and {:description "The basis the agent's latest accepted model reply was presented; wakes at or before it are answered."} :seon.db/basis-t]`
  (no history needed: `:seon.db/no-history? true`).
- `latest-answering-turn-t` becomes `(or (:seon.agent/answered-t (db/pull database [:seon.agent/answered-t] [:seon.agent/id agent-id])) 0)`:
  one EAVT read. Its name stays until CN-19.
- **Cap.** `spent-runs` counts the agent's model call rows recorded since the outside anchor `outside-t`: call rows
  carrying a model attempt (`:seon.turn/attempts`) whose own transaction is ≥ `outside-t`, and call rows of model eval
  requests that failed before an attempt (the provider-failure recording of RP-14a also carries the attempt row with its
  error, so one clause suffices once RP-14b lands). The writer checks the count: the model recording's
  `record-evaluated-call` refuses `::cap-exhausted` when `(>= (spent-runs db agent-id nil) limit)` on its own db (the
  agent's proc already defers before calling; this is the authority check, CLAUDE.md "decide at the authority").
- **Continuation** (agent-loop.md §3.5 first row) is unchanged in shape: after a model eval request that evaluated ≥ 1
  form, the next work derivation sees `answered-t` advanced and the cap not reached.

## Proof
`seon.turn-work-test/model-passes-answer-only-the-basis-they-presented` (ledger name, new): with the fixture provider,
a message arrives **during** the provider call (the fixture's reply function transacts a message to the agent before
answering, an external effect injected as a value); after the eval request, `:seon.agent/answered-t` equals the
presented basis (< the message's t), and the next work derivation (`next-agent-work`, `:2832`) answers that message.

# A1: Answers are specced data on the agent

**Q-A answered (owner 2026-10-08):** a question task declares its answer's Malli schema; `answer!` validates the answer
against it and stores it as ordinary Datahike data. No blob path; scratch values stay live in the agent's Vars.
Group E. Model: Sonnet.

## The one rule

The task names a registered entity (map) schema key in `:seon.task/answer-schema`. The answer is a map that validates
against that schema; it is stored as a component entity of the agent, `:seon.agent/answer`, so every value in it is
an ordinary attribute value the checked writer validates (a scalar answer is a one-entry map the task author declares,
e.g. `:tq.dates/answer [:map [:tq.dates/day :int]]`). One rule, no special case for scalars.

## Files

- `resources/seon/schemas/seon.task.edn` (one task member)
- `resources/seon/schemas/seon.agent.edn` (three agent members)
- `src/my/agent.clj`, `resources/seon/tasks/my.agent.edn` (the request and answer schemas, as the row names them)
- `test/my/agent_test.clj`

## Schema

- `seon.task.edn`, beside `:signal` (`:63`), same reference form:
  `:answer-schema [:qualified-keyword {:seon.db/reference-to :seon.schema/key :description "The registered entity schema a question task's answer must satisfy (my.agent/answer!)."}]`,
  optional on the task entity.
- `seon.agent.edn`: `:answer [:and {:seon.db/component true :description "The agent's answer to its held task, validated against the task's :seon.task/answer-schema."} :seon.db/ref]`;
  `:sources [:set {:description "The evaluations the answer came from."} :seon.db/ref]`;
  `:source-names [:set [:string {:min 1}]]` (outside references: URLs, documents). All optional on the agent.

## Functions (`my.agent`)

- `my.agent/answer!` `[request]`, contract
  `[:=> [:cat [:map [:my.agent/answer :map] [:seon.agent/sources {:optional true} [:vector :symbol]] [:seon.agent/source-names {:optional true} [:set [:string {:min 1}]]] [:seon.db/connection :seon.db/connection] [:seon.agent/id :seon.agent/id]]] [:or :my.agent/answered :my.agent/answer-invalid-error :my.agent/unknown-source-error :my.agent/no-answer-schema-error :seon.error/value]]`
  (connection and id supplied from the world by schema name). Body: the held task (`seon.task/agent-task`,
  `task.clj:600`, on the task home) → its `:seon.task/answer-schema` K (absent → `:my.agent/no-answer-schema-error`
  naming the task); validate the answer with the branch projection's validator for K
  (`seon.schema/projection-validator`); invalid → `:my.agent/answer-invalid-error` carrying Malli's explanation
  (`m/explain`, humanized by the printer, never printed here); each source symbol (`result/e…`) resolves to its
  evaluation by the inverse of `seon.sci.admit/result-handle` (`sci/admit.clj:691`), an unknown one refuses
  `:my.agent/unknown-source-error` naming it. Then ONE transaction on the agent's own branch:
  `{:seon.agent/id id :seon.agent/answer answer :seon.agent/sources eval-refs :seon.agent/source-names names}`
  (a new answer replaces the component: retract the old one in the same transaction). Answers
  `{:my.agent/answered K}`.
- `my.agent/answer` `[request]`, contract
  `[:=> [:cat [:map [:seon.db/db :seon.db/database-value] [:seon.agent/id :seon.agent/id]]] [:or :map :my.agent/no-answer-error :seon.error/value]]`:
  pull `:seon.agent/answer` with the selector derived from K's entity schema (never a hand list), `:db/id` removed;
  none → `:my.agent/no-answer-error`.
- Error variants (`resources/seon/tasks/my.agent.edn` or the schema file holding `my.agent` errors; follow where
  `:my.agent/*-error` keys live today): each `[:and :seon.error/base [:map …]]` with its members.

## Proof

`my.agent-test/an-answer-is-data-on-the-agent`, through `seon.mcp/call` as an agent holding a task whose
`:seon.task/answer-schema` is a schema the test registers (`[:map [:tq.a1/day :int] [:tq.a1/note :string]]`):
a valid answer reads back equal through `my.agent/answer`; an answer violating the schema refuses
`:my.agent/answer-invalid-error` and writes nothing; a task without an answer schema refuses
`:my.agent/no-answer-schema-error`; an unknown source handle refuses `:my.agent/unknown-source-error`; a second answer
replaces the first (one component remains).

`--test my.agent-test --test seon.task-ingestion-test`

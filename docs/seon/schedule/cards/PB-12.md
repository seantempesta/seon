# PB-12: clj-kondo reads its configuration once

Ledger row PB-12 (group E). Task `seon.fn.analyzer/each-analysis-resolves-the-lint-configuration-from-disk`
(`resources/seon/tasks/seon.fn.analyzer.edn:17`). Source: `defn-why/defn-why.md` finding 9. Split in two cards
(a fork seam, then Seon). Model: Sonnet for both.

Every `seon.fn.analyzer/invoke-kondo` call (`src/seon/fn/analyzer.clj:293-303`) runs `clj-kondo.core/run!`, which
resolves the configuration from disk each time: `core-impl/resolve-config` reads `.clj-kondo/config.edn`, globs
`**/config.edn` and `imports/**/config.edn`, reads the home config and merges them
(`reference-code/clj-kondo/src/clj_kondo/core.clj:133-139`, `impl/core.clj:148-200`, pinned `57252e07`): about 2 MB
of a one-form analysis (cache sync is another 2.1 MB, out of scope here: it loads the cache entries the analysis
needs). A JVM runs a committed archive, never the working tree, so the configuration cannot change during the JVM's
life.

## PB-12a: our clj-kondo fork accepts a resolved configuration

- Files: `reference-code/clj-kondo/src/clj_kondo/core.clj`, a fork test under
  `reference-code/clj-kondo/test/clj_kondo/`, the gitlink.
- Change `clj-kondo.core/run!`: destructure one more key, `resolved-config`; at `core.clj:139` bind
  `config (or resolved-config (core-impl/resolve-config cfg-dir (if (sequential? config) config [config]) repro debug))`.
  `resolved-config` is exactly a value `clj-kondo.core/resolve-config` (`core.clj:301-311`) returned for the same
  `cfg-dir`; document that in the docstring's option list. Nothing else changes (`cfg-dir` still names the cache
  directory and hook loading).
- Fork test: on a fixture directory whose `config.edn` disables one linter, (1) `run!` with
  `:resolved-config (resolve-config cfg-dir)` gives the same `:findings` as without it; (2) a `:resolved-config`
  resolved from a different directory that enables the linter wins over the on-disk file, which proves the file was
  not read.
- Commit in the fork, push to `seantempesta/clj-kondo`, bump the gitlink in Seon:
  `bin/lane commit <lane> -m "PB-12a: clj-kondo fork run! accepts a resolved configuration" --test seon.fn.analyzer-test reference-code/clj-kondo`

## PB-12b: Seon resolves the configuration once per launched archive

- Files: `src/seon/fn/analyzer.clj`, `test/seon/fn/analyzer_test.clj`.
- ADD `seon.fn.analyzer/resolved-config`
  `{:malli/schema [:=> [:cat :string :map] :map]}` `[config-dir config]`: `(seon.cache/lookup ::resolved-config
  [config-dir config] (fn [resolved] (* 64 (count resolved))) #(clj-kondo/resolve-config (io/file config-dir) [config] true))`.
  The key is the directory path and the in-code `analysis-config` (`analyzer.clj:26`): the files under it are the
  launched archive's and fixed for the JVM's life. (`seon.cache/lookup`'s argument order: read its definition in
  `src/seon/cache.clj` and match `seon.program/program-attributes`'s call, `src/seon/program.cljc:76-82`.)
- CHANGE `invoke-kondo` (`analyzer.clj:293`), contract unchanged: after the `merge`, when `(:config-dir options)` is
  the shared `config-directory`, `assoc :resolved-config (resolved-config (:config-dir options) (:config options))`.
  A fixture or scratch run with its own `:config-dir` keeps resolving (rare, and its directory is not the archive's).
- Proof `seon.fn.analyzer-test/one-form-analysis-resolves-configuration-once`: analyze one form twice through
  `seon.fn.analyzer/analyze` (the public entrance the existing tests use; read `analyzer_test.clj` first); assert
  `(seon.cache/status)` shows `::resolved-config` with one miss and one hit, and the two analyses are equal.
- `--test seon.fn.analyzer-test seon.fn.publication-test`
- Cost: expected one resolution per JVM; measured parent ~2 MB per one-form analysis (defn-why); measure one form's
  analysis allocation on parent and change with `seon.pass-probe/window` and report both.
- Commit: `bin/lane commit <lane> -m "PB-12b: clj-kondo configuration resolved once per launched archive" --test seon.fn.analyzer-test seon.fn.publication-test src/seon/fn/analyzer.clj test/seon/fn/analyzer_test.clj`

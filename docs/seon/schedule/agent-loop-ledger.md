# Agent-loop ledger

This is the only ordered list of agent-loop work. The behavior it implements is specified in
[agent-loop.md](../specs/agent-loop.md) and [merge.md](../specs/merge.md); the authority above both is
`docs/research/agent-platform/2026-10-08/review/owner-rulings.md`, then CLAUDE.md. A row here says what to change,
where, how it is proven and in which order. It never restates a law; if a row and the spec disagree, the spec wins and
the row is corrected.

It absorbs, and supersedes as execution order: `split/reconciled-plan.md` (S1, S3-S7, PB, CS, AR, Q answers),
`repl-audit/repl-plan.md` §5 (P0-P14), `s5-admission/admission-design.md` §7 (S5-04a-j), merge.md's former M slices,

## How to read a row

- **Id and title.** The id is for lanes and commits; the title says in plain English what becomes true. The critical
  path (§5) uses titles only.
- **Status.** `landed <commit>`; `in flight (<lane>)`; `ready` (fully specified: files, contract, proof, budget);
  `blocked-on-owner (<question>)` (an owner decision is missing, listed in §6); `waits on <lane or root>` (another
  lane's design or a root split must land first); `ready after its deps`; `shelved` (the owner set it aside). A row
  launches only when it is `ready` **and** every dependency is landed.
- **Group** is the file-ownership group. Rows in one group run in series; rows in different groups run in parallel
  when their claimed files are disjoint (`bin/lane status` is the ledger of claims).
  A render/printer (`print.cljc`, `render/value.clj`, `render.clj`, `repl.clj`) · B turn (`turn.clj`, `turn/batch.clj`,
  `batch.clj`) · C SCI (`sci/eval.clj`, `sci/arm.clj`) · D context and wire (`context.clj`, `ai.clj`,
  `cluster/prompt.clj`, `render/web.clj`) · E stores and tests (`db.clj`, `blob.clj`, `health.clj`, `effect.clj`,
  `test.clj`, `task.clj`) · F errors (`error.clj`, `instrument.clj`, `fault.clj`) · H help and lookups (`bootstrap.clj`)
  · K competency (`test/seon/competency*_test.clj`, `resources/seon/tasks/seon.competency.edn`) · M merge
  (`cluster/source.clj`, `my/program.clj`, `cluster.clj`) · O operator (`deps.edn`, `script/seon/operator.clj`)
  · T tooling (`bin/*`, `.clj-kondo/`) · V vocabulary and living documents (`docs/seon/`, `.agents/skills`).
- **Budgets** (owner 2026-10-08: no arbitrary targets; judge cost against what the work must do). Every budget reads:
  expected from the work (what it is proportional to and the rough cost that implies); measured parent and change;
  10× or more over the expectation is a defect to diagnose, and any regression is reported (CLAUDE.md's hot-path rule
  still asks that one over 20% or 50 ms is fixed before commit). The owner's own numbers are rulings and stay: a model
  pass at 20-40 MB transient is fine and never GB; the whole process fits a 16 GB machine beside the user's work; a
  core function's raw return stays under 2,000 estimated tokens in ordinary use; CLAUDE.md's 1 s (a finding naming the
  owners) and 10 s (owner authorization and an issue). Invented MB and ms targets are deleted. The codes name the probe
  and what the work follows:
  **O** `seon.pass-probe/run-mcp` SCI and JVM plus `run-model` through the HTTP fixture: a pass reads, evaluates and
  prints its forms and writes one recording transaction, so its cost follows its forms and the datoms they write; a
  model pass stays in the owner's 20-40 MB, never GB. **L** `seon.pass-probe/window` around one lookup through MCP SCI:
  follows the one definition or namespace read and rendered. **H** history of 1/10/200 exchanges at ~2 KB: an append
  follows the appended text. **I** one model wake with the current-state block: the block follows the task, its proofs
  and the unread items it shows, with no whole-program work; the pass as O. **T** `seon.pass-probe/run-check`: runner
  work follows the selected tests and their reach inputs, never the program; member and request commits counted apart.
  **F** injected refusal/timeout/late exit: attempts, durable commits and held resources counted. **D** documentation or
  deletion: the narrow proof, zero calls on the deleted path. **R** reply size, `seon.ai.tokens/estimate` of the MCP
  reply: follows what the reply shows; a raw return under the owner's 2,000. **M**
  `docs/research/agent-platform/2026-10-08/memory/probe.clj`: live heap after full GC and RSS; retained heap follows
  live agents and the values they hold.
- **Proof** names a deftest asserting DATA through the real MCP entrance (`seon.mcp/call`), new unless marked
  existing. A slice lands with `bin/lane commit LANE --test <its proofs>`.
- **Words.** Rows use git's words (merge.md "Words"): main, branch, merge request, source and target branch, merge
  branch, ours and theirs, unmerged, norm. Older ids keep their letters; their text does not. Code names (pass,
  settlement, armed, projection, world, custody …) stay as the code spells them until their rename row (§3.18) lands;
  that row converts this ledger and the specs in the same commit.

**The owner's change to finishing (2026-10-08 afternoon).** After a pass that changes code, the task's proofs AND the
tests reaching the change run automatically on the agent's branch, the last version winning; breaking another test is
a blocker the agent sees and fixes; agents never call `my.test/check` by hand. This supersedes "reaching tests only at
merge" (the old F, AR and EN wording). The step is bounded: proofs first, reaching tests after, and what the bound
leaves continues on the next pass and shows in the block. Consequences in the rows: F4a and F4b run both requests; the
reaching request now runs per changing pass on a branch, so the shared reach cache (LR-CACHEb) is a hard dependency of
F4a (a branch's first reaching check costs 2.9-3.8 GB today); CS-01d shows broken tests; F4a-d no longer wait on EN-6 and
S6-05 (they make it cheaper and stricter later; the 400 ms one-test interim is allowed while it stays under GB).

**Other answers.** Live results live in `seon.cache` as an LRU under its byte budget, with no count (SR-H, replacing
MEM-03's and OD-Q16's 64 handles). Storage roles landed (`94dbfc5f6`, §3.17): the cache holds the full live value; a
database fact holds small facts plus shown text up to 4096 bytes; a blob holds anything larger, the fact keeping its
digest and size; no second printed copy of a value is ever stored. Diagnostics storage is therefore unblocked (SR-D,
SR-I). The Datahike fork change for cross-branch revisions is approved (OD-Q17: LR-CACHEb). A
definition's pointer to its evaluation is dropped at merge (NK-8a, MA-11). No kinds anywhere (§3.15). Git's words in
everything agent- or owner-facing (§3.16). Task steps shelved; the priority is tasks running with the current-state
block built from what the task names (§3.7, §5). Renames to Clojure's, Malli's and Datahike's words are approved, one
scripted sweep per slice, after the tasks-running work (§3.18); one submission of forms is an **eval request**, and
`seon.batch` folds into `seon.repl` with clojure.main's stages. Atoms: one validated state map per process and one per
cluster (§3.19). Ordered data uses the installed vector cells (§3.20). Stop reinventing: where a dependency does the
job, use it and delete ours; keeping ours is an owner decision per case (§3.22). From `review/owner-decisions.md`, the
split's Q2b is settled (§4) and its Q7 is superseded by the approved REPL plan.

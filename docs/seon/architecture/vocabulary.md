# Vocabulary

Use the library's word for what the library does; coin a Seon word only for what no library names. The order of
preference: Clojure's own name, then the closest dependency's (read its source under `reference-code/` and take its
name and its semantics), then, for a concept genuinely ours, one coined word recorded here once. Preserve literal
identifiers and historical quotations where accuracy needs them; do not carry retired spellings into new prose or
code. When you meet one, convert it in the same commit when in scope, otherwise file the issue.

[AGENTS.md "Words and where they come from"](../../../AGENTS.md) is the authority for the first table; this page
adds each library's source path, the git words, and Seon's own words. The approved renames (ledger §3.18, the CN entries,
and `script/seon/vocabulary.edn`, which the vocabulary check reads) apply to living documents now; code keeps its
old spelling until its CN rename converts it with every caller. One submission of forms is an **eval request**
(nREPL's word; code: `pass`, `seon.batch`, CN-20); its one transaction is the **recording transaction** (code:
`settlement`, CN-7); what returns is the **reply** (code: `envelope`, CN-8); the stored text is the **printed value**
(code: `shown`, CN-9).

## Git words

Datahike already speaks git (`branch!`, `delete-branch!`, `merge!`, `commit-id`, `parent-commit-ids` in
`reference-code/datahike/src/datahike/versioning.cljc`), so a merge uses git's words where git's meaning holds. The
reasoning and the rename slices live in [git-vocab](../../research/agent-platform/2026-10-08/git-vocab/git-vocab.md);
a word marked (target) names its rename, not yet merged.

| Term | Meaning | Retired words |
|---|---|---|
| branch | `branch!`: a named pointer to a commit; no copy | lane branch, worktree, fork of the database |
| main | a cluster's own branch, the line every accepted change is merged into; one per cluster, so a store has several | cluster head, home, "HEAD" for it |
| checked-out branch | the branch an agent's context holds (`my.agent/branch`, `git branch --show-current`); a new checkout is a new context | custody |
| merge, merged | `merge!` and git's merge: a source branch's changes enter the target branch, as a merge commit or a fast-forward; merged is the state after (owner 2026-10-12, CN-26) | land, landed, landing, unlanded |
| merge request | a merge task's merge of its source into its target branch (git's, GitLab's word), with the merge base (`seon.cluster.source/merge-base`); target (task-model T3b, [task model](../../research/agent-platform/2026-10-17/task-model.md) §6.2): a task with a `:seon.task/target`, listed by `my.root/merge-requests`; installed until T3b: the one merge of a chain branch into main with the terminal attempt as its source (`seon.merge/merge!`) | proposal, candidate |
| source branch, target branch | GitLab's pair: the branch proposed, the branch it is merged into; a task's `:seon.task/target` is the target branch its done step writes (absent: the done step writes only the task's own branch). It is not `:seon.task.attempt/target`, which is the task a send-back names | head and base (both mean something else here), the proposing branch |
| merge base | the newest common ancestor commit (`git merge-base`) | base digest |
| merge branch | the branch root's merge creates off the target, where tests run on the merged result before main moves | S, the candidate, the tested branch |
| ours, theirs | in a conflict, ours is the target and theirs is the source, as in `git merge`; Seon never rebases | head digest, branch digest, changed-on-head |
| unmerged | a declaration both sides of a merge changed since the merge base, recorded as an unmerged entry (`:seon.unmerged/entry`: base, ours and theirs digests) beside ours, which the branch holds (main wins on a merge branch); the done rule and root's merge refuse it until a write of the declaration or `my.program/resolve!` resolves it | conflict markers, unresolved |
| at | where a referenced name is read (`:seon.ref/at`): a branch's head or a commit, the merge base included; `[name at]` in a code span, `{:seon.ref/name name :seon.ref/at at}` as data; absent, the checked-out branch | version, revision, ref spec |
| behind | the identities main modified since the merge base (`git diff branch...main`) | head-only |
| norm | Datahike's named, once-only data change (`:tx/norm`, `reference-code/datahike/src/datahike/norm/norm.clj`); a merge may carry one to convert main's entities | migration |
| delete branch | `delete-branch!`: the branch leaves `d/branches`, its commits wait for retention GC; "retire" is for agents only | unlink, retire a branch |
| commit | a Datahike commit with parents; the program part has its own content identity, the program digest | basis (for a commit) |
| squash merge | git's merge --squash as the copy-back: the three-way of declared cluster facts between the merge base, a source branch and main, merged as one plain transaction on main with no parent link to the source (`seon.merge/squash-merge`) | cherry-pick, data relay |

## Seon's words

Words no library names. Each has one meaning.

| Term | Meaning | Retired words |
|---|---|---|
| program context | the SCI context holding exactly the program one commit holds, frozen as a value (`seon.sci.eval/program-context`): keyed by program content in `seon.cache`, forked once per agent, never written; an agent's context is its fork plus its checked-out branch and its private layer | base context, overlay context, branch program copy, "environment" for the SCI context |
| task | the one family for work an agent does: one entity with a `plan`, `instructions`, `proofs`, an environment and the tasks it `needs` ([TASK-CHAIN](../schedule/cards/TASK-CHAIN.md) §1); a single task is a task with no needs, and "chain" survives only as plain prose for tasks written together; installed until task-model T3b: tasks linked by `next`, a chain of one for a single task; a detected defect is a task whose subject came from a detector | issue, work packet, subject task, step, child task |
| `:seon.cluster` | the entity-schema partition for facts that reach main when a merge task is accepted (installed until task-model T3b: a chain's merge), with conflict rules declared on the schema or its entries (`seon.program/cluster-attributes`); messages remain `:seon.data` | mergeable data roster, end copy |
| inbox | the Flow channel carrying message values to an agent; its recipient writes received messages on its own branch | stored transport |
| proof | a qualified deftest symbol in a task's `:seon.task/proofs`; the one set that must be green for the task to be done (TASK-CHAIN §1, §2.4); installed until S2c-2: a deftest naming a task in `:seon/tasks` | gate (for a task's tests), product, obligations, tag |
| growth profile, growth class | a function's counted cost (armed calls, `seon.db` reads, allocated bytes) measured at two sizes per dimension (generated input, untouched datoms, touched datoms) and the class of each measure's exponent (`:seon.cost.growth/class`: constant, sublinear, linear, superlinear, quadratic); `seon.cost.growth/database-growth`, `seon.cost.growth/input-growth` ([cost probe](../../research/agent-platform/2026-10-17/cost-probe.md)) | complexity score, cost probe (for the result) |
| default cost contract, touched size N, steps, pain | every function's cost bound without writing one: per call, steps (armed calls inside it), reads (`seon.db` read entrances inside it) and allocated bytes each at most k × N + c, N the call's touched size (its arguments' and value's extents, `seon.profile/bracket` on sampled calls), k and c the `:seon.config.fn.cost/steps-k` ... `bytes-c` dials; **pain** is the live cost a function spends in its own body (self: less its counted callees') beyond that contract, per dimension with its share of the system's (`seon.profile/pain`, the one live ranking health reads too), the inclusive figures kept beside as data; a function inside its contract has none however hot ([cost evidence](../../research/agent-platform/2026-10-17/cost-evidence.md)) | hot (as a ranking of cost), complexity score |
| reaching test | a test whose current dependencies reach a changed definition (`my.program/tests-reaching`); differs from a test's recorded past `:seon.test/reach` | gate set, test closure |
| turn | the unit a model call answers: an agent's ordered evaluations and provider attempts, open until closed (`seon.turn`) | run (meaning one turn), `seon.cluster.run` |
| run | a budget of turns for one attempt or one message reply, counted to the reply or the cap (`seon.turn/turns-left`); derived by query, never an entity (CN-19 retires "run" for one turn) | episode, session bound |
| render function | a function of the data that selects what to show: an AI/HTML pair per entity schema, read-only | producer, view, face |
| current-state block | the part of an agent's context rendered live from its record each turn (`seon.context/current-state`) | status tail |
| situation | one agent step as the miner reads it from a kept branch (`:seon.mine/situation`, `seon.mine/situations`): what the step's eval request showed (each evaluation's render, printed tokens, cuts and error), the forms the agent wrote next, how its attempt ended, and the next forms charged as waste to the producer of what was shown; distinct from `:seon.turn.work/situation`, the kind of work a model call opens for | data point, sample, trace row |
| write-back | writing accepted declarations into source files, checking the files did not change since read, then reindexing (`seon.cluster.source/write-back!`) | export, push |
| wake | a listened event the agent has not yet answered (a message, an attempt end, a task change) | notification, trigger |
| babashka-loadable | the `{:seon/babashka true}` metadata on an `ns` form: the edit hook loads this namespace in Babashka (`bin/seon-hook`, `seon.edit/exact`), so it and everything it requires must load there; `seon.babashka-load-test` runs `bb` over every declaring namespace | bb-safe, hook-ns |
| help | `(help)`, the first form an agent reads: the Markdown document `resources/seon/help.md` in titled sections, resolved like a plan (`seon.bootstrap/help-value`) | fixed help strings |
| answered t | `:seon.agent/answered-t`: the database basis `t` the agent has answered; wakes after it are due (Datomic's basis t) | answered basis, handled |
| references | `:seon.task/references`: the qualified symbols a task's `plan` and `instructions` cite as code spans, derived by the one task writer through the one reference parser (`seon.ref/names`) and re-derived whenever either changes; never authored | must-read, evidence, reading list |
| desired state, observed state | Kubernetes' spec and status, as Seon uses them (task model, [plan](../../research/agent-platform/2026-10-17/task-model.md) §1, §3): desired state is the task facts on main that root, the task writer and config apply write (`needs`, `branch`, `target`, `config`, `model`, `execution`, the config dials); observed state is facts written by their observer when the event happens (a graph process, an attempt and its end, a judged done, a merge, a test result, a branch head); nothing is inferred from history. Target (task-model T3a/T3b); installed until then: the chain fact, `launch-facts` and the registry read in `run-pass!` | intent (for the whole), status mirror, derived-from-history state |
| reconcile | `seon.cluster.reconcile/reconcile` (installed by task-model T3a, pure and not yet wired; T3b makes it db<->flow's pass): a pure function of (desired, observed) answering the minimal actions, each action's actor writing the observed fact that closes its gap; reconciling the same state twice answers nothing the second time. `seon.reconcile` (config) already uses the word this way | scheduler, dispatcher, planner (as a separate mechanism) |
| transition table | a vector of rows over a state that is a map of Malli enums with its impossible combinations named as schemas (`:seon.flow.actions/task-state`, `:seon.flow.actions/branch-state`): `seon.cluster.reconcile/transitions` and `seon.cluster.reconcile/branch-transitions`. Its rows are disjoint and every possible state matches exactly one, proven by enumeration (`seon.cluster.reconcile-test/the-transition-table-is-exhaustive-deterministic-and-convergent`) | state machine, statechart, gap table, dispatch `cond` |
| row | one entry of a transition table, `:seon.flow.actions/transition`: its name (`G1`, `N6`), its condition (per dimension or derived value, a value or a set of values) and its actions, or none for a steady row; matched by `seon.cluster.reconcile/row`. Rows have no order and no default | rule, clause, case |
| steady row | a row with no actions, named for the state it holds (`"working"`, `"done"`): a state needing nothing is matched by a steady row, so an unmatched state is a red test and never a silent no-op | default, fallthrough, `:else` |
| needs | `:seon.task/needs`: a set of prerequisite tasks written on the dependent, GitHub Actions' `jobs.<id>.needs`; the one dependency edge (fan-in and fan-out both work; a task is ready only when every need is done where that need's attempts live). Un-retired by the task model (TASK-CHAIN §1); replaces `:seon.task/next` (cardinality one, forward) | next, prev, `:seon.chain/first`, children (as dependency) |
| `:seon.task/target` | the branch a task's done step writes, git's target branch: the merge task's builder sets it to main's branch, and the task's own branch is built against it; absent, the done step writes only its own branch (`:done`). Not `:seon.task.attempt/target`, the task a send-back names. Target (task-model T1) | `:seon.chain/merge?`, a merge flag, the merge step's append |
| `:seon.task/config` | the task's config decisions over main's, a map of dial keys to values, converged onto the task's branch when it starts (target, task-model T1); replaces `:seon.chain/config`. `:seon.task/desired-config` stays the runnable view's decided key | `:seon.chain/config` |
| environment (of a task) | a task's branch, target, config and model, desired state on the task entity; an agent starts only once it is complete (`:seon.task/environment`), and a difference between the desired and the observed environment restarts the agent. Distinct from the per-cluster `seon.env` value ("boot / environment / running") | chain, chain config, world |
| `:seon.agent/environment` | the observed environment: the digest of the decided config an agent's turn loop read, written at context acquisition beside `:seon.agent/branch` (target, task-model T4) | |
| `:seon.agent/graph-process` | the process whose registry runs this agent's graph, asserted when `start-flow!` has a started entry and retracted when `stop-flow!` observes every proc thread exited; boot retracts values naming another process (target, task-model T2); replaces reading `:seon.agent/started` from the in-memory registry as the observation | started flag, liveness flag |
| restart | stopping an agent whose observed environment differs from its task's desired one, closing its attempt `:closed` "environment changed" and starting a fresh agent on the new environment (a new attempt, agent identity and SCI context; private SCI state is lost by design); the owner's clean restart (target, task-model T4) | environment swap, in-place advance |
| release | root writing `:seon.task/execution :running` on a `:held` task (`my.root/run!`): the only start signal, a start or a resume after a bail alike; nothing autoruns (owner, 2026-10-17). Target (task-model T3b) | start, launch, autorun |
| chain fact | **retired by the task model**, replaced by the tasks on main: `:seon.task/needs` (order), `:seon.task/branch` (the branch, claimed by `seon.cluster.registry/cluster-claims`), `:seon.task/target` (whether a merge follows), `:seon.task/config` (the overlay) and `:seon.task/execution` (discovery and permission; all `:seon.wake/starts`). Installed until task-model T3c: the one entity on main per chain (`:seon.chain/first`, `:seon.chain/branch`, optional `:seon.chain/merge?`, `:seon.chain/config`, `:seon.chain/from`), non-program, wakes root (TASK-CHAIN §1) | chain row, subject task, chain entity |
| owned | `{:seon.task/owned true}` on a task content member's schema (exactly `instructions` and `proofs`): set by the chain's template, changeable by an agent, never carried to the next task | inherited, per-step |
| instructions | `:seon.task/instructions`: what this task's agent does, an owned member set by the chain's template and never carried to the next task (TASK-CHAIN §1) | handoff, per-step intent, effective task |
| ready | the derived set of tasks that should start now: execution `:running`, latest attempt neither `:done` nor `:merged`, no attempt without an outcome (TASK-CHAIN §2.2; code: `seon.task/ready`, installed until task-model T3b, then the readiness rule inside `seon.cluster.reconcile/reconcile`: execution `:running`, every task in `:seon.task/needs` done where its attempts live, no open attempt on the task's branch, open attempts fewer than `:seon.config.agent/max-running`); never stored | frontier, ready list, queue, scheduler state |
| attempt | one agent's turn at one task on a branch, numbered within its task (`seon.id/id [handle number]`, `seon.task/attempt-tx`); its `:seon.task/outcome` is `:done`, `:merged` or `:closed` (`:done` lands in S3a-3; installed: `:merged`) | run (of a task), launch |
| execution | `:seon.task/execution`, the stored permission for an attempt: `:held` (never launched), `:running`, `:paused` (graph exists, nothing runs), `:stopped` (graph gone, resumable), `:cancelled` (terminal); it is the one release gate: every written or ingested task is `:held` (target, task-model T1; installed: the first task of a chain is `:running`) and only root's `my.root/run!` (a release) writes `:running`; cluster `:seon.cluster/execution` is `:running` or `:paused` | intent (the word now names nothing), status, run state |
| db<->flow | the one Flow process in the cluster graph that links Datahike and Flow both ways (`seon.cluster.agent/db<->flow`): it reads the facts, decides what to do (`seon.cluster.agent/launch-actions` for what to start and `seon.cluster.agent/next-actions` for what to end, so "plan" names only the task field: facts, the registry of running graphs and `:seon.config.agent/max-running` in, a vector of actions out), writes the attempt first and makes Flow follow (start, resume, pause, stop); the only thing that starts agent graphs; target (task-model T3a/T3b): its pass is `observe`, `seon.cluster.reconcile/reconcile`, apply | armer, dispatcher, launcher, a separate scheduler (the task graph is the scheduler, `needs` its order and `:seon.config.agent/max-running` its cap) |
| plan | `:seon.task/plan`: Markdown that starts as the user's request and that every task improves, with the references it cites; carried to the next task at each advance (TASK-CHAIN §1, §3) | intent, goal, description |
| start-flow!, stop-flow! | create, start and (under execution `:running`) resume one agent's graph on its branch, recorded in the registry of running graphs under `:seon.agent/started` (target, task-model T2: also asserted as the fact `:seon.agent/graph-process`); its orderly stop and join (`seon.cluster.agent/start-flow!`, `stop-flow!`) | arm!, disarm!, arm an agent, arm (for contracts: instrument) |
| problem task | a task root writes on main from facts when an attempt ends other than done (capped, stalled, given back, sent back, error, refused done or merge); its `plan` says what to do (TASK-CHAIN §2.7; installed: assigned to root or a fresh agent) | alert, escalation, fault notification |
| clock | the one proc that writes a firing fact for every cron task at its due instant and calls a cron task's function when it has one | timer, schedule proc, `seon.schedule.task` |
| firing | `:seon.task.fire/*`: one due instant of a cron task, idempotent by `[task nominal-at]`; delivered to a live agent as a wake, else an attempt | tick, schedule fire |
| heartbeat | the cron task with a function that pings every graph and writes `:seon.agent/observed` on change and `:seon.cluster/heartbeat-t` per period; older than two periods reads as unknown | liveness probe, health poll |

# Ignore generated Python bytecode during source admission

## Problem

The admitted Seon source closure includes `script/`, whose maintained process
helper is Python. Running its tests created an untracked `__pycache__` entry.
The root repository had no Python bytecode ignore rule, so Git reported that
generated file as dirty selected source and every Inspect run failed closed.

## Owner

The repository `.gitignore` owns generated artifacts. Source admission consumes
ordinary Git status and must not grow a second exclusion policy.

## Acceptance

Generated `__pycache__` and `.pyc` files are ignored throughout the repository,
while a modified tracked Python source file inside an admitted path remains a
source-admission failure.

## Resolution

The root ignore policy now excludes standard Python bytecode. A temporary-Git
regression uses the real repository rules and proves generated bytecode yields
no dirty admitted path while changing the tracked helper yields exactly that
source path. The focused source-admission gate passes 17 tests.

# Architecture: Static Flow, Malli-Derived Datahike Schemas, and COW Runtimes

Seon runs one static `clojure.core.async.flow` graph over a durable multi-process Datahike LMDB store, multiplexing scoped agents and isolated `clojure.test` + Malli generative runs across a bounded pool of Copy-on-Write (`fork`) OS processes.

## 1. Malli as Single Schema Authority & Program Ref Graph (`seon.schema`, `seon.schema.datahike`)

Every Datahike attribute (`:db/ident`, `:db/valueType`, `:db/cardinality`, `:db/unique`, `:db/index`, `:db/noHistory`, `:db/contentId`) is derived automatically from co-located multi-segment Malli schemas stored in `resources/seon/schemas.edn` (`316` schemas deriving `263` Datahike attributes `[M]`, spanning `:seon.code.*`, `:seon.agent.*`, `:seon.task.*`, `:seon.rule.*`, `:seon.signal.*`, `:seon.ui.*`, `:seon.user.*`, `:seon.view.*`, `:seon.error.*`, `:seon.health.*`, `:seon.test.*`, `:seon.summary.*`, `:seon.bench.run.*`, and `:seon.fix/*`).

- **Canonical `:db.type/ref` program graph:** Schemas expose `:seon.schema/keys`, `:seon.schema/optional-keys`, and `:seon.schema/ref-targets`; vars expose `:seon.code.var/input`, `:seon.code.var/optional-input`, `:seon.code.var/output`, and `:seon.code.var/calls` (unified across Jolt compiler IR and Malli AST); namespaces link `:seon.code.ns/requires-ns`; docs link `:seon.code.doc/references`; tests link `:seon.test/var-ref`; and rules link `:seon.rule/schema` and `:seon.rule/fn`. Pure `ns-map -> ns-map` renderers whose `:seon.code.var/output` includes `:seon.ui/hiccup` are discovered mechanically via `seon.render.fit/discover-renderers`.
- **Native `:db.type/data` & `:db/contentId`:** Malli forms (`:seon.schema/form`, `:seon.code.var/schema`), arglists, pull patterns, rule `:seon.rule/query` / `:seon.rule/assert` clauses, and benchmark run snapshots store natively via FASL (`:db.type/data`). Content-addressed identities carry `:seon.db/content-id true` so independent branches creating identical vars, schemas, rules, or tasks receive the same `:db/id`.
- **Co-located multi-segment naming:** Shallow `one/thing` schema keys are refused at registration; schemas live under the namespace hierarchy of the code that uses them.
- **Write-seam validation & safe migration:** `seon.store/validate-tx-data!` validates every transacted datom against the branch's live Malli registry before writing to LMDB. `(user/register-schema! k form opts)` validates a `seed = 42` generator and installs derived `:db/ident` declarations immediately; `seon.merge/three-way` blocks any merge that retypes an installed attribute or invalidates stored datoms.
- **Reactive LRU cache (`seon.store/lru-get!`):** Datahike block/index cache hits compose transparently with `datahike.reads/with-reads` (`datahike.index.interface/*reads*`), capturing and replaying index read ranges so cached UI walks, ambient signals, and incremental rule evaluations never miss live SSE invalidations.

## 2. Static Flow Graph & COW Fork Parent (`seon.main`, `seon.fork`, `seon.agent`)

Seon spawns a 1-thread `ForkParent` at the very start of `seon.main/-main` before Flow starts any worker threads or loads multi-threaded native libraries, guaranteeing safe `~6 ms` COW forks.

- **Static Flow topology (zero `flow/update!`):**
  - `:server` (`seon.server`): Request router for `/op` EDN and `/mcp` JSON-RPC 2.0.
  - `:transactor` (`seon.transactor`, `seon.transactor.calls`, `seon.transactor.merge`): Sole serialized writer of `:main`; executes 3-way merges, syncs active coordinator branches, advances `ForkParent` (`:advance-image`), and hot-loads merged deltas into the standing process.
  - `:reconciler` (`seon.reconciler`): Pure `O(|Δ|)` derivation of agent status (`:runnable`, `:running`, `:testing`, `:merging`, `:waiting`, `:merged`) — never stores derived status in Datahike.
  - `:agents` (`seon.agent`): Multiplexes logical agents onto `max-os-procs` warm persistent COW processes with LRU idle eviction and zero-PID cleanup on `:merged`.
  - `:model` (`seon.model`, `seon.model.wire`): Streaming OpenAI-compat / DeepSeek client over fiber-parking `jolt.http.core` (`StringBuilder` SSE accumulator, `reasoning_content` replay, `prompt_cache_hit_tokens`, `::flow/input-filter` backpressure). API keys stay exclusively in `:model`.
  - `:test` (`seon.test`): Transitive reach selection (`seon.code.reach`), 2-tier fail-fast (`<= 150 ms` fast shard first), `seed = 42` generative checks, content-addressed green cache, and anti-test-deletion checks.
  - `:git` (`seon.git`, `seon.git-proc`): Lossless `Datahike :main === Git main` write-back and zero-worktree `refs/heads/seon/<branch>` export via `git fast-import`.
  - `:web` (`seon.web`, `seon.web.actions`, `seon.web.styles`, `seon.render.surface`, `seon.render.fit`, `seon.render.entities`, `seon.signals`): 100% non-blocking HTTP/SSE server, 120 fps `datahike.reads` incremental walk over ONE unified rule-projected surface (`:canvas`, `:workspace`, `:debug`), debounced browser viewport sync (`seon.web/set-viewport!`), and in-process `/mcp`.
  - `:browser` (`seon.browser`, `native/browser/seon_browser.m`): Embedded macOS `WKWebView` host (`target/seon-browser`) for ephemeral end-of-context visual feedback.

## 3. Codebase Indexing, Native `d/q` Rules, Cold-Boot Sync & `O(|Δ|)` Rails (`seon.code.*`, `seon.rule`, `seon.merge`, `seon.switchover`)

Every `.clj`, `.md`, and `.edn` source artifact is parsed losslessly into structured Datahike entities (`:seon.code.ns/*`, `:seon.code.form/*`, `:seon.code.var/*`, `:seon.code.doc/*`, `:seon.code.file/*`, `:seon.schema/*`, `:seon.task/*`, `:seon.rule/*`).

- **Modular `< 8k` tok namespaces:** Focused sub-namespaces with zero legacy render/query/board/instrument duplicates:
  - `seon.code.{analyze,cst,cst.ns,edit,files,graph,io,migrate,overlay,parse,reach,refactor,rewrite}`
  - `seon.ctx`, `seon.ctx.project`, `seon.signals`, `seon.cite`, `seon.error`, `seon.task`, `seon.task.gate`
  - `seon.fork.{calls,container,helpers,worker-support}`, `seon.repl`
  - `seon.health.{contracts,efficiency,metrics,static}`, `seon.schema.{datahike,index}`, `seon.store.query`
  - `seon.render.{surface,fit,entities,ui,wire,data,tiles,ns-tile,lineage,chronicle,markdown,walk,print*}`
  - `seon.rule`, `seon.rule.{context,effects,seed}`, `seon.transactor.{calls,merge}`, `seon.web.{actions,css,styles}`, `seon.bench.{cluster,helpers,proxy}`
- **Native Datahike `d/q` + `d/pull` incremental rule engine (`seon.rule`, `seon.rule.effects`, `seon.rule.context`, `seon.ctx.project`):** Zero custom Datalog interpreter. Editable `:seon.rule/*` entities (persisted 1-to-1 to `resources/seon/rules.edn`) carry native Datahike `:seon.rule/query` and `:seon.rule/assert` clauses evaluated via `d/q` with shared recursive `%` rules (`seon.rule/default-datalog-rules`: `calls*`, `needs*`, `compatible-fn`, `render-fn`, `schema-doc`, `var-doc`) over `$main`, `$branch`, `$code`, `$task`, `$wm`, `?agent`, and `?agent-eid`. `seon.rule/step-rules` runs inside `datahike.reads/with-reads` (forwarding reads from both executed and skipped rules into outer `datahike.index.interface/*reads*`) to skip untouched rules in `O(|Δ|)`. Together with generic 2-read world discovery (`seon.ctx.project/agent-world-datoms`), `seon.ctx/related-updates`, and the dual-target Upgrade Ladder (`seon.render.fit/fit-projections`), one engine powers both responsive HTML (`seon.render.surface/render-surface`) and OpenAI Wire context (`seon.render.wire/build-live-wire-request`).
- **Cold-boot overlay & unloaded namespace hydration:** On startup (reboot or `--seed-store` isolated benchmark instances), `seon.main/sync-cold-boot-forms!` overlays all `:seon.code.form/*` entities (`src/` and `test/`, pulling `:seon.code.form/deps`) modified after `aot-build-ms`, while `seon.code/apply-overlay!` hydrates unloaded target namespaces (`#ns` + sibling forms) in topological order before overlaying deltas.
- **Automatic atomic switch-over (`seon.switchover`) & mid-session branch sync:** When a merge modifies boot inputs (`seon.main`, `seon.fork`, `deps.edn`, `native/*`), Seon runs `bin/build seon` -> `--self-test` -> graceful drain -> `--take-over 9998` automatically. Warm agent workers automatically hot-load newly merged `:main` deltas (`seon.fork/sync-conn-to-latest-branch-head!`) overlaid with their own branch edits before each eval.
- **Declarative persistence (`seon.code.files`) & thin outside footprint:** `resources/seon/schemas.edn`, `resources/seon/tasks.edn`, `resources/seon/rules.edn`, `resources/seon/agents/{root,examples}.edn`, `resources/seon/config/default.edn`, `AGENTS.md`, `docs/*.md`, `src/`, and `test/` import on fresh install and write back atomically on every green merge. `bin/mcp` (stdio relay to `POST /mcp`) and `bin/seon` (CLI relay to `POST /op`) hold zero business logic; `bin/build` bootstraps native C/Chez/Jolt/LMDB artifacts.

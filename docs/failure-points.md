# Failure points

Every place the outside world can fail us is named here with its one catching edge and its declared error; nothing else catches, and no guard stands in for naming it.

A **failure point** is a place where the world outside our code can fail us. Exactly one function meets it, its **edge**, which either answers a declared variant (plain data its callers handle as an ordinary branch) or is an **entrant boundary**, which turns a defect into a recorded error map. A refusal or a death answers its asker with the error map alone, never an imitation of success: every asker branches on `seon.contract/error?`. Whatever an edge raises reaches the requester whole ([an error keeps data](errors.md#an-error-keeps-data)).

This page is the law's list: every function in `src/` holding a `catch` must be named on it in backticks (```seon.problems/laws```, the `:unnamed-site` row that `bin/check health` prints; [health](health.md#a-laws-unnamed-site)). [Clocks](clocks.md) and [resolution](resolution.md) are judged the same way by `bin/laws`.

## Entrant boundaries (a defect becomes a recorded error map)

The boundaries where a defect in a request becomes a recorded error map instead of ending its process.

An eval's record is plain data: a value in it that is not (a library's record inside an exception's data) is kept as its printed text (```seon.repl/record-details```, the one place a record is made storable), and a record the branch still refuses is answered to the eval (`seon.repl/record!`, above).

| boundary | edge | what it records |
|---|---|---|
| reading and evaluating an agent's form | `seon.repl/eval-code` | an `:err` reply item; reading goes on after an error, the request ends after an interrupt |
| a component's render on any page, and a render called inside hiccup | `seon.render/render!`; `seon.web.html/write!` | `:seon.render/component-defect` (the render, the throw, its data under `:seon.render/threw`) as the component's part; every other component draws. A model render runs in its own try at the same edge, so it never blanks the person's page |
| a reaction's run (agents write renders) | `seon.ratom/Reaction` (`seon.ratom/->Reaction`) | the throw kept as the reaction's state and rethrown at its next deref; `flush!` goes on (`seon.ratom-test/catching`) |
| an agent's definition that breaks Seon's recording of it | `seon.repl/wrap-record`, by `seon.repl/undo-definition!` | the vars put back; `:seon.repl/definition-undone` |
| a turn of the agent's loop meeting the branch's program (the agent may have redefined what Seon calls) | `seon.turn/work!`, `seon.turn/status-now` (`seon.turn/turn-error!`) | the error map as a message from seon, read at the next turn; a second consecutive throw with no model turn between ends the agent `:error`. So a turn's decisions read stored facts, never re-run code the agent may have broken: ```seon.reconcile/hairy``` takes the task's names from its stored cites, not by re-parsing its plan with ```seon.ref/scan``` (`seon.agent-test/a-broken-parser-reaches-the-model`). `seon.turn/end!` runs outside it |
| a request's evaluation | `seon.repl/eval-string` | the answers so far plus one `:err` item. Only the forms and the REPL's machinery run inside it: the record keeps the call's intent unparsed (```seon.repl/record-details```), so a broken parser cannot stop the REPL answering (`seon.repl-test/a-broken-parser-leaves-the-repl-answering`) |
| the plan's parse while an agent asks about a name that is no var | `my.agent/plan-cites`, under `my.agent/no-var` | the answer names the throw and reads the task's stored cites (```seon.task/task-cites```) |
| the agent process's loop | `seon.repl/serve!` | Flow's error channel: the cause on stderr, the request answered with the error map (`seon.repl/defect-answer`), and the agent goes on so it can repair what it broke |
| a test run in an agent's test child | `seon.agent/run-tests-forked` | an `:error` report |
| A test in an agent's test child waits on what nothing can deliver | ```seon.agent/test-child-runs!``` (``jolt.host/on-quiescent!``) | `:seon.test/deadlock` `{:test :dump}` thrown into the test's fiber, once: that test is `:error`, and its report and the run's answer reach the agent |
| a defect in a test run's fold (a throw in its resume or its step) | ```seon.agent/test-run-step``` (```seon.agent/fold-threw```) | every live child killed and its proc removed; the throw is the run's answer, raised by ```seon.agent/run-tests-forked``` as the run's own: the run ends, never hangs |
| a value the test child sends that does not read as EDN | ```seon.agent/child-codec``` | `:seon.test/unreadable-line` with the value's head; the test it was about ends `:error` once and the fold goes on. The producer sends only what crosses EDN (```seon.agent/test-report```) |
| a namespace's tests in a proof run (a fixture that throws, or past its tick budget) | `seon.proofs/run-tests!` | each unreported test an `:error` result, never stored |
| an effect worker performing a request | `seon.fx/worker-proc` | `:seon.fx/defect` as the outcome: the asker is always answered |
| an effect worker folding a streamed reply | `seon.fx/stream-step` | `:seon.fx/defect`, the rest of the stream read and dropped |
| one outside connection's request (line EDN or MCP's JSON-RPC) | `seon.server/respond` | `:seon.server/defect` (for MCP a JSON-RPC error, `-32700` for a line opening `{"` that is not JSON); every other connection goes on |
| every root proc | Flow's error channel, piped to the api's `:back` | `:root-errors` in the api's view, written once per signature on main with repeats counted (`seon.error/flush-tx`; `my.root/problems` reads both) |

A timed wait, a foreign call or an unrecorded raw wait counts as running |
| A db value read after its store's last release | `konserve.jolt.lmdb-ffi/live-env` | `{:type :lmdb-env-closed :path}` ([storage](storage.md#a-value-is-read-before-its-last-release)) |
| Datahike refuses an agent's run-ahead apply | `datahike.writer/apply!`, called by `seon.agent/transact!` | thrown into the agent's eval |

## Physics: who may run threads

The rules of the OS and Chez that no code may "fix" by adding a thread or a check.

- **A process that forks must be one OS thread when it forks.** `seon.lib/fork!` forks only while its caller is the one active Chez thread, but a thread counts as inactive while it still holds a channel's mutex (`reference-code/chez/c/thread.c` deactivates before the wait releases it), so a child can inherit a locked mutex with no owner. Jolt's process-wide locks are made afresh in the child (`define-process-local`, `jolt-after-fork-child!`; Jolt's `test/chez/fork-held-locks-test.clj`), as are object monitors (`monitor-reset-after-fork!`); a lock inside any other object (a channel's, a promise's) is why the rule stands. Chez's parallel-collector sweeper threads hang a forked child too, so the binary's `-main` fixes the pool at 0 and root fixes it at `:seon.config.root/gc-sweepers` (0) after it forks the fork server (`seon.lib/gc-sweepers!`, Chez branch ``jolt/gc-sweepers``).
  - **The one exception** is `seon.lib/end-with!`'s C watcher thread: made with every signal blocked, holding no Chez or libc lock, never registered with Chez; `fork!` arms it again in the child (```seon.lib-test/a-process-forks-beside-its-watch```).
  - **Who forks, and from where.** Root (once: its fork server), the fork server (agents and its standby) and every agent (test children, `clone!`) each fork from `jolt.host/main-carrier-run!`, which runs every fiber, timer and poller on the calling thread. Root's boot runs on it up to the fork (```seon.system/boot!```), so the fork server shares root's loaded program copy-on-write; then root starts its threads, and a second boot in one process is refused (```seon.system-test/a-second-boot-in-one-process-is-refused```). The fork server and its agents stay on the main carrier. A test that forks does it from a fresh process's main carrier (```seon.lib-test/a-forked-child-runs-go-blocks-and-makes-a-store```, `seon.check/fork-cases`, `seon.check/cycles`).
  - **On the main carrier:** a blocking foreign call stops every fiber until it returns, so a wait on another process parks on the I/O poller (```seon.sock/line-reader```'s `jolt.io-poller/wait-ready`; the test child's exit on `jolt.io-poller/exit-chan`, ```seon.lib-test/a-wait-for-a-line-parks-the-fiber```); a poller's ready is a hint, and a read that finds nothing parks again. The loop wakes on root's SIGUSR1 and SIGIO through kqueue (`jolt.io-poller/wake-on-signals!`). On Linux, with no kqueue, an agent runs on its thread.
  - Only root, which never forks after boot, holds `jolt.async.remote` ends with pump threads. `bin/check threads` counts the fork server's and an agent's OS threads.
- **A forked child must not touch an Apple framework.** Once a process has made a thread, macOS treats its forks as multithreaded: a child that first touches an Objective-C class aborts, and Metal in a child never compiles. Every Seon process is threaded before it forks, so a forked process may use DNS and TLS but not Metal, Foundation, Security or CFNetwork; work that needs them runs in an exec'd process (the embedding model, `seon embed-worker`, [vector](vector.md#the-model)).
- **A forked child holds none of its parent's threads, only their bookkeeping.** fork(2) copies the calling thread, so the child resets Jolt's carrier pool, timer, thread tables and shutdown watcher first (`jolt-after-fork-child!`, Jolt branch ``jolt/fork-carriers``; `seon.lib-test/a-forked-child-runs-go-blocks-and-makes-a-store`), starting no thread, so a child that forks again is still one thread. A pool made with `jolt-fiber-pool-make` is not restarted: make it after the fork.
- **On macOS, a descriptor in flight by SCM_RIGHTS can be discarded when other unix sockets close,** so the sender keeps its copy until the receiver confirms (the fork server's `:in-flight`; a clone's socket until `:cloned`), and a descriptor rides a frame of its own, sent only while the pump is idle (`seon.agent-proc/send-fd!`, `:fd-ready`).
- **A child that cannot end.** A child stuck in a mutex wait with a zombie grandchild ignores SIGTERM and writes no fiber dump; a test child at Jolt's heap ceiling may park instead of dying. Take `sample`, `lsof` and the thread list before a SIGKILL ([machine](machine.md#reading-a-hang)).

## A model's reply is read after it is forgiven

Text from a model or a person may not read, and the loaders and the REPL need its forms. ```seon.reader/opts``` is edamame's options for text in a namespace (every Clojure syntax, `::kw` resolved, any tag read as its form, the `:clj` branch); ```seon.reader/read-all``` reads every form; ```seon.reader/arglists``` reads a definition's params from its recorded source. A form's lead (the comments before it) is found by ```seon.reader/line-starts```, ```seon.reader/lead-end``` and ```seon.reader/lead```; a comment on the line the previous form ended on is that form's. ```seon.reader/forgive``` turns a reply into source a REPL reads, answering `{:text :repairs}`: a line of prose becomes a comment and unbalanced delimiters are repaired; a reply with a code block reads only its code.

## Contracts over host objects are proved by deftests, never by generation

`bin/check mg-check` runs `malli.generator/check` only on pure namespaces' contracts. A function over a pid, a descriptor, a signal, a socket or a connection is never handed generated arguments (a generated pid passed to `kill(2)` is a real signal); its deftests and the end-to-end checks prove it with the values the system holds.

## The profile's counts are exact on one thread only

`seon.profile` keeps each armed function's counts in a plain vector with no lock, since a lock costs more than the counter. Agents, the fork server and test children are single-threaded, so their counts are exact and cost proofs run there; root's are approximate and nothing reads them as proof. A measurement nested in another restarts the epoch, so the outer one records only the calls after it.

## A directory walk enters no linked directory

`file-seq` follows a symbolic link to a directory, so a link to an ancestor is a walk with no end. The walk of a tree is `seon.fx/files-under`: every regular file once, no linked directory entered (`seon.fx-test/a-walk-of-a-tree-with-a-link-cycle-counts-each-file-once`); `read-source` and the verdict cache's eviction use it. A test child works in a directory of its own (`seon.fx/run-dir`), removed by its agent when the child ends (`seon.lib/remove-tree!`; `seon.agent-test/a-test-run-leaves-nothing-in-its-agents-working-directory`).

## LMDB locks

LMDB's locks are our fork's ``MDB_USE_FCNTL`` (`bin/build lmdb` builds `reference-code/lmdb` with ``MDB_USE_ROBUST``; [forks](forks.md#lmdb)): the reader table, writer and sync locks are each a process mutex plus a record lock on one byte of `lock.mdb`, taken through an open file description of its own (`F_OFD_SETLKW`, `mdb_flock_wait` in `mdb.c`). One description per lock, because with one POSIX owner per process the kernel answered two processes' crossed lock waits with EDEADLK. The kernel releases a record lock when its process dies, so a SIGKILL inside a write transaction never leaves the writer lock held (the next holder repairs the region), and LMDB makes no SysV semaphore, so no death or deletion fills a system table.

A process opens a lock file once (`MDB_lockfile`) and every env of it in the process shares its descriptors, since closing any descriptor drops all its POSIX locks. A child of fork() closes the descriptions it inherited inside `fork()`, before any of its code runs, and opens its own: each agent opens the store itself (```seon.db/after-fork!```) and makes every inherited db value again through its own env ([storage](storage.md#an-agents-reads-and-writes)). A transaction begun through an inherited env is refused with ``MDB_ENV_FORKED`` (`native/lmdb_kill.c` case 10), since its reader slot would stand under the parent's pid. Seon forks with libc `fork()` and starts programs with `posix_spawn` or fork-then-exec; nothing calls `vfork` or `clone`. A dead process's reader slot is cleared by a reader that finds the table full and by a writer whose oldest reader is dead. The lock region's format is the build's: while one build holds a store, another build's open is refused with ``MDB_VERSION_MISMATCH``; the first open when no process holds it remakes the region in its own format. `bin/check`'s `lmdb-kill` (`native/lmdb_kill.c`) and `lmdb-lock` (`native/lmdb_lock.c`) steps prove each claim, case by case.

A directory that may hold a store is deleted through ```seon.lib/remove-tree!``` (`bin/remove-tree` in the shell), which first closes this process's stores under it (``konserve.jolt.lmdb/close-envs-under!``), so nothing of a deleted store stays mapped or anywhere outside its tree (`seon.db-test/a-deleted-store-leaves-nothing`).

## LMDB crash safety

A store is opened ``MDB_SAFENOSYNC`` (```seon.db/store-cfg```, [durability](storage.md#durability-is-continuous-group-commit)): a commit is not flushed, and ```seon.db/sync!``` (`mdb_env_sync`) makes the newest commit the steady snapshot: it orders every write before it (`F_BARRIERFSYNC`), writes a checksummed mark of that commit's meta into the meta pages' unused tails, flushes (`F_FULLFSYNC`), and only then lets the previous snapshot's pages be reused. After an OS reboot, the first writer to open the store alone rolls it back to the mark: the commits after the last sync are lost, the store is whole. Until then every other open fails with `MDB_UNSETTLED`; where the OS's boot cannot be identified, the flag fails with EINVAL. So a SIGKILL loses nothing, and an OS crash or power loss loses only the commits since the last sync. `bin/check`'s `lmdb-crash` step (`native/lmdb_crash.c`) crashes 40 commits at every write point, with the unflushed writes landing in any subset and order, and every image reopens holding the last synced commit. Not shown: what the drive does with the flushes at power loss, and a volume that loses writes without a reboot. While the flusher is stalled, the file grows by the pages freed since its last sync.

Production opens one store per process; a test process holds what its tests open, and a test's own store ends with the test. An open store holds only a mapping and descriptors, no system table. A store is made whole or not at all (```seon.db/open!```): built in a sibling directory (`<path>.making-<uuid>`) and renamed to its path, so a failed create leaves only garbage beside it (`seon.db-test/a-create-that-fails-leaves-no-store`).

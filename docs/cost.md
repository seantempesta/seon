# Cost proofs

**Cost is work done (ticks, bytes, calls), never wall or CPU time** (owner, 2026-10-23: "I like ticks vs wall clock or anything that is load dependent. Work done, not scheduled time slices").

A cost proof (`seon.cost/proof`) states what a function's work should cost as its input grows, measures it at a few sizes, and is red when a size costs past its estimate or grows steeper than the work needs, in a dimension that is counted exactly (```seon.cost/exact```: bytes and calls). Time is measured, recorded and shown beside them, and is never red: it moves with the machine's load, while a green is reused forever at its reach digest ([merging](merging.md#a-merge-runs-what-the-change-reaches)), so a verdict must be a function of the code and its input alone (owner via root, 2026-10-23; before, a proof green on a quiet machine was reused under load and one judged under load went red: thread CPU 158 µs at load 10, 210 µs at load 17). Time's counted dimension is the engine's ticks (below).

## What is measured

A proof measures the function under test, on the thread that calls it, and nothing else in the process (task ``seon.cost/a-proof-measures-only-its-own-thread``):
- **time** is that thread's CPU time, `seon.profile/cpu-ns` (CLOCK_THREAD_CPUTIME_ID). Another thread's work and a pause the scheduler gave to someone else are not the call's. A call that waits (on a channel, a socket, a lock, a sleep) is measured by what it does, not by how long it waits: the waiting is its dependency's cost, proved on that dependency (`seon.profile-test/a-measures-time-is-what-its-thread-does`: a call sleeping 20 ms reads under 2 ms). What the thread's time still holds: a collection that runs on it (the collector runs on the thread that triggers it), and how fast its core runs. Under load the scheduler moves it between the M1's performance and efficiency cores and the clock speed changes, so the same work costs more CPU time: 3.9 ms alone and 5.2 ms (1.34x) beside 16 busy threads, measured 2026-10-23, its wall time hardly more. So time over its estimate (3x) is a finding shown in the verdict (`TIME OVER (measured, not red)`), never a red; bytes and calls are exact;
- **bytes** are what that thread allocated, `seon.profile/alloc-bytes`: Chez's per-thread count on our branch `jolt/thread-bytes` (its allocation areas less the tails it dropped, and its large objects). Another thread's allocation, a collection's copying of live data, and the conses the collector and the runtime's own books make on this thread (`during_alloc` raised: locked objects, guardians) are not counted. Chez's own `(statistics)` and `bytes-allocated` count the whole process: under them a proof read whatever else ran during it (1.4 GB in 200 ms while one other thread allocated), and a proof went red in one full `bin/test --reach` and green everywhere else;
- **calls** are the contracted functions it called, counted exactly (`seon.profile`);
- **ticks** are the work the call did, counted by the engine timer at compiled code's procedure entries and loop back-edges: `jolt.host/ticks-of` (dry-run's Jolt `jolt/thread-ticks`, the one owner of the timer: budgets and fibers read the same count). Measured 2026-10-23 (worktree session pure-tests, `notes/pure-tests/ticks.md`): over 30 runs in each of 6 processes, at load 21 and at 47 with four burners, every form counted the same ticks (a reduce over 1e5: 579053; a 1e4 map build: 425691; a sort of 1e4: 1440586), while thread CPU time over the same runs spread 36-860%; twice the input gave 2.000x and 4x gave 3.999x; an extra inner loop that allocates nothing gave 2.56x the ticks with byte-identical allocation (CPU time 1.6x). A collection adds about 11 ticks. **The blind spot:** work done in C, a foreign call or a bulk copy, costs next to no ticks (a string concat measured 3000 ticks at 1 MB and at 4 MB while its CPU time grew 4x), and waiting costs none; bytes count the copies, which is why bytes stay beside ticks. Ticks belong to the compiled code, so a Jolt or Chez change moves them: both pins are in every result's digest. Until that pin lands a verdict is decided on bytes and calls.

Each size is the least of several repeats (`seon.cost/measure`), less what measuring an empty call costs. The proofs: `seon.profile-test/a-threads-allocation-is-its-own`, `seon.profile-test/a-measure-is-the-same-beside-another-thread`.

## Where it is used

An agent's task names its cost proofs as goals ([agent](agent.md)); `bin/test` runs them with every other test; the time a proof's estimate is priced in is the unit table `seon.cost/units`. Clocks that order events are `seon.profile/now-ns` ([machine](machine.md#the-clock)); `cpu-ns` orders nothing ([clocks](clocks.md)).

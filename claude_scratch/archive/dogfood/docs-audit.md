# Docs-in-the-db audit (read-only), checkout jolt/dogfood = main, scripted root :8240

Headline: the owner's idea 4 is mostly built. A section is already an entity with heading, lead, text, parent, resolved references, and three depths (:summary / :doc / :code) already exist as `seon.docs/view` -> `seon.ref/shown`. What is missing is a "references" level on that view, a way for an agent/UI to ask for a page at a depth, and (the 223) a stale check that is real-by-design but noisy.

## 3. Stale sections
- Class `:stale-section`, `seon.problems/stale-sections` (problems.clj:219-260). Row per (section, var) where the var's current `:form/id` differs from `:seon.section/read[var]`, or `then = "absent"` (var did not exist at the section's last commit); plus one `"... baseline"` row per `:seon.section/baseline-unread` (git could not give the baseline). Baseline comes from `git blame` of the section's lines + `defining-ids` at that commit (`docs/baseline-reads`, docs.clj:~185); `read` is kept while text unchanged (load-tx). Attention only, never refuses done (docs/health.md#a-stale-section). Closed by editing the section or `my.docs/reviewed!`.
- The 223: NOT reproducible on :8240. That scripted root stored 0 `:seon.section/read` (no baseline taken), so `stale-sections` = 0 there; I did not touch the owner's main root. From the code the 223 are rows = sections x cited vars, of kind: (a) "changed" (cited var edited since the doc's last commit; any edit, even a docstring/whitespace-sensitive form-digest change, counts), (b) "absent" (doc cites var added after the doc's last commit; "code now, read it"), (c) baseline-unread (git could not answer). Get the split with `(frequencies (map #(cond (nil? (:name %)) :baseline (= "absent" (:then %)) :absent :else :changed) (seon.problems/stale-sections db {})))` and top pages/names on the owner root.
- Real drift or check defect? By design real: form digest moves exactly when the var's text does, so it flags every edit to a cited var, relevant to the prose or not (health.md says so: "every edit of a var stales the sections that cite it"). A counted row per (section, var) inflates it (223 rows is probably far fewer sections). Defect candidates to check on the owner root: "absent" rows for a section whose lines are mid-edit (uncommitted -> read as today, fine), and a section citing a var at `:code` depth (full-source citation) staling on every edit. Cheapest cut: report per section, or only stale when the var's arglists/contract/docstring changed (not body).

## 4. Summary and renders that exist today
- Lead is stored (`:seon.section/lead`, ref.clj `sections` ~430: the heading's next block when a paragraph; else `:seon.ref/opening`, not stored) and the summary is derived: `seon.ref/lead-sentence` (ref.clj:424) = first sentence; `shown` (ref.clj:473) :summary = heading + lead's first sentence, :doc = lead/opening + `below` (child addresses/headings), :code = whole section. 54/364 sections have no lead -> `:no-lead` problem-kind.
- Renders/readers of sections: 
  - `seon.docs/view` (docs.clj:~170): one section at a depth; used by `reached`/`cited-view` for citations in the model context (`seon.context` line 176 task :sections; `docs/cited`) and `seon.render/walk` kind `:section` (seon.render.edn:36), `seon.render.ui` 894 (cites in a run page).
  - `seon.docs/page` / `page-text` (docs.clj:~190-210): the whole page from sections (headings, leads, text); used for the system prompt and help page (`seon.context` 19-35, 587) and `my.agent/help` (my/agent.clj:163-170: list of sections with first-sentence lead, or one section's text).
  - No UI page/route for docs found in render/ui.clj (only `docs/source-of`/`cited` for runs); no render declared on the section schema (no `:seon.render/*` on seon.section.edn); `resolve-ref` gives vars the same 3 depths (docs.clj:~275).
- Gaps: no depth that returns resolved references; `view` shows `below`, not `references`/backlinks; `page` has no depth parameter (always body); no page-level summary.

## 5. Design sketch (no new attribute)
Three levels per section, all derived from stored attributes:
- summary = `ref/lead-sentence` of `:seon.section/lead` (already `view ... :summary`).
- body = `:seon.section/lead` + `:seon.section/text` (already `:doc`/`:code`).
- references = `:seon.section/references` pulled with `{:seon.section/references [:seon.section/address :seon.section/heading :seon.section/lead :var/name]}` (the pull in `docs/section` already does this as addresses) plus names/backlinks via the reverse `[?x :seon.section/references ?s]`; each shown at :summary through the same `docs/cited`/`resolve-ref`.
Minimum change: (1) add `:seon.ref/references` (and `:seon.ref/cited-by`) to the `:seon.ref/view` schema (seon.ref.edn:79, a view key, not a db attribute) and fill it in `docs/view` when depth is :refs (or at :doc); (2) give `docs/page` a depth arg so `my.agent/help`, context and a UI page ask for page summary (all leads' first sentences), body (page-text) or with references; (3) the UI/walk render `:section` kind through the same printer. Replaces: `my.agent/help`'s own two-arity shaping (agent.clj:163-170) and `docs/section` (a third ad-hoc pull) both fold into `view`; no new proc, no new attribute. Fix first: the 54 lead-less sections (summary falls back to `opening` or heading), and decide the stale rule (per section, or contract/doc-level change only) so "docs in sync" is a signal not 223 rows.

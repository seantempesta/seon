# Parking and resuming an agent in Jolt/Chez (read-only research, 2026-10-25)

Measured vs read: everything below is from code and docs. I ran nothing; idle CPU and per-parked-agent footprint are NOT measured anywhere I found (only "~1.4 MB each", config comment for max-agents, default.edn:28, f2-final provenance).

## 1. Parking cheaply

What an agent already is: a single-threaded Chez process (processes.md:5, failure-points.md:89-101). Its idle state is `seon.agent/next-msg!` -> `recv-raw!` -> `seon.sock/recv!` (src/seon/agent.clj:39-61, sock.clj:189) = a blocking read(2) on its socket. No Flow, no fibers, no go blocks in an agent: only root runs threads/Flow (processes.md:5). So the "Flow can park it" half lives in root's agent proc (`seon.agent-proc`), not in the child.
- Threads: a parked agent has exactly 1 OS thread. `proto-fork-alone` (src/seon/lib.clj:149-160) refuses to fork if `$active-threads` != 1 and the child calls `jolt-after-fork-child!` (forks.md, jolt `6871f997..4342b73c`) to drop carrier/timer/shutdown-watcher bookkeeping, so none of Jolt's service threads (fibers.ss carriers, timer, io-poller; scheme-adapter-runtime.ss:49) exist until first use in the child. Jolt fibers/`go` (`*go-backend* :fiber`, forks.md `93af2568`; core/async.clj:31) only matter in root.
- GC: Chez collects only when an allocation trips `collect-trip-bytes`, via `collect-request-handler` (Jolt installs its own policy: scheme-adapter-runtime.ss:1225, rt.ss:434). A process blocked in read allocates nothing, so it has no collect request: no timer, no sweeper wakeups. Sweepers: `lib/gc-sweepers! 0` in `seon.main` (main.clj:103) before anything collects, so none exist in the fork server or agents (root fixes 0 too, default.edn:75). An idle agent is ~0 CPU by construction (the signal handlers SIGUSR1/SIGIO, sock/signal-at-input!, only fire on input).
- Memory: fork gives COW sharing of the precompiled program; `mem-mb` = macOS `phys_footprint` (cost.md:42, lib.clj mp-probe) charges only what the child wrote. What dirties pages: the turn's allocation (trip 4 MB, default.edn:210, agent.clj:743) and everything promoted by collections (Chez copies, so every surviving object is a new private page; shared code pages are not rewritten except GC touching headers/remembered sets).
- Settings that help, none used by Seon today (grep src/seon: no hit):
  - `(heap-reserve-ratio 0.0)` (Jolt wrapper `sa-gc-reserve-ratio!`, scheme-adapter-runtime.ss:119-124). Chez default 1.0 keeps one free page per page in use after a collection, so a worked agent holds up to 2x its live data.
  - `(release-minimum-generation)` default = max generation (chez s/back.ss:47): freed segments return to the OS only after a max-generation collection (`S_free_chunks`, c/segment.c:467 munmap). So before parking: `(collect (collect-maximum-generation))` with reserve-ratio 0 gives back the nursery and garbage; the heap shrinks to live data. One full collect on a small heap is ms-scale (not measured here). Do it once when the agent goes idle, not on a timer (§4: no clock).
  - macOS also compresses idle private pages, but `phys_footprint` still counts compressed pages (cost.md:42), so releasing is the only way to lower the charged number.
  - No madvise call exists in Jolt/Chez; Chez uses munmap. Not needed.

## 2. State images (jolt.image)

stdlib/jolt/image.clj (180 lines) is a STATE image, not a heap image: "The value graph travels; execution does not. No thread stacks, no continuations" (image.clj:1-30). No `save-heap`, and Chez's own `$heap` dump is not used. API: `dump!`/`read-image` of one value, `dump-world!`/`restore-world!` (writes the root of every data var in non-clojure/jolt namespaces, skips fn-valued vars because "the restoring process is the same build and already has it"), `scan`, `register-handler!`, before-dump/after-restore hooks. Format 11 (CHANGELOG:351), pinned to the runtime version, survives machine/arch but not a Chez upgrade.
- Covered: persistent data, lazy seqs (unforced), vars, named fns, anonymous closures as SOURCE + captured values, records with protocols, multimethods/namespaces as names, channels (CHANGELOG:2367).
- Refused or lost: open resources (ports, sockets, LMDB handles, procs, foreign libs) unless a handler or stub mode; unfinished futures; transients; closures whose captures were optimized into compiled code; runtime-built fns.
- Seon turned the closure-source part OFF: `:seon.config.build/jolt-compiler-options "{:image-fn-forms false}"` (default.edn:261-267, bin/env:42, forks.md `eba8826a`; saves ~1/3 of defn compile allocation, 5.03 -> 3.42 MB). So an anonymous closure in an agent's atom or def would not dump unless that option were on for that code (fn forms registered by `image-register-fn-form!`, host/chez/fn-form-registry.ss).
- Cost: writing walks the graph and renders fn sources; reading COMPILES every carried anon fn. Not measured by Seon. Restoring also needs the program loaded first. Trusted-code only.
- Verdict for resume: usable for REPL-local data (atoms' contents are data; "host cells come back empty" in storage.md:150 is what an image would fix), not as a replacement for the branch program. It does not capture what Seon cares about most (live sockets/store handles are remade at init anyway: agent.clj:738-760). A per-commit image would duplicate what the db holds (definitions + evaluation records) and ties resume to one Chez/Jolt build.

## 3. Re-evaluation / program load as resume

Seon already has it. docs/storage.md:150: a branch's program at commit C is `d/commit-as-db` at C (0.7-0.9 ms) then `seon.program/load-diff!` (program.clj:799-815) from definitions; "code and data definitions restore exactly; host cells (atoms, delays) come back empty and host objects ... made fresh, as at boot". A real form loads in 1.6-5 ms (storage.md:150); load-diff! cost = reading both dbs' form ids and pointers as datoms + one `form-row` per added form (was ~1.4 s of four live-forms reads on Seon's whole program before the rework). Compile cost context: notes/check-form-measure-2026-10-23.md (3,397 units, 0 failures); the emitter allocates ~ -49% after "one buffer" (plan.md:23). So resume = fork the warm server (0.08 s warm attach, perf-2026-10-24.md:14) + load-diff! of the branch's own changes since its merge base (agent.clj:763-764, the `resumed` path, exactly this) = ms per form.
- So loading the branch program restores code, defs and data defs. Left: (a) host cells whose value came from a def init (`(def a (atom ...))` comes back re-initialised by re-running the init, not the later swaps), (b) REPL evaluations that are not defs (records only, storage.md:150; results are data in the eval record but not re-bound), (c) open handles.
- What can be skipped: non-def forms entirely (their effect on durable state is already in the branch via transactions; their effect on process state is the gap). Forms whose results are data: only worth binding if the agent used them by var name, i.e. were a `def`, which load already covers.
- Re-run option for (a)/(b): replay the recorded eval forms after load, only those whose records touched process state (a `swap!`/`reset!`/`def` of a host cell). Only on owner-approved resume ("if user approved this is fine"). Costs forms x ms plus the forms' own work (ticks are recorded per eval: wrap-cost, cost.md:48) so a budget (sum of recorded :ticks) can be shown before replaying.

## 4. Fork from a commit

Today: the fork server holds main's db at commit k (fork-server.clj, processes.md:11), forks a child that inherits main's compiled program; `:fork` carries commit/t and `seon.agent/misaligned` records `:seon.agent/fork-misaligned` if not equal (agent.clj:763-765, storage.md:152). A resumed kept branch (agent.clj:748-764): `base` = branch-base (merge base with main), program = main head + `load-diff!(base, branch head)`.
- A branch at an older commit C: children get main's head program; to get the branch's program at C: db = `d/commit-as-db` at C (0.7-0.9 ms), then `load-diff!` from the fork's db0 to db-at-C (this already removes defs main gained and loads defs C had: `remove-definition!` for from-not-in-to). Cost = (forms different between main head and C) x 1.6-5 ms + datom reads. For a branch a few commits behind main this is small; for an old branch whose base is far behind main it grows with main's distance, but still ms per form.
- A parent per commit: no. Each parent is a Chez process that must stay single-threaded and idle, holding a full program (shared COW but dirtied by GC and its own loads); with ~hundreds of commits per branch this is exactly the parking cost multiplied. Load-diff is cheaper and uses the db that already stores everything.
- Change needed: add a `:commit` target to resume (db-at-C instead of the branch head) in `agent/init!`'s `resumed` path; the rest exists.

## 5. Recommendation

(a) Parking: keep the agent process as is (1 thread, blocked read, no GC activity = ~0 CPU) and, when it goes idle (the turn ended and no message pending), run ONE full collect with `heap-reserve-ratio` 0 so it hands the nursery and garbage back; restore ratio at next message. Change: a small `seon.lib` helper over `sa-gc-reserve-ratio!` + `collect` (both exist; no Chez or Jolt change), called from the agent loop at the idle point already in `next-msg!` (agent.clj:48-61) as an event, not a timer. Measure footprint with `lib/real-mb` before/after at n <= 100 under `nice`. Expected: footprint falls to ~ live data, i.e. close to the 1.4 MB/agent figure plus whatever the agent holds. Upper bound: dirtied-pages-by-live-data.
(b) Resume: use `load-diff!` at commit C (and replay only owner-approved process-state forms after it). Do not build heap images. If REPL-local data matters, add an optional `dump-world!` of the agent's own namespace as data (needs `:image-fn-forms true` only for forms that define closures held in data; otherwise stubs) as an extra, not the base mechanism; costs: image graph walk + recompiling carried fns; no Chez change. Jolt/Chez changes needed: none for (a) or (b). Optional later: a Chez atfork handler resetting sweepers (failure-points.md:98) would let root fork too, but it is not needed for this goal.

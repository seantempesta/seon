# What the slowest tests and check steps are worth (2026-10-23)

Read-only review for the "full run much faster, unneeded tests deleted" brief. Rule applied: a test
is needed when it is the only one that would go red if a mutation broke what it covers. Nothing
below was re-run; every second is the 2026-10-23 baseline on a machine at load ~25
(`notes/pure-tests/baseline/per-test.txt`, `target/check/20261023T053153/*.time`), so CPU-bound
wall times are inflated, and niced work (builds) most. "Where the time goes" comes from reading
the code and logs; where I estimate a split rather than measure it, the table says "est.".
Unmeasured: swarm's log came in late, and e2e-loop, e2e-stuck, resume and scale had not finished
when this was written.

Baseline totals: bin/test --all shards 437 / 110 / 68 / 397 s wall (shard 0 is 87 s CPU: it
mostly waits on the restart test's child roots); bin/check steps, run serially, about 1,000 s.

## Shared-setup cuts (one change speeds many)

1. **One booted root per test namespace instead of one per test** (`seon.agent-test/in-agent`, used
   by agent-test, repl-test and server-test: 19 boots in the baseline, est. 10–20 s each). A
   fixture boots one root per distinct `{:dirs :sets}` and each test attaches its own task (one
   decl per test in the root's task file) and talks to its own agent. That makes about 5 roots:
   src; src+test; and one each for `ai/script=two-calls`, `provider=:none` and `eid-lease=50`.
   The tests that end or kill their agent (my.turn/wait, fail!, the throwing agent) only need
   their own task. Est. saving: 120–160 s of test wall, the largest single cut in bin/test.
   Deleting source-answers and an-agents-test-run and folding root-test's library test removes
   3 more boots.
2. **Import the tree once per process, keyed by its content** (§5 allows content-keyed reuse for
   units measured as expensive): `test_runner/program-db` (already computed to select the run),
   render-test `src-program`, source-test's whole-src imports, and program-test's three
   whole-tree tests. Est. 25–35 s.
3. **An agent's observe computes base's reach digests once per attempt**, not once per turn:
   `seon.agent/test-plan` (`src/seon/agent.clj:302`) calls `program/reach-digests` on both db
   and base for every test run, and base is fixed for the attempt. A turn's `:tests-ms` is
   1.5–4.4 s while the tests take ~20 ms. That cost multiplies through e2e-calc, conflict,
   semantic, hairy, sibling, newns, swarm (40 attempts), e2e-loop, resume, the restart test's
   turns and agent-test's run tests. Better still, make `reach-digests` incremental on the
   branch's changes. Est.: about half of every e2e step's attempt time.
4. **Bound the slow contract generators** (with-merge, needs-problem, cycle-in, proofs/failures,
   proofs/costs, proofs/plan): mg-check's wall goes from 136 s to ~40 s, with nothing checked
   less.
5. **Work budgets in checks sized to the proof, not to production**: robust's 1e9-tick spins and
   1 GB heap (→ 1e8 and 64 MB), db-test's 100,000-id lease (→ 50), backpressure's 200 agents
   (→ 8), drain's 32 (→ 8), fx's benchmark loops, swarm 20 → 10, inc-test 150 → 75 steps (after
   the mutation check), lifecycle 10 → 3 cycles (after its leak is fixed).
6. **A generation build clones only what `bin/build seon` reads**: `bin/worktree setup` copies
   check-store, check-store-agents, hello.build and every log in target/ into each generation.
7. **Delete**: root-test/a-build-without-whole-program-inference-reads-with-tools-reader (Jolt's
   build-smoke covers it), repl-test/source-answers-a-platform-var-from-the-program (rows of
   an-agent-repl-answers), agent-test/an-agents-test-run-is-its-proofs-and-what-its-change-reaches
   (once a-wide-reach is green), root-test/root-threads-are-what-root-declares (lifecycle's
   subset). No old namespace duplicates seon.server-test: there is no seon.entrance-test left,
   and "entrance" survives only as the config key `:seon.config.root/entrance-port`.

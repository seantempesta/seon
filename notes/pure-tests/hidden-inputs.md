# Hidden inputs: what a test's or check step's result depends on that its reach digest does not cover

Read-only research, 2026-10-23, worktree next-pure-tests at b39cef5 (bin/test and bin/check carry
uncommitted `/usr/bin/time` edits that change nothing below). Found by grep and reading, not from
compiler facts (no program db was booted), so "tests affected" names the test namespaces that call
the site directly, plus the known callers.

What the digest covers (`seon.program/reach-digests` src/seon/program.clj:769, `seon.fx/inputs`
src/seon/fx.clj:145):
- the test's own form, its namespace's plain forms, and every live form its refs reach (methods,
  impls, contract schema keys, and system.edn's procs through :data-refs);
- :env: every git-tracked file except `.md`, task files and src/test `.clj`, every gitlink, and
  `config-input` (the config in force, minus the TCP ports, with the checkout path written as
  `<checkout>`);
- :tree (`tree-id`: HEAD plus `git add -A`, in an index of its own), only when a reached form
  references slurp, file-seq or seon.test-store/binary-sh (less env-readers).

A green is reused forever, across checkouts (the results directory is `<checkout>/../test-results`).
A hidden input can therefore leave a stale green standing. Classes that can only cause a spurious
red (a flake) are marked "red-only": they cost reruns and trust, but they never store a wrong green.

## The build identity, and the reported stale green (report only; another session owns it)

- **How the pins are held.** Chez and Jolt are separate top-level submodules (`.gitmodules`:
  reference-code/chez, reference-code/jolt). Jolt's own submodules are vendor/* only (cli, sci,
  irregex…), so **Chez is not nested in Jolt**, and its gitlink is in every test's :env by itself:
  `env-input?` keeps `reference-code/chez`. A Chez bump moves every digest.
- **18b0774 does not bump Chez.** `git show --stat 18b0774` touches only docs, seon.cost.edn,
  src/seon/cost.clj, src/seon/profile.clj and test/seon/profile_test.clj. The bumps are 93394fc
  (d19eb3b, thread-bytes) and f7afe29 (80e4b9f). Between 18b0774 and 93394fc, main's src called
  `(cs)thread_bytes_allocated` while its pin named a Chez without it.
- **The binary.** bin/test runs `bin/build seon` (Chez → Jolt → native → lmdb → lz4 → zstd → seon,
  each by its HEAD stamp) only when something runs, before the shards. So target/jolt/jolt and
  target/seon match the pins, except for dirty submodule files (#3). target/seon itself is not
  digested; a binary-sh test takes :tree instead, and `store-steps!` checks target/seon.tree.
- **Candidate causes of the stale program-cost-test green, unverified:**
  1. #1: a cost proof's :ns measured green on a quiet machine. Nothing in the digest says "load".
  2. #3: a worktree whose reference-code/chez *working checkout* was already at the new Chez stored
     greens at a digest naming that gitlink (`git add -A` stages the submodule's checked-out HEAD),
     which main's digest then matched after the bump. That reuse is correct only if no dirty files
     were built.
  3. #2: shard composition.

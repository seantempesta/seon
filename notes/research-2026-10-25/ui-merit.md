## What a human sees today at http://127.0.0.1:7777/ (live, root 7888)

`/` (200, 76 KB): dark page, nav "seon on jolt", then root's entity as data (`#:seon.root{:id :root :boot ... :quiescent {...}}`), a "spawn" input and `all=>` evaluate input, then "what it ran, newest first": a list of evaluations by an "outside agent, through root's server" - each is a form (e.g. `(my.root/problems sys)`), `⇒` result as printed, cost line ("16,256,170 ticks · 58.5 ms · warning 78.2 MB alloc"), a "costliest: my.root/problems · 10 functions" disclosure, errors in red (many "No such var: my.root/main-db" by a prior outside agent). There are no live agents and no turns, so the page is an eval log, not a conversation. `/agent/root` serves the same page; `/walk/1` shows a raw schema entity (`:db/ident :seon.tx/branch`), i.e. walk works on any eid. `/agent/1/debug` returns 200 only because `/agent/` is a prefix match: "1/debug" is taken as the id; there is no debug route. ## What next lacks that v1 had

1. A real debug URL at all (`/agent/{id}/debug`).
2. One row per provider call with prompt/cached/completion tokens and finish reason (next records the facts as `:seon.turn/*`, the page shows only header chips in a cut row).
3. What each call was sent, re-derived from its basis, lazy, every cut named. (next has `context/remade` and `request-text`, but nothing routes to them on main.)
4. "What the next call would be sent now" (live), and the raw "Record" disclosure.
5. Token badge per section. (`context/sections` exists only on the prototype branch.)

## Lessons from the notes (what cost hours)

- Rendering a chat before the context format was settled: the window (+670/-370) and its 6 browser-tester rounds, 4 fresh-eyes review rounds and messages-as-facts work were over a context that the owner then replaced (standard chat format, 1.6 KB vs 17 KB). The view must read whatever the turn recorded and show the new format when it lands.
- The owner judges by looking: debug output, prose glue or a cut text reads as failure. Show nothing until a fresh-eyes check (Sonnet on rendered output only, Haiku browser on a screenshot) passes.
- Cutting text in a view: "a cut on this page defeats its purpose"; the printer cut and `turn-text-budget` were the repeated complaint. A render shapes data so the important part survives the printer's cut; never port v1's prose renders.
- Environment traps: do not rebuild a worktree's `target/seon` while its tests/root run (a runner waits forever); a store built before a schema change cannot open; Datahike gives a content id only to top-level maps; `subs` in a display namespace trips the one-printer test; a view page waiting for the branch read ("being read" first paint).
- Merge gotchas: pins after merges, stale submodule checkouts staged by `git add -A`.

## Merit verdict and a build recommendation for /agent/{id}/debug and the normal agent page

Merit: the infrastructure is worth keeping (entity-as-location, walk, units with containers + Datastar patches, Tailwind with safelist, the `evaluation` atom, `context/remade`, tx-ordered interleaving, messages as facts, cost/cache chips, tester loop). What is not worth keeping is any layout that shows the context cut or nested per turn, and newest-first lists as transcripts.

- `/agent/{id}/debug` (root only): oldest-first transcript of the messages the model was sent, each shown once (system once, user task once, each assistant reply with its `thinking`, tool call code, tool result), taken from the last turn's `remade` request plus each turn's added tail; per message: tokens; per assistant message: model, finish, hit/miss tokens, cost; whole text, scrolling; a "next request now" tail as v1 did.
- Normal agent page: compose from the agent's record via renders on schemas: head (task prose + status + why-one-line), then a prose-first timeline: each turn's reply/reasoning (`:seon.render/prose true`) as markdown, the evaluations collapsed to one `:inline` line each (form `⇒` result) that expand to `evaluation`'s block, errors in red; proofs/diff/cost in tiles; link each evaluation/turn/task to `/walk/{eid}` and the agent to `/agent/{id}/debug`.

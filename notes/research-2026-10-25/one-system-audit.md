## 0. The shape of the problem

There are two programs. (a) **Root**: a Flow graph (`seon.root/start!`, api proc + reconciler + writer + fork server + render + web + prove + fx owners), with its own API (`seon.root/request!`, ext-op/back-op ~220 lines), its own REPL namespace (`root.repl`), its own fact entity (`{:seon.root/id :root}`), its own `my.*` namespace (`my.root`, 371 lines) and its own judge/merge flights inside the reconciler. (b) **An agent**: a forked process with `my.agent`/`my.task`/`my.branch`/`my.turn`, one branch, one task. Root drives agents through `request!` -> `agent-proc` -> socket -> `seon.agent/handle!`. The owner's "one system" is: root = an agent whose branch is main, whose tasks are the root tasks.

What already exists and is the right base: tasks as data with `:seon.task/branch`, `:model`, `:kind`, `:config` (template.clj, reconcile `desired-env`); `hold-tx` (the "held for root" sink); merge tasks (`:merge` kind, instructions, `seon.merge` three-way on the branch); `seon.prove` test service keyed by digest; `:outside` model for an outside agent on a task (server `attach!`).

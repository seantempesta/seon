## 3. db and function schemas
- No render fn receives a db today. Renders are (value opts); db-needing work is done upstream: walk/page take db (render.clj:281, :351), render.proc reads main-db (proc.clj:114-133) and builds walk values before rendering. seon.render.ui/page gets a pre-walked value. Nothing in :seon.render/opts carries a db.
- Every render fn already has `{:malli/schema [:=> [:cat <schema> :seon.render/opts] ...]}` metadata (contract/defn macro, contract.clj:181; instrumented via m/-instrument :154). So a render fn that wanted db would literally say `[:cat :seon.host/db ...]` (:seon.host/db pred is `datahike.db.DB`, contract.clj:52); nothing reads those schemas to decide injection. Input schemas are mostly :map/:any/:seon.render/walk, not the schema the value is registered under.

## 4. Validation
- Selection never validates. The only validation is instrumentation of the render fn's own contract at call time (bad input -> :seon.instrument/contract-error map, contract.clj:126-140, caught at an entrant; contract.clj:120 `problems` uses m/explain). Printer of a refused value: print-value answers an insufficient-budget error map; print-html turns that into a [:span.seon-print-refused] (render.clj:111). `render`/`render-of` never m/validate the value against the schema it chose.

## 7. Distance to target

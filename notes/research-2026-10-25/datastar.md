# Datastar facts for lazy units (our version: v1.0.0-RC.7, resources/public/datastar.js header)
Docs: https://data-star.dev/reference/attributes , /reference/sse_events . "Verified in JS" = read in our datastar.js.

Attributes registered in our build: peek attr bind class computed effect indicator init json-signals on on-intersect on-interval on-signal-patch ref show signals style text; watchers datastar-patch-elements, datastar-patch-signals. Also ignore, ignore-morph, preserve-attr, viewtransition.

1. Visibility: `data-on-intersect="@post('/x')"` exists (verified in JS). Mods: __once, __half, __full, __threshold.N (percent 0-100), __exit (fire on leaving), __delay, __debounce. Code: IntersectionObserver, default root = viewport. Fires on every entry unless __once. Works inside an overflow-y container: IO accounts for ancestor overflow clipping (browser behaviour, not tested here). Our own use: render/ui.clj:547 sentinel `:data-on-intersect "@post('/more?view=..')"` (no __once; sentinel is replaced by patch).
2. Details: `data-on:toggle` works - data-on is a plain addEventListener of any event name (verified in JS; docs say "works with events and custom events"; docs don't mention toggle specifically). `toggle` doesn't bubble, so put it on the <details> itself. Use `data-on:toggle="el.open && @post(...)"`. Add __once to load only first open. UNTESTED in browser.
3. State: signals are one global store, not per element, so they persist across any morph. Caveat: `data-signals` re-applies its value whenever the (re-patched) element's attribute is processed, unless `data-signals:foo__ifmissing`. Use `data-signals:open-u123__ifmissing="false"` (or keep state in native <details open>).
   NATIVE open does NOT survive by default: morph (verified in JS) copies every attr from new element and REMOVES attrs absent from new one, except those listed in the NEW element's `data-preserve-attr`. So a re-patch lacking `open` closes it. Fix: `<details data-preserve-attr="open">` (docs: "Preserves the value of an attribute when morphing DOM elements"). data-ignore-morph skips element AND children (both old and new need it) - wrong for a unit you want updated. data-show: toggles inline display via style; morph strips style if absent from new element but a MutationObserver on style reapplies it.
4. Patching: `event: datastar-patch-elements` default mode outer morph "by matching top-level elements based on their ID" (docs); put id on top-level element. Placeholder id=u-123 -> patch element with same id (render it with same id and tag). All SSE events, whether from @get/@post's own response (text/event-stream) or the long-lived feed, go through the same document-level 'datastar-fetch' event and same watcher (verified in JS: datastar-fetch listeners bind to document). Both work. Our existing pattern (web.clj:141): POST /more returns 204, result arrives via /feed. Recommended for us: keep that (one producer, per-tab feed fan-out, no per-request stream). Own-response stream is simpler only if the response is per-requester and nothing else needs it.
5. Unloading: no Datastar reason; nothing leaks per patch (morph replaces nodes; observers disconnect via cleanup). Reason would only be DOM size/memory with thousands of rendered units. Replacing with a placeholder needs the sentinel to re-fire and loses client-only state (scroll height jumps: placeholder needs a min-height). Leave rendered until measured need.

Our :more path: ui.clj:541-547 sentinel `<p id=unit data-on-intersect="@post('/more?view=V')">`; web.clj:142 routes POST /more -> {:op :more :view} to render proc (proc.clj:24 "renders only the rows a tab has scrolled to"), 204; rows arrive on /feed. html.clj:66-67 other actions use data-on:click / data-on:submit with @post(call-url).

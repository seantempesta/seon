## Overbuilt or questionable, with the correction
1. **seon.render/shown renders the AI face of every page part**, and records the render that made each one. Nothing reads them. render/data and render/rendered are test-only, and /walk duplicates /agent. Render only the HTML face, and delete those. About −40 src.
2. **The wiki baseline is rebuilt from git history:**
   - git blame per page, plus old-commit parsing;
   - a regex over code (§9);
   - Reviewed: trailers and my.docs;
   - an env switch, SEON_WIKI_BASELINE.

   A section is stale only when a cited form changes after it was loaded. About −280 src and −200 test.
3. **The vector search is layered:** a 128-dim pass, then a rerank, a C kernel, and RRF fusion. The fusion measured worse than embeddings alone (0.451 against 0.495), and the C step costs 0.08 ms against 1.9–4.6 ms of datom reads. Use exact search, and drop the first pass, the kernel and RRF. About −100 src, −91 C, −8 keys.
4. **The judge (seon.judge, my.root/first-moves!) is a second turn path in src.** It makes one call, so it can't measure "acts by its second move". Move it to test/, or rebuild it as a two-turn real run through seon.turn, scored from the run's facts. About −200 src.
5. **tick-quantum overlaps repeats' minimum of 3.** Store measured the extra chunk on 15–60% of calls, so the minimum of 3 still misses it in about 3–22% of measurements. Choose one: more repeats, or the quantum. growth-share and repeats are literals and want config keys.

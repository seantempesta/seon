## Edge-triggered waits with no level check (end only on an event that may already have happened)

1. test/seon/await.clj `await-quiet` (and its callers): described above; `quiet` writes once per spell and `(inc t)` / `(max-tx now)` demands a report newer than the system's current quiet state.
2. src/seon/fork_server.clj:289-292: `:ext` stats/static requests are appended to `:waiters` and answered by "the next :stats/:static event"; if the server has no pid (`(when (:pid st) ...)`, after `:fork-server-lost`) the request is queued and no event ever comes, and `fork-server-lost` (root.clj:475) does not answer queued waiters. C. Fix: on `:fork-server-lost` and in the `:ext` arm when `(nil? (:pid st))`, answer the waiters with the lost-server error.
3. src/seon/fork_server.clj:243-246 `promote`: waiters are re-sent to the standby, but the answers are paired by FIFO `(peek (:waiters st))`; an answer lost with the dead server leaves the pairing off by one (the request is re-sent so it is answered, but a stats event for a request the dead server had already answered would pop the wrong waiter). Edge-triggered pairing; fix: carry the rid in the event.
4. src/seon/root.clj:1013 `await-db` itself is level-safe (it checks the current value after registering the watch), and server.clj:164's pred is a level on the run's status. It is only edge-triggered via its end condition (needs a commit to happen), see C rows.

## How the runner waits on its shards

- `bin/test` (zsh, bin/test:47-60) starts every shard as `{ time (runner --shard "$f" > log 2>&1) } 2> time &`
  (bin/test line `for f in $F; do ... & P+=($!); done`), then `for i ...; wait $P[$i]; s=$?` in order.
  `wait` has no timeout and no liveness check: it returns only when that shard JVM (`jolt -A:test run -m test-runner --shard FILE`,
  test/test_runner.clj:329 -> `shard!` :197) exits. The parent therefore observes exactly one fact per shard: its exit status
  (A for a shard that dies or finishes). A shard whose test parks keeps its process alive at 0% CPU, so `wait` never returns: C.
- Inside the shard, `shard!` -> `proofs/run-tests!` (src/seon/proofs.clj:251) runs each test under
  `:seon.config.agent/test-ticks` (test_runner.clj:216). That bound is engine ticks of work (Jolt `run-interruptible`):
  a thread parked in a blocking wait (`<!!`, `@promise`, a socket read, `sh/sh` waiting on a child) does no work, so it
  spends no ticks, and per test/seon/agent_test.clj:`a-blocked-agent-ends-with-its-root` a thread in Chez's condition-wait
  reaches no safe point so no signal/timer handler runs. The tick budget catches `(loop [] (recur))`, not a parked test.
- Can the parent see a shard's own children (test roots, agents, `bin/check` runs)? No. They are started through
  `seon.test-store/binary-sh` (test_store.clj:113-119) under `bin/held` with `SEON_STARTER_FIFO` = the shard's own fifo
  (test_store.clj:96-111, held RW by the shard JVM). The only link is bin/held's watcher (bin/held: `fork` watch child, `sysread` on the fifo,
  then `kill KILL, -$cmd`): when the SHARD EXITS, however it ended, its roots/agents are SIGKILLed (A for cleanup). That edge is
  child-follows-parent only. Nothing flows the other way: bin/test never learns that a shard's test root died, parked, or
  is still running; a root that parks while its shard is alive keeps both alive (the 1h45m a-failure-marked-... hang).
- Also: `bin/test` waits shards in index order, so a hung shard 1 hides later shards' output (their logs are only grepped after `wait`).
  `bin/check` (bin/check:278 final `wait`, and `wait ${CP[...]}` :181) has the same shape for its steps (`./seon MODE` under bin/held).

## The a-failure-marked-through-the-server-holds-the-task hang (agent_test.clj:395-407), traced

1. `in-agent` starts a test root (`ts/start-root!`, A: returns on ROOT LISTENING) and an agent a1, then `(mapv ask forms)`.
2. The 4th form is `{:op :eval :agent "root" :code "(let [t (:max-tx @(:conn sys))] (seon.await/await-quiet sys (inc t)) ...)"}`.
   `await-quiet` -> `seon.root/await-db` (root.clj:1013): `(add-watch ...)`, `(pred db)` on the current value, then `@p` with no timeout.
3. `(inc t)` is above every earlier quiescent fact. If the reconciler had ALREADY recorded quiescence (or never will, because the failed-task state is
   terminal and nothing re-triggers it) no commit arrives to satisfy `(>= (:t q) (inc t))` and no `:platform` defect is recorded: the promise stays undelivered.
4. The root's eval is parked in `@p` (a root fiber/thread in condition-wait, 0% CPU). The server connection is open.
5. `ts/ask` = `sh/sh bin/ask PORT`; bin/ask is blocked in `my $line = <$s>` on an open socket to a live root: no EOF, no reset (A did not apply).
6. The shard JVM is blocked in `sh/sh` (waiting the child's exit); `run-tests!` spends no ticks while parked, so the tick bound never fires.
7. `bin/test`'s `wait $P[i]` is the last link: nothing ends it. Result: 1h45m at 0% CPU.
Fix targets, in order of cause: (1) `await-quiet`: quiescence recorded at or after the call's own state is a fact it can return without a future commit
(compare against the quiescent fact present now plus "nothing running/ready" instead of requiring `(inc t)`); (2) the server answers an eval whose
evaluating thread is parked with nothing able to wake it (root already knows every proc/agent state: a parked eval with an idle reconciler is a recorded
`:seon.root/eval-parked` problem answered to the requester); (3) bin/test's shard wait learns about shard-children state through bin/held's done/status fifo
instead of a bare `wait`.

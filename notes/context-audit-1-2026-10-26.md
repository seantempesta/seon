Method: read the ten `audit/*.txt` pages, the plans in `seon.fixtures/requests`, the fix sites in the tree, and the template and render source. ## Finding 0 (verified in source): the `:whole` instructions are not on any page

- `grep -c "Your task"` over the ten pages gives 0 for each.
- `seon.render.ui/task-page` (ui.clj:896-908) draws kind, the plan as prose and `(dissoc data :task)`. `seon.context/task-data` (context.clj:313) puts `:seon.task/instructions` under `:task`, and the page dissocs `:task`. The page tells the agent `(dissoc (my.task/data) :task :write-set)`, which points away from them.
- `task-box` (ui.clj:372) draws instructions, but it is the dashboard's render, not the agent's page.
- The earlier format (`ctx-a1-t0.md` line 17, 87) carried them.
- So the P6/P7 fixes (reproduce first, `fail!` if already right, stop reading once wrong, build the input like the existing tests, `:merge` readiness, "run ends once :ready") reach no agent. The system prompt says only "A reply with prose and no eval call ends your turn, and waits for the user", which contradicts the `:whole` flow.
- Producer: the task part's render (`seon.render.ui/task-page`). Fix: draw `(:seon.task/instructions task)` as prose above the plan, or have the system page say to read `(:seon.task/instructions (:task (my.task/data)))`. The first is the render declared on the value. Add a `template_test`/context test that a held `:whole` task's page contains "reproduce what the plan says is wrong".
- Cost: every request pays for it; an agent without the order of steps repeats P6.

## Instructions, ctx, noise (cross-request)

- **System prompt** (2281 chars, 10x identical): clear on "one eval, prose first", cuts, and `:same-as`. Two parts do not serve these tasks: (a) the `@ctx` paragraph ("`swap!` it to see more of it (its pattern)", ~220 chars) is abstract and no request needs it; an agent will not know when it applies. (b) "A reply with prose and no eval call ends your turn, and waits for the user" is wrong for a `:whole` task whose run ends by `:merge :ready`; with Finding 0 an agent can end its turn after the red proof. Producer: docs/prompt.md. Fix: after Finding 0, move the work order out of nowhere and say "a whole task ends when `(my.task/status)` shows `:merge :ready`".
- **The `:whole` text** (not seen by the agent, but audited in template.clj:72-80): one paragraph of ~1500 chars, in a good order. Faults: "in its test namespace (`ns.x-test`)" is the task's ns plus `-test`, which is right for 3 of 10 (context, ref, print) and wrong for `seon.render.ui` (render-test), `my.agent` (seon.agent-test), `seon.print.emit` (print-test). It never says that a failed premise is for the example to check with the test; it does say `fail!`. "Cost proof for a function whose input grows" is vague (none of the ten grows). It does not say how many turns to spend, nor to read the existing test via `(my.agent/callers 'ns/f)`.
- **Per-page noise, chars** (of the 2.1-11 KB):
  - `:callers` lists: 0-3299 (print-value 2168-char cites carry ~240 each; `split-lines` 1941; related-list 3299). Alphabetical, cut by count, mostly tests for infrastructure vars.
  - Cited vars that are the repro's callees (`test-db`, `db-with`, `split-lines`, `load-tx`): 2090-2139 each, 6.4 KB on one page, 2 KB on another.
  - `:run` part: ~290 chars on every page (`name#1 · –`, a nil), no information.
  - Related: 640-870 chars per page; 5 `:schemas` (~150 chars) and decisions.md section addresses that are 80-char slugs with no text (P4: addresses, not text). Two of ten had the right function in `:functions`.
  - hiccup scaffolding (`[:section {:class "tile"} [:h2 {:class "kicker"} ...`, `{:budget 600, :handle ...}` per part): ~150 chars x 4 parts.
  - The `:to-prove` plan repeat (long-string): ~750.
- **Prose-only requests (no backticked var):** all ten put their callee in a code form. The parser cited `seon.ref/lead-sentence`, `names`, `bytes-str`, `cut-words`, `help`, `print-value`; it missed `printed-run`. The related seed found the right function for printed-run (1st), first-sentence (3rd), fill-members (2nd), `select/show` (nearest, not the site); it missed `emit-collection`/`member-indent` and `trim-word`, `related-view` and `cut-words` were cited rather than found.

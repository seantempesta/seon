# Review of in-flight branches, 2026-10-22

Standard: AGENTS.md §4 (principles), §5 (laws), §7a (words), §9 (mistakes). Read-only review of
`git diff main...BRANCH` (committed) plus uncommitted work where a worktree was mid-work
(`jolt/prove`, `jolt/dup-helpers`). Each finding was checked against the surrounding code;
anything I could not confirm was dropped. Ranked most serious first within each branch.
File:line refers to the branch's worktree (`../next-<name>`).

## Cross-branch: two producers of "what the branch changed" (land4 vs context-v2)

**Must fix before both merge.** Kind: second mechanism / wrong place.

- land4 fixes `seon.program/changed-vars` (next-land4 `src/seon/program.clj:721`) to compare
  forms by `:form/id`, because `merge-main!` applies main's forms under the branch's own
  entity ids. It also makes the agent's `:base` follow the merge base (`src/seon/agent.clj`,
  `merge-main!`: `(swap! state assoc ... :base (pdb/branch-base conn main-b (:branch @state)))`).
- context-v2 adds `seon.program/divergence` (next-context-v2 `src/seon/program.clj:712`), which
  still compares by entity id (`(not= (a e) (b e))`), rewrites `changed-vars` on top of it,
  and adds a second merge-base reader, `seon.agent/merge-base` (`src/seon/agent.clj:193`),
  which recomputes `branch-base` from the store every turn (`src/seon/turn.clj:77`:
  `:will-merge (program/divergence (agent/merge-base) db)`).
- After any `merge-main!`, context-v2's `:will-merge` would list every form main brought in
  as `:changed`, which is the bug land4 just fixed. Merging both also conflicts in
  `changed-vars`.
- **Fix:** have one producer. `divergence` compares by `:form/id`, as land4's `changed-vars`
  does, and `changed-vars` derives from it. One merge base: the turn reads the agent's
  `:base` (land4), and `agent/merge-base` is deleted, or the reverse, but not both. Add a
  divergence test across a `merge-main!`.

## jolt/land4 (tasks-at-once attach race + store-native fork base, `:seon.tx/runtime`): 5 findings

Good work:
- `seon.entrance/attach!` now spawns first and writes the env, the release and the attempt in
  one transaction. That fixes the race at its cause, and
  `entrance-test/a-refused-attach-writes-nothing` proves it through the server.
- The `changed-vars` content comparison is a correct fix at the producer.

1. **Guard: a nil check on a value that is never nil.** `src/seon/agent.clj:546`:
   `misaligned (when (and commit (not resumed) ...`. The only producer of `:fork`
   (`seon.writer` `:spawn`, `src/seon/writer.clj:164`) always sends `:commit` and `:t`, so
   `(and commit ...)` hides a defect instead of exposing it.
   **Fix:** drop the `commit` test; a missing `:commit` should fail the `:fork` contract.
2. **Check that nothing observed asks for, with no test.** The whole `:misaligned` path
   (`agent.clj:546-552`, `repl.clj` hello, `agent_proc.clj:137-140`
   `:seon.agent/fork-misaligned`) records a problem for an invariant that the writer and the
   FIFO already establish, and that `procs_test/a-fork-names-the-commit-its-agent-starts-at`
   proves at the producer. No test makes it fire. §4 asks: "What observed thing breaks
   without it?"
   **Fix:** delete it, keeping the producer's test, or write a test that makes it fire and
   name the observation that motivated it.
3. **Weak test.** `test/seon/db_test.clj`, `each-transaction-names-the-runtime-that-made-it`,
   passes `(pdb/tx-meta)` into `dw/transact-batch!` and `dw/apply!` itself. It proves that
   Datahike stores tx-meta, not that Seon's callers pass it. Its docstring says the merge path
   is "proved here", but no test covers `merge-db`'s tx-meta (`writer.clj:103`,
   `agent.clj` `merge-main!`).
   **Fix:** assert `:seon.tx/runtime` on the commit that a real `merge-main!` (agent_test) and
   a writer `:merge` (procs_test) produce, and drop the Datahike-only test.
4. **Special case for one attribute.** `src/seon/db.clj:146`:
   `(cond-> {:tx-data missing} (get have :seon.tx/runtime) (assoc :tx-meta (tx-meta)))`, and
   the same reasoning in `seed!`.
   **Fix:** install `:seon.tx/runtime` alone in the store's first schema transaction, so every
   later transaction carries tx-meta without a branch.
5. **Absent runtime presented as no metadata (minor).** `src/seon/db.clj:115`:
   `(if-let [fp (jolt.host/runtime-fingerprint)] {:seon.tx/runtime fp} {})`. Jolt answers `#f`
   only for an unbaked runtime. Absent-when-unknown is the house convention, so this is
   acceptable, but a baked binary must never write `{}`.
   **Fix:** a contract or `bin/check` assertion that the release binary's fingerprint is a
   string.

## jolt/context-v2: 6 findings (plus the cross-branch one above)

Good work:
- `seon.context/system-prompt` and `seon.template/repl` are deleted for one help page that a
  test runs (`repl_test/the-help-page-runs`).
- Unresolved references now share one problem.
- `turn/usage` keeps absent-is-unknown for cache tokens.

1. **Second mechanism, and the render can no longer be reproduced from its basis.**
   `src/seon/context.clj:19-22` `help-text` is `(slurp (io/file (cfg/checkout) help-page))`,
   and it is the system message (`context.clj:335`). `render` is documented as "the one maker
   of a context ... and so is every later reading of it" from the turn's commit. But the help
   page is read from today's checkout, not from the commit, so re-rendering an old turn shows
   today's page. The wiki is already mirrored in the db (`seon.docs/view`, used by
   `cited-view`). `my.agent/help` (`src/my/agent.clj:96`) reads the file a third way, through
   `ref/file-view`.
   **Fix:** read the help page from main's doc sections on `db` (`seon.docs`), in both
   `messages` and `my.agent/help`.
2. **Wrong place: the producer adds what the render then removes.**
   `src/seon/context.clj:398`: `(= :outside origin) (dissoc :turn)`, after
   `(assoc observed :turn turn ...)` a few lines above.
   **Fix:** don't assoc `:turn` for an outside read (or have `basis!` record no turn for
   origin `:outside`).
3. **Silent fallback when a scrollback lacks its attempt sections.** `context.clj` `messages`:
   `(or (:attempt (first turns)) (attempt-message block))`. With non-empty `turns`, a missing
   `:attempt` is a defect in `render`, and the fallback silently sends the current block,
   which breaks the byte-identical prefix that the cache relies on.
   **Fix:** split the arities: the no-turns case builds the attempt message, and the
   with-turns case requires `:attempt`.
4. **Weak test.** `test/seon/program_test.clj`, `divergence-names-each-change-a-merge-carries`, builds base and branch by hand with fresh entities. It cannot
   catch the merged-by-content case from the cross-branch finding.
   **Fix:** add a case where main's form lands on the branch under a new eid with the same
   `:form/id` and expect `{}`.
5. **Weakened assertion.** `test/seon/repl_test.clj` (template instructions) goes from
   `(< 20 (count forms))` to `(is (seq forms))`. This is acceptable now that the navigation
   lives on the help page (and `the-help-page-runs` keeps `< 20`), but `seq` passes on one
   form.
   **Fix:** assert each kind's own forms (merge's `my.branch/*`) by name.
6. **Old words in new text (§7a).** `test/seon/repl_test.clj:77,94,107` ("ending verbs",
   "navigation verbs") and `test/seon/task_test.clj:26` ("navigation verbs"). Task plans added
   in `resources/seon/tasks/*.edn` say "Lane AGENTS", "Landed", "verbs exist", "census
   idea 3", and the vocabulary row for `seon.repl/wrap-admit` keeps "admit" in its var
   (stored name, acceptable).
   **Fix:** "functions", "worktree session", "merged".

## jolt/mcp-relay: 6 findings

Good work:
- `seon.mcp` (a 729 MB Seon binary per Claude session) is deleted. root's server answers MCP
  itself, and the relay's footprint is bounded by a config key that `mcp-proof` checks.
- The DRAGONS row moved with the failure point.

1. **Second config reader, regex over a config file.** `bin/mcp:14-18`:
   `PORT=${1:-${SEON_ENTRANCE_PORT:-}}`, then
   `PORT=$(sed -n 's/^ *:seon.config.root\/entrance-port .*SEON_ENTRANCE_PORT \([0-9][0-9]*\)\].*/\1/p' "$ROOT/config/local.edn")`.
   This re-implements the config resolution (env, then local.edn) outside the one resolver.
   It ignores `--config`/`--set` layers and breaks as soon as someone edits `local.edn` into
   another shape (bin/ports invites that edit). §5 says "read through one resolver";
   §9 lists "regex over code".
   **Fix:** have `bin/ports` print the ports from what it wrote without booting Seon (it
   already knows E and W when it writes them), or keep them in a plain `config/ports` file
   that both read. Better still, make the port the explicit argument in `.mcp.json`.
2. **Fake default: an unknown method answers an empty result.** `src/seon/entrance.clj:153`:
   the `case` default `{}`, so any unknown JSON-RPC method with an id gets
   `"result" {}` (moved from `seon.mcp`, now new code here).
   **Fix:** answer JSON-RPC `-32601` "Method not found" naming the method.
3. **Format sniffing as a special case.** `src/seon/entrance.clj:167`:
   `mcp? (str/starts-with? (str/triml line) "{\"")`. An EDN request whose first key is a
   string reads as JSON.
   **Fix:** acceptable if documented as the protocol rule (EDN requests are keyword-keyed
   maps). State it in `ops`' doc and refuse a string-keyed EDN map explicitly, rather than
   misparsing it.
4. **A swallowed parse in the relay.** `bin/mcp:25`: `my $id = eval { decode_json($line)->{id} };`.
   A malformed line leaves `$id` undefined, so if root then fails to answer, the client gets
   nothing for it. This is minor, because root answers a malformed line as a defect.
   **Fix:** name it in the new DRAGONS row ("a line that is not JSON is relayed as is; root
   answers its defect").
5. **Echoed protocol version.** `entrance.clj:142`:
   `(get params "protocolVersion" "2024-11-05")` echoes whatever the client sends. The server
   should state the version it implements.
   **Fix:** answer the version root implements (a config key or a constant with its
   provenance).
6. **Old word kept in code being changed (§7a).** `src/seon/root.clj:822`: `[verb id args a]`.
   The docstring was renamed to "op", but the parameter was not.
   **Fix:** rename the parameter to `op`.

## jolt/check-events: 4 findings

Good work:
- Five `Thread/sleep` windows ("no event says it started") are replaced by real events:
  `:started` from the agent's REPL step, `:tests-started` with the child pid, a probe's
  `:probe` events, and a render-proc `:settled` mark.
- `seon.root/agent-health`/`health`, which answered `:unknown` after 1000 ms, are deleted.
  That fixes a fake default and a clock at once.
- `bin/lane-check` drops `timeout 30`.

1. **Literal bounds, not config (§5 "only documented config").** `src/seon/check.clj:61-68`:
   `(def ping-ms ... 10000)`, `(def hold-ms ... 500)`, `(def pages-ms ... 500)`. They are named
   in `docs/clocks.md`, but they are still literals with no unit or provenance in
   `default.edn`.
   **Fix:** `:seon.config.check/ping-ms`, `hold-ms`, `pages-ms` in `default.edn` under a
   schema, read through `cfg/value`.
2. **Fake default in a ping map.** `src/seon/agent_proc.clj:243`: `:noise (:noise st 0)`. The
   backpressure check compares `n0`/`n1` from it, and absent shows as 0.
   **Fix:** initialise `:noise 0` in the proc's init arity (it is a count from start), and
   read `(:noise st)`.
3. **Unbounded quadratic accumulation in a check reader (minor).**
   `src/seon/check.clj:1134,1143`: `feed (atom "")` with `(swap! feed str ...)` on every read,
   then `index-of` over the whole string on each watch.
   **Fix:** keep only what the wait needs (a flag set when the keyframe is seen, then one
   when `: settled` follows), or a StringBuilder in the edge reader.
4. **Depends on mcp-relay without saying so.** `bin/lane-check` removes `timeout 30` around
   `./bin/mcp`. With main's `bin/mcp` (the `seon mcp` binary), a root that never answers
   hangs the step, and only mcp-relay's relay answers every id.
   **Fix:** merge after mcp-relay, or state the dependency in the task's `:needs`.

## jolt/prove (mid-work, uncommitted in ../next-prove): 6 findings

1. **An ignored answer.** `src/seon/proofs.clj:120-127` `store!` calls
   `(fx/write-file {:req ...})` and returns `r` whatever it answered. `write-file` answers
   `:seon.fx/io-error` as data (`src/seon/fx.clj:30-45`), so a failed write reads as stored.
   The same applies to `test/test_runner.clj:79,119-120`. §9: "an ignored answer". It also
   calls the edge function directly, and does `.mkdirs` outside it.
   **Fix:** check the answer and return or throw the typed error. Let `write-file` (the edge)
   create the directory.
2. **A catch outside DRAGONS that loses the cause.** `src/seon/proofs.clj:186-187`:
   `(try (t/test-vars ...) (catch Throwable e (.write out (str "\n" n ": " (ex-message e) "\n"))))`.
   The exception goes only into printed output. The recorded result for each unreported test
   says `"no report: ... (a fixture threw?)"`, a guess, instead of the actual message.
   `bin/dragons catch` will also flag it.
   **Fix:** put `(ex-message e)` and its data into each unreported test's `:error` result, and
   name `seon.proofs/run-tests!` in DRAGONS' "Entrant boundaries" (a test run).
3. **A nil filter that hides a misnamed root.** `src/seon/program.clj:788`:
   `(digest-of k (keep var-form vars))`. A `check-steps` function with no form in the program
   db (renamed, or not imported) is dropped silently. The step's digest then reaches only
   `:env`, and its green is reused forever. `every-bin-check-step-is-keyed` checks
   `find-var` (the runtime), not the program db.
   **Fix:** throw (or answer a typed error) when a root var has no form.
4. **Two lists of bin/check's steps.** `src/seon/proofs.clj:80` `check-steps` hand-copies
   bin/check's step names. `proofs_test/every-bin-check-step-is-keyed` reconciles them by
   regex over `bin/check`, with special cases (`seed`, `e2e-$k`, `census`, `orphan`,
   `-write`/`-read`). `bin/check:71`
   (`[[ $name == seed ]] || want ${${name%-write}%-read} || return 0`) adds the same special
   cases in shell.
   **Fix:** declare the steps once as data (an EDN file that bin/check iterates, or
   `check-steps` printed for bin/check to read), so neither side parses the other.
5. **Env vars as an interface (§9 "an env var instead of config").** `SEON_CHECK_STEPS` and
   `SEON_CHECK_GREEN` (`bin/check:62,167`, `bin/prove`) pass the selection and the result
   between scripts.
   **Fix:** acceptable as process arguments between two scripts, but pass them as bin/check
   arguments or files under `target/prove` (bin/prove already writes `steps`), not
   environment.
6. **Atoms outside procs.** `src/seon/proofs.clj` `run-tests!`: `counts`, `ran`, `t0` atoms in
   a non-proc function (§5). In a forked shard child this is harmless, and clojure.test's
   `report` callback forces some state.
   **Fix:** acceptable with a docstring line saying why, or one volatile local to the
   binding.

## jolt/dup-helpers (urgent seon.source fix, uncommitted in ../next-dup-helpers): 1 finding

Good work: `src/seon/source.clj:86`. `analyze-form` now always runs the file's ns form
(`(when (or ns-form? ...)`) instead of special-casing "a namespace not in loaded-libs". That
removes a special case at its cause. `source_test/a-changed-ns-form-applies-its-requires-before-its-forms`
reproduces the owner's root death (`No such namespace: ts`), asserts its own setup, and would
fail on the old code.

1. **A default change beyond the fix, with no measured cost.**
   `resources/seon/config/default.edn:208`:
   `:seon.config.source/dirs ["src" "test" "resources/seon/schemas"]`. Every root, check and
   in-agent test now imports `test/` as program on main, so it is merged, written back and
   loaded at boot. The reason is sound (checks boot what the owner's root boots), but it
   changes boot time, store size and every check's datoms, and no numbers are given.
   **Fix:** land the `analyze-form` fix alone now. Make the dirs change its own small task,
   with boot ms and datoms before and after (§3: numbers against estimates).

## 1. Corpus
- context-patterns.edn (../context-patterns.edn): 117 forms, 4 attempts, ONE task (seon.ref/wildcard-citations-are-prose), 46 model calls. Form row: {:attempt :turn :ordinal :class :reply-tokens :source :elided-in-history}. Attempt row: {:end :calls :calls-to-green :forms :repeated :agent-errors :platform-errors :prompt-tokens ...}. clm/common.py parse() regex-reads it.
- Label = step CLASS of the form the agent ran (targeted-read 42, re-read-after-elision 16, probe-own-fix 15, in-ns 14, search 9, progress 8, contract-refusal 4, ...), made by first-match rules over source+error text (context-patterns.md sec 3), 20/20 hand spot-check, known miss (errored deftest = progress). Not usefulness, not independent human labels.
- Reuse for "which item did the agent need next": weak. No replies/outputs were stored; branches mostly deleted; one task. But :source + :elided-in-history + :turn give "what was read next"; rank-signals/live_instance.py already derives live-reads (10 seon.ref decls the agents read). The real label source is the kept branches (KEEP-BRANCHES) with :seon.cluster.eval/* rows (source, output, error, read evidence).
- Better, larger label set: rank-signals/instances.jsonl (382 instances: query = deleted task plan or commit message, ground truth = top-level decls whose lines a commit touched; split.json time split 60/40). Label = "declaration was needed by the change", not "needed next".
- Weak outcome labels proposed (prototype.md exp5): attempt ended green, proof red->green after the eval, result never referenced later, same source re-read, eval errored, reply elided then re-read next turn.

## 2. Structured features / situations
- Situations in v1 were rules over source/error text, not learned: re-read-after-elision ("seen this exact form/target before" - they note CLM cannot do this; replace with a data lookup), in-ns navigation (regex), contract refusal (wrong call shape), invented name / unresolved name, search/discovery, cleanup. History-relation (first vs repeat) is the distinction embeddings miss.
- rank-signals (exact, all computed at parent commit via clj-kondo): plan_ref (backticked/any qualified symbols in query), graph_plan (1-hop callers/callees of refs; best single R@10 0.386, reach 65%), test_reach/test_calls (static callees of deftests), schema_contract/schema_text (ns keywords in :malli/schema), cochange, recency, task_citation, embed_src_{code,search}. Learned: COMBINED_gbt / LR over score + 1/rank per signal, log tokens, private flag. Untrained RRF of 4 (plan_ref_any, graph_plan, embed_src_code, test_reach) nearly as good (R@10 0.441 vs 0.457; best at 2k-token budget 0.314).
- next-turn predictability.md: candidate sources mru, sessfreq, markov, res1/res3 (names in last 1/3 tool results), pre (names in agent text), user, graph, prior, fused by IRLS logistic over 53 rank-bucket features (ENSEMBLE). Next-file @10 75.7 vs MRU 71.7, CLM zero-shot 37.0; "named in last 3 results" top-1 19.1 alone; session frequency @10 57.2.
- Gaps: no "last eval threw" / "proof red" / "var just redefined" features were defined as such; closest are error-in-eval and proof state after eval (weak labels list above). Dynamic reach (per-test set of called decls, Ochiai) was not obtainable; v1 asked for it to be recorded durably.

## 3. Evaluation methods and numbers
- Leave-one-ATTEMPT-out (exp5_probe.py, 4 folds): logistic probe 300 Adam steps, standardized, majority baseline per fold. action-proj512 76.2%, state 73.5%, both 74.6%, raw 4096-d 72.0%, majority 36.5%. Caveat stated: identical forms recur across attempts + labels are source-text rules, so part is memorised surface form.
- Zero-shot Choice (11 classes): 8.5% k=0, 23.1% k=4, 26.5% k=8; calibrated 29.9-33.3%; majority 35.9%. Progress verifier (Noul) AUC 0.34/0.42/0.51; next-form ranking mean rank 15.3 vs 15.5 random, top-1 5.1%. 1-NN: CLM vectors 77.8% vs char-3gram 74.4% (72.6 vs 70.9 excluding identical sources).
- Other cautions (training.md): split by TASK not step, need ~50+ distinct tasks, early stopping on task-disjoint val (heads overfit fast), same encoder/precision for cached and served vectors (q4 breaks ranks), small-n differences <2 points are noise.
- Bootstrap intervals / length-matched negatives: NOT actually run in these scripts. oss-decision-models.md sec 2.5 only RECOMMENDS "paired comparison with bootstrap intervals, report counts" and "strip length features or add a length-matched negative" (Qwen Verification Horizon: static judges exploited by length). rank-signals gave 95% CIs on R@10 (0.34-0.58 at n=42) and noted every ablation lay inside the CI. zero-shot-probes: untuned CLM lost to BM25/Markov on 4 probes.
- Baselines used: majority, char-3gram, recency/MRU, Markov, BM25, RRF, random R@10 ~0.003.

## 4. Instruction/task prompts on the query side
- CLM: question text appended after the state ("context first, question last"); Noul instruction variants tried (exp2.py INS: "moves closer to proof green", "gets new info", negated "repeats work"): all AUC 0.34-0.51, P(true) 0.85-0.89 for everything, uncalibrated. Rephrasing criteria as example forms changed per-class results but not overall accuracy. Next-file probe used instruction "Which file will the agent open or edit next?" and lost.
- EmbeddingGemma 2 (rank-signals): query prefixes "task: code retrieval | query:" vs "task: search result | query:" gave EQUAL results (R@10 0.259 vs 0.274); doc prefix "title: .. | text: ..", 256-dim Matryoshka, 2048-token cap. Source text beat docstring text. embedding/report.md proposes "task: classification | query:" head test for the 117 forms (never run). Qwen3-Embedding/Reranker instructions worth ~1-5% on retrieval (model card, not measured here).

## 5. Directly reusable for scoring candidates vs recent evals
- Embeddings are best as a fallback with full reach, not primary: strongest single signal only on post-hoc message queries; on task plans exact refs + graph neighbourhood beat them; removing embed/test groups gave the largest drops.
- Two-stage design recommended: structural union (refs, 1-2 hop graph, test_reach) generates (93% reach, ~2000 candidates), then rank (RRF or small GBT/LR over rank features), evaluated at token budgets (R@2k/4k/8k). Their live replay: 3k tokens of RRF4 would have pre-empted most of 42 reads/16 re-reads.
- Recency/MRU of touched targets and "names in last k tool results" are cheap, strong (next-file 34% top-1 MRU); CLM ignores recency, fusing naively destroys top ranks.
- Re-reads after elision (14% of forms, 6 whole turns wasted) are a data lookup, not an embedding task: show the elided source / add a reference.
- Cost: bf16 8B CLM 0.4-0.6 ms/token (~0.3 s/state), EmbeddingGemma much lighter; cache vectors by content digest + model + dim + task; heads-only training on cached vectors takes seconds; ~100 rows gives first jump, 1k most of gain (toy).

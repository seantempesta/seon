### Stability: one hung test froze every agent (S1, S2)

- **S1, seen:** from 20:58 to 21:05 no run took a turn; root, the fork server and all five agents
  at 0% CPU, no provider connection open. a2's design had ended `:green` (work! answered at
  11 turns) and gone to the judge, which ran the tests its branch reaches, among them main's
  `seon.model-test/a-streamed-reply-ends-when-the-server-ends-it`: in a2's test fork (pid 46610,
  LISTEN on 127.0.0.1:27080) the test's ring-chez server never answered, and `seon.model/complete`
  read with no end (no read timeout, no keepalive: notes/stability-waits-2026-10-25.md, the
  model.clj:81 row). Killing that one fork: the judge closed a2's run, and the other agents moved
  at once (implement 0 -> 1 turn). **Cause:** every agent's turn observes its proofs through the one
  test service, so one test that never ends blocks every agent's next turn (head-of-line), and a
  main test that serves HTTP from inside a forked test process never ends there.
  **Owner:** the stability lead (waits that never end at their producer): a test fork's death is
  the only end today. Filed: the test service answers each run's waiter independently of another
  run's hung test; the streamed-reply test's server in a fork (`a/thread` + fibers after fork).
- **S2, seen:** `ring-chez: unclaimed fault: connection accepted and handed on, but never claimed`
  in runs/root.log at the same time.
- **Mine (method):** this root watches its checkout's refs, so my commits in the worktree during the
  round moved its main (an agent's `(my.branch/changes)` listed my F1/F2 vars as against main).
  From here on, fixes are committed only between rounds.

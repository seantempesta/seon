# D1–D5 page data in the task's pattern (branch jolt/the-page-holds-what-the-work-needs)

The data is only in the default pull pattern (`:seon.task/task-fact`'s `:seon.ctx/pattern`). Agent view's build 3 draws it. Measured on this worktree's own root, with all 848 tasks loaded from `resources/seon/tasks` and 830 of them citing vars. The numbers are print sizes through `seon.print.select/chars-tokens`, uncut.

The page as build 3 would draw it is the record with each var's callers cut to its tests. It comes to a median of 2.6k tokens, p90 20k and max 92k (`seon.template/a-request-is-one-linked-transaction`: 89 tests, 72k of them test source). For a1's task, `seon.ctx/the-record-is-an-atom`, it is 22.4k tokens, 7 tests and 10k of test source. These are uncut upper bounds, not the page. Per root's ruling, the cut is build 3's render: each test and source at the printer's budget, with a named form for the rest. The number that counts is the page's size after those cuts, within its configured budget. Agent view has this distribution as build 3's target.

The record itself holds all 50 callers' sources, not just the tests'. Before → after, in tokens:
- median 3.9k → 3.9k;
- p90 18.8k → 34.1k;
- max 72k → 214k (`seon.context/related-weighs-a-neighbour-by-its-rarity`).

That is memory and the printer's cut, not what is sent. If it matters, the next step is a narrower callers pattern. That collides with held-once (below).

## Held once, and why there is no `:calls` join

An entity is held once, at its first path, and other paths hold `{:db/id}`. A `:calls` join (`:form/refs :by :var/name` with a narrow `[:var/name :var/kind :var/doc]`) reached a cited var by the narrow pattern before `:cited` did, or the other way round depending on order. Either way one side lost data: the var's `:form` and `:callers`, or the form's `:calls`.

I built the union, an entity held with what every path asks (merge-spec, a re-walk, relocation on a lost path). The self-review rated it questionable, rightly:
- its option merge silently kept one join's `:limit`;
- a callers window rolling would rebuild the whole record on a patch.

I deleted it. The proof's `:form/refs` already names every var it calls, so the join added nothing D5 needs. With no join of a different shape for the same entity, held-once loses nothing. Callers and a proof's form both pull `[*]`.

## Top 5 gaps, ranked by what they cost me

1. **The design surface is invisible from the REPL.** The plan cites no function, so I had to discover the whole surface myself: a grep returned names only (no lines, 350 ms and 240 MB per call), and I needed about ten evals (e05-e11, e14-e17) of callers, source, dir and prn to find that the defect is in two producers (`tree-node`'s `:name` case and `cut-text`'s `:name` case) plus two test helpers (`cuts-of` docstring and `reads-exactly?`). Fix: the context should list the plan's resolved references (the functions it touches, with their callers and the tests that cover them) so the design step starts from them. The screen should show where a symbol is defined and used, with file:line or the ns, not just names.
2. **Multi-form evals return only the last value.** Prompt: "each form's value ... what it printed". Reality: `:value` holds only the final form's result, and earlier values are lost unless printed (e02, which I had to re-run as e03; afterwards I used `prn`/`:out` everywhere). Fix: the prompt should say "print what you need with `prn`; only the last form's value is returned", or the REPL should return every form's value.
3. **The proof lifecycle is opaque.** `(my.task/status)` says `:seon.turn/not-observed` until something (which the prompt does not name) observes the turn (e12, still after prove, e26). Running red proofs made the task `:execution :held` (the done help says a refused run is held for root), which the design step REQUIRES (red proofs). Writing deftests did not attach them to the task (`:proofs #{}`). The prove response has an unexplained `:recorded` key on the eval, and for `reads-exactly?` it says only `:actual "false"`. Fix: the prompt should say which of these to expect at design, how a deftest gets attached to the task, what `:held` means for a design step, and what `:recorded` is.
4. **`seon-op done` ends the agent with no verdict.** It returns `{:judging ...}` only, and the agent is gone at once (`seon.root/ended`), so I could not check the judge's answer, and the context's "end your turn with prose" was never reached. Fix: `done` should return the verdict, or the prompt should say that done ends the run and where the verdict is written (e.g. the task's `:execution` or the wiki).
5. **The cost-proof rule is ambiguous and its input undocumented.** `seon.cost/proof` says "estimate e" and never says what an estimate is (its keys); the only example is a test (`seon.cost-test/linear`, which I did not read). The rule "a function whose input grows" does not say whether a function whose work is capped by a budget counts. I spent four evals (e21-e24) and then made the call alone ("no cost proof"). Fix: the help or the context should carry one worked estimate and say when a budget-bounded function needs a proof.

Minor: the `my.agent/help` list has nothing on the design step, `(my.task/status)`'s prose says "first failing assertion" but the prove output gives four fails, and the `…+N` defect repro (eval 18) was the most useful single form: a `print-value` with and without `:handle` makes the bug visible in one reply.

## A parked test ends as a recorded failure

(b) of root's brief. A test that parks does no work, so the per-test tick budget (seon.proofs/test-vars) never ends it, and no clock may. The end must be a fact. There are two cases, and each ends at its cause:

1. **The test waits on a child (a test root, an agent) that is alive and parked.** The test is in an I/O wait, which is legitimate: the child may still answer. The child must end its own wait. Root knows when it is quiet (the reconciler's quiescence report: no message in flight, every proc parked). An open wait whose pred is false at that report can never become true from inside root, so root answers it with :seon.root/never-true. The child's answer unwinds the socket read, the test records the error, and the shard goes on. A child that dies ends the read by EOF (already an A). Task seon.root/a-wait-on-main-ends-when-nothing-can-make-it-true.
2. **The test parks in its own process with nothing able to answer** (an undelivered promise, a <!! with no putter, a mutex inherited across a fork). The process is globally quiescent: every thread and fiber is parked, no timer, no foreign call, no I/O wait. Jolt's scheduler can see that. Like Go's runtime, it raises a typed :jolt/deadlock error in each parked wait, naming what each waits on. The test reports it as its :error with those stacks, and the runner goes on to the next test. Task jolt.async/a-process-whose-every-thread-parks-ends-its-waits.

Together these unwind any chain of parked waits from the bottom up, child first, with no timer. The runner keeps knowing only its children's exits (bin/test's wait, bin/held's fifo), plus reporting each shard as it ends (wait -n). Case 1's quiescence is the reconciler's own report, so it adds no new mechanism. Case 2 is one Jolt change.
